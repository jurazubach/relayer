# Приёмы и структуры

Обозначения источников — как в `principles.md`: [Knox], [GA], [VanDine], [Alex-3], [Alex-node], [WD].
Соглашение для примеров: улики, нужные финалу, отмечаются переменной `clue_*` (`VAR clue_x = false`, `~ clue_x = true`).
Это обычные переменные ink: игрок их не видит, а бот может прочитать (см. `for-relayer.md`, §2).

---

### PAT-01. Три улики на вывод (Three Clue Rule — правило трёх улик)
- **Когда применять:** у каждого вывода, без которого игрок не поймёт разгадку или не получит хороший финал. **Когда нет:** у фоновых фактов, которые только добавляют цвета, — им хватит одной улики.
- **Схема:**
  ```
  вывод «токен читает вики»
    ├─ улика 1: чат sec — «в окружении админ-токен на всю организацию»   (ствол)
    ├─ улика 2: чат notes — «заметки синкаются в вики-репо»              (ствол)
    └─ улика 3: чат ghost — цитирует фразу из заметки                    (ветка А)
                 или чат intern — «клоны репо с августа»                 (ветка Б)
  ```
  Три улики должны приходить разными путями: из разных чатов, в разной форме (реплика, системная строка, заметка) и в разных главах. Три похожие строки одного контакта считаются за одну.
- **На ink:**
  ```ink
  # contact: sec, Меган, indigo
  # contact: notes, Заметки, green
  # contact: ghost, Неизвестный номер, grey
  VAR clue_token = false
  VAR clue_wiki = false
  VAR clue_quote = false
  в окружении процесса был токен гитхаба #from:sec #delay:3s
  админский. на всю организацию
  ~ clue_token = true
  черновики синкаются в вики-репо, заберу утром #delay:4s
  ~ clue_wiki = true
  * [записать подробно #to:notes]
      — защита: образы пересоберём без отладчика #from:notes #delay:2s
  * [записать коротко #to:notes]
      — вход через отладчик #from:notes #delay:2s
  - #delay:2h
  «Пересоберём без отладчика». Мило. #from:ghost #unlock:ghost #delay:3s
  ~ clue_quote = true
  -> END
  ```
- **Цена:** две-три лишние реплики на вывод. Сложности почти не добавляет, если улики стоят на общем стволе.
- **Ловушки:** улика в ветке, куда игрок не пошёл, не существует для него (P-08). Три улики, которые выдаёт один и тот же помощник подряд, читаются как одна. Если улика есть только во всплывающем уведомлении из чата, который игрок не открыл, он её тоже не увидит.
- **Источник:** [Alex-3] — правило трёх улик: игрок одну пропустит, другую проигнорирует, третью поймёт неверно. Требование разных каналов и «похожие строки считаются за одну» — наш перенос на чаты и ветки (см. P-07).

### PAT-02. Ворота дедукции (по мотивам «Challenge to the Reader» — вызова читателю)
- **Когда применять:** перед каждой главной разгадкой, когда все три улики уже показаны. **Когда нет:** в первой главе, если правила мира ещё не объяснены, — игроку не из чего выводить.
- **Схема:**
  ```
  последняя улика → #delay (долгая пауза: игрок думает) → вопрос NPC «ну и как?»
     ├─ верный вывод  → NPC подтверждает, называет 2 улики, ~ solved = true
     ├─ ложный след   → NPC опровергает уликой, цена (время, доверие)
     └─ «не знаю»     → NPC сам называет вывод, но solved = false
  ```
  Реальная пауза relayer играет роль страницы с вызовом: между уликой и ответом проходят минуты, и игрок успевает перебрать чат.
- **На ink:**
  ```ink
  # contact: sec, Меган, indigo
  VAR solved = false
  VAR trust_sec = 0
  Хорошие у тебя заметки. #from:sec #delay:3s
  это он мне переслал. откуда он их читает? #delay:20m
  * [токен бота. он читает весь гитхаб, вики там же #to:sec]
      ~ solved = true
      ~ trust_sec += 1
      да. токен на всю организацию + синк заметок в репо #from:sec #delay:4s
  * [у нас крот в команде #to:sec]
      крот не знал бы, что заметки лежат в репо #from:sec #delay:5s
      а этот цитирует черновик, который никто не открывал
  * [не знаю #to:sec]
      токен. вики лежит в гитхабе, который он читает #from:sec #delay:4s
  - -> END
  ```
- **Цена:** один узел и 3 короткие ветки. Ветки сразу сходятся, на карте почти не видно.
- **Ловушки:** если верная кнопка сформулирована подробнее остальных, игрок угадывает её по форме, а не по уликам. Делай все варианты одной длины и одной уверенности. Неверный вариант без опровержения оставляет игрока с ложной версией.
- **Источник:** вызов читателю в романах Эллери Куина — знание модели, уверенность: высокая (на открытых страницах Википедии об этом не сказано). Требование, чтобы сыщик действительно выводил разгадку из улик, — [VanDine]. Ветки с ценой ошибки — наше переложение.

### PAT-03. Ложный след с опровержением и ценой (red herring — «копчёная селёдка»)
- **Когда применять:** нужен ложный подозреваемый или ложная версия, чтобы разгадка удивила. **Когда нет:** если улик для настоящего вывода меньше трёх, сначала добавь их, а не ложные.
- **Схема:**
  ```
  улика-приманка (правдоподобна, у неё своя логика)
     → игрок может пойти по ней (кнопка) → цена: потерянное время или доверие
     → опровергающая улика (обязательно, на общем стволе)
  ```
- **На ink:**
  ```ink
  # contact: argus, Аргус, red
  # contact: lead, Кай, blue
  # contact: devops, Рид, orange
  VAR blamed_rid = false
  я все коммиты подписываю. меган заставила #from:devops #delay:4s
  #delay:2h
  [audit] коммит в master. автор: рид. 01:42 #from:argus #delay:3s
  * [рид, объясни #to:devops]
      ~ blamed_rid = true
      я спал. ты серьёзно? #from:devops #delay:6s
  * [кай, проверь подпись коммита #to:lead]
      не подписан. у рида подписаны все #from:lead #delay:5s
  - автор в гите — просто текст. имя взяли из истории репо #from:lead #delay:4s
  -> END
  ```
  Опровержение (подпись) посажено за два часа до приманки, а итог «автор — просто текст» приходит в обеих ветках.
- **Цена:** приманка + опровержение + реплика с ценой — 4–6 строк.
- **Ловушки:** игроки держатся за первую найденную версию и плохо от неё отказываются. Опровержение должно быть явным, а не намёком. Если приманку никто не опроверг, финал выглядит обманом.
- **Источник:** [Alex-3] — ложные следы переоценены, игроки сами цепляются за ложные выводы, нужен явный способ опровергнуть. [WD] — у ложного следа должна быть своя правдоподобная причина.

### PAT-04. Улика на виду (hiding in plain sight)
- **Когда применять:** улика должна остаться в истории чата, но не бросаться в глаза при первом чтении.
- **Схема — четыре способа спрятать:**
  1. **В быту:** улика стоит в организационной реплике («заберу утром»), а не в той, где говорят о деле.
  2. **В списке:** третий пункт из четырёх, рядом с ярким первым.
  3. **Перед отвлечением:** сразу за уликой — громкое событие (алерт, звонок партнёра, новый контакт).
  4. **Через отсутствие:** чего-то нет там, где оно должно быть (лог пустой, человек не ответил в обычное время).
- **На ink:**
  ```ink
  # contact: intern, Итан, cyan
  # contact: argus, Аргус, red
  VAR clue_quiet_day = false
  что нашёл по сентябрю: #from:intern #delay:3s
  — депозиты по мелочи три недели
  — одна сессия с подменённым шифтом
  — накануне ни одной ставки. весь день
  ~ clue_quiet_day = true
  — все операторы крипто
  [S1] rtp 140% на gx-7 #from:argus #delay:2s
  -> END
  ```
- **Цена:** ноль строк: улика встраивается в уже нужный текст.
- **Ловушки:** если спрятать слишком хорошо, разгадка покажется взятой из воздуха. Проверка: в разгадке NPC может сослаться на эту строку, и её можно найти прокруткой (PAT-06). Строку, которая пришла и тут же скрылась за долгой паузой в другом чате, игрок может не прочитать вообще.
- **Источник:** знание модели, уверенность: средняя (общая практика жанра). [VanDine] называет «собаку, которая не залаяла» среди заезженных приёмов. Сам приём «улика через отсутствие» от этого не хуже, но знаменитую собаку не копируй.

### PAT-05. Проактивная улика (proactive clues — «бей по голове»)
- **Когда применять:** игрок молчит, отвечает «не знаю» или пошёл не туда. Сюжет не ждёт, пока он догадается: противник делает ход, и ход оставляет новую улику. **Когда нет:** если игрок уже сделал верный вывод — тогда ход противника нужен для напряжения, а не для подсказки.
- **Схема:**
  ```
  выбор: [вывод A] [вывод B] [промолчать]
                               └─ #delay → противник действует → улика 4 в новом чате
  ```
- **На ink:**
  ```ink
  # contact: ghost, Неизвестный номер, grey
  # contact: sec, Меган, indigo
  VAR clue_quote = false
  Добрый вечер. #from:ghost #unlock:ghost #delay:3s
  * [кто это? #to:ghost]
      Тот, кто читает вашу вики раньше вас. #from:ghost #delay:6s
  * [промолчать #to:ghost #silent]
      #delay:15m
      «Образы пересоберём без отладчика». Узнаёшь? #from:ghost #delay:3s
      ~ clue_quote = true
      это из твоего черновика. дословно #from:sec #delay:4s
  - -> END
  ```
- **Цена:** одна ветка на молчание. В relayer это ещё и честное использование `#silent`: молчание тоже двигает сюжет.
- **Ловушки:** если проактивная улика приходит только тому, кто молчит, получается, что молчание выгоднее ответа. Дай её и второй ветке, другим способом.
- **Источник:** [Alex-3] — когда игроки застряли, пусть что-то произойдёт: атака, новая жертва, ход злодея, и этот ход даёт новые улики.

### PAT-06. Разгадка со ссылками («я же это видел»)
- **Когда применять:** в узле разгадки и в итоговом разборе.
- **Схема:** вывод → 2–3 улики, на которые он опирается, каждая с указанием, где её искать (чей чат, когда) → только потом новое. Ссылка зависит от ветки: называй только те улики, которые игрок точно видел.
- **На ink:**
  ```ink
  # contact: sec, Меган, indigo
  VAR clue_token = true
  VAR clue_quote = false
  VAR clue_clones = false
  крота нет. крот — это токен #from:sec #delay:4s
  {clue_token: помнишь первую ночь? токен на всю организацию #delay:3s}
  и наши заметки лежат в том же гитхабе. я сама тебе писала #delay:3s
  {clue_quote: поэтому он и цитировал твой черновик дословно #delay:3s}
  {clue_clones: и поэтому клоны репо математики с августа #delay:3s}
  -> END
  ```
- **Цена:** 2–4 строки, условия на переменных-уликах.
- **Ловушки:** ссылка на улику, которой игрок не видел, — для него это неправда. Без условий `{clue_*:}` эта ошибка появится в каждой ветке, где улика не пришла.
- **Источник:** [Knox], [VanDine] — разгадка должна опираться на уже показанные улики. Ссылки на чат и время — наше: в мессенджере история переписки и есть папка с делом.

### PAT-07. Список откровений (revelation list)
- **Когда применять:** до первой строки ink, в шапке сценария, и при ревью.
- **Схема:** раздели факты на два списка.
  - **Структурные** — без них не будет разгадки или хорошего финала. Каждому — переменная `clue_*`, три улики (PAT-01), узел, где он нужен.
  - **Фоновые** — колорит и объяснения «почему». Им переменная не нужна.
  ```
  // reveal: token_reads_wiki  needs: clue_token clue_wiki clue_quote  at: ch3_ghost_vera
  // reveal: shifts_from_repo  needs: clue_clones clue_quote           at: debrief
  ```
- **На ink:**
  ```ink
  # contact: sec, Меган, indigo
  // reveal: token_reads_wiki  needs: clue_token clue_wiki  at: reveal
  VAR clue_token = false
  VAR clue_wiki = false
  токен админский #from:sec #delay:3s
  ~ clue_token = true
  заметки синкаются в репо #delay:3s
  ~ clue_wiki = true
  -> reveal
  === reveal ===
  он читает вики токеном #from:sec #delay:4s
  -> END
  ```
  Комментарии `//` компилятор выбрасывает, игрок их не видит, а скрипт может прочитать их из исходника.
- **Цена:** 5–10 строк комментариев на историю и дисциплина ставить `~ clue_x = true`.
- **Ловушки:** если отметить уликой всё подряд, список перестаёт помогать. Структурных откровений 1–2 в истории до 25 минут и 3–6 в длинной (наша оценка, `attention.md` §4).
- **Источник:** [Alex-node] — правило «в каждом узле ≥3 улик и ≥3 улик ведут к нему». Второй проход закрыл вопрос ревью: список откровений описан в «Three Clue Rule» (раздел «ничто не надёжно»: выводы, под ними улики, отметки найденного и сделанного вывода) и в «Using Revelation Lists» (29.10.2018, https://thealexandrian.net/?p=40978 — список «что ведёт сюда» против списка «что лежит здесь»); разделение на структурные и фоновые откровения — «Running Mysteries: Background Revelations» (31.07.2024, https://thealexandrian.net/?p=51319). Формат комментария — наш.

### PAT-08. Двойник с предупреждением (по мотивам правила о близнецах)
- **Когда применять:** в сюжете есть подменный контакт, фишинг, чужой номер с знакомым именем, ИИ-голос.
- **Схема:** заранее покажи, что противник знает имена и детали команды → двойник пишет с отдельного контакта (отдельный `# contact:`) → у игрока есть канал проверить настоящего.
- **На ink:**
  ```ink
  # contact: devops, Рид, orange
  # contact: fake, Рид (новый номер), orange
  // warn: fake clue_impostor
  VAR checked_fake = false
  VAR clue_impostor = false
  он знает, как нас зовут. даже про жену рида #from:devops #delay:4s
  ~ clue_impostor = true
  #delay:1h
  это рид. телефон сдох, скинь код доступа #from:fake #unlock:fake #delay:3s
  * [рид, это ты с другого номера? #to:devops]
      ~ checked_fake = true
      нет. я тут #from:devops #delay:4s
  * [держи #to:fake]
      спасибо #from:fake #delay:4s
  - -> END
  ```
- **Цена:** один контакт и одна предупреждающая реплика заранее.
- **Ловушки:** если подмену никак не предупредили, это нарушение честной игры: игрок проигрывает из-за трюка, о котором не мог знать. Предупреждение после выбора не считается — так сейчас в `ch4_fake` «Слепого пятна» (`for-relayer.md` §4.5). Строка `// warn:` связывает двойника с уликой-предупреждением, чтобы бот мог это проверить (RED-11).
- **Источник:** [Knox] — близнецы и двойники допустимы, только если читателя к ним подготовили.

### PAT-09. Перевёрнутый детектив (inverted detective story, howcatchem — «как поймают»)
- **Когда применять:** противник известен с первой главы, загадка в том, как он действовал и как его остановить. Подходит техническим историям вроде «Слепого пятна»: главный вопрос там «как», а не «кто».
- **Схема:** покажи противника и его ход рано → вопросы главы «как он вошёл / что он знает / что сделает дальше» → каждая глава закрывает один вопрос и открывает следующий.
- **На ink:**
  ```ink
  # contact: ghost, Неизвестный номер, grey
  # contact: lead, Кай, blue
  Я в вашем кластере с 23:10. #from:ghost #unlock:ghost #delay:3s
  Угадаешь, как вошёл?
  * [открытый порт? #to:lead]
      9229. отладчик. проверю, кто подключался #from:lead #delay:5s
  * [утёкший пароль? #to:lead]
      пароли не менялись, входов по ним нет #from:lead #delay:5s
      значит, не через вход. через процесс
  - -> END
  ```
- **Цена:** правила честной игры те же, только улики ведут к способу, а не к имени.
- **Ловушки:** если имя противника — финальный сюрприз, а сам противник появился только в последней главе, игрок воспримет это как обман (P-02).
- **Источник:** знание модели, уверенность: высокая — перевёрнутый детектив связывают с Р. Остином Фрименом (сборник 1912 г.) и сериалом «Коломбо». Перенос на наши истории — наш.

### PAT-10. Возвращение с уликой (дело после паузы)
- **Когда применять:** после `#delay` от 1 часа, если до паузы был открыт вопрос загадки. **Когда нет:** после коротких пауз внутри сцены — пересказ раздражает.
- **Схема:**
  ```
  вопрос загадки → #delay ≥ 1h → NPC: «на чём стоим» (вопрос + 1–2 улики их же словами)
     → ход противника за время паузы (новая улика) → вопрос → ворота
  ```
- **На ink:**
  ```ink
  # contact: sec, Меган, indigo
  # contact: ghost, Неизвестный номер, grey
  VAR clue_quote = false
  VAR clue_wiki = false
  VAR solved = false
  «Пересоберём без отладчика». Узнаёшь? #from:ghost #unlock:ghost #delay:3s
  ~ clue_quote = true
  это из твоего черновика. кто его вообще видел? #from:sec #delay:4s
  #delay:3h
  я вернулась. напомню, на чём стоим: #from:sec #delay:3s
  он дословно цитирует твой черновик
  и черновик лежит только у нас в заметках
  пока тебя не было, он написал ещё раз #delay:4s
  Вики у вас уютная. #from:ghost #delay:2s
  ~ clue_wiki = true
  так откуда он читает? #from:sec #delay:1m
  * [из вики-репо. токен бота видит весь гитхаб #to:sec]
      ~ solved = true
      да. и черновики синкаются туда же #from:sec #delay:4s
  * [кто-то из команды пересылает #to:sec]
      тогда он бы не знал, что это вики #from:sec #delay:4s
  - -> END
  ```
- **Цена:** 2–3 реплики на каждую долгую паузу.
- **Ловушки:** напоминание пересказывает события, а не улики; ворота ставятся сразу после паузы без напоминания; напоминание называет улику, которой в этой ветке не было (оберни в `{clue_x:}`, PAT-06).
- **Источник:** проблема потери контекста между сессиями — Golden Idol (`lessons.md`, LESSON-07); ход противника как новая улика — [Alex-3] (проактивные улики). Схема — наша.

### PAT-11. Ступенчатая дедукция (проверка по частям)
- **Когда применять:** разгадка складывается из 2–3 частей (как вошёл, зачем, кто). **Когда нет:** вывод один и простой — хватит PAT-02.
- **Схема:**
  ```
  часть 1: вопрос → 2 версии → подтверждение/опровержение сразу
  часть 2: вопрос → 2 версии → подтверждение/опровержение сразу
  итог: NPC называет, сколько частей игрок вывел сам
  ```
- **На ink:**
  ```ink
  # contact: lead, Кай, blue
  VAR v_entry = false
  VAR v_motive = false
  VAR wrong = 0
  давай по шагам. сначала: как он вошёл? #from:lead #delay:3s
  * [через порт отладчика #to:lead]
      ~ v_entry = true
      да. 9229 был открыт #from:lead #delay:4s
  * [по утёкшему паролю #to:lead]
      ~ wrong += 1
      входов по паролям не было. порт 9229, отладчик #from:lead #delay:5s
  - теперь: зачем ему наш кластер? #delay:3s
  * [ему нужны выигрышные шифты #to:lead]
      ~ v_motive = true
      да. генератор он не трогал, он читал готовое #from:lead #delay:4s
  * [он хочет нас уронить #to:lead]
      ~ wrong += 1
      уронить мог давно. он полгода тихо забирал выигрыши #from:lead #delay:5s
  - {v_entry && v_motive: два из двух. ты быстрее меня|ладно. картина есть, дальше вместе} #delay:3s
  -> END
  ```
- **Цена:** по выбору на часть; ветки сразу сходятся.
- **Ловушки:** подсказка «сколько верно» облегчает и укорачивает загадку — Golden Idol это признал (LESSON-05); у нас это допустимая плата за короткую сессию. Не подтверждай пачкой в конце: игрок в чате не держит три версии в голове (LESSON-09, `attention.md`).
- **Источник:** Golden Idol — частичная обратная связь вместо «верно/неверно» за всю разгадку (`lessons.md`, LESSON-05); Obra Dinn — подтверждение пачкой против перебора (LESSON-09). Перенос — наш.

## Нюансы к приёмам (второй проход)

- **PAT-01, 5 против 50 сообщений.** В сцене на 5 сообщений три улики не помещаются: две улики двумя голосами и кнопка. В главе на 50 — три улики в трёх формах. Обратное правило ([Alex-node2]): к концу главы у игрока ≥ 3 улик на ещё не раскрытые откровения, иначе следующей главе не за что тянуть.
- **PAT-02.** Ворота сразу после паузы > 1 часа — плохо (PAT-10). Кнопка «не знаю» без цены становится лучшей стратегией; цена — `solved = false` в финале или реплика NPC с разочарованием. Текст кнопки должен предсказывать реплику героя (LESSON-11).
- **PAT-03.** Опровержение-событие сильнее опровержения-рассуждения (LESSON-03). Одна приманка на историю до 25 минут.
- **PAT-04.** На беглом чтении «спрятанная» улика невидима. Прятать только одну из трёх; способ «через отсутствие» — только страховочной.
- **PAT-05.** Проактивная улика после долгой паузы — лучшая первая реплика возвращения (PAT-10).
- **PAT-07.** Подтверждено по [Alex-rev], [Alex-bg]; бот проверяет только структурные откровения.
- **PAT-09.** В перевёрнутом детективе «вызов» не про имя, а про способ; ступенчатая дедукция (PAT-11) подходит ему лучше одних ворот.
