# Чек-листы

Опираются на принципы `P-NN` и приёмы `PAT-NN`. Каждый шаг — действие и что должно получиться.

## 1. Как придумать и начать историю-тайну

- [ ] **Запиши правду до сюжета.** Хронология того, что на самом деле сделал противник, по минутам или часам, 8–15 строк. → Есть «дело», от которого будут отпочковываться улики.
- [ ] **Выбери тип загадки:** кто (whodunit), как (howdunit, PAT-09) или зачем (whydunit). → Одна фраза-вопрос, которую игрок сможет сформулировать к концу главы 1.
- [ ] **Составь список откровений** (PAT-07): 3–6 структурных фактов, без которых нет разгадки или хорошего финала. → Каждому дано имя и узел `at:`, где он прозвучит.
- [ ] **На каждое откровение — три улики** (P-06) в разных чатах и формах (P-07). → Таблица «откровение | улика | контакт | глава».
- [ ] **Реши, где виновник появляется впервые** (P-02). → Глава 1–2: его чат или его след.
- [ ] **Придумай 1–2 приманки** (PAT-03) и для каждой — опровергающую улику и цену ошибки. → Строки «приманка → опровержение → цена».
- [ ] **Назначь честных контактов** (P-03): кто из персонажей не врёт. → Список; у остальных — мотив врать или молчать.
- [ ] **Перечисли механизмы, которые игроку нужно понять** (P-11), и кто их объяснит. → Каждый механизм объяснён в главе раньше разгадки.
- [ ] **Напиши первые 10–15 сообщений вокруг измеренной аномалии:** факт + норма рядом («312 игроков на одной строке, в норме 1 к 1»). → Загадка названа, первая улика выдана.
- [ ] **Внеси в шапку ink** `// culprit:` и строки `// reveal:`, объяви `VAR clue_*`. → Бот сможет проверить разметку.

## 2. Как написать главу или сцену

- [ ] **Выпиши, какие улики выдаёт глава** (из таблицы шага 1.4). → В каждой главе до финальной ≥1 улика и ≥1 новый вопрос.
- [ ] **Поставь каждую обязательную улику на общий ствол** или продублируй во всех ветках (P-08). → Нет улики, которая живёт только в одной ветке.
- [ ] **Спрячь одну улику из трёх** (PAT-04: быт, список, перед отвлечением, отсутствие). → При чтении вслух коллега её не выделяет.
- [ ] **У каждой кнопки, меняющей переменную финала, проверь предупреждение о риске** (P-12). → Перед кнопкой есть реплика, из которой риск можно вывести.
- [ ] **Если сцена — разгадка:** перед ней пауза ≥5 минут и вопрос от NPC (P-13), затем ворота дедукции (PAT-02). → Игрок выбирает вывод сам.
- [ ] **Уравняй варианты ворот** по длине и уверенности. → Верный вариант не длиннее остальных больше чем в 1,5 раза.
- [ ] **Дай неверным вариантам опровержение и цену** (GREEN-05). → У каждой неверной кнопки есть реплика «почему нет» и изменение переменной или потеря времени.
- [ ] **В реплике разгадки сошлись на 2 улики**, обернув ссылки в `{clue_x:}` (PAT-06). → Ни одной ссылки на непоказанное.
- [ ] **Поставь `~ clue_x = true`** сразу после строки каждой улики. → Бот видит улику.

## 3. Как провести ревью готового сценария

- [ ] **Восстанови список откровений по тексту**, не глядя в план автора. → Если список не совпадает с `// reveal:`, план и текст разошлись.
- [ ] **Для каждого откровения заполни таблицу:** улика | узел | контакт | на стволе или в ветке. → Видно, где меньше трёх улик и где все в одном чате (RED-01).
- [ ] **Найди узел разгадки каждого откровения** и проверь, кто делает вывод: игрок кнопкой или NPC. → NPC → RED-02.
- [ ] **Проверь, что ни одна улика не приходит в узле разгадки** (RED-03). → Все улики раньше хотя бы на один выбор.
- [ ] **Найди первое появление виновника** (P-02). → Позиция в первой трети, иначе RED-04.
- [ ] **Выпиши приманки и их опровержения** (P-09). → Без опровержения → RED-05.
- [ ] **Выпиши все ложные утверждения по контактам** (P-03). → Ложь от честного контакта без опровержения → RED-09.
- [ ] **Разбери финальный узел:** переменные условий → кнопки, которые их меняют → предупреждения перед кнопками (P-12). → Таблица; пустая ячейка «предупреждение» → RED-07.
- [ ] **Проверь термины разгадки** на раннее объяснение (P-11). → Новые механизмы → RED-12.
- [ ] **Посчитай строки разбора после последнего выбора** (P-15). → >15 → RED-10.

## 4. Как тестировать

- [ ] **Прогони `npm run check:story`.** → Нет тупиков и недостижимых узлов; все финалы встречаются.
- [ ] **Собери карту `npm run graph`** и найди на ней узлы `at:` из `// reveal:`. → Для каждого видна доля прогонов, которая через него проходит.
- [ ] **Если в `check:story` есть проверка улик** (for-relayer §2): прочитай предупреждения `улики:`. → Каждое предупреждение либо исправлено, либо записано с причиной.
- [ ] **Проверь самый бедный путь:** пройди по отладочной шторке ветками, где игрок молчит и выбирает «не знаю». → На нём всё ещё ≥2 улики к каждой разгадке.
- [ ] **Дай тестеру задание:** до разгадки остановиться и написать свою версию одной фразой. → Доля тестеров, которые угадали: 30–70% (порог — наша оценка). Все угадали — улики слишком явные; никто — слишком тёмные или их мало (P-16).
- [ ] **После прохождения спроси тестера:** какие улики разгадки он помнит, и попроси найти их прокруткой. → Нашёл ≥2 → «я же это видел» работает (P-14).
- [ ] **Спроси, какие подозрения остались неразрешёнными.** → Если тестер назвал приманку, по которой ходил кнопкой, — её опровержение не дошло (RED-05).
