# Приёмы и структуры

Все примеры на ink скомпилированы inkjs и прогнаны по одному пути.

### PAT-01. Две оси отношения (по мотивам attitude system — системы отношений из The Gryphon Tapestry)
- **Когда применять:** у ключевого контакта, который проходит через всю историю и реагирует на ложь или честность игрока. **Когда нет:** у эпизодических контактов: хватит одного флага.
- **Схема:**
  ```
  выбор ─┬─ trust ±1
         └─ respect ±1
  … пауза …
  условная реплика: смотрит на сочетание (trust<0 и respect>0 → «не верю, но уважаю»)
  ```
- **На ink:**
  ```ink
  # contact: nina, Нина, teal
  VAR nina_trust = 0
  VAR nina_respect = 0
  Вы обещали ответить до девяти. #from:nina
  * [Простите, я соврал про работу #to:nina]
      ~ nina_trust -= 1
      ~ nina_respect += 1
  * [Был занят #to:nina]
      ~ nina_trust -= 1
  - #delay:2h
  {
  - nina_respect > 0:
      Я Вам не верю. Но Вы хотя бы не выкручиваетесь. #from:nina
  - else:
      Понятно. #from:nina
      С уважением, Н. Орлова.
  }
  -> END
  ```
- **Цена:** по две переменные на персонажа. На каждое сочетание осей, которое реально встречается, нужна одна-две условные реплики.
- **Ловушки:** завести шесть осей, как в исходной системе, и читать одну. Записывать оси только `+= 1`: без минусов они не расходятся.
- **Источник:** шесть осей и шкала −6…+6 — https://emshort.blog/2017/12/05/character-development-and-storytelling-for-games-lee-sheldon/. Сокращение до двух осей — наше.

### PAT-02. Реплика-подпись как индикатор отношения
- **Когда применять:** у персонажа с формальным голосом, когда нужно, чтобы молчание игрока было заметно, но без нового текста. **Когда нет:** у болтливых контактов: подпись будет выглядеть чужой.
- **Схема:** маркер голоса (подпись, эмодзи, «Вы») → игрок промолчал или обидел → маркер усиливается или урезается → при пороге меняется.
- **На ink:**
  ```ink
  # contact: nina, Нина, teal
  VAR nina_cold = 0
  Вы получили документы? #from:nina
  * [Да, спасибо #to:nina]
  * [Промолчать #to:nina #silent]
      ~ nina_cold += 1
      С уважением, Н. Орлова. #from:nina #delay:5m
  - #delay:3h
  Завтра суд. #from:nina
  * [Я приду #to:nina]
  * [Промолчать #to:nina #silent]
      ~ nina_cold += 1
      {nina_cold >= 2:
          Н. О. #from:nina #delay:10m
      - else:
          С уважением, Н. Орлова. #from:nina #delay:5m
      }
  - -> END
  ```
- **Цена:** почти бесплатно: одна строка на реакцию.
- **Ловушки:** подпись, которая никогда не меняется, со временем становится обоями. Её смысл появляется, когда она сократилась или исчезла.
- **Источник:** наш приём на основе `P-05` и `P-12`. Его образец — «Kind regards, J. Marsh.» в `chuzhoy-golos`. У Шелдона его нет.

### PAT-03. Модульная глава (modular storytelling — модульное повествование)
- **Когда применять:** в начале расследования или главы, где надо опросить нескольких людей. **Когда нет:** в кульминации: там нужен один нарастающий разговор, а не меню.
- **Схема:**
  ```
          ┌─ модуль A (чат lev) ─┐
  hub ────┼─ модуль B (чат ira) ─┼──> hub … seen >= 2 ──> gate
          └─ модуль C (чат guard)┘
  ```
- **На ink:**
  ```ink
  # contact: lev, Лев, blue
  # contact: ira, Ира, pink
  # contact: guard, Охранник, grey
  VAR seen = 0
  -> hub
  === hub ===
  {seen >= 2: -> gate}
  * [Лев, ты был там в ту ночь? #to:lev]
      -> lev_line
  * [Ира, кто дал тебе ключ? #to:ira]
      -> ira_line
  * [Здравствуйте, вы дежурили? #to:guard]
      -> guard_line
  === lev_line ===
  был. ушёл в час #from:lev #delay:1m
  ~ seen += 1
  -> hub
  === ira_line ===
  никто. он висел на гвозде #from:ira #delay:3m
  ~ seen += 1
  -> hub
  === guard_line ===
  Дежурил. Камера не работала с июня. #from:guard #delay:10m
  ~ seen += 1
  -> hub
  === gate ===
  мне надо тебе кое-что сказать #from:lev #delay:30m
  -> END
  ```
- **Цена:** на каждый модуль 3–10 строк. Сложность растёт, только если модули ссылаются друг на друга.
- **Ловушки:** если модули не дают разных находок, порядок не важен и свобода фальшивая. Если выход открывается только после *всех* модулей, это обязательный обход, а не выбор. Лучше порог `2 из 3`, а недопрошенный модуль пусть откликнется позже.
- **Источник:** глава Modular Storytelling — https://www.routledge.com/Character-Development-and-Storytelling-for-Games/Sheldon/p/book/9780367248987. Устройство хаба — наше, уверенность в трактовке: средняя.

### PAT-04. Обязательная сцена со сроком (obligatory scene)
- **Когда применять:** персонаж ставит условие или срок, и ответ на него — сцена, которую игрок ждёт. **Когда нет:** если сцену нельзя гарантировать во всех мирах. Тогда не давай срок вслух.
- **Схема:** обещание (срок N) → счётчик или обратный отсчёт в репликах → сцена-ответ всегда приходит, отличается только содержанием.
- **На ink:**
  ```ink
  # contact: mark, Марк, orange
  VAR told_name = false
  VAR days_left = 3
  Я помогу. Но к пятнице скажите, кто Вы. #from:mark
  -> day
  === day ===
  ~ days_left -= 1
  {days_left == 1:
      Завтра пятница. #from:mark #delay:2h
  }
  {days_left == 0: -> friday}
  + [Меня зовут Кира. Я сестра свидетеля #to:mark]
      ~ told_name = true
      -> friday
  + [Пока не могу #to:mark]
      -> day
  === friday ===
  {told_name:
      Спасибо, Кира. Теперь слушайте. #from:mark #delay:1h
  - else:
      Пятница. Вы молчите — и я молчу. #from:mark #delay:1h
  }
  -> END
  ```
- **Цена:** узел-ответ с двумя-тремя вариантами и напоминание в середине.
- **Ловушки:** `*` вместо `+` в цикле: одноразовый вариант исчезнет на втором круге, и выбор станет вынужденным. Сцена-ответ только в одном финале — это `RED-04`.
- **Источник:** понятие — https://emshort.blog/2017/12/05/character-development-and-storytelling-for-games-lee-sheldon/. Механика со сроком — наша.

### PAT-05. Отложенный отклик (память персонажа)
- **Когда применять:** после выбора, который «только меняет реплику» и сразу сходится. Отклик через главу превращает его в последствие. **Когда нет:** если отклик ничего не меняет в отношении: тогда это просто напоминание.
- **Схема:** ранний выбор → флаг → ветки сходятся → через паузу ≥ 1h персонаж ссылается на выбор.
- **На ink:**
  ```ink
  # contact: dan, Дэн, amber
  VAR alias = ""
  VAR lied_job = false
  как тебя записать? #from:dan
  * [Вера #to:dan]
      ~ alias = "Вера"
  * [Ника #to:dan]
      ~ alias = "Ника"
  - а работаешь где? #from:dan #delay:20s
  * [В библиотеке #to:dan]
      ~ lied_job = true
  * [Нигде сейчас #to:dan]
  - ок #from:dan #delay:2h
  {lied_job:
      {alias}, я звонил в библиотеку. там такой нет #from:dan #delay:1m
  - else:
      {alias}, есть подработка. если надо #from:dan #delay:1m
  }
  -> END
  ```
- **Цена:** одна переменная и одна условная реплика на выбор.
- **Ловушки:** отклик сразу после выбора не ощущается как память. Сработавший флаг нигде больше не читается — значит, след остался только в одной реплике.
- **Источник:** развитие идеи системы отношений (`P-06`). У Шелдона в такой форме нет.

### PAT-06. Тон, который накапливается в развилке «только реплика»
- **Когда применять:** развилка из 2–4 вариантов, которые отличаются тоном и сразу сходятся. У нас таких кнопок 126 из 338. **Когда нет:** если варианты действительно равнозначны, например выбор ваучера.
- **Схема:** варианты → `heat += 0/1/2` → немедленная реакция по ступеням → через сцену порог меняет факт, который персонаж сообщает.
- **На ink:**
  ```ink
  # contact: oleg, Олег, red
  VAR oleg_heat = 0
  ты сказал ей про деньги? #from:oleg
  * [Нет. Как договаривались #to:oleg]
  * [Сказал. Она имеет право знать #to:oleg]
      ~ oleg_heat += 2
  * [А ты бы не сказал? #to:oleg]
      ~ oleg_heat += 1
  - {oleg_heat:
      - 0: ок #from:oleg #delay:20s
      - 1: я бы промолчал #from:oleg #delay:1m
      - else: ясно #from:oleg #delay:5m
  }
  -> next
  === next ===
  #delay:3h
  {oleg_heat >= 2:
      ключ от склада у меня. забудь про него #from:oleg
  - else:
      ключ под ковриком, как раньше #from:oleg
  }
  -> END
  ```
- **Цена:** одна переменная на персонажа и одна-две точки чтения на главу.
- **Ловушки:** пороги, которые на практике всегда проходятся одинаково. Проверь ботом распределение значений перед точкой чтения.
- **Источник:** наш приём. Опирается на `P-02` и `P-06`.

### PAT-07. Расписание персонажа
- **Когда применять:** когда нужно показать, что у персонажа своя жизнь (`P-03`), и при этом выдержать паузу. **Когда нет:** в сцене погони, где молчание читается как баг.
- **Схема:** персонаж объявляет окно («до восьми на смене») → `#delay` на это окно → по возвращении реагирует на то, что игрок писал в его отсутствие.
- **На ink:**
  ```ink
  # contact: zoya, Зоя, lime
  VAR asked = false
  я на смене до восьми #from:zoya
  не пиши, телефон в шкафчике
  * [Где стояла машина? #to:zoya]
      ~ asked = true
  * [Ок #to:zoya]
  - #delay:8h
  вышла #from:zoya
  {asked:
      видела про машину. я не игнорю, у нас правда шкафчики #delay:30s
  }
  она стояла у карьера всю ночь #delay:30s
  -> END
  ```
- **Цена:** одна реплика-объявление и одна условная реплика.
- **Ловушки:** пауза без объявленной причины выглядит как «игра зависла». Объявленное окно, которое потом не выдержано (написала через пять минут), ломает доверие к персонажу.
- **Источник:** развитие `P-03`. Знание модели, уверенность: средняя.

### PAT-08. Разговор с терпением (ограниченное диалоговое дерево)
- **Когда применять:** допрос или трудный разговор, где игрок хочет спросить всё сразу (`P-15`). **Когда нет:** с союзником, который сам рад рассказать: там ограничитель выглядит искусственно.
- **Схема:**
  ```
  хаб вопросов ─┬─ вопрос A ─┐
                ├─ вопрос B ─┼─> patience -= 1 ─> patience > 0 ? хаб : персонаж уходит
                └─ вопрос C ─┘
  мягкий вопрос даёт ответ, но стоит больше; «уйти» — всегда доступен (+)
  ```
- **На ink:**
  ```ink
  # contact: vera, Вера, purple
  VAR patience = 2
  VAR knew_key = false
  -> ask
  === ask ===
  {patience <= 0: -> gone}
  * [Кто ещё знал, где ключ? #to:vera]
      ~ patience -= 1
      ~ knew_key = true
      Брат знал. Доволен? #from:vera #delay:2m
      -> ask
  * [Почему вы не позвонили в полицию? #to:vera]
      ~ patience -= 2
      А вы бы позвонили? #from:vera #delay:5m
      -> ask
  * [Где вы были в ту ночь? #to:vera]
      ~ patience -= 1
      Дома. Одна. #from:vera #delay:1m
      -> ask
  + [Спасибо. Больше не держу #to:vera]
      -> gone
  === gone ===
  Всё. Мне на работу. #from:vera #delay:30s
  Вера не в сети #sys:vera
  -> END
  ```
- **Цена:** одна переменная на разговор и реплика ухода. Недоспрошенное надо где-то вернуть или сознательно потерять.
- **Ловушки:** терпения хватает на все вопросы — ограничитель мёртвый (проверь ботом долю прогонов, где выбраны все варианты). Персонаж уходит без названной причины — читается как баг.
- **Источник:** наш приём, развитие `P-15` и `P-03`. У Шелдона в такой форме нет.

# Второй проход

### PAT-09. Крючок → пауза с причиной → ответ на крючок
- **Когда применять:** перед каждой паузой ≥ 30m, особенно в конце главы. **Когда нет:** в сцене, где пауза сама по себе — событие (персонаж пропал без объяснений, и это тайна). Тогда тайна объявлена системной строкой.
- **Схема:**
  ```
  обещание/вопрос NPC → причина паузы в мире → (кнопка или #silent) → #delay ≥ 30m
  → первая реплика отвечает на обещание + одной строкой напоминает контекст
  → реакция на то, что игрок сделал или не сделал до паузы → кнопка не позже 3-го сообщения
  ```
- **На ink:**
  ```ink
  # contact: zoya, Зоя, lime
  VAR asked_key = false
  VAR silent = false
  я спрошу у неё про ключ #from:zoya
  после смены. до восьми телефон в шкафчике
  если она соврёт — я пойму
  * [Спроси, кто ещё брал #to:zoya]
      ~ asked_key = true
  * [Промолчать #to:zoya #silent]
      ~ silent = true
      ладно. сама #from:zoya #delay:1m
  - Зоя не в сети #sys:zoya #delay:10s
  - #delay:8h
  {asked_key:
      спросила и про «кто ещё». говорит — никто #from:zoya
  - else:
      спросила. говорит — не трогала #from:zoya
  }
  врёт. ключ висел не тем концом #delay:20s
  * [Откуда ты знаешь? #to:zoya]
  * [Что будешь делать? #to:zoya]
  - {silent:
      вчера от тебя ни слова. я решила сама #from:zoya #delay:1m
  }
  завтра скажу ей в лицо #from:zoya #delay:30s
  -> END
  ```
- **Цена:** одна условная строка на возврат и одна — на молчание.
- **Ловушки:** крючок, на который первая реплика после паузы не отвечает: игрок ждал зря (`P-08`). Пауза «до восьми», а персонаж пишет через пять минут. Напоминание контекста системной строкой, а не голосом персонажа.
- **Источник:** паузы по длительности действия и «уведомление просит ответа» — Lifeline (`LESSON-01`, `LESSON-02`); ответ на молчание — Oxenfree (`LESSON-09`); связь с обязательной сценой — наша.

## Нюансы к приёмам

| PAT | когда ломается | на 5 сообщениях | на 50 сообщениях |
|---|---|---|---|
| PAT-01 две оси | если варианты двигают оси одинаково, получается одна ось с двумя именами | не применять | одна-две развилки, где оси расходятся, и 2–3 чтения сочетания |
| PAT-02 подпись | подпись, которая стоит и в нейтральных репликах, перестаёт быть сигналом (`ch9_hook` в «Чужом голосе») | один раз: подпись пропала | 2–3 ступени: полная → инициалы → нет |
| PAT-03 модули | модули с одинаковыми находками; хаб в первой минуте | не применять | 2–3 модуля, порог `2 из 3`, недопрошенный откликается позже |
| PAT-04 срок | срок длиннее одной сессии без напоминаний: игрок забывает | срок «через минуту» в той же сцене | напоминание раз за главу, ответ во всех мирах |
| PAT-05 отклик | отклик раньше, чем через паузу, — не ощущается памятью | отклик в последнем сообщении | отклик через ≥ 1 длинную паузу или главу |
| PAT-06 тон | ступени, которые бот проходит почти всегда одинаково | одна ступень | 2–3 ступени, распределение проверено ботом |
| PAT-07 расписание | окно длиннее реальной сессии игрока без крючка — игрок не вернётся (`PAT-09`) | «напишу через минуту» | смены и сон, у каждого окна крючок |
| PAT-08 терпение | терпения хватает на все вопросы; уход без причины | 2 вопроса, ответ на один | терпение в каждом допросе, недоспрошенное возвращается |
| PAT-09 крючок | ответ на крючок пришёл, но не по теме крючка | не нужен (нет длинных пауз) | перед каждой паузой ≥ 30m |
