# Чек-листы — Cron, Wired for Story

Процедуры построены на идеях Крон (ссылки на `P-`/`PAT-`), порядок шагов и пороги — наш вывод. Каждый шаг даёт проверяемый результат.

## 1. Придумать и начать историю

- [ ] Записать одну фразу «о чём история» в виде «X хочет Y, но верит Z». **Результат:** строка, где есть NPC, цель и убеждение (P-06). Если строка не пишется, сюжета ещё нет: есть только события.
- [ ] Записать главный вопрос истории комментарием `// вопрос: …`. **Результат:** один вопрос, который игрок задаст себе на первом экране и на который ответит каждый финал (P-17).
- [ ] Найти событие из прошлого NPC, которое породило убеждение Z. **Результат:** одно конкретное событие с годом или местом. Его выдадут по частям (P-13, PAT-07).
- [ ] Записать, чего хочет «ты», своё, не NPC. **Результат:** одна строка личной ставки (P-07).
- [ ] Назвать противника и срок с ценой провала. **Результат:** «к <время> или <что случится>» (P-08). Нет внешнего срока — записать «срока нет, давление — <что>».
- [ ] Придумать несоответствие для первого экрана. **Результат:** одна деталь, после которой игрок спросит «почему?» (P-02).
- [ ] Набросать первый экран по PAT-01. **Результат:** 4–8 входящих до первой кнопки. Три ответа подчёркнуты, срок стоит на стволе.
- [ ] Завести переменную-ось и решить, какие финалы её читают. **Результат:** `VAR <npc>_<ось> = 0` и черновой список финалов с порогами (PAT-04, P-16).
- [ ] Сверить карточку истории (`synopsis`, `tagline`) с первым экраном. **Результат:** цифры и сроки совпадают (см. разбор в `for-relayer.md` §4).

## 2. Написать главу или сцену

- [ ] Записать, какое следствие прошлой главы её запускает. **Результат:** первая реплика ссылается на итог прошлой главы (PAT-03).
- [ ] Записать, как глава давит на убеждение NPC. **Результат:** одна сцена с кнопками +1/−1 по оси (PAT-04).
- [ ] Наметить ухудшение: что делает «ты» самым лёгким способом и чем это обходится. **Результат:** переменная-цена или закрытый контакт (P-12, PAT-06).
- [ ] Для каждого нового факта решить, где он выстрелит. **Результат:** факт → `note_*` или переменная → условие в этой или следующей главе (P-10, PAT-05).
- [ ] Заменить абстракции конкретикой. **Результат:** в каждой цепочке из трёх входящих есть цифра, имя, предмет или `#photo` (P-11).
- [ ] После каждой новости поставить реакцию. **Результат:** 1–3 сообщения о том, что это значит для говорящего (P-05).
- [ ] Закончить главу открытым вопросом и новым фактом. **Результат:** последний блок перед паузой от 1h содержит вопрос, который игрок унесёт (P-03).
- [ ] Прогнать каждую кнопку через «And so?». **Результат:** у каждого варианта отмечено, что он меняет: ветку, переменную или ответ, который запомнят. Пустые заменены на `#me:` или получили последствие (P-04).

## 3. Ревью готового сценария

- [ ] Прочитать первый экран. **Результат:** три ответа и одно несоответствие найдены или записаны как RED-01/RED-02.
- [ ] Найти строку срока и проверить, на стволе ли она. **Результат:** имя узла, где стоит срок, и вывод «ствол» или «ветка» (RED-03).
- [ ] Выписать по одной строке «что изменилось» для каждого узла главы 1 и последней главы. **Результат:** список, где пустые строки помечены RED-05.
- [ ] Выписать все `note_*` и прочие флаги, найти, где они читаются. **Результат:** таблица «подводка → выстрел». Строки без выстрела — RED-07.
- [ ] Найти переменную-ось и узел выбора финала. **Результат:** условие финала читает ось, или запись RED-08.
- [ ] Прочитать первые три реплики каждой главы. **Результат:** каждая отсылает к прошлой главе, или RED-10.
- [ ] Пройтись по паузам от 10m. **Результат:** для каждой записан вопрос, с которым игрок ждёт, или RED-04.
- [ ] Для каждой главы записать, что она добавляет к ответу на главный вопрос, и проверить, что каждый финал на него отвечает. **Результат:** строка на главу; пустая глава или финал без ответа — RED-16 (P-17).
- [ ] Для каждой главы назвать одно «всё не то, чем кажется». **Результат:** список несоответствий по главам. Глава без него — кандидат на скуку.
- [ ] Свести находки в отчёт: ID флага, узел, предложенная правка. **Результат:** список правок с именами узлов ink.

## 4. Тестировать

- [ ] `npm run check:story`. **Результат:** нет тупиков. Каждый финал выпадает хотя бы в 1% прогонов.
- [ ] Посчитать долю прохождений, где показан срок и главное противоречие главы 1 (A2). **Результат:** ≥ 90%, иначе RED-03 или нужна страховка (PAT-02).
- [ ] `npm run graph`, открыть карту и найти узлы с долей прохождений < 5%, в которых стоит важная подводка. **Результат:** список подводок, которые видит почти никто (RED-14).
- [ ] Пройти первый экран с `?fresh=1` без ускорения. **Результат:** время до первой кнопки ≤ 90 с реального времени (наш порог) и записанный ответ на три вопроса после него.
- [ ] Дать прочитать первый экран человеку, который не знает историю, и попросить пересказать одной фразой и задать один вопрос. **Результат:** пересказ совпадает с фразой «X хочет Y», а вопрос — с задуманным несоответствием. Не совпало — правим PAT-01.
- [ ] Пройти одну и ту же главу дважды, выбирая противоположные варианты. **Результат:** список мест, где ответы NPC совпали слово в слово (кандидаты в RED-05).

## 5. Второй проход: добавочные шаги

- [ ] Перед первой строкой ink длинной истории записать три строки: чего хочет главный NPC, во что он верит и что ему мешает, какое событие прошлого это убеждение создало (`principles.md` S-2). **Результат:** три строки в комментарии ink. Для истории на 5 минут — только первые две.
- [ ] Каждый узел, где NPC чего-то хочет, проверить по схеме `PAT-09`. **Результат:** у узла есть план на входе и сдвиг (переменная или ветка) на выходе.
- [ ] Прочитать первые 2 входящих. **Результат:** понятно, кто пишет и откуда знает «тебя» (A11, RED-17).
- [ ] Выписать все загадки, открытые после главы 1. **Результат:** каждая привязана к `// вопрос:` или закрыта до последней главы (RED-19).
- [ ] Открыть каждый финал. **Результат:** есть хотя бы одна условная реплика о конкретном решении игрока (A12, RED-20).
