# Чек-листы — по inkle

Источники [S1]–[S10] — в `principles.md`. Каждый шаг: действие → ожидаемый результат. Ссылки на P/PAT/RED — откуда шаг взялся.

## 1. Придумать и начать историю

- [ ] **Выбрать одну метрику тона.** В 80 Days это была гонка вокруг света любым путём: по ней решали спорные вопросы дизайна [S2]. → Одна строка вида «каждая сцена приближает или отдаляет X», записанная в начале файла комментарием `//`.
- [ ] **Решить, что в истории идёт в любом порядке, а что строго.** → Список: какие контакты открыты в хабе, какие по сюжету. Свободный порядок закладывается сразу (P-16).
- [ ] **Выписать 3–6 состояний, которые будут копиться.** В 80 Days хватило трёх характеристик и трёх черт на сотню городов [S2]. → `VAR` в шапке; у каждой переменной в комментарии указан узел, где её прочтут.
- [ ] **Выписать цепочки знаний.** → `LIST` с фактами в порядке узнавания (PAT-04). Для каждого факта — кто и в какой главе его говорит.
- [ ] **Поставить главный факт завязки на все пути первой главы.** → В первых 15 сообщениях любого прохождения есть ставка: что случилось и почему пишут именно игроку («Почему начало не цепляет» в flags.md).
- [ ] **Сделать первую развилку со своими ответами.** → У всех вариантов первой развилки своя реплика до сборки (PAT-01). Хотя бы один из трёх первых выборов меняет текст в ближайших 5 сообщениях.
- [ ] **Дать игроку отказаться в начале.** → Вариант-отказ встречен нажимом с новым фактом, отказ записан в переменную (PAT-05).

## 2. Написать главу или сцену

- [ ] **Написать сцену сначала как переписку, без веток.** → Текст сверху вниз, один узел. Weave позволяет вставить выборы потом, не перестраивая переходы (P-10).
- [ ] **Вставить кнопки так, чтобы между ними было ≤ 12 входящих.** → Скрипт RED-01 по узлу молчит (P-01, PAT-02).
- [ ] **Дописать каждой кнопке свой ответ.** → Нет вариантов, которые сразу упираются в `-` (P-02).
- [ ] **Проверить адресата ответа.** → После `#to:X` первая строка — `#from:X` или `#sys:X` (P-03).
- [ ] **Последнюю реплику перед кнопками сделать вопросом или фактом.** → Кнопки читаются без предыдущих сообщений, непонятные — с `#label:` (P-08).
- [ ] **Каждому `#silent` дать цену.** → Пауза ≥ 5 минут и реакция или `~` (P-07, PAT-07).
- [ ] **Для узла с несколькими входами написать защитный вход.** → Блок `{ - … - else: }` по тому, что игрок мог узнать по дороге (PAT-03).
- [ ] **Найти повторяющиеся реплики.** → Каждая строка, которую можно увидеть дважды, через `{ stopping: … }` или условие (P-11).
- [ ] **Найти копии одинаковых кнопок.** → Копии заменены потоком или туннелем (PAT-08, RED-11).
- [ ] **Поставить хотя бы одну условную кнопку.** → Начиная со второй главы в каждой главе есть `* {x}`, которую видит только часть игроков (P-09, PAT-10).

## 3. Ревью готового сценария

- [ ] **Прочитать только кнопки главы подряд.** → Понятно, что происходит. Если нет, кнопкам нужен `#label:` или вопрос перед развилкой (P-08).
- [ ] **Прогнать подсчёт «сообщений без кнопки» по узлам.** → Список узлов > 12; для каждого вне финала план вставки (RED-01).
- [ ] **Посчитать долю пустых кнопок и пустых `#silent` по главам.** → Главы выше порогов (20 % и 1/3) помечены как «скучно» (RED-02, RED-03).
- [ ] **Для каждого узла с 2+ входами проверить, кого игрок мог знать.** → Нет реплик «мы не знакомы» после знакомства (RED-04).
- [ ] **Для каждой кнопки-улики проверить условие.** → Каждая кнопка, которая называет факт, имеет условие на его запись (RED-05).
- [ ] **Сверить записи и чтения переменных.** → Нет переменных без чтений (RED-06). Каждая переменная финала звучит в реплике или условии кнопки до последней главы (P-06).
- [ ] **Проверить кульминации.** → Узел, давший главе название, проходят ≥ 50 % прогонов бота (RED-10).
- [ ] **Проверить отказы.** → Каждый вариант «нет / не буду» ведёт к новой реплике и пишет переменную (RED-08).

## 4. Тестировать

- [ ] **`npm run check:story`.** → Тупиков 0, все узлы посещены, каждый финал ≥ 5 % прогонов. Если один финал > 50 %, проверить, не ведёт ли к нему `#silent` (так в «Чужом голосе»: `fin_revenge`).
- [ ] **`npm run graph`, посмотреть долю прохождений через узлы.** → Узлы кульминаций ≥ 50 %, побочные ≥ 20 %, иначе их никто не увидит.
- [ ] **Два человеческих прохождения с разными первыми выборами, в режиме `?fast=1`.** → Отчёт: где было скучно (листал), где непонятно (перечитывал), где игра «не заметила» поступок. Бот этого не ловит (P-15).
- [ ] **Одно прохождение «молчуна»: на каждой развилке `#silent`, если есть.** → История доходит до конца, молчание каждый раз получает реакцию, нет двух одинаковых напоминаний подряд.
- [ ] **Одно прохождение «отказника»: всегда отказ или грубость.** → Нажим каждый раз новый, финал помнит отказы.
- [ ] **Сохранить журнал ходов каждого человеческого прохождения.** → К отчёту приложен путь (узел + кнопка), по нему воспроизводится баг. В 80 Days именно это сделало отзывы после выхода полезными [S2].
