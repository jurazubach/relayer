# Паттерны — inkle: weave, защитная логика, учёт знаний

Источники [S1]–[S10] — список со ссылками в `principles.md`. Все примеры ink компилируются inkjs (проверено на ревью). Теги — только из `docs/capabilities.json`. Сюжеты примеров свои: подъезд, пустая квартира 43, машина во дворе. Исключения — PAT-08 и PAT-09: они показывают приём на персонажах «Чужого голоса», но реплики в них новые.

---

### PAT-01. Выбор со своим ответом и сборкой (weave: choices and gathers, плетение: выборы и сборки)
- **Когда применять:** основной разговор сцены, где ответы игрока окрашивают реплику, но не меняют сюжет. **Когда нет:** если ветка живёт дольше 3–4 реплик или в неё придут из других мест — выноси в узел.
- **Схема:**
  ```
  реплика → * A → свой ответ A ┐
            * B → свой ответ B ├→ - сборка → дальше
            * C → свой ответ C ┘
  ```
  Метка на варианте (`* (asked_plate)`) — это счётчик: позже в той же сцене можно спросить, выбирал ли его игрок, без отдельной переменной.
- **На ink:**
```ink
# contact: nika, Ника, teal
VAR nika_trust = 0
ты видел сообщение в чате подъезда? #from:nika
* [Какое? #to:nika]
    про машину во дворе #from:nika #delay:20s
* [Видел. Чья она? #to:nika]
    ~ nika_trust += 1
    никто не знает #from:nika #delay:20s
* [Мне некогда #to:nika]
    ~ nika_trust -= 1
    ок #from:nika #delay:40s
- стоит третий день #from:nika #delay:10s
двигатель тёплый по утрам
* [Значит, кто-то в ней ночует #to:nika]
    или прогревает #from:nika #delay:20s
* (asked_plate) [Номер посмотрела? #to:nika]
    посмотрела. не наш регион #from:nika #delay:30s
- {asked_plate:запишу номер тебе в заметки|ладно. посмотрю, что дальше} #from:nika #delay:15s
{nika_trust < 0:если тебе неинтересно, так и скажи}
-> END
```
- **Цена:** 1–2 строки на вариант. Объём растёт линейно, не удваивается.
- **Ловушки:** вариант без своей строки до `-` — пустая кнопка (P-02). Метка варианта видна только внутри узла; из другого узла пиши `узел.метка`, иначе ошибка компиляции `Unresolved variable`.
- **Источник:** [S5] (Part 2: gathers, labelled options), [S10].

### PAT-02. Вставка выбора в монолог (breaking up text, разбивка текста)
- **Когда применять:** персонаж должен рассказать предысторию на 10+ сообщений. **Когда нет:** в финальной сцене-развязке, где игрок уже всё решил.
- **Схема:** монолог режется на куски по 4–6 сообщений. Между ними — 2 варианта: уточняющий вопрос и реакция (или `#silent`). Обе ветки сходятся в следующий кусок. Порядок фактов не меняется.
- **На ink:**
```ink
# contact: lev, Лев, indigo
у нас в подъезде пропал курьер #from:lev
то есть не пропал. заказ принёс, а вниз не спустился #delay:10s
* [В смысле не спустился? #to:lev]
    лифт ушёл на девятый пустой #from:lev #delay:20s
* [Может, по лестнице? #to:lev]
    лестница на камере. там никого #from:lev #delay:20s
- консьержка говорит, он спрашивал про 43-ю #from:lev #delay:15s
* [А кто в 43-й? #to:lev]
    вот. никто. она пустая с весны #from:lev #delay:30s
* [Промолчать #to:lev #silent]
    ты тут? #from:lev #delay:2m
    в 43-й никто не живёт с весны
- и у меня сейчас свет в глазке погас #from:lev #delay:20s
-> END
```
- **Цена:** +2–4 строки на вставку, логика не меняется. Документация ink называет это главным удобством weave: выбор вставляется посреди фразы без перестройки переходов.
- **Ловушки:** вопрос в кнопке не должен опережать факт: если игрок спрашивает «кто в 43-й?» до того, как о ней сказали, это ошибка порядка. Ответ на вопрос — новая деталь, а не повтор следующей реплики.
- **Источник:** [S5] (the weave philosophy), [S1] (частота выбора).

### PAT-03. Защитный вход в сцену (defensive logic, защитная логика)
- **Когда применять:** в узел ведут несколько путей, и персонаж может знать или не знать игрока. **Когда нет:** узел, в который ведёт ровно одно ребро.
- **Схема:**
  ```
  вход → { - самое узкое условие: вариант 1
           - условие:            вариант 2
           - else:               вариант по умолчанию }  → общий хвост
  ```
  Ветки идут от самого конкретного состояния к общему. `else` обязателен.
- **На ink:**
```ink
# contact: ira, Ира, amber
VAR saw_photo = false
VAR asked_lev = false
-> courtyard
=== courtyard ===
Ира пишет снова #sys:ira
{
- saw_photo:
    -> ira_photo
- asked_lev:
    -> ira_lev
- else:
    -> ira_cold
}
= ira_photo
ты видел фото. значит, видел и номер #from:ira
-> after
= ira_lev
лев тебе написал. он всегда пишет первым #from:ira
-> after
= ira_cold
привет. мы не знакомы, я из 41-й #from:ira
-> after
= after
* [Что тебе нужно? #to:ira]
    поговорить, пока он не вернулся #from:ira #delay:30s
- -> END
```
- **Цена:** одна-две строки на каждое состояние входа. Хвост сцены общий.
- **Ловушки:** проверяй не только переменные, но и счётчики посещений (`{ch1_owen: …}`): ink считает их сам. Если вариантов входа больше трёх, это признак, что сцену надо делить. В документации ink есть та же форма для «сделай то, что сейчас уместно» — список условий по приоритету.
- **Источник:** [S6] (defensive logic, по аннотации), [S5] (Part 3, context-relevant content). Запись приёма — наша.

### PAT-04. Цепочка знаний на LIST (incremental knowledge, накопительное знание)
- **Когда применять:** расследование, где факты открываются по порядку и кнопки зависят от того, что игрок уже знает. **Когда нет:** если фактов два-три и они независимы — хватит `VAR`-флагов.
- **Схема:**
  ```
  LIST Car = seen_car < warm_engine < plate_known < owner_known
  learn(plate_known)  → know = {seen_car, warm_engine, plate_known}
  between(a, b)       → знает a, но ещё не b
  ```
- **На ink:**
```ink
# contact: nika, Ника, teal
LIST Car = seen_car, warm_engine, plate_known, owner_known
VAR know = ()
-> scene
=== function learn(x)
// факт тянет за собой все предыдущие: номер не узнать, не увидев машину
~ know += LIST_RANGE(LIST_ALL(Car), LIST_MIN(LIST_ALL(Car)), x)
=== function knows(x)
~ return know ? x
=== function between(x, y)
~ return know ? x && not (know ? y)
=== scene ===
~ learn(plate_known)
{ between(plate_known, owner_known):
    номер есть, а чей — не знаем #from:nika
}
* {knows(plate_known)} [Пробей номер #to:nika]
    ~ learn(owner_known)
    пробила. владелец — наш управдом #from:nika #delay:2m
* [Ничего не делай #to:nika #silent]
    как хочешь. номер я записала #from:nika #delay:10m
- -> END
```
- **Цена:** три функции один раз на историю, потом одна строка на факт. Заменяет россыпь флагов вида `note_*`.
- **Ловушки:** порядок в `LIST` — это порядок знания. Если факты можно узнать в любом порядке, это не цепочка: делай отдельный LIST без `LIST_RANGE`. Панель отладки relayer показывает переменные; проверь, что LIST в ней читается.
- **Источник:** [S5] (Part 5: «Example: basic knowledge tracking» и «Long example: crime scene», функции `reached` / `between` / `reach`). `learn` через `LIST_RANGE` — наша упрощённая версия их `reach`; их `between` проверяет пересечение `^` с набором, наша — одно значение `?`.

### PAT-05. Отказ с нажимом (coerce, подталкивание)
- **Когда применять:** сюжету нужно, чтобы игрок согласился, но отказ должен быть настоящим ходом. **Когда нет:** если отказ может вести в полноценную другую ветку — дай её.
- **Схема:**
  ```
  предложение → да ───────────────────────┐
              → нет → нажим с новым фактом → да ─┤
                                         → нет → история идёт без согласия (refused = 2)
                                                  └→ общий узел, который помнит отказ
  ```
- **На ink:**
```ink
# contact: ira, Ира, amber
VAR refused = 0
нужна помощь. одно сообщение от тебя #from:ira
* [Ок, что написать? #to:ira]
    -> go
* [Я не лезу в чужое #to:ira]
    ~ refused += 1
    это не чужое #from:ira #delay:40s
    он спрашивал про тебя. по имени
    ** [Ладно. Что написать? #to:ira]
        -> go
    ** [Всё равно нет #to:ira]
        ~ refused += 1
        тогда напишу сама. с твоего имени #from:ira #delay:20m
        -> go
=== go ===
{refused >= 2:ты сам отказался. я сделала как смогла #from:ira}
{refused < 2:напиши ему: «я видел машину» #from:ira}
-> END
```
- **Цена:** одна вложенная развилка и счётчик.
- **Ловушки:** нажим, который повторяет просьбу, — это фальшивый выбор. Каждый такт нажима даёт новую ставку. Счётчик отказа читается дальше, иначе отказ ничего не стоил: так сейчас в `ch1_refuse` «Чужого голоса» — нажим есть, записи нет (см. for-relayer, раздел 4).
- **Источник:** [S7] (pace and coerce, только формулировка аннотации). Схема — наша; что inkle показывали в докладе, не проверено.

### PAT-06. Хаб тем с одноразовыми вопросами, выходом и запасным выбором (fallback choice, запасной выбор)
- **Когда применять:** допрос, сбор сведений, «написать кому-то из списка». **Когда нет:** если порядок вопросов важен для сюжета.
- **Схема:**
  ```
  hub ─* вопрос 1 → ответ → hub
      ─* вопрос 2 → ответ → hub
      ─* вопрос 3 → ответ → hub
      ─+ {спросил ≥ 2} выход → after
      ─* -> after   (невидимый: если кнопки кончились)
  ```
- **На ink:**
```ink
# contact: lev, Лев, indigo
VAR asked = 0
-> hub
=== hub ===
* (where) [Где ты был ночью? #to:lev]
    ~ asked += 1
    дома. как обычно #from:lev #delay:30s
    -> hub
* (who) [Кто ещё знает про 43-ю? #to:lev]
    ~ asked += 1
    консьержка. и ты #from:lev #delay:30s
    -> hub
* (key) [У кого ключ? #to:lev]
    ~ asked += 1
    у управдома. и, похоже, не только #from:lev #delay:40s
    -> hub
+ {asked >= 2} [Хватит. Я понял #to:lev #silent]
    -> after
* -> after
=== after ===
{hub.key:ключ — это важно. запомни #from:lev}
ладно, мне пора #from:lev #delay:10s
-> END
```
- **Цена:** по 2–3 строки на тему. Защищает от тупика: когда одноразовые варианты кончились, запасной выбор уводит дальше сам.
- **Ловушки:** петля только из `*` без запасного выбора и без `+` кончается ошибкой «закончился контент». Выход, доступный сразу, позволяет пропустить весь хаб — поставь условие на число вопросов. Запасной выбор не показывается игроку, поэтому без строки-перехода после хаба пропадёт ощущение, что разговор кончился.
- **Источник:** [S5] (Part 1: fallback choices, sticky choices; там же пример одноузловой мини-игры на одноразовых вариантах с запасным выбором).

### PAT-07. Напоминание при молчании, которое не повторяется
- **Когда применять:** игрок может молчать несколько раз подряд, а собеседник ждёт. **Когда нет:** если молчание должно сразу менять сюжет.
- **Схема:** `+ Тут` / `+ Промолчать` → реплика из последовательности (каждый раз новая, паузы растут) → после N раз сцена уходит дальше без игрока.
- **На ink:**
```ink
# contact: ira, Ира, amber
VAR nudges = 0
-> wait
=== wait ===
+ [Тут #to:ira]
    {nudges > 0:наконец|ну вот} #from:ira #delay:10s
    -> END
+ [Промолчать #to:ira #silent]
    ~ nudges += 1
    { stopping:
    - ау? #from:ira #delay:5m
    - ты пропал #from:ira #delay:20m
    - ладно. утром напишу #from:ira #delay:1h
    }
    {nudges < 3: -> wait}
    -> morning
=== morning ===
доброе утро. ты так и не ответил #from:ira #delay:7h
-> END
```
- **Цена:** 4–5 строк. Паузы `5m → 20m → 1h → 7h` сами создают ощущение, что собеседник сдаётся.
- **Ловушки:** варианты здесь липкие (`+`): с `*` «Промолчать» исчезнет после первого раза. Однострочная последовательность без ключевого слова ломается, если первый вариант кончается на `?`: `{ау?|ты пропал}` компилятор читает как выражение с оператором `?` (проверка вхождения в LIST) и падает. Пиши с ключевым словом — `{stopping: ау?|ты пропал}` — или многострочным блоком, как здесь. Счётчик нужен явный (`nudges`), потому что условие выхода считает именно молчания, а не все визиты в `wait`.
- **Источник:** [S5] (Part 1: Variable Text, sequences), [S9] (замена повторов).

### PAT-08. Общий вариант через поток (threads, потоки `<-`)
- **Когда применять:** одну и ту же кнопку («Сохранить в заметки», «Переслать Джудит») нужно предлагать в многих сценах. **Когда нет:** если кнопка нужна в двух местах — проще написать дважды.
- **Схема:** `<- save_note(текст, факт, -> куда_дальше)` добавляет вариант к развилке сцены. Вариант липкий, но скрывается по условию, если факт уже записан.
- **На ink:**
```ink
# contact: jess, Джесс, pink
# contact: notes, Заметки, green
LIST Notes = fight, wet_shoes
VAR saved = ()
-> talk
=== talk ===
лили и элли весь вечер ругались #from:jess
<- save_note("Лили и Элли ругались весь вечер", fight, -> after)
* [Из-за чего? #to:jess]
    не знаю #from:jess #delay:20s
    -> after
* [Спасибо #to:jess]
    -> after
=== after ===
а потом элли вернулась мокрая #from:jess #delay:30s
<- save_note("Элли вернулась мокрая", wet_shoes, -> done)
* [Понятно #to:jess]
    -> done
=== save_note(what, fact, -> back) ===
+ {saved !? fact} [{what} #to:notes #label:Сохранить в заметки]
    ~ saved += fact
    -> back
=== done ===
{ saved ? fight:
    в заметках: ругались весь вечер #from:notes
}
-> END
```
- **Цена:** один узел-поток на историю. Убирает копии вроде `ch6_story` / `ch6_story_note` в «Чужом голосе», где кнопка заметки написана дважды.
- **Ловушки:** с `*` в потоке вариант сгорает один раз на всю историю, а не на сцену, поэтому `+` и условие по LIST. Парсер карты (`scripts/story-graph.mjs`) разбирает переходы и туннели, а `<-` в нём не встречается: проверь, что карта показывает вариант, прежде чем полагаться на неё.
- **Источник:** [S5] (Part 4: Threads, «adding the same choice to several places»).

### PAT-09. Видимая память: запись в заметки и кнопка-цитата
- **Когда применять:** у игрока должно быть ощущение, что игра помнит, а карты и характеристик нет. **Когда нет:** для мелочей тона — там хватит реплики собеседника.
- **Схема:** факт → кнопка `#to:notes` пишет флаг и `#sys:notes` подтверждает → позже условная кнопка цитирует запись дословно.
- **На ink:**
```ink
# contact: ellie, Элли, amber
# contact: notes, Заметки, green
VAR note_time = false
VAR ellie_trust = 0
я ушла в половине двенадцатого #from:ellie
* [Элли: ушла в 23:30 #to:notes #label:Сохранить в заметки]
    ~ note_time = true
    Сохранено в заметки #sys:notes
* [Ок #to:ellie]
- #delay:2h
коннор говорит, вы с лили пошли к воде в 00:30 #from:ellie
* {note_time} [У меня записано твоё «ушла в 23:30». Это неправда? #to:ellie]
    ~ ellie_trust -= 1
    ты записываешь за мной? #from:ellie #delay:1m
* [Коннор мог перепутать #to:ellie]
    ~ ellie_trust += 1
    мог #from:ellie #delay:30s
- -> END
```
- **Цена:** одна кнопка и одна условная кнопка на факт.
- **Ловушки:** запись, которую нигде не цитируют, — обещание без исполнения. Цитата должна совпадать с текстом заметки: игрок проверит, пролистав чат «Заметки».
- **Источник:** [S1] (карта как доказательство, что выбор учтён), [S8]. Перенос на чат заметок — наш, приём уже есть в «Чужом голосе».

### PAT-10. Награда за побочный чат — новая кнопка в кульминации
- **Когда применять:** есть необязательный контакт, и надо, чтобы игроки к нему ходили. **Когда нет:** если без этой кнопки кульминация не работает — тогда контакт не побочный.
- **Схема:**
  ```
  побочный чат (можно пропустить) → ~ heard = true
  …
  кульминация → * {heard} [ход, которого иначе нет]
             → * обычные варианты
  ```
- **На ink:**
```ink
# contact: lev, Лев, indigo
# contact: baba, Валентина Петровна, purple
VAR heard_tapping = false
-> optional
=== optional ===
* [Написать Валентине Петровне с девятого #to:baba #label:Спросить соседку сверху]
    кто это? #from:baba #delay:1h
    а. из 41-й. по ночам в 43-й стучат. по батарее #delay:30s
    ~ heard_tapping = true
* [Не отвлекаться #to:lev #silent]
- -> climax
=== climax ===
он говорит, в 43-й пусто, и я ему поверил #from:lev #delay:30s
* {heard_tapping} [Там стучат по ночам. Соседка слышала #to:lev #label:Сказать про стук]
    тогда я поднимаюсь #from:lev #delay:20s
* [Поверь и иди домой #to:lev]
    иду #from:lev #delay:20s
* [Промолчать #to:lev #silent]
    ладно. сам разберусь #from:lev #delay:15m
- -> END
```
- **Цена:** одна переменная и одна условная кнопка.
- **Ловушки:** новая кнопка должна давать другой исход, а не ту же реплику другими словами. Кнопка с ограниченной информацией видна не всем: проверь ботом, что её показывают хотя бы 20 % прохождений.
- **Источник:** [S2] (награда маршрутами за необязательный контент в 80 Days).

## Идиомы ink, которые стоит брать в истории и генератор

| идиома | синтаксис | зачем в relayer | источник |
|---|---|---|---|
| сборка | `- ` | свести варианты сразу после ответа | [S5] Part 2 |
| метка варианта или сборки | `* (x) [...]`, `- (x)` | проверка «выбирал ли», без `VAR` | [S5] Part 2 |
| счётчик посещений | `{knot}`, `{knot > 1}` | защитный вход, вариации повтора | [S5] Part 1 |
| запасной выбор | `* -> after` | хаб без тупика | [S5] Part 1 |
| липкий вариант | `+ [...]` | петли ожидания, хабы | [S5] Part 1 |
| последовательность | `{ stopping: - … - … }` | неповторяющиеся напоминания | [S5] Part 1 |
| условный блок по приоритету | `{ - a: … - b: … - else: … }` | защитный вход, выбор финала | [S5] Part 3 |
| LIST как набор флагов | `LIST F = a, b`, `F ? a` | улики, знания | [S5] Part 5 |
| поток | `<- knot(...)` | общий вариант в многих сценах | [S5] Part 4 |
| туннель | `-> knot ->` / `->->` | общий кусок с возвратом (`fin_coda`) | [S5] Part 4 |
| `TURNS_SINCE(-> x)` | число ходов игрока с последнего визита | «давно не писал»: ход — это нажатая кнопка, не минуты | [S5] Part 1 |

`TURNS_SINCE` считает ходы, а не реальное время. В relayer это разные вещи: между двумя ходами могут пройти часы. Для «прошло много времени» нужна своя переменная, ink о паузах не знает.

## Второй проход: системы inkle по устройству

Источники `[L…]` — в `lessons.md`. Пять систем: две из языка ink (SYS-1, SYS-2), три из производства игр inkle (SYS-3…SYS-5). Каждая разобрана как механизм: элементы, шаги с входом и выходом, что будет без шага, где её понимают неправильно, как ужать до короткой формы.

### SYS-1. Weave (плетение): выборы, сборки, метки, уровни вложенности
- **Элементы:** вариант `*` (одноразовый) или `+` (липкий) — ход игрока; текст в `[…]` — сама кнопка; строки под вариантом — ответ; сборка `-` — точка, где ветки сходятся; метка `(x)` на варианте или сборке — счётчик «был ли здесь»; уровень (`**`, `- -`) — вложенная развилка внутри ветки. Поток всегда идёт вниз, назад вернуться нельзя без явного `->`.
- **Шаги:**
  1. Написать сцену как линейную переписку. *Вход:* план сцены. *Выход:* 15–40 строк без кнопок.
  2. Найти места, где игрок может ответить. *Вход:* линейный текст. *Выход:* 1 развилка на 5–8 входящих (P-01).
  3. Вставить варианты и сборку. *Вход:* место развилки. *Выход:* `*`-варианты, каждому — своя строка (P-02), затем `-` и продолжение исходного текста.
  4. Пометить варианты, которые прочитают позже. *Вход:* варианты с последствием. *Выход:* `* (label)` и чтение `{label}` ниже по сцене.
  5. Вынести в узел только ветку длиннее 3–4 реплик или с несколькими входами (P-10).
- **Если пропустить:** без шага 1 автор пишет граф, а не разговор, и ветки расходятся без нужды. Без шага 3 (своя строка) — пустые кнопки, RED-02. Без шага 4 выбор забыт сразу после сборки, отсюда «126 кнопок, которые только меняют реплику» в `chuzhoy-golos`.
- **Ошибки понимания:** «weave = линейно = плохо». Нет: weave дешёвый носитель голоса игрока, расхождение ему дают метки и переменные [S5]. Вторая ошибка — думать, что сборка обнуляет выбор: метка переживает сборку и читается в той же сцене (`{asked_plate:…}`), а из другого узла — как `узел.метка`.
- **Короткая форма:** вся история на 5 минут — один узел, 3–4 сборки, 1–2 метки, которые читает последняя реплика. Узлы не нужны вовсе.
- **Источник:** [S5] (Part 2), [S10].

### SYS-2. Защитная логика (defensive logic): две проверки на входе
- **Элементы:** «нужные состояния» — без чего реплика бессмысленна; «лишние состояния» — что делает её уже ненужной; приоритет — порядок проверки, от самого конкретного к общему; `else` — версия по умолчанию. Деление на нужное и лишнее — из Heaven's Vault [L3]; у Sorcery! известна только формулировка аннотации [S6].
- **Шаги:**
  1. Перечислить входы в узел. *Вход:* карта (`npm run graph`). *Выход:* список рёбер-входов.
  2. Для каждого входа выписать, что игрок мог узнать и кому писал. *Вход:* пути. *Выход:* различающиеся флаги, контакты, счётчики посещений.
  3. Нужные состояния: какие реплики узла без них врут. *Выход:* условие на каждую такую реплику.
  4. Лишние состояния: какие реплики узла уже сказаны или сделаны в другом месте. *Выход:* условие `not x` на каждую.
  5. Упорядочить: свежий и узкий случай выше. *Выход:* блок `{ - … - … - else: }`.
- **Если пропустить:** без шага 3 — «мы не знакомы» после знакомства (RED-04). Без шага 4 — персонаж спрашивает то, на что уже ответили в другом чате; формально верно, но звучит как бот (проблема Heaven's Vault до переделки [L3]). Без шага 5 — общий случай перехватывает частный, и защитная ветка не срабатывает никогда.
- **Ошибки понимания:** «защитная логика = много веток». Нет: это одна-две условные строки на вход, хвост общий. Вторая ошибка — проверять только переменные, забывая счётчики посещений узлов: ink считает их сам.
- **Короткая форма:** одна реплика `{знает: …|…}` в узле, где сходятся два пути. Лишнее проверять только для вопросов собеседника.
- **Источник:** [S6], [L3], [S5] (Part 3).

### SYS-3. Хребет и заплатки (core spine and patches)
- **Элементы:** хребет — версия сцены, когда игрок ничего не сделал; шаг хребта с проверкой «подходит ли он состоянию» (если нет — пропуск); заплатка — самостоятельный кусок, который сам решает, уместен ли он, и не срабатывает дважды; место вставки — точка в хребте, где заплатка может сработать [L1].
- **Шаги:**
  1. Написать хребет при начальных значениях всех переменных. *Выход:* сцена проходит от начала до конца без единой заплатки.
  2. К каждому шагу хребта дописать условие пропуска. *Выход:* шаг, который врёт при каком-то состоянии, скрыт.
  3. На каждое последствие игрока написать заплатку-туннель (`-> p_x ->` с условием и проверкой `not p_x`). *Выход:* по туннелю на последствие.
  4. Расставить точки вставки. *Выход:* условный вызов заплатки там, где она уместна по смыслу.
  5. Прогнать бота и человека. Где темп провисает — добавить заплатку, хребет не трогать.
- **Если пропустить:** без шага 1 у финала нет версии «по умолчанию», и игрок-молчун получает обрубок (ср. `fin_revenge`, RED-10). Без проверки `not p_x` заплатка повторяется. Без шага 5 провисания чинят переписыванием хребта, и сочетания снова растут.
- **Ошибки понимания:** это не «ветвление на финал». Ветки финала здесь не пишутся целиком: финал один, меняются вставки. Вторая ошибка — делать хребет «хорошей» версией. Хребет — версия бездействия, всё хорошее приходит заплатками за поступки.
- **Короткая форма:** финал на 6–8 сообщений и 1–2 заплатки. См. PAT-11.
- **Источник:** [L1].

### SYS-4. Модель знаний (knowledge model)
- **Элементы:** состояние знания (игрок/персонаж знает X); метка на реплике — какие знания ей нужны и какие делают её лишней; журнал — где игрок видит, что узнал (Timeline в Heaven's Vault, «Вопросы» в Overboard!); свежесть — какое знание появилось последним [L1], [L3].
- **Шаги:**
  1. Перечислить факты, на которых держится сюжет. *Выход:* список, у нас — `VAR` или `LIST` (PAT-04).
  2. Пометить реплики и кнопки условиями на факты в момент написания, а не потом. Overboard! так и делали, и всё равно чинили сотни нестыковок [L1].
  3. Показать игроку журнал: заметки с фактами и открытыми вопросами (LESSON-04).
  4. Для персонажей, которые узнают сами, завести отдельные факты «X знает Y». В Overboard! персонажи узнают независимо от игрока и опережают его [L1].
- **Если пропустить:** без шага 2 кнопки про незнакомые факты (RED-05). Без шага 3 вернувшийся игрок не помнит, что знает. Без шага 4 все персонажи знают ровно то же, что игрок, — мир плоский.
- **Ошибки понимания:** «знания = улики». Знания нужны и для тона: Бет знает, писал ли ей игрок (`beth_written`).
- **Короткая форма:** 2–3 флага знаний, один из них — у персонажа («она уже знает, что ты писал Тому»).
- **Источник:** [L1], [L3], [S5] (Part 5).

### SYS-5. Конвейер производства inkle
- **Элементы:** текстовая сборка целиком (без графики) → слои деталей → автоигрок с проверками → тест на людях → кнопка отчёта с журналом.
- **Шаги:**
  1. Полный сценарий от начала до конца как играбельный текст. Overboard! имел его на третьей неделе из ~14 [L2]. *Выход:* прохождение до финала, пусть грубое.
  2. Показать людям. Если ядро нравится, дальше только контент и полировка, без пересмотра основы [L2].
  3. Наращивать слоями: сценарист даёт текст города, дизайнер добавляет логику сверху (80 Days, [L8]).
  4. Автоигрок плюс проверки невозможных состояний (LESSON-05).
  5. Кнопка отзыва с журналом (LESSON-06).
- **Если пропустить:** без шага 1 механики проверяются на кусках, и что-то вроде мини-игры с фактами в 80 Days вырезают за три недели до выхода (LESSON-09). Без шага 4 — сотни нестыковок, которые находят игроки.
- **Ошибки понимания:** «сначала одна глава идеально». inkle наоборот: вся история грубо, потом слои.
- **Короткая форма:** для истории на 5 минут шаг 1 — это 20 строк ink за вечер, шаг 2 — один человек с `?fast=1`.
- **Источник:** [L1], [L2], [L8].

### PAT-11. Финал-хребет с заплатками-туннелями (core spine and patches)
- **Когда применять:** финал или кульминация, которые должны реагировать на 3+ переменных. **Когда нет:** если финалов несколько и они действительно разные по событию — тогда это разные узлы.
- **Схема:**
  ```
  хребет: шаг 1 → [заплатка A?] → шаг 2 (или заплатка B вместо него) → развилка → END
  заплатка: условие && not заплатка → туннель → ->-> обратно в хребет
  ```
- **На ink** (скомпилирован inkjs; при всех `false` проходит хребет, при `heard_tapping` и `has_key` — обе заплатки):
```ink
# contact: lev, Лев, indigo
VAR heard_tapping = false
VAR has_key = false
VAR lev_trust = 0
-> door
=== door ===
// хребет: версия «игрок ничего не сделал»
я у 43-й #from:lev
{ heard_tapping && not p_tapping:
    -> p_tapping ->
}
стучу. тихо #delay:20s
{ has_key:
    -> p_key ->
- else:
    заперто. ухожу? #from:lev #delay:10s
}
* [Уходи #to:lev]
    иду. но я вернусь #from:lev #delay:20s
* {lev_trust > 0} [Подожди минуту #to:lev]
    жду. ради тебя #from:lev #delay:1m
* [Промолчать #to:lev #silent]
    ладно. сам решу #from:lev #delay:5m
- -> END
=== p_tapping ===
соседка была права. изнутри стучат #from:lev #delay:30s
->->
=== p_key ===
ключ подошёл. открываю #from:lev #delay:30s
там кто-то есть
->->
```
- **Цена:** хребет пишется один раз. Каждое последствие — 2–4 строки заплатки и одна строка вызова. Объём растёт линейно по числу последствий, а не по их сочетаниям.
- **Ловушки:** заплатки не должны зависеть друг от друга по порядку, иначе вернётся комбинаторика. Если заплатка меняет смысл следующего шага хребта, этот шаг тоже нужно скрывать условием (`p_key` заменяет «заперто»). Карта (`story-graph.mjs`) показывает туннели; проверь, что доля прохождений через каждую заплатку ≥ 10 %, иначе её никто не увидит.
- **Источник:** [L1]; запись на ink наша.

## Нюансы к PAT-01…PAT-10

| паттерн | не работает, когда | пограничный случай | 5 сообщений против 50 |
|---|---|---|---|
| PAT-01 weave | ответ на кнопку должен жить дольше сцены | одна из веток длиннее 4 реплик: выноси её, остальные оставь в weave | 5: одна развилка, одна метка. 50: 5–7 сборок, метки читаются в конце сцены |
| PAT-02 вставка в монолог | монолог — признание, которое нельзя перебивать по смыслу | вставка `#silent` с реакцией «ты тут?» — тоже вставка, если реакция новая | 5: не нужна. 50: 2–3 вставки, после паузы ≥ 1h первая не позже 5-го сообщения |
| PAT-03 защитный вход | один вход в узел | вход после долгой паузы, за которую «в мире» что-то случилось: проверка и знания, и того, что игрок сделал до паузы (`ch8_jess`) | 5: одна условная реплика. 50: блок на 2–3 состояния + проверка «лишнего» (SYS-2) |
| PAT-04 LIST-знания | фактов < 5 или их узнают в любом порядке | факты из разных чатов, один из которых игрок мог не открыть | 5: не нужен. 50: оправдан, если есть кнопки-обвинения |
| PAT-05 отказ с нажимом | отказ — законный конец истории | игрок отказывается молчанием (`#silent`) — считать как отказ | 5: один нажим. 50: два такта, отказ читается в финале |
| PAT-06 хаб | порядок вопросов важен | собеседник сам закрывает хаб после 2–3 вопросов (LESSON-14) | 5: 2 вопроса из 3. 50: 3–4 темы, ответы пишут знания |
| PAT-07 напоминание при молчании | молчание должно сразу менять сюжет | реальная пауза между напоминаниями больше суток: третье звучит как спам | 5: одно «ау?». 50: последовательность из 3 с растущими паузами |
| PAT-08 поток | кнопка нужна в 1–2 местах | карта не видит `<-` | 5: не нужен. 50: при 5+ одинаковых кнопках |
| PAT-09 кнопка-цитата | запись нигде не цитируется | цитата расходится с текстом заметки после правки: проверять скриптом | 5: одна цитата в последнем сообщении. 50: по цитате на главу |
| PAT-10 награда ходом | без кнопки кульминация не работает | побочный чат посещают < 20 % прогонов: награду никто не видит | 5: один необязательный вопрос → одна кнопка в конце. 50: 2–3 побочных чата, каждый открывает свою кнопку |
