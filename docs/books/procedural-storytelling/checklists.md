# Чек-листы — Procedural Storytelling in Game Design

Процедуры можно отдать человеку или модели. Ссылки на `P-`, `PAT-`, `RED-` ведут в соседние файлы, `A…` — в `for-relayer.md`.

## 1. Придумать и начать историю

- [ ] **Карточки персонажей по четырём компонентам** (`P-05`). На каждого контакта 4 строки: мотив, отношения (к игроку и к каждому другому контакту), умение, знание (что знает только он). *Результат:* таблица, где у каждого есть хотя бы один уникальный факт в «знании».
- [ ] **Одна утрированная черта письма и одна черта поведения на персонажа** (`P-06`): «пишет капсом», «отвечает через 6 часов». *Результат:* двух персонажей с одинаковой чертой нет.
- [ ] **Реестр фактов** (`P-15`): что игрок сообщает о себе (имя, легенда) и что узнаёт (имена, события). Для каждого — переменная и глава введения. *Результат:* список `факт → VAR → глава`.
- [ ] **Оси, которые развилят сюжет:** не больше 2–3 счётчиков отношения (`P-03`, `RED-12`). Для каждого: в какой главе пишется, где первый видимый сигнал, где читается. *Результат:* у каждой оси сигнал стоит в той же главе, что и первая запись.
- [ ] **Превращения** (`P-09`): для каждого из 2–3 главных персонажей одна смена состояния, её триггер и глава. *Результат:* таблица `персонаж → A → триггер → B`.
- [ ] **Простой ствол первым** (`P-01`): написать главу 1 линейно, с паузами, прогнать `npm run check:story`, прочитать один проход. *Результат:* понятно, где проход провисает. Развилки ставятся туда.
- [ ] **Первые 10 сообщений:** персонаж с утрированной чертой, его мотив (чего он хочет от игрока) и почему именно игрок. *Результат:* три пункта находятся в тексте ствола, а не в ветке.

## 2. Написать главу или сцену

- [ ] **Объявить контракт каждого узла** (`P-13`): «читает: …, пишет: …». *Результат:* нет узлов вне ствола с пустым контрактом (`RED-11`).
- [ ] **Сцены-слияния защитить** (`P-14`, `PAT-07`): найти узлы с 2+ входами, выписать факты, которые есть не на всех путях, обернуть их упоминания в условия. *Результат:* A8 молчит.
- [ ] **Условные блоки — от узкого к общему, с `else`** (`P-12`, `PAT-01`). *Результат:* A3 молчит.
- [ ] **У каждой записи в счётчик — сигнал** (`P-10`, `PAT-05`), хотя бы при пересечении порога. *Результат:* A2 не находит «немых» записей в этой главе.
- [ ] **Минимум одно событие с двумя реакциями** (`P-08`, `PAT-03`). *Результат:* A5 находит в главе ≥ 1 такой узел.
- [ ] **Развилки без последствия различить** (`P-04`, `P-02`): у каждой кнопки свой факт, пауза, адресат или отправитель ответа. *Результат:* A4 не ругается.
- [ ] **Шафл только в проходных репликах** (`P-11`, `PAT-06`). *Результат:* A7 молчит.
- [ ] **Последняя реплика перед длинной паузой и перед `#chapter` открывает вопрос** (`P-16`). *Результат:* A10 молчит.

## 2а. Сгенерировать главу моделью

- [ ] **Опись до генерации** (`P-17`): 1–2 образцовые сцены из наших историй, три обязательных свойства главы, запреты (`P-11`, `P-18`). *Результат:* список, который вставляется в запрос вместе с правилами из `for-relayer.md` §1.
- [ ] **Три варианта, а не один** (`P-17`). *Результат:* три черновика главы.
- [ ] **Отсев:** каждый вариант через `npm run check:story` и проверки A1–A13; вариант с нарушением запрета отбрасывается целиком. *Результат:* остаётся вариант, на котором проверки молчат, или задача на переписывание.
- [ ] **Имена** (`P-18`, `RED-13`): все имена собственные из A13 проверены человеком. *Результат:* ноль реальных брендов и людей.

## 3. Ревью готового сценария

- [ ] Прогнать `npm run graph` и `npm run check:story`, сохранить отчёты. *Результат:* есть доли прохождений по узлам и список невыбранных веток.
- [ ] **Таблица переменных:** записи, чтения, глава первой записи, глава первого чтения. Отметить `RED-01`, `RED-02`, `RED-12`. *Результат:* список переменных с действием (удалить, добавить сигнал, слить).
- [ ] **Слепой тест голосов** (`P-06`, `RED-08`): 10 реплик двух персонажей без имён. Ревьюер угадывает ≥ 8. *Результат:* пары с перепутанными голосами.
- [ ] **Превращения:** у каждого персонажа с 20+ репликами найти точку смены состояния и её триггер (`P-09`). *Результат:* у кого нет, тот в списке на доработку.
- [ ] **Действия:** у каждого основного персонажа есть действие-тег (`P-07`, `RED-07`). *Результат:* список «молчаливых» персонажей.
- [ ] **Финал:** для каждой переменной в условии финала найти, где игрок «слышал» её значение (`RED-10`). *Результат:* переменные без сигнала.
- [ ] **Реестр фактов:** каждое упоминание темы личности игрока (имя, легенда) стоит под условием (`P-15`, A9). *Результат:* ноль безусловных упоминаний.

## 4. Тестировать

- [ ] `npm run check:story` — тупики, финалы, длительность, ветки условных блоков, которые ни разу не выполнились (A3). *Результат:* ноль тупиков, у каждой ветки ≥ 1 выполнение.
- [ ] **Различимость прохождений** (`P-04`, A11): взять 20 случайных проходов, посчитать попарную долю общих сообщений. *Результат:* медиана < 0,8. Если выше, выборы не меняют текст.
- [ ] **Два прохода рядом:** прочитать глазами самый «правильный» и самый «неправильный» проход одной главы. *Результат:* ревьюер в двух предложениях называет, чем они различаются для игрока. Если не может, это `RED-03` на уровне главы.
- [ ] **Проход с `?fresh=1&fast=1`** в браузере: убедиться, что реакции в двух чатах (`PAT-03`) поднимают оба чата наверх списка, а `#rename` видно в шапке. *Результат:* скриншот `npm run shots` без расхождений.
