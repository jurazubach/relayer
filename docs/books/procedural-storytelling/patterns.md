# Приёмы и структуры — Procedural Storytelling in Game Design

Все примеры ink скомпилированы `inkjs/full` 2026-10-24 без ошибок. Источники [S1]–[S9] — в `README.md`.

### PAT-01. Каскад от частного к общему (salience, most specific rule wins)
- **Когда применять:** в узле-слиянии, куда игрок приходит с разным набором фактов, и в реакциях персонажа на накопленное отношение. **Когда нет:** если вариантов всего два и они равноправны. Тогда хватит обычного `{cond: a | b}`.
- **Схема:**
  ```
  вход → [a && b] → реплика-1 (самая узкая)
       → [a && c] → реплика-2
       → [a]      → реплика-3
       → [else]   → общая реплика (есть всегда)
  → общий текст дальше
  ```
- **На ink:**
  ```ink
  # contact: mira, Мира, teal
  VAR knows_name = false
  VAR lied_once = false
  -> ask
  === ask ===
  кто тебе дал мой номер #from:mira
  * [Лео дал #to:mira]
      ~ knows_name = true
  * [Нашёл в общем чате #to:mira]
  - ты его знаешь? #from:mira #delay:1m
  * [Да, с детства #to:mira]
      ~ lied_once = true
  * [Нет #to:mira]
  - -> reply
  === reply ===
  {
  - knows_name && lied_once:
      лео тебя не знает. я спросила #from:mira #delay:2m
  - knows_name:
      лео, значит. ладно #from:mira #delay:1m
  - lied_once:
      с детства. и номер из общего чата? #from:mira #delay:3m
  - else:
      ладно. пиши, раз уж написал #from:mira #delay:3m
  }
  -> END
  ```
  Все четыре ветки достижимы, бот должен выбрать каждую хотя бы раз (проверка A3). Если поставить `- knows_name:` первой строкой, ветка `knows_name && lied_once` станет мёртвой.
- **Цена:** 2–4 реплики на узел. Сложность растёт с числом условий линейно, а не комбинаторно: сочетания, которые не покрыты отдельно, уходят в `else`.
- **Ловушки:** широкое условие выше узкого делает узкое недостижимым. Без `else` персонаж молчит, и игрок видит дыру. Переменные, которые никогда не встречаются вместе, порождают мёртвые ветки.
- **Источник:** [S7] Emily Short о Ruskin; [S5].

### PAT-02. Пул сцен с предусловиями и счётчиками (storylets, QBN)
- **Когда применять:** расследование, где порядок разговоров свободный, а важно, сколько игрок узнал и насколько засветился. **Когда нет:** в первой главе (игрок ещё не понимает, что ищет) и в кульминации (нужен один авторский путь).
- **Схема:**
  ```
  hub ─┬─ сцена A (всегда)          → progress+1
       ├─ сцена B {progress>=1}     → progress+1, heat+1
       └─ сцена C (рискованная)     → heat+2
  hub проверяет: progress>=2 → итог «успех»; heat>=2 → итог «провал»
  ```
  Progress — счётчик продвижения, heat — счётчик угрозы. Похожие «угрозы» (menaces) есть в Fallen London, на котором Emily Short объясняет QBN [S5]; сама пара progress/heat — наша (знание модели, уверенность: средняя).
- **На ink:**
  ```ink
  # contact: ana, Ана, blue
  # contact: kir, Кир, amber
  VAR progress = 0
  VAR heat = 0
  -> hub
  === hub ===
  { progress >= 2 || heat >= 2: -> close }
  * [Спросить Ану про ключ #to:ana #label:Ана]
      ключ был у охранника #from:ana #delay:2m
      ~ progress += 1
      -> hub
  * {progress >= 1} [Спросить Кира, кто охранник #to:kir #label:Кир]
      зачем тебе? #from:kir #delay:5m
      ~ heat += 1
      ~ progress += 1
      -> hub
  * [Спросить Кира в лоб, где ключ #to:kir #label:Наугад]
      ~ heat += 2
      -> hub
  === close ===
  { heat >= 2:
      тебя уже ищут. я выхожу из чата #from:ana #delay:20m
  - else:
      завтра в семь у ворот #from:ana #delay:1h
  }
  -> END
  ```
- **Цена:** каждая сцена должна читаться в любом порядке (`P-14`), это +20–40% текста на защитные условия. Зато новую сцену можно добавить, не трогая остальные.
- **Ловушки:** выход из хаба должен существовать при любом порядке. Бот ловит это как тупик. Пул из одних сцен «+1 к progress» — та же «овсянка» (`P-04`): сцены должны давать разные факты. Большой пул в начале главы перегружает игрока выбором, маленький выглядит пустым (наше наблюдение; в [S5], [S6] этого нет).
- **Источник:** [S6], [S5] Emily Short.

### PAT-03. Один катализатор, две реакции
- **Когда применять:** после выбора, который касается двух контактов, и после новости, которую узнают все. **Когда нет:** если второму персонажу нечего добавить, кроме повтора первого. Тогда реакция — шум.
- **Схема:**
  ```
  выбор игрока ─► чат A: быстрая эмоциональная реакция (#delay секунды)
               └► чат B: медленная расчётливая (#delay минуты)
  ```
- **На ink:**
  ```ink
  # contact: ana, Ана, blue
  # contact: kir, Кир, amber
  VAR sent_photo = false
  -> catalyst
  === catalyst ===
  * [Переслать фото обоим #to:ana #label:Переслать фото]
      ~ sent_photo = true
  * [Оставить себе #to:ana #silent]
  - {sent_photo:
      это же моя куртка #from:ana #delay:40s
      откуда у тебя
      ты кому ещё это отправил? #from:kir #delay:6m
      удали. сейчас же
  - else:
      ты пропал #from:ana #delay:2h
  }
  -> END
  ```
- **Цена:** 2–5 реплик на событие. Структуру не усложняет.
- **Ловушки:** обе реакции одного тона не раскрывают никого (`P-06`). Если вторая реакция приходит через несколько часов, связь с катализатором теряется: держи её в пределах 30 минут или называй событие прямо.
- **Источник:** [S2] Tanya X. Short.

### PAT-04. Превращение с триггером (transformation)
- **Когда применять:** раз на персонажа за историю. Это точка, ради которой игрок запомнит контакт. **Когда нет:** у второстепенных контактов с 3–5 репликами превращение не успевает окупиться.
- **Схема:**
  ```
  состояние A (тон, имя, сторона) ─ триггер (кнопка или факт) ─ пауза ─ видимый сдвиг (#rename, смена тона) ─ новое состояние B, которое потом подтверждается
  ```
- **На ink:**
  ```ink
  # contact: unknown, Неизвестный номер, grey
  VAR caught = false
  -> pre
  === pre ===
  Вы не из нашего города. #from:unknown #delay:7h
  * [Кто это? #to:unknown]
  * [Я знаю, что это вы, Рут #to:unknown #label:Назвать по имени]
      ~ caught = true
  - {caught:-> turn|-> stay}
  === stay ===
  Неважно. #from:unknown #delay:3h
  -> END
  === turn ===
  ... #from:unknown #delay:25m
  #rename:unknown, Рут
  да. это я #from:unknown #delay:4m
  только не говори дочери
  больше никаких «вы» #delay:30s
  -> END
  ```
- **Цена:** одна сцена плюс подтверждение новым тоном в 1–2 последующих репликах. Подтверждение обязательно, иначе сдвиг выглядит случайным.
- **Ловушки:** превращение без триггера, которым был выбор игрока, кажется произволом автора. Если персонаж после сдвига пишет прежним тоном, это стоит проверить ревьюером. Превращение в ветке, куда попадает меньше 10% игроков, — дорогая находка для немногих, рядом нужен вариант для ствола.
- **Источник:** [S2] Tanya X. Short.

### PAT-05. Лупа: озвучь изменение скрытого счётчика (magnifying glass)
- **Когда применять:** при каждой записи в счётчик отношения, который потом развилит сюжет. **Когда нет:** для счётчиков-сюрпризов, где загадка в том, что игрок не знает. Но и там дай способ расследовать задним числом: персонаж в финале объясняет, за что.
- **Схема:**
  ```
  кнопка → ~ trust ±1 → реплика-сигнал по направлению изменения (в той же сцене) → … → развилка по trust
  ```
- **На ink:**
  ```ink
  # contact: ana, Ана, blue
  VAR ana_trust = 0
  -> s1
  === s1 ===
  мне нужен человек, который не задаёт вопросов #from:ana
  * [Я такой #to:ana]
      ~ ana_trust += 1
  * [Зависит от вопросов #to:ana]
      ~ ana_trust -= 1
  - {ana_trust > 0:
      ок. ты мне нравишься. не порти #from:ana #delay:30s
  - else:
      запомню #from:ana #delay:2m
  }
  -> END
  ```
- **Цена:** одна условная реплика на запись. Это дёшево и сразу превращает «пустую» кнопку в ощутимую.
- **Ловушки:** сигнал не должен называть число («доверие +1»). Это ломает жанр переписки. Сигнал на каждую из 23 записей утомит: достаточно сигнала на пересечение порога и на каждую 2–3-ю запись.
- **Источник:** [S2] Tanya X. Short.

### PAT-06. Перемешанные проходные реплики (простой генератор)
- **Когда применять:** петли ожидания, напоминания, реакции на молчание, повторяющиеся служебные фразы. **Когда нет:** в любом месте, где реплика несёт факт или поворот (`P-11`).
- **Схема:** `{~вариант|вариант|вариант}` в повторяемом узле, плюс счётчик выхода.
- **На ink:**
  ```ink
  # contact: kir, Кир, amber
  VAR waited = 0
  -> loop
  === loop ===
  {~ты там?|ау|ну?|я жду} #from:kir #delay:20m
  ~ waited += 1
  { waited >= 3: -> gone }
  * [Тут #to:kir]
      наконец #from:kir #delay:30s
      -> END
  + [Промолчать #to:kir #silent]
      -> loop
  === gone ===
  всё, проехали #from:kir #delay:1h
  -> END
  ```
  «Промолчать» помечена `+`, поэтому она остаётся на каждом круге, и после третьего напоминания (два молчания подряд) срабатывает выход `gone`. Со `*` кнопка исчезла бы после первого раза, и выход стал бы недостижим. Бот поймал бы это как узел без посещений.
- **Цена:** почти нулевая.
- **Ловушки:** шафл делает проход недетерминированным, и скриншоты/e2e могут плавать. Варианты должны быть в одном голосе персонажа: перемешивание не повод смешивать стили.
- **Источник:** [S4] Kazemi (простые случайные правила), [S9] Compton; синтаксис ink — знание модели, уверенность: высокая.

### PAT-07. Защитная сцена-слияние (defensive convergence)
- **Когда применять:** в любом узле, куда ведут 2+ пути с разными фактами. В «Чужом голосе» это начала глав (`ch6`, `ch10`) и узлы вида `*_after`. **Когда нет:** в стволе, который все проходят одинаково.
- **Схема:**
  ```
  путь A (узнал X) ─┐
                    ├─ merge: {X: опирайся на X | введи X заново} → общий текст
  путь B (не узнал) ┘
  ```
- **На ink:**
  ```ink
  # contact: ana, Ана, blue
  VAR met_kir = false
  VAR heard_name = false
  -> start
  === start ===
  * [Сначала к Киру #to:ana]
      ~ met_kir = true
      ~ heard_name = true
  * [Сначала спросить Лео #to:ana]
      ~ heard_name = true
  * [Сразу к Ане #to:ana]
  - -> merge
  === merge ===
  {
  - met_kir:
      кир уже всё рассказал, да? #from:ana #delay:1m
  - else:
      ты ещё ни с кем не говорил? хорошо #from:ana #delay:1m
  }
  {heard_name:
      да, его звали Ян
  - else:
      его звали Ян. ты не слышал? #delay:20s
  }
  -> END
  ```
- **Цена:** 1–2 условные реплики на каждый факт из веток. Разрастается, если веток с уникальными фактами много: тогда факты сокращай, а не условия.
- **Ловушки:** «пересказ» в стволе, повторяющий то, что игрок уже видел в ветке, раздражает. Используй условие и короткое подтверждение («да, его звали Ян»), а не полный повтор.
- **Источник:** аннотация GDC 2017 «Narrative Sorcery» (только поисковый сниппет https://gdcvault.com/play/1023989/), остальное — знание модели, уверенность: средняя; [S8] (реестр фактов).

# Нюансы к паттернам (второй проход)

Источники [L1]–[L10] — в `lessons.md`; устройство систем С-1…С-5 — в `principles.md`.

### К PAT-01 (каскад)
- **Не заменяет сцену с целью** (`LESSON-11`): каскад даёт реакцию, но не ведёт разговор. Если персонаж чего-то добивается, сцену пишем ветками.
- **Запись сказанного** (С-3, знание модели). Сказанная реплика должна становиться фактом. Без этого узкая ветка повторится при втором заходе в узел. В ink защищай повторный вход условием на счётчик посещений узла.
- **5 против 50.** Для короткой истории — две ветки и `else`, для длинной — до трёх (`attention.md` §4).

### К PAT-02 (пул сторилетов)
- **Строгость условий** (`LESSON-02`): если бот находит сторилет реже 1% прогонов, условие слишком узкое. Ослабь вход, а различие перенеси внутрь сцены каскадом.
- **Кастинг вместо выбора сцены** (С-5): в генерации моделью пул задаёт автор, модель распределяет роли среди контактов, но не придумывает новые сторилеты на лету.
- **Короткая форма:** в истории до 30 минут вместо пула — одна условная кнопка `* {x} [...]`.

### К PAT-03 (катализатор и две реакции)
- **Согласованность реакций** — главная цена. Short отмечает, что реакция зависит от многих отношений сразу ([L6]). Перед написанием выпиши для обоих персонажей одну строку: что событие значит для него (мотив из `P-05`). Реакции, у которых эти строки совпадают, сольются.

### К PAT-04 (превращение)
- Исходное состояние и обязательный триггер — см. нюанс к `P-09` в `principles.md`. На 5-минутной истории превращение ставим в последнюю треть.

### К PAT-06 (перемешанные проходные реплики)
- **Граница со спамом:** в петле ожидания не больше двух напоминаний, потом `#sys` о том, что персонаж не в сети (`attention.md` §5).
- **Комедия:** в лёгкой истории шафл допустим шире (`P-11`, нюанс).

### К PAT-07 (защитная сцена-слияние)
- **Якорь после паузы:** если слияние стоит сразу после паузы ≥ 1h, первая реплика содержит имя или предмет из последних пяти сообщений до паузы (`attention.md` §3).
