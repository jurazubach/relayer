# Приёмы и структуры

Сокращения источников — в `README.md`. Все примеры ink проверены компилятором inkjs; теги и цвета — из `docs/capabilities.json`.

### PAT-01. Необязательный разговор с наградой (опциональный Explore из 80 Days)
- **Когда применять:** побочные свидетели, справочные чаты, «поспрашивать вокруг». **Когда нет:** сцена несёт обязательный для финала факт. Тогда её не прячь, а сокращай.
- **Схема:**
  ```
  хаб ──[побочный чат]──► факт/контакт ──► хаб (появилась новая кнопка)
   │
   └──[хватит, дальше]──► сюжет (реплика учитывает, что найдено, а что нет)
  ```
- **На ink:**
  ```ink
  # contact: nora, Нора, teal
  # contact: vik, Вик, orange
  # contact: dock, Сторож причала, grey
  VAR got_key = false
  -> hub
  === hub ===
  кому пишем? до отлива два часа #from:nora #delay:10s
  * [Спрошу Вика про лодку #to:vik #label:Написать Вику]
      лодка? та, что без номера? #from:vik #delay:1m
      сторож знает, чья. вот его номер #delay:20s
      ~ got_key = true
      -> hub
  * {got_key} [Написать сторожу #to:dock #unlock:dock]
      Лодка стоит третью неделю. Хозяина не видел. #from:dock #delay:3m
      -> tide
  * [Хватит. Идём к воде #to:nora]
      -> tide
  === tide ===
  {got_key:у тебя есть сторож. это уже что-то|ладно. пойдём вслепую} #from:nora #delay:30s
  -> END
  ```
- **Цена:** одна реплика-развилка в точке выхода на каждый флаг. Хаб с 3–4 ветками — 20–40 строк.
- **Ловушки:** ветка, которая возвращает в хаб ни с чем (`ch1_beth`: «Бет не в сети» и обратно), тратит выбор впустую. Дай хотя бы реплику, которая сработает позже: в `ch2_beth` она есть, это правильно. Если выход из хаба открыт сразу, часть игроков не увидит ничего. Держи один обязательный разговор.
- **Источник:** GD80.

### PAT-02. Отношение меняет форму разговора (сжимающийся пазл Florence)
- **Когда применять:** у героя есть персонаж, с которым игрок проходит путь от чужого к близкому. **Когда нет:** короткая история на одну сессию — не хватит повторов, чтобы заметить сдвиг.
- **Схема:** чем выше доверие, тем меньше шагов и короче паузы до важного ответа.
  ```
  trust 0:  вопрос → отказ → кнопка → уточнение → (может, ответ)
  trust 1+: вопрос → ответ
  ```
- **На ink:**
  ```ink
  # contact: ian, Иэн, indigo
  VAR ian_trust = 0
  -> talk
  === talk ===
  ты кто вообще #from:ian #delay:40s
  * [Друг Мэй #to:ian]
      ~ ian_trust += 1
  * [Неважно #to:ian]
  - {ian_trust >= 1:
      а. она говорила #from:ian #delay:20s
      -> fact
  }
  и что тебе надо #from:ian #delay:2m
  * [Где она была в пятницу? #to:ian]
      не твоё дело #from:ian #delay:1m
  * [Просто поговорить #to:ian]
      ~ ian_trust += 1
      ну говори #from:ian #delay:1m
  - {ian_trust >= 1: -> fact}
  Иэн не в сети #sys:ian
  -> END
  === fact ===
  в пятницу она была у меня до двух #from:ian #delay:30s
  -> END
  ```
- **Цена:** 1 переменная и одна короткая и одна длинная дорога к каждому факту.
- **Ловушки:** если дорога для низкого доверия кончается ничем, а факт обязателен, получишь тупик по смыслу. Дай факту второй источник (PAT-04).
- **Источник:** GW, WF.

### PAT-03. Отложенная оплата выбора («will remember» с ответом через главу)
- **Когда применять:** выбор, по которому игрок должен почувствовать, что его заметили: ложь, отказ, обещание. **Когда нет:** чистая окраска голоса (P-04), её оплата — сама реплика.
- **Схема:**
  ```
  глава N:   выбор → персонаж отмечает («запомню») → переменная
  глава N+1..N+2: реплика, которая называет выбор прямо
  ```
- **На ink:**
  ```ink
  # contact: rae, Рэй, amber
  VAR lied_to_rae = false
  -> ch1
  === ch1 ===
  ты видел, кто взял ключ? #from:rae #chapter
  * [Нет #to:rae]
      ~ lied_to_rae = true
      ок #from:rae #delay:30s
      запомню #delay:5s
  * [Видел. Это Сол #to:rae]
      спасибо #from:rae #delay:30s
  - -> ch3
  === ch3 ===
  День 3 #sys:rae #chapter #delay:2h
  {lied_to_rae: -> caught}
  ты был прав про Сола. он вернул ключ #from:rae #delay:20s
  -> END
  === caught ===
  Сол сказал, ты стоял рядом. и сказал мне «нет» #from:rae #delay:20s
  * [Испугался #to:rae]
      понятно #from:rae #delay:1m
  * [Промолчать #to:rae #silent]
      Прочитано #sys:rae #delay:1m
  - -> END
  ```
- **Цена:** одна-две реплики в будущей главе на каждый отмеченный выбор.
- **Ловушки:** «запомню» без оплаты хуже, чем ничего: игрок ждёт и разочаровывается. Не используй надпись движка вроде `#sys` «Рэй это запомнит» — это голос автора, а у нас его нет. Пусть отметит сам персонаж.
- **Источник:** TWD (уведомления о выборе, адресные реакции по журналу выборов), IF50; метка «Carley will remember that» и то, что её иногда ставили как обманку, — [GB3] (второй проход; прежняя формулировка про Клементину была знанием модели).

### PAT-04. Факт из двух половин (лимит выдачи Her Story)
- **Когда применять:** ключевая улика, имя виновника, место встречи. **Когда нет:** факт нужен, чтобы вообще понять завязку. Его давай сразу (см. `RED-10`).
- **Схема:**
  ```
  контакт A → половина 1 ─┐
                           ├─► {a && b} откровение (#rename, «Заметки», новый контакт)
  контакт B → половина 2 ─┘
  ```
- **На ink:**
  ```ink
  # contact: lena, Лена, pink
  # contact: max, Макс, blue
  # contact: notes, Заметки, green
  VAR saw_car = false
  VAR heard_time = false
  -> start
  === start ===
  * [Что ты видела у дома? #to:lena]
      машину. серую. фары не горели #from:lena #delay:40s
      ~ saw_car = true
  * [Во сколько ты ушёл? #to:max]
      в 23:40. на парковке кто-то сидел в машине #from:max #delay:1m
      ~ heard_time = true
  - {saw_car && heard_time: -> both}
  * [Спросить второго #to:notes #silent #label:Подумать, кого ещё спросить]
      -> start
  === both ===
  Серая машина без фар, 23:40, водитель внутри #sys:notes
  -> END
  ```
- **Цена:** два источника вместо одного, плюс реплика, если собрана только одна половина.
- **Ловушки:** половины, которые игрок не может связать без авторской подсказки. Пусть в обеих встречается общее слово («машина»).
- **Источник:** PGB.

### PAT-05. Оборонительный хаб (defensive scripting, Sorcery!)
- **Когда применять:** любой хаб, где игрок выбирает порядок разговоров. **Когда нет:** линейная сцена.
- **Схема:** каждая ветка до выдачи факта проверяет, слышал ли его игрок в другой ветке, и подстраивает реплику.
  ```
  ветка B: {факт_из_A: «да, я тоже это видел»| «слушай, на парковке…»}
  ```
- **На ink:** в PAT-01 реплика `tide` уже работает так. Для каждой пары веток допиши `{flag:...|...}` в месте, где ветка сообщает пересекающийся факт.
- **Цена:** одна условная строка на каждое пересечение. При N ветках до N·(N−1)/2 проверок, поэтому держи хаб на 3–4 ветках.
- **Ловушки:** проверки на уровне «весь текст по-разному» быстро взрывают объём. Меняй одну строку, не сцену.
- **Источник:** XS — аннотация называет «defensive logic», но не раскрывает её; что это именно проверки «что игрок уже знает» — знание модели о докладе Ингольда, уверенность средняя.

### PAT-06. Сводка главы (экран статистики Telltale)
- **Когда применять:** в конце главы, где игрок принял 2–5 решений с последствиями, и перед финалом, который выбирает скрытый счёт. **Когда нет:** после каждой сцены — это превращает историю в отчёт.
- **Схема:** чат «Заметки» или персонаж перечисляет состояние, без оценок.
- **На ink:**
  ```ink
  # contact: bo, Бо, cyan
  # contact: notes, Заметки, green
  VAR told_bo = false
  VAR kept_photo = false
  -> scene
  === scene ===
  * [Рассказать Бо про звонок #to:bo]
      ~ told_bo = true
  * [Не рассказывать #to:bo #silent]
  - * [Сохранить фото #to:notes]
      ~ kept_photo = true
  * [Удалить фото #to:notes #silent]
  - Итоги дня #sys:notes #delay:30s
  {told_bo:Бо знает про звонок|Бо не знает про звонок} #sys:notes
  {kept_photo:Фото сохранено|Фото удалено} #sys:notes
  -> END
  ```
- **Цена:** 2–5 строк на главу.
- **Ловушки:** у Telltale было сравнение с другими игроками. У нас нет сервера, так что сравнения нет. Не придумывай цифры «47 % игроков». Строки в «Заметках» должны звучать как заметки героя, а не системы. Лучше `Бо знает про звонок`, чем `Выбор сохранён`.
- **Источник:** TWD.

### PAT-07. Выравнивание знакомства перед выбором между людьми (урок Дуга и Карли)
- **Когда применять:** «кого спасти», «кому отдать запись», «кому поверить». **Когда нет:** если перекос задуман и персонаж с меньшим числом сцен — ловушка.
- **Схема:** до развилки у каждого кандидата: личная просьба к игроку, одна уязвимость, сопоставимое число входящих. После — реакция, которая помнит прошлый ответ игрока.
- **На ink:**
  ```ink
  # contact: kit, Кит, green
  # contact: zoe, Зои, purple
  VAR kit_bond = 0
  VAR zoe_bond = 0
  -> c1
  === c1 ===
  у меня бензина на один рейс #from:kit #delay:20s
  * [Ты справишься #to:kit]
      ~ kit_bond += 1
  * [Заправься по дороге #to:kit]
  - я Зои, твой номер дал Кит. мне страшно #from:zoe #unlock:zoe #delay:1m
  * [Я с тобой #to:zoe]
      ~ zoe_bond += 1
  * [Где ты? #to:zoe]
  - он опять приходил. у меня ребёнок #from:zoe #delay:40s
  кстати, я из-за тебя вообще поехал #from:kit #delay:2m
  -> pick
  === pick ===
  могу забрать только одного. меня или Зои? #from:kit #delay:30s
  * [Зои. У неё ребёнок #to:kit]
      {kit_bond > 0:ладно. ты же сам сказал, что я справлюсь|ок} #from:kit #delay:1m
  * [Тебя. Ты уже в пути #to:kit]
      {zoe_bond > 0:
          ты же сказал(а), что со мной #from:zoe #delay:5m
      - else:
          Прочитано #sys:zoe #delay:5m
      }
  - -> END
  ```
- **Цена:** 3–6 реплик на «отстающего» кандидата.
- **Ловушки:** выравнивание объёмом без уязвимости не работает. У Дуга было мало сцен, где он раскрывается, а не просто мало строк.
- **Источник:** GI.

### PAT-08. Провал без обнуления (династия Reigns)
- **Когда применять:** глава с «плохим» исходом, после которого хочется переиграть. **Когда нет:** финал истории. Там провал — законный конец.
- **Схема:**
  ```
  попытка → провал → (пауза, новая глава) → персонаж помнит провал → попытка 2 с новой репликой
  ```
- **На ink:**
  ```ink
  # contact: ada, Ада, red
  VAR run = 0
  VAR lost_before = false
  -> night
  === night ===
  ~ run += 1
  {lost_before:
      в прошлый раз меня видели у двери. туда не пойду #from:ada #delay:20s
  }
  дверь или окно? #from:ada #delay:30s
  * [Дверь #to:ada]
      там свет. меня видели #from:ada #delay:1m
      Ада не в сети #sys:ada #delay:2m
      ~ lost_before = true
      {run < 2: -> retry}
      -> END
  * [Окно #to:ada]
      я снаружи #from:ada #delay:1m
      -> END
  === retry ===
  вернулась. давай ещё раз, по-другому #from:ada #delay:1h #chapter
  -> night
  ```
- **Цена:** одна реплика-воспоминание на каждый провал и лимит попыток.
- **Ловушки:** без лимита (`run < 2`) это бесконечный цикл, бот его найдёт. Вторая попытка с тем же текстом — это перезапуск, а не династия.
- **Источник:** AU, INV.

### PAT-09. Колода фоновых реплик вместо дерева (карточная система Reigns)
- **Когда применять:** повторяющееся ожидание (ночь, слежка, осада), где нужны разные сообщения на одну ситуацию и накопление состояния. **Когда нет:** сюжетные реплики. Случайность ломает авторский ритм и мешает боту сравнивать прогоны.
- **Схема:**
  ```
  цикл: случайная реплика из колоды → кнопка меняет счётчик → порог → выход
  ```
- **На ink:**
  ```ink
  # contact: tia, Тиа, lime
  VAR fear = 0
  -> loop
  === loop ===
  {~на лестнице кто-то есть|опять скрипнула дверь|свет в коридоре мигнул} #from:tia #delay:20s
  + [Не выходи #to:tia]
      ~ fear += 1
  + [Проверь #to:tia]
      ~ fear -= 1
  - {fear >= 2 || loop >= 4: -> hide}
  {fear <= -2: -> go}
  -> loop
  === hide ===
  я заперлась. до утра не выйду #from:tia #delay:1m
  -> END
  === go ===
  выхожу. если что — звони #from:tia #delay:1m
  -> END
  ```
- **Цена:** 3–6 вариантов реплики и счётчик. `+` — повторяемая кнопка, обычная `*` в цикле исчерпается, и история упрётся в тупик.
- **Ловушки:** у Reigns 770 карт, отбираемых по состоянию королевства (INV). Наш формат — авторская переписка, колоду держи маленькой и короткой (до 4 кругов).
- **Источник:** INV; синтаксис `{~…}` и `+` — знание модели об ink, высокая, проверено компилятором.

### PAT-10. Пауза длиной в дело героя (темп реального времени Lifeline)
- **Когда применять:** любая пауза от 10m. **Когда нет:** короткие паузы набора (секунды), они задают живой темп и в объяснении не нуждаются.
- **Схема:**
  ```
  выбор → персонаж называет дело и срок → #delay = длительность дела → первая реплика = результат дела
  ```
- **На ink:**
  ```ink
  # contact: sam, Сэм, teal
  VAR took_left = false
  -> night
  === night ===
  связь есть. я у развилки, фонарь садится #from:sam #delay:20s
  * [Налево, к реке #to:sam]
      ~ took_left = true
  * [Направо, к дороге #to:sam]
  - ок. идти минут сорок. напишу, как дойду #from:sam #delay:30s
  -> arrive
  === arrive ===
  {took_left:дошёл до реки. тут чья-то лодка|дошёл до дороги. машин нет} #from:sam #delay:40m
  * [Что видишь? #to:sam]
      {took_left:в лодке телефон. экран светится|на обочине куртка. моя} #from:sam #delay:1m
  * [Не трогай ничего #to:sam]
      поздно #from:sam #delay:1m
  - -> END
  ```
- **Цена:** одна реплика-анонс перед паузой и условная первая реплика после неё.
- **Ловушки:** срок в анонсе («минут сорок») расходится с `#delay` (2h). Игрок решит, что история сломалась. Первая реплика после паузы — «привет, я тут»: она не напоминает контекст. После паузы нужен результат дела, лучше зависящий от выбора до неё.
- **Источник:** [LLGD], [LLGA] (паузы по длительности действия, первое ожидание в час, сжатие к кульминации). Пример наш, проверен компилятором inkjs.

## Устройство систем из постмортемов

Здесь разобраны пять систем, которые студии описали достаточно подробно. Для каждой: элементы, шаги с входом и выходом, что ломается без шага, где систему понимают неправильно, как её ужать до короткой формы.

### SYS-1. Выбор → метка → память → реакция (Telltale, The Walking Dead)
- **Элементы:** выбор без правильного ответа, иногда с таймером; метка «X это запомнит»; журнал выборов; адресная реплика позже; сводка эпизода с долями других игроков.
- **Шаги:**
  1. *Выбор.* Вход: сцена, где оба варианта плохие [GB1]. Выход: запись в журнал. Таймер ставится, только если герой чувствует угрозу [GB2].
  2. *Метка.* Вход: запись. Выход: ожидание последствия у игрока. Наша интерпретация: без метки поздняя реакция кажется случайной. Метка без последствия читается как издёвка, даже если обмана не задумывали [GB3].
  3. *Реакция.* Вход: журнал. Выход: реплика или мелкая перемена позже. Ветка не нужна: ранние выборы не дают другой второй половины, они меняют, как персонажи помнят и отвечают [GB1]. Без этого шага метка — обман (LESSON-10).
  4. *Сводка.* Вход: журнал эпизода. Выход: экран 5 решений и сравнение с другими (TWD).
- **Неправильно понимают:** 1) как систему очков. Telltale от очков отказалась [GB2]. 2) как обещание крупной развилки. Студия сама называет игру во многом линейной [GB1]. 3) Думают, что неизбранный вариант ничего не стоит. Вэнамен говорит, что видимые, но не нажатые реплики тоже работают: они показывают, что можно было сказать [GB2].
- **Короткая форма:** шаги 1 и 3 в одной главе. Метку пишет персонаж («запомню»), реакция через 10–30 сообщений. Сводка — 2 строки в «Заметках» (PAT-06), без долей других игроков.

### SYS-2. Колода по состоянию мира (Reigns)
- **Элементы:** карта (персонаж, одна-две фразы, два свайпа); четыре шкалы королевства; вес каждой карты зависит от состояния; цепочки событий; смерть при крайнем значении шкалы; династия.
- **Шаги:**
  1. *Тянуть карту.* Вход: состояние. Выход: карта, чьи шансы выросли от состояния [GT]. Пул может сузиться до одной карты, и тогда идёт линейная нить [GT].
  2. *Свайп.* Вход: карта. Выход: сдвиг шкал. Последствие видно сразу.
  3. *Смерть → наследник.* Вход: шкала в крайнем значении. Выход: новый правитель, мир помнит прошлое (AU, INV). Без шага провал = перезапуск.
- **Неправильно понимают:** будто случайность заменяет автора. Персонажей писали вручную, от одиночных карт к аркам [GT] (LESSON-16).
- **Короткая форма:** у нас только фон (PAT-09) и династия (PAT-08). Идея «пул сужается до одной карты» переносится как хаб, который к концу главы оставляет одну кнопку.

### SYS-3. Маршрут из городов и переездов (80 Days)
- **Элементы:** город (необязательная прогулка), переезд (обязательный текст с выборами), шесть сквозных значений, карта как видимая структура, контекст выбора в названии направления.
- **Шаги:**
  1. *Выбор направления.* Вход: карта и знание мира. Выход: маршрут. Если у варианта нет контекста, выбор слепой — так было в Sorcery! [GDIGF80].
  2. *Переезд.* Вход: маршрут. Выход: сдвиг значений, встречи. Короткие фразы, частые мелкие выборы [IF50].
  3. *Город.* Вход: прибытие. Выход: новые маршруты за любопытство. Прогулку сделали пропускаемой (GD80). Без этого шага, при обязательной прогулке, — рутина на 200 тыс. слов.
- **Неправильно понимают:** считают, что ценность в объёме. Джаянт собирает отклик мелкими приёмами, а не уникальными ветками [CS]. Сама команда описывает выбор как блэкджек: каждый следующий рискованнее [GDIGF80].
- **Короткая форма:** контакт = город, разговор = прогулка, переход в следующий чат = переезд. Хаб из 2–3 контактов, каждый может закрыть новую кнопку (PAT-01).

### SYS-4. База с лимитом выдачи (Her Story)
- **Элементы:** поисковая строка; лимит в 5 клипов на запрос; клипы с несколькими смыслами; ручная подгонка частот слов.
- **Шаги:**
  1. *Запрос.* Вход: слово, которое игрок вынес из прошлого клипа. Выход: первые 5 клипов (PGB).
  2. *Просмотр.* Вход: клип. Выход: новые слова для запроса. Без лимита игрок увидит всё сразу и не будет выводить.
  3. *Подгонка автором.* Вход: частоты слов. Выход: правка базы, чтобы ключевое не находилось ни слишком легко, ни никогда (GDHS).
- **Неправильно понимают:** будто это случайный порядок без структуры. Порядок управляется частотами и лимитом.
- **Короткая форма:** у нас нет ввода. Переносится лимит (собеседник отвечает на один вопрос, не на все) и факт из двух половин (PAT-04). Результат формы: 100 тыс. копий за шесть недель [HS], при минимальном интерфейсе.

### SYS-5. Реальное время на уведомлениях (Lifeline)
- **Элементы:** один собеседник; два варианта ответа с экрана блокировки; пауза длиной в дело; плейсхолдер «занят»; смерть с откатом к выбору; Fast Mode после финала.
- **Шаги:**
  1. *Уведомление.* Вход: реплика. Выход: короткая встреча с выбором [LLGD]. Уведомление без выбора — шум.
  2. *Ответ.* Вход: 2 кнопки. Выход: реакция в характере: на подначку Тейлор отвечает обидой или сарказмом [LLGD].
  3. *Пауза.* Вход: названное дело. Выход: ожидание с понятным сроком [LLGA]. Без названного дела ожидание читается как поломка (RED-11).
  4. *Провал.* Вход: неверное решение. Выход: смерть, откат к выбору [LLW].
  5. *Повтор.* Вход: любой финал. Выход: режим без пауз [LLW].
- **Неправильно понимают:** будто удерживает ожидание. Удерживает выбор за каждым уведомлением и длина паузы, понятная по смыслу. Ожидание без этого и платный пропуск провалились (LESSON-04).
- **Короткая форма:** это и есть наш формат. Переносится целиком, кроме ответа с экрана блокировки: системных уведомлений у нас нет, только `toast` внутри открытой вкладки.
