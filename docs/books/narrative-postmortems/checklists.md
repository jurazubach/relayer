# Процедуры

Сокращения источников — в `README.md`, номера пунктов — в `principles.md`, `patterns.md`, `flags.md`.

## 1. Как придумать и начать историю

- [ ] **Сформулируй главный выбор финала одной строкой** и назови двух-трёх людей, которых он касается. Результат: строка вида «кому отдать запись: Джудит, Мае или Оуэну».
- [ ] **Для каждого из этих людей запланируй сцены до финала:** просьбу к игроку, уязвимость, момент, где он помог или подвёл. Результат: таблица «персонаж × глава», без пустых строк у кандидатов финального выбора (P-05).
- [ ] **Выбери 4–8 сквозных переменных** и запиши, где каждая показывается игроку. Результат: список VAR, у каждой — глава, где её назовёт персонаж (P-02, P-03).
- [ ] **Напиши только главу 1:** один собеседник в первые 3 минуты, к концу главы не больше 3 контактов (второй проход: `for-relayer.md` §6), один хаб с обязательным и необязательными разговорами, один выбор с оплатой в главе 2. Результат: глава проходит `check:story` без тупиков (P-14, PAT-01).
- [ ] **Поставь ставку в основную линию первых 10–15 входящих**, а не за кнопку. Результат: на карте узел со ставкой посещается не меньше чем в 90 % прогонов, лучше в 100 % (RED-10).
- [ ] **Сыграй главу 1 на настоящих паузах** и дай сыграть одному человеку, который не знает сюжета. Результат: записанные места, где он спросил «а что делать?», и места, где выбор казался очевидным (P-15, P-18).
- [ ] **Реши, остаётся ли форма.** Если глава не держит, меняй формат (контакты, ритм, роль игрока), а не дописывай главу 2. Результат: решение «продолжать / переделать» записано (P-14).

## 2. Как написать главу или сцену

- [ ] **Выпиши, какие прошлые выборы глава оплачивает.** Результат: минимум одна реплика, которая называет выбор из предыдущей главы (PAT-03).
- [ ] **Определи, что в главе обязательно, а что — по желанию.** Результат: обязательная линия без коридоров длиннее 12 входящих, необязательные чаты дают контакт, факт или кнопку (P-01, RED-01).
- [ ] **Если в главе хаб, проверь все пересечения фактов между ветками.** Результат: для каждого общего факта есть `{flag:...|...}` (PAT-05).
- [ ] **Ключевой факт главы раздели между двумя людьми.** Результат: откровение стоит за `{a && b}` или за двумя репликами разных контактов (PAT-04).
- [ ] **У каждого выбора-окраски проверь, что реплики после кнопок разные.** Результат: нет кнопок с одинаковым ответом (P-04).
- [ ] **Кнопки — 2–6 слов, тяжесть — в паузе и реакции.** Результат: ни одна кнопка без `#label` не длиннее 60 символов (P-12).
- [ ] **Перед каждой паузой больше 1h персонаж называет причину ухода.** Результат: у каждой такой паузы есть `#sys` «не в сети» или реплика «напишу после…» (RED-11).
- [ ] **Разметь заходы игрока.** Отрезки между паузами от 30m — 2–6 минут чтения, минимум две кнопки, в конце вопрос, обещание со сроком или `#unlock`. Результат: ни одного отрезка с RED-13 (P-19).
- [ ] **Если глава кончается выбором с последствиями, добавь сводку в «Заметки».** Результат: 2–5 строк состояния голосом героя (PAT-06).

## 3. Как провести ревью готового сценария

- [ ] **Прогони бота и выпиши распределение финалов.** Результат: доли всех финалов. Флаг, если один больше 50 %, а другой меньше 1 % (RED-08).
- [ ] **Найди VAR без чтения.** Результат: список, каждую оплатить или удалить (RED-02).
- [ ] **Посчитай сквозные переменные.** Результат: число VAR, которые пишут в одной главе, а читают в другой. Флаг при числе больше 10 (RED-04).
- [ ] **Для каждого выбора «между людьми» посчитай входящие от кандидатов до развилки.** Результат: соотношение. Флаг при перекосе больше 2:1 (RED-05).
- [ ] **Найди ветки-сёстры по 5+ строк, которые сходятся без записи переменных.** Результат: список на сжатие (RED-03).
- [ ] **Сравни объём глав.** Результат: строки и кнопки по главам. Флаг, если глава меньше 50 % медианы (RED-09).
- [ ] **Проверь переменные финала.** Результат: каждая переменная из условий последнего узла хотя бы раз названа игроку до развилки (RED-07, GREEN-07).
- [ ] **Сравни первую и последнюю главу по приёмам.** Результат: список тегов и приёмов, которых нет в главе 1 (RED-12, P-07).
- [ ] **Пометь выборы с «правильным ответом».** Результат: список кнопок, которые очевидно лучше соседних (P-18).

## 4. Как тестировать

- [ ] **Бот:** `npm run check:story`. Результат: 0 тупиков, все узлы посещены, длительность совпадает с `minutes`.
- [ ] **Карта:** `npm run graph -- --open`. Результат: найдены узлы с долей меньше 5 % и больше 20 строк — дорогой редкий контент (P-10).
- [ ] **Быстрый проход автором:** `?story=<id>&fresh=1&fast=1`, после каждой правки текста. Результат: правка проверена в игре за минуты, а не после сборки. Так Her Majesty писали с живой загрузкой текста (KOT, GDHM).
- [ ] **Живые тестеры на настоящих паузах:** 5+ человек, которые не знают сюжета. Результат: у каждого снят прогресс (`localStorage` → `relay:<storyId>`; кнопка `export` выгружает только саму историю) и записаны места «не понял, что делать». Журнала выборов в приложении пока нет, см. `for-relayer.md` §3 (P-15).
- [ ] **Сверка выборов тестеров с ботом.** Результат: выборы, где тестеры жмут одну кнопку чаще 70 % при равных вариантах. Это перекос знакомства (RED-05) или «правильный ответ» (P-18).
- [ ] **Застревание по смыслу:** спроси тестера в каждой паузе больше 1h, чего он ждёт. Результат: паузы, где ответ «не знаю», получают реплику с причиной и сроком (RED-11).
