# Процедуры

Каждый шаг — действие и ожидаемый результат. Ссылки ведут на principles.md (P), patterns.md (PAT) и flags.md (GREEN/RED).

## 1. Как придумать и начать историю (с расчётом на проверку)

- [ ] Сформулируй в одной строке цель игрока, ставку и срок. → Строка вида «помочь Элли найти, кто был у воды, до слушания через 4 дня».
- [ ] Напиши скелет: одна строка на сцену, все развилки и все финалы. → Файл скелета; для каждого финала понятно, каким выбором до него доходят (P-01).
- [ ] Собери скелет в ink (PAT-09) и прогони `check:story`. → Нет тупиков; ни один финал не берёт >50 % (RED-12).
- [ ] Проведи читку скелета на двоих (PAT-09). → Список мест, где «игрок» спросил «кто это?» или выбрал неожиданное.
- [ ] Напиши эталонный транскрипт главы 1 с пометками `[цель]`, `[ставка]`, `[крючок]` (PAT-01). → Цель стоит до 10-й строки, ставка — до первой паузы ≥1 ч на **каждом** маршруте главы 1 (RED-20).
- [ ] Посчитай новые имена до первого выбора. → Не больше 3, или каждое вводится своей репликой (RED-21).
- [ ] Проверь первую кнопку. → Она появляется не позже 8-й строки (GREEN-01), и среди вариантов есть «Промолчать» или отказ с реакцией (GREEN-08, RED-24).

## 2. Как написать главу или сцену

- [ ] Выпиши факты, которые к концу главы игрок должен знать, комментариями `// ФАКТ-n` (PAT-10). → 2–5 фактов на главу.
- [ ] Для каждой развилки запиши, что меняется: узел, переменная или только реплика. → Косметических кнопок в главе ≤60 % (RED-02).
- [ ] Для каждой новой переменной впиши эхо в этой или следующей главе (PAT-06). → Нет переменной, у которой первое чтение отстоит на ≥3 главы (RED-03).
- [ ] У каждого ответа в хабе есть реакция с новым фактом (PAT-08). → Нет узлов «≤1 строка и назад» (RED-01).
- [ ] Перед каждой паузой ≥1 ч стоит вопрос, угроза или незакрытое действие. → RED-05 пуст.
- [ ] Глава кончается крючком (GREEN-03). → Последние 3 строки содержат открытый вопрос.
- [ ] Строки с цифрами и временем внесены в таблицу фактов в шапке ink. → GREEN-05; дубли длинных строк вынесены в туннель (RED-16).
- [ ] Прогони `check:story`. → Новых недостижимых узлов нет; самый длинный кусок без кнопок ≤25 строк (RED-06).

## 3. Как провести ревью готового сценария (нарративный QA)

Делается в два прохода (P-02). Сначала поломки, потом впечатление.

**Проход A — поломки (бот и карта)**
- [ ] `npm run check:story`. → 0 неизвестных тегов, 0 тупиков, все узлы посещены (кроме `test_*`).
- [ ] Выпиши доли финалов по узлам `fin_*` (или по `ending`), а не по последним строкам из вывода бота. → Нет финала >50 % (RED-12). У финалов <1 % есть намёк (GREEN-07).
- [ ] Посмотри, в какой главе наступает каждый `END`. → <20 % прогонов кончаются до последней главы (RED-13).
- [ ] `npm run graph`: найди узлы с долей <2 %, которые не являются финалами. → Список с решением для каждого: оставить как награду или упростить вход (RED-11).

**Проход B — шесть списков нарративного QA (P-14).** Каждый сдаётся, даже если пустой («проверено, нет»).
- [ ] Хронология и факты: все времена, даты, суммы, числа, сверенные по таблице. → Список расхождений с узлами (RED-10).
- [ ] Голос: для каждого контакта выпиши 3 правила (регистр, длина, эмодзи, обращения) и найди нарушения. → Список строк, которые выбиваются (RED-08).
- [ ] Обрывы логики: персонаж знает то, чего ему не сообщали; ответ не на тот вопрос. → Список с узлом и тем, откуда персонаж «должен был» узнать.
- [ ] Пропущенные реплики: кнопка без ответа, ветка, где собеседник не реагирует. → RED-01, GREEN-08.
- [ ] Имена: написание по каждому говорящему и `#rename`. → RED-09.
- [ ] Орфография и пунктуация: выгрузи весь текст `ink` в файл и прогони проверку орфографии. Строчные буквы и сленг, которые входят в голос контакта, внеси в исключения. → Список опечаток с узлами.

**Проход C — ощущение выбора**
- [ ] Для каждого финала выпиши переменные, которые к нему ведут, и найди в тексте финала строку про каждую. → RED-25 пуст.
- [ ] Найди кнопки-одиночки подряд и кнопки, отличающиеся только словами. → RED-26, RED-27.

**Итог ревью:** таблица `ID флага | узел | симптом | решение`. Решения тестеров не копировать (P-05).

## 4. Как тестировать с людьми

**Подготовка сборки**
- [ ] Ревью из раздела 3 пройдено. → Тестеры не тратятся на то, что ловит бот (P-02).
- [ ] Вычитка орфографии (последний пункт прохода B). → 0 опечаток в главах, которые идут в тест ([Short]: выгрузить текст игры в файл и прогнать проверку орфографии до отправки).
- [ ] Если история не готова, после последней готовой главы стоит заглушка-конец (PAT-02).
- [ ] Для поздних глав готовы входы `test_*` с набранным состоянием (PAT-03).

**Набор и бриф**
- [ ] Набери тестеров обоих типов: 1–2 «ломателя» и 2–3 «обычных игрока» (P-07).
- [ ] Каждому отправь записку: срок; 1–3 вопроса автора; что не готово; список известных багов; форма отзыва (P-03).
- [ ] «Обычным» запрети `?fast=1` и отладочную шторку минимум на главы 1–2 (P-17).

**Форма отзыва (отдаётся тестеру)**
```
маршрут: имя/алиас, ключевые кнопки (или скриншоты с подписями)
по ходу: [время · чат] реплика → что подумал(а)       ← пометки с префиксом **
сцена не работает: узел или примерная реплика · почему
нестыковка: что с чем не сходится
понравилось: место · чем
итог: 3 строки — общее впечатление, главное, что починить
```

**Анкета после главы 1 и после финала.** Шкала 1–7 (1 — совсем не согласен, 7 — полностью согласен). Пункты 1–5 — пересказ пунктов [PTC] (там их семь; «легко читать текст» и «легко слышать диалоги» выкинуты, см. for-relayer §5), 6–9 — наши для формата. В [PTC] не сказано, какие пункты переворачивать, разметка (−) — наша. Пункты, помеченные (−), при подсчёте переворачиваются (8 − ответ).
1. Я легко понимал(а), что происходит в истории.
2. (−) Иногда мне было трудно понять, что происходит.
3. (−) Мне неясно, кто эти люди и чего они хотят.
4. (−) Мысли уходили в сторону, пока я читал(а) переписку.
5. Я сопереживал(а) кому-то из персонажей.
6. По манере письма я понимал(а), кто пишет, не глядя на имя.
7. Когда приходило уведомление, мне хотелось сразу открыть чат.
8. (−) Был момент, когда кто-то написал так, как этот человек написать не мог.
9. Мои ответы что-то меняли в истории.

Открытые вопросы:
- В каком месте хотелось закрыть приложение? (чат, примерная реплика) → «скучно»
- Где пришлось перечитывать или гадать, кто пишет? → «непонятно»
- Кому вы не поверили и в какой момент? → «не верю»
- Перескажите в 3 предложениях: что случилось, кто чего хочет, что будет дальше (PAT-10).

**Раунды**
- [ ] Отзывы принимай частями, по главам, а не одним письмом в конце. → Правки начинаются раньше ([Short]).
- [ ] После каждой волны сделай сводку: `узел | тип (скучно / непонятно / не верю / нестыковка / баг) | сколько тестеров | решение`. → Каждое место с ≥2 совпадениями закрыто или обосновано (P-06).
- [ ] Каждый баг сначала воспроизведи маршрутом и сохрани маршрут (P-16).
- [ ] Отправь тестерам список изменений с флажками. → Тестеры прошлой волны проверяют только его (P-08).
- [ ] В следующую волну позови хотя бы одного нового человека на главу 1 (P-08).
- [ ] Указывай тестеров в титрах и не вини их в багах, которые попали в релиз ([Short]).

**Разбор анкеты**
- [ ] Посчитай средние по пунктам 1–9 после переворота (−). → Пункт со средним <4 — главная проблема волны.
- [ ] Сопоставь: низкий 1–3 → чинить «непонятно»; низкий 4 и 7 → «скучно»; низкий 6 и 8 → «не верю»; низкий 9 → «выбор не ощущается» (flags.md, разделы).
- [ ] Шкальные данные сравнивай между волнами, а не с внешней нормой: пункты не валидированы ([PTC]).

## 5. Ранний групповой разбор скелета (по SYS-02)

- [ ] Собери 3–4 человека, из них 1–2 не пишут истории. → Состав записан. Никто из них не будет потом «свежим» тестером главы 1 (P-08).
- [ ] Раздай скелет главы: 10–15 строк, по одной на сцену, все развилки и финалы. → Прозы нет, только события и выборы (PAT-09).
- [ ] Каждый молча пишет 3 заметки: где не понял, где не поверил, где потерял интерес. → 9–12 заметок с привязкой к строке скелета.
- [ ] Автор сводит заметки сам: место · тип (скучно / непонятно / не верю) · сколько человек. → Таблица без имён авторов заметок.
- [ ] Обсуждение 15 минут, только про решения для мест с ≥2 заметками. → У каждого такого места решение или обоснование (P-06).
- [ ] Правки внесены в скелет до начала прозы. → Дата правки скелета раньше первой версии `ink` (P-01).

## 6. Быстрый тест истории на 5 минут (attention.md)

- [ ] `check:story` без ошибок, персоны `first`/`last` не приводят к одному финалу. → RED-28 пуст.
- [ ] Один свежий человек играет без `?fast=1`. Автор молчит. → Записано время до первой кнопки и место, где человек отвлёкся.
- [ ] Три вопроса после игры: «где хотелось закрыть?», «где гадал, кто пишет?», «кому не поверил?». Потом пересказ: что случилось, почему, что дальше. → Ответы размечены по типам (P-15, PAT-10).
- [ ] Починить места с ответами и позвать нового человека только на начало. → Первый крючок держит (attention.md §2).
