# Выжимка для relayer

## 1. Правила для генератора историй (в `docs/PROMPT.md`)

```
- Первая кнопка — не позже 8-й строки истории.
- До первой паузы #delay от 1h игрок на любом маршруте должен знать цель, ставку и срок. Ставь их в общий узел, а не в одну из веток.
- До первого выбора — не больше трёх новых имён. Если имён больше, вводи каждого его собственной первой репликой.
- Перед каждой паузой от 1h последняя строка — вопрос, угроза или незакрытое действие. Не «ок», не «спасибо», не «пока».
- Каждая глава кончается открытым вопросом.
- Не больше 25 строк подряд без кнопки игрока.
- У каждой кнопки есть реакция, отличная по смыслу от реакции на соседнюю кнопку. Если реакция одинаковая, это #me, а не выбор.
- Каждую переменную, которую меняет кнопка, упомяни репликой в этой или следующей главе, а не только в финале.
- Ветка хаба, в которой собеседник не отвечает, всё равно приносит факт: отказ, «прочитано», чужое имя.
- На «Промолчать» (#silent) собеседник реагирует: переспрашивает, обижается, пишет другому.
- Ни один финал не должен забирать больше половины прохождений. Если ранний финал срабатывает от одного ответа, перед ним нужен узел «последний шанс».
- Финал, который выбирает скрытая проверка, называет репликой хотя бы одну причину: что игрок сделал раньше.
- Не ставь выигрышную кнопку всегда первой или всегда последней.
- У каждого контакта три правила голоса (регистр, длина, эмодзи/пунктуация). Запиши их в characters[].about и не нарушай.
- Одно имя пишется одинаково у одного и того же говорящего. Разные формы — только у разных людей и намеренно (взрослый говорит «Лилиан», подростки — «лили»).
- Время, суммы и номера, которые встречаются больше одного раза, повторяются символ в символ. Длинную строку, нужную в нескольких узлах, вынеси в туннель.
- Комментарием `// ФАКТ-n:` пометь, что игрок должен знать к концу главы.
```

## 2. Автоматические проверки (`scripts/check-story.mjs` и карта)

Все данные уже доступны боту: текст, `currentTags`, `currentChoices`, `VisitCountAtPathString`, переменные через `story.variablesState`. Пороги — стартовые, калибровать на трёх историях.

| проверка | что считать | данные | порог | текст предупреждения |
|---|---|---|---|---|
| Доминантный финал | доля каждого финала. Сейчас бот группирует по последней строке, и один финал распадается на варианты (`fin_truth` в «Чужом голосе» — две строки). Группировать по последнему узлу `fin_*` (`currentPathString` перед `END`) или по переменной `ending` | `finals`, `variablesState.ending` | >50 % | `финал «…» забирает N % прохождений — проверьте развилку <узел>, из которой туда уходят чаще всего` |
| Узел-источник ловушки | для доминантного финала — последний узел с выбором перед `END`, и сколько его кнопок ведут в этот финал | путь `currentPathString` перед последним выбором | считать только для финала >50 % | `в <узел> K из M кнопок ведут в финал «…»` |
| Персоны | доли финалов у ботов `random/silent/talker/first/last` (PAT-04); `first` и `last` детерминированы, им хватает одного прогона | правило выбора по `tags` и индексу | у `first`/`last` один финал при `random` <50 %; у `silent` один финал 100 % |  `«всегда первая кнопка» в N % приводит к «…»: правильный ответ угадывается по позиции` |
| Ранний конец | глава (`#chapter` по счёту), в которой наступил `END`; если в истории есть узел-кульминация (имя передаётся флагом), то доля прогонов, прошедших через него | счётчик глав, `VisitCountAtPathString` | >20 % прогонов до последней главы или мимо кульминации | `N % прохождений кончаются в главе K из L` |
| Время до первого выбора | строки и сумма `#delay` до первого выбора | — | >8 строк или >60 с | `первая кнопка на строке N — игрок долго только читает` |
| Монолог | максимальная серия строк без выбора, с узлом | — | >25 | `в <узел> N строк подряд без кнопки` |
| Пауза без крючка | `#delay` ≥1h, перед которым последняя строка без «?» и есть в словаре закрывающих (`ок`, `ладно`, `спасибо`, `пока`, `понятно`, `до связи`) | текст + тег | любая | `пауза <D> после «…» в <узел>: нечем держать ожидание` |
| Косметические кнопки | для каждого выбора: варианты не уходят `->` и не содержат `~`, gather ближе 2 строк. Статически по исходнику или динамически: сравнить состояние после разных вариантов через `story.state.toJson()` минус счётчики | исходник / клон состояния | >60 % в главе | `глава K: N % кнопок ничего не меняют` |
| Эхо переменной | глава первой записи и первого чтения каждой `VAR` | исходник: `~ x` и `{x`… по узлам, номер главы по порядку `#chapter` | разрыв ≥3 главы | `<var>: меняется в главе A, впервые видна в главе B` |
| Мёртвая переменная | записывается, не читается | исходник | любая | `<var> нигде не проверяется` |
| Пустая ветка хаба | узел ≤1 текстовой строки, выход — в узел, из которого пришли | граф карты | любая | `<узел>: кнопка без ответа` |
| Реакция на молчание | после кнопки `#silent` до следующего выбора нет входящей строки | прогон | любая | `«Промолчать» в <узел> проходит незамеченным` |
| Кнопки-близнецы | у вариантов одного выбора расстояние Левенштейна <30 % длины | `currentChoices` | любая | `кнопки «…» и «…» почти одинаковы` |
| Одиночки подряд | `choices.length === 1` ≥3 раза подряд | прогон | ≥3 | `три кнопки-одиночки подряд в <узел> — это #me` |
| Профиль голоса | по каждому `#from`: средняя длина, доля строк с заглавной буквы, доля с точкой в конце, эмодзи на строку, `!!`/капс | текст + `#from` | строка вне 2σ по ≥2 признакам; контакты с <20 строками пропускать; строки `#photo` и `#sys` не считать | `<контакт> в <узел>: «…» не похоже на его голос` |
| Имена | все формы имён из `characters[].name` (основа слова + окончания) по говорящим | текст + `#from` | две формы у одного говорящего | `<контакт> зовёт Лили и «Лили», и «Лилиан»` |
| Таблица фактов | строки с `\d{1,2}:\d{2}`, `£\d+`, `\d+ (дн|час|мин)`, номерами | текст | одно и то же слово-якорь (имя, «слушание», «звонок») в окне ±3 слова от разных чисел | вывод таблицы `факт → узлы` для глаз; предупреждение при расхождении у одной сущности (эвристика, нужна ручная проверка) |
| Дубли текста | строки >60 символов в ≥2 узлах | исходник | любая | `строка «…» скопирована в <узлы> — вынесите в туннель` |
| Доля текста | медиана строк за прохождение / текстовые строки ink | прогон + исходник | только вывод | `за прохождение видно N % текста` |
| Редкие сцены | доля прохождений через узел, кроме финалов | `VisitCountAtPathString` | <2 % | `<узел> видят N % игроков` |
| Тестовые входы | узлы `test_*` не считать недостижимыми, но проверять, что из старта в них не попасть | статически: нет `-> test_` вне самих `test_*`; динамически: `VisitCountAtPathString('test_…') == 0` во всех прогонах | любое попадание | `<узел> достижим из игры — это тестовый вход` |
| Транскрипты | `--transcript N`: сохранить N прохождений разных персон в `.md` (`время · чат · кто · текст`, кнопки жирным) для чтения человеком | прогон | не проверка, а выгрузка | — |

На карте: подсветить красным узлы из «пустых веток» и «ловушек», показать у каждого финала доли по персонам, а у переменных — главу записи и главу первого чтения.

## 3. Идеи скиллов и команд

**`/story-review <id>`** — нарративный QA.
- *Когда:* перед тем как отдавать историю тестерам или после крупной правки.
- *Вход:* `src/stories/<id>.json`, вывод `check:story` с персонами.
- *Выход:* `docs/reviews/<id>-<дата>.md` с таблицей `флаг | узел | симптом | решение`, двумя проходами (поломки / впечатление) и шестью списками QA (P-14).
- *Шаги:* прогнать бота → разобрать доли финалов и ловушки → пройти шесть списков (checklists §3) → проверить ощущение выбора → не предлагать готовые реплики без указания симптома.

**`/story-transcript <id> [persona]`** — транскрипт для читки.
- *Когда:* нужно прочитать историю глазами игрока без 7 дней ожидания.
- *Вход:* история, персона бота, seed.
- *Выход:* `.md` с одним прохождением: время, чат, реплики, нажатые кнопки, маркеры `#chapter`.
- *Шаги:* прогон с seed → запись → в шапке маршрут (индексы кнопок) для воспроизведения (P-16).

**`/playtest-kit <id>`** — пакет для тестеров.
- *Когда:* перед волной теста.
- *Вход:* история, список известных проблем, вопросы автора.
- *Выход:* записка тестеру, форма отзыва, анкета (checklists §4), адрес со `?story=<id>&fresh=1`. Для «ломателей» — список входов `test_*`.
- *Шаги:* собрать известное → выбрать 1–3 вопроса → подставить в шаблоны.

**`/playtest-digest <id> <файлы отзывов>`** — сводка волны.
- *Вход:* отзывы и анкеты.
- *Выход:* таблица `узел | тип (скучно / непонятно / не верю / нестыковка / баг) | сколько тестеров | цитата-симптом | решение`, средние по анкете после переворота.
- *Шаги:* разметить каждое замечание узлом и типом → отделить предложения от симптомов (P-05) → свести совпадения → места с ≥2 вынести наверх (P-06) → предложить маршрут воспроизведения для багов.

**`/first-minutes <id>`** — проверка начала.
- *Вход:* история.
- *Выход:* для каждого маршрута главы 1: строка, где впервые есть цель, ставка, срок; число имён до первого выбора; первая пауза ≥1 ч и строка перед ней.
- *Шаги:* перебрать все маршруты главы 1 (их мало, полный перебор до первого `#chapter`) → найти пометки или спросить модель по каждому транскрипту «назови цель и срок» → флаги RED-20…24.

## 4. Разбор «Чужого голоса» (`chuzhoy-golos`)

Данные: `check:story` (400 прогонов) и наш прогон пяти персон по 300 раз с подсчётом финала по `ending` (перепроверено при ревью, октябрь 2026).

1. **Ловушка в `ch10_maya`.** Финал `fin_revenge` («Дэн бы сказал, что я дура.») получают 242–274 из 400 случайных прохождений (доля плавает от прогона к прогону). «Делай, что считаешь нужным» ведёт в него сразу. «Промолчать» ведёт через `ch10_maya_go`, где спасает только `tom_hold`. Даже «Подожди» уходит туда же при `maya_trust < 3`, если Джесс не призналась. Бот-«молчун» и «всегда последняя кнопка» получают этот финал в 100 % прогонов. Узел срабатывает только при `maya_target == "jess"`, иначе сцена пропускается. Игрок, который не выстроил доверие с Маей, уходит из сезона до сцены у двери (`ch10_door`), а ведь к ней вела вся десятая глава. **Чинить:** узел «последний шанс» между `ch10_maya_go` и `fin_revenge` (PAT-07), например Мая у дома Марш ждёт ещё одно сообщение. Ранний финал остаётся, но ведёт в него осознанный выбор.
2. **Выигрыш по позиции.** «Всегда первая кнопка» приводит к `fin_truth` в 100 % прогонов. Значит, в ключевых развилках правильный ответ стоит первым. Игрок, перепроходящий историю, заметит это за две главы. **Чинить:** перемешать порядок в узлах, где растут `proof`, `jess_bond`, `maya_trust`, и перегнать персону `first`: доля одного финала должна стать <90 %.
3. **Срок звучит не у всех.** О смерти Лили игрок узнаёт на любом маршруте через `ch1_jess`. Но срок («слушание у коронера через 4 дня») есть только в `ch1_party`, а туда ведёт одна кнопка из трёх в `ch1`. Остальные впервые слышат о слушании в `ch5_files`, и четыре дня ожидания идут без часов. **Чинить:** перенести две строки про слушание в `ch1_terms`, общий узел для всех маршрутов (RED-20).
4. **Пустые ветки хаба главы 1.** `ch1_beth` — это «Бет не в сети» и возврат в хаб. `ch1_kt` даёт «Прочитано», одно «кто это?» от Кирана, ответ игрока и уход Кирана в оффлайн. Это две из четырёх кнопок, открытых в первом хабе сразу (пятая, «Подождать Элли», открывается после Джесс), то есть половина первых самостоятельных действий игрока ничего не приносит. Последствие у Бет есть: в `ch2_beth` она извиняется («я вчера не ответила»), но в самой главе 1 кнопка выглядит пустой, а у `ch1_kt` нет и такого отклика. **Чинить:** PAT-08: «прочитано» и отказ с фактом (например, Бет упоминает полицейского, тем самым готовя `ch8_hart`).
5. **Финал без «потому что».** `ch10_route` складывает `proof` из пяти флагов. `fin_unproven` срабатывает по `else`, и в его тексте не сказано, какой улики не хватило. Игрок не видит, что его выборы глав 6–9 сработали (RED-25). **Чинить:** в `fin_unproven` и `fin_truth` по строке на каждую найденную или ненайденную улику (`bill_found`, `ladder_known`, `owen_turned`, `fake_note_caught`).

Что работает: первая кнопка на 6-й строке, через 17 секунд (GREEN-01). Отказ в `ch1_refuse` вызывает реакцию — перевод £12 «просто так» (RED-24 не срабатывает). Главы кончаются отдельными узлами-крючками `ch*_hook` (GREEN-03). «00:52» согласовано в пяти местах, но три копии детализации в `ch9_bill*` стоит вынести в туннель (RED-16). Формы «Лилиан» у Джудит и «лили» у Джесс — правильный голос, а не ошибка (RED-09 не срабатывает).

## 5. Что не подходит нашему формату

- **Транскрипт с комментариями внутри игры.** В парсерной IF тестер набирает `* комментарий` прямо в игре ([Short]). У нас ввода нет, только кнопки. Замена — скриншоты с подписями или будущая выгрузка транскрипта с полем заметки. Комментарий внутри чата `Заметки` использовать нельзя: это сюжетный контакт.
- **Проверка синонимов, глаголов и реакций по умолчанию** ([Short]: синонимы, граничные объекты, стандартные ответы библиотеки) нам не нужна: парсера нет. Ближайший аналог — неизвестные теги, их уже ловит бот.
- **10 000 прогонов и пороги CoG для статов.** Пороги рассчитаны на игры со статами и проверками по 1/X. У нас переменных мало, и они флаговые. Порог 1 % для «очень редкого» финала берём, а формулы баланса по числу статов — нет.
- **Ориентир 10–20 % текста за прохождение.** Это норма для длинных игр, рассчитанных на перепрохождение. Мы делаем историю на одно прохождение длиной в неделю реального времени, и 40 % здесь — сознательный выбор. Цифра полезна только для того, чтобы следить, как меняется ветвление.
- **Шкалы PTC про текст и звук** («легко читать», «легко слышать») для нас вырождены: у нас нет озвучки, а читаемость проверяют скриншоты. Их заменили пунктами про голос и уведомления.
- **Открытая бета на сотни человек** (практика Hosted Games). При неделе реального времени и без сервера сбор отзывов не масштабируется. Нам подходят 3–8 человек волнами.
- **Ранний нарративный ревью Ubisoft** в полном виде (6–10 человек, исследователь сводит заметки) рассчитан на студию. Шаги известны только по пересказу доклада (SYS-02), вопросов и метрик нет. Берём упрощённую версию на 3–4 человека (checklists §5).
- **Наше несогласие с источником.** Обсуждение в ifMUD склоняется к тому, что боты для впечатления бесполезны. Для переписки это неверно: темп (паузы, серии без кнопок, крючки перед паузами) — измеряемое свойство текста, и часть «скучно» бот находит раньше человека. Чего бот не сделает, так это не скажет «не верю».

## 2а. Проверки, добавленные при углублении

| проверка | что считать | порог | текст предупреждения |
|---|---|---|---|
| Затишье (по Overboard, LESSON-02) | серия входящих без выбора, `#photo`, `#unlock`, нового `#from`, `?` | >12 сообщений | `<узел>: N сообщений подряд ничего не происходит` |
| Петли подтверждения (LESSON-03) | выборы, из ветки которых `->` ведёт обратно в узел того же выбора | вывод списка рядом с долями финалов | `доли финалов искажены петлёй в <узел>` |
| Возвращение | первые две строки после `#delay` ≥3h: `?`, `#photo`, `#unlock`, другой `#from`, слово срока; отдельно — словарь приветствий | нет ни одного признака / первая строка — приветствие | `после паузы <D> в <узел> игрока встречает «…»` (GREEN-11, RED-29) |
| Длина сообщения | символы текста без тегов, кроме `#photo` | >90 предупреждение, >160 ошибка | `<узел>: сообщение N символов — разбейте` (RED-32) |
| Ночные уведомления | старт по флагу `--start 19:00`, часы прихода каждого сообщения после паузы ≥1h; число таких возвращений за сутки | приход 23:00–8:00 или >6 в сутки | `пауза в <узел> кончается в 03:40` (RED-33) |
| Журнал ходов | в сохранении `relay:<id>` есть список «узел · индекс · время» | отсутствие — задача на движок | — (LESSON-01) |

## 6. Согласия и противоречия с другими источниками

**Согласия** — правило подкреплено с двух сторон, берём без оговорок:
- Мёртвая или поздно прочитанная переменная (RED-03, RED-04) — то же, что emshort-structures:P-15, ashwell-standard-patterns:P-06, sheldon-character-storytelling:P-06, choiceofgames-design:P-10. Четыре источника требуют одну автопроверку.
- Бот и карта не равны опыту игрока (P-11) — ashwell-standard-patterns:P-14 (карта не показывает состояние), schell-art-of-game-design:P-17 (смотри на игрока, а не на граф).
- Проверять до прозы (P-01, SYS-02) — procedural-storytelling:P-01 (сначала простая версия), bateman-game-writing:P-12 (предскажи, где застрянут, и проверь на других), choiceofgames-design:P-17 (план до текста).
- Хранить историю ходов (P-04, P-16) — inkle-ingold:P-15 и тот же случай 80 Days (LESSON-01).
- Финал без «потому что» (RED-25) — schell-art-of-game-design:P-18, mystery-fair-play:P-12, choiceofgames-design:P-12.
- Длина серии без кнопки (RED-06, RED-31) — inkle-ingold:P-01 (80–100 слов), choiceofgames-design:P-13 (100–200 слов).
- Голос в нарративном QA (P-14) — nicklin-writing-for-games:P-03 (слепой тест), sheldon-character-storytelling:P-05 (проверяемые маркеры).
- Таблица фактов (GREEN-05, RED-10) — dille-ultimate-guide:P-04 (библия правды), procedural-storytelling:P-15 (реестр фактов).
- Пересказ «что, почему, что дальше» (PAT-10, SYS-05) — cron-wired-for-story:P-01 (на первом экране — чья история, что происходит, что на кону).
- Чтение случайного транскрипта (`--transcript`) — maass-fire-in-fiction:P-16 (случайный срез).
- Крючок перед паузой и событие после неё (attention.md §3) — messenger-genre:P-01, P-02, failbetter-qbn:P-14.

**Противоречия и как их решаем:**
1. **Порог первой кнопки.** У нас GREEN-01 — 8 строк и 60 с, у messenger-genre:P-04 — 30 с и 6 строк. Bury me, my Love пришлось переносить выборы в начало после отказа Apple (LESSON-06). *Решение:* 30 с и 6 строк — правило генератора, 8 строк и 60 с — порог ошибки в `check:story`. THE NUMBER (8 строк, 46 с) попадает в предупреждение.
2. **«Промолчать».** choiceofgames-design:P-04 не советует варианты «не участвовать», meaningful-choice:P-11 и наш GREEN-08 считают молчание ходом. К этому добавляется технический довод: повторы после молчания создают петли, которые перевзвешивают бота (LESSON-03, RED-30). *Решение:* `#silent` остаётся, но у него своё последствие, а повтор «ты тут?» даёт новую информацию и не повторяет тот же выбор дословно.
3. **Реакция на каждую кнопку.** Наше правило генератора и inkle-ingold:P-02 требуют своей реплики на каждую кнопку, failbetter-qbn:P-09 советует откликаться на немногое. *Решение:* немедленная реакция в одну строку — на каждую кнопку, это дёшево. Отложенный отклик (PAT-06) — на немногие, на те, где доля прохождений ≥2 % (LESSON-04, отсылки Telltale).
4. **С какой главы писать.** PAT-01 предлагает эталон главы 1 первым, choiceofgames-design:P-16 — писать первую главу после 2–3 других. *Решение:* скелет всей истории → эталон главы из середины → глава 1. Тестировать главу 1 при этом первой и на свежих людях (P-08): писать и проверять — разный порядок.
5. **Доля текста за прохождение.** CoG ориентируется на 10–20 % (P-13), ashwell-standard-patterns:P-10 и meaningful-choice:P-15 — трать ветки там, где их увидят. *Решение:* для истории на одно прохождение 40 % — норма. Метрика нужна, чтобы следить за изменениями, а не чтобы попасть в диапазон CoG.
6. **Может ли бот судить о скуке.** Участники обсуждения в ifMUD склоняются к «нет» (P-11). Overboard роняет автоигрок на «давно ничего не происходило» (LESSON-02), schell-art-of-game-design:P-01 строит кривую интереса по заменителям. *Решение:* бот ищет кандидатов в затишья (RED-31), человек подтверждает. «Не верю» остаётся только за человеком.
7. **Одни и те же тестеры или новые.** Short держит постоянных (LESSON-11), Bromley запрещает повторных на проверке понимания (SYS-05). *Решение:* разные роли — см. нюанс P-08 в principles.md.
