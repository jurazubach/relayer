# Процедуры

Ссылки `P-`, `PAT-`, `RED-`, `GREEN-` — на соседние файлы. Каждый шаг: действие → что должно получиться.

## 1. Придумать и начать историю

- [ ] Напиши фразу сущностного опыта в шапку ink: `// опыт: …` (P-16). → Одно предложение, где есть роль игрока и переживание.
- [ ] Нарисуй от руки кривую интереса всей истории по главам: крючок, 2–4 растущих пика, кульминация в последней главе, короткий спад (P-01, P-03, P-04). → Список глав, у каждой оценка 1–5 и самое сильное событие; последняя глава — максимум.
- [ ] Для каждой главы запиши три строки: сдвиг положения игрока (P-06), открытый вопрос, закрытый вопрос (P-13). → Таблица глав без пустых ячеек, кроме «закрыт» у первой.
- [ ] Разложи дистанцию: в какой главе событие впервые касается близкого игроку персонажа, в какой — самого игрока (P-08, PAT-08). → Номер главы для «ты» и для «я»; «я» — не позже середины.
- [ ] Напиши первые 3–8 сообщений до первой кнопки: вопрос к игроку или факт, которого нет в `synopsis` (P-02). → Первая кнопка не позже 8-го сообщения.
- [ ] Убедись, что центральный вопрос истории звучит текстом во всех ветках до первого хаба. → Поиск по ветвям первой главы: в каждой есть строка с этим вопросом или фактом.
- [ ] Перед хабом проводник даёт по одной строке о каждом контакте: зачем он нужен (P-10). → Игрок может выбрать, кому писать, по причине, а не наугад.

## 2. Написать главу или сцену

- [ ] Начни главу с крючка — первого сообщения после паузы, которое работает как уведомление (PAT-03). → Первая строка после `#chapter` — вопрос, угроза, новый контакт или факт.
- [ ] Построй лестницу: 2–3 пика, между ними передышки с полезной деталью (PAT-04, P-15). → Нет трёх тяжёлых узлов подряд.
- [ ] Перед каждой значимой кнопкой дай 2–5 сообщений нарастания желания (P-11). → У кнопок с `#label` выше в узле есть вопрос, ультиматум или угроза.
- [ ] В ключевой развилке дай безопасный и рискованный вариант, цену риска назови текстом (P-12, PAT-05). → Рискованный вариант меняет переменную; цена видна до нажатия.
- [ ] Если персонаж подталкивает к ветке, оставь кнопку против совета и награди её информацией (P-10, PAT-06). → Ветка «против» не короче трёх сообщений и содержит факт.
- [ ] Вставь одно удивление (P-14, PAT-09). → Ревьюер, знающий только `about`, его не предскажет.
- [ ] Передай одно событие формой: `#sys`, `#rename`, `#unlock`, другой канал (P-07). → В главе есть хотя бы один такой тег.
- [ ] Проверь каждую паузу ≥ 1 ч: перед ней — пик сеанса, после — новый крючок (P-05). → Нет первых сообщений после паузы вида «ок», «ладно», «я тут».
- [ ] Закончи главу открытым вопросом, который откроет следующую (GREEN-03). → Последнее сообщение главы нельзя прочитать как «всё, можно закрыть историю».
- [ ] Для каждой переменной, которую меняют кнопки главы, найди место, где она звучит в тексте (P-09). → У каждой `~ var` есть чтение `{var: …}` в этой или следующей главе.

## 3. Ревью готового сценария

- [ ] Прогони `npm run check:story` и замер кривой (PAT-01, `for-relayer.md` §2). → Таблица по главам: сообщения, выборы, максимум без выбора, паузы, очки интереса.
- [ ] Отметь главы, где максимум без выбора > 15 (RED-01). → Список узлов с длинными монологами.
- [ ] Выпиши первые сообщения после пауз ≥ 1 ч и пометь пустые (RED-02). → Список «узел — текст — пауза» с пометкой «чинить».
- [ ] Измерь развязку каждого финала (RED-03). → Для каждого `fin_*`: сообщений и часов после последней кнопки; > 10 сообщений или > 15 мин — чинить.
- [ ] Сверь форму кривой с эталоном: крючок, рост пиков, высший пик в конце (RED-07). → Вердикт «форма держится / провал в главе N».
- [ ] Разрежь главы на сеансы по паузам ≥ 1 ч и проверь каждый (GREEN-08, RED-15). → Список сеансов «узел начала — сообщений — где пик»; сеансы с пиком не в последней трети или длиннее 30 сообщений помечены.
- [ ] Для каждой главы проверь сдвиг, удивление, открытый и закрытый вопрос (RED-04, RED-05, RED-06). → Таблица без пустых ячеек.
- [ ] На карте найди узлы, где все кнопки сходятся и не меняют переменных (RED-09). → Список узлов; в каждом решено: оставить как бытовой ответ или добавить запоминание.
- [ ] Найди переменные, которые читаются только в маршрутизаторе финала (RED-10). → Для каждой — реплика, где персонаж её упоминает.
- [ ] Посмотри распределение финалов (RED-11). → Ни один финал не > 50 %; редкие финалы имеют видимые ступени.
- [ ] Проверь первую главу по разделу «Почему начало не цепляет» в `flags.md`. → Крючок до хаба, вопрос во всех ветках, у контактов хаба есть причина.

## 4. Тестировать

- [ ] Бот: 400+ прогонов, без тупиков и недостижимых узлов (`npm run check:story`). → Зелёный вывод.
- [ ] Бот: замер кривой и порогов из `for-relayer.md` §2. → Нет предупреждений или каждое снято комментарием `// peak` / `// намеренно` с причиной.
- [ ] Быстрый проход глазами: `?story=<id>&fresh=1&fast=1`, без пауз. → Отмечены места, где хочется пролистать, — их узлы.
- [ ] Живой тест в реальном времени на одного человека, без `fast` (P-17). → Протокол: для каждой паузы ≥ 1 ч время от уведомления до открытия; для каждой ключевой кнопки — время до нажатия.
- [ ] Попроси тестера нарисовать свою кривую интереса по главам от 1 до 5 после прохождения. → Сравнение с нашей оценкой; расхождение > 2 баллов — глава на разбор.
- [ ] Спроси тестера, какой финал он получил и почему, по его мнению (P-18). → Если причина не совпадает с условием в `ch*_route`, — RED-10.
- [ ] Сверь места, где тестер бросил или долго не возвращался, с провалами кривой. → Каждый провал объяснён узлом и сигналом из `flags.md`.
