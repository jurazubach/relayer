# Приёмы и структуры — Edgerton, Hooked

Все примеры ink проверены компиляцией inkjs. Теги — только из `docs/capabilities.json`. Сокращения источников — в `README.md`.

---

### PAT-01. «Пять сообщений» — каркас первой сцены (наш перевод четырёх первичных компонентов)
- **Когда применять:** начало истории и начало каждой главы, которая открывает новую линию. **Когда нет:** глава-продолжение, где проблема уже открыта, — там начинай сразу с её развития.
- **Схема:**
  ```
  0. #sys: время / место        ← setup, одна строка (P-05)
  1. входящее: инцидент          ← норма нарушена (P-01), это же превью (P-10)
  2. входящее: цена / срок       ← поверхностная проблема (P-02)
  3. входящее: странная деталь   ← предвестие глубинной проблемы (P-12)
  4. входящее: вопрос / просьба  ← адресовано игроку
  5. развилка: 2–3 реакции + #silent (P-09)
  ```
  Сообщений может быть 3–6. Главное — порядок: инцидент раньше объяснений, развилка не позже пятого входящего.
- **На ink:**
  ```ink
  # contact: mira, Мира, teal
  Глава 1 · Не тот адрес #sys:mira #chapter
  вторник, 02:14 #sys:mira
  ты забрал ключи от лодки? #from:mira #delay:20s
  не отвечай «какие ключи», не сейчас #delay:5s
  береговая охрана уже у причала
  на корме что-то лежит. под брезентом #delay:8s
  скажи что ты их забрал
  * [Вы ошиблись номером #to:mira]
      -> wrong
  * [Что под брезентом? #to:mira]
      -> tarp
  * [Промолчать #to:mira #silent]
      -> tarp
  === wrong ===
  нет #from:mira #delay:10s
  это номер ника. он сам мне его дал
  -> END
  === tarp ===
  не по переписке #from:mira #delay:30s
  -> END
  ```
- **Цена:** почти ноль текста. Тяжело другое: придумать инцидент, который одновременно странный, срочный и адресован игроку.
- **Ловушки:** слишком сжатое начало становится непонятным (см. `for-relayer.md` §5). Если игрок после пятого сообщения не может сказать, кто пишет и чего хочет, добавь одну строку завязки, а не абзац. Вопрос в п. 4 должен касаться инцидента, а не формы («ты же не бот?»).
- **Источник:** отрывок WD (первичные компоненты: инцидент, поверхностная и глубинная проблемы, завязка); раскладка по сообщениям — наш вывод.

### PAT-02. Предыстория по запросу (наш приём под P-06)
- **Когда применять:** у NPC много прошлого, которое игроку нужно знать. **Когда нет:** факт нужен, чтобы понять сам инцидент, — тогда одна строка прямо в каркасе PAT-01.
- **Схема:**
  ```
  реплика с дырой («со мной они не говорят»)
     ├─ + [вопрос А] → 1–2 сообщения прошлого ─┐
     ├─ + [вопрос Б] → 1–2 сообщения прошлого ─┤ (лимит вопросов)
     └─ * [к делу]  → дальше ←─────────────────┘
  ```
- **На ink:**
  ```ink
  # contact: ellie, Элли, amber
  VAR asked = 0
  -> brief
  === brief ===
  работа простая: пишешь им как студент #from:ellie
  + {asked < 2} [Почему они не говорят с тобой? #to:ellie]
      ~ asked += 1
      в июне я была там. с ней #from:ellie #delay:20s
      все думают, что я знаю больше #delay:6s
      -> brief
  + {asked < 2} [Кто «она»? #to:ellie]
      ~ asked += 1
      лили. в газетах всё есть #from:ellie #delay:15s
      -> brief
  * [Ладно. Давай номера #to:ellie]
      -> numbers
  === numbers ===
  вот первый. джесс #from:ellie #unlock:jess #delay:5s
  -> END
  ```
- **Цена:** одна петля и счётчик. Текста — столько же, сколько у монолога, только нарезанного.
- **Ловушки:** `+` без лимита даёт бесконечную петлю, а повтор той же реплики раздражает. Ставь счётчик или `*`. Если важный факт спрятан только за необязательным вопросом, игрок, который сразу нажал «к делу», останется без завязки. Факт, без которого не понять историю, должен быть в общем стволе (см. разбор `ch1_party` в `for-relayer.md`).
- **Источник:** отрывок WD (минимум предыстории в начале); механика — наш вывод.

### PAT-03. Эстафета поверхностных проблем (surface problem chain)
- **Когда применять:** между первой сценой и второй волной, особенно когда между ними стоит долгая пауза. **Когда нет:** финал главы, где нужна передышка, — но и там оставь глубинный вопрос.
- **Схема:**
  ```
  проблема А (Тео: «кто ты?») ── решена ──┐
                                           ├─ в той же реплике тень Б («не плати за бокс»)
  #delay:15m                               │
  проблема Б приходит из нового чата ←─────┘ (#unlock)
  ```
- **На ink:**
  ```ink
  # contact: theo, Тео, blue
  # contact: storage, Склад, grey
  -> theo_talk
  === theo_talk ===
  рэй? просто напиши что живой #from:theo
  * [Это не Рэй. Новый номер #to:theo]
  - понял #from:theo #delay:20s
  только не плати за его бокс. что бы ни писали #delay:6s
  #delay:15m
  -> storage_bill
  === storage_bill ===
  Склад: Р. Колдуэлл, бокс №114, долг 3 месяца. Через 48 часов — аукцион. #from:storage #unlock:storage
  * [Какой бокс? #to:storage]
      -> END
  * [Тео, мне пишут про бокс 114 #to:theo]
      -> END
  ```
- **Цена:** одна строка-тень на каждый переход между проблемами.
- **Ловушки:** тень не должна раскрывать Б целиком, иначе приход Б уже ничего не сообщит. Новые проблемы должны расти из первой, иначе выйдет набор эпизодов. Проверка: можно ли объяснить Б через А одной фразой.
- **Источник:** Beth Mad (поверхностные проблемы следуют одна из другой, глубинная одна); тень перед паузой — наш вывод.

### PAT-04. Глубинная ось (наш перевод story-worthy problem)
- **Когда применять:** в каждой истории, где больше одного финала. **Когда нет:** в коротком демо на один финал — там ось может закрыться репликой.
- **Схема:**
  ```
  гл.1: выбор ценности → VAR ось   (врать / сказать правду; помочь / уйти)
  гл.2…N-1: поверхностные проблемы проверяют ось (варианты по условию, реакции NPC)
  гл.N: условие финала читает ось
  ```
- **На ink:**
  ```ink
  # contact: ellie, Элли, amber
  VAR voice = ""
  ты пишешь им как студент? или как есть? #from:ellie
  * [Студент. Как договорились #to:ellie]
      ~ voice = "lie"
  * [Скажу правду #to:ellie]
      ~ voice = "truth"
  - -> finale
  === finale ===
  {voice == "lie":
      я знаю, что ты не студент #from:ellie #delay:2h
      -> END
  - else:
      ты хоть раз сказал им правду. мне этого хватит #from:ellie #delay:2h
      -> END
  }
  ```
- **Цена:** одна переменная и одно условие в финале. Дороже середина: ось должна хотя бы пару раз всплыть в реакциях NPC, иначе игрок забудет, что выбирал.
- **Ловушки:** если ось влияет только на текст финала, а выбор финала её не читает, игрок почувствует обман задним числом (RED-07). И наоборот: ось, которая решает всё одна, обесценивает остальные выборы — пусть она будет одним из условий. По Beth Mad, развязка глубинной проблемы приносит герою и выигрыш, и потерю: финал по оси лучше строить так, чтобы «правильное» значение тоже чего-то стоило.
- **Источник:** отрывок WD, Beth Mad (глубинная проблема связана с поверхностной и закрывается к концу); переменная — наш вывод.

### PAT-05. Каталог инцидентов для мессенджера (наш вывод под P-01)
- **Когда применять:** когда придумываешь первую сцену и нужен инцидент, который можно передать только перепиской.
- **Схема:** пять семейств. У каждого своя первая поверхностная проблема.
  ```
  адресат   — пишут не тебе / тебе как другому     → «кто ты?», «передай»
  доступ    — номер, аккаунт, код достались тебе    → «это не моё», чужие уведомления
  просьба   — работа, услуга, деньги вперёд         → «соглашаться ли?»
  тревога   — что-то сломалось / случилось сейчас   → «что делать в ближайшие 10 минут?»
  пропажа   — человек замолчал / «доставлено»       → «где он?»
  ```
  Сильнее всего работают два семейства сразу: THE NUMBER — доступ и пропажа, «Слепое пятно» — тревога и просьба.
- **На ink:** инцидент из семейства «доступ»:
  ```ink
  # contact: bank, Банк, lime
  # contact: unknown, Неизвестный номер, grey
  Банк: код для входа 4417. Никому его не сообщайте. #from:bank
  #delay:40s
  пришёл код? #from:unknown
  это мой аккаунт, твой номер у меня старый #delay:6s
  * [4417 #to:unknown #label:Переслать код]
      -> END
  * [Какой аккаунт? #to:unknown]
      -> END
  * [Промолчать #to:unknown #silent]
      -> END
  ```
- **Цена:** ноль, это инструмент выбора.
- **Ловушки:** семейство «просьба» в одиночку слабее всех. Пока в ней нет угрозы или странности, это рутина (так начинается «Чужой голос»). Добавь к ней странную деталь из другого семейства в первых трёх сообщениях.
- **Источник:** наш вывод на основе P-01, P-02.

### PAT-06. Завязка в карточке (setup offload, наш вывод)
- **Когда применять:** мир или роль игрока сложно объяснить перепиской за две строки: профессия, чужой город, жаргон. **Когда нет:** вся сила истории в том, что игрок не знает, куда попал (THE NUMBER). Тогда в карточке только роль, без фактов сюжета.
- **Схема:**
  ```
  карточка (synopsis, chapters[0].about, characters[].role) ← кто я, где, кто эти люди
  чат: сразу PAT-01, без объяснений из карточки
  правило: каждый факт, без которого первые 5 сообщений непонятны,
           есть либо в карточке, либо в самих сообщениях
  ```
- **На ink:** чат начинается с инцидента, завязка — в `title` и в `synopsis` файла:
  ```ink
  # title: Береговая · Не тот адрес
  # contact: mira, Мира, teal
  Глава 1 · Не тот адрес #sys:mira #chapter
  ник, ты где? лодка пустая #from:mira #delay:10s
  -> END
  ```
- **Цена:** правка `synopsis` и `characters[].role`.
- **Ловушки:** игрок может не читать карточку: в relayer по умолчанию «сразу играть». Значит, карточка снимает только «приятно знать», а критичный факт всё равно дублируется в чате одной строкой. Не раскрывай в `synopsis` инцидент, который должен ударить в чате: «Чужой голос» в карточке уже рассказывает про запись со счётом до трёх.
- **Источник:** наш вывод; основание — P-05 и возражение DeFreitas (README).

### PAT-07. Хвост перед паузой (open loop before delay, наш вывод под P-04)
- **Когда применять:** перед каждой паузой от 10 минут в первой и второй главе. Именно в паузе игрок закрывает вкладку.
- **Схема:**
  ```
  реплика-ответ → реплика-прощание → РЕПЛИКА-ХВОСТ (вопрос/угроза/тайна) → #delay:≥10m → вход
  ```
- **На ink:**
  ```ink
  # contact: jess, Джесс, pink
  -> talk
  === talk ===
  лили и элли весь вечер грызлись #from:jess
  * [Из-за чего? #to:jess]
  - не могу. мама зовёт #from:jess #delay:8s
  только не говори элли что это я сказала. она знает про куртку #delay:5s
  #delay:3h
  -> morning
  === morning ===
  ты ещё тут? #from:jess
  -> END
  ```
- **Цена:** одна строка на паузу.
- **Ловушки:** хвост на каждой паузе превращается в мыльный клиффхэнгер. Достаточно хвоста на паузах от 10 минут, а в середине главы хватает открытого вопроса без нажима. Хвост должен вести к проблеме, которая действительно придёт после паузы.
- **Источник:** наш вывод на основе Beth Mad (цепочка поверхностных проблем).

### PAT-08. Возвращение как малая первая сцена (наш вывод из P-01, P-04, P-10)
- **Когда применять:** первая реплика после каждой паузы ≥ 2 ч, особенно ночной. **Когда нет:** короткие паузы внутри сцены (секунды, минуты) — там игрок ещё в контексте.
- **Схема:**
  ```
  хвост: тень проблемы Б (конкретная вещь) → #delay:≥2h
  1-е входящее после паузы: Б пришла и сдвинулась (≤ 60 символов, понятна без чата выше)
  2-е: цена или срок
  кнопка не позже 3-го входящего
  ```
  Напоминание контекста вшито в событие: вещь из хвоста названа снова, но уже с новостью. Отдельного «напоминаю, вчера мы…» нет.
- **На ink:** (проверено компиляцией и прогоном inkjs)
  ```ink
  # contact: theo, Тео, blue
  # contact: storage, Склад, grey
  VAR paid = false
  -> evening
  === evening ===
  только не плати за его бокс #from:theo
  что бы ни писали #delay:5s
  * [Почему? #to:theo]
      потом. мне на смену #from:theo #delay:10s
  * [Ладно #to:theo]
  - #delay:2h
  -> morning
  === morning ===
  Склад: аукцион по боксу №114 перенесён на сегодня, 18:00. #from:storage #unlock:storage
  Оплата долга ещё возможна. #delay:6s
  * [Оплатить #to:storage]
      ~ paid = true
      -> theo_back
  * [Что в боксе? #to:storage]
      -> theo_back
  === theo_back ===
  {paid:
      ты заплатил?? #from:theo
  - else:
      склад тебе писал? #from:theo
  }
  -> END
  ```
- **Цена:** одна-две строки на паузу; самое дорогое — придумать, как проблема Б сдвинулась за время паузы.
- **Ловушки:** новость после паузы не должна требовать нового имени или термина (`attention.md`, «Нагрузка»). Если хвост был на одной ветке, а возвращение предполагает его на всех, игрок без хвоста получит «бокс 114» как непонятное слово (P-07): проверяй по веткам. Первое сообщение после паузы видно в уведомлении — к нему применяются A8 и P-10.
- **Источник:** наш вывод; основание — P-04 (дыра между проблемами), LESSON-05 (конец главы 1), Hammad и др., CHI 2021 (момент «щелчка» при возвращении; см. `attention.md`, §3).

## Нюансы к приёмам (второй проход)

- **PAT-01.** На 5 сообщениях все шаги каркаса не помещаются: шаги 2 и 3 (цена и предвестие) сливаются в одну строку, а шаг 0 уходит в заголовок главы. На 50 сообщениях каркас — только первая волна, и после развилки нужна вторая волна с новым фактом не позже чем через 10 сообщений (наша оценка). Не работает без строки «чего ты хочешь от меня» (LESSON-08): добавлять её в шаг 4, не отдельным сообщением.
- **PAT-02.** Не работает, если игрок не знает, о чём спросить: кнопки-вопросы должны называть дыру словами самого NPC («Кто „она“?»). Пустая кнопка «Расскажи подробнее» — пустое поле поиска (LESSON-07).
- **PAT-03.** Тень проблемы Б — предмет или число, а не настроение. На коротких историях эстафета из двух проблем; три и больше — уже для глав.
- **PAT-04.** На 5 минутах ось — одна развилка-дилемма и одно условие в последнем узле. Ось, которую игрок не узнаёт в финале, хуже, чем никакой: финал по оси начинается с отсылки к выбору («ты им так и не сказал»).
- **PAT-05.** Добавлено после LESSON-01: семейство «доступ» (чужой код, чужой аккаунт) сильнее всех рискует быть непонятным — у игрока нет ориентира, кто пишет. Нужна строка самопредставления в первых трёх сообщениях.
- **PAT-06.** Смягчено LESSON-06: в карточку можно отдать тему и направление (что кто-то погиб, что придётся говорить со свидетелями) без ущерба для удара. Нельзя — конкретику удара: кто, как, какой срок. Это граница RED-10.
- **PAT-07.** Хвост ведёт в PAT-08: если после паузы приходит не то, что обещал хвост, оба приёма теряют силу.
