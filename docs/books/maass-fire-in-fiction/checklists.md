# Процедуры

Коды `P-`, `PAT-`, `RED-` ведут в соседние файлы. Каждый шаг заканчивается результатом, который можно предъявить.

## 1. Как придумать и начать историю

- [ ] Назови общую ставку одной строкой (слушание, суд, увольнение, срок) и контакт, которому она грозит лично. → строка в `synopsis` и имя контакта (`P-10`).
- [ ] Назови угрозу самому игроку как персонажу (раскрытие, деньги, «тебя найдут»), даже если она проявится в главе 3. → строка в заметках автора.
- [ ] Для каждого контакта с ролью в финале запиши в `characters[].about` его главное чувство, противоположное ему чувство и «никогда бы не». → три коротких поля на персонажа (`P-01`, `P-12`).
- [ ] Набросай первую очередь до первой кнопки без дат, прошлого и посторонних имён. Последняя строка — вопрос, в котором слышно второе чувство. → 3–6 реплик, проверка `P-13`.
- [ ] Выпиши 3–5 вопросов сюжета, которые первая глава откроет, и главу, где каждый закроется. → таблица «вопрос → узел ответа» (`P-04`).
- [ ] Напиши лестницу ухудшения: по одной потере на главу и момент, когда она случится (лучше сразу после выигрыша). → список «глава → что отнято» (`P-09`, `PAT-06`).
- [ ] Для каждого раскрытия запиши два узла с намёками и один узел с последствием. → таблица «поворот → намёки → последствие» (`P-11`).

## 2. Как написать главу или сцену

- [ ] Запиши цель собеседника в этой сцене одной строкой. → цель есть или сцена — разговор без цели (тогда её держит только `P-01`).
- [ ] Придумай 2–3 шанса «получится» и 2–3 помехи. Чередуй их. → разметка «+ / −» в черновике (`P-08`, `PAT-04`).
- [ ] Назови поворот: какая реплика меняет ситуацию и в какой реплике собеседник звучит иначе, чем в начале. → две строки с именем узла (`P-07`).
- [ ] Пройди по каждой очереди реплик между кнопками: найди строку со вторым чувством, недомолвкой или трением. Нет — допиши или разрежь кнопкой. → у каждой очереди есть такая строка (`P-01`, `P-03`).
- [ ] Если в сцене угроза — найди реплику, где собеседник говорит о себе, и реплику с чувством не по жанру. → обе есть (`P-02`, `P-14`).
- [ ] В ключевом выборе назови жертву каждой кнопки. Если жертвы нет, переписать вариант. → у каждой кнопки есть цена (`P-05`, `PAT-08`).
- [ ] Если сцена — признание или рассказ о прошлом, разрежь его кнопками реакции не реже чем через 8 реплик и придержи один факт. → нет очереди ≥ 10 реплик одного контакта (RED-02).
- [ ] Последняя реплика перед долгой паузой — открытый вопрос или чувство без разрешения. → проверка глазами.

## 3. Как провести ревью готового сценария

- [ ] Запусти `npm run check:story` и эвристики из `for-relayer.md` §2: плоские очереди, монологи, узлы без поворота, эхо-кнопки. → список кандидатов с именами узлов.
- [ ] Для каждого кандидата «узел без поворота» ответь на три вопроса: что меняется, в какой реплике, как изменился собеседник. Нет ответа → вырезать или слить. Узлы-развилки, где только условия и `->`, пропускай. → решение по каждому узлу.
- [ ] Возьми 10 случайных отрезков по 8 реплик из разных прохождений, читай без контекста. Для каждого назови открытый вопрос и столкновение чувств. → не больше 2 пустых из 10 (`P-16`).
- [ ] Составь таблицу потерь по главам. → в каждой главе после первой есть потеря (`P-09`).
- [ ] Для каждого раскрытия проверь два намёка и последствие. → таблица заполнена или помечена RED-09.
- [ ] Для каждого контакта сравни голос в первой и последней главе. → в ссоре регистр меняется (RED-11).
- [ ] Для каждой переменной, которую меняет кнопка, найди первое место, где игрок видит последствие. → не только финал (RED-08).

## 4. Как тестировать

- [ ] Тест «что дальше» (по разбору сцены с пумой у Маасса): остановить читателя перед кнопкой и спросить, что сейчас случится. Если он не может назвать ни одного варианта или называет один очевидный, напряжения нет. → по 2+ гипотезы на ключевой кнопке.
- [ ] Тест «конкурирующие версии» (по WU-DMT): после каждой главы спросить, какие у игрока версии происходящего. → к середине истории у него 2–3 правдоподобные версии, а не одна.
- [ ] Посмотреть в отчёте бота кнопки, которые выбирают < 10% прохождений, но читатели-люди выбирают всегда (или наоборот). Расхождение значит, что один вариант очевидно правильный. → список выборов без колебания (`P-05`).
- [ ] Отметить, где живой тестер закрыл вкладку или пропустил уведомление больше чем на час. Сверить с плоскими очередями и узлами без поворота. → совпадения — первые на починку.

## 5. Построчная проверка переписки (микронапряжение)

Процедура для одного узла или главы. Коды те же, что у `/tension-pass` в `for-relayer.md` §3.

- [ ] Разбей узел на очереди: всё, что приходит между двумя кнопками (или между началом узла и первой кнопкой). → список очередей с номерами строк.
- [ ] Каждой реплике собеседника поставь коды: `Q` — открыт вопрос, `C` — два чувства рядом, `G` — слова расходятся с `#sys`, паузой или следующей репликой, `F` — трение между людьми, `T` — угроза или срок, `S` — игрок узнал то, что меняет понимание. Реплика без кода — нейтральная. → разметка по строкам.
- [ ] Очередь без `Q`, `C`, `G` и `F` — плоская, даже если в ней есть `T`: угроза без внутреннего чувства не держит (`P-01`, `P-02`). → список плоских очередей.
- [ ] Проверь последнюю реплику перед каждой паузой ≥ 10m: у неё должен быть `Q` или `C`. Игрок уходит из приложения с этой строкой в голове. → у каждой долгой паузы есть такой код.
- [ ] Проверь каждую кнопку: варианты получают разные ответы, и хотя бы один ответ несёт `C` или `F` (`RED-06`, `P-05`). → нет групп кнопок с одним и тем же «ок».
- [ ] Для каждой плоской очереди предложи одну строку правки: второе чувство (`P-01`), зазор (`P-03`, `PAT-02`) или разрез кнопкой (`RED-02`). Текст автора без подтверждения не переписывай. → таблица «очередь → предлагаемая строка».
- [ ] Посчитай долю плоских очередей в узле. → больше трети — узел на переписку целиком, а не на точечную правку.
