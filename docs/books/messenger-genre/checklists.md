# Процедуры

Ссылки на `P-`, `PAT-`, `RED-` ведут в соседние файлы.

## 1. Как придумать и начать историю

- [ ] **Сформулировать, зачем собеседнику нужен именно игрок**, одной строкой, которая прозвучит в первой сцене. Результат: реплика вида «со мной не говорят, с тобой будут» (`P-05`).
- [ ] **Выбрать масштаб реального времени:** сколько дней идёт история и сколько активных минут в день. Lifeline рассчитана на три реальных дня (IF50). Результат: строка для `synopsis` («идёт 4 дня, 10–15 минут в день»), см. RED-12.
- [ ] **Раскидать главы по сюжетным суткам.** Каждая ночь — граница главы или долгая пауза с причиной. Результат: таблица «глава → когда начинается → чем кончается → что приходит после паузы».
- [ ] **Решить, кто молчит и почему**: для каждой долгой паузы назвать причину (сон, смена, дорога, батарея). Результат: список причин без повторов подряд (`P-01`).
- [ ] **Собрать состав контактов:** основной собеседник, 1–3 второстепенных с разными сведениями, один незнакомый номер, по желанию один шумовой. Для каждого — что он знает такого, чего не знают другие. Результат: таблица «контакт → секрет → в какой главе открывается (`#unlock`)» (`P-10`).
- [ ] **Написать первые 6 строк:** первая реплика задаёт ситуацию, к 2–4 строке вопрос к игроку, первая кнопка до 30 секунд суммарного `#delay`. Результат: бот показывает первую кнопку до 30s (RED-01).
- [ ] **Выбрать носитель финала:** что придёт последним и в какой форме (`#photo`, перевод, новый контакт, системная строка). Результат: по строке на финал (`P-14`).

## 2. Как написать главу или сцену

- [ ] **Начать главу с новости:** первое сообщение после паузы приносит событие или вопрос. Результат: до первой кнопки ≤ 4 строк (`P-02`).
- [ ] **Разбить реплики на очереди:** 2–4 строки по 3–8s, между очередями иногда 1–5m. Результат: в сцене нет пяти пауз одной длины подряд (`P-03`).
- [ ] **Перед каждой развилкой с последствием положить улику** в этот или другой чат. Результат: для каждой такой кнопки можно назвать реплику-улику (`P-06`, `PAT-06`).
- [ ] **Хотя бы раз за главу перенести сведения между чатами** кнопкой `#to` по флагу. Результат: условная кнопка в другой чат и реакция получателя (`PAT-05`).
- [ ] **Отразить прошлые накопители**: одна реплика, которая звучит по-разному в зависимости от переменной, выставленной в прошлой главе. Результат: условие `{var: …|…}` в тексте главы (RED-11).
- [ ] **Проверить кнопки:** ≤ 40 символов или `#label`, 2–4 варианта, текст совпадает с отправленным (`P-07`, `P-13`).
- [ ] **Закончить главу крючком** перед долгой паузой: обещание, угроза или вопрос без ответа. Причина паузы названа (`PAT-02`, `PAT-01`).
- [ ] **Выровнять ночь:** если ветки главы разной длины, утренняя пауза выбирается флагом (`PAT-03`).

## 3. Как провести ревью готового сценария

- [ ] **Прочитать первые 30 секунд** (`?fresh=1`, без `fast`). Результат: ответ на вопросы «кто пишет, чего хочет от меня, почему мне» и время до первой кнопки.
- [ ] **Выписать все паузы ≥ 15m** с тремя строками до и двумя после. Результат: таблица; у каждой есть причина до и событие после, иначе RED-02/RED-03.
- [ ] **Пройти карту (`npm run graph`)**: отметить развилки в разные узлы. Для каждой назвать улику. Результат: список слепых развилок (RED-05).
- [ ] **Выписать все `#me`** и проверить, не упрекают ли игрока потом за их содержание. Результат: список подмен (RED-06).
- [ ] **Проверить переменные:** для каждой `VAR` — где меняется и где читается. Результат: список переменных, которые читает только финал (RED-11).
- [ ] **Посмотреть распределение финалов** в выводе бота. Результат: доля самого частого и самого редкого (RED-10).
- [ ] **Прочитать эпилоги:** сумма пауз после последней кнопки. Результат: ≤ 15 минут (RED-09).
- [ ] **Сверить сюжетные часы:** «спокойной ночи» → «доброе» не меньше 5h (RED-13).
- [ ] **Проверить текст на «правильный финал»:** нет слов «хорошая / плохая концовка» (`P-15`).

## 4. Как тестировать

- [ ] **`npm run check:story`.** Результат: 0 тупиков, все узлы посещены, распределение финалов без перекоса > 50% (RED-10; помнить, что бот группирует по последней строке, а не по `ending`), медиана реального времени совпадает с обещанием в карточке (RED-12).
- [ ] **Пройти первую главу в реальном времени** на телефоне, с закрытой вкладкой во время пауз. Результат: после каждого возвращения понятно, что произошло, без пролистывания вверх.
- [ ] **Пройти сюжет с ×60 в отладке**, отмечая моменты, когда хочется нажать «пропустить ожидание». Результат: список пауз-кандидатов на сокращение.
- [ ] **Проверить быстрый режим (`?fast=1`) на главе с переносом улик между чатами.** Результат: тосты из второго чата видны, нить не теряется.
- [ ] **Дать сценарий внешнему читателю** (раннюю сборку Bury Me, My Love проходили женщина, чья история легла в основу, и её сестра; были и обычные плейтесты, GD). Результат: где он в первый раз отвлёкся и какой выбор назвал случайным.
