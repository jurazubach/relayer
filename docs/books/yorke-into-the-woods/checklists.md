# Чек-листы — Yorke, Into the Woods

## 1. Как придумать и начать историю

- [ ] **Напиши финал первым.** Результат: 1–3 последних сообщения главного финала и список переменных, которые он читает (`P-10`).
- [ ] **Определи «дом» и «лес».** Результат: строка `// ДОМ:` (первый собеседник и привычная ситуация) и `// ЛЕС:` (контакты и мир, которые откроются по `#unlock`) (`P-01`).
- [ ] **Сформулируй ключевое знание середины.** Результат: `// СЕРЕДИНА:` — факт, после которого цель «A» становится целью «B» (`P-03`, `PAT-06`).
- [ ] **Расставь пять опор по главам.** Результат: строка `// ОПОРА вызов: … · поворот: … · середина: … · худшее: … · развязка: …` с именами узлов (`P-02`, `PAT-01`).
- [ ] **Наметь внутреннюю линию.** Результат: над каждой главой `// внешнее:` и `// внутреннее:` по одной фразе (`P-02`).
- [ ] **Сформулируй кризис как дилемму.** Результат: `// КРИЗИС: X ↔ Y` — две ценности, и у каждой кнопки названа потеря (`P-08`).
- [ ] **Выбери рамку.** Результат: `// РАМКА:` — образ из первых 10 входящих и его перевёрнутая версия в финале (`PAT-04`).
- [ ] **Напиши начало.** Результат: 3–6 входящих «дома» → вызов → кнопка отказа с ценой → ставка названа или показана намёком не позже 10-го входящего (`PAT-08`, `RED-01`).
- [ ] **Пометь ставку.** Результат: `// СТАВКА:` с 2–3 словами, по которым бот найдёт её первое появление.

## 2. Как написать главу

- [ ] **Возьми крючок прошлой главы.** Результат: первые 3 входящих отвечают на него или поднимают ставку, а не отменяют (`RED-07`).
- [ ] **Дай событие главы в первых 5 входящих.** Результат: новый `from`, вложение, `#unlock` или вопрос (`RED-02`).
- [ ] **Определи гостя главы, если сезон длинный.** Результат: контакт с `#unlock` в этой главе и строка `// ГОСТЬ: id — чего хочет — чем закончится` (`PAT-10`).
- [ ] **Распиши линии A/B/C, если чатов три и больше.** Результат: порядок чередования в комментарии (`PAT-09`).
- [ ] **Проверь каждую сцену на перемену.** Результат: у каждого узла есть `~`, факт, контакт или смена тона; над узлом `// вход → выход` (`PAT-03`).
- [ ] **Поставь открытие главы в её середину.** Результат: одна реплика-факт, после которой меняется, кому и о чём пишет игрок.
- [ ] **Дай дилемму ближе к концу.** Результат: развилка в разные узлы или с переменной, которую потом прочитают (`PAT-07`).
- [ ] **Закончи крючком-разворотом.** Результат: последнее входящее перед `#delay` ≥ 1h — вопрос, вложение или новый голос; закрывающая реплика стоит раньше (`PAT-05`).
- [ ] **Запиши сдвиг сезона.** Результат: над главой `// сдвиг: <переменная> — кто её читает`; переменная ставится в этой главе и читается позже (`P-16`, `RED-13`).
- [ ] **Сверь главу с её зеркалом.** Результат: для главы `k` записана рифма с главой `N+1−k` (`P-04`).

## 3. Как провести ревью готового сценария

- [ ] **Найди опоры.** Запусти бота и возьми медианный путь. Результат: таблица «опора — узел — доля»; всё, что вне коридоров `PAT-01` больше чем на 10 п. п., выписано.
- [ ] **Проверь середину.** Результат: да/нет — меняется ли после неё цель и адресаты игрока (`GREEN-02`, `RED-03`).
- [ ] **Проверь ход фортуны.** Результат: график доли отказов по главам; после середины он растёт (`P-05`, `GREEN-05`).
- [ ] **Проверь концы глав.** Результат: для каждой главы — последнее входящее перед паузой и пометка «разворот / закрытие» (`RED-04`).
- [ ] **Проверь кризис.** Результат: доля прохождений через финальную развилку ≥ 80%, у каждой кнопки названа цена (`RED-08`, `RED-09`).
- [ ] **Проверь рамку и возвращение.** Результат: найдена рифма первых 10 входящих с финалом; первый контакт есть в последней главе (`GREEN-03`, `RED-12`).
- [ ] **Проверь сцены без перемены.** Результат: список узлов по `RED-05`; для каждого решение «слить / добавить след / оставить».
- [ ] **Проверь антагониста и персонажей.** Результат: для антагониста — пары «успех игрока → его ход»; для каждого главного контакта — пара «самоописание ↔ противоречие» (`P-11`, `P-13`).
- [ ] **Проверь главы-филлеры.** Результат: для каждой главы — переменная, которую она оставляет сезону; главы без неё выписаны (`RED-13`).
- [ ] **Проверь темп второй половины.** Результат: Σ пауз и число входящих по главам; акт 4 короче акта 2 (`RED-06`).

## 4. Как тестировать

- [ ] `npm run check:story` — результат: нет тупиков; доля прохождений через узел `// ОПОРА развязка` ≥ 80%.
- [ ] `npm run graph` — результат: на карте видны узлы опор; у узла середины после него есть развилка с разными `#to`.
- [ ] Пройти главу 1 руками с `?fast=1` по самому короткому пути (всегда первая кнопка). Результат: номер входящего, где впервые понятна ставка, ≤ 10.
- [ ] Пройти главу 1 через кнопку отказа. Результат: отказ стоит чего-то и возвращает в ствол с памятью (`PAT-08`).
- [ ] Прочитать подряд только последние входящие каждой главы и первые три следующей. Результат: каждый переход — «вопрос → ответ/рост ставки» (`PAT-05`).
- [ ] Прочитать подряд первые 10 входящих и последние 5 каждого финала. Результат: рифма заметна (`PAT-04`).

## 5. Второй проход: стыки, паузы и короткая форма

- [ ] **Выбери число опор по длине.** Результат: до 15 минут — три опоры (`PAT-11`), от трёх глав — пять (`PAT-01`).
- [ ] **Проверь стык 1→2.** Результат: полная пауза стыка (Y17, а не только тег у `#chapter`) не длиннее медианы межглавных и ≤ 2h; последнее входящее главы 1 — крючок (`RED-14`, LESSON-02).
- [ ] **Проверь входы в главы.** Результат: в каждой главе после паузы первое входящее — напоминание или последствие, а не приветствие; первая кнопка — до 5-го входящего (`PAT-12`, `RED-15`).
- [ ] **Объясни каждую длинную паузу.** Результат: у каждого `#delay` ≥ 1h в трёх входящих перед ним есть причина (`GREEN-08`).
- [ ] **Посчитай всю паузу сезона.** Результат: Σ `delay` медианного пути ≤ 72h, иначе список пауз к сокращению (`RED-16`).
- [ ] **Проверь превью крючков.** Результат: ключевое слово каждого крючка — в первых 40 знаках сообщения (`attention.md` §3).
- [ ] **Проверь вопросы глав.** Результат: для каждой главы — строка `// вопрос главы → ответ`, ответ есть внутри главы (`RED-19`).
- [ ] **Пройди одну паузу по-настоящему.** Результат: прочитана очередь главы разом, как читает вернувшийся через сутки; первые 3 входящих понятны без памяти о прошлой главе.
