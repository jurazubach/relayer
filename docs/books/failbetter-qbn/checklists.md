# Процедуры

Опираются на процесс Failbetter: заявка → скелет с проверкой → проза → QA, которая занимает около трети времени написания ([F10]). Источники — в `principles.md`.

## 1. Как придумать и начать историю

- [ ] Запиши заявку в 6 строк: о чём, сколько глав, какие 2–4 качества держат сюжет, какой ресурс тратит игрок (время, доверие, улики), сколько финалов, что может пойти не так. → Есть файл-план, по которому видно, чем история отличается от линейной.
- [ ] Для каждого качества напиши строку `VAR` с комментарием: смысл, диапазон, кто поднимает, где читается (P-03). → 2–4 строки; новое качество без места чтения не заводится.
- [ ] Назови цель игрока одной фразой и решай, кто из персонажей будет озвучивать прогресс к ней (P-07). → Имя контакта и формат реплики-счётчика.
- [ ] Реши, где первый хаб: не раньше, чем игрок услышит ставку от одного голоса. → В плане главы 1 — один контакт до хаба.
- [ ] Назначь каждой главе одну структуру из `patterns.md` (хаб, цепочка, лестница, угроза). Хаб — только если в главе набирается 3–4 сторилета, один из них по состоянию (P-17); иначе прямая линия. → Таблица «глава — структура — качества».

## 2. Как написать главу или сцену

- [ ] Сначала скелет: все узлы, варианты, условия, `~`, по одной строке-биту на узел (P-01). → ink компилируется, в узлах по 1–2 реплики.
- [ ] Прогони `npm run check:story`. → Нет тупиков, глава проходится ботом.
- [ ] Проверь, что в главе читаются ≥ 2 переменные и хотя бы одна записана в другой главе (P-02, P-09). → Список чтений по главе.
- [ ] Порядок обязательных шагов — одной стадией, не набором флагов (P-04). → Нет условий из 3+ флагов.
- [ ] Перед каждым `#delay` ≥ 1h персонаж называет срок (P-08); первое сообщение после — новость и напоминание ставки (P-14, P-15). → У каждой длинной паузы есть пара «срок до / напоминание после».
- [ ] Для каждого рискованного варианта цена — переменная, которая потом читается (P-12, PAT-07). → Пара «запись — чтение».
- [ ] Поворотный выбор вынеси в отдельный узел после подводки (P-11). → Узел-подводка и узел выбора.
- [ ] Только теперь пиши реплики. Кнопки ≤ 12 слов, без чувств за игрока (P-16). → Глава готова к ревью.

## 3. Как провести ревью готового сценария

- [ ] Выпиши все `VAR`: записи, чтения, глава первого чтения. → Таблица; отметь читаемые ≤ 1 раза (RED-04) и без комментария (GREEN-02).
- [ ] Найди узлы маршрута финала и все переменные в их условиях. Для каждой — есть ли раньше реплика, которая показывает её значение (RED-01). → Список скрытых порогов.
- [ ] По `npm run graph` выпиши посещаемость финалов (RED-02) и узлов < 10 % (P-06). → Финалы вне 2–50 % помечены.
- [ ] Найди условия с 3+ флагами (RED-03), счётчики только вниз (RED-05) и хабы не того размера (RED-11). → Список с номерами строк.
- [ ] Проверь угрозы: у каждой есть видимый уровень и сцена на пороге (PAT-08, P-13). → Для каждой — узел провала.
- [ ] Проверь первую главу: одна ставка до хаба, цель названа, хотя бы одно условие по ответу игрока внутри главы. → Да/нет по трём пунктам.
- [ ] Отчёт: таблица флагов `RED-NN` с узлами и предложением правки. → Документ, по которому автор правит, не перечитывая всё.

## 4. Как тестировать

- [ ] Пройди историю сам от начала до конца в `?fast=1`, как Failbetter требует от автора перед QA ([F10]). → Заметки по узлам, где было непонятно, куда идти.
- [ ] `npm run check:story`: тупики, недостижимые узлы, длительность. → Чистый прогон.
- [ ] `npm run graph`: доли финалов и редких узлов. → Совпадают с замыслом из заявки (п. 1).
- [ ] Для каждого скрытого порога сыграй «на грани»: на единицу ниже и на порог. → Обе ветки осмысленны; разница объяснена репликой.
- [ ] Сыграй один раз «с перерывами»: закрывай вкладку на каждой паузе ≥ 1h и возвращайся; перед этим прочитай 5 реплик до паузы и 2 после подряд, без остального текста. → После каждого возвращения понятно, о чём речь (P-14, RED-14); после ночной паузы есть «Напомни» (PAT-11).
- [ ] Сыграй первые 3 минуты как новичок, по `attention.md` §2: к 30-й секунде есть кнопка, к 3-й минуте названа цель. → Отметки по трём точкам; что не выполнено — RED-13.
