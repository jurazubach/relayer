Термины: **quality** (качество) — числовая переменная персонажа: навык, предмет, отношение, стадия сюжета. **storylet** (сторилет) — кусок текста с условием входа по качествам, выбором и изменением качеств. **branch** (ветка) у Failbetter — вариант внутри сторилета, а не ветка дерева. В ink качество — это `VAR`, сторилет — узел `===` или вариант `* {условие} [...]`.

Общий разбор QBN по статье Short уже есть в `../emshort-structures/`; здесь — то, что добавляет сама студия: как она режет, считает и проверяет контент.

### P-01. Собери скелет из условий и эффектов до того, как писать реплики
- **Суть:** Failbetter требует от автора сначала играбельный каркас: все сторилеты, ветки, условия и изменения качеств, плюс по строке на каждый сюжетный бит. Прозу пишут после проверки каркаса на темп и «гринд».
- **Почему работает:** Ошибки структуры (тупик, лишнее ожидание, недостижимая сцена) дешевле всего чинить, пока на узле нет сорока реплик, которые жалко выбросить. Автор, который боится «с чего начать», начинает с таблицы, а не с первой реплики.
- **В relayer:** Первый проход — ink, где у каждого узла одна строка-заглушка с `#from` и `#delay`, все `VAR`, все `* {условие}` и `-> узел`. Сразу `npm run check:story` и `npm run graph`. Только потом настоящие реплики.
- **Пример:**
  ```ink
  # contact: dina, Дина, amber
  VAR car_known = false // знает ли игрок про машину у дома. читается: ch2_hook
  -> ch2_dina
  === ch2_dina ===
  [бит: Дина признаётся, что видела машину] #from:dina #delay:40m
  * [Какую машину? #to:dina]
      ~ car_known = true
  * [Промолчать #to:dina #silent]
  - -> ch2_hook
  === ch2_hook ===
  [бит: {car_known:Дина присылает номер|Дина замолкает до вечера}] #from:dina #delay:5m
  -> END
  ```
- **Как проверить:** Каркас проходит `npm run check:story` без тупиков; в каждой главе (`#chapter`) есть хотя бы одна запись `~` и одно чтение переменной. Пока это не так, в узлах не больше 3 реплик (считается по строкам с `#from`/`#me` между заголовками `===`).
- **Источник:** [F10] (planning and midflight check).

### P-02. Заводи как можно меньше качеств, но не меньше двух на кусок
- **Суть:** Студия называет это parsimony (бережливость): каждое новое качество усложняет экономику, рождает баги и забывается игроком. При этом кусок контента с одним качеством превращается в простую цепочку или «гринд»; два — минимум для интересной структуры.
- **Почему работает:** Память автора и игрока. 80 переменных никто не держит в голове, и половина из них читается один раз. Одно качество даёт только «больше/меньше», два — уже напряжение между ними (доверие против улик).
- **В relayer:** Перед новым `VAR` спроси: можно ли выразить это уже существующей переменной? Флаги-проходы вида `c7_ellie_out` заменяй проверкой посещения узла (`{ch7_gate}` в ink). В главе должны работать хотя бы две переменные, которые читаются в этой же главе.
- **Пример:**
  ```ink
  // было: VAR asked_tom = false, VAR tom_angry = false, VAR tom_helped = false
  VAR tom = 0   // отношение Тома: −2…+2, читается в ch3 и ch5
  ```
- **Как проверить:** Скрипт: доля `VAR`, у которых ≤1 чтения; в «Чужом голосе» это 22 из 80. Порог для предупреждения — больше 20 %. Глава, где читается меньше двух разных переменных, — кандидат в «цепочку».
- **Источник:** [F5] (parsimony: мало качеств), [F11] (два качества — минимум для интересной структуры, иначе цепочка или гринд), [F4].

### P-03. Дай каждому качеству одно значение и запиши его рядом
- **Суть:** Качество, которое в одной сцене значит «доверие», а в другой «сколько раз помог», ломает логику и позволяет обходить условия. Failbetter требует к каждому качеству заметку (quality note), понятную человеку без контекста.
- **Почему работает:** Через месяц автор (или генератор) поднимет `trust` не за то, за что его проверяет финал, и условие начнёт срабатывать случайно.
- **В relayer:** Комментарий на строке `VAR`: что значит, диапазон, кто поднимает, где читается. Генератору — то же правило.
- **Пример:**
  ```ink
  VAR maya_trust = 0  // верит ли Мая, что Элли невиновна. 0..4. +1 за проверяемый факт. читается: ch7_maya_pull, ch10_maya (>=3)
  ```
- **Как проверить:** Каждая строка `VAR` с числом имеет комментарий; все `>=`-пороги в коде попадают в объявленный диапазон.
- **Источник:** [F4] (parsimony of qualities: одно значение), [F11] (quality notes).

### P-04. Держи порядок событий одним счётчиком
- **Суть:** Нарратив на качествах плохо держит последовательность, если она собрана из нескольких независимых условий. Когда сцены должны идти строго по порядку, ими управляет одно качество-стадия.
- **Почему работает:** Пять флагов дают 32 комбинации, из которых автор проверил три. Одна стадия даёт ровно столько состояний, сколько шагов.
- **В relayer:** Внутри главы-хаба порядок обязательных битов — через `stage`, а не через `a && !b && c`. Главы сами по себе — уже такой счётчик.
- **Пример:**
  ```ink
  # contact: dina, Дина, amber
  VAR stage = 1 // шаг разговора с Диной о машине: 1..3, только растёт
  -> photo
  === photo ===
  * {stage == 1} [Покажи мне фото #to:dina]
      ~ stage = 2
      -> photo
  * {stage == 2} [Это его машина? #to:dina]
      ~ stage = 3
  - -> END
  ```
- **Как проверить:** Условие на варианте или в `{ - ... }` с тремя и более флагами через `&&`/`||` — предупреждение «замени стадией».
- **Источник:** [F4] (keep it simple).

### P-05. Пусть счётчики растут, а не убывают
- **Суть:** Игрок ждёт, что число начинается с малого и растёт. Качества, которые считают вниз, путают, особенно рядом с растущими.
- **Почему работает:** Ожидание. «Подозрение 3» читается как «уже много», «осталось попыток 3» требует пересчёта в голове.
- **В relayer:** Игрок числа не видит, но видит автор и генератор: `suspicion` от 0 вверх, а не `patience` от 5 вниз. Если в истории есть отрицательное направление — отдельная угроза (P-12), а не минус у доверия.
- **Пример:** `~ suspicion += 1` и `{suspicion >= 3:` вместо `~ patience -= 1` и `{patience <= 0:`.
- **Как проверить:** Скрипт: переменная, которую только уменьшают (`-=`) и сравнивают с `<=`, — предупреждение.
- **Источник:** [F9] (qualities should count up).

### P-06. Строй реку, а не дерево
- **Суть:** Большую часть контента должен видеть почти любой игрок; студия называет ориентир около 90 % для одного персонажа. Контент, видимый только при редкой комбинации многих качеств, — это combinatorial explosion (комбинаторный взрыв).
- **Почему работает:** Каждая реплика стоит денег и времени. Сцена, которую видит 2 % игроков, почти не окупается и почти не тестируется.
- **В relayer:** Ветки должны расходиться и сходиться, а различия жить в переменных и в нескольких репликах. Редкое — только финалы и одна-две «награды» за редкую комбинацию.
- **Пример:** «Чужой голос»: около 85 из 165 узлов проходит ≥ 90 % ботов — это река. Но `fin_puppet` (около 1 %) и `fin_herself` (2–4 %) требуют совпадения нескольких условий.
- **Как проверить:** По `npm run graph`: доля узлов с посещаемостью < 10 % (кроме финалов) больше 10 % — предупреждение; финал < 2 % или > 50 % прохождений — предупреждение.
- **Источник:** [F5] (river, not tree; ориентир ~90 %), [F7] (combinatorial explosion).

### P-07. Показывай, сколько осталось до цели
- **Суть:** Игроку нужна цель или выбор между целями, и видно, насколько он от неё далеко. Ключевые шаги сюжета лежат там, где игрок их видит; случайное — только для сюрпризов.
- **Почему работает:** Ожидание с понятным горизонтом выдерживается, ожидание без горизонта превращается в скуку. Скрытый порог (`proof >= 3`) игрок не может ни добивать, ни бояться.
- **В relayer:** Числа на экране у нас нет, поэтому прогресс озвучивает персонаж: «у нас два факта из трёх», «ещё одна такая выходка — и я пишу в полицию». Заметки (`#from:notes`) — удобное место для списка «что известно».
- **Пример:**
  ```ink
  # contact: judith, Джудит, teal
  VAR proof = 2 // факты для полиции: 0..3, порог финала >= 3
  { proof:
  - 1: Один факт. Для полиции мало. #from:judith #delay:5m
  - 2: Два. Нужен ещё один, и я подпишу. #from:judith #delay:5m
  }
  -> END
  ```
- **Как проверить:** Для каждой переменной, которая сравнивается с порогом в узле выбора финала, есть хотя бы одна условная реплика с её значением в предыдущих главах. Нет — предупреждение «скрытый порог».
- **Источник:** [F6] (дать цель и показать, сколько до неё осталось; ключевые шаги — в постоянно доступных сторилетах, случайные — для сюрпризов); [S1] (у QBN связь между накопленным ресурсом и его использованием легко теряется из памяти игрока).

### P-08. Покажи орудия: длину испытания видно заранее
- **Суть:** В жёстком контенте игрок готов страдать, но хочет знать, сколько. Студия формулирует это как «show them the implements» (покажи им орудия пытки).
- **Почему работает:** Неопределённая длина неприятного отрезка ощущается дольше реальной; известная — терпится и даже предвкушается.
- **В relayer:** Перед долгой паузой или тяжёлым эпизодом персонаж называет срок: «до утра я молчу», «слушание в 10:00». Двухчасовой `#delay` без объявления — худший вариант.
- **Пример:**
  ```ink
  # contact: ellie, Элли, amber
  -> ch4_end
  === ch4_end ===
  меня забирают на допрос. телефон отдам #from:ellie #delay:1m
  до утра не пиши #delay:20s
  -> ch5
  === ch5 ===
  День 5 · Утро #sys #chapter #delay:8h
  отпустили. ты не поверишь, что они спрашивали #from:ellie #delay:1m
  -> END
  ```
- **Как проверить:** Скрипт: `#delay` ≥ 1h, перед которым в последних трёх репликах нет слова со временем (утро, ночь, час, завтра, цифры) — предупреждение.
- **Источник:** [F4] (show them the implements).

### P-09. Записывай почти каждый выбор, откликайся на немногие
- **Суть:** Большинство решений игрока стоит сохранить в качествах, но последствий писать мало: время от времени мир вспоминает прошлый поступок. Реакция на всё сразу ведёт к комбинаторному взрыву.
- **Почему работает:** Редкий отклик воспринимается как доказательство, что история помнит всё, — игрок экстраполирует. Отклик на каждую кнопку раздувает текст без заметной пользы.
- **В relayer:** 126 кнопок «только реплика» в «Чужом голосе» — дешёвый материал: поставь на часть из них `~ tone += 1` и раз в главу верни одну реплику-колбэк.
- **Пример:**
  ```ink
  # contact: tom, Том, cyan
  VAR called_rude = false // нагрубила ли Тому в главе 2. читается: ch5_tom
  -> ch5_tom
  === ch5_tom ===
  {called_rude:
      ты тогда мне нагрубила. но ладно #from:tom #delay:2m
  }
  я нашёл, где стоит катер #from:tom #delay:1m
  -> END
  ```
- **Как проверить:** На каждую главу хотя бы одно чтение переменной, записанной в другой главе. `called_bluff`: одна запись, ноль чтений — потерянный выбор.
- **Источник:** [F7].

### P-10. Дели решение на несколько маленьких выборов и не повторяй сделанный
- **Суть:** Пять выборов из двух вариантов интереснее, чем одно меню из десяти, из которого выбирают пять раз. Вариант, который игрок только что взял, сразу предлагать снова бессмысленно.
- **Почему работает:** Короткий выбор читается целиком; длинный список утомляет и размывает каждую опцию. Повторённый вариант сообщает, что первый выбор ничего не изменил.
- **В relayer:** 2–3 кнопки на узел; хаб «кому написать» из 5+ вариантов — исключение, и вариант после использования исчезает (`*`, а не `+`).
- **Пример:** вместо одного хаба на 6 контактов — два хаба по 3 в разных частях главы.
- **Как проверить:** Скрипт: точка выбора с > 4 вариантами; липкий `+` вариант, который ведёт обратно в тот же хаб без изменения переменных.
- **Источник:** [F7].

### P-11. Большой выбор готовь отдельным узлом
- **Суть:** Сложную ситуацию трудно передать в тексте кнопки. Для поворотного решения сначала ситуация в одном сторилете, потом выбор — в следующем.
- **Почему работает:** Игрок принимает решение, когда понял ставки. Если ставки и выбор в одном экране, он жмёт по первому впечатлению и потом чувствует себя обманутым.
- **В relayer:** Узел-подводка из 4–8 реплик с ясной ценой каждого пути, затем `#delay` 1–5 минут и узел с 2–3 кнопками с `#label`.
- **Пример:** PAT-10.
- **Как проверить:** Для каждой точки выбора, где пишется переменная, читаемая в маршруте финала (`~ final_choice =` или аналог): в том же узле до первой `*` стоит ≥ 3 реплик, или в узел ведёт ровно один переход из узла без вариантов, где ≥ 3 реплик.
- **Источник:** [F7].

### P-12. Обозначай трудность ценой, а не словами
- **Суть:** Не пиши в тексте, что задача трудная: у игрока может быть такое состояние, при котором она лёгкая, и текст соврёт. Сообщай успех или провал, а трудность показывай тем, что за попытку надо заплатить.
- **Почему работает:** Доверие к тексту. Фраза «это почти невозможно» после гарантированного успеха делает весь текст декорацией.
- **В relayer:** Кнопка с риском прямо называет цену в `#label` или ответе персонажа: «если спросишь — она поймёт, что ты знаешь». Цена — переменная, которая потом читается.
- **Пример:**
  ```ink
  # contact: tom, Том, cyan
  VAR tom_suspects = false // понял ли Том, что игрок копает. читается: ch6_tom
  * [Скинь пароль от группы #to:tom #label:Попросить пароль — Том поймёт, что ты копаешь]
      ~ tom_suspects = true
  * [Ладно, сама найду #to:tom]
  - -> END
  ```
- **Как проверить:** Скрипт-кандидат: реплика, совпавшая с `/сложн|рискован|невозможн|опасн|почти нереальн/i`, в последних 3 строках перед `*`, а ни в одной ветке этого выбора нет `~`. Дальше глазами.
- **Источник:** [F8].

### P-13. Делай провал драматичным откатом, а не потерей очков
- **Суть:** Провал записывают уменьшением прогресса или ростом угрозы (menace — качество-проблема вроде ран или скандала). Когда угроза зашкаливает, нужна заметная, запоминающаяся беда: потерянный прогресс игрок забудет, яркий провал — нет.
- **Почему работает:** Эмоция и память. Про «−1 доверие» никто не расскажет другу, про «меня заблокировали посреди допроса» — расскажут.
- **В relayer:** Угроза — растущий счётчик (P-05) с порогом, на пороге — сцена: контакт блокирует, уходит в полицию, публикует пост. После этого история продолжается, не обрывается.
- **Пример:** PAT-08.
- **Как проверить:** Для каждой переменной-угрозы на пороге есть отдельный узел с ≥ 3 репликами; бот доходит до него хотя бы в 5 % прогонов.
- **Источник:** [F8]; Fallen London: при высокой угрозе персонаж попадает в отдельную локацию, где её надо отработать — [W] https://en.wikipedia.org/wiki/Fallen_London.

### P-14. Напоминай, где игрок остановился
- **Суть:** Игроки приходят урывками и делают перерывы, поэтому в контенте нужны напоминания: подсказка о следующем шаге и отдельная ветка-напоминание в главных сценах.
- **Почему работает:** Память. После перерыва игрок не помнит, о чём шла речь и чего от него ждут, и уходит из «непонятной» истории.
- **В relayer:** У нас перерыв встроен: `#delay:2h`, `#delay:7h`. Первое сообщение после долгой паузы напоминает ставку одной строкой («слушание через час, а Оуэн так и не ответил»). Начало главы — то же.
- **Пример:**
  ```ink
  День 3 · Город #from:judith #sys:judith #chapter #delay:7h
  Доброе утро. Слушание через два дня. #from:judith #delay:1m
  Вы так и не сказали, кто такая Бет. #delay:20s
  ```
- **Как проверить:** Скрипт: после `#delay` ≥ 2h первая реплика не упоминает ни контакта, ни сущности из прошлой главы — предупреждение для ревьюера (точно не посчитать, только кандидаты).
- **Источник:** [F11] (reminders, players play in spurts).

### P-15. Пиши опорные точки, а переходы между ними оставь игроку
- **Суть:** Failbetter называет это fires in the desert (костры в пустыне): сторилеты — освещённые точки, дорогу между ними игрок достраивает сам. Не объясняй каждый пропуск времени и каждую неясность.
- **Почему работает:** Воображение игрока заполняет промежуток лучше и дешевле автора; монтаж ощущается как собственная история.
- **В relayer:** Паузы делают это за нас: между `#delay:5h` ничего не надо описывать. Ошибка — когда персонаж после паузы пересказывает, что было, вместо того чтобы прийти с новостью.
- **Пример:** «я у её дома. синяя калитка» после девяти часов молчания — без «я выехала, доехала, постояла».
- **Как проверить:** Глазами: первая реплика после долгой паузы — новость или действие, а не отчёт о промежутке.
- **Источник:** [F5] (fires in the desert); [F2] (монтаж из отдельных кусков).

### P-16. Кнопка — ясное действие героя, без чувств за игрока
- **Суть:** Вариант выбора почти всегда — понятное действие персонажа; шутки допустимы, но действие должно читаться хотя бы по тексту кнопки. Не вкладывай игроку в голову мысли и чувства — описывай то, что он видит и что происходит.
- **Почему работает:** Агентность. Кнопка «Почувствовать вину» решает за игрока; кнопка «Извиниться» оставляет чувство ему.
- **В relayer:** Кнопка — реплика, которую игрок отправит, или `#label` с намерением. Длина: Failbetter держит текст ветки до 20 слов, корень сторилета до 30, результат до 100; у нас кнопка — до 12 слов, `#label` — до 6.
- **Пример:** `* [Извини. Я не должна была писать Оуэну #to:ellie]`, а не `* [Мне стыдно #to:ellie]`.
- **Как проверить:** Скрипт: текст кнопки > 12 слов; кнопка, начинающаяся с «Почувствовать», «Понять», «Решить».
- **Источник:** [F12] (длины, ясное действие, не вкладывать мысли), [F7] (не говорить игроку, что он чувствует).

### P-17. Открывай хаб сторилетов, только когда в нём есть из чего выбирать
- **Суть:** Структура на качествах пресна, пока сторилетов мало, и утомляет, когда их слишком много. Хаб оправдан при 3–4 вариантах, из которых хотя бы один появляется по состоянию; меньше — пиши прямой линией, больше — дели хаб на два (P-10).
- **Почему работает:** Внимание. Два варианта в «свободном» порядке игрок не отличает от обычного выбора, а цену хаба (учёт, условия выхода) автор уже заплатил. Шесть вариантов разом читаются как список дел, а не как сцены.
- **В relayer:** Хаб — узел, который возвращается в себя (`-> hub` из вариантов). В нём 3–4 `*`, один с условием по прошлому ответу (`{hub > 1 && clues >= 1}` или флаг из другой главы), выход — по счётчику. Это и есть способ сочетать сторилеты с главами: внутри главы — хаб, переход между главами — линейный.
- **Пример:** PAT-01: два безусловных вопроса, третий открывается после первого ответа, выход при `clues >= 2`.
- **Как проверить:** Скрипт: узел, у которого есть переход в себя, — хаб; в нём < 3 или > 4 вариантов `*`/`+` (не считая fallback `* ->`) или ни одного варианта с `{...}` — предупреждение.
- **Источник:** [S1] (у StoryNexus контент неинтересен, пока сторилетов в базе мало; при большом объёме список доступного подавляет игрока).

## Устройство авторских систем (второй проход)

Источники [L1]–[L13] — в `lessons.md`. У Failbetter четыре системы, которые работают вместе: сторилет как единица текста, качества как состояние, правило «что показать» (всегда / иногда / ярус) и производственный процесс. Ниже каждая разобрана по элементам.

### Система 1. Анатомия сторилета

| элемент | функция | вход → выход |
|---|---|---|
| условие показа | решает, видит ли игрок сторилет вообще | качества → да/нет |
| корень (короткий текст до выбора) | ставит ситуацию; у студии до 30 слов ([F12]) | состояние → понимание ставки |
| ветки (варианты) | действия героя, у каждой своё условие и, иногда, проверка навыка; до 20 слов ([F12]) | понимание → решение |
| проверка | шанс успеха по навыку. Fallen London показывает его словом-уровнем, за которым стоит диапазон процентов ([L13]) | навык → успех / провал |
| исход (успех и провал отдельно) | текст последствия, до 100 слов ([F12]) | решение → новое знание |
| эффекты | меняют качества: прогресс, ресурс, угроза | исход → новое состояние, от которого зависят следующие условия |

**Если пропустить шаг:**
- Без условия показа сторилет виден всем и всегда. Это не сторилет, а узел дерева.
- Без корня ставка звучит на кнопке, и кнопка распухает (против P-16).
- Без отдельного исхода провала провал молчит (против P-13).
- Без эффекта выбор ничего не меняет, и следующий сторилет не может на него сослаться (против P-09).

**Типичные ошибки понимания:**
- «Сторилет = сцена». Нет: это единица с условием и эффектом. Без них даже длинная сцена — просто текст.
- «Ветка = ветка дерева». У Failbetter branch — вариант внутри сторилета, после которого игрок возвращается в общий пул.
- «Сторилеты отменяют ветвление». Short показывает, что ими собирают и классические формы: коридор, ветвление с горлышком, петлю с ростом ([L9]). А маленький кусок с настоящим ветвлением можно вложить внутрь сторилета ([L9]).

**Для коротких форм.** В переписке корень — 1–3 реплики собеседника, ветки — 2–3 кнопки, исход — 1–4 реплики ответа, эффект — одна строка `~`. Сторилет на 5 сообщений: реплика, реплика, кнопка, ответ, `~`. На 50 сообщений это уже глава из 5–8 сторилетов, и тогда нужен хаб (P-17) или прямая линия.

### Система 2. Типы качеств

Kennedy признал, что в модели 2009 года все качества устроены одинаково. Черта, деньги и стадия сюжета хранятся и меняются одним способом, и следующие игры студии пытались задним числом это различие вернуть ([L7]). Вывод для нас — указывать тип в комментарии к `VAR` с самого начала.

| тип | как меняется | как читается | у Failbetter | пример у нас |
|---|---|---|---|---|
| прогресс | только растёт, по шагам | открывает следующий сторилет (`==`, `>=`) | стадия линии, venture ([F1]); качество-ярус ([L3]) | `stage`, `clues` |
| угроза | растёт от ошибок, иногда сбрасывается сценой | на пороге — яркая сцена (P-13) | menaces ([F8]) | `suspicion` |
| ресурс | тратится и пополняется | условие «хватает ли» и списание | валюты, предметы ([L7]) | `tom_risk` (PAT-07) |
| отношение | растёт и падает | меняет тон реплик, иногда открывает вариант | связи с персонажами | `maya_trust` |
| факт | ставится один раз | условная реплика-колбэк | одноразовые отметки (Mark of Cain, [F1]) | `called_bluff` |

**Если тип не указан:** отношение начинают читать как прогресс (`trust >= 3` открывает финал), а падение доверия неожиданно закрывает сюжет. Или факт заводят на каждый визит, хотя ink сам считает посещения (P-02).

**Ошибки понимания:** у угрозы и прогресса оба счётчика растут, но угрозу игрок хочет держать низкой. Значит, уровень угрозы озвучивают как предупреждение, а прогресса — как цель (P-07, PAT-08).

**Для коротких форм:** в истории на 25 минут — одно отношение и одна угроза или один прогресс. Остальное — факты, и они читаются хотя бы раз.

### Система 3. Что показать: всегда, иногда, ярус

| элемент | функция | ошибка, если пропустить |
|---|---|---|
| always (постоянные сторилеты) | ключевые шаги к цели, всегда на виду ([F6]) | игрок не находит, как продвинуться |
| sometimes (колода возможностей) | случайные, но уместные эпизоды; отбор по состоянию ([F9]) | мир без сюрпризов; или, наоборот, важное в случайном (RED-08, [L6]) |
| ярус прогресса | внутри яруса открыто всё, переход — по завершению историй ([L3]) | игрок не понимает, почему контент исчезает (окно по диапазону навыка, [L3]) |
| релевантность | случайный эпизод появляется, только когда он уместен: лечение — при ранах ([L5]) | случайный пул засоряется бесполезным |

**Порядок:** сначала always (цель видна), потом sometimes (разнообразие), переход по ярусу — когда always-шаги пройдены.

**Ошибки понимания:** «случайный пул — способ сэкономить на важном». Нет: если через случайное идёт главный путь, игроки превращают его в гринд, а студия потом закрывает лазейку ([L6]).

**Для коротких форм:** глава — это ярус. `#chapter` и есть переход, и в его первой реплике — награда и показ следующего яруса (PAT-12). Sometimes — один случайный эпизод на 2–3 главы, не больше: на телефоне случайное трудно отличить от бага.

### Система 4. Производственный процесс

| шаг | вход | выход | если пропустить |
|---|---|---|---|
| заявка | идея | одна страница: о чём, какие качества, ресурс, сколько контента ([F10]) | качества заводятся по ходу, и каждая линия тащит свои ([L7], комментарий читателя) |
| midflight, играбельный каркас | заявка | все сторилеты, условия и эффекты, по строке на бит; проверка на темп и гринд ([F10]) | структурные ошибки находятся, когда на узлах уже проза (P-01) |
| проза | проверенный каркас | текст в лимитах длины ([F12]) | — |
| QA | готовый текст | около трети времени написания ([F10]) | баланс начинают делать по отзывам ветеранов, и начало остаётся сырым ([L11]) |

**Ошибки понимания:** QA — не вычитка. Это прогон на темп, достижимость и баланс. У нас это `check:story`, `graph` и одна игра «новичком» (checklists §4).

**Для коротких форм:** заявка — 6 строк, каркас — 1 час, QA — один прогон бота и одна живая игра. Не пропускается ни один шаг, сжимается только время.

## Нюансы к принципам (второй проход)

- **P-02, бережливость.** Не работает, если переменная — единственный способ запомнить поступок, который вернётся через 5 глав: тогда факт оправдан и при одном чтении. Предупреждение RED-04 про переменные, которые не читаются нигде или читаются в той же сцене, где записаны. 5 сообщений: ни одной переменной. 50 сообщений: 1–2.
- **P-04, порядок одной стадией.** В короткой форме порядок держит сам порядок узлов ink, и стадия лишняя. Стадия нужна там, где сторилеты в хабе должны открываться по очереди.
- **P-05, счётчики вверх.** Пограничный случай — отношение, которое честно падает (`maya_trust`). Падение допустимо, но порог проверяют снизу вверх (`>= 3`), а не сверху (`<= 0`). И условие с верхней границей у растущего качества (`< 3`) делает вариант исчезающим — это ровно ошибка, которую Failbetter убирала в 2015 году ([L3], RED-12).
- **P-06, река.** Студия знала про ветку, которую не видел ни один игрок, и правила баланс, чтобы её увидели ([L5]). Значит, правило не «удали редкое», а «редкое достижимо намеренно». На 5 сообщениях реки нет: всё видят все. На 50 — 1–2 реплики различаются, остальное общее.
- **P-07, видимый прогресс.** Не работает для тайны, где число улик само спойлер: тогда персонаж говорит не «два из трёх», а «мне не хватает одного: кто был в машине». Fallen London показывает трудность проверки системным словом, а не прозой ([L13]). У нас системного слоя нет, его роль играет `#label` или `#sys`.
- **P-08, покажи орудия.** Срок нужен только перед паузой, которую игрок почувствует: от 10–15 минут реального времени. Перед `#delay:2m` срок лишний и замедляет.
- **P-10, мелкие выборы.** Конфликтует с правилом трёх вариантов в важной развилке (`choiceofgames-design:P-05`). Решение — в `for-relayer.md`, «Согласия и противоречия».
- **P-12, трудность ценой.** Уточнение по [L13]: сама игра показывает уровень трудности словом у кнопки, но его считает система по навыку, и он не врёт. Запрет — на прозу, которая называет задачу трудной независимо от состояния. У нас нет проверки навыка, поэтому только цена.
- **P-13, яркий провал.** Первый провал мягче поздних: смерть сильнее всего била по новичкам, и студия облегчила первый визит ([L5]). В первой главе угроза предупреждает, но не обрывает линию.
- **P-14, напоминание.** Подтверждено масштабом: «не помню, что делал» — самая частая жалоба почти 8 700 игроков ([L1]). Пересказ — персонажем и по запросу ([L2], PAT-11). Не работает, если пауза короче 10 минут: напоминание тогда звучит как повтор.
- **P-17, хаб по размеру.** Порог объёма подтверждён на StoryNexus: мир из немногих сторилетов пресен, и на это сетовали создатели ([L8]). В историях до 30 минут хаб — максимум один.

## Где мы расходимся с источником

- **«Игрок в центре, а не наблюдатель» ([F7]).** В мессенджере игрок по определению смотрит на чужие события. Берём мягкую версию: в каждой главе хотя бы одно событие, которое случилось из-за ответа игрока (переменная, записанная его кнопкой, меняет реплики в этой же главе).
- **Гринд и pacing wheel ([F6]).** Failbetter растягивает истории повторяемым контентом, набирающим очки. У нас нет повторяемых действий, а время и так идёт настоящими часами. Растягивать нельзя; брать только мысль «прогресс виден».
- **Термин QBN.** По [S1], сама студия перестала называть подход quality-based narrative. Автор термина Kennedy в 2017 году назвал его неудачным и предложил «resource narrative» (повествование на ресурсах) ([L7], `lessons.md`). Мы пользуемся словами «качество» и «сторилет», а «QBN» — только как ярлык из литературы.
- **Длины текста ([F12]).** Их лимиты — для прозы во втором лице. Наши пороги в P-16 — перенос, подобранный под переписку, а не цифры студии.
