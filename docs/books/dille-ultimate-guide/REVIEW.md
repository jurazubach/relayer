## Что осталось под вопросом

- Названия рабочих документов (pitch, concept, bible, design doc) подтверждены как темы книги [S2], но устройство документов в книге (поля питча, формат библии, flow/beat-лист) — знание модели. Нужна сверка с бумажной книгой. Затронуты `P-01`, `P-02`, `P-04`, `PAT-07`, `P-13`.
- Работа с лицензией (`P-12`): по открытым источникам подтверждено только, что книга сравнивает свою IP и лицензию [S2]. Правила канона — знание модели, уверенность низкая, так и помечено.
- `[S3]` Goodreads используется как подтверждение тем. Это слабый источник, повторно его не открывал. При желании заменить другой рецензией.
- Пороги (12 сообщений подряд, 60% доли прохождений, 20 реплик, 10 сообщений на срок) придуманы, а не взяты из книги. Откалибровать на трёх историях каталога, прежде чем делать их ошибками в `check:story`. Проверка срока уже показала 7 срабатываний из 10.
- `RED-01`/`GREEN-01` и проверка «Обещания без механики» держатся на шапке `// promise`, которой пока нет ни в одной истории. До её появления проверка ничего не находит.

## Лучшее из источника для скиллов

- **P-11 + RED-05** — переменная как ресурс: запись без чтения означает невидимый выбор. Проверка дешёвая и уже нашла `called_bluff`.
- **P-03 + PAT-06 + RED-03** — play, don't show: улику добывают кнопкой, NPC не делает вывод. Даёт правило генератора и метрику (длина NPC-отрезка без выбора).
- **P-09 + RED-07 + PAT-03** — критический путь и награда за необязательное. Проверяется по доле прохождений бота, пример `ch2_beth`.
- **P-08 + PAT-02/PAT-04** — назвать структуру главы заранее и сверять с картой `npm run graph`. Воронка = branch and bottleneck, узловая = контакт как место.
- **P-01 + PAT-01 + RED-01** — концепт-шапка с привязкой каждого пункта `features` к механике. Основа для скилла `/story-concept`.
- **P-12 + PAT-05 + RED-08** — канон серии и свёртка исходов в 2–3 мира, проверка «исход молча упал в `else`».
