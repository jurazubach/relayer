# Процедуры — Dille & Platten

Источники [S1]–[S5] перечислены в `README.md`. Процедуры собраны из идей книги: питч и концепт, библия, структуры, шаблоны персонажа, ресурсы и награды. Шаги и пороги — наши.

## 1. Как придумать и начать историю (документы до сценария)

- [ ] **Питч одной строкой.** Напиши `tagline`: роль игрока + действие + нарушение. *Результат:* в строке есть действие игрока, строка не длиннее 15 слов, а `synopsis` обращается к игроку на «ты» (P-02).
- [ ] **Концепт-шапка.** Заполни `// concept`, `// promise N ->` по каждому пункту `features`, `// structure` по главам (PAT-01). *Результат:* у каждого обещания есть стрелка на будущую переменную или узел.
- [ ] **Хронология правды.** Выпиши `// truth:` с точным временем всех событий, которые игрок будет восстанавливать (P-04). *Результат:* каждое событие, на котором держится поворот, имеет время и свидетеля.
- [ ] **Кто что знает.** У каждого контакта — `// knows`: что видел, что скрывает, при каком условии расскажет. *Результат:* у каждого скрытого факта есть условие раскрытия — флаг или глава.
- [ ] **Карточки контактов.** По 6 полей: функция, чего хочет от игрока, чего боится, что скрывает, голос, когда раскрывается (P-05, P-06). *Результат:* у главных контактов функции не повторяются.
- [ ] **Схема отношений.** `// rel a -> b:` для каждой пары, между которыми есть тайна или долг (P-07). *Результат:* каждый поворот в хронологии опирается хотя бы на одно ребро.
- [ ] **Поток глав.** По строке `// flow chN:` на главу: срок, что игрок узнаёт, что решает, крючок (PAT-07). *Результат:* у каждой главы, кроме последней, есть крючок, а срок не пуст.
- [ ] **Первая глава по концепту.** Пройди мысленно основной путь (первую кнопку в каждом выборе). *Результат:* за первые 15 сообщений названы роль игрока, конфликт (что случилось) и срок. Если что-то из этого только за необязательной кнопкой, вынеси на основной путь.
- [ ] **Перенос из прошлой части (если серия).** Выпиши `// canon:` и `// carry:`, сведи исходы прошлой части к 2–3 мирам (P-12, PAT-05). *Результат:* у каждого значения итоговой переменной прошлой части есть мир.

## 2. Как написать главу

- [ ] Открой `// flow` главы и назови тип структуры: воронка, критический путь или узловая (P-08). *Результат:* строка `// structure chN:` над `#chapter`.
- [ ] В первом блоке назови срок или угрозу (P-10). *Результат:* в первых 10 сообщениях или в `about` главы есть срок по регулярке из P-10.
- [ ] Отметь обязательную улику главы и сделай так, чтобы игрок добыл её кнопкой: вопрос, сохранение, пересылка (P-03, PAT-06). *Результат:* у улики есть флаг, который ставит кнопка.
- [ ] Для каждой необязательной ветки назначь награду: переменная, которую читают позже, `#unlock` или улика (P-09, PAT-03). *Результат:* у каждой ветки хаба есть запись, которую кто-то читает.
- [ ] В точке схождения прочитай переменные развилок главы (PAT-02). *Результат:* после схождения есть хотя бы одна условная реплика.
- [ ] Кончи главу крючком (P-13). *Результат:* последний узел содержит вопрос, срок, новый контакт или угрозу. Кнопки, которая закрывает вопрос, там нет.
- [ ] Сверь все времена и факты в репликах с `// truth:` (P-04). *Результат:* время либо совпадает, либо помечено `// lie:`.
- [ ] Обнови библию в том же изменении, если глава добавила факт.

## 3. Как провести ревью готового сценария

- [ ] **Обещания.** Для каждого пункта `features` назови узел и переменную, где он выполняется. *Результат:* таблица «пункт → узел». Пустая строка — RED-01.
- [ ] **Питч.** Проверь `tagline` и `synopsis` на роль игрока. *Результат:* роль есть, иначе RED-02.
- [ ] **Структура.** Открой `npm run graph`, для каждой главы сравни фактический тип с заявленным в `// structure`. *Результат:* расхождение записано: «заявлена воронка, на деле линейная».
- [ ] **Ресурсы.** Выпиши `VAR` с числом записей и чтений. *Результат:* список переменных без чтений (RED-05) и переменных, где записей больше 3, а чтение одно.
- [ ] **Кнопки «сохранить в заметки».** Для каждой кнопки `#to:notes` проверь, ставит ли она переменную и читается ли та. *Результат:* список «косметических» сохранений. Если `features` обещает, что заметки открывают ответы, каждое такое сохранение — RED-01.
- [ ] **Критический путь.** По метрикам бота найди узлы с долей 100% и необязательные узлы без награды. *Результат:* список RED-07.
- [ ] **Отношения.** Для каждого `// rel` найди упоминание в тексте. *Результат:* список связей, которые игрок не увидит.
- [ ] **Канон.** Если это продолжение, сверь все значения итоговой переменной прошлой части с функцией свёртки. *Результат:* RED-08 или «ок».
- [ ] **Эмоциональные последствия.** Для 5 главных выборов ответь: меняется ли отношение собеседника к игроку (тон, доверие, готовность отвечать), а не только сюжетный факт. *Результат:* выборы, у которых есть только сюжетное последствие, помечены для доработки (наше правило под формат переписки).

## 4. Как тестировать

- [ ] `npm run check:story` — тупики, недостижимые узлы, финалы. *Результат:* ноль тупиков, каждый финал достигнут.
- [ ] По выводу бота возьми долю прохождений по узлам и отметь узлы меньше 5%. *Результат:* для каждого редкого узла решено: награда за поиск (оставить) или ошибка в условии (чинить).
- [ ] Пройди основной путь с `?fast=1` и выпиши первые 15 сообщений. *Результат:* в них есть роль, конфликт и срок (п. 1).
- [ ] Пройди путь «всегда необязательное» (заходи во все ветки хабов). *Результат:* каждая ветка дала что-то, что позже упомянуто.
- [ ] Пройди путь «всегда промолчать» (`#silent`, где можно). *Результат:* история не стоит, персонажи замечают молчание.
- [ ] Для серии пройди по одному прохождению на каждый мир свёртки. *Результат:* в первой главе продолжения тексты различаются.
