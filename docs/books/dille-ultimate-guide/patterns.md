# Приёмы и структуры — Dille & Platten

Источники [S1]–[S5] перечислены в `README.md`. Названия структур (PAT-02 – PAT-04) взяты из книги по рецензии [S1]. Схемы и ink написаны под наш формат, это не авторские примеры. Все примеры ink скомпилированы inkjs.

---

### PAT-01. Концепт-шапка ink (one-page concept)
- **Когда применять:** перед первой строкой любой новой истории и перед каждым сезоном серии. **Когда нет:** короткая проба на 2–3 минуты, где обещание одно и оно в `tagline`.
- **Схема:**
  1. `// concept:` одна фраза — кто игрок и что он делает.
  2. `// promise N:` по пункту `features`, у каждого стрелка на механику (переменная, узел, тег).
  3. `// structure:` тип на главу (см. PAT-02 – PAT-04).
  4. `// role <id>:` функция каждого контакта (P-05).
  5. Только после этого — `-> start`.
- **На ink:**
  ```ink
  // concept: ты отвечаешь на объявление и пишешь свидетелям чужим голосом
  // promise 1: «решаешь, кому врать» -> VAR cover, кнопки в start
  // promise 2: «улика открывает ответы» -> note_jacket читается в ask
  // structure ch1: nodal, сходится в ask
  // role ellie: наниматель, держит игрока
  // role notes: служебный
  # contact: ellie, Элли, amber
  # contact: notes, Заметки, green
  VAR cover = "student"
  VAR note_jacket = false
  -> start
  === start ===
  День 1 · Подработка #from:ellie #sys:ellie #chapter
  привет. ты по объявлению? #from:ellie #delay:5s
  * [Да. Пишу как студент #to:ellie]
      ~ cover = "student"
  * [Да. Но врать не буду #to:ellie]
      ~ cover = "honest"
  - её куртка была у костра #from:ellie #delay:20s
  * [Куртка у костра #to:notes #label:Сохранить в заметки]
      ~ note_jacket = true
  * [Ок #to:ellie]
  - -> ask
  === ask ===
  * {note_jacket} [Чья куртка была у костра? #to:ellie]
      моя #from:ellie #delay:1m
  * [Что дальше? #to:ellie]
      жди #from:ellie #delay:30s
  - -> END
  ```
- **Цена:** 10–20 строк комментариев. Текста для игрока не добавляет.
- **Ловушки:** шапку пишут один раз и забывают. Если `features` в JSON поменялись, а `// promise` нет, проверка P-01 врёт. Обещание без стрелки на механику — уже признак RED-01.
- **Источник:** [S2] (концепт и дизайн-документ); форма шапки — наша.

### PAT-02. Воронка (funneling) — ветки расходятся внутри главы и сходятся на её границе
- **Когда применять:** главы в реальном времени, где следующая глава начинается через часы. Схождение на границе главы дёшево, а память выбора хранится в переменной. **Когда нет:** выбор, который должен изменить *события* следующей главы, а не только её реплики. Тогда нужен PAT-05 или отдельная ветка.
- **Схема:**
  ```
  ch2 ─┬─ ch2_full ────┐
       ├─ ch2_partial ─┼─> ch2_hook ─> ch3  (state: ellie_trust)
       └─ ch2_none ────┘
  ```
- **На ink:**
  ```ink
  # contact: ellie, Элли, amber
  VAR told = 0
  -> ch2
  === ch2 ===
  День 2 · Свидетели #from:ellie #sys:ellie #chapter
  ты им сказал про меня? #from:ellie #delay:1m
  * [Да, всё #to:ellie]
      ~ told = 2
      -> ch2_full
  * [Только что ты наняла #to:ellie]
      ~ told = 1
      -> ch2_hook
  * [Нет #to:ellie]
      -> ch2_hook
  === ch2_full ===
  зачем #from:ellie #delay:3m
  ладно. уже всё равно #delay:40s
  -> ch2_hook
  === ch2_hook ===
  {told >= 1:теперь они знают моё имя|они до сих пор не знают, что это я} #from:ellie #delay:6h
  кто-то выложил скрин опроса #delay:20s
  -> END
  ```
- **Цена:** одна переменная на развилку и 1–3 строки условного текста в точке схождения.
- **Ловушки:** если в точке схождения переменную не читают, воронка становится косметической (RED-05). Схождение сразу после кнопки, без своего узла и реакции, игрок замечает: ответ одинаковый, выбор не ощущается.
- **Источник:** [S1] (funneling, по Short — то же, что branch and bottleneck).

### PAT-03. Критический путь с необязательными узлами (critical path)
- **Когда применять:** главы-расследования, где есть одна обязательная улика и несколько дополнительных. **Когда нет:** короткая глава-кульминация: отступления сбивают темп.
- **Схема:**
  ```
  hub ──> [обязательный] jess ──┐
   ├──> [необязательный] beth ──┤ награда: note_beth
   └──> [необязательный] owen ──┤ награда: owen_knows
                                └─> evening (выход открыт только после jess)
  ```
- **На ink:**
  ```ink
  # contact: jess, Джесс, pink
  # contact: beth, Бет, purple
  # contact: ellie, Элли, amber
  VAR jess_done = false
  VAR note_beth = false
  -> hub
  === hub ===
  * [Привет! Пару вопросов? #to:jess #label:Написать Джесс]
      омг да #from:jess #delay:1m
      они с лили ругались весь вечер #delay:20s
      ~ jess_done = true
      -> hub
  * [Привет! Пару вопросов? #to:beth #label:Написать Бет]
      лили писала мне в 00:52 #from:beth #delay:2h
      ~ note_beth = true
      -> hub
  * {jess_done} [Хватит пока #to:ellie #silent]
      -> evening
  === evening ===
  кто-нибудь ответил? #from:ellie #delay:1h
  * [Джесс: вы ругались #to:ellie]
  * {note_beth} [Бет: Лили писала ей в 00:52 #to:ellie]
      что?? покажи #from:ellie #delay:20s
  - -> END
  ```
- **Цена:** хаб и по узлу на ветку. Каждая необязательная ветка требует хотя бы одного чтения своей переменной.
- **Ловушки:** нельзя давать необязательную улику всем через другой узел — награда обесценивается (так вышло с `ch2_beth` в «Чужом голосе»). Если выход из хаба открывается до обязательного узла, критический путь рвётся. В ink выше выход скрыт условием `{jess_done}`.
- **Источник:** [S1] (critical path); правило награды — знание модели, уверенность: средняя.

### PAT-04. Узловая структура (nodal): контакт как место
- **Когда применять:** середина истории, когда у игрока 3–5 открытых чатов, и каждый — своя маленькая история со своим началом и концом. **Когда нет:** первые 5 минут, когда игрок ещё не знает людей, и финал, где нужен один фокус.
- **Схема:** у каждого контакта своя короткая дуга (вопрос → сопротивление → улика). Порядок свободный. Глава кончается, когда закрыты все дуги или наступил срок.
  ```
          ┌─ connor: 3 узла ─┐
  ch3 ────┼─ owen:   3 узла ─┼─> ch3_hook
          └─ judith: 2 узла ─┘
  ```
- **На ink:** скелет главы такой же, как хаб в PAT-03, но у каждой ветки свой `=== x_end ===`, который ставит `x_closed = true` и возвращает в хаб. Выход из хаба — `* {a_closed && b_closed} [...]` или кнопка «день закончится» с `#label`.
- **Цена:** большая: по 2–4 узла на контакт. Выгоднее всего, когда дуги отдают улики друг другу (улика Коннора открывает кнопку у Джудит).
- **Ловушки:** дуги, которые не пересекаются, превращаются в пять отдельных историй, и игрок не видит, зачем ему все пять. В реальном времени параллельные дуги с разными `#delay` перемешиваются, поэтому каждая реплика должна быть понятна без соседнего чата.
- **Источник:** [S1] (nodal — истории, организованные вокруг мест); перенос «место = чат» — наш.

### PAT-05. Свёртка исходов в состояние мира (канон серии)
- **Когда применять:** у пилота или части несколько финалов, а продолжение одно. **Когда нет:** у части один финал. Тогда хватит `// canon:`.
- **Схема:**
  ```
  7 исходов act1 ──> function sync_world() ──> world ∈ {open, hidden, owen}
                                              │
                         каждая глава сезона читает world в 1–3 местах
  ```
- **На ink:**
  ```ink
  # contact: maya, Мая, red
  VAR act1 = "owen"
  VAR world = ""
  -> s2
  === function sync_world() ===
  {
  - act1 == "owen" || act1 == "alone_owen":
      ~ world = "owen"
  - act1 == "hides":
      ~ world = "hidden"
  - else:
      ~ world = "open"
  }
  === s2 ===
  ~ sync_world()
  День 6 · Сестра #from:maya #sys:maya #chapter
  {
  - world == "owen": Брайт прислал мне файл. Сам. #from:maya #delay:1h
  - world == "open": Полиция дала послушать запись. #from:maya #delay:1h
  - else: Записи у меня нет. #from:maya #delay:1h
  }
  -> END
  ```
- **Цена:** одна функция, плюс по 1–3 вилки `world` в каждой главе продолжения.
- **Ловушки:** значение `act1`, которого нет ни в одной ветке функции, молча попадает в `else`. Каждое значение мира нужно читать, иначе ветки пилота сольются (проверка P-12). Не делай миров больше трёх: на каждый мир нужен свой текст в каждой главе.
- **Источник:** [S2] (своя IP или лицензия); приём — наш, сделан по `sync_world()` в «Чужом голосе».

### PAT-06. Улика через действие (play, don't show)
- **Когда применять:** любой факт, на котором держится поворот или финал. **Когда нет:** фон и атмосфера, которые игрок не обязан помнить.
- **Схема:** намёк от NPC → кнопка «сохранить», «спросить» или «переслать» → флаг → условная кнопка в другом чате → реакция другого персонажа.
- **На ink:**
  ```ink
  # contact: connor, Коннор, orange
  # contact: judith, Джудит Марш, teal
  # contact: notes, Заметки, green
  VAR note_pills = false
  -> c
  === c ===
  в куртке у неё ничего не было #from:connor #delay:1m
  я сам проверил #delay:20s
  * [Коннор проверял её куртку. Зачем? #to:notes #label:Сохранить в заметки]
      ~ note_pills = true
  * [Понятно #to:connor]
  - -> j
  === j ===
  Вы что-то узнали? #from:judith #delay:3h
  * {note_pills} [Коннор зачем-то проверял куртку Лили #to:judith]
      Он мне этого не говорил. #from:judith #delay:5m
      Я спрошу его сама. #delay:30s
  * [Пока нет #to:judith]
      Понимаю. #from:judith #delay:2m
  - -> END
  ```
- **Цена:** флаг и условная кнопка. Плюс реплика реакции, без которой улика не ощущается.
- **Ловушки:** если NPC сам формулирует вывод («значит, это он забрал таблетки»), игроку остаётся только нажать «ок». Намёк должен быть неполным. Если условная кнопка стоит рядом с безусловной на тот же текст, флаг ничего не даёт.
- **Источник:** [S1] (play don't show).

### PAT-07. Лист рабочих документов истории (bible pack)
- **Когда применять:** история длиннее 30 минут или серия. **Когда нет:** история меньше 10 минут: хватит PAT-01.
- **Схема:** пять документов комментариями в начале ink или в отдельном `docs/stories/<id>.md`:
  1. концепт (PAT-01);
  2. хронология правды `// truth:` с точным временем (P-04);
  3. карточки контактов из 6 полей (P-05, P-06);
  4. схема отношений `// rel` (P-07);
  5. поток глав (flow): по строке на главу — срок, что игрок узнаёт, что решает, крючок (P-10, P-13).
- **На ink:** только комментарии плюс минимальный рабочий узел:
  ```ink
  // flow ch1: срок «слушание через 4 дня»; узнаёт: ссора Элли и Лили; решает: легенду; крючок: неизвестный номер
  // flow ch2: срок «пятница»; узнаёт: сообщение 00:52; решает: что сказать маме; крючок: пост в группе
  // truth: 00:52 Лили пишет Бет про куртку
  // rel jess -> ellie: завидует, распускает слух
  # contact: ellie, Элли, amber
  -> start
  === start ===
  День 1 #from:ellie #sys:ellie #chapter
  привет #from:ellie
  -> END
  ```
- **Цена:** час работы до сценария. Экономит переписывание глав, когда находится противоречие.
- **Ловушки:** библия, которую не обновляют при правке ink, хуже отсутствующей: ревьюер сверяет текст с неверным эталоном. Правь библию в том же коммите, что и ink.
- **Источник:** [S2] (game bible, design document); состав пакета — наш, знание модели, уверенность: средняя.

## Устройство: пять типов структуры (второй проход)

Названия типов — по рецензии Short [S1]. Описания ниже — их функция в нашем формате, а не авторские определения. Линейную структуру Short не упоминает, поэтому здесь её нет.

| тип | что делает | вход (что нужно заранее) | выход (как выглядит на карте) | где ломается |
|---|---|---|---|---|
| ограниченное ветвление (limited branching) | несколько точек, где история реально расходится; число веток держат малым | список 1–2 решений на главу, которые меняют события | 1–2 узла с кнопками в разные узлы на главу, ветки живут несколько узлов | если ветки не сходятся, текст растёт кратно; The Walking Dead отказалась от расширенной роли Марка: она ничего не добавляла [L7] |
| критический путь (critical path) | обязательная цепочка плюс необязательные отступления | список обязательных улик | узлы с долей 100% и узлы < 60% с наградой (PAT-03) | награду за отступление дают всем (RED-07) |
| воронка (funneling) | расходится внутри главы, сходится на её границе | переменная, которая помнит ветку | ромбы, сходящиеся в `chN_hook` (PAT-02) | в точке схождения переменную не читают (RED-05) |
| открытая (open-ended) | нет заложенной структуры выбора, финала может не быть [S1] | система, а не сценарий | — | в реальном времени игрок без цели уходит (`for-relayer.md`, раздел 5) |
| узловая (nodal) | короткие истории привязаны к местам [S1]; у нас место = чат | 3–5 дуг по контакту | хаб и дуги с собственным концом (PAT-04) | дуги не обмениваются уликами и превращаются в отдельные истории |

- **Порядок выбора:** сначала бюджет текста и длина в минутах, потом тип. Короче 15 минут — воронка. 15–40 минут — критический путь, в середине одна узловая глава. Длиннее — смесь по главам, тип пишут в `// structure chN`.
- **Ошибка понимания 1:** считать, что тип выбирают на всю историю. На деле он выбирается для главы: «Чужой голос» — узловая первая глава (`ch1_hub`), воронки в середине, ограниченное ветвление в финале (`ch10_route`).
- **Ошибка понимания 2:** путать воронку с иллюзией выбора. Воронка честная, если после схождения переменная читается. Если нет — это косметика.
- **Если пропустить выбор типа:** граф растёт случайно. У нас уже есть замер этого: в «Чужом голосе» кнопки расходятся только в 24 узлах из 165, и карта выглядит линейной, хотя задумана как расследование.
- **Короткая форма (5 минут):** одна воронка. 5 сообщений — развилка — 3 сообщения на ветку — схождение с одной условной репликой — финал.

## Нюансы к паттернам

- **PAT-01 концепт-шапка.** Шапку делят на `// core:` и `// now:` — см. нюанс к P-01 и LESSON-08.
- **PAT-02 воронка.** На 5 сообщениях схождение должно отличаться хотя бы одной репликой. На 50 нужно 2–3 чтения в следующей главе: одно игрок может пропустить, отвлёкшись на другой чат.
- **PAT-03 критический путь.** Выход из хаба по `{jess_done}` честен, только если игрок понимает, что нужно сделать. Если обязательный контакт не назван в последней реплике перед хабом, игрок с короткой сессией застрянет. Назови его: «начни с Джесс, она болтает».
- **PAT-04 узловая.** В первой главе не больше двух дуг (`attention.md`, раздел 4). В реальном времени дуга с `#delay:2h` в одном чате и дуга с `#delay:1m` в другом создают ложный приоритет: игрок решит, что медленный чат неважен.
- **PAT-05 свёртка.** Добавь проверку «якорей» (P-12, [L4]): если в каком-то мире `world` главный контакт прошлой части исчезает, в первой главе нового сезона это объясняют.
- **PAT-06 улика через действие.** Используй лестницу подачи (`principles.md`, раздел «Устройство: лестница подачи»): если кнопку поставить негде, давай артефакт (скрин, голосовое), а не пересказ.
- **PAT-07 пакет документов.** Добавь шестой документ — суперкат основного пути (LESSON-04, команда `/story-supercut`). Документы, которые правились последними, сверяют с суперкатом.
