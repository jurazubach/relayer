# Процедуры — Truby, The Anatomy of Story

Каждый шаг: действие → что должно получиться. Ссылки на пункты — в скобках. Маркеры — `for-relayer.md` §2.

## 1. Придумать и начать историю

- [ ] Напиши посылку одной фразой: кто меняется, чего добивается, кто мешает → `// ПОСЫЛКА:` в шапке, три слота заполнены (P-01).
- [ ] Проверь посылку на три ошибки Труби: идея не банальна, есть линия желания, есть сильный противник → ответ «да» на все три, иначе переписать посылку, а не начинать текст.
- [ ] Выбери носителя перемены: роль игрока или главный NPC → `// ПЕРЕМЕНА: player` или `<id>` (P-04).
- [ ] Запиши моральную слабость с жертвой и, если носитель — NPC, психологическую → `// СЛАБОСТЬ` с именем жертвы из `characters` (P-03).
- [ ] Запиши для носителя ХОЧЕТ и НУЖНО так, чтобы они противоречили → пара строк, где выполнение первого мешает второму (P-06).
- [ ] Назови противника, который хочет той же вещи, и опиши, как он бьёт в слабость → `// ПРОТИВНИК: <id>` + одна строка удара (P-07).
- [ ] Реши, будет ли скрытый противник; если да — кто он и какие 2–3 улики его выдадут → `// СКРЫТЫЙ: <id>` и список `// clue:` (P-08).
- [ ] Сформулируй вопрос посылки и раздай позиции 3–5 контактам → `// ВОПРОС:` и по строке на контакт, все разные (P-13, PAT-07).
- [ ] Придумай призрака носителя и главу, где он раскроется → `// ПРИЗРАК:`, глава в середине (P-14).
- [ ] Сформулируй принцип построения через механику чата → `// ПРИНЦИП:` с тегом из реестра (P-02).
- [ ] Придумай план, о котором игрок и NPC договорятся, и контрудар противника по нему → `// step: plan` в первой трети, `// step: counterattack` до середины (P-17).
- [ ] Разложи семь шагов по главам → таблица из PAT-01 в комментарии шапки (PAT-01).
- [ ] Выпиши лестницу раскрытий: по одному на главу, «было → стало» → список R1..Rn, последние идут чаще (P-09, PAT-02).
- [ ] Напиши первые 10 входящих: цель, срок, почему пишут игроку, правило мира → бот находит `// step: desire` ≤ 10, есть `// rule:` (P-05, P-15).

## 2. Написать главу или сцену

- [ ] Назови раскрытие, которым кончится глава, до того как писать её начало → строка `// reveal:` стоит в последнем узле главы (P-09).
- [ ] Определи, на какую слабость давит глава и кто давит → в первом узле главы комментарий `// давит: <id> → <слабость>` (P-07).
- [ ] Начни сцену как можно позже: первое сообщение уже внутри конфликта → нет приветствий и пересказа прошлой главы в первых 3 сообщениях (знание модели, уверенность средняя).
- [ ] Дай противнику хотя бы одну реплику в главе или поставь бытовое упоминание → `#from:<противник>` или его имя в главе (RED-06).
- [ ] Если глава средняя — добавь одну грязную кнопку и запиши её в переменную → вариант с `// immoral` и `~ x += 1` (P-10).
- [ ] Если в прошлых главах была грязная кнопка — поставь отклик союзника → условие на эту переменную с репликой союзника (PAT-05).
- [ ] Проверь, что хотя бы одна развилка главы разводит варианты по разным `#to` или по «хочет / нужно» → есть `// want` и `// need` или ≥ 2 `#to` (P-06).
- [ ] Поставь раскрытие перед самой долгой паузой главы → `#delay` ≥ 30 мин идёт после `// reveal:` (P-09).

## 3. Ревью готового сценария

- [ ] Найди в шапке посылку, носителя перемены, слабость, противника → всё есть; если нет — восстанови по тексту и проверь, держится ли история (RED-01, RED-02).
- [ ] Выпиши первые 10 входящих → в них цель, срок и почему именно игрок (RED-03).
- [ ] Для каждой главы выпиши раскрытие и «было → стало» → в каждой главе есть; глава без него — кандидат на скуку (RED-05).
- [ ] Посчитай интервалы между раскрытиями → во второй половине короче, чем в первой (P-09).
- [ ] Проследи противника по главам → нет двух глав подряд без него (RED-06).
- [ ] Если есть скрытый противник — найди его первую реплику и улики → первая треть пути, ≥ 1 улика в стволе (RED-07).
- [ ] Выпиши все кнопки с `Соврать`, `Надавить`, `Выдать` в `#label` → у каждой есть отклик позже (GREEN-06, RED-10).
- [ ] Прочитай последнюю развилку → две ценности, разные `#to`, финалы от неё зависят (RED-08).
- [ ] Прочитай финалы → нет «я понял(а), что»; есть эхо первых сообщений (RED-09, GREEN-08).
- [ ] Выпиши позиции NPC по вопросу посылки → нет двух одинаковых (RED-11).

## 4. Проверить историю по семи шагам

Для каждого шага найди узел, где он случается, и ответь на вопрос. Ответ «нет» или «не нашёл» — правка. Результат — таблица из семи строк: шаг | узел ink | охват бота | да/нет.

- [ ] **Слабость и потребность** (P-03, P-06): в первой главе ствола видно, какой поступок роли игрока или носителя перемены вредит другому человеку → узел и имя жертвы.
- [ ] **Желание** (P-05): цель со сроком названа в первых 10 входящих, через узел проходит ≥ 90% → узел и номер входящего.
- [ ] **Противник** (P-07): контакт, который хочет той же вещи, пишет игроку сам в первой трети, его угроза бьёт в слабость из первого шага → узел и реплика.
- [ ] **План** (P-17): игрок и NPC договорились, что делать дальше, противник это сломал → два узла: договор и контрудар.
- [ ] **Битва** (P-11): в последней главе противник и игрок в одной сцене, ответ игрока чего-то стоит → узел, охват ≥ 60%.
- [ ] **Самораскрытие** (P-12): носитель перемены показывает перемену поступком, или игроку задают вопрос о нём самом → узел; grep «понял(а), что» по нему пуст.
- [ ] **Новое равновесие** (P-16): финал повторяет форму строки из первой главы, содержание другое → пара узлов с `// echo:`.
- [ ] Сверь шаги друг с другом: битва решает ту же цель, что названа в «желании», а самораскрытие касается той же слабости, что в первом шаге → если нет, история распадается на две, правь посылку (P-01).

## 5. Тестировать

- [ ] `npm run check:story` → нет тупиков; распределение финалов показывает, что каждая опция последней развилки ведёт хотя бы в один свой финал.
- [ ] Посчитай скриптом write-only переменные (`for-relayer.md` §2, проверка 6) → список пуст или каждая объяснена.
- [ ] `npm run graph` → на карте найди узлы с `// reveal:`; доля прохождений через каждое ключевое раскрытие ≥ 90%.
- [ ] Пройди историю с `?fast=1`, выбирая везде «грязные» варианты → союзник реагирует, хотя бы один финал другой.
- [ ] Пройди, выбирая везде «чистые» варианты → самораскрытие и финальная развилка всё равно наступают (давление не зависит от того, что игрок «плохой»).
- [ ] Дай прочитать только первые 10 сообщений человеку, не знающему историю, и спроси: чего хочет NPC, к какому сроку, почему пишут тебе → три ответа совпадают с шапкой.
