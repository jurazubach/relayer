# Процедуры — Snyder, Save the Cat!

Каждый шаг — действие и результат, который можно проверить. Ссылки — на `principles.md`, `patterns.md`, `flags.md`. Маркеры (`// beat:`, `// ±` и т. д.) — наша разметка из `PAT-01`–`PAT-04`.

## 1. Как придумать и начать историю

- [ ] **Написать логлайн** по `PAT-01`: роль игрока, что ему досталось, ирония, объём. → В шапке ink есть `// ЛОГЛАЙН:` до 35 слов с противопоставлением.
- [ ] **Проверить иронию вслух:** пересказать логлайн человеку или модели и попросить досказать сюжет. → Собеседник сам назвал главный конфликт. Если нет — переписать картинку, а не добавлять слова.
- [ ] **Выбрать один жанровый тип** и выписать его три элемента (`P-02`, `PAT-10`). → `// ЖАНР:` и три строки «элемент = конкретная вещь в истории».
- [ ] **Назвать первобытную цель** каждого ключевого NPC (`P-04`). → `// ХОЧЕТ:` у каждого, 3–5 слов, без «понять», «разобраться».
- [ ] **Задать голос** каждому ключевому NPC (`P-21`). → `// ГОЛОС:` с двумя-тремя приметами письма; у двух NPC приметы не совпадают.
- [ ] **Назначить антагониста**, линии A и B, тему и ось (`P-08`, `P-11`, `P-13`). → В шапке `// АНТАГОНИСТ:`, `// A:` (префиксы переменных улик), `// B:` (NPC и его `*_trust`), `// ТЕМА:` (вопрос), `// ОСЬ:` (переменная).
- [ ] **Разложить биты по главам** по `PAT-02` (5 глав) или `PAT-03` (10 глав). → Скелет ink: узлы `ch1`…`chN` с комментариями `// beat:` и пустыми переходами. Компилируется.
- [ ] **Собрать доску** по `PAT-04`: по ряду на четверть истории, карточка-комментарий на узел. → На каждую главу 6–10 карточек с `// ±` и `// X >< Y`. Ряды отличаются по числу карточек не больше чем в 1,5 раза.
- [ ] **Написать первые пять входящих** так, чтобы в них были ирония и катализатор (`P-05`, `RED-01`, `RED-02`). → Маркер `// beat: catalyst` стоит не дальше пятого входящего, и до него нет `#delay` ≥ 10m.
- [ ] **Вставить «котика»** главного NPC в ствол первой главы (`PAT-09`). → Строка с `// cat` есть в каждом прохождении бота.
- [ ] **Сделать первую развилку дебатом** (`PAT-05`). → У неё есть вариант отказа или `#silent`, и у его ветки свои реплики и переменная.

## 2. Как написать главу или сцену

- [ ] **Найти карточки главы на доске** и прочитать бит, к которому глава ведёт. → Известно, каким событием глава кончается и какой вопрос остаётся перед паузой.
- [ ] **Записать тон главы** одним словом (`P-19`). → `// ТОН:` отличается от тона соседних глав.
- [ ] **Для каждой сцены записать заряд и конфликт** до текста. → Над узлом `// + → −` (или наоборот) и `// игрок >< Х`. Если знаки совпадают, сцену сливают с соседней или добавляют поворот.
- [ ] **Убедиться, что сцена выполняет обещание завязки** (только для глав II акта, `P-09`). → В главе есть хотя бы одна сцена с основным действием из логлайна (`// premise`).
- [ ] **Если в сцене больше трёх сообщений прошлого — поставить таймер** (`PAT-08`). → В серии одного `#from` длиннее пяти входящих есть число с «%», «мин» или «час» или маркер `// clock`.
- [ ] **Проверить, кто двигает сцену** (`P-07`). → Ключевой шаг сцены делает игрок кнопкой. Если NPC делает его сам, у пассивной ветки есть цена в переменной.
- [ ] **Дать антагонисту ход** (только во второй половине, `P-11`). → В главе есть его собственное входящее с новым фактом об игроке.
- [ ] **Закончить главу открытым вопросом перед паузой.** → Последняя строка перед `#delay` ≥ 1h или перед `#chapter` — вопрос, угроза или новость, а не прощание.
- [ ] **Скомпилировать и прогнать бота.** → `npm run check:story` без тупиков, узлы главы посещены.

## 3. Как провести ревью готового сценария

- [ ] **Восстановить логлайн по тексту**, не глядя в шапку. Сравнить с `// ЛОГЛАЙН:`. → Расхождение записано как «текст ушёл от идеи» или «логлайн устарел».
- [ ] **Определить жанровый тип и найти три элемента** с номерами узлов (`P-02`). → Таблица «элемент → узел». Пустая строка — красный флаг.
- [ ] **Найти 10 опорных битов** (открывающий кадр, тема, катализатор, дебат, переход во II, середина, всё потеряно, тёмная ночь, переход в III, финальный кадр) и поставить каждому узел и долю входящих. → Таблица «бит → узел → %». Сравнить с коридорами из `PAT-02`.
- [ ] **Пройти красные флаги** `RED-01`…`RED-16`. → Список «флаг → узел → строка → предлагаемая правка», отсортированный по месту в сценарии.
- [ ] **Проверить финал на синтез:** выписать переменные, которые читает узел выбора финала, и разделить их на A и B (`P-13`). → Есть и A, и B. Если нет — флаг `RED-09` или правка по `PAT-07`.
- [ ] **Выписать первую и последнюю реплики** главных NPC и сравнить (`P-20`). → У всех, кроме антагониста, видна перемена.
- [ ] **Положить рядом первое входящее и последние строки финалов** (`P-15`). → Зеркало есть или предложено.
- [ ] **Отделить мнение Снайдера от формата:** все правки, которые требуют «один герой, одна дуга», проверить по `for-relayer.md` §5. → В отчёте нет советов, которые ломают многочатовость или реальное время.

## 4. Как тестировать

- [ ] **`npm run check:story`** → нет тупиков и недостижимых узлов; записаны медиана строк и медиана времени.
- [ ] **Посчитать доли битов на медианном пути** (проверки `B1`–`B4` из `for-relayer.md` §2). → Каждый бит в своём коридоре или есть объяснение отклонения.
- [ ] **Посчитать паузы по главам** (`B7`). → Сумма пауз в последней главе меньше медианы по главам II акта. Между `all_is_lost` и `break3` ≥ 2 ч.
- [ ] **Сравнить голоса** (`B15`). → Для главных собеседников признаки письма различаются; если нет — `RED-16`.
- [ ] **Проверить доли финалов** в отчёте бота. → Каждый финал выпадает хотя бы в 3% прохождений. Финал на 0% — мёртвый порог в условии (`PAT-07`).
- [ ] **`npm run graph`** и открыть карту. → Узлы с `// beat:` видны. Ряды доски (по маркерам) не перекошены. Узел выбора финала читает A и B.
- [ ] **Сыграть начало вручную** с `?fresh=1&fast=1` до первой длинной паузы. → За первые 2 минуты игрок может назвать, кто он, что от него хотят и почему это плохо кончится.
- [ ] **Сыграть ветку отказа** в первой развилке и ветку «промолчать везде». → В обеих есть свои реплики. Пассивный путь проходит до финала и отличается переменными.

## 5. Второй проход: дополнительные шаги

- [ ] **Выбрать число битов по длине** (`attention.md` §4, LESSON-02). → В шапке `// БИТЫ: 4` (до 10 мин) или 10 (от 25 мин). Число `// beat:` в тексте совпадает.
- [ ] **Для каждого опорного бита написать, кто его делает** (LESSON-11). → У переходов во II и в III и у смены плана в финале — «игрок, кнопка в узле X».
- [ ] **Проверить, что каждый бит служит логлайну** (LESSON-03). → У каждого `// beat:` в пределах узла есть `// premise`, запись или чтение A/B. Иначе бит вырезан, сцена не дописана.
- [ ] **Разложить последнюю главу на пять шагов** (`PAT-12`). → Помечены шаги 1–5. В шаге 4 ≥ 2 условных варианта, бот показывает, что ≥ 2 варианта доступны в ≥ 50% прохождений.
- [ ] **Пройти все паузы ≥ 1h** (`attention.md` §3). → Перед каждой открытый вопрос или срок; первая реплика после — событие с деталью ставки, а не приветствие.
- [ ] **Сверить формы крючков глав** (LESSON-04). → Нет трёх глав подряд с одинаковым видом крючка.
- [ ] **Холодный тест на 3-й минуте** (LESSON-05). → Читатель без синопсиса называет, кто пишет, что от него хотят и чем это плохо кончится. «Не понял» правим раньше «скучно».
- [ ] **Пометить ненаписанные карточки `// todo`** (LESSON-08). → Перед ревью `// todo` в ink нет.
