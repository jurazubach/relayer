# Процедуры

Каждый шаг — действие, после стрелки → ожидаемый результат. Процедуры подходят и человеку, и модели.

## Как придумать и начать историю

- [ ] Запиши 1–3 вещи ядра, каждую не длиннее шести слов и без имён собственных → строка `// ядро: (1) … (2) … (3) …` в начале ink (`P-01`, `P-02`).
- [ ] Проверь, что каждая вещь — правило или способность, а не событие. Спроси себя, что ещё может случиться из-за этой вещи → у каждой вещи не меньше трёх ответов. Если ответов меньше, вещь заменяется.
- [ ] Для каждой вещи допиши «обычно …, а здесь …» → хотя бы для одной вещи фраза складывается (`P-12`).
- [ ] Заполни матрицу пар (`PAT-02`) → в каждой клетке одна сцена в одну строку. Пустых клеток нет.
- [ ] Распредели главы по клеткам → у каждой главы в `chapters[].about` указана клетка. Две главы на одну клетку не приходятся.
- [ ] Напиши `tagline` как ядро одной строкой → в ней ≤ 1 имени и ≤ 1 числа (`P-10`).
- [ ] Напиши `synopsis` только из событий первой главы и ставки → в нём нет имён, которые впервые появляются после главы 1.
- [ ] Выбери, кто произносит ядро. Это 1 контакт, максимум 2 → в первой главе 2–4 живых контакта. Сервисные допустимы, только если сами работают как вещь ядра (`P-11`).
- [ ] Напиши первые 8 реплик: вещи ядра по одной на реплику, бытовыми словами → в первых 15 репликах не больше 7 новых сущностей, которые не относятся к ядру (`P-04`, `P-09`).
- [ ] Поставь первую кнопку не позже 8-й реплики. Варианты — гипотезы о ядре или реакция на него → ни одного варианта из одной вежливости (`PAT-04`, `RED-07`).

## Как написать главу или сцену

- [ ] Назови клетку матрицы, которую закрывает глава → одна строка в комментарии над узлом `chN`.
- [ ] Перечисли новые сущности главы → их не больше 3. У каждой записан мост к вещи ядра (`P-08`).
- [ ] У каждого нового контакта первая реплика объясняет, почему он пишет игроку, через ядро → в первых трёх репликах после `#unlock` есть слово или событие ядра (`PAT-05`).
- [ ] Найди в главе момент, где ядро поворачивается новой стороной. Поставь перед объяснением кнопки-гипотезы → объяснение приходит после выбора, а не до него (`P-05`, `RED-10`).
- [ ] Вычеркни точные числа и названия, без которых сцена не меняется → в главе остаются только числа, которые игрок использует дальше: код, время, номер.
- [ ] Термины, которые нужны голосу персонажа, объясни по кнопке → объяснение только в ветке, где спросили, и дальше сюжет на термине не держится (`PAT-03`).
- [ ] Для последней главы: собери вещи ядра заново, ничего не добавляя → финал вводит не больше одного нового контакта, и тот зеркальный (`PAT-06`).

## Ревью начала

- [ ] Прочитай `tagline`, `synopsis` и первые 15 реплик `ch1`. Перескажи завязку одной фразой → фраза совпадает с `// ядро:`. Если ядра в комментарии нет, его надо восстановить и записать.
- [ ] Выпиши все новые сущности первых 15 реплик: имена, названия, числа, термины, контакты → таблица «сущность | вещь ядра | можно позже?». Порог — 7 сущностей не из ядра (`RED-02`).
- [ ] Отметь сущности, которые не относятся к ядру, и для каждой найди первое место, где она действительно нужна → список переносов «реплика → узел».
- [ ] Найди списки имён одним сообщением или `#photo` → таких нет (`RED-03`).
- [ ] Посчитай контакты, впервые появившиеся в главе 1 → ≤ 5 (`RED-04`).
- [ ] Сравни описание с ink: каждое число и имя из `synopsis` встречается в первой главе с тем же значением → ни одного расхождения (`RED-08`).
- [ ] Найди самое сильное событие истории. Есть ли его намёк в `ch1`? → да, или зафиксировано решение, почему нет (`RED-05`).
- [ ] Посмотри на первые две развилки: варианты касаются ядра? → хотя бы один вариант в каждой — гипотеза или ход, связанный с ядром (`RED-07`).

## Ревью всего сценария

- [ ] Для каждой главы найди клетку матрицы → у каждой главы есть клетка, повторов нет (`RED-09`).
- [ ] Выпиши контакты и правила мира, которые впервые появляются в последней трети глав → у каждого есть мост к ядру. Без моста — «лось» (`RED-06`).
- [ ] Проверь, на какую вещь ядра опирается финал → финал называет хотя бы две вещи ядра (`PAT-06`).

## Как тестировать

- [ ] Тест холодного читателя: дай человеку или модели без контекста `tagline` и первые 15 реплик, затем спроси «о чём история и что может случиться дальше?» → он называет вещи ядра и предлагает ≥ 3 вариации, совпадающие с клетками матрицы. Если вместо этого он пересказывает детали, начало перегружено.
- [ ] Тот же читатель: «что из прочитанного ты не понял или забыл?» → забытое должно быть не из ядра. Если забыта вещь ядра, её надо поднять раньше и сказать проще.
- [ ] После правок `npm run check:story` → нет новых тупиков, медиана длительности не выросла больше чем на 10%.
- [ ] `npm run graph`: проверь, что узлы, куда перенесены факты, проходит ≥ 60% прогонов → перенесённая улика не потерялась в редкой ветке.
- [ ] Если проверки из `for-relayer.md` §2 реализованы, запусти их → предупреждений о плотности начала и о «лосях» нет или каждое объяснено в комментарии `// ядро-исключение:`.
