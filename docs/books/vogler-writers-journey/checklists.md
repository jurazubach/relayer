# Процедуры — Vogler, The Writer's Journey

Процедуры для человека и для ИИ. У каждого шага есть ожидаемый результат. Разметка — из `patterns.md`.

## 1. Придумать и начать историю

- [ ] **Назвать героя-NPC.** Записать `// HERO: <контакт>` и одной фразой: чего он хочет и чего боится. Результат: строка в шапке ink, страх назван конкретно («меня тоже посадят», а не «правды»).
- [ ] **Назвать роль игрока.** `// PLAYER:` — 1–3 маски (mentor, ally, herald, threshold_guardian) и один личный риск игрока. Результат: понятно, почему пишут именно ему (`P-03`).
- [ ] **Найти зов и его вестника.** Кто пишет первым, что просит и какой срок. Результат: первое сообщение содержит просьбу или событие, а второе-третье — деталь обычного мира героя (`P-04`).
- [ ] **Написать отказ.** Кнопка отказа или `#silent` в первой главе, переменная, ответ вестника с поднятой ставкой (`PAT-02`). Результат: в ink есть `// stage: refusal` и `~ <var> = true`.
- [ ] **Решить, кто наставник и что он дарит.** NPC-наставник для героя или игрок как наставник. Записать дар и где он сработает. Результат: пара «переменная — узел применения» в комментарии `// GIFT: has_code -> ch3_switch`.
- [ ] **Поставить порог.** Первое необратимое действие игрока: сообщение новому контакту, ложь, отправленный файл (`P-07`). Результат: `// stage: threshold` в конце главы 1 или в начале главы 2.
- [ ] **Набросать остальные стадии одной строкой на главу** (`PAT-01`). Результат: таблица в комментарии; не все 12 стадий, но обязательно `ordeal` в середине, `resurrection` и `elixir` в конце.
- [ ] **Проверить, где шаблон не нужен.** Если история — расследование по кругу, хроника без героя или короче трёх глав, оставить из схемы только зов, испытание и эликсир (`P-17`). Результат: строка `// JOURNEY:` в шапке.

## 2. Написать главу или сцену

- [ ] **Определить стадию главы и маски.** Какая стадия героя и какие маски у контактов в этой главе. Результат: `// stage:` и `// mask:` над первыми строками.
- [ ] **Назвать, что изменится у героя к концу главы.** Внешне (что он знает, что у него есть) и внутренне (переменная дуги). Результат: хотя бы одно `~ <ARC-переменная>` в главе.
- [ ] **Если это порог — дать стражу три выхода** (`PAT-04`). Результат: ≥ 2 вариантов с разными `~`, один условный.
- [ ] **Если это середина — сделать испытание «смертью»** (`PAT-06`). Результат: герой пропадает с `#delay` ≥ 1h, другие чаты в это время пишут о худшем, герой возвращается с новым решением.
- [ ] **Если после испытания — проверить, что награду можно заработать** (`P-11`). Результат: условие по прошлой переменной меняет скорость или полноту награды.
- [ ] **Если это дорога назад — дать тени написать самой и поставить срок** (`P-12`). Результат: входящее от контакта с `mask = shadow` и число со временем.
- [ ] **Проверить, не повторяется ли маска.** Если третий контакт подряд отвечает «кто вы?» — убрать проверку (`RED-08`). Результат: не больше двух стражей в истории на 5 глав.
- [ ] **Закрыть главу крючком следующей стадии.** Последнее входящее главы обещает следующую стадию: угрозу, новый контакт, находку. Результат: длинная пауза (`#delay` ≥ 1h) только после такого крючка.

## 3. Ревью готового сценария

- [ ] **Разметить стадии, если их нет.** Пройти ink и поставить `// stage:` там, где стадия происходит. Результат: список «стадия → узел».
- [ ] **Найти пропуски.** Нет `call`, `ordeal`, `resurrection` или `elixir` — это проблема. Нет `mentor` или `road_back` — решить, нужны ли они. Результат: список пропусков с решением «добавить / не нужно, потому что…».
- [ ] **Найти шаблонность.** Все 12 стадий подряд, по одной на сцену → `RED-01`. Результат: 1–2 места, где стадии можно слить или переставить.
- [ ] **Проверить, чей путь.** Есть ли один NPC с дугой от первой главы до последней; не угрожают ли игроку напрямую (`RED-02`). Результат: имя героя и номер узла, где его дуга закрывается.
- [ ] **Проверить маски.** Для каждого контакта выписать маски по главам. Результат: ≥ 1 смена маски; улика стоит раньше смены (`P-09`).
- [ ] **Проверить отклики.** Отказ, дар, ответ на испытание: у каждого найти узел, где он читается. Результат: таблица «переменная → где читается»; пустые строки — кандидаты в `RED-04`/`RED-05`.
- [ ] **Проверить воскрешение.** Решает ли герой сам? Есть ли условные варианты из прошлого и один безусловный? Результат: вердикт по `RED-10`/`RED-11`.
- [ ] **Проверить эликсир.** Выписать первое входящее и последние строки каждого финала. Результат: в каждом финале есть деталь первой сцены или явная перемена у ≥ 3 контактов.

## 4. Тестировать

- [ ] **Прогнать сценарий ботом.** `npm run check:story`. Результат: 0 тупиков, все узлы посещены, все прохождения дошли до конца.
- [ ] **Сравнить место испытания с серединой.** По медианному пути найти номер входящего у `// stage: ordeal`, поделить на общее число. Результат: 40–60%. Если вне коридора — сдвинуть или пометить, почему нарочно.
- [ ] **Посмотреть распределение финалов.** Если одна концовка выпадает у > 50% случайных прохождений, проверить, не обходит ли она воскрешение ранним выходом. Результат: у каждого финала, кроме «пассивного», путь проходит через узел `resurrection`.
- [ ] **Пройти три роли руками** (с `?fast=1`): «согласный помощник», «отказник», «молчун» (всегда `#silent`, если есть). Результат: у отказника и молчуна в финале есть строки, которых нет у согласного.
- [ ] **Проверить паузы испытания.** В отладке поставить ×1 и пройти испытание. Результат: во время долгой паузы игрок получает уведомление из другого чата хотя бы раз в 1–2 часа сюжетного времени.
- [ ] **Карта** (`npm run graph`). Результат: узел `resurrection` читает ≥ 2 переменных из разных глав; у узлов порога и испытания ≥ 2 исходящих ветки или ≥ 2 разных `~`.
- [ ] **Проверка компиляции отдельного ink-фрагмента:** `node -e "const {Compiler}=require('inkjs/full');const c=new Compiler(require('fs').readFileSync(process.argv[1],'utf8'));try{c.Compile();console.log('ok')}catch(e){console.log(c.errors)}" файл.ink`. Результат: `ok`.

## 5. Второй проход: дополнительные шаги

- [ ] **Записать, зачем герою игрок** (к §1). Рядом с `// HERO:` — нехватка героя: опыт, связь, доверие. Результат: герой задаёт игроку вопрос в первых 3 входящих (LESSON-05, `RED-13`).
- [ ] **Холодный тест на заботу** (к §4). Дать первую главу человеку, не знающему историю, и спросить: «Ради кого ты откроешь следующее уведомление?» Результат: ответ называет героя, а не загадку (LESSON-08).
- [ ] **Проверить основания советов** (к §3). Для каждой развилки, где совет игрока меняет судьбу героя, найти сообщение раньше, из которого совет можно вывести. Результат: нет «слепых» развилок с ценой (LESSON-07).
- [ ] **Сравнить испытание и воскрешение** (к §3). Выписать ставку обеих сцен. Результат: в воскрешении ставка выше или лично дороже; последняя кнопка — у игрока (LESSON-03, `RED-15`).
- [ ] **Проверить паузу испытания** (к §4). Для каждого `#delay` ≥ 1h на `ordeal` — есть ли входящее другого контакта. Результат: ни одной пустой паузы (`V15`, `RED-14`).
- [ ] **Короткая история — четыре шага** (к §1). Если история ≤ 15 минут, разметить только `call`, `threshold`, `ordeal`, `elixir` (`PAT-11`). Результат: `// JOURNEY: partial (…)` в шапке, ни одной пустой стадии.
