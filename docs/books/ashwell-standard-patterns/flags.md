# Флаги — Ashwell, Standard Patterns in Choice-Based Games

Флаги про структуру ветвления. Сам признак обычно описан у Эшвелла (статья, IFWiki). Пороги и способы подсчёта — наши: Эшвелл чисел не даёт.
Данные для подсчёта: `graph/index.html` (в `knots[]` у узла есть `visits`, `edges[].path` с `choice` и `cond`, `chapter`), исходник ink и отчёт `npm run check:story`.

## Красные флаги

| id | признак | почему плохо | как обнаружить | как чинить |
|---|---|---|---|---|
| RED-01 | Больше 60% узлов на 100%, `V`-развилок меньше двух, а переменные читаются только в финале | это коридор с сортировкой в конце, выборы до финала ни на что не влияют | карта: доля `visits >= 99`. Скрипт: все чтения переменных в последней главе | `PAT-12`: перевести в branch and bottleneck |
| RED-02 | Развилка сходится через `-`, и ни один вариант ничего не записывает | выбор стирается слиянием (`P-02`) | ink: блок `*` … `-` без `~` и без `->` в другом узле, и у всех вариантов одинаковый `#to:` | привязать хотя бы один вариант к оси (`~ ось += 1`) или убрать развилку |
| RED-03 | Первые две главы у всех проходов одинаковы по узлам | ветвление с горлышком расходится поздно, и начало ощущается линейным (`P-04`) | карта: в главах 1–2 нет узлов с `visits < 90`, кроме однострочных | в главе 1 дать один выбор с видимым откликом в той же главе, через 2–5 сообщений |
| RED-04 | Переменная записывается и ни разу не читается | потраченный выбор (`P-06`) | скрипт: чтений = 0. Пример — `called_bluff` в «Чужом голосе» | прочитать в следующей главе или удалить запись |
| RED-05 | Отношение записей к чтениям больше 4 | много выборов сжаты в один-два невидимых порога, игрок не узнаёт своих решений | скрипт: `writes / reads > 4`. Примеры — `ellie_trust` 23/5, `jess_clues` 14/2, `maya_trust` 16/3 | добавить промежуточные пороги с репликами (`{ellie_trust >= 2: …}`) в главах между записями |
| RED-06 | Финалы выбирает только скрытая проверка без последнего выбора | игрок не понимает, за что получил финал | условия финальной `V`-развилки не содержат ни одной переменной, записанной в последней главе | дать последнюю кнопку, которая пишет `final_choice` (`P-11`) |
| RED-07 | Финал решает только последняя кнопка, без условий | десять глав выборов обнуляются одной кнопкой | у узла с ребрами в 3+ финала: развилка `C` без `{cond}` на кнопках и без `V` после | добавить `[v]` по ранним осям внутри каждого финала или после кнопки (`end_ellie` уже так делает) |
| RED-08 | Боковой узел набирает меньше 10% прохождений и длиннее 15 сообщений | дорогой текст, который почти никто не увидит (`P-10`) | карта: `visits < 10`, число элементов `msg/me/sys` > 15 | сократить, поднять вероятность входа или сделать намеренной наградой |
| RED-09 | Правильная игра даёт меньше текста, чем неправильная | награда воспринимается как наказание | сравнить длину ветки `visits` у «хорошего» пути с длиной ствола: в «Слепом пятне» `ch4_locked` (18,5%) — 28 строк ink против ≈150 в стволе `ch4_oidc…ch4_cleanup` | дописать в короткую ветку свою сцену с новой угрозой, чтобы глава не теряла длину |
| RED-10 | Глава строится на `+` кнопках без выхода по условию | открытая карта без цели, игрок крутится в петле (`PAT-08`) | ink: узел с `+` и `-> сам себя`, без кнопки `{cond}` наружу | добавить выход после N заходов или по событию |
| RED-11 | Ветка закрывается без причины: «Конец» без реплики собеседника или `#sys` | обрыв выглядит отказом автора (`P-05`) | узел с одним входом, у которого последняя строка перед `-> END` — `Конец #sys` и не больше 2 строк до неё | дать собеседнику закрыть дверь своим голосом |
| RED-12 | Ставка или срок истории есть только в необязательной ветке | у части игроков нет опоры, и начало непонятно (`P-08`) | грепом найти строки со сроком («через N дн», «завтра», «до …») и посмотреть `visits` их узла. `ch1_party` — 35% | перенести срок в ствол первой главы |

## Где игроку станет скучно

У Эшвелла скука прямо не обсуждается, но две структуры он описывает как замедляющие. Открытая карта даёт неторопливый, менее направленный темп. Петля требует оправдания повтора. Вместе с нашими метриками это даёт такие признаки:

- **Длинный ствол из пустых выборов.** Больше 3 узлов подряд на 100%, все развилки которых сходятся без записи (`RED-02` по цепочке). Пример — `laundry_arrival` в THE NUMBER, разбор в `for-relayer.md`, раздел 4, п. 7.
- **Серия косметических выборов.** Три пустые развилки подряд (`P-09`). Игрок перестаёт читать варианты и жмёт первый. Бот это видит: на таких развилках кнопки выбирают примерно поровну, но разницы на выходе нет.
- **Повтор без роста.** `+` кнопка, которая при втором нажатии даёт тот же текст (`RED-10`).
- **Ожидание без отклика.** Пауза в часы (`#delay:2h`+) перед сценой, которая не отличается в зависимости от прошлого выбора. Игрок ждал, а пришло то же, что пришло бы любому. Ставить после долгой паузы условную первую реплику (`GREEN-01`).

## Почему начало не цепляет или непонятно

Про начало у Эшвелла есть только структурные следствия:
- Ветвление с горлышком в начале по определению похоже у всех (`RED-03`). Если история на нём построена, первая глава должна цеплять другим: ставкой, срочностью, загадкой. На ветвлении её не вытянуть.
- Широкое раннее ветвление (sorting hat, time cave) без опор даёт свободу без понимания (`P-08`). В первой главе держать 1–3 контакта и одну ставку.
- Ставка, спрятанная в необязательную ветку, у большинства игроков не появляется вовсе (`RED-12`).
- Проверка по боту: в первой главе есть хотя бы одна кнопка, после которой разница видна в пределах той же главы (не только в финале).

## Почему выбор не ощущается

- Слияние без памяти (`RED-02`).
- Запись без чтения (`RED-04`) или сжатие многих записей в один порог (`RED-05`).
- Чтение только в скрытой финальной проверке (`RED-06`).
- Распределение по линиям не обозначено, и игрок принимает линейную вторую половину за отсутствие выбора (`P-07`). Эшвелл называет такой сигнал важным, но прямым правилом не формулирует.
- Невидимое горлышко с одинаковыми кнопками, где шов виден (`PAT-05`): те же формулировки вариантов в обеих ветках, а текст перед ними одинаков по смыслу.
