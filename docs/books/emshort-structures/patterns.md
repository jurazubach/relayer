### PAT-01. Выбор с подтверждением (Confirmation-required Choice)
- **Когда применять:** один вариант рискованный и интересный, другой безопасный и пресный; риск должен стать сценой, а не одной кнопкой. **Когда нет:** оба варианта равноценны (тогда PAT-02) или риск ни к чему не приведёт (тогда предупреждения — ложь, см. P-02).
- **Схема:**
  ```
  [риск] → деталь 1 → [настоять | отступить]
                     → деталь 2 → [настоять | отступить]
                                 → ИСХОД (плохой, не смягчать)
  [безопасно] ───────────────────────→ отступление
  ```
- **На ink:**
  ```ink
  # contact: mira, Мира, teal
  VAR reckless = 0
  мне кажется в подвале кто-то есть #from:mira
  дверь приоткрыта
  * [Спустись и посмотри #to:mira]
      ~ reckless += 1
      там пахнет бензином #from:mira #delay:40s
      и ступенька сломана
      ** [Всё равно иди #to:mira]
          ~ reckless += 1
          слышу шаги. не мои #from:mira #delay:1m
          *** [Иди дальше #to:mira #label:Настоять в третий раз]
              ~ reckless += 1
              -> cellar
          *** [Поднимайся. Быстро #to:mira]
              -> retreat
      ** [Ладно, не надо #to:mira]
          -> retreat
  * [Не ходи. Звони в полицию #to:mira]
      -> retreat
  === cellar ===
  телефон сел на 2% #from:mira #delay:30s
  Мира не в сети #sys:mira
  -> END
  === retreat ===
  ок. я наверху #from:mira #delay:20s
  -> END
  ```
- **Цена:** 2–3 коротких такта на одну развилку, одна переменная. Ветки отступления сходятся в один узел.
- **Ловушки:** паузы между тактами больше пары минут гасят напряжение; детали повторяют друг друга («опасно», «очень опасно») вместо новой информации; исход на «настоял трижды» ничем не хуже отступления.
- **Источник:** [S1].

### PAT-02. Выбор с переключением колеи (Track Switching Choice)
- **Когда применять:** одно трудное решение, где герой должен колебаться; у каждой стороны есть свои минусы. **Когда нет:** решение очевидно, или минусы одной стороны нечем показать.
- **Схема:**
  ```
  [A | B] → минус текущей стороны → [переключиться | остаться]
          → ещё минус текущей      → [переключиться | решено]
          → реакция по flips
  ```
- **На ink:** туннель `flip` переключает сторону и считает колебания.
  ```ink
  # contact: dan, Дэн, blue
  VAR go = false
  VAR flips = 0
  мне предлагают уехать в осло. ответ завтра #from:dan
  * [Соглашайся #to:dan]
      ~ go = true
  * [Оставайся #to:dan]
  - {go:мама расстроится|но контракт же на два года} #from:dan #delay:1m
  * [Тогда наоборот #to:dan]
      -> flip ->
  * [Нет, я за своё #to:dan]
  - {go:квартиру сдать до пятницы|в офисе опять сокращения} #from:dan #delay:2m
  * [Ладно. Наоборот #to:dan]
      -> flip ->
  * [Решено #to:dan]
  - {flips >= 2:ты меня совсем запутал|ок. так и сделаю} #from:dan #delay:30s
  -> END
  === flip ===
  ~ go = not go
  ~ flips += 1
  ->->
  ```
- **Цена:** каждый такт — две версии реплики (по стороне). Кнопки общие.
- **Ловушки:** реплика такта не зависит от стороны, тогда переключение бессмысленно; больше трёх тактов утомляет.
- **Источник:** [S1].

### PAT-03. Выбор по очкам (Scored Choice)
- **Когда применять:** монтаж мелких решений на одну ось (работа ↔ близкий человек, правда ↔ безопасность), исход — по перевесу. **Когда нет:** нужно одно ясное решение с понятной ценой.
- **Схема:** `N мелких выборов (N нечётное) → a += 1 | b += 1 → { a > b: X | Y }`
- **На ink:** голосование тем, в какой чат ответить.
  ```ink
  # contact: lena, Лена, pink
  # contact: boss, Шеф, grey
  VAR work = 0
  VAR lena = 0
  у меня концерт в семь. придёшь? #from:lena
  отчёт к утру, без вариантов #from:boss #delay:3m
  * [Приду! #to:lena]
      ~ lena += 1
  * [Сделаю к утру #to:boss]
      ~ work += 1
  - шеф опять пишет? #from:lena #delay:20m
  * [Выключил телефон #to:lena]
      ~ lena += 1
  * [Да, извини, минуту #to:lena]
      ~ work += 1
  - где цифры по маю #from:boss #delay:30m
  * [Утром #to:boss]
      ~ lena += 1
  * [Высылаю #to:boss]
      ~ work += 1
  - {work > lena: -> late | -> came}
  === late ===
  мы уже на бисе #from:lena #delay:1h
  -> END
  === came ===
  вижу тебя у сцены! #from:lena #delay:1h
  -> END
  ```
- **Цена:** дёшево — кнопки сходятся сразу, разница только в счётчике и финальной ветке.
- **Ловушки:** чётное N без обработки ничьей; голоса не видны в репликах, и итог выглядит случайным — дай собеседнику реагировать по ходу («шеф опять пишет?»).
- **Источник:** [S1].

### PAT-04. Узел разговора с повторным входом (Re-enterable Conversation Node)
- **Когда применять:** нужно выдать экспозицию или улики, порядок неважен; хочется узнать, что интересует игрока. **Когда нет:** темы зависят друг от друга по порядку (тогда цепочка).
- **Схема:**
  ```
       ┌──── тема A ────┐
  хаб ─┼──── тема B ────┼─→ хаб (asked += 1) ─→ лимит → выход
       └── [Хватит] ────┴──────────────────────────────→ выход
  ```
- **На ink:** `*` тема пропадает после выбора, `+` выход доступен всегда, `asked` ограничивает число тем.
  ```ink
  # contact: ira, Ира, amber
  VAR asked = 0
  VAR cares_money = false
  есть десять минут, спрашивай что хочешь #from:ira
  -> topics
  === topics ===
  {asked >= 2: -> leave}
  * [Кто ещё знал про ключ? #to:ira]
      ~ asked += 1
      только я и сосед #from:ira #delay:30s
      -> topics
  * [Сколько стоила та картина? #to:ira]
      ~ asked += 1
      ~ cares_money = true
      тебе правда это важно? #from:ira #delay:40s
      -> topics
  * [Почему ты не позвонила сразу? #to:ira]
      ~ asked += 1
      испугалась #from:ira #delay:1m
      -> topics
  + [Хватит, спасибо #to:ira]
      -> leave
  === leave ===
  всё, мне пора #from:ira #delay:20s
  {cares_money:и не думай про деньги, ладно?}
  -> END
  ```
- **Цена:** одна реплика на тему плюс флаг; ветвления нет.
- **Ловушки:** нет выхода без перебора всех тем; все темы обязательны (тогда это просто линейный текст с лишними кликами); флаги интереса нигде не используются.
- **Источник:** [S1] (лимит и гейт тем — stat enhancements из статьи).

### PAT-05. Распределяющая шляпа в первой главе (Chapter One Sorting Hat)
- **Когда применять:** историю будут перепроходить; нужно, чтобы разница была видна с первых минут. **Когда нет:** короткая история на один раз — две полных линии первой главы не окупятся.
- **Схема:**
  ```
  старт → [роль A] → линия A (свои мелкие выборы → флаги) ┐
        → [роль B] → линия B (свои мелкие выборы → флаги) ┴→ бутылочное горлышко → глава 2 (реплики по роли)
  ```
- **На ink:**
  ```ink
  # contact: oleg, Олег, orange
  # contact: vera, Вера, purple
  VAR origin = ""
  VAR loud = 0
  Глава 1 · Кто ты #sys:oleg #chapter
  ты кто вообще? #from:oleg
  * [Сестра Веры #to:oleg]
      ~ origin = "sister"
      -> sister
  * [Её адвокат #to:oleg]
      ~ origin = "lawyer"
      -> lawyer
  === sister ===
  она про тебя не говорила #from:oleg #delay:30s
  * [Мы не общались три года #to:oleg]
  * [Значит, было за что #to:oleg]
      ~ loud += 1
  - -> ch2
  === lawyer ===
  мне нечего вам сказать без своего юриста #from:oleg #delay:30s
  * [Это неформальный разговор #to:oleg]
  * [Тогда увидимся в суде #to:oleg]
      ~ loud += 1
  - -> ch2
  === ch2 ===
  Глава 2 · Вера #sys:vera #chapter #delay:2h
  {origin == "sister":привет. не ожидала|здравствуйте. вы по делу?} #from:vera #unlock:vera
  {loud > 0:олег говорит, ты на него наехал #delay:20s}
  -> END
  ```
- **Цена:** первая глава пишется N раз (по числу ролей); дальше — только реплики-колбэки.
- **Ловушки:** после шляпы история становится почти неинтерактивной (Short предупреждает: если шляпа — структура всей игры, после первого решения она почти неинтерактивна); роль нигде не упоминается после горлышка.
- **Источник:** [S1]; определение — [S4].

### PAT-06. Пещера времени в финале (Endgame Time Cave)
- **Когда применять:** последняя глава истории с накопленными переменными: каждой комбинации — свой финал. **Когда нет:** в середине истории (взрыв объёма) и если переменных, которые игрок осознаёт, меньше двух.
- **Схема:**
  ```
  итоговый узел ─┬─ {A && B}  → финал 1
                 ├─ {A}       → финал 2
                 ├─ {C >= 3}  → финал 3
                 └─ else      → финал 4
  ```
- **На ink:** значения переменных заданы для примера; в истории их набирают главы раньше.
  ```ink
  # contact: kai, Кай, cyan
  VAR kai_trust = 2
  VAR proof = 1
  VAR told_police = false
  -> route
  === route ===
  {
  - told_police && proof >= 2: -> fin_case
  - told_police: -> fin_doubt
  - kai_trust >= 3: -> fin_friend
  - else: -> fin_alone
  }
  === fin_case ===
  дело открыли. спасибо #from:kai
  -> END
  === fin_doubt ===
  мне сказали: доказательств нет #from:kai
  -> END
  === fin_friend ===
  я никому не скажу. но я помню #from:kai
  -> END
  === fin_alone ===
  Кай удалил чат #sys:kai
  -> END
  ```
- **Цена:** каждый финал — отдельный текст, зато продолжать его не нужно. Эпилоги-колбэки по флагам добавляются строчкой.
- **Ловушки:** финал выбирает скрытая проверка, а игрок не знает, что эти переменные что-то значили (см. P-09); один финал выпадает в 70 % прохождений, другие почти недостижимы.
- **Источник:** [S1]; трудоёмкость time cave — [S3], [S4].

### PAT-07. Пул улик в любом порядке (storylets / quality-based narrative)
- **Когда применять:** игрок собирает несколько фактов, и порядок не важен; часть фактов открывается только после других. **Когда нет:** важна последовательность откровений (каждое меняет смысл предыдущего).
- **Схема:**
  ```
  хаб: [факт A] [факт B] [факт C если B] → clues += 1 → хаб
  clues >= 2 → обвинение (вариант только при нужной паре фактов)
  ```
- **На ink:** каждый вариант — сторилет: условие в фигурных скобках, текст, эффект `~`.
  ```ink
  # contact: nik, Ник, indigo
  # contact: zoya, Зоя, green
  VAR clues = 0
  VAR ticket = false
  VAR photo = false
  -> board
  === board ===
  {clues >= 2: -> accuse}
  * [Где ты был в субботу? #to:nik]
      ~ ticket = true
      ~ clues += 1
      в кино. билет сохранил. сеанс 21:40 #from:nik #delay:1m
      -> board
  * [Есть фото с вечеринки? #to:zoya]
      ~ photo = true
      ~ clues += 1
      вот. ник в углу, 21:50 #from:zoya #delay:2m
      -> board
  * {photo} [Кто звонил Нику в 21:52? #to:zoya]
      ~ clues += 1
      я. он вышел говорить на улицу #from:zoya #delay:1m
      -> board
  === accuse ===
  * {ticket && photo} [Сеанс в 21:40, а в 21:50 ты на фото #to:nik]
      ...ладно. я не ходил в кино #from:nik #delay:4m
      -> END
  + [Пока ничего не спрашивать #to:nik #silent]
      ок #from:nik #delay:10m
      -> END
  ```
- **Цена:** линейная по числу фактов; порядок прохождения — бесплатно.
- **Ловушки:** обвинение доступно только при одной комбинации, и бот показывает, что до неё доходят редко; игрок не понимает, почему кнопки обвинения нет — дай персонажу намекнуть, чего не хватает.
- **Источник:** [S2] (пример про три улики в любом порядке как сильная сторона QBN), [S3].

### PAT-08. Самая подходящая реплика (salience-based)
- **Когда применять:** приветствие в начале главы, реакция на возвращение в чат, эпилог — когда состояний много, а реплика одна. **Когда нет:** выбор основной сцены или финала без контроля дуги (P-12).
- **Схема:** `условия от узкого к широкому → первое совпадение → else (общая реплика)`
- **На ink:** блок `{ - … }` берёт первую подходящую ветку.
  ```ink
  # contact: ana, Аня, amber
  VAR lied_to_ana = false
  VAR met_brother = false
  VAR late = true
  -> react
  === react ===
  // реплика с самым узким условием — первой, общая — последней
  {
  - lied_to_ana && met_brother:
      брат сказал, ты был у него. зачем врал? #from:ana
  - lied_to_ana:
      ты опять что-то не договариваешь #from:ana
  - late:
      ты где был всю ночь? #from:ana
  - else:
      привет #from:ana
  }
  -> END
  ```
- **Цена:** одна строка на правило; добавляется по одному.
- **Ловушки:** широкое условие стоит выше узкого и перекрывает его навсегда; нет `else`, и при неожиданном состоянии реплика пустая.
- **Источник:** [S2]; порядок по специфичности — [S5].

### PAT-09. Разговор по путевым точкам (waypoint narrative)
- **Когда применять:** у собеседника своя цель (выманить, признаться, попросить), а игрок может тянуть время и уводить разговор. **Когда нет:** игрок сам ведёт разговор и у собеседника нет цели.
- **Схема:**
  ```
  тема-старт → [увод] → тема-мост → … → ЦЕЛЬ
             ↘ после N уводов персонаж говорит прямо ↗
  ```
- **На ink:** переменная `topic`, счётчик уводов `pulled`; любой путь ведёт к цели.
  ```ink
  # contact: rita, Рита, red
  VAR topic = "weather"
  VAR pulled = 0
  // цель Риты — тема "debt". Игрок может увести разговор, но Рита вернётся
  ну и ливень сегодня #from:rita
  -> steer
  === steer ===
  {topic == "debt": -> debt}
  {pulled >= 2: -> debt_forced}
  * [Как мама? #to:rita]
      ~ pulled += 1
      нормально. кстати, о маме — она спрашивала про деньги #from:rita #delay:40s
      ~ topic = "money"
      -> steer
  * [Слушай, мне бежать #to:rita]
      ~ pulled += 1
      две минуты. это важно #from:rita #delay:20s
      -> steer
  * {topic == "money"} [Ты про долг? #to:rita]
      ~ topic = "debt"
      -> steer
  === debt_forced ===
  ладно, прямо: ты должен мне сорок тысяч #from:rita #delay:30s
  -> END
  === debt ===
  да. я про долг #from:rita #delay:30s
  -> END
  ```
- **Цена:** реплика на каждый переход; сеть тем быстро разрастается, в ink держи её в 3–5 темах.
- **Ловушки:** персонаж на увод отвечает не по теме (выглядит как бот); нет «прямого» выхода, и разговор зацикливается; приём растянут на всю главу, и игрок только тормозит чужой разговор — Short сама называет узкую роль игрока слабостью waypoint.
- **Источник:** [S2] (метод Glass). Наша версия упрощена: настоящая система ищет путь по сети тем, у нас переходы прописаны руками.

### PAT-10. Прогресс и угроза (progress stat + menace stat)
- **Когда применять:** серия однотипных испытаний (взлом, погоня, допрос), где ошибки должны копиться, а не обрывать историю сразу. **Когда нет:** одно решение с ясной ценой.
- **Схема:** `шаг → верно: progress += 1 | ошибка: menace += 1 → ворота: menace >= M → провал; progress >= P → успех; иначе → шаг`
- **На ink:**
  ```ink
  # contact: lev, Лев, lime
  VAR progress = 0
  VAR menace = 0
  -> step
  === step ===
  {menace >= 2: -> caught}
  {progress >= 2: -> out}
  {мне нужен код от двери|теперь вторая дверь|последняя} #from:lev #delay:1m
  + [Код 4471 #to:lev]
      ~ progress += 1
      открыто #from:lev #delay:30s
  + [Не помню, попробуй 0000 #to:lev]
      ~ menace += 1
      пищит. кажется, сработало что-то #from:lev #delay:30s
  - -> step
  === out ===
  я снаружи #from:lev
  -> END
  === caught ===
  охрана. всё #from:lev
  -> END
  ```
- **Цена:** 2 переменные и 2 проверки вместо дерева ошибок. По нашему прочтению это gauntlet (коридор) Ashwell, где ошибка не сразу обрывает историю; в [S3] gauntlet собран из сторилетов только на схеме.
- **Ловушки:** угрозу видно только по цифре в отладке — собеседник должен нервничать сильнее с каждой ошибкой; петля с `*` вместо `+` заканчивает варианты и даёт тупик.
- **Источник:** [S3] (progress — насколько далеко игрок продвинулся, menace — насколько он в беде); термин gauntlet — [S4].

### PAT-11. Счётчик тона с функцией-реакцией (наше расширение scored choice)
- **Когда применять:** много кнопок, которые различаются только тоном (в «Чужом голосе» таких 126 из 338). **Когда нет:** выбор меняет факты сюжета: тогда это флаг поступка, а не тон.
- **Схема:** `тональная кнопка → ~ warm ± 1 → сразу сходится → … → функция reply(warm) в другом узле и главе`
- **На ink:** порог живёт в функции, узлы её только вызывают.
  ```ink
  # contact: dina, Дина, teal
  VAR warm = 0
  я опять всё испортила #from:dina
  * [Эй. Бывает #to:dina]
      ~ warm += 1
  * [Ну да, испортила #to:dina]
      ~ warm -= 1
  * [Что именно? #to:dina]
  - ладно #from:dina #delay:30s
  Глава 2 · Утро #sys:dina #chapter #delay:2h
  {greet()} #from:dina
  -> END
  === function greet() ===
  {
  - warm > 0: ~ return "спасибо за вчера"
  - warm < 0: ~ return "доброе. если оно доброе"
  - else: ~ return "привет"
  }
  ```
- **Цена:** одна строка `~` на кнопку и одна функция на собеседника.
- **Ловушки:** счётчик читается только в финале (RED-02); порог дублируется в разных узлах с разными числами (как `ellie_trust`: `>= 3` и `>= 2`), а функция держит его в одном месте.
- **Источник:** наше расширение [S1], см. P-16.

### PAT-12. Петля с ростом (loop-and-grow)
- **Когда применять:** история идёт днями или сменами. Каждый день повторяет одну рамку (утро — разговор — вечер), но состояние копится, и рамка звучит иначе. У нас день и так задаёт реальное время. **Когда нет:** каждый день приносит новое событие, рамку незачем повторять. Тогда это обычные главы.
- **Схема:** `рамка дня → выбор (+ счётчик) → проверка «последний день?» → реплика по счётчику → рамка следующего дня (приветствие по значимости)`.
- **На ink:** петля на `+`: вариант `*` исчезает после первого дня и даёт тупик на втором. Мы на этом обожглись при проверке примера.
  ```ink
  # contact: sasha, Саша, teal
  VAR day = 0
  VAR trust = 0
  -> morning
  === morning ===
  ~ day += 1
  {
  - day == 1: опять не спала. ты тут? #from:sasha
  - trust >= 2: ты первый, кому я пишу с утра #from:sasha #delay:8h
  - else: доброе #from:sasha #delay:8h
  }
  + [Тут. Что случилось? #to:sasha]
      ~ trust += 1
  + [Давай позже #to:sasha]
  - (after)
  {day >= 3: -> ending}
  {trust >= day:спасибо что слушаешь|ладно, пойду} #from:sasha #delay:1m
  -> morning
  === ending ===
  {trust >= 2:я всё-таки пошла к врачу. с тобой не страшно|я так никуда и не пошла} #from:sasha #delay:2m
  -> END
  ```
- **Цена:** одна рамка вместо N глав; на каждый день — 1–2 строки, зависящие от счётчика. Дешевле всего в паттернах.
- **Ловушки:** рамка не меняется, и игрок видит повтор (RED-15). Хотя бы приветствие должно зависеть от состояния. Петля с `*` кончается тупиком. Дней больше 3–5: в реальном времени это неделя одинаковых утр.
- **Источник:** [S3] (loop-and-grow как одна из классических структур на сторилетах; пример — Bee). Пример ink наш, скомпилирован и прогнан 300 раз, оба финала выпадают примерно поровну.

## Устройство систем источника

В статьях пять систем. Ниже для каждой: элементы, шаги со входом и выходом, что ломается без шага, где систему понимают неправильно и как её сжимают для коротких форм. Термины и смысл — по [S1]–[S3], формулировки и примеры наши.

### SYS-1. Мелкие структуры с «усилителями состояния» (stat enhancements) — [S1]

**Элементы.**
- *Базовая структура* — одна из шести (PAT-01…PAT-06). Определяет форму сцены: сколько тактов, куда сходятся ветки.
- *Усилитель состояния* (stat enhancement) — счётчик, который запоминает, как игрок прошёл структуру. Важен не выбранный вариант, а манера: как долго держался риска, как часто стоял на итоговой стороне, какие темы спрашивал.
- *Отложенное чтение* — место позже, где усилитель меняет текст. В статье это подразумевается, а не расписано: Short ссылается на статью Choice of Games о шкалах ([L9] в `lessons.md`).

**Шаги.**
| шаг | вход | выход |
|---|---|---|
| 1. Назвать тип решения | сцена, в которой игрок что-то решает | один из шести типов: риск, дилемма, ось ценностей, экспозиция, старт, финал |
| 2. Взять структуру | тип | PAT-01…PAT-06 со схемой тактов |
| 3. Навесить усилитель | структура | `VAR` с ясным смыслом («сколько раз настоял») |
| 4. Назначить чтение | `VAR` | узел в другой сцене и реплика по порогу |

**Если шаг пропустить.** Без шага 1 структуру берут по вкусу: подтверждение риска на равноценной дилемме превращается в «точно? точно?». Без шага 3 структура работает только внутри сцены, и Short сама замечает, что выбор по очкам практически требует переменных. Без шага 4 получается RED-01: счётчик есть, ответа мира нет.

**Ошибки понимания.**
- «Подтверждение = диалог „вы уверены?“». Нет: каждый такт добавляет новую информацию об опасности, иначе это лишний клик.
- «Шляпа — структура всей истории». Short называет её началом для перепроходимых историй. Как структура целиком она почти лишает игру интерактивности после первого выбора.
- «Пещера времени в финале = много концовок». Концовки должны выдавать итог накопленных шкал. Веер без накопленного состояния — просто дорогая развилка.
- «Шесть приёмов — каталог, бери любой». Они парами решают разные задачи: подтверждение и переключение колеи — для одного решения, очки — для серии, хаб — для экспозиции, шляпа и пещера — для краёв истории.

**Короткие формы.** На 5 минут — одна структура на сцену и один усилитель, который читается в последней строке. На главу — две-три структуры, усилители читаются в следующей главе. Шляпа и пещера окупаются, только если история длиннее одной сессии.

### SYS-2. Нарратив на качествах (QBN) — [S2], [S3]

**Элементы.**
- *Качество* (quality) — число: предмет, навык, отношение, шаг сюжета.
- *Сторилет* (storylet) — короткий кусок текста с выбором, у него есть *предусловия* (prerequisites) и *эффекты* (effects).
- *Отбор* — какие сторилеты сейчас доступны. В QBN из доступных выбирает игрок.
- *Хребет* — качество-прогресс, которое ведёт главную линию. Short называет ручной учёт хребта многими значениями слабостью системы.

**Шаги.** Завести качества (вход — оси истории, выход — список `VAR`) → написать сторилеты (вход — событие, выход — текст + условие + эффект) → отбор (вход — состояние, выход — набор доступных кнопок) → выбор игрока → эффект меняет состояние → снова отбор.

**Если шаг пропустить.** Без хребта история распадается на независимые эпизоды без кульминации. Без эффектов сторилеты не открывают друг друга, и меню не меняется. Без колбэков к раннему контенту (ветки, которые открывает предмет из прошлой истории) теряется то, что Short считает сильной стороной системы.

**Ошибки понимания.**
- «QBN — это гринд». Гринд был чертой раннего Fallen London, а не системы ([S3]), и Failbetter сама его урезала ([L7]).
- «QBN — значит без структуры». Классические структуры собираются из сторилетов через прогресс и угрозу ([S3]); см. SYS-5.
- «Чем больше сторилетов, тем лучше». Мало — пресно, много — перегружает ([S2], [L11]).

**Короткие формы.** Хаб внутри одной главы на 3–4 сторилета, 1–2 из них открываются по состоянию (PAT-07). Хребет — номер главы.

### SYS-3. Нарратив на значимости (salience) — [S2]

**Элементы.** Пул реплик или сцен с условиями; мера значимости (сколько условий совпало или их вес); правило ничьей (у Short — случайное); общая запасная реплика; для сцен — переменные дуги, которые не дают выпасть развязке рано.

**Шаги.** Написать общую реплику (вход — ситуация, выход — `else`) → играть и замечать момент, который стоит отметить → написать частную реплику с условием → поставить её выше общей → прогнать случайными прохождениями и посмотреть, что не выпадает и что выпадает слишком часто.

**Если шаг пропустить.** Без общей реплики при неожиданном состоянии наступает тишина (RED-10). Без прогона широкое условие перекрывает узкое навсегда. Без переменных дуги — развязка не вовремя (P-12). Без правила ничьей поведение недетерминировано, и баг не воспроизвести.

**Ошибки понимания.**
- «Значимость решает, какая будет сцена». Для реплик это безопасно, для сцен рискованно. Short сама не уверена, решала ли The King of Chicago эту проблему.
- «Веса надо вычислить». Их угадывают и правят пробами ([S2], ответ в комментариях); см. LESSON-14.
- «Это то же, что QBN». В QBN выбирает игрок из доступного, в salience выбирает система.

**Короткие формы.** Только реплики: приветствие главы, первая строка после паузы, эпилог. Порядок веток вместо весов.

### SYS-4. Нарратив по путевым точкам (waypoint) — [S2], метод Glass

**Элементы.** Сеть тем; реплики висят на *переходах* между темами, а не на самих темах; *темы-триггеры* двигают сюжет; персонаж *прокладывает путь* к ближайшему триггеру; уже пройденные переходы весят меньше; есть запасной текст; есть темы, куда может свернуть только игрок, и они уводят в другие сцены.

**Шаги.** Нарисовать сеть тем (вход — что персонаж хочет сказать и о чём игрок может спросить, выход — граф 3–8 тем) → написать реплику на каждый переход → отметить триггеры → назначить игроку темы, недоступные персонажу → прогнать: из любого состояния персонаж доходит до триггера.

**Если шаг пропустить.** Без реплик на переходах персонаж отвечает «не по теме», как бот. Без понижения весов он ходит одним путём, и разговор повторяется. Без запасного текста — тупик. Без тем только для игрока у игрока нет рычага, он только тормозит.

**Ошибки понимания.**
- «Игрок ведёт разговор». Ведёт персонаж, игрок проявляет подтекст и задерживает. Short прямо говорит, что ответственность за ход сюжета лежит на персонажах, а у игрока роль «нарушителя», и оправдывает это в Glass рамкой (игрок — попугай). Слабостью она это не называет; ограниченность роли — наш вывод для формата без такой рамки.
- «Это дерево диалога». Нет: реплика определяется парой «откуда — куда», поэтому один и тот же триггер звучит по-разному.

**Короткие формы.** PAT-09: 3–5 тем, переходы руками, после двух уводов персонаж говорит прямо. Тема только для игрока — одна кнопка, которая уводит в другой узел.

### SYS-5. Классические структуры из сторилетов: прогресс и угроза — [S3]

**Элементы.** Счётчик прогресса (как далеко продвинулся игрок) и счётчик угрозы (насколько он в беде). Из них собираются: коридор (gauntlet, ошибка меняет путь), ветвление с горлышком, шляпа, петля с ростом (loop-and-grow, Bee), пещера времени.

**Шаги.** Выбрать классическую структуру → выразить её порогами прогресса и угрозы → написать сторилеты с этими предусловиями → прототипировать на карточках: одна карточка на сторилет, на ней текст и правила качеств. Short так работает сама и так ведёт мастерские.

**Если шаг пропустить.** Без карточек сторилеты пишут в тексте сразу и не видят, какие из них никогда не откроются. Без угрозы коридор не наказывает за ошибку, и игрок перестаёт её бояться.

**Ошибки понимания.** «Пещера времени на сторилетах — то же самое». Нет: каждый кусок зависит от точного маршрута, нужны уникальные метки, и преимущества сторилетов теряются ([S3]).

**Короткие формы.** Прогресс = номер главы или шага, угроза — один счётчик с порогом 2 (PAT-10). Петля с ростом — дни реального времени (PAT-12).
