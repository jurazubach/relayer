# Чек-листы — структуры выбора по Emily Short

Источник процедур: идеи [S1]–[S4] (ссылки в `principles.md`), порядок шагов и пороги — наши. Ссылки `P-`, `PAT-`, `RED-` ведут в соседние файлы.

## 1. Как спроектировать структуру истории до текста

- [ ] Выписать 2–4 оси, по которым игрок будет отличаться (доверие к герою, правда/безопасность, кому помогает). Результат: список будущих переменных, у каждой — смысл одной фразой.
- [ ] Для каждой оси выбрать механику набора: счётчик тона (P-16, PAT-11), выбор по очкам (PAT-03) или флаг поступка. Результат: таблица «ось → `VAR` → где набирается».
- [ ] Решить, будет ли ранняя развилка с разными линиями первой главы (PAT-05). Если историю не будут перепроходить — не делать. Результат: «да, N ролей» или «нет».
- [ ] Наметить итоговый узел: какие 2–4 переменные выбирают финалы и сколько финалов (PAT-06). Результат: таблица условий `{…} → финал`, у каждого условия есть `else`.
- [ ] Для каждой переменной из итогового узла назначить главу, где она впервые вспомнится вслух (P-09). Результат: ни одна переменная не молчит больше двух глав (RED-03).
- [ ] Разметить, где будут хабы с темами (PAT-04) и пулы улик (PAT-07), а где — линейные разговоры. Результат: план по главам с типом сцены.

## 2. Как написать сцену

- [ ] Определить тип сцены: линейный разговор, хаб тем, пул улик, рискованный выбор, тяжёлое решение, монтаж мелких выборов, тональные ответы, разговор с персонажем, у которого цель. Результат: выбран паттерн PAT-01…PAT-11 или «линейно».
- [ ] Если в сцене есть рискованный вариант — добавить 2 такта подтверждения с новыми деталями и счётчик (PAT-01). Результат: исход на «настоял» хуже, чем на «отступил».
- [ ] Если решение тяжёлое — дать 1–2 такта на переключение, реплики зависят от текущей стороны (PAT-02).
- [ ] Если экспозиции больше 12 входящих подряд — превратить в хаб тем с лимитом и выходом (PAT-04, RED-14).
- [ ] Для каждой кнопки решить, что она делает: ведёт в другой узел, пишет переменную, или только меняет реплику. Результат: в сцене есть хотя бы одна кнопка первых двух типов (RED-11).
- [ ] Варианты одной развилки по возможности развести по разным чатам `#to:` (RED-13).
- [ ] В начале сцены поставить условный блок приветствия: узкие условия первыми, `else` последним (PAT-08). Результат: реплика откликается на прошлые выборы.
- [ ] Если в сцене срабатывает переменная из прошлого — персонаж называет ранний поступок деталью (P-09).
- [ ] Ветки свести в общий узел не дальше чем через 2 узла, кроме финала (RED-07).

## 3. Как провести ревью готового сценария

- [ ] Выписать все `VAR`, для каждой — число записей, чтений, главу первой записи и первого чтения. Результат: список RED-01 (нет чтений), RED-02 (одно чтение в финале), RED-03 (разрыв > 2 глав).
- [ ] Для каждой переменной из RED-02/RED-03 предложить конкретную строку-колбэк и место (узел).
- [ ] Посчитать кнопки по типам: в другой узел / только переменная / только реплика. Результат: если «только реплика» > 35 %, выбрать 3–5 таких развилок и превратить в счётчики тона или монтаж (RED-11).
- [ ] Пройти рискованные развилки: есть ли подтверждения, есть ли реальная цена (RED-04).
- [ ] Пройти хабы: есть ли выход без перебора, используются ли флаги интереса (RED-05).
- [ ] Проверить порядок веток в каждом условном блоке и наличие `else` (RED-10).
- [ ] Открыть карту (`npm run graph`): ветвление по главам должно расти к финалу; после главы 1 есть узлы с разными исходами (RED-06, GREEN-05).
- [ ] Проверить итоговый узел: каждое условие финала опирается на переменные, о которых игроку хотя бы раз сказали вслух.
- [ ] Результат ревью: список «узел → флаг → правка одной строкой».

## 4. Как тестировать структуру

- [ ] `npm run check:story`: тупиков 0, все узлы посещены. Петли с `*` без выхода видны как тупики (RED-09).
- [ ] По отчёту финалов: каждый финал ≥ 5 % прохождений; если какой-то < 1 % — проверить, достижим ли он вообще осмысленной игрой (через отладку, переключая переменные).
- [ ] Посмотреть, сколько строк до каждого финала: ни один не раньше 30 % медианы (RED-08).
- [ ] Сравнить два прохождения с разной первой развилкой (`?fresh=1&fast=1`, затем отладка): разница видна в первые 5 минут (GREEN-04).
- [ ] В отладке выставить «крайние» значения счётчиков (0 и максимум) и пройти итоговый узел: каждый финал выпадает при ожидаемой комбинации.
- [ ] Для выбора по очкам проверить ничью: выставить равные счётчики и убедиться, что ветка определена.
