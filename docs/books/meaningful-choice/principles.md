# Принципы осмысленного выбора

Сокращения источников: **[M]** Morrison 2013, **[C]** Compton 2019, **[F]** Filament Games о докладе Мейера, **[SZ]** Salen & Zimmerman (Википедия), **[S]** Sarian 2018, **[DG]** Den of Geek о TWD. Ссылки — в `README.md`. Фрагменты ink в принципах компилируются, если объявить их переменные через `VAR` (проверено inkjs); полные примеры — в `patterns.md`.

### P-01. Показывай развилку целиком и сразу
- **Суть:** игрок должен понимать, что это выбор, и видеть все варианты одновременно. Альтернатива, о которой он не знал, для него не существует. Если последствие всё же наступит, он обвинит игру, а не себя.
- **Почему работает:** чувство авторства («это я решил») рождается только при сравнении вариантов. Нет сравнения — нет и ответственности, и сожаления.
- **В relayer:** решающий выбор — это минимум две кнопки в одной группе. Если кнопка одна, это «далее», а не выбор. `#label` описывает действие («Переслать Мае», «Сказать Джудит, что это Оуэн»), а не повторяет реплику. Когда варианты расходятся по адресатам (`#to:jess` против `#to:judith`), адресат должен быть виден в подписи.
- **Пример:**
  ```
  * [Скрин Оуэна #to:maya #label:Отправить угрозу Мае]
  * [Скрин Оуэна #to:judith #label:Отправить угрозу Джудит]
  * [Никому не показывать #to:notes #silent]
  ```
- **Как проверить:** разбор ink считает группы выбора с одной безусловной кнопкой (в «Чужом голосе» их 8 из 126 по `parseInk`). Группа, где все кнопки взаимоисключающие по условию (`{cover == "student"}` / `{cover == "honest"}`), для игрока тоже одна кнопка: считай её вместе с одиночными. Для каждой кнопки, которая ведёт в другой узел, на карте должна быть подпись `#label` или явный адресат.
- **Источник:** [M] (awareness), [SZ] (discernable).

### P-02. Дай достаточно сведений, чтобы предсказать исход
- **Суть:** игрок должен примерно понимать, к чему ведёт каждая кнопка. Вариант с неясным смыслом превращает выбор в лотерею.
- **Почему работает:** без ожидания нечего подтвердить или опровергнуть, поэтому исход не вызывает ни гордости, ни сожаления.
- **В relayer:** за 1–3 сообщения до кнопок персонаж называет ставку («если покажешь ей — она пойдёт к ним сама»). Перед узлом, где финал выбирает скрытая проверка, игрок получает сводку того, что у него есть (`PAT-07`).
- **Пример:**
  ```
  если отправишь это джудит, она пойдёт в полицию сегодня же #from:maya
  а без записи с телефона там посмеются
  * [Отправить Джудит сейчас #to:judith]
  * [Подождать телефон #to:maya]
  ```
- **Как проверить:** найди переменные в условии последнего маршрутизирующего узла. Если хотя бы одна из них ни разу не проверяется в условии вывода текста за две главы до финала, финал выбирается вслепую.
- **Источник:** [C] (predictability); переложение на скрытые проверки — наше.

### P-03. Заставляй платить: каждый вариант чего-то стоит
- **Суть:** интересен выбор, где, взяв одно, игрок теряет другое. Если у варианта нет цены, выбора нет.
- **Почему работает:** у упущенного варианта появляется вес, и игрок продолжает о нём думать (opportunity cost, упущенная выгода).
- **В relayer:** у нас три валюты — доверие контактов (`*_trust`), сведения (`note_*`, флаги находок) и время (что пришло ночью, а что утром). Хороший компромисс поднимает одну переменную и опускает другую или открывает один чат ценой другого.
- **Пример:**
  ```
  * [Рассказать Элли про куртку #to:ellie]
      ~ ellie_trust += 1
      ~ connor_ally = false
  * [Сначала спросить Коннора #to:connor]
      ~ connor_ally = true
      ~ ellie_trust -= 1
  ```
- **Как проверить:** по коду кнопок. В группе с изменениями переменных найди вариант, у которого нет минуса и есть плюс, тогда как у остальных только ноль: это бесплатный вариант. Порог: больше 30 % таких групп в главе — предупреждение.
- **Источник:** [F] (tradeoffs по Мейеру); triangularity у Schell — знание модели, уверенность средняя.

### P-04. Убирай очевидно лучший вариант
- **Суть:** если один вариант почти все выбирают, выбора нет: остальные кнопки только для вида.
- **Почему работает:** игрок оптимизирует. Когда «правильный» ответ виден заранее, он нажимает его без раздумий.
- **В relayer:** типичная ловушка — вежливый ответ против грубого, когда за грубость штраф и ничего взамен. Дай грубому варианту выигрыш (собеседник проговаривается, открывается чат, приходят сведения).
- **Пример:**
  ```
  * [Спасибо, что рассказал #to:connor]
  * [Ты врёшь. Есть фото #to:connor]
      ~ connor_ally = false
      ладно. было не так #from:connor
      ~ knows_tox = true
  ```
- **Как проверить:** бот этого не увидит, тут нужны люди. На плейтесте считай распределение ответов: если вариант берут больше 85 % игроков, перепиши или убери. Глазами: у грубого или рискованного варианта должен быть свой плюс.
- **Источник:** [C] (non-obviousness, случаи, когда выбор не нужен); dominant strategy (доминирующая стратегия) у Schell — знание модели, уверенность средняя.

### P-05. Делай правильный ответ зависимым от того, что игрок узнал
- **Суть:** лучший вариант определяет обстановка, а не общее правило. Тогда выбор требует думать здесь и сейчас.
- **Почему работает:** игрок применяет собранные сведения, и выбор становится проверкой его внимания, а не угадайкой.
- **В relayer:** условные кнопки `* {knows_tox} [...]` и реплики, которые меняют смысл в зависимости от `note_*`. Знание из одного чата должно давать ход в другом.
- **Пример:**
  ```
  * {note_beth} [Лили писала Бет в 00:55. Ты был рядом? #to:connor]
      ~ connor_told = true
  * [Где ты был ночью? #to:connor]
  ```
- **Как проверить:** доля групп выбора, где хотя бы одна кнопка с условием на переменную из прошлой главы. Ориентир: хотя бы одна такая группа на главу, начиная со второй.
- **Источник:** [F] (situational, только название). Толкование — знание модели, уверенность средняя.

### P-06. Оставляй выбор ради выражения себя — и возвращай его игроку
- **Суть:** выбор может ничего не менять в сюжете, если через него игрок говорит, кто он: имя, тон, отношение к собеседнику. Такой выбор держится, только если персонажи потом на него реагируют.
- **Почему работает:** игрок собирает свою версию героя. Отражение (обращение по выбранному имени, ответ на выбранный тон) подтверждает, что игра его услышала.
- **В relayer:** `alias` и `cover` в «Чужом голосе» — образцовые случаи: `{alias}` подставляется 5 раз, последний — в `fin_truth`. Выражение себя ставим на моменты, где ничего не решается: знакомство, утешение, прощание.
- **Пример:**
  ```
  * [Мне жаль #to:ellie]
      ~ tone = "warm"
  * [Давай по делу #to:ellie]
      ~ tone = "dry"
  ```
- **Как проверить:** у каждой переменной, которую задают выражающие кнопки, должно быть хотя бы одно чтение в условии вывода текста или в подстановке `{var}`.
- **Источник:** [F] (personal, только название); знание модели, уверенность средняя. Связь с отражением — наш вывод из [M] (reminders).

### P-07. Делай последствие видимым в интерфейсе, а не только в тексте
- **Суть:** сильнейшее последствие меняет то, как игрок играет, а не только то, что он читает. Смена одной реплики — самый слабый вид последствия.
- **Почему работает:** изменение возможностей (новый чат, замолчавший контакт, недоступная кнопка) замечаешь сразу и помнишь дольше, чем другую фразу.
- **В relayer:** у нас «механика» — это чаты и время. Значит, последствие — `#unlock` нового контакта, контакт, который уходит в офлайн и не отвечает, ответ, который приходит через час, а не через минуту (`#delay`), кнопка, которая появилась или исчезла.
- **Пример:**
  ```
  * [Скинуть номер Оуэна Мае #to:maya]
      ~ maya_trust += 1
      Мая не в сети #sys:maya
      #unlock:owen
  ```
- **Как проверить:** доля значимых кнопок (ведут в другой узел или задают переменную), у которых в ветке есть `#unlock`, `#sys`, заметная разница в `#delay` или условная кнопка дальше по ходу. Ориентир — от 20 %.
- **Источник:** [M] (gameplay consequences); перевод на наш интерфейс — наш.

### P-08. Связывай решение со всей историей
- **Суть:** последствие не должно сводиться к немедленной реакции. Решение главы 2 должно сработать в главе 5.
- **Почему работает:** когда отклик приходит далеко от причины, у игрока появляется ощущение мира, который помнит. Немедленный ответ воспринимается просто как реакция собеседника.
- **В relayer:** каждая переменная, которую задаёт выбор игрока, читается хотя бы в одной следующей главе. Наши главы идут днями, поэтому отложенное последствие получается само: через сутки.
- **Пример:**
  ```
  // глава 2
  * [Элли и Лили ругались в тот вечер #to:judith]
      ~ told_judith_ellie = true
  // глава 4
  {told_judith_ellie:
      Я спросила Элли про ту ссору. Она плакала. #from:judith
  }
  ```
- **Как проверить:** для каждой переменной — глава первой записи и глава последнего чтения. Если чтений нет, это мёртвая переменная (`called_bluff`). Если читается только в той же главе, переменная живёт недолго; таких должно быть меньше половины.
- **Источник:** [SZ] (integrated), [F] (persistent, только название).

### P-09. Напоминай игроку о его выборе словами персонажа
- **Суть:** если позже о решении никто не вспоминает, игрок его забывает, и ни гордости, ни сожаления не возникает. Напоминание стоит одну реплику и окупается сильнее новой ветки.
- **Почему работает:** память о решении держится на повторе. Напоминание связывает текущее событие с прошлым поступком и создаёт причинность там, где граф линеен.
- **В relayer:** реплика-отклик, обёрнутая в условие: «твой вопрос про куртку — без него я бы не нашла». Лучше всего, когда напоминает не тот, с кем говорили, а третий персонаж: это доказывает, что мир связан. Чат `notes` работает как дневник выборов.
- **Пример:** в `ch7_ellie` на `found_jacket_self` Элли благодарит игрока за догадку из главы 4. Это готовый образец.
- **Как проверить:** доля переменных выбора, у которых хотя бы одно чтение управляет выводом текста (условный блок с репликой), а не только переходом. Ориентир — от 50 %.
- **Источник:** [M] (reminders). [DG] показывает обратную сторону: напоминание, за которым позже ничего не следует, игрок со временем считает обманом. Поэтому напоминание должно называть уже наступивший след, а не обещать будущий.

### P-10. Не давай отменить решение — ни кнопкой, ни сюжетом
- **Суть:** если после последствия выбор можно переиграть, он превращается в формальность. Сюжет, который силой возвращает к нужному варианту, — та же отмена.
- **Почему работает:** вес решения держится на том, что последствие окончательно. Если исход можно переиграть, игрок перестаёт взвешивать варианты.
- **В relayer:** откатить ход нельзя, и это преимущество формата. Слабое место — петли отказа: игрок отказался, а единственная следующая кнопка «Ладно, что делать?». Если отказ нужен сюжету как дверь, пусть он хотя бы оставит след (переменную и отклик).
- **Пример:**
  ```
  * [Это не для меня #to:ellie]
      ~ refused_once = true
  // глава 3
  {refused_once:
      сначала было «нет». что поменялось? #from:ellie
  }
  ```
- **Как проверить:** найди кнопки с отказом или `#silent`, после которых в той же ветке в течение 1–2 сообщений идёт группа из одной кнопки и та ведёт туда же, куда согласие.
- **Источник:** [M] (permanence); петли отказа — наше применение.

### P-11. Считай молчание полноценным ходом
- **Суть:** в мессенджере не ответить — тоже ответ. Если «Промолчать» ведёт к тому же исходу через паузу, игрок понимает, что кнопка декоративная.
- **Почему работает:** молчание игрок выбирает сознательно, против давления собеседника. Если отклика нет, нарушается обещание жанра («игрок всегда может промолчать», `docs/PROMPT.md`).
- **В relayer:** у `#silent` своё последствие: собеседник обижается (`trust -= 1`), пишет другому контакту, принимает решение сам (`judith_waits = false`), сообщение приходит позже. Повторный вопрос после молчания должен предлагать хотя бы два варианта, включая повторное молчание.
- **Пример:**
  ```
  * [Промолчать #to:jess #silent]
      ~ jess_bond -= 1
      вы теперь меня ненавидите. я понимаю #from:jess #delay:10m
  ```
- **Как проверить:** в «Чужом голосе» 60 кнопок `#silent`. Для каждой посмотри ветку: есть ли запись переменной или переход, отличный от соседей. Если нет — отмечай как немое молчание.
- **Источник:** наш вывод из [M] (awareness + consequences) и правила жанра из `docs/PROMPT.md`.

### P-12. Отмеряй вес выбора по месту в главе
- **Суть:** не всякий момент заслуживает выбора, и не всякий выбор должен быть тяжёлым. Тяжёлые решения редки и стоят в конце сцены, лёгкие держат ритм между паузами.
- **Почему работает:** если каждая кнопка решающая, игрок устаёт и перестаёт взвешивать. Если ни одна, он перестаёт читать варианты.
- **В relayer:** в главе 1–2 решающих выбора, обычно перед хуком главы. Между ними ритмические кнопки: короткая реакция, у каждой свой ответ собеседника. Кнопка, за которой ни ответа, ни переменной, ни перехода, ритма не даёт, это просто лишний тап.
- **Пример:**
  ```
  * [омг #to:jess]
      ага. я тоже чуть не упала #from:jess
  * [Ты уверена? #to:jess]
      на сто. видела сама #from:jess
  ```
- **Как проверить:** профиль кнопок по разбору ink (проверка 13 в `for-relayer.md`): доли «переход / только переменная / только реплика / без тела». В «Чужом голосе» 55 кнопок без тела из 338. Цель — 0 групп, где пусты все варианты. Число решающих групп на главу: от 1 до 4. Косметический выбор оправдан, если он стоит вне решающей группы главы и у каждой кнопки свой ответ (ритм) или переменная выражения читается позже (`P-06`); вредит, если пусты все кнопки группы (`RED-01`) или он стоит на месте решения (`RED-10`).
- **Источник:** [C] (когда выбор не нужен); знание модели о ритме, уверенность средняя.

### P-13. Не давай больше четырёх вариантов в одной реплике
- **Суть:** избыток вариантов тормозит и снижает удовлетворение: растут упущенная выгода, самообвинение и ожидания.
- **Почему работает:** analysis paralysis (паралич анализа) и paradox of choice (парадокс выбора). На экране телефона пятая кнопка ещё и уезжает за край.
- **В relayer:** в обычной реплике 2–3 кнопки, считая `#silent`. Пять–шесть допустимы только в хабе вида «кому написать» (`ch1_hub`), где каждая кнопка — отдельный чат с подписью.
- **Пример:** хаб с `#label:Написать Джесс`, `#label:Написать Бет` нормален, а шесть вариантов ответа одной Джесс — нет.
- **Как проверить:** группы с 5+ кнопками, где не у всех кнопок разный `#to`. Предупреждение.
- **Источник:** [C].

### P-14. Если ветка не расходится, ставь в выбор дилемму, которую проверит финал
- **Суть:** выбор без долгих последствий всё равно наполнен смыслом, если это моральная дилемма, а серия таких дилемм ведёт к общей теме. Тогда финальный выбор становится экзаменом.
- **Почему работает:** игрок переживает дилемму в момент выбора, а повтор темы учит его думать о ней. Финал проверяет, что он вынес.
- **В relayer:** у «Чужого голоса» тема — правда против защиты своих. Ранние кнопки «прикрыть Элли / сказать Джудит» могут не ветвиться, если финал в `ch10_door` ставит тот же вопрос прямо.
- **Пример:** глава 2: «Сказать Джудит про ссору Элли?» Глава 6: «Удалить кадры с Элли?» Глава 10: «Отдать Джудит всю правду / дать Джесс сказать самой».
- **Как проверить:** выпиши дилеммы по главам одной строкой. Каждая должна укладываться в одну ось темы; финальный выбор — по той же оси.
- **Источник:** [S]. Morrison с этим бы спорил (по нему без напоминаний выбор пустой), поэтому дилемму всё равно подкрепляй `P-09`.

### P-15. Трать ветвление там, где игрок его увидит
- **Суть:** ощущение выбора создают видимые точки, а не устройство графа. The Walking Dead почти линейна и всё равно ощущается как история последствий.
- **Почему работает:** игрок проходит историю один раз и сравнивает себя не с другими ветками, а со своими ожиданиями. Реальное расхождение замечают только там, где оно показано.
- **В relayer:** историю в реальном времени перепроходят редко, поэтому иллюзия держится дольше, чем в обычной игре. Дорогие ветки — 3–5 на историю, в концах глав и в финалах. Остальное — следы (`P-09`).
- **Пример:** в «Чужом голосе» кнопки расходятся всего в 24 узлах из 165, но кнопка `ch4_jacket` («Связать сообщение Лили и куртку») ощущается сильной: находка приходит через 15 минут, а не через 3 часа (`ch4_late`), а в главе 7 Элли об этом вспоминает.
- **Как проверить:** по карте: узлы с реальным расхождением должны стоять в последних 20 % главы или перед `#chapter`. Ранние расхождения, которые сходятся через 1–2 узла без переменной, — растрата.
- **Источник:** [DG]; критика иллюзии — [DG] и [M] (Beyond: Two Souls как слабый пример).

# Второй проход: устройство авторских систем

Дополнительные источники второго прохода — в `lessons.md` ([L1]–[L11]). Morrison перечитан целиком; запись доклада Мейера 2012 года по-прежнему не просмотрена (GDC Vault).

## SYS-1. Четыре компонента Morrison (awareness → consequences → permanence, reminders поверх)

Morrison не ранжирует компоненты и требует всех четырёх. Но из его разборов следует порядок зависимостей: без осознанности нечего фиксировать, необратимость наступает после того, как последствие уже видно, а напоминанию нечего напоминать, если мир не изменился.

| шаг | вход | выход | если пропустить | частая ошибка понимания |
|---|---|---|---|---|
| awareness (осознанность) | момент, где сюжет может пойти иначе | игрок видит, что это развилка, и видит все варианты | последствие воспринимается как произвол игры, игрок винит автора | думать, что игрок должен знать последствия. По Morrison достаточно, чтобы выбор был явным: значение вопроса может быть неясным, если интерфейс всегда показывает несколько ответов |
| gameplay consequences (последствия в игре) | сделанный выбор | меняется то, как дальше играется, а не только то, что показывают | выбор ощущается пустым: игрок проходит цепочку заранее решённых сцен (так Morrison приводит отзыв Kyle Orland о Beyond: Two Souls) | считать последствием другую реплику. У Morrison это предмет, отличающийся только цветом; у нас аналог настоящего последствия — чаты, паузы и кнопки (P-07) |
| permanence (необратимость) | последствие уже наступило | вернуть выбор нельзя или неудобно | выбор становится формальностью; сюжетный откат на несколько секунд раздражает, а не впечатляет (RED-06) | думать, что нужна техническая защита. Morrison признаёт, что перезагрузка возможна; хватает того, что она неудобна. Для нас угроза — сюжетная отмена |
| reminders (напоминания) | последствие, которое продолжает действовать | игрок снова вспоминает решение, гордится или жалеет | через несколько глав игрок «ничего не чувствует» | считать напоминанием обещание. Напоминание работает, только если прошлое ещё влияет на настоящее; по мере продвижения выбор набирает вес |

**Короткая форма.** На 5 минутах все четыре шага помещаются в одну группу кнопок и 4–6 сообщений после неё: подпись с ценой (awareness) → контакт уходит в офлайн (consequence + permanence) → последнее сообщение истории называет тот самый поступок (reminder). Убирать шаг нельзя, сжимать можно.

## SYS-2. Интересные решения Мейера

Мейер описывает игру как цепочку решений. В докладе 2012 года, по Filament Games, у интересного решения четыре качества: tradeoffs, situational, personal, persistent. Открытое определение есть только у первого. Пересказ на вторичной странице (не открыта, через поисковую выдачу) сводит идею к трём условиям: ни один вариант не лучше явно, варианты не одинаково привлекательны, игрок выбирает со знанием дела. Это согласуется с Compton.

| качество | функция | у нас | если нет |
|---|---|---|---|
| tradeoffs (компромисс) | взяв одно, теряешь другое | P-03, PAT-02 | бесплатный плюс, RED-04 |
| situational (по ситуации) | лучший ответ зависит от обстановки | P-05, условные кнопки | правильный ответ один на всю историю, его запоминают |
| personal (личное) | выбор говорит о стиле игрока | P-06, PAT-03 | все проходят одинаково, выражения себя нет |
| persistent (долгое) | последствие остаётся | P-08, PAT-01 | отклик только в той же сцене |

Толкование трёх последних — по-прежнему модельное, уверенность средняя (REVIEW). Новое в этом проходе — доклад Мейера 2010 года о психологии игрока (LESSON-05, LESSON-06): игрок оценивает шансы по ощущению. Для скрытых проверок это важнее, чем точное определение «situational».

**Ошибка понимания.** «Интересное» у Мейера — не «важное для сюжета». Мелкое решение с компромиссом интереснее крупного с очевидным ответом. Поэтому декоративная кнопка с ценой (P-03 без ветвления) лучше дорогой ветки без цены.

**Короткая форма.** Из четырёх качеств на 5 минутах остаются tradeoffs и personal: обстановке не хватает времени измениться, а долгому последствию — дистанции.

## SYS-3. Три свойства Compton и случаи, когда выбор не нужен

Элементы: consequences (последствия), predictability (предсказуемость), non-obviousness (неочевидность). Работают парой ограничений: предсказуемость без неочевидности даёт очевидный ответ, неочевидность без предсказуемости даёт лотерею. Порядок проверки при написании: сначала последствие (есть ли разница вообще), потом предсказуемость (может ли игрок её ожидать), потом неочевидность (нет ли лучшего ответа).

- **Пропуск предсказуемости** — RED-08, скрытая сумма в финале. LESSON-05 показывает, что игрок ещё и неверно оценивает шансы, поэтому предсказуемость нужно давать с запасом.
- **Пропуск неочевидности** — LESSON-02, LESSON-04 и `emshort-structures` LESSON-08: от 75/25 до «примерно 92 %» в одну сторону.
- **Частая ошибка:** решить, что неочевидность — это скрыть последствие. Неочевиден лучший ответ, а не то, что будет.

## SYS-4. Discernable и integrated (Salen & Zimmerman)

Два условия осмысленной игры: результат действия заметен (discernable) и встроен в дальнейшую игру (integrated). Это сжатая пара Morrison: discernable ≈ awareness + видимое последствие, integrated ≈ consequences + reminders. Нам полезна как двухвопросный фильтр для ревью кнопки: «игрок заметит разницу сразу?» и «разница скажется дальше?». Если «нет/нет» — кнопка ритмическая или лишняя.

## Нюансы к принципам

| P | когда не работает | пограничный случай | 5 сообщений / 50 сообщений |
|---|---|---|---|
| P-01 | в хабе «кому написать» варианты — не альтернативы, а порядок; осознанность там не про цену | кнопка-запрет с ценой в подписи (`Написать Оуэну, хотя Элли просила не писать`) — одна кнопка в хабе, но полноценный выбор | 5: одна группа на 2 варианта; 50: у каждой решающей группы подпись с адресатом |
| P-02 | ставка звучит как совет: игрок выбирает названное (LESSON-03) | ставка для обоих вариантов одним сообщением: «отправишь ей — она пойдёт сама. не отправишь — пойдёт мая» | 5: одно сообщение-ставка; 50: ставка + сводка перед финалом |
| P-03 | у одного варианта цена отложена на 3 главы, у другого сразу — игрок считает первый бесплатным | цена во времени: ответ через час против ответа через минуту (`ch4_jacket` / `ch4_late`) | 5: минус другому контакту в той же сцене; 50: цена может проявиться в следующей главе |
| P-04 | мораль «добро/зло»: большинство идёт в «добро» (LESSON-04) | вариант, который выбирают 75 %, допустим, если меньшинство получает уникальную сцену (Telltale хотел 50/50, но не убрал 75/25, [L1]) | 5: бесполезно мерить, хватит глаз; 50: плейтест 3–5 человек |
| P-05 | условие на сведение, о котором игрок не знает, что оно у него есть | условная кнопка без пометки, откуда знание: игрок не связывает её со своей находкой | 5: одна условная кнопка на предыдущую реплику; 50: условия на переменные прошлых глав |
| P-06 | выражение себя в момент решения (RED-10) | имя подставлено в следующей же реплике — отражение сразу, без отложенности; этого хватает | 5: подстановка сразу; 50: подстановка в финале |
| P-07 | последствие в интерфейсе, которое игрок не связывает с кнопкой (контакт ушёл в офлайн через 2 ч без реплики) | `#delay` как последствие работает, только если разницу видно (минута против часа) | 5: `#sys`; 50: `#unlock`, условные кнопки позже |
| P-08 | реальные сутки между главами: отклик через 3 главы игрок не узнаёт (`attention.md`) | отклик повторяет ключевое слово кнопки — тогда дальность можно увеличить | 5: последнее сообщение от первого выбора; 50: следующая глава |
| P-09 | отклик на ветку, куда почти никто не попадает (LESSON-01) | обещание «он это запомнит» без последствия ([DG]) | 5: одна реплика; 50: отклик от третьего контакта |
| P-10 | отказ, который нужен сюжету как дверь | право передумать до того, как последствие наступило, — не отмена (Morrison: необратимость после последствия; `emshort-structures:P-04`) | 5: ни одной петли; 50: петли отказа с переменной допустимы в первой главе |
| P-11 | пауза, которую поставила игра, — не молчание игрока | Oxenfree: можно молчать всю игру, потому что паузы заполняют другие (LESSON-08) | 5: `#silent` даёт свою строку; 50: свою переменную |
| P-12 | глава из одних тяжёлых решений — усталость | ритмическая кнопка в середине длинного монолога (PAT-08) | 5: одна тяжёлая в конце; 50: 1–4 на главу |
| P-13 | хаб, где все варианты — разные чаты | 4 варианта одному собеседнику с длинными подписями на 360 px | без разницы |
| P-14 | дилемма только в тексте, без лиц и голоса | серия дилемм, где финал задаёт вопрос по другой оси | 5: не нужен; 50: ось темы в шапке |
| P-15 | реплей: игрок перепроходит и видит, что ветки сходятся | ветка ради смерти контакта стоит дорого и всё равно окупается (LESSON-10) | 5: одна развилка; 50: 3–5 дорогих веток |
