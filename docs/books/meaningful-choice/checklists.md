# Процедуры: выбор в истории

Каждый шаг — действие и ожидаемый результат. Ссылки на пункты: `P-NN` (principles.md), `PAT-NN` (patterns.md), `RED/GREEN-NN` (flags.md).

## 1. Придумать историю: каркас выборов

- [ ] Сформулируй ось темы одной строкой вида «X против Y» (например, «правда против защиты своих»). → Строка в шапке сценария комментарием `// тема: …` (P-14).
- [ ] Выпиши 3–5 тяжёлых решений по этой оси, по одному на 1–2 главы, и последний — финальный выбор. → Список «глава → дилемма → что теряет игрок в каждом варианте» (P-03).
- [ ] Для каждого тяжёлого решения определи, как оно проявится в интерфейсе: какой чат откроется, кто замолчит, какая кнопка появится позже. → У каждого пункта есть хотя бы один `#unlock`, `#sys` или условная кнопка (P-07).
- [ ] Заведи переменные заранее и для каждой запиши, где её прочтут: глава и персонаж. → Таблица `VAR → глава записи → глава чтения → кто напомнит` без пустых ячеек (P-08, P-09).
- [ ] Если финал выбирает скрытая проверка, запланируй сводку перед ним. → В плане последней главы есть узел-сводка (PAT-07).
- [ ] Реши, какие 1–2 выбора в первой главе дадут отклик в той же главе. → Отмечены в плане (flags.md, «Почему начало не цепляет»).

## 2. Написать главу или сцену

- [ ] Сначала напиши решающую группу в конце сцены, потом подводку. → Решение стоит в последних 20 % сцены (P-12, P-15).
- [ ] За 1–3 сообщения до решающей группы персонаж называет ставку. → Есть реплика «если… то…» или прямое следствие (P-02).
- [ ] Проверь, что у каждого варианта есть цена: что игрок теряет. → У каждой кнопки, кроме ритмических, есть минус или упущенная выгода (P-03, PAT-02).
- [ ] Добавь `#silent`, где молчание осмысленно, и дай ему своё следствие. → У кнопки молчания есть `~` или свой переход (P-11, PAT-04).
- [ ] Между решениями поставь не больше 2–3 ритмических групп, у каждой кнопки свой ответ. → Ноль групп, где все кнопки пустые (RED-01, PAT-08).
- [ ] Вставь 1–2 отклика на выборы прошлых глав, хотя бы один от другого контакта. → Условные блоки с текстом на переменные из прошлых глав (PAT-01, GREEN-02).
- [ ] Если в сцене копится счётчик, проверь, что персонаж озвучит пересечение порога. → Условная реплика на `var >= N` до решающей проверки (PAT-06).
- [ ] Посчитай кнопки в каждой группе. → 2–4, кроме хабов «кому написать» (P-13).

## 3. Ревью готового сценария

- [ ] Собери карту: `npm run graph -- src/stories/<id>.json --open`. → Видны узлы-развилки и доли прохождений.
- [ ] Выпиши все переменные: число записей, чтений, главы первой записи и последнего чтения (скрипт из `for-relayer.md`, проверка 2). → Список мёртвых переменных (RED-02) и счётчиков вслепую (RED-07).
- [ ] Найди пустые и одиночные группы. → Список узлов с RED-01 и RED-05; для каждого решение: дать отклик, добавить вариант или заменить на `#me:<id>`.
- [ ] Пройди каждую кнопку `#silent` и каждый отказ. → Список мест RED-06.
- [ ] Для каждой развилки на карте проверь, оставляет ли ветка след после схождения. → Список RED-03 с предложенным осадком.
- [ ] Выпиши дилеммы по главам по одной строке; убедись, что финальный выбор задаёт тот же вопрос. → GREEN-07 или замечание.
- [ ] Возьми последний маршрутизирующий узел, выпиши переменные из его условий и для каждой найди, где игроку о ней говорят перед выбором. → RED-08 или GREEN-03.
- [ ] Сведи найденное в таблицу по четырём компонентам Morrison (flags.md, «Почему выбор не ощущается»). → Для каждого компонента 0–N замечаний с узлами.

## 4. Тестирование

- [ ] `npm run check:story` проходит без тупиков. → Базовая целостность есть.
- [ ] По прогонам бота посчитай для каждой значимой группы, как выбор кнопки меняет распределение финалов (проверка 7 в `for-relayer.md`). → Список групп, которые не влияют ни на финал, ни на текст; это кандидаты в ритмические или на удаление.
- [ ] Дай историю 3–5 людям и после каждой главы спроси: «Какой твой выбор в этой главе что-то изменил?» → Если игрок не может назвать ни одного, в главе не хватает awareness или reminders.
- [ ] Собери ответы игроков по группам (сейчас такой отладки нет: опрос или запись экрана; если добавим журнал выборов в отладку — из него). → Варианты, которые выбирают больше 85 % игроков, — кандидаты на переписывание (P-04).
- [ ] Через сутки после прохождения спроси, какие решения игрок помнит. → Решения, которые никто не вспомнил, — кандидаты на напоминание (P-09).
