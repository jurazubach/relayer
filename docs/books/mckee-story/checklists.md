# Процедуры

Каждый шаг — действие и результат, который можно предъявить. Ссылки — на `principles.md` (P), `patterns.md` (PAT), `flags.md` (RED/GREEN).

## 1. Придумать и начать историю

- [ ] **Выбрать главную ценность-пару.** Результат: одна строка в шапке ink вида `// главная ценность: Тео не один / Тео один` (P-02).
- [ ] **Расписать шкалу ценности на 4 ступени** от «+» до «хуже противоположного». Результат: строка-шкала в шапке; плохие финалы привязаны к нижней ступени (P-03).
- [ ] **Сформулировать побуждающее событие одной фразой в настоящем времени:** что ломается сейчас и у кого из контактов. Результат: фраза начинается не с «раньше» и не с «героя наняли» (P-09).
- [ ] **Поставить событие до первой кнопки или сразу после неё, в общую часть, а не в ветку.** Результат: каждое прохождение бота видит строку события до второй кнопки (RED-01).
- [ ] **Выписать, что игрок должен знать, чтобы понять событие, и вычеркнуть всё остальное из первой сцены.** Результат: ≤ 10 реплик до первой кнопки.
- [ ] **Для каждого главного контакта назначить тайну прошлого и главу раскрытия.** Результат: таблица в шапке `тайна → глава`, ни одна не в главе 1 (P-13, PAT-09).
- [ ] **Выбрать 1–2 сервисных контакта (банк, склад, клиника) и для каждого — что они посеют в главе 1 и где выстрелит.** Результат: комментарии `// выплата: <узел>` (P-17).
- [ ] **Наметить кризис каждой главы как пару потерь.** Результат: по строке на главу «если A — теряет X, если B — теряет Y» (P-10).

## 2. Написать главу или сцену

- [ ] **Написать над узлом `// ценность: X, знак → знак`.** Результат: строка есть и знаки разные; если не получается — узел вливается в соседний (P-01).
- [ ] **Разложить сцену на 2–4 бита: кнопка и реакция мимо ожидания.** Результат: ни одна реакция на кнопку-решение не «ок» (P-04, PAT-01).
- [ ] **Выбрать, чем повернётся сцена: действием или откровением; откровение — извне чата.** Результат: в конце сцены есть реплика из другого контакта, `#sys`, `#photo` или поступок (P-06, PAT-04).
- [ ] **Первую кнопку сцены с целью сделать самой осторожной.** Результат: переменная риска не растёт в первом узле главы (P-08).
- [ ] **Выстроить помехи главы лестницей и отметить `// невозврат`.** Результат: 3–4 помехи по нарастающей; после невозврата кнопки отступления получают отказ мира (P-07, PAT-05).
- [ ] **Всю предысторию в сцене раздать через конфликт.** Результат: нет серий ≥ 5 реплик о прошлом без вопроса и противника (P-12, PAT-03).
- [ ] **Проверить, кто знает больше: игрок или собеседник.** Результат: хотя бы одна сцена главы с драматической иронией и кнопкой «предупредить / промолчать» (P-16, PAT-08).
- [ ] **Закончить главу кризисом-дилеммой.** Результат: 2–3 кнопки, `#label` называет ценность, у каждой — потеря (P-10, PAT-06).
- [ ] **Выписать знаки концов сцен главы.** Результат: нет трёх одинаковых подряд; последний — самый глубокий или резкий разворот (P-15, PAT-07).
- [ ] **Ответить одной строкой: какая ценность сменилась в главе.** Результат: над `#chapter` комментарий `// глава N: <главная ценность>, знак → знак`, знаки разные, ценность из шапки (P-18).

## 3. Ревью готового сценария

- [ ] **Собрать таблицу сцен:** узел | ценность | знак до | знак после | чем повёрнуто (действие / откровение). Результат: таблица на все узлы с `#from`, кроме служебных.
- [ ] **Пометить nonevent:** строки, где знаки совпали. Результат: список узлов на слияние или переписку (RED-02).
- [ ] **Собрать таблицу глав:** глава | главная ценность | знак до | знак после. Результат: нет глав без смены главной ценности и двух глав подряд с одинаковым поворотом (P-18).
- [ ] **Проверить первую сцену:** фраза «что сломалось» и есть ли событие во всех ветках до второй кнопки. Результат: да / нет с номером узла (RED-01).
- [ ] **Пройти все кнопки-решения (ставят `~`) и выписать первую реакцию.** Результат: список «согласий» для замены (RED-03).
- [ ] **Найти монологи о прошлом.** Результат: список узлов, где экспозицию надо превратить в боеприпас или отложить (RED-04).
- [ ] **Оценить силу помех по главам 1–3.** Результат: в каждой главе последняя помеха сильнее первой (RED-05).
- [ ] **Проверить серии одинаковых знаков по таблице сцен.** Результат: нет серий ≥ 3 (RED-07).
- [ ] **Для каждого кризиса выписать потери кнопок.** Результат: у каждой кнопки есть потеря (RED-09).
- [ ] **Для каждого финала найти видимую кнопку, которая его вызвала, и реплику, которая на неё ссылается.** Результат: ни одного финала, который выбран только скрытой проверкой (RED-10, GREEN-07).
- [ ] **Найти обещания последствий («если …, то …») и проверить, взысканы ли они.** Результат: каждое обещание сыграно хотя бы в одной ветке (RED-11).
- [ ] **Сверить таблицу тайн с текстом.** Результат: раскрытие не в той же сцене, что намёк (RED-12).

## 4. Тестирование

- [ ] **Прогнать `npm run check:story`.** Результат: нет тупиков; доля прохождений через сцену с побуждающим событием — 100 %.
- [ ] **Открыть `npm run graph` и отметить узлы, через которые проходит < 10 % прогонов.** Результат: если там лежит поворот, нужный для понимания финала, — перенести поворот в общий узел.
- [ ] **Посчитать долю реакций-согласий на кнопках-решениях (скрипт из `for-relayer.md` §2).** Результат: < 5 %, иначе — список на переписку.
- [ ] **Сыграть главу с `?fast=1` и после каждой сцены записать одним словом, что изменилось.** Результат: ни одного «ничего»; если «ничего» — сцена в RED-02.
- [ ] **Дать сыграть главу 1 человеку без контекста и спросить после первой сцены «чего боится этот контакт?».** Результат: он называет ценность из шапки; если не может — RED-01.
- [ ] **Сыграть финал дважды противоположными кризисными кнопками.** Результат: финалы различаются, и в каждом названо решение игрока.
