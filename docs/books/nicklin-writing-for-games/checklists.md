# Процедуры — Hannah Nicklin, Writing for Games

Источники [S1]–[S15] — в начале `principles.md`. Ссылки P-, PAT-, RED- ведут в соседние файлы.

## 1. Как придумать и начать историю

Семена (seeds) — у Nicklin это крошечные затравки, из которых растёт идея. Отрывок [S7] перечисляет девять способов их добывать. Нам подходят три, остальные (коллажи, вырезки, карточки Oblique Strategies) требуют физических материалов.

- [ ] **Собери 5 семян.** Используй три способа: «как X, но Y» (скрестить жанр, место и героя), вычёркивание (взять заметку из вымышленной местной газеты и вычёркивать слова, пока не останется одна реплика), поток без остановки 3 минуты. *Результат:* 5 строк, каждая — ситуация или реплика.
- [ ] **Выбери семя, из которого получается переписка.** Критерий: у ситуации есть хотя бы два человека, которым игрок может написать, и причина, почему они пишут именно ему. *Результат:* одно семя и строка «почему пишут игроку».
- [ ] **Заполни карточку формы (P-06).** Регистр, длина в главах, упаковка (день = глава?), единица внимания в минутах, степень свободы (маршрут, тон, крупные выборы). *Результат:* 5 строк в комментарии в шапке ink.
- [ ] **Назови формат (P-07).** Одно-два слова на всю историю и на каждую главу: допрос, ограбление, обратный отсчёт, опрос под прикрытием. *Результат:* над каждым `#chapter` стоит комментарий `// format:`.
- [ ] **Составь ансамбль.** 3–6 контактов. Для каждого: типаж, что его ломает и в какой главе (P-14). *Результат:* таблица «контакт — типаж — слом — глава».
- [ ] **Заполни листы голоса (P-02).** По 6 строк на контакт. Проверь, что у любых двух контактов различаются хотя бы два параметра формы. *Результат:* комментарии `// <id>: …` в шапке ink.
- [ ] **Проверь голоса одной новостью (PAT-01).** Дай всем контактам одну новость и сделай слепой тест. *Результат:* ≥ 8 из 10 верных угадываний по каждой паре.
- [ ] **Составь таблицу фактов (P-13).** Ключевое событие и кто что о нём скажет. *Результат:* у каждого ключевого факта ≥ 2 версии.
- [ ] **Задай первую главу формой.** Первое сообщение называет правило формата (что за работа, какой срок). Первые три контакта — с самыми разными голосами (RED-17). *Результат:* по первым 20 сообщениям можно ответить на вопрос «что это за игра».

## 2. Как написать главу или сцену

- [ ] **Определи линии A/B/C (P-08).** A — вопрос главы и контакт, который его ведёт. B — контрастный тон, другой чат. C — 1–3 мелочи, одна из них отзовётся позже. *Результат:* три строки в комментарии над `#chapter`.
- [ ] **Реши, где свобода (P-09).** Хаб, тон-выбор или крупная развилка. Не больше одного хаба на главу; если хаб был в прошлой главе, в этой его может не быть. *Результат:* схема главы в 3–5 строк.
- [ ] **Назови обязательное и таймер (P-10).** Персонаж говорит, что важно и когда станет поздно. *Результат:* реплика-таймер до хаба, `#label` на кнопке-выходе.
- [ ] **Напиши черновик, не останавливаясь.** Разметка глаголами потом. *Результат:* глава компилируется (`npm run check:story` без тупиков).
- [ ] **Разметь глаголами (PAT-02).** *Результат:* каждый блок `#from` с `// verb:`; блоки без глагола вырезаны.
- [ ] **Проверь ремарки (P-05).** Все `#sys` и `#photo` описывают поведение, а не чувства. *Результат:* регулярное выражение RED-04 ничего не находит.
- [ ] **Дай вариант «послушать» в тяжёлой сцене (P-11).** *Результат:* хотя бы один `#silent`, на который персонаж реагирует.
- [ ] **Прочитай главу вслух.** Воркшоп Nicklin держится на чтении вслух: так слышно, что звучит естественно, а что деревянно [S6]. *Результат:* реплики, на которых споткнулся, переписаны короче.
- [ ] **Проверь кнопки (P-12).** Реплики игрока одного регистра, действия — через `#silent` + `#label`. *Результат:* RED-07 ничего не находит.
- [ ] **Проверь регистры (P-19).** `#sys` — поведение, `#label` — короткая команда, заметки — сухой факт. *Результат:* RED-21 ничего не находит.

## 3. Как провести ревью готового сценария

- [ ] **Прогони бота и карту.** `npm run check:story`, `npm run graph`. *Результат:* список тупиков, финалов, длительности и доля прохождений по узлам.
- [ ] **Посчитай голоса (RED-01).** Скрипт профиля голоса по контактам. *Результат:* таблица профилей и список неразличимых пар.
- [ ] **Сделай слепой тест для подозрительных пар (P-03).** *Результат:* точность по каждой паре; пары ниже 8 из 10 — в список правок.
- [ ] **Найди пустые узлы и молчащие контакты (RED-02, RED-03).** *Результат:* список узлов и контактов с решением «дать глагол» или «убрать».
- [ ] **Проверь линии глав (RED-11).** Сколько контактов говорит в каждой главе. *Результат:* главы с < 3 или > 6 говорящими помечены.
- [ ] **Проверь хабы (RED-05, RED-18).** Есть ли обязательное, таймер, `#label`. *Результат:* для каждого хаба — да или нет.
- [ ] **Проверь переменные тона (RED-19).** *Результат:* список переменных, которые пишутся, но не читаются.
- [ ] **Составь таблицу фактов (P-13).** *Результат:* ключевые факты с одним источником помечены.
- [ ] **Проверь этику (P-16).** Тяжёлые темы названы в `synopsis` или `features`, нет кнопок с похвалой, ни один финал не подан как награда за «правильные» ответы. *Результат:* RED-09 ничего не находит; список тем в описании.
- [ ] **Для каждого сокращения запиши замену (P-17).** *Результат:* ни одного «вырезать» без «вместо этого».

## 4. Как тестировать с людьми: критический отклик

Nicklin адаптирует для игр метод Critical Response (критический отклик) Лиз Лерман [S12]. В нём четыре стадии и три роли: автор, отвечающие, ведущий. Порядок стадий нужен, чтобы автор не защищался. Ниже — версия для одной главы истории.

- [ ] **Подготовься как автор.** Выбери главу, сформулируй 3–5 своих вопросов («где хотелось закрыть приложение?», «кому ты не поверил?»), назови, что сейчас не обсуждаем (например, оформление). *Результат:* лист вопросов и список тем, закрытых для обсуждения.
- [ ] **Найди ведущего.** Лучше человек, который главу не писал. Если некому, ведёшь сам, но строго по стадиям. *Результат:* имя ведущего.
- [ ] **Дай сыграть.** Ссылка с `?story=<id>&fresh=1&fast=1` и глава целиком. Попроси игрока писать в заметки, где он отложил телефон. *Результат:* у каждого игрока прохождение и заметки.
- [ ] **Стадия 1 — что это значило.** Игроки рассказывают, какой была глава по ощущению. Без оценок и советов. *Результат:* записанные впечатления.
- [ ] **Стадия 2 — вопросы автора.** Задаёшь свои вопросы. Советы «как исправить» пока откладываются. *Результат:* ответы на каждый вопрос.
- [ ] **Стадия 3 — нейтральные вопросы игроков.** Вопрос без спрятанного мнения («почему Элли пишет строчными?» — нейтральный; «зачем Элли так странно пишет?» — нет). Автор отвечает коротко, без оправданий. *Результат:* список вопросов — это места, где текст непонятен.
- [ ] **Стадия 4 — мнения с разрешения.** Игрок спрашивает «могу сказать мнение про X?», автор вправе отказаться. *Результат:* мнения, на которые автор дал согласие.
- [ ] **Запиши и разбери позже.** Запись сессии ведёт нейтральный человек. К отклику возвращаешься позже, когда первая реакция уляжется [S12]. *Результат:* список правок, каждая привязана к узлу ink.
- [ ] **Сверь с ботом.** Места, где игроки откладывали телефон, сравни с длиной заходов (RED-12) и долей прохождений через узел на карте. *Результат:* для каждой жалобы — номер узла и метрика.
