# Чек-листы

Номера `P-`, `PAT-`, `GREEN-`, `RED-` — из соседних файлов. «Сессия» — отрезок между паузами ≥ 1h.

## 1. Как придумать и начать историю

- [ ] **Выбери угрозу с часами.** Запиши одной строкой, кто или что угрожает и к какому сроку. Результат: «до слушания 4 дня», «он вернётся через 20 минут» (`P-08`).
- [ ] **Реши формат по длине.** До 20 минут — одна сессия без пауз ≥ 1h, как «Слепое пятно». Дольше — главы-дни (`P-15`, `PAT-05`). Результат: в карточке `minutes` и строка в `features` о реальном сроке (`P-13`).
- [ ] **Напиши первые 5 строк по тесту «скриншот».** Голос, кто пишет, чего хочет, срок. Результат: посторонний по пяти строкам пересказывает ситуацию одной фразой (`P-06`, `PAT-04`).
- [ ] **Поставь первую кнопку не дальше 6-й строки.** Результат: бот показывает первый выбор ≤ 6 строк от начала.
- [ ] **Спланируй первую сессию на 2–5 минут набора с 2+ кнопками.** Она кончается крючком и названным сроком. Результат: первые 40–60 строк, первая пауза ≥ 1h стоит после строки с «?», фото или новым контактом (`P-02`).
- [ ] **Проверь, что крючок первой сессии виден до паузы.** Результат: три строки перед первой долгой паузой можно процитировать как тизер (`P-03`).

## 2. Как написать главу (день)

- [ ] **Первая строка главы возвращает вчерашний вопрос.** Результат: общее имя или предмет с последними строками прошлой главы (`PAT-05`, GREEN-04).
- [ ] **Первая кнопка — в первые 10 минут сюжетного времени после заголовка.** Результат: между строкой с `#chapter` и первой кнопкой сумма `#delay` ≤ 10m (RED-03).
- [ ] **Разбей главу на 3–6 эпизодов-укусов.** Каждый: 6–20 строк, 1–3 кнопки (`PAT-01`). Результат: список эпизодов с крючком для каждого.
- [ ] **Для каждой паузы ≥ 1h впиши причину и срок.** Результат: в 3 строках перед паузой — «не в сети», причина и время (`P-04`, `P-05`, `PAT-03`).
- [ ] **Проверь, что пауза не стоит сразу после ответа игрока на закрытой реплике.** Результат: между кнопкой и долгой паузой есть строка-крючок (`PAT-02`, RED-02).
- [ ] **Дай в главе одну развилку с резким вариантом.** Результат: один вариант ведёт в свой узел, и последствие видно до конца главы или в начале следующей (`PAT-06`).
- [ ] **Разрежь длинные реплики.** Результат: ни одной строки `#from` длиннее 90 знаков, кроме скриншотов и документов (`P-16`).
- [ ] **Последняя пауза главы — на самом сильном незакрытом вопросе дня.** Результат: последние 3 строки главы без «спасибо / спокойной ночи» в конце.

## 3. Ревью готового сценария

- [ ] **Прогони бота и выпиши сессии.** Результат: таблица «сессия → строк / кнопок / секунд набора / последняя строка».
- [ ] **Отметь микросессии** (≤ 3 строк без кнопки). Результат: список мест для склейки (`PAT-07`, RED-01). Цель — меньше 10% сессий.
- [ ] **Прочитай три строки перед каждой паузой ≥ 1h.** Результат: каждая помечена «крючок / закрытая». Цель — 70% крючков (GREEN-02).
- [ ] **Найди события, спрятанные за паузой.** Результат: для каждого `#unlock`, `#rename`, `#photo` после паузы ≥ 3h есть анонс до неё (RED-04).
- [ ] **Проверь вход в главы.** Результат: в каждой главе первая кнопка ≤ 10m после заголовка (RED-03).
- [ ] **Найди серии > 15 строк без кнопки.** Результат: в каждой вставлена кнопка (хотя бы `#silent`) или пауза с крючком (RED-06).
- [ ] **Посчитай развилки, где все варианты сходятся.** Результат: в каждой главе есть хотя бы одна с резким вариантом (RED-07).
- [ ] **Сверь карточку с реальным временем.** Результат: срок в днях есть в `features` или `synopsis`, если медиана пауз > 10 × `minutes` (RED-09).
- [ ] **Проверь угрозу на улики.** Результат: для каждой угрозы найдено сообщение до неё, по которому её можно было предвидеть (RED-08).

## 4. Как тестировать

- [ ] **`npm run check:story`** — тупики, финалы, реальное время. Результат: 0 тупиков, все узлы посещены.
- [ ] **Сессии и микросессии.** Пока в боте нет отчёта, используй симуляцию на inkjs: разрезать по `#delay` ≥ 1h, время набора по формуле `engine.ts` (`for-relayer.md` §2). Результат: медиана чтения за сессию ≥ 60 секунд, микросессий < 10%.
- [ ] **Первая сессия вживую.** Открой `?story=<id>&fresh=1` без `fast`, засеки время до первой долгой паузы. Результат: 2–10 минут, игрок может пересказать, кто ему пишет и что на кону.
- [ ] **Возвращение вживую.** Закрой вкладку на первой долгой паузе. Вернувшись через несколько часов, запиши, помнил ли ты вопрос. Результат: первая строка после паузы понятна без прокрутки вверх.
- [ ] **Тест «скриншот» на человеке.** Покажи первые 5 строк человеку, который не читал карточку. Результат: он отвечает, кто пишет и чего хочет.
- [ ] **`npm run graph`.** Результат: в каждой главе виден узел с расходящимися кнопками и переменная, которую читают раньше финала.
