# Выжимка для relayer

## 1. Правила для генератора историй

Готовые строки для `docs/PROMPT.md`:

- Между двумя паузами ≥ 1h давай не меньше 6 сообщений и хотя бы одну кнопку. Одна строка после часа тишины — не сцена.
- Последние три строки перед паузой ≥ 1h — крючок: вопрос без ответа, угроза, фото, новый номер. Не заканчивай отрезок на «спасибо», «ок», «спокойной ночи».
- Если игрок только что ответил, не начинай долгую паузу сразу после реакции на ответ. Сначала строка, которая открывает новый вопрос.
- Перед паузой ≥ 1h персонаж называет причину и срок относительным временем: «после смены», «часа через три», «утром».
- Самое сильное событие главы анонсируй до долгой паузы, а не только после неё: у игрока нет push-уведомлений.
- После заголовка главы (`#chapter`) первая реплика приходит не позже чем через 2m, а первая кнопка — в первые 10m.
- Первая строка главы возвращает незакрытый вопрос прошлой главы.
- Первые пять строк истории называют, кто пишет, чего хочет и к какому сроку. Тайна — в причине, а не в ситуации.
- В каждой главе есть развилка, где один из вариантов резкий (обвинить, переслать, заблокировать, соврать) и ведёт в свой узел с последствием до конца главы.
- Не ставь больше 15 сообщений подряд без кнопки, кроме финала. Если персонаж рассказывает долго, дай игроку `#silent` или короткую реакцию посередине.
- Угроза должна иметь улику, которую игрок мог увидеть раньше. Не пугай ради испуга.
- Если история идёт дольше суток, напиши реальный срок в `features`: «Идёт N дней, по 5–10 минут за раз».
- Одна реплика — одна мысль, до 90 знаков. Длинную мысль дели на 2–3 сообщения с `#delay` 3–10s.

## 2. Автоматические проверки

Все считаются по прохождениям бота. Время набора — по `engine.ts`: `min(5, max(1.1, 0.6 + 0.05·длина))` с + пауза 0,35–0,95 с; для `#sys` 0 + 0,7 с, для `#photo` 2,6 с.

| проверка | что считать | данные | порог | текст предупреждения |
|---|---|---|---|---|
| Микросессии | Разрезать прохождение по `#delay` ≥ 1h. Сессия «микро», если в ней ≤ 3 строк и 0 кнопок | `#delay`, строки, выборы | > 10% сессий | `⚠ микросессии: N% возвращений дают ≤ 3 строк без кнопки (пример: «…» → 3h → «…»). Склейте или уберите паузу` |
| Чтение за возвращение | Медиана времени набора в сессии | как выше + длина строк | < 60 с | `⚠ за возвращение после паузы ≥ 1h игрок читает в среднем N с` |
| Повисший ответ | Пауза ≥ 1h, до которой ≤ 2 строк от последней кнопки, а последняя строка из стоп-списка (`спасибо, ок, ладно, понятно, пока, спокойной, попробую, хорошо`) | `#delay`, позиция кнопки, текст | любой случай; сводка: топ-5 мест | `⚠ ответ игрока повисает: «<строка>» → <пауза>. Добавьте крючок до паузы` |
| Крючок перед паузой | В 3 строках до паузы ≥ 1h есть `?`, `#photo`, `#unlock` или первое сообщение нового контакта | теги, текст | < 70% пауз | `⚠ только N% долгих пауз начинаются с крючка` |
| Срок паузы | В 3 строках до паузы ≥ 1h есть `#sys` «не в сети» или регулярка `\d|утр|вечер|ноч|завтра|после|час` | текст, `#sys` | < 70% пауз | `⚠ N пауз ≥ 1h без причины и срока` |
| Пустой вход в главу | Сумма `#delay` после строки с `#chapter` (без её собственной) до первой кнопки | `#chapter`, `#delay` | > 10m | `⚠ глава «<заголовок>»: после заголовка игрок ждёт N до первой кнопки` |
| Событие за паузой | Строка сразу после паузы ≥ 3h содержит `#unlock`, `#rename` или `#photo`, а 3 строки до паузы без `?` | теги | любой случай | `⚠ «<строка>» ждёт за паузой N без анонса: вернутся не все` |
| Серия без кнопки | Максимальная серия строк между выборами, кроме отрезка после последней кнопки | строки, выборы | > 15 | `⚠ N строк подряд без кнопки в узле <knot>` |
| Первая сессия | Строки, кнопки и время набора до первой паузы ≥ 1h | как выше | < 2 мин или < 2 кнопок, > 15 мин | `⚠ первая сессия: N мин, K кнопок` |
| Длинные реплики | Доля строк `#from` без `#photo` и `#sys` длиннее 90 знаков | текст, теги | > 5% главы | `⚠ глава N: K% реплик длиннее 90 знаков — набор упирается в 5 с, игрок не успевает читать` |
| Резкий вариант (карта) | Узлы, где кнопки расходятся в разные узлы, по главам | граф ink | 0 в главе | `⚠ глава N: все развилки сходятся` |

Для карты (`npm run graph`): подсветить узлы, после которых бот видит паузу ≥ 1h, цветом по «крючок / закрытая», а в подписи узла показать медиану строк до следующей кнопки.

## 3. Идеи скиллов и команд

### `/session-map`
- **Когда:** после черновика главы или перед ревью длинной истории.
- **Вход:** `src/stories/<id>.json`.
- **Выход:** таблица сессий (номер главы, первая и последняя строка, строк, кнопок, секунд набора, пауза после, метка «крючок / закрытая / микро») и сводка с порогами из §2.
- **Шаги:** 1) 300 прохождений inkjs; 2) разрез по паузам ≥ 1h; 3) склейка одинаковых сессий по тексту первой строки; 4) сортировка по частоте; 5) топ-10 проблем со ссылкой на узел.

### `/hook-before-pause`
- **Когда:** `/session-map` показал повисшие ответы или события за паузой.
- **Вход:** узел ink и строка паузы.
- **Выход:** 2–3 варианта строки-крючка до паузы в голосе персонажа (или `#sys`-событие), с правкой ink.
- **Шаги:** 1) прочитать 10 строк до и после паузы; 2) найти, что после паузы удивит игрока; 3) написать анонс, который намекает, но не раскрывает; 4) проверить, что не повторяется крючок прошлой паузы; 5) скомпилировать.

### `/episode-draft`
- **Когда:** пишем новую главу-день.
- **Вход:** синопсис главы, вопрос из конца прошлой главы, контакты.
- **Выход:** ink главы из 3–6 эпизодов по `PAT-01`, у каждого паузы с причиной и сроком.
- **Шаги:** 1) план эпизодов (крючок каждого); 2) первая строка главы = вопрос прошлой; 3) по эпизоду ink; 4) одна развилка `PAT-06`; 5) прогон бота и `/session-map` по главе.

### `/opening-screenshot`
- **Когда:** начало истории или новой линии кажется непонятным.
- **Вход:** первые 10 строк.
- **Выход:** ответы на «кто пишет / чего хочет / к какому сроку» по первым 5 строкам. Если ответа нет — переписанное начало по `PAT-04`.

## 4. Разбор «Чужого голоса» (`chuzhoy-golos`)

Замеры: 300 прохождений на inkjs, разрез по паузам ≥ 1h. Медиана — 55 пауз ≥ 1h за прохождение и 56 сессий. Медиана набора за сессию — около 20 секунд, 19–20% сессий — микро. Крючок (`?`, `#photo`, `#unlock`) в трёх строках перед паузой ≥ 1h есть лишь у ~13% пауз. Первая сессия — 58 строк, 16 кнопок, 2–3,5 минуты набора. Для сравнения, в «THE NUMBER» 8 сессий с медианой около 2,5 минуты. Замеры повторены при ревью, расхождение в секундах — от того, как считать паузы между сообщениями.

1. **Работает: крючки до пауз в главах 3 и 4.** Конец главы 3 — Оуэн спрашивает, рассказывала ли Элли, что была там, когда погиб Денни, и только потом 7h. Конец главы 4 (`ch4_end`) — фото карты microSD и «это его» перед паузой. Так и надо (`P-02`): вопрос уходит с игроком на ночь.
2. **Сломано: событие спрятано за паузой без анонса (`ch7_hook`, `season_hook`).** В `ch7_hook` до 7h игрок видит «Спи, Элли» → «попробую». После паузы пишет человек с телефона Лили. В `season_hook` до 6h стоит закрытая реплика (в одной из веток — «я скажу правду»), а после — Мая. Оба события сильнейшие в своих главах, но вернётся к ним только тот, кто вернётся сам (RED-04). **Починить:** перед `#delay:7h` в `ch7_hook` дать `Пропущенный вызов · +44 7700 900521 #sys:lily #unlock:lily`. Сейчас номер игроку ничего не говорит, но ночной звонок без ответа уже крючок. А в главе 9, когда номер всплывёт в детализации у Джудит (`ch9_bill`), игрок узнает его задним числом. Перед `season_hook` — строку Элли: «мне пишет какая-то девушка. про денни. не отвечаю пока».
3. **Сломано: пустой вход в главу 9 (`ch9_morning`).** После 7h на строке «День 9 · Лестница» стоит ещё `#delay:150m` до первой реплики Джудит. Игрок вернулся к заголовку и ждёт 2,5 часа (RED-03). В ветке `ch9_bill` первая реплика приходит через минуту. **Починить:** перенести 150m в паузу строки главы (`#delay:9h`) и дать «Джессика была у меня в восемь» через 1m.
4. **Сломано: россыпь микросессий в развязке пятой главы (`end_*` → `season_hook`).** «Слушание отложено» / «меня вызвали давать показания» / «вердикт…» идут по 1–3 строки с паузами 1–3h. Кнопок нет 16 строк (медиана по главе). Это новостная лента, которую игрок собирает по строке за возвращение (RED-01, RED-06). **Починить:** склеить в 2 сессии («утро слушания» и «вечер»), паузы внутри сократить до 2–20m (`PAT-07`). В середину дать одну кнопку-реакцию Элли, хотя бы `#silent`.
5. **Сломано: ответ игрока повисает.** В 33 из 55 долгих пауз (медиана) пауза начинается в пределах двух строк после кнопки игрока. Частые случаи: глава 2 «спасибо» → 3h → «Здравствуйте.», глава 1 «она будет рада что кто-то этим занимается» → 1h, глава 8 «ау??» → 150m (RED-02). **Починить:** между ответом и паузой вставить строку, которая открывает вопрос (`PAT-02`), или сдвинуть паузу на одну реплику позже, после крючка.

## 5. Что не подходит нашему формату

- **«Подожди или заплати» и реклама вместо ожидания.** У нас нет монетизации, и пауза — содержание, а не плата. Перенимаем только то, что срок ожидания известен (`P-04`).
- **Тап на каждое сообщение.** Темп у нас задаёт движок (набор ~20 знаков/с), игрок его не ускоряет. Метрика «тап = внимание» недоступна. Заменитель — время до действия игрока (`P-10`).
- **Платные выборы (гемы Yarn).** Берём только наблюдение, что за деньги продавали вариант, который сдвигает сюжет (`P-11`). Сам приём — продажа последствия — для нас вреден: выбор должен быть равнодоступен.
- **Читатель как зритель чужой переписки.** У Hooked читатель смотрел чужой чат (HU), у нас игрок — участник, и ему пишут лично. Сцены, где игрок только наблюдает, у нас скучнее, чем там.
- **Ставка на шок и насилие для подростков.** Рынок на этом вырос, но его критиковали за шаблонность и жестокость (CSM). Наши истории длиннее, и без улик и арок шок не держит десять дней.
- **Уход в видео (Hooked TV, видео Yarn).** Это смена продукта, а не приём письма. Нам из этого полезно лишь то, что смешанный формат был лучше чисто видео (DD), поэтому `#photo` — акцент, а не основа (`P-14`).
- **Закрытия и падения (Tap, Rapids, выход Hooked из топ-200).** Открытых данных о причинах нет. Rapids бросили при ~120 тыс. установок без маркетинга (TC18). Hooked покупал аудиторию рекламой на YouTube (OMR), а аудитория Yarn по comScore за год упала с ~364 до ~163 тыс. (DD; comScore считал только взрослых 18+, то есть без основной подростковой аудитории, так что сигнал слабый). Вывод «формат держится на покупном трафике, а не на возвращениях» — наша гипотеза, уверенность: низкая. Для прототипа без трафика она означает одно: каждое возвращение надо зарабатывать текстом.

## 6. Дополнения второго прохода

### Правила для генератора (добавить к §1)
- Срок и цель истории называй в стволе, до первой развилки, а не в одной из её веток.
- В одном сообщении — не больше трёх новых имён. Список участников подавай по частям или через `#unlock` по одному.
- Первый хаб — не больше двух адресатов. Остальных открывай по ходу.
- В развилке у каждого варианта есть свой ответ. Осторожный вариант не наказывай репликой-упрёком (`LESSON-04`, `PAT-09`).
- Обрыв без «не в сети» (`PAT-08`) — не больше двух на историю и не в первой главе. Деталь, на которой оборвалось, возвращается позже.
- Обещанное перед долгой паузой приходит в первых трёх репликах после неё.

### Автоматические проверки (добавить к §2)

| проверка | что считать | порог | текст предупреждения |
|---|---|---|---|
| Срок в стволе | В узлах первой главы с посещаемостью 100% есть число со словом «дн / час / завтра / пятниц…» до первой развилки в разные узлы | нет | `⚠ срок истории звучит только в ветке <knot>: часть игроков его не услышит` |
| Имена в сообщении | Число слов с заглавной буквы (кроме первого слова), совпадающих с именами из `# contact`, в одной реплике | > 3 | `⚠ «<начало строки>»: N новых имён в одном сообщении` |
| Ширина развилки | Число видимых вариантов в одной точке выбора (с учётом условий в типичном прохождении) | > 4 | `⚠ <knot>: N кнопок на экране` |
| Длина кнопки | Слов в тексте кнопки без `#label` | > 6 у > 15% кнопок | `⚠ N% кнопок длиннее 6 слов` |
| Награда за крючок | Для каждой паузы ≥ 1h, перед которой есть «?», в первых 3 строках после неё есть реплика того же контакта | < 80% | `⚠ крючок «<строка>» не получает ответа после паузы` |
| Дневной бюджет | Сумма набора по главе (`#chapter` = день) | > 15 мин | `⚠ глава N: ~M мин чтения за день` |

### Идеи для реестра и команд (добавить к §3)
- **Повтор без долгих пауз.** После `END` вторая игра идёт с паузами, ужатыми до ≤ 10s (как Fast Mode Lifeline после первой концовки, `LESSON-01`). Статус в `docs/capabilities.json` — `planned`. Обычный первый проход не трогать.
- **Режим на карточке.** «Живое время» или «без долгих пауз» до первого запуска, как в Bury Me, My Love (`LESSON-02`). Статус — `planned`; для историй с паузами в часы, у которых тяжёлая тема или повтор.
- **Набор ответа игрока.** 0,5–1 с анимации перед появлением выбранной реплики (`LESSON-08`). Сейчас у `out` в `engine.ts` набора нет, только пауза 0,9 с.
- **`/hook-ledger`.** Вход — история. Выход — таблица пар «крючок до паузы → первая реплика после» с пометками «сбылся / ложный / нет крючка». Шаги: 1) прохождения бота; 2) пары на паузах ≥ 1h; 3) совпадение контакта и общего существительного; 4) топ ложных крючков.

### Разбор (добавить к §4)
6. **Срок только в ветке (`ch1` → `ch1_party`).** «Слушание у коронера через 4 дня» слышит лишь тот, кто спросил про вечеринку. **Починить:** строку про слушание дать в `ch1` до кнопок «Ок, давай / А что за вечеринка? / Я пас».

**Противоречия и как их решаем:**
- **Откат решения.** Lifeline давал откатиться к прошлому решению после гибели героя (WLF), а `meaningful-choice:P-10` запрещает отменять решение. **У нас:** внутри прохождения отката нет: переписка необратима, как в жизни. Сброс прогресса (`reset`) и повтор без долгих пауз решают ту же задачу, что откат у Lifeline: снимают цену повторной попытки, не обесценивая выбор первого прохода.
- **Каждое сообщение — клиффхэнгер** (TC15, `P-09`) **против мира, который не двигает сюжет** (`messenger-genre:P-11`). **У нас:** клиффхэнгер нужен только на границе сессии (нюанс к `P-02`). Внутри сессии допустим «шум» (банк, заметки) не чаще одной строки на 10, и лучше, если он работает уликой.
- **Резкий вариант как самый желанный** (`P-11`, вывод из платных выборов Yarn) **против «убирай очевидно лучший вариант»** (`meaningful-choice:P-04`). **У нас:** резкий — не лучший, а самый рискованный. У него видимая цена (блок, обида, раскрытие), а у осторожного — своя награда (`PAT-09`).
- **Дневной бюджет 10–15 минут** (`LESSON-06`) **против «длину задаёт история»** (`narrative-postmortems:P-17`). **У нас:** общую длину задаёт история, бюджет ограничивает только порцию за один день реального времени. Длинную историю растягивают на больше дней, а не уплотняют.
- **Пауза перед разгадкой** (`mystery-fair-play:P-13`) **против «после кульминации не заставляй ждать»** (`messenger-genre:P-16`). Противоречие кажущееся: в `mystery-fair-play` речь о 10–30 секундах на размышление, в `messenger-genre` — о часах. **У нас:** перед разгадкой — секунды и вопрос игроку. Долгая пауза допустима до кульминации, если перед ней крючок и названный срок (`P-03`, `P-04`), после кульминации — нет.
- **Метрика по боту** (`P-10`) **против «не доверяй частотам случайного бота»** (`narrative-testing:P-11`). **У нас:** бот находит структурные места (серии без кнопок, микросессии), а не поведение игрока. Пороги по доле прохождений — только для поиска мест, не для решений о вкусе.
