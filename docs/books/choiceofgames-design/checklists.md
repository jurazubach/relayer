# Процедуры

Каждый шаг — действие и ожидаемый результат. Процедуры опираются на S9, S10, S11, S12 (процесс) и S1, S4, S7, S13–S15 (критерии). Ссылки — в `README.md`.

## 1. Как придумать и начать историю

- [ ] **Формула в одну фразу.** Написать одно предложение с темой и главным напряжением, без названия жанра. → Если фразу можно заменить жанром или чужим сюжетом, переписать; если она не помещается в одну фразу, упростить замысел (S6, S10).
- [ ] **Список сцен с запасом.** Набросать 15–20 ярких сцен в духе истории, не заботясь о порядке. → Список-сырьё (S10).
- [ ] **Ужать до 8–12 сцен (глав).** Выбрать главный конфликт и выкинуть всё, что ему не служит, даже любимое. → Пронумерованный список: каждая сцена в 1–2 предложениях, с условиями ветвления (S10).
- [ ] **Герои.** Выписать собеседников, которые повторяются в сценах. Оставить 5–6 на 10 глав, каждого не меньше чем в 3–4 главах. → Блок `characters` в JSON, у каждого отмечены главы появления (S10, `P-17`).
- [ ] **Цели.** Назначить 2–4 независимые цели, которые тянут в разные стороны; удобно: у каждого ключевого контакта своя просьба. Проверить: любые две совместимы, все сразу — нет. → Список целей, по каждой 2–3 исхода (S8, `P-11`).
- [ ] **Переменные.** Разложить черновые `VAR` по шести категориям: способ действовать, черты, мораль, отношения/мир, ресурсы, цели. Найти хотя бы одну пару противовесов. → Таблица переменных с колонками «категория / что двигает / где проверяется» (S4, S5, `P-08`, `P-09`).
- [ ] **Финальная структура.** Решить, где поздняя развилка (рука и пальцы) и какие переменные её решают. → Набросок `route` с условиями по нескольким целям (S8, `PAT-03`).
- [ ] **Первой писать не первую главу.** Выбрать яркую сцену ранней середины, которую ясно видно, и написать её первой. Потом ещё одну-две. → 2–3 готовые главы, понятен тон (S9, `P-16`).
- [ ] **Теперь глава 1.** Проверить по списку обязанностей: мир (из чужих сообщений), кто такой игрок для собеседника, тон, крючок в первых 3–5 сообщениях, правила (что тут можно делать: отвечать, молчать, писать другим), стартовые переменные через вопросы героя, а не анкету. → Каждая обязанность закрыта строкой или развилкой; ни одна переменная главы 1 не остаётся непрочитанной в главах 2–3 (S9).

## 2. Как написать главу или сцену

Порядок проходов из S11 и способ «сначала структура» из S12, переложенные на ink.

- [ ] **Проход 1: каркас.** Написать узлы, развилки и `->` с текстом-заглушкой: кто пишет, что предлагают кнопки. Проверки переменных описать словами в комментарии `//`, у каждой развилки — `// тип:` (`P-20`). → Глава компилируется, `npm run check:story` проходит без тупиков (S11, S12).
- [ ] **Проход 2: ревизия каркаса.** Найти ветки, которые не возвращаются в общий узел, противоречивые варианты, особые случаи. Сверить с таблицей переменных: глава и меняет, и проверяет. → Список правок к каркасу; в главе есть `~` и чтение переменной из прошлой главы (S11, `P-07`).
- [ ] **Эхо на входе.** Добавить в начало главы 1–3 строки-эха. → Хотя бы одна строка зависит от выбора прошлой главы (`PAT-09`).
- [ ] **Каждая развилка — по чек-листу выбора:** (а) ставки названы в реплике или `#label` (`P-01`); (б) нет очевидно лучшего варианта (`P-03`); (в) у `#silent` своё последствие (`P-04`); (г) если сложность разная, она объявлена (`P-02`); (д) в развилках, меняющих состояние, три варианта (`P-05`). → У каждой развилки отмечено, к какому типу она относится: фальшивая, устанавливающая, проверочная, на цель, развилка сюжета (S13–S15).
- [ ] **Проход 3: текст.** Заменить заглушки репликами. Реплики игрока без указания пола. → Ни одной заглушки, ни одного «я был / была» в кнопках (S6, `RED-10`).
- [ ] **Проход 4: правка текста.** Проверить имена, факты, время, отсылки к прошлым главам. → Нет противоречий с прошлыми главами (S11).
- [ ] **Проход 5: переменные и пороги.** Проставить `~` и условия, сверить пороги с таблицей по главам: позднее препятствие требует больше. → Таблица порогов обновлена (S11, `P-15`).
- [ ] **Смесь типов.** Пометить развилки главы П/Д/С/И (`P-19`). → В главе развилки хотя бы двух типов.
- [ ] **Тестировать по ходу.** Прогонять бота после каждого крупного куска, а не в конце. → Ошибки ловятся рядом с местом, где появились (S12).

## 3. Как провести ревью готового сценария

- [ ] **Учёт выборов.** Разложить все развилки по типам `P-20`: fake / flavor / establishing / objective / forking / testing / climax. → Доли типов по главам. Фальшивые на решениях, а не на эмоциях, — `RED-05`; устанавливающие после первых двух глав или проверочные в первой главе — пересмотреть (S13–S15).
- [ ] **Сюрпризы.** Пройти все ветки с `-=` и ветки к худшим финалам: есть ли сигнал до кнопки. → Список `RED-01`/`RED-02` с узлами.
- [ ] **Лёгкие выборы.** Для развилок, меняющих состояние, выписать «даёт / отнимает». → Список развилок с очевидно лучшим вариантом (`RED-03`).
- [ ] **Пустое молчание и ложный отказ.** → Список `#silent` без последствий и отказов без следа (`RED-04`, `RED-14`).
- [ ] **Переменные.** По каждой `VAR`: присваивания, чтения, главы чтения. → Список мёртвых (`RED-06`) и «одноразовых в той же сцене» (`RED-07`).
- [ ] **Категории и противовесы.** → Пустые категории из `P-08`; есть ли хоть одна пара противовесов (`P-09`).
- [ ] **Финалы.** Какие переменные решают распределитель; сколько независимых целей; объясняет ли каждый финал свою причину; нет ли финала раньше 75%; нет ли «чистого поражения». → Таблица финалов: условие, доля у бота, строки-объяснения (S7, S8, `RED-09`, `RED-12`).
- [ ] **Герои.** Число глав с репликами каждого контакта. → Список героев меньше чем с тремя главами (`RED-16`).
- [ ] **Повторяющиеся подходы.** → Есть ли Four Point Trap (`RED-13`).

## 4. Как тестировать

- [ ] **Бот на всё.** `npm run check:story` → нет тупиков, все узлы посещены, финалов больше одного.
- [ ] **Распределение финалов.** Из вывода бота выписать долю каждого финала. → Финалы с долей <2% отметить и проверить: недостижимы или просто требуют целенаправленной игры (`RED-08`). Бот кликает случайно, поэтому редкий финал не всегда ошибка.
- [ ] **Целенаправленные прогоны.** Пройти вручную (`?fresh=1&fast=1`) три раза с разной стратегией: «всем доверяю», «всех проверяю», «молчу». → Каждая стратегия доходит до своего финала, и финал объясняет, почему (S7).
- [ ] **Пороги.** Для каждой проверки `>= N` посмотреть, какие значения переменной бывают у дошедших до неё (метод S16: сложность зависит от того, кто дошёл). → Уникальный исход достаётся примерно 10–15% дошедших до развилки (ориентир S16), обычная проверка — около половины.
- [ ] **Слова между выборами.** Посчитать (см. `for-relayer.md`, проверка 4). → Нет участков >150 слов без кнопки.
- [ ] **Карта.** `npm run graph` → посмотреть узлы, где кнопки расходятся, и скрытые проверки. Каждая скрытая проверка финала сопровождается подсказкой раньше по сюжету (`P-01`).

## 5. Паузы и возвращения (второй проход)

- [ ] **Список пауз.** Выписать все `#delay` ≥30 мин с узлами. → Таблица пауз (`/pause-audit`).
- [ ] **Причина.** У каждой паузы ≥30 мин в 3 строках до неё есть причина молчания героя. → Нет пауз «просто так» (`GREEN-12`, `LESSON-02`).
- [ ] **Крючок.** Перед паузой ≥1 ч — развилка или вопрос без ответа; сильные обрывы — только перед паузами в часы. → Проверка 20 чиста, обрывы не повторяются подряд (`P-23`).
- [ ] **Первая реплика после.** Новость или имя, не служебное слово. → Проверка 21 чиста (`RED-18`).
- [ ] **Эхо и кнопка.** В 1–3 сообщениях после паузы — эхо выбора до неё, кнопка не позже пятого. → Вернувшийся игрок действует в первые полминуты (`attention.md` п. 3).
