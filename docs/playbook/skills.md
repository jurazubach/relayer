# План скиллов и команд

Свод идей из разделов «Идеи скиллов и команд» (`for-relayer.md` §3, а также §6–8, где они есть) и процедур (`checklists.md`) всех 30 разборов в `docs/books/`. Два вида инструментов:

- **Команда** (`npm run …`) — детерминированный скрипт. Он считает то, что можно посчитать без модели: прохождения бота, таблицу переменных, паузы. Живёт в `scripts/`.
- **Скилл** — `.claude/skills/<имя>/SKILL.md` для Claude Code. Он читает вывод команд, применяет правила из базы знаний и пишет отчёт или правку ink.

Скиллы не считают на глаз то, что умеет считать команда: каждое число в отчёте берётся из вывода команды. Модель отвечает за то, что скрипт не видит: смысл, голос, «понятно ли».

Ссылки: `алиас:/команда` — откуда идея скилла; `алиас:P-NN`, `PAT-NN`, `RED-NN` — пункт разбора; `алиас:чек-лист §N` — раздел `checklists.md`. Соседние файлы свода: `rules.md` (правила генератора, разделы 1–9), `checks.md` (проверки `C-NN`), `story-findings.md` (находки по трём историям).

### Общие правила для всех скиллов

1. Ink пишется только тегами со статусом `ready` в `docs/capabilities.json`. Если скиллу нужен тег `planned`, он пишет это в отчёте и не использует тег (так требует `CLAUDE.md`).
2. Любая правка ink заканчивается `npm run check:story`: 0 тупиков, все узлы посещены. Если в узле поменялись `->`, ещё и `npm run graph`.
3. Текст автора без подтверждения не переписывается. Сначала отчёт с предложением, потом правка (`maass-fire-in-fiction:/tension-pass`). Каждое «вырезать» идёт вместе с «вместо этого» (`nicklin-writing-for-games:P-17`).
4. Находка оформляется как `флаг · узел · симптом · правка`. Без имени узла находка не принимается (`narrative-testing:/story-review`, `postmortem-review`, `failbetter-qbn:чек-лист §3`).
5. Упрощается подача, а не сюжет. Правка не может удалить улику или мотив (`attention-today:P-14`, `RED-10`).
6. Сначала чиним непонятное, потом скучное (`edgerton-hooked:LESSON-01`, `snyder-save-the-cat:LESSON-05`).
7. Всё в историях вымышлено: проверка имён на реальные бренды и людей входит в каждый генерирующий скилл (`procedural-storytelling:P-18`, `RED-13`).

## 1. Фундамент

### D-01. Шапка истории — единая разметка в комментариях ink

> **Заменено** `build-plan.md` §9: шапка из 4 строк и 3 вида меток (`superseded.md` A-06). Десять полей ниже — история, не брать как действующее.

Разные источники предлагают свою разметку: `// ядро:` (video), `// ЛОГЛАЙН:` и `// beat:` (snyder), `// ПОСЫЛКА:` (truby), `// HERO:` и `// stage:` (vogler), `// ДОМ:` и `// ОПОРА` (yorke), `// concept` и `// truth:` (dille), `// главная ценность:` (mckee), `// опыт:` (schell). Если принять всё, шапка займёт экран, и ни один бот её не прочтёт.

- **Вход:** ink истории (новой или из `src/stories/`). **Выход:** блок комментариев в начале ink по схеме ниже; на поля ссылаются R-01 из `rules.md` и C-53 из `checks.md`.

**Решение:** одна обязательная шапка из 10 полей и несколько необязательных меток. Поля выбраны так, чтобы каждое читал хотя бы один скилл или команда.

```
// ядро: (1) … (2) … (3) …          — 1–3 правила мира, ≤ 6 слов, без имён        video-three-things:P-01, PAT-02
// роль: я — …, мне пишут, потому что …                                           vogler-writers-journey:P-03, skolnick-video-game-storytelling:P-14, messenger-genre:P-05
// герой: <id> хочет …, верит …, боится …; событие прошлого: …                    cron-wired-for-story:P-06, P-13, vogler-writers-journey:/helper-adapt, truby-anatomy-of-story:P-06
// ставка: что потеряет <id> · срок: к <когда> или <что случится>                chat-fiction-apps:P-08, maass-fire-in-fiction:P-10, narrative-testing:чек-лист §1
// противник: <id> — чего хочет той же вещи                                       truby-anatomy-of-story:P-07, skolnick-video-game-storytelling:чек-лист §1
// вопрос: главный вопрос, на который отвечает каждый финал                       cron-wired-for-story:P-17, truby-anatomy-of-story:P-13
// ось: VAR — смысл; пишется в главах …, читается в …                             ashwell-standard-patterns:P-04, edgerton-hooked:PAT-04, failbetter-qbn:P-03
// финал читает: последняя кнопка × <оси>                                         ashwell-standard-patterns:P-11, yorke-into-the-woods:P-10
// темп: сериал N дней, M мин в день | одна сессия                                serial-hooks:чек-лист §1, messenger-genre:чек-лист §1
// flow chN: срок · вопрос главы → где закрыт · что решает · крючок · структура   dille-ultimate-guide:PAT-07, serial-hooks:P-14, ashwell-standard-patterns:чек-лист §1
```

Необязательные метки ставятся там, где их читает скилл:
- `// логлайн:` — для `story-core`, `// рамка:` — для `story-endings` (`rules.md` R-02, R-109);
- `// reveal: <имя> at: <узел> needs: clue_a, clue_b`, `// culprit:`, `// truth:`, `// lie:` — для `clue-audit` и C-54 (`mystery-fair-play:/clue-audit`, `dille-ultimate-guide:P-04`);
- `// крючок: угроза|откровение|дилемма|прибытие|срок|отношения` — для `pause-audit` (`serial-hooks:PAT-08`);
- `// <id>: голос …` — лист голоса для `voice-check` (`nicklin-writing-for-games:P-02`);
- `// застрянут:` — прогноз автора для `playtest` (`bateman-game-writing:P-12`);
- `// намеренно: <причина>` — снимает предупреждение проверки (`schell-art-of-game-design:чек-лист §4`);
- метки автопроверок (`// событие`, `// середина`, `// кризис`, `// promise:` / `// payoff:`, `// term:`, `// хорошие финалы:`) — по `checks.md` C-53.

Эта схема общая для `rules.md` (R-01 и правила с метками) и `checks.md` (C-53, C-54). Меняется в одном месте — здесь.

Стадии Воглера, биты Снайдера, семь шагов Труби и знаки ценности Макки в шапку не входят. Это линзы ревью (`S-10 --lens`): их разметку ставит сам скилл и показывает автору как дифф комментариев (`vogler-writers-journey:/journey-map`).

**Готово, когда:** раздел о шапке есть в README и `docs/PROMPT.md` (через реестр). Хотя бы одна из трёх историй размечена. `story-graph` показывает поля шапки на карте.

### K-01. `npm run story:trace` — прохождение с маршрутом и персонами

- **Слито из:** `narrative-testing:/story-transcript`, `dille-ultimate-guide:/story-supercut`, `chat-fiction-apps:/session-map` (симуляция), персоны из чек-листов: `choiceofgames-design:чек-лист §4` («всем доверяю / всех проверяю / молчу»), `inkle-ingold:чек-лист §4` (молчун, отказник), `vogler-writers-journey:чек-лист §4` (три роли), `dille-ultimate-guide:чек-лист §4` («всегда необязательное»), `narrative-testing:чек-лист §6` (персоны `first`/`last`).
- **Вход:** `[-- story.json] --persona first|last|random|silent|refuse|curious --seed N --until chN`.
- **Выход:** `.md` с одним прохождением. Для каждой строки: сюжетное время, чат, отправитель, текст, нажатая кнопка, `#chapter`, `#delay`. В шапке файла — маршрут (индексы кнопок), по которому прохождение можно воспроизвести (`narrative-testing:P-16`), и снимок переменных на каждом `#chapter`. С `--json` то же самое выдаётся данными для других скиллов.
- **Персоны:** `first` — всегда первая кнопка (основной путь, `dille-ultimate-guide:/story-supercut`); `last` — всегда последняя; `silent` — `#silent`, где он есть; `refuse` — кнопка с отказом (по `#label` или по словам «нет / не буду»); `curious` — сначала все необязательные ветки хаба.
- **Шаги:** взять цикл бота из `check-story.mjs` → вынести выбор кнопки в функцию персоны → писать события в журнал → считать время набора по формуле `engine.ts`.
- **Готово, когда:** два запуска с одним `--seed` дают один и тот же файл; маршрут из шапки воспроизводит прохождение; `silent` и `refuse` доходят до `END` на всех трёх историях или выдают узел, где застряли.

### K-02. `npm run story:vars` — переменные: запись → чтение

- **Слито из:** `emshort-structures:/story-vars`, `failbetter-qbn:/story-qualities`, `inkle-ingold:/story-memory`, `narrative-postmortems:/story-payoffs`, `dille-ultimate-guide:/story-resources`, `sheldon-character-storytelling:/attitude-audit`, `procedural-storytelling:/story-consequences` (таблица), `meaningful-choice:чек-лист §3`.
- **Вход:** `[-- story.json]`; ink разбирается статически, как индекс переменных в `checks.md` («Общие данные»).
- **Выход:** таблица `VAR · записей · чтений в условиях · чтений в тексте · глава первой записи · глава первого чтения · глава первого упоминания в реплике · читает ли финал · комментарий-смысл`. Метки:
  - `мёртвая` — 0 чтений (`emshort-structures:RED-01`, `choiceofgames-design:RED-06`, `bateman-game-writing:RED-04`);
  - `только финал` — единственное чтение в маршрутизаторе финала (`emshort-structures:RED-02`, `messenger-genre:RED-11`, `schell-art-of-game-design:RED-10`);
  - `молчит` — между записью и первым чтением больше 2 глав (`emshort-structures:RED-03`);
  - `немая запись` — `~ x += N` без реплики, которую игрок видит в той же главе (`procedural-storytelling:P-10`);
  - `одноразовая` — запись и единственное чтение в одной сцене (`choiceofgames-design:RED-07`);
  - `сложное условие` — условие из 3+ флагов (`failbetter-qbn:RED-03`);
  - `счётчик вниз` — переменная только убывает (`failbetter-qbn:RED-05`).
- **Спорное:** сколько глав переменная может молчать. Порог `emshort-structures:RED-03` — больше 2 глав, `narrative-testing:RED-03` — от 3. **Берём «больше 2 глав» как предупреждение:** при 5 главах разрыв в 3 главы — это больше половины истории.
- **Готово, когда:** таблица для `the-number` сходится с ручным подсчётом по `grep '~'`. Каждая метка ссылается на узел.

### K-03. `npm run story:sessions` — паузы, сессии, реальное время

- **Слито из:** `chat-fiction-apps:/session-map`, `/hook-ledger`, `choiceofgames-design:/pause-audit`, `serial-hooks:/pause-audit`, `snyder-save-the-cat:/pause-audit`, `yorke-into-the-woods:/pause-map`, `/chapter-ends`, `messenger-genre:/story-pacing`, `schell-art-of-game-design:/hook-audit`, `mobile-interactive-stories:/story-hooks`.
- **Вход:** `[-- story.json] --min 30m`; прохождения бота из `K-01`.
- **Выход:** две таблицы по медианному пути и сводка по 400 прохождениям.
  - **Паузы ≥ 30m:** глава · узел · длина · 3 строки до · 3 строки после · есть ли в 3 строках до причина или время · сколько сообщений до первой кнопки после паузы · первые 3 слова после паузы.
  - **Сессии** (куски между паузами ≥ 30m, как в `checks.md`): сообщений · кнопок · секунд набора · последняя строка · метка `крючок / закрытая / микро`.
  - **Сводка:** доля микросессий, доля пауз ≥ 1h с крючком, сумма пауз по главам, полное реальное время, пауза на стыке 1→2.
- **Спорное:** с какой длины паузу вносить в таблицу. Предлагают 10m (`snyder`), 15m (`messenger-genre`), 30m (`choiceofgames`, `serial-hooks`). **Берём 30m по умолчанию и флаг `--min 10m`:** с 30m `attention-today` считает паузу длинной, а короче игрок обычно не уходит из чата.
- **Готово, когда:** на `chuzhoy-golos` таблица находит стык 1→2, описанный в `yorke-into-the-woods:for-relayer §7` (закрытие → 7h → крючок после паузы).

### K-04. Финалы по узлам в `check:story`

- **Зачем:** бот группирует финалы по последней строке. На THE NUMBER разных последних строк две, а исходов больше (`ashwell-standard-patterns:чек-лист §4`, `messenger-genre:чек-лист §4`, `narrative-testing:чек-лист §3`).
- **Вход:** история, которую `check:story` уже прогоняет. **Выход:** раздел «Финалы» в выводе `check:story`.
- **Что добавить:** долю каждого `fin_*` (или значение `ending`) · в какой главе наступил `END` · для каждой кнопки, у которой исходы расходятся, — как её выбор меняет распределение финалов (`meaningful-choice:проверка 7`, `mobile-interactive-stories:/choice-audit`) · для каждого порога `>= N` — значения переменной у тех, кто до него дошёл (`choiceofgames-design:чек-лист §4`).
- **Готово, когда:** на всех трёх историях вывод совпадает с числом узлов `fin_*`.

### K-05. Журнал выборов в отладке

- **Слито из:** `narrative-postmortems:§3` (журнал для тестеров), `inkle-ingold:чек-лист §4` (в 80 Days отзывы стали полезными благодаря журналу ходов), `choiceofgames-design:/tester-feedback`.
- **Вход:** живая игровая сессия в браузере. **Выход:** файл журнала `узел · кнопка · время`, который читает `K-01 --route`.
- **Что:** кнопка в `DebugSheet` «Скачать прохождение»: список `узел · кнопка · время`. Логика в `engine`, кнопка в `ui` (так требует `CLAUDE.md`). Формат совпадает с маршрутом `K-01`, поэтому журнал тестера воспроизводится ботом.
- **Готово, когда:** журнал, выгруженный из браузера, `story:trace --route` проигрывает до того же узла. Есть e2e-проверка кнопки с `data-testid`.

### S-00. `cold-reader` — холодный читатель (общий протокол)

Модель без доступа к сценарию получает только фрагмент и отвечает на один вопрос. Это замена живому тестеру для вопросов «понятно ли» и «интересно ли». Протокол один, а вопросы зависят от режима.

- **Слито из:** `attention-today:/cold-read`, `maass-fire-in-fiction:/what-next`, `nicklin-writing-for-games:/blind-voice`, `procedural-storytelling:/story-cast` (слепой тест), `video-three-things:/opening-audit` (тест холодного читателя), `snyder-save-the-cat:чек-лист §1` (досказать логлайн), `edgerton-hooked:чек-лист §4`, `truby-anatomy-of-story:чек-лист §5`, `vogler-writers-journey:чек-лист §5`.
- **Режимы:**

| режим | что видит читатель | вопрос | зачёт |
|---|---|---|---|
| `button` | 3 сообщения над кнопкой и сами кнопки | о чём этот выбор? | совпадает с намерением автора (`attention-today:P-01`, `RED-04`) |
| `next` | переписка до кнопки | 2–3 версии того, что будет дальше, и насколько тебе не всё равно | ≥ 2 версии и не «всё равно» (`maass-fire-in-fiction:/what-next`) |
| `opening` | `tagline` и первые 15 входящих | кто пишет, чего хочет, к какому сроку, кто ты здесь | три ответа без «не знаю» (`edgerton-hooked:чек-лист §4`, `truby-anatomy-of-story:чек-лист §5`) |
| `core` | `tagline` и первые 15 входящих | о чём история, что может случиться дальше | названы вещи ядра и ≥ 3 вариации (`video-three-things:чек-лист «Как тестировать»`) |
| `logline` | `// логлайн:` | доскажи сюжет | сам назвал главный конфликт (`snyder-save-the-cat:чек-лист §1`) |
| `return` | только первое сообщение после паузы | о чём речь? | понятно без текста выше (`edgerton-hooked:второй проход`, `failbetter-qbn:чек-лист §4`) |
| `voice` | 10 реплик каждого из двух контактов без `#from`, перемешаны | разложи по листам голоса | ≥ 8 из 10 (`nicklin-writing-for-games:P-03`, `procedural-storytelling:чек-лист §3`) |
| `guess` | всё до узла разгадки | твоя версия одной фразой | у живых тестеров 30–70% угадавших — **наша оценка** (`mystery-fair-play:P-16`); у модели только качественно: версия опирается на улики |

- **Вход:** режим из таблицы и фрагмент из `K-01 --json` (или `tagline` и `// логлайн:`). **Выход:** `понятно / нет`, ответ читателя и причина расхождения с намерением автора.
- **Шаги:** взять фрагмент из `K-01 --json` → запустить отдельного агента без доступа к файлам истории → сравнить ответ с шапкой (`D-01`) или с намерением автора → выдать `понятно / нет` и причину.
- **Ограничение:** модель не заменяет человека в вопросах «скучно» и «где отложил телефон» (`inkle-ingold:P-15`). Такие пункты скиллы помечают «нужен живой тест».
- **Готово, когда:** на одном и том же фрагменте режим даёт устойчивый вердикт в 3 запусках из 3.

## 2. Создание

### S-01. `story-core` — придумать завязку и ядро

- **Когда:** «придумай историю», «с чего начать», «есть идея: …», «нужна завязка», «сделай логлайн», «не знаю, о чём писать», «помоги с концептом».
- **Вход:** идея в 1–5 строк (или пусто — тогда шаг 0), желаемая длина в минутах, жанр по желанию.
- **Выход:** заполненная шапка `D-01` и черновики полей карточки (`tagline`, `synopsis`, `features`). Плюс 2–3 варианта логлайна с разной иронией и вердикт холодного читателя по каждому.
- **Алгоритм:**
  0. *Если идеи нет:* 5 семян вида «как X, но Y» в нашем жанре. Отбросить те, где игроку некому писать или непонятно, почему пишут именно ему (`nicklin-writing-for-games:/seeds`, `чек-лист §1`).
  1. **Роль игрока.** Одна строка: «я — …, мне пишут, потому что …». Игрок здесь помощник на телефоне, а не герой на экране: главного героя-NPC выбрать так, чтобы он рисковал больше всех (`vogler-writers-journey:/helper-adapt`, `skolnick-video-game-storytelling:P-14`, `messenger-genre:P-05`).
  2. **Ядро.** 1–3 вещи: правило или способность, а не событие. Для каждой вещи нужно ≥ 3 ответа на вопрос «что ещё из этого может случиться?», иначе вещь заменить. Хотя бы для одной вещи складывается фраза «обычно …, а здесь …» (`video-three-things:/story-core`, `P-01`, `P-12`). Из кандидатов выбирать ту вещь, что бьёт по слабости героя (`video-three-things:§7` — решение спора с `truby-anatomy-of-story:P-15`).
  3. **Герой.** «X хочет Y, но верит Z» и событие прошлого, которое создало Z. Если строка не пишется, есть только события, а сюжета ещё нет: остановиться (`cron-wired-for-story:/story-core`, `P-06`, `P-13`).
  4. **Ставка и срок.** Что потеряет герой, если игрок не поможет; срок и цена провала. Отдельно — личная ставка «тебя» (`cron-wired-for-story:P-07`, `P-08`, `maass-fire-in-fiction:чек-лист §1`, `chat-fiction-apps:P-08`).
  5. **Инцидент, поверхностная и глубинная проблема.** Три строки. Из первой логически следует вторая, а решение второй упирается в третью (`edgerton-hooked:P-01–P-03`, `чек-лист §1`).
  6. **Противник** хочет той же вещи и верит в свой мотив (`truby-anatomy-of-story:P-07`, `skolnick-video-game-storytelling:P-10`).
  7. **Главный вопрос** и **ось.** Вопрос, на который ответит каждый финал. Одна-две переменные под глубинную проблему и финалы, которые их читают (`cron-wired-for-story:P-17`, `edgerton-hooked:PAT-04`, `meaningful-choice:P-14`).
  8. **Несоответствие первого экрана:** деталь, после которой игрок спросит «почему?». И предвестие, которое вернётся в финале (`cron-wired-for-story:P-02`, `edgerton-hooked:P-12`).
  9. **Логлайн**, 2–3 варианта с разной иронией (поручение против интереса, помощь против улики, роль против правды). Ирония должна уместиться в первые 5 сообщений (`snyder-save-the-cat:/logline`, `PAT-01`).
  10. **Карточка.** `tagline` не длиннее 15 слов: роль + действие + нарушение, ≤ 1 имени и ≤ 1 числа (`dille-ultimate-guide:P-02`, `video-three-things:P-10`). В `synopsis` — роль, мир и тон, но не сам инцидент (`edgerton-hooked:RED-10`). Имена, которые появляются только после главы 1, в `synopsis` не пишутся (`video-three-things:чек-лист`).
  11. **Темп.** Сериал (паузы в часы, N дней) или одна сессия. До 20 минут — одна сессия без пауз ≥ 1h (`chat-fiction-apps:P-15`, `serial-hooks:чек-лист §1`).
  12. Прогнать `S-00 logline` и `S-00 core` по черновику первых строк.
- **Короткая форма (история ≤ 15 минут):** только шаги 1, 2, 4 и 7 без оси (`attention-today:§1`, `cron-wired-for-story:второй проход`, `vogler-writers-journey:PAT-11`).
- **Знания:** `docs/playbook/rules.md` §1; `docs/books/video-three-things/{principles,patterns,checklists}.md`; `cron-wired-for-story/checklists.md §1`; `edgerton-hooked/checklists.md §1`; `snyder-save-the-cat/patterns.md PAT-01`; `vogler-writers-journey/for-relayer.md §3` (таблица переноса «герой → помощник»); `dille-ultimate-guide/checklists.md §1`; `nicklin-writing-for-games/checklists.md §1`.
- **Готово, когда:**
  - все 10 полей шапки заполнены, а у короткой формы — 4;
  - `S-00 logline` назвал главный конфликт, `S-00 core` — вещи ядра;
  - у каждой вещи ядра ≥ 3 следствия;
  - строка «X хочет Y, но верит Z» и личная ставка игрока не пусты;
  - `tagline` ≤ 15 слов, в `synopsis` нет инцидента.
- **Спорное и решение:** разные источники ставят в центр разное: ядро-правила (video), убеждение героя (cron), ценность-пару (mckee), посылку (truby), логлайн с иронией (snyder). Это не альтернативы, а слои. Ядро задаёт мир, убеждение — героя, логлайн — продажу. Ценность Макки и посылку Труби в шапку не берём: их работу делают поля `герой` и `вопрос`.

### S-02. `story-plan` — скелет истории до текста

- **Когда:** «распиши главы», «сделай план сезона», «структура истории», «скелет», «разложи по главам», «у меня есть ядро, что дальше».
- **Вход:** шапка из `S-01`, число глав (обычно 5 или 10), длина в минутах.
- **Выход:** компилируемый скелет ink: узлы `ch1…chN`, строки `// flow chN:`, объявления `VAR` с комментарием «пишется → читается → какой финал», горлышки на границах глав, маршрутизатор финала с `else`, текст-заглушки по одной строке на сцену. Плюс таблица героев «контакт → функция → главы появления → что знает только он».
- **Алгоритм:**
  1. **Бюджет отсекает структуры.** Quest и branch-and-bottleneck короче ≈ 3 глав не окупаются, «распределяющая шляпа» — короче ≈ 4 глав (порог наш); time cave в реальном времени не окупается вовсе (`ashwell-standard-patterns:чек-лист §1`).
  2. **Каркас из пяти опор:** вызов · поворот · середина (знание, которое меняет цель A на цель B) · худшее · развязка. Опоры разложить по главам. История до 15 минут — три опоры (`yorke-into-the-woods:/five-acts`, `PAT-01`, `PAT-11`).
  3. **Каждой главе одну строку `// flow`:** вопрос главы и узел, где он закрыт; срок; что игрок узнаёт; что решает; крючок; структура `hub | gauntlet | B&B | hat | final` (`dille-ultimate-guide:PAT-07`, `serial-hooks:P-14`, `ashwell-standard-patterns:чек-лист §1`, `failbetter-qbn:чек-лист §1`). Ни в одной главе, кроме последней, число открытых вопросов не падает до нуля (`mobile-interactive-stories:P-03`).
  4. **Лестница ставок и потерь:** ставка каждой главы выше прошлой; по одной потере на главу, лучше сразу после выигрыша (`skolnick-video-game-storytelling:P-08`, `maass-fire-in-fiction:/stakes-ladder`, `P-09`).
  5. **Лестница раскрытий:** по раскрытию на главу («было → стало»); во второй половине интервалы короче (`truby-anatomy-of-story:/reveal-ladder`, `P-09`). Для каждого раскрытия — два узла с намёками и узел с последствием (`maass-fire-in-fiction:P-11`).
  6. **Оси и переменные.** 2–3 оси (не больше 2–3 счётчиков отношения, `procedural-storytelling:P-03`), у каждой дистанция ≥ 1 главы и первая видимая реплика в той же главе, что и первая запись (`ashwell-standard-patterns:P-04`, `procedural-storytelling:чек-лист §1`). Новая переменная без места чтения не заводится (`failbetter-qbn:P-03`).
  7. **Горлышки:** по событию на каждую границу главы. Длинная пауза, затем условная первая реплика по оси (`ashwell-standard-patterns:P-03`, `GREEN-01`).
  8. **Герои:** 5–6 на 10 глав, каждый в ≥ 3 главах (`choiceofgames-design:чек-лист §1`, `RED-16`). Говорящих в главе 3–6 (`nicklin-writing-for-games:RED-11`). У каждого функция, а не профессия (`sheldon-character-storytelling:P-04`), и уникальное знание (`procedural-storytelling:P-05`). У любых двух различаются хотя бы два параметра голоса (`nicklin-writing-for-games:P-02`).
  9. **Цели и финал.** 2–4 цели, которые тянут в разные стороны: любые две совместимы, все сразу нет (`choiceofgames-design:чек-лист §1`). Формула финала: последняя кнопка × оси из ранних глав. Если финал решает только кнопка или только скрытая проверка, план переделать (`ashwell-standard-patterns:RED-06`, `RED-07`). Для кандидатов финального выбора «между людьми» запланировать сцены: просьба, уязвимость, помог или подвёл (`narrative-postmortems:P-05`).
  10. **Тайна** (если есть): правда до сюжета (8–15 строк хронологии), 3–6 откровений, по три улики на каждое, 1–2 приманки с опровержением и ценой. Виновник появляется в главе 1–2 (`mystery-fair-play:/mystery-skeleton`, `чек-лист §1`). Разметка `// truth:`, `// reveal:`, `// culprit:`, объявления `VAR clue_*`.
  11. **Сутки мира:** когда персонажи спят, работают, едут. Из этого расписания берутся причины пауз. В главах 1–2 не больше одной паузы от 2h. Самый сильный крючок до середины ставится в главе 2 (`serial-hooks:чек-лист §1`, `P-12`).
  12. **Собрать скелет в ink** с заглушками → `npm run check:story` → `npm run story:vars`. Ни один финал не должен брать > 50% (`narrative-testing:PAT-09`, `RED-12`).
  13. *По желанию:* групповая читка скелета. 3–4 человека молча пишут по 3 заметки («не понял / не поверил / потерял интерес»), и места с ≥ 2 заметками правятся до прозы (`narrative-testing:чек-лист §5`).
- **Знания:** `docs/playbook/rules.md` §3, §8; `docs/books/yorke-into-the-woods/patterns.md PAT-01, PAT-11`; `ashwell-standard-patterns/{patterns,checklists}.md`; `choiceofgames-design/checklists.md §1`; `mystery-fair-play/checklists.md §1`; `serial-hooks/checklists.md §1`; `failbetter-qbn/checklists.md §1`; `emshort-structures/checklists.md §1`.
- **Готово, когда:**
  - скелет компилируется, `check:story` даёт 0 тупиков, ни один финал не > 50%;
  - `story:vars` не находит мёртвых переменных и переменных «только финал»;
  - у каждой главы заполнена `// flow`, у каждой границы есть горлышко;
  - у каждого героя ≥ 3 главы;
  - ставка и срок стоят в узле главы 1, через который проходит 100% прогонов (`ashwell-standard-patterns:RED-12`).
- **Спорное и решение:**
  - *Каркас.* Предлагались биты Снайдера, стадии Воглера, семь шагов Труби, три акта Сколника, пять опор Йорка. **Берём пять опор:** их число совпадает с числом глав наших историй, есть короткая версия на три опоры, и бот проверяет опоры по доле пути (`yorke-into-the-woods:чек-лист §3`). Остальные каркасы работают линзами в `S-10`.
  - *С какой главы писать.* `choiceofgames-design:P-16` — сначала яркую сцену ранней середины; `procedural-storytelling:P-01` — сначала простой ствол главы 1; `yorke-into-the-woods:P-10` — сначала финал. **Порядок:** последние 1–3 сообщения финала → скелет всех глав → проза главы 1. Финал задаёт, что должны прочитать переменные. Скелет даёт проверку ботом. Главу 1 стоит проверить на человеке раньше остальных: если форма не держится, меняют формат, а не дописывают главу 2 (`narrative-postmortems:P-14`). Совет `choiceofgames` — это порядок прозы, а не плана (так его читает и сам разбор, `choiceofgames-design:§10, п. 10`).
  - *Где ветвиться.* `emshort-structures:P-08` бережёт ветвление для финала, `narrative-postmortems:LESSON-13` решает выбор в первой трети, `yorke-into-the-woods:RED-08` требует, чтобы кризис проходили все. **Две фазы:** выборы, которые копят состояние, идут рано, развилки сюжета — после кризиса, а сам кризис стоит в стволе (`yorke-into-the-woods:§8`, `narrative-postmortems:§6`).

### S-03. `chapter-write` — написать главу

- **Когда:** «напиши главу N», «допиши день 3», «сгенерируй следующую главу», «напиши сцену, где …», «распиши эпизод».
- **Вход:** скелет (`S-02`), номер главы, последние 3 строки прошлой главы, вывод `story:vars`.
- **Выход:** ink главы, вставленный в историю. Над главой — комментарии `// глава N: вопрос → ответ`, `// хочет / мешает`, `// A / B / C`, `// сдвиг: <VAR> — кто читает`. Плюс отчёт проверок.
- **Алгоритм** (проходы по `choiceofgames-design:чек-лист §2` и `failbetter-qbn:P-01`: сначала скелет, потом текст):
  1. **План главы.** Линия A (вопрос главы и контакт, который её ведёт), B (контрастный тон, другой чат), C (1–3 мелочи, одна отзовётся позже). Место свободы: хаб, тон или развилка, не больше одного хаба на главу (`nicklin-writing-for-games:/episode-plan`, `P-08`, `P-09`). Эпизоды: 3–6 штук, в каждом 6–20 строк и 1–3 кнопки (`chat-fiction-apps:/episode-draft`, `PAT-01`).
  2. **Каркас.** Узлы, кнопки, `->`, `~`, заглушки «кто пишет, что предлагают кнопки». У каждой развилки комментарий `// тип: окраска | переменная | узел | другой чат` (`choiceofgames-design:P-20`, `ashwell-standard-patterns:чек-лист §2`). Компиляция и `check:story` проходят.
  3. **Вход в главу.** Первая строка возвращает вопрос или следствие прошлой главы. Это рекап голосом персонажа, без «напомню» (`chat-fiction-apps:PAT-05`, `cron-wired-for-story:PAT-03`, `serial-hooks:PAT-03`). Дальше 1–3 условные строки-эха на выборы прошлых глав, хотя бы одна от другого контакта (`choiceofgames-design:PAT-09`, `meaningful-choice:PAT-01`). Событие главы приходит в первых 5 входящих, первая кнопка — до 5-го входящего и не позже 10m сюжетного времени (`yorke-into-the-woods:RED-02`, `PAT-12`, `chat-fiction-apps:RED-03`).
  4. **Кнопки.** У каждой кнопки свой ответ (`inkle-ingold:P-02`). У решений названа цена, у `#silent` своё последствие (`meaningful-choice:P-03`, `P-11`). 2–3 варианта, 4 только в хабе «кому написать» (`attention-today:§4`). Кнопка 2–6 слов, без чувств за игрока, без указания пола (`messenger-genre:P-13`, `failbetter-qbn:P-16`, `choiceofgames-design:RED-10`). Ставку называет персонаж за 1–3 сообщения до решающей группы (`meaningful-choice:P-02`). Реакция на кнопку-решение — не «ок», а отказ, условие или новый факт (`mckee-story:P-04`).
  5. **Одна развилка с резким вариантом.** Вариант ведёт в свой узел, последствие видно до конца главы или в начале следующей (`chat-fiction-apps:PAT-06`). Дилемма ставится ближе к концу (`yorke-into-the-woods:PAT-07`). Перед развилкой с последствием в этом или другом чате лежит улика (`messenger-genre:P-06`).
  6. **Хаб,** если он есть: обязательная ветка, таймер, выход за условием «2 из 3», а не полный обход. У каждой ветки награда, которую позже прочитают (`ashwell-standard-patterns:PAT-10`, `sheldon-character-storytelling:P-11`, `dille-ultimate-guide:P-09`, `nicklin-writing-for-games:P-10`).
  7. **Узлы с несколькими входами** защищены: `{ - … - else: }` по тому, что игрок мог узнать по дороге; узкие условия первыми (`inkle-ingold:PAT-03`, `procedural-storytelling:PAT-07`, `emshort-structures:PAT-08`).
  8. **Паузы.** Перед паузой от 15m персонаж называет причину, срок возвращения не называет (отменено `superseded.md` A-01: было «от 3h — ещё и время», `serial-hooks:P-05`, `RED-08`). Пауза стоит после события и реакции на него, а не после анонса (`serial-hooks:P-03`). Первая реплика после паузы повторяет деталь крючка и добавляет новость (`attention-today:P-06`).
  9. **Конец главы:** крючок-разворот, то есть вопрос, вложение или новый голос. Закрывающая реплика стоит раньше, после неё «спокойной ночи» нет (`yorke-into-the-woods:PAT-05`, `chat-fiction-apps:чек-лист §2`).
  10. **Проза.** Заглушки заменить репликами: одна мысль на сообщение, до 90 знаков, кроме скриншотов и документов (`attention-today:P-02`, `chat-fiction-apps:P-16`). В каждой цепочке из трёх входящих есть цифра, имя, предмет или `#photo` (`cron-wired-for-story:P-11`). `#sys` описывает поведение, а не чувства (`nicklin-writing-for-games:P-05`).
  11. **Если главу генерирует модель:** опись (1–2 образцовые сцены из наших историй, три обязательных свойства, запреты) → три варианта → отсев проверками → остаётся вариант, на котором проверки молчат (`procedural-storytelling:чек-лист §2а`, `P-17`).
  12. **Самопроверка:** `check:story` → `story:vars` (переменные главы читаются в этой или следующей главе) → `story:sessions --until chN+1` → `S-04`, если это глава 1 → `S-05` и `S-06` по главе.
- **Знания:** `docs/playbook/rules.md` §2–§6; `docs/playbook/checks.md` (первая волна); `docs/books/chat-fiction-apps/checklists.md §2`; `choiceofgames-design/checklists.md §2`; `inkle-ingold/checklists.md §2`; `serial-hooks/checklists.md §2`; `yorke-into-the-woods/checklists.md §2, §5`; `procedural-storytelling/checklists.md §2а`; `emshort-structures/patterns.md` (PAT-01…PAT-11 — каталог сцен).
- **Готово, когда:**
  - `check:story` — 0 тупиков;
  - серия входящих без кнопки ≤ 12 в главе 1 и ≤ 15 дальше (`attention-today:§4`);
  - начиная со второй главы есть условная кнопка `* {x}` (`inkle-ingold:P-09`) и хотя бы одна строка-эхо;
  - нет кнопок с одинаковым ответом;
  - у каждой паузы ≥ 1h есть причина до и новость после;
  - последние 3 строки главы — открытый вопрос;
  - `S-05` и `S-06` по главе не дают ошибок.

## 3. Ревью

### S-04. `story-opening` — первые 30 секунд, 3 минуты, глава 1

- **Когда:** «начало не цепляет», «проверь начало», «первая глава скучная», «ревью первой сцены», «перепиши начало».
- **Слито из:** `cron-wired-for-story:/story-opening`, `inkle-ingold:/story-opening`, `messenger-genre:/story-opening`, `skolnick-video-game-storytelling:/story-opening`, `edgerton-hooked:/hook-review`, `/opening-draft`, `mckee-story:/opening-check`, `video-three-things:/opening-audit`, `chat-fiction-apps:/opening-screenshot`, `choiceofgames-design:/first-minutes`, `narrative-testing:/first-minutes`. Это одиннадцать источников: тема самая частая в базе.
- **Вход:** история; режим `review` (по умолчанию) или `draft` (написать варианты).
- **Выход (`review`):** таблица метрик по каждому маршруту главы 1, вердикты холодного читателя, таблица `флаг · узел · строка · правка`, отсортированная по месту в сценарии, и до трёх правок с готовым ink. **Выход (`draft`):** три варианта первой сцены из разных семейств инцидентов (`edgerton-hooked:PAT-05`). У каждого варианта строка «инцидент / поверхностная / глубинная / ось» и пометка, какой порог он задевает.
- **Алгоритм (`review`):**
  1. `story:trace --until ch2` по всем маршрутам главы 1. Их мало, поэтому полный перебор (`narrative-testing:/first-minutes`).
  2. **Метрики** по каждому маршруту:
     - номер входящего и секунды до первой кнопки;
     - новые имена до первой кнопки;
     - новые сущности в первых 15 входящих, кроме ядра;
     - номер входящего, где впервые названы цель, ставка и срок;
     - доля прогонов, проходящих через узел со ставкой;
     - первая пауза ≥ 1h и строка перед ней;
     - число собеседников в первой сцене.
  3. **Три вопроса первого экрана** («кто пишет», «чего хочет», «к какому сроку») — `S-00 opening`. Отдельно `S-00 core`: перегружено ли начало (`video-three-things`).
  4. **Первая развилка:** у каждой кнопки можно назвать отношение одним словом, и отношения не повторяются (`edgerton-hooked:P-09`). Нет ветки, после которой игрок не знает главного факта (`edgerton-hooked:RED-06`). Есть отказ или «промолчать» с реакцией (`narrative-testing:GREEN-08`, `RED-24`, `inkle-ingold:PAT-05`). Хотя бы один из трёх первых выборов меняет текст в ближайших 5 сообщениях (`inkle-ingold:чек-лист §1`).
  5. **Монолог предыстории** в начале → ремонт `F-04`.
  6. **Карточка против текста:** `synopsis` не пересказывает инцидент (`edgerton-hooked:RED-10`), цифры и имена совпадают с первой главой (`video-three-things:RED-08`, `cron-wired-for-story:чек-лист §1`).
  7. **Первое сообщение** работает как превью уведомления: аномалия или обращение, а не приветствие (`edgerton-hooked:P-10`).
  8. **Конец главы 1** проверить отдельно: хвост-крючок на каждой ветке (`edgerton-hooked:LESSON-05`). Стык 1→2 не длиннее медианы межглавных пауз и ≤ 2h (`yorke-into-the-woods:RED-14`).
- **Пороги** (согласованы с `attention-today:§2, §4`):

| метрика | цель | предупреждение | ошибка |
|---|---|---|---|
| первая кнопка | ≤ 5 входящих и ≤ 30 с | > 6 входящих или > 60 с | — |
| новые имена до первой кнопки | ≤ 3 | 4 | — |
| цель, ставка, срок | ≤ 10-го входящего на каждом маршруте | — | только в ветке |
| узел со ставкой | 100% прогонов | < 100% | < 90% |
| собеседников до первой кнопки | 1 | ≥ 2 | — |
| новых сущностей не из ядра в первых 15 | ≤ 7 | > 7 | — |

- **Знания:** `docs/playbook/rules.md` §2; `docs/books/attention-today/attention.md §2`; `edgerton-hooked/checklists.md §2–4`; `video-three-things/checklists.md` («Ревью начала»); `cron-wired-for-story/patterns.md PAT-01`; `messenger-genre/patterns.md PAT-01, PAT-02`; `skolnick-video-game-storytelling/patterns.md PAT-08`.
- **Готово, когда:** таблица метрик заполнена по всем маршрутам главы 1; ни одной ошибки по порогам; `S-00 opening` дал три ответа; у каждой находки есть узел и правка.
- **Спорное и решение:**
  - *Первая кнопка.* Порог «6-я строка» (`chat-fiction`, `skolnick`) и «8-я» (`schell`, `video`, `narrative-testing`) против «5 входящих и 30 с» (`attention-today`, `messenger-genre:P-04`). **Берём 5 и 30 с как цель:** около 40% запусков приложений короче 15 с, и 30 секунд — всё, что часть игроков увидит (`attention-today:§2`). Предупреждение — больше 6 входящих или 60 с, как в `rules.md` R-13 и `checks.md` C-20.
  - *Сколько обязанностей у начала.* `choiceofgames-design:P-16` требует много (мир, роль, тон, правила), `edgerton-hooked:P-05` и `cron-wired-for-story:P-02` — минимум завязки. **Решение `choiceofgames-design:§10`:** обязанности распределяются на всю главу 1, а первый экран держит только три ответа и несоответствие.

### S-05. `story-pace` — скучные и перегруженные места

- **Когда:** «где скучно», «середина провисает», «читается ровно», «слишком много всего», «запутанно», «кто все эти люди», «глава тянется», «перегружено».
- **Слито из:**
  - скука: `inkle-ingold:/story-pace`, `maass-fire-in-fiction:/tension-pass`, `/scene-cut`, `cron-wired-for-story:/story-and-so`, `mckee-story:/scene-turn`, `/beat-gap`, `nicklin-writing-for-games:/verb-pass`, `schell-art-of-game-design:/interest-curve`, `yorke-into-the-woods:/midpoint`, `procedural-storytelling:/story-variety`, `skolnick-video-game-storytelling:/story-acts`;
  - перегруз: `attention-today:/attention-audit`, `/name-ledger`, `bateman-game-writing:/glossary-check`, `video-three-things:/moose-check`.
- **Вход:** история, по желанию номер главы.
- **Выход:** таблица узлов с метриками и суммой превышений; три худших места с приёмом ремонта и готовым ink; таблица имён и терминов; кривая интереса по главам.
- **Алгоритм:**
  1. `story:trace` (400 прогонов) и `story:sessions`.
  2. **Метрики скуки** по узлам:
     - самая длинная серия входящих без кнопки;
     - монолог одного контакта о прошлом;
     - разрыв между новыми фактами (≤ 5 реплик, `attention-today:P-12`);
     - доля кнопок с одинаковым ответом (`inkle-ingold:RED-02`);
     - доля пустых `#silent`;
     - повторы строк, которые видно дважды (`inkle-ingold:P-11`);
     - узлы, где все кнопки сходятся и не меняют переменных (`schell-art-of-game-design:RED-09`);
     - доля общих сообщений у 20 случайных прохождений: медиана выше 0,8 значит, что выборы не меняют текст (`procedural-storytelling:A11`).
  3. **Поворот сцены.** Для каждого узла с `#from` одна строка «что изменилось: знание / отношение / положение / ставка» (`cron-wired-for-story:/story-and-so`). Если до и после одно и то же — это nonevent (`mckee-story:RED-02`). Трёх одинаковых концов сцен подряд быть не должно (`mckee-story:RED-07`). Для кандидатов — три вопроса `maass-fire-in-fiction:P-07`: что меняется, в какой реплике, как изменился собеседник. Вердикт: оставить / слить с соседним узлом (показать перенаправление `->`) / вырезать / дописать поворот (`maass-fire-in-fiction:/scene-cut`).
  4. **Микронапряжение** в очередях между кнопками: коды `Q` (открыт вопрос), `C` (два чувства), `G` (зазор слов и поступков), `F` (трение), `T` (угроза или срок), `S` (сдвиг понимания). Очередь без Q, C, G и F плоская, даже если в ней есть T. Больше трети плоских очередей — узел на переписку целиком (`maass-fire-in-fiction:чек-лист §5`). Это делает модель, по главе.
  5. **Кривая интереса** по главам: окна по 5 сообщений, пик в последней трети каждой сессии, высший пик в последней главе, рост к финалу (`schell-art-of-game-design:/interest-curve`, `PAT-01`, `RED-07`). **Середина:** где она по доле пути, меняются ли после неё цель и адресаты игрока, растёт ли доля отказов мира (`yorke-into-the-woods:/midpoint`, `GREEN-02`, `P-05`).
  6. **Метрики перегруза:**
     - новые имена, места и понятия за сцену и в одном сообщении;
     - новые чаты за сцену и активные чаты в главе 1;
     - длина сообщения;
     - формы имени одного человека без связки (`attention-today:RED-06`, `/name-ledger`);
     - термины без объяснения рядом, по таблице «термин → первое упоминание → доля прогонов → объяснён ли» (`bateman-game-writing:/glossary-check`, `RED-01`);
     - «лоси» — новые контакты, правила и силы в последней трети без моста к ядру (`video-three-things:/moose-check`, `RED-06`).
  7. **Сортировка** узлов по сумме превышений. Для трёх худших — приём: `F-04` (монолог), `F-05` (экспозиция в спор), `F-06` (хаб вместо коридора), разрез кнопкой, вставка второго чувства (`maass-fire-in-fiction:P-01`), глагол блока (`nicklin-writing-for-games:PAT-02`).
  8. Для мест, где модель не уверена, — `S-00 next`. Одна очевидная версия или «всё равно» означает кандидата на правку.
- **Пороги** (`attention-today:§4`, где не сказано иное; почти все — **наша оценка** источника):

| что | порог |
|---|---|
| серия без кнопки | ≤ 8 в главе 1 и после паузы, ≤ 12 дальше; > 25 — ошибка |
| монолог одного контакта | ≤ 5 входящих подряд, о прошлом — ≤ 3 (`rules.md` R-19, R-61; `maass-fire-in-fiction:RED-02`, `sheldon-character-storytelling:P-13`) |
| разрыв между новыми фактами | ≤ 5 реплик |
| кнопки с одинаковым ответом | ≤ 20% в главе (`inkle-ingold:RED-02`) |
| новые имена и понятия | ≤ 3 за сцену, ≤ 2 в сообщении |
| новые чаты | ≤ 1 за сцену, ≤ 3 активных в главе 1 |
| длина сообщения | ≤ 90 знаков, доля длиннее — ≤ 5 % главы; > 140 — предупреждение, > 160 — ошибка; медиана ≤ 40 (C-34) |
| плоские очереди в узле | ≤ 1/3 (`maass-fire-in-fiction:чек-лист §5`) |

- **Знания:** `docs/playbook/rules.md` §5, §6, §9; `docs/books/attention-today/attention.md §4`; `maass-fire-in-fiction/checklists.md §3, §5`; `mckee-story/checklists.md §3`; `inkle-ingold/checklists.md §3`; `schell-art-of-game-design/patterns.md PAT-01`; `yorke-into-the-woods/checklists.md §3`; `video-three-things/checklists.md` («Ревью всего сценария»).
- **Готово, когда:** у каждого узла главы есть строка «что изменилось»; топ-3 мест с правкой; таблица имён без форм без связки; ни одной ошибки по порогам; в отчёте разделены «скучно» и «перегружено».
- **Спорное и решение:**
  - *Длина серии без кнопки.* Пороги от 5 (`skolnick-video-game-storytelling:RED-09`) и 6 (`bateman-game-writing:P-10`) до 25 как ошибки (`narrative-testing:RED-06`, `mobile-interactive-stories:P-11`). **Берём 8 / 12 / 25, как `rules.md` R-61 и `checks.md` C-35.** Ритм `inkle-ingold:P-01` (кнопка раз в 80–100 слов при 5–6 словах на реплику) даёт около 15 реплик, но в реальном времени каждая стоит анимации набора. Порог 5 оставляем для монолога одного контакта: там скука наступает раньше.
  - *Чем чинить скучную сцену.* Поднять событие, то есть риск и угрозу (`schell-art-of-game-design:P-06`), или чувства собеседника (`maass-fire-in-fiction:P-02`). **Решение `schell-art-of-game-design:§6`:** сначала подача и близость (второе чувство, зазор), и только если узел остаётся без поворота — событие.

### S-06. `pause-audit` — паузы, крючки, возвращение

> Отменено решениями автора (`superseded.md` A-01, A-02): проверки «время возвращения названо», «срок совпадает с `#delay`» и всё про ночь игрока. Скилл заменён `story-pauses` + `story-time` (`build-plan.md` §14).

- **Когда:** «тестеры не возвращаются», «проверь паузы», «крючки», «что игрок видит после паузы», «главы рвутся», «слишком долго ждать».
- **Слито из:** `serial-hooks:/pause-audit`, `/hook-pass`, `/recap-line`, `/session-merge`, `chat-fiction-apps:/session-map`, `/hook-before-pause`, `/hook-ledger`, `choiceofgames-design:/pause-audit`, `messenger-genre:/story-pacing`, `schell-art-of-game-design:/hook-audit`, `mobile-interactive-stories:/story-hooks`, `yorke-into-the-woods:/pause-map`, `/chapter-ends`, `snyder-save-the-cat:/pause-audit`.
- **Вход:** история, по желанию глава.
- **Выход:** таблица `K-03` с вердиктом по каждой паузе (флаг или «ок»); карта крючков главы по типам; пары «крючок → первая реплика после» с пометками «сбылся / ложный / нет крючка»; три самые важные правки.
- **Алгоритм:**
  1. `story:sessions`.
  2. **Перед паузой ≥ 30m:**
     - последняя реплика — вопрос или обещание факта, а не прощание, статус или полуданная инструкция (`serial-hooks:RED-01`, `attention-today:P-13`);
     - причина паузы названа персонажем, срока возвращения нет (A-01; было «у пауз ≥ 3h — ещё и время», `serial-hooks:RED-06`, `messenger-genre:P-01`);
     - нет анонса без содержания вида «надо кое-что сказать» (`serial-hooks:RED-02`);
     - пауза не стоит сразу после ответа игрока на закрытой реплике (`chat-fiction-apps:RED-02`).
  3. **После паузы:**
     - первая реплика — новость или имя, не служебное слово (`choiceofgames-design:RED-18`, `schell-art-of-game-design:RED-02`);
     - она повторяет деталь крючка и добавляет новую (`attention-today:P-06`);
     - кнопка — в пределах 5 сообщений, после паузы от 6h — 3 (`rules.md` R-72, `checks.md` C-28);
     - сессия — от 6 сообщений и с кнопкой (`serial-hooks:RED-05`);
     - возврат не отменяет крючок фразами «показалось», «шучу» (`serial-hooks:RED-03`);
     - первые 3 слова повторяются не больше 2 раз за историю (`attention-today:LESSON-07`).
     Каждую первую реплику проверить `S-00 return`.
  4. **События за паузой:** у `#unlock`, `#rename`, `#photo` после паузы ≥ 3h есть зацепка до неё — не пустой анонс, а факт, который об этом событии намекает (`chat-fiction-apps:RED-04`).
  5. **Карта крючков** по `// крючок:` или по тексту: не больше двух одинаковых подряд, жёстких не больше половины (`serial-hooks:RED-04`, `PAT-08`). Нет трёх глав подряд с одним видом крючка (`snyder-save-the-cat:LESSON-04`).
  6. **Стыки глав:** последнее входящее, пауза, «разворот / закрытие», первые 3 входящих следующей главы, окупается ли крючок (`yorke-into-the-woods:/chapter-ends`).
  7. **Ритм:** доля микросессий (≤ 3 строк без кнопки) < 10%, доля крючков перед паузами ≥ 1h ≥ 70% (`chat-fiction-apps:GREEN-02`, `RED-01`). Две длинные паузы подряд без кнопки — предупреждение, три — ошибка (`attention-today:§4`).
  8. **Реальное время:**
     - в главе 1 паузы ≤ 2h, кроме ночной в конце (`serial-hooks:P-12`);
     - пауза > 24h — ошибка (`serial-hooks:RED-07`);
     - сумма пауз на медианном пути ≤ 48h (`rules.md` R-67, `checks.md` C-31; `yorke-into-the-woods:RED-16` допускает 72h);
     - «спокойной ночи» → «доброе» ≥ 5h (`messenger-genre:RED-13`);
     - ~~названный срок расходится с `#delay` не больше чем вдвое~~ — отменено A-01: срок не называется (`serial-hooks:RED-08`);
     - медиана пауз кульминации не больше медианы средних глав (`serial-hooks:RED-14`);
     - срок в днях стоит в карточке, если паузы длинные (`chat-fiction-apps:RED-09`).
  9. **Правки** через ремонты `F-01` (крючок), `F-02` (рекап), `F-03` (склейка сессий).
- **Знания:** `docs/playbook/rules.md` §5; `docs/books/serial-hooks/{principles,patterns,flags,checklists}.md`; `attention-today/attention.md §3`; `chat-fiction-apps/checklists.md §3`; `choiceofgames-design/checklists.md §5`; `yorke-into-the-woods/checklists.md §5`; `messenger-genre/checklists.md §3`.
- **Готово, когда:** у каждой паузы ≥ 30m есть вердикт; ноль ошибок (> 24h, три пустые паузы подряд, сессия после паузы без кнопки); доля крючков ≥ 70%; каждая предложенная правка не меняет переменных и переходов (`serial-hooks:/hook-pass`).
- **Спорное и решение:** «крючок до паузы» (`chat-fiction-apps:P-03`) против «пауза после события» (`serial-hooks:P-03`). **Это одно правило:** событие и реакция идут до паузы, а пауза стоит на последствии. Запрещён только пустой анонс. Схема `chuzhoy-golos` «закрытие → 7h → крючок» работает только при уведомлениях, а их у нас нет, так что её нужно чинить (`yorke-into-the-woods:§7`).

### S-07. `choice-audit` — ощущается ли выбор

- **Когда:** «выбор не ощущается», «граф линейный», «ничего не решаю», «кнопки ни на что не влияют», «проверь развилки».
- **Слито из:** `choiceofgames-design:/choice-audit`, `meaningful-choice:/choice-audit`, `mobile-interactive-stories:/choice-audit`, `emshort-structures:/choice-weight`, `bateman-game-writing:/choice-weight`, `messenger-genre:/story-choices`, `skolnick-video-game-storytelling:/story-agency`, `procedural-storytelling:/story-consequences`, `narrative-postmortems:/choice-balance`, `ashwell-standard-patterns:/story-structure`, `mckee-story:/beat-gap`, `dille-ultimate-guide:/story-resources`.
- **Вход:** история, по желанию глава.
- **Выход:** таблица развилок `узел · тип · что даёт и отнимает каждая кнопка · флаги · правка`; доли типов по главам; таблица `K-02`; по 3 места на главу, где окраску стоит превратить в выбор.
- **Алгоритм:**
  1. `npm run graph`, `story:vars`, `check:story` с `K-04`.
  2. **Тип каждой кнопки:** окраска (своя реплика) / пустая (общий ответ) / переменная / узел / другой чат (`bateman-game-writing:P-02`, `emshort-structures:RED-11`). **Тип развилки:** фальшивая, устанавливающая, проверочная, на цель, сюжетная, кульминационная (`choiceofgames-design:P-20`, S13–S15). Фальшивая на решении, а не на эмоции, — `choiceofgames-design:RED-05`. Устанавливающие после главы 2 и проверочные в главе 1 пересмотреть.
  3. **Структура:** доля ствола (узлы с ≥ 99% визитов к числу всех узлов). Доля > 60% при < 2 развилках, которые расходятся и снова сходятся, — `ashwell-standard-patterns:RED-01`. Серии из 3+ пустых развилок подряд (`ashwell-standard-patterns:P-09`). Ветвление растёт к финалу (`emshort-structures:RED-06`). На главу приходится 1–4 узла, где кнопки расходятся (`mobile-interactive-stories:RED-07`).
  4. **Четыре компонента осмысленного выбора** (`meaningful-choice`, Morrison):
     - *осознанность:* до кнопки есть улика или названная ставка (`messenger-genre:RED-05`, `vogler-writers-journey:LESSON-07`);
     - *последствие:* ветка оставляет след после схождения (`meaningful-choice:RED-03`);
     - *напоминание:* переменная звучит до финала (`K-02`, `inkle-ingold:P-06`);
     - *необратимость:* нет отмены выбора условием (`mobile-interactive-stories:RED-01`).
  5. **Сюрпризы и лёгкие выборы:** у веток с `-=` и к худшим финалам есть сигнал до кнопки (`choiceofgames-design:RED-01`, `RED-02`); у развилок, меняющих состояние, нет очевидно лучшего варианта (`choiceofgames-design:RED-03`); у кнопки < 1% выборов или выбранной > 85% живыми людьми — тоже (`meaningful-choice:P-04`, `skolnick-video-game-storytelling:RED-10`).
  6. **Отказы и молчание:** каждый отказ ведёт к новой реплике и пишет переменную (`inkle-ingold:RED-08`, `skolnick-video-game-storytelling:RED-04`); `#silent` получает реакцию и не закрывает историю сразу (`attention-today:RED-07`); упрёки и благодарности стоят под условием (`skolnick-video-game-storytelling:RED-08`, `messenger-genre:RED-06`); ключевой вывод делает кнопка игрока, а не `#me:` (`sheldon-character-storytelling:P-10`, `RED-08`).
  7. **Выбор между людьми:** у кандидатов сравнить число сообщений, просьб и уязвимостей до развилки. Перекос больше 2:1 — `narrative-postmortems:RED-05`, нужна сцена отстающему (`PAT-07`).
  8. **Кнопки-улики:** каждая кнопка, называющая факт, стоит под условием его записи (`inkle-ingold:RED-05`).
  9. Для 3–5 ключевых кнопок — `S-00 next` (`maass-fire-in-fiction:/what-next`).
  10. **Правки** через `F-07` (оживить кнопку), `F-08` (эхо и колбэки), `F-09` (показать порог), `F-06` (хаб), `F-11` (развилка в горлышке).
- **Пороги:** косметические кнопки > 50% главы — предупреждение (`checks.md` C-10; у `emshort-structures:RED-11` — 35%, у `bateman-game-writing:чек-лист §3` — 40%, у `narrative-testing:RED-02` — 60%); пустые кнопки > 20% — предупреждение (`inkle-ingold:RED-02`); условная кнопка показана 10–60% раз (`mobile-interactive-stories:GREEN-05`).
- **Знания:** `docs/playbook/rules.md` §4; `docs/books/meaningful-choice/{flags,patterns}.md`; `choiceofgames-design/checklists.md §3`; `emshort-structures/patterns.md`; `ashwell-standard-patterns/patterns.md` (таблица структур); `skolnick-video-game-storytelling/checklists.md §3`.
- **Готово, когда:** у каждой развилки есть тип; в каждой главе после первой есть развилка, где кнопки расходятся, и чтение переменной из прошлой главы; нет мёртвых переменных без решения «удалить / оплатить»; по каждой главе 3 предложения с ink.
- **Спорное и решение:** окраска — брак (`bateman-game-writing:P-02`) или норма (`narrative-postmortems:P-04`)? **Решение `narrative-postmortems:§6`:** окраска допустима, если ответ на каждую кнопку свой. Брак — общий ответ. Поэтому скилл считает пустые кнопки отдельно от окрасок.

### S-08. `story-endings` — финалы

- **Когда:** «проверь финалы», «финал не заработан», «все попадают в одну концовку», «перед последней главой», «распиши финальную развилку».
- **Слито из:** `ashwell-standard-patterns:/story-endings`, `messenger-genre:/story-endings`, `emshort-structures:/endings-map`, `choiceofgames-design:/ending-matrix`, `snyder-save-the-cat:/finale`, `schell-art-of-game-design:/shorten-resolution`, `meaningful-choice:/finale-recap`, `failbetter-qbn:/reveal-thresholds`, `yorke-into-the-woods:/mirror`.
- **Вход:** история.
- **Выход:** формула распределителя; таблица «цель × исход»; доля каждого финала (`K-04`); для каждой переменной в условии — где она набирается и где звучит вслух; длина развязки; рифма с началом.
- **Алгоритм:**
  1. Найти маршрутизатор: узлы, ведущие в `-> END`. Разобрать условия, у каждого должен быть `else` (`emshort-structures:PAT-06`).
  2. **Формула:** в условиях есть и последняя кнопка, и ранние оси (`ashwell-standard-patterns:GREEN-05`). Ни один финал не выбирается только скрытой проверкой без видимой кнопки и реплики-ссылки (`mckee-story:RED-10`).
  3. **Видимость порогов:** каждая переменная условия хотя бы раз названа игроку до развилки (`emshort-structures:RED-02`, `failbetter-qbn:RED-01`, `narrative-postmortems:RED-07`). Если не названа — `F-09`. Если финал решает скрытая проверка, перед ним стоит узел-сводка (`meaningful-choice:PAT-07`, `F-10`).
  4. **Доли:** ни один финал не берёт > 50%; финал < 2% — подсказка «проверь целенаправленной игрой», 0% — предупреждение (C-15, C-40) (`ashwell-standard-patterns:GREEN-07`, `snyder-save-the-cat:чек-лист §4`). Если финал > 50%, проверить, не ведёт ли к нему `#silent` (так `fin_revenge` в «Чужом голосе», `inkle-ingold:чек-лист §4`). Меньше 20% прогонов кончаются до последней главы (`narrative-testing:RED-13`). Ни один финал не раньше 30% медианной длины (`emshort-structures:RED-08`).
  5. **Каждый финал объясняет себя:** называет конкретный прошлый поступок игрока условной репликой (`cron-wired-for-story:RED-20`, `sheldon-character-storytelling:чек-лист`, `narrative-testing:RED-25`). Нет «я понял(а), что» (`truby-anatomy-of-story:RED-09`). Нет ярлыков «хорошая / плохая концовка» (`messenger-genre:P-15`). Финал не подан как награда за «правильные» ответы (`nicklin-writing-for-games:P-16`).
  6. **Развязка:** после последней кнопки ≤ 10 сообщений и ≤ 15 минут пауз (`schell-art-of-game-design:RED-03`, `messenger-genre:RED-09`). Перед `END` нет новых `#unlock` и неотвеченных вопросов (`serial-hooks:RED-12`). Последнее сообщение — носитель финала: `#photo`, перевод, новый контакт, системная строка (`messenger-genre:P-14`). Если длинно — `F-12`.
  7. **Рифма:** первые 10 входящих рядом с последними 5 каждого финала. Деталь первой сцены или перемена у ≥ 3 контактов (`yorke-into-the-woods:PAT-04`, `vogler-writers-journey:чек-лист §3`, `truby-anatomy-of-story:GREEN-08`).
  8. **Проверка краёв:** в отладке выставить крайние значения счётчиков и ничью; каждый финал выпадает при ожидаемой комбинации (`emshort-structures:чек-лист §4`). Сыграть «на грани»: на единицу ниже порога и на пороге (`failbetter-qbn:чек-лист §4`).
- **Знания:** `docs/playbook/rules.md` §8; `docs/books/ashwell-standard-patterns/flags.md`; `choiceofgames-design/checklists.md §3–4`; `emshort-structures/patterns.md PAT-06`; `messenger-genre/principles.md P-14–P-16`; `schell-art-of-game-design/flags.md`.
- **Готово, когда:** все финалы > 0% и ни один не > 50%; у каждой переменной условия есть реплика до развилки; в каждом финале есть строка про решение игрока; развязка ≤ 10 сообщений.
- **Спорное и решение:** нижний порог доли финала — 1% (`cron`), 2% (`choiceofgames`, `mobile`, `failbetter`), 3% (`ashwell`, `snyder`), 5% (`emshort`, `inkle`). **Берём 2% как подсказку и 0% как предупреждение, как `checks.md` C-40 и C-15.** Бот кликает случайно, поэтому редкий финал, который нужно заработать, — не всегда ошибка (`choiceofgames-design:RED-08`). Предупреждение снимается видимыми ступенями к финалу (`narrative-testing:GREEN-07`).

### S-09. `clue-audit` — загадка и улики

- **Когда:** «проверь загадку», «честная ли разгадка», «улики», «игрок не может догадаться», «слишком очевидно», «кто убийца угадывается сразу», «подводки и выстрелы».
- **Слито из:** `mystery-fair-play:/clue-audit`, `/reveal-check`, `cron-wired-for-story:/story-setup-payoff`, `truby-anatomy-of-story:/reveal-ladder`, `sheldon-character-storytelling:/promise-ledger`, `dille-ultimate-guide:/story-bible-check`, `maass-fire-in-fiction:чек-лист §3` (два намёка и последствие), `mckee-story:чек-лист §3` (тайны), `narrative-testing:чек-лист §3` (хронология), `vogler-writers-journey:/mask-audit` (улика раньше смены маски).
- **Вход:** история; по желанию — узел одной разгадки (режим `reveal`).
- **Выход:** таблица `откровение · улики (узел, контакт, форма, ствол/ветка) · доля прогонов с ≥ 2 уликами · приманки и опровержения`; таблица «подводка → выстрел → доля прогонов, где сработало»; реестр обещаний; флаги с узлами.
- **Алгоритм:**
  1. **Список откровений.** Прочитать `// reveal:`, `// culprit:`, `// truth:`. Если разметки нет, восстановить откровения по тексту, не глядя в план, и предложить разметку. Если восстановленный список не совпал с планом, текст и план разошлись (`mystery-fair-play:чек-лист §3`).
  2. **Улики на откровение:** ≥ 3 в разных чатах и формах (`mystery-fair-play:P-06`, `P-07`). Обязательные — на стволе или во всех ветках (`mystery-fair-play:P-08`). На самом бедном пути (`K-01 --persona silent` и выбор «не знаю») ≥ 2 улики к каждой разгадке (`mystery-fair-play:чек-лист §4`). Улика не приходит в узле разгадки и опережает его хотя бы на один выбор (`mystery-fair-play:RED-03`). Улику видит ≥ 60% прогонов, а ключевое раскрытие ≥ 90% (`video-three-things:чек-лист`, `truby-anatomy-of-story:чек-лист §5`). После каждой улики стоит `~ clue_x = true`.
  3. **Кто делает вывод:** игрок кнопкой-воротами, а не NPC (`mystery-fair-play:RED-02`, `PAT-02`). Варианты ворот уравнены: верный не длиннее остальных больше чем в 1,5 раза. У неверных есть опровержение и цена (`mystery-fair-play:GREEN-05`). Перед разгадкой — короткая пауза на размышление и вопрос от NPC (`mystery-fair-play:P-13`). В реплике разгадки ссылки на 2 улики стоят под `{clue_x:}` (`mystery-fair-play:PAT-06`).
  4. **Виновник** появляется в первой трети (`mystery-fair-play:RED-04`). Скрытый противник выдан хотя бы одной уликой в стволе (`truby-anatomy-of-story:RED-07`). Улика стоит раньше смены маски (`vogler-writers-journey:P-09`).
  5. **Приманки** имеют опровержение (`mystery-fair-play:RED-05`). Ложь честного контакта без опровержения — `mystery-fair-play:RED-09`.
  6. **Механизмы и термины** разгадки объяснены раньше неё (`mystery-fair-play:P-11`, `RED-12`). Финал не опирается на факт, которого не было до последней главы (`dille-ultimate-guide:LESSON-01`).
  7. **Подводки и выстрелы:** каждая `note_*` и прочие флаги где-то читаются (`cron-wired-for-story:RED-07`). Подводка в узле < 5% визитов — `cron-wired-for-story:RED-14`. Каждое обещание последствия («если …, то …») и каждый срок, названный вслух, сыграны в каждом мире (`mckee-story:RED-11`, `sheldon-character-storytelling:RED-04`). У каждого раскрытия два намёка и последствие, и раскрытие не в той же сцене, что намёк (`maass-fire-in-fiction:P-11`, `mckee-story:RED-12`).
  8. **Хронология:** все времена, даты и суммы в репликах сверены с `// truth:`. Расхождение либо помечено `// lie:`, либо это ошибка (`dille-ultimate-guide:P-04`, `narrative-testing:RED-10`). Каждый факт, который персонаж называет, ему кто-то сообщил (`skolnick-video-game-storytelling:P-12`).
  9. **Риск у кнопок финала:** перед каждой кнопкой, меняющей переменную финала, есть реплика, из которой риск можно вывести (`mystery-fair-play:P-12`, `RED-07`).
  10. `S-00 guess` по узлу перед разгадкой. Если модель уверенно угадывает без опоры на улики — подсказки слишком явные. Если версий нет — улик мало. Живой порог 30–70% проверяется в `S-13`.
  11. Разбор после последнего выбора ≤ 15 строк (`mystery-fair-play:RED-10`).
- **Режим `reveal`:** только шаги 2, 3 и 9 для одного узла: какие улики к нему ведут и с какой долей прогонов, есть ли ворота и пауза, все ли ссылки под условием (`mystery-fair-play:/reveal-check`).
- **Знания:** `docs/playbook/rules.md` §7; `docs/books/mystery-fair-play/{principles,patterns,flags,checklists}.md`; `cron-wired-for-story/checklists.md §3`; `dille-ultimate-guide/checklists.md §1, §3`; `truby-anatomy-of-story/patterns.md PAT-02`; `maass-fire-in-fiction/checklists.md §1, §3`.
- **Готово, когда:** у каждого откровения ≥ 3 улики, из них ≥ 2 на бедном пути; нет улики в узле разгадки; у каждой приманки есть опровержение; хронология без расхождений; у каждой подводки есть выстрел или пометка «сознательно».
- **Спорное и решение:**
  - *Пауза перед разгадкой* (`mystery-fair-play:P-13`) против «не разрывай паузой нужное» (`attention-today:P-13`) и «после кульминации не заставляй ждать» (`messenger-genre:P-16`). **Решение:** пауза в секунды или минуты допустима, если все улики пришли до неё. Часы недопустимы (`attention-today:§6`, `chat-fiction-apps:§7`).
  - *Мерить правильность вывода или настойчивость* (`mystery-fair-play:P-05` против `emshort-structures:P-03`)? **Оба:** `solved` нужен для честности финала, счётчик настойчивости — для характера (`mystery-fair-play:§6`).

### S-10. `story-review` — ревью сценария (оркестратор)

- **Когда:** «сделай ревью», «проверь историю перед релизом», «что не так со сценарием», «готова ли история для тестеров», «посмотри всю историю».
- **Слито из:** `narrative-testing:/story-review` (два прохода и шесть списков QA), `narrative-postmortems:/postmortem-review`, `schell-art-of-game-design:/review-schell`, `truby-anatomy-of-story:/truby-review`, `snyder-save-the-cat:/beat-review`, `/board`, `ashwell-standard-patterns:/story-structure`, `skolnick-video-game-storytelling:/story-acts`, `vogler-writers-journey:/journey-map`, `mckee-story:/scene-turn` (линза), `dille-ultimate-guide:/story-bible-check`, `inkle-ingold:/story-coherence`, `procedural-storytelling:/story-merge-guard`.
- **Вход:** история; флаги `--quick` (только проход A и начало) и `--lens snyder|vogler|truby|mckee|yorke`.
- **Выход:** `docs/reviews/<id>-<дата>.md`: итог в трёх строках; таблица `флаг · узел · симптом · решение`; 3 сильных и 3 слабых места; правки по главам, не больше 7 на главу, отсортированные по влиянию и цене (в строках текста); список «нужен живой тест».
- **Алгоритм:**
  1. **Проход A — поломки** (бот и карта):
     - `check:story`: 0 неизвестных тегов, 0 тупиков, все узлы посещены, кроме `test_*`;
     - финалы по `K-04`;
     - узлы < 2% визитов, которые не финалы: решение «награда» или «упростить вход» (`narrative-testing:RED-11`);
     - дорогие редкие ветки: < 10% визитов при > 15 сообщениях (`ashwell-standard-patterns:RED-08`);
     - хороший путь не короче плохого больше чем вдвое (`ashwell-standard-patterns:RED-09`);
     - нет `->` в середину чужой главы (`bateman-game-writing:RED-10`);
     - глава не меньше 50% медианы по строкам (`narrative-postmortems:RED-09`).
  2. **Проход B — смысл.** Вызвать `S-04`, `S-05`, `S-06`, `S-07`, `S-08`, `S-12`, а для тайны ещё `S-09`. Добавить то, что эти скиллы не покрывают:
     - **узлы с несколькими входами:** кого игрок мог знать, нет «мы не знакомы» после знакомства (`inkle-ingold:RED-04`, `procedural-storytelling:PAT-07`) → ремонт `F-13`;
     - **обещания карточки:** у каждого пункта `features` есть узел, где он выполняется (`dille-ultimate-guide:RED-01`);
     - **герои:** у каждого основного персонажа есть точка смены состояния и её триггер (`procedural-storytelling:P-09`). Противник не пропадает на две главы подряд (`truby-anatomy-of-story:RED-06`). Антагонист ходит в ответ на успехи игрока (`yorke-into-the-woods:P-11`);
     - **вопрос главы:** у каждой главы есть «что она добавляет к главному вопросу», и вопрос закрыт внутри главы (`cron-wired-for-story:RED-16`, `yorke-into-the-woods:RED-19`);
     - **этика:** тяжёлые темы названы в `synopsis` или `features`, нет кнопок с похвалой (`nicklin-writing-for-games:P-16`);
     - **вымысел:** нет реальных имён и брендов (`procedural-storytelling:RED-13`, `CLAUDE.md`).
  3. **Шесть списков QA** (`narrative-testing:P-14`). Сдаются, даже если пустые: хронология и факты · голос · обрывы логики · пропущенные реплики · имена и `#rename` · орфография (весь текст ink выгрузить в файл и прогнать проверку; сленг голоса — в исключения).
  4. **Проход C — ощущение выбора:** для каждого финала найти строку про каждую переменную, которая к нему ведёт; кнопки-одиночки подряд; кнопки, которые различаются только словами (`narrative-testing:RED-25–27`).
  5. **Линзы** (только по флагу `--lens`; разметка показывается автору диффом комментариев):
     - `snyder`: 10 опорных битов, узел и доля входящих у каждого, сравнение с коридорами `PAT-02`, `B1–B4` (`snyder-save-the-cat:/beat-review`);
     - `vogler`: стадии, пропуски `call / ordeal / resurrection / elixir`, шаблонность 12 стадий подряд (`vogler-writers-journey:/journey-map`, `RED-01`); перед этим — фильтр «чей путь» (`vogler-writers-journey:RED-02`);
     - `truby`: таблица семи шагов, узел и охват каждого (`truby-anatomy-of-story:чек-лист §4`);
     - `mckee`: таблица сцен «ценность · знак до · знак после · чем повёрнуто» (`mckee-story:/scene-turn`);
     - `yorke`: опоры по медианному пути, отклонение от коридоров больше 10 п. п. (`yorke-into-the-woods:чек-лист §3`).
  6. **Фильтр формата:** выбросить советы, которые ломают многочатовость или реальное время. Например, «один герой — одна дуга» сверить с `snyder-save-the-cat:for-relayer §5` и `vogler-writers-journey:for-relayer §5`. Решения тестеров не копировать: каждая правка начинается с симптома (`narrative-testing:P-05`).
  7. Свести, отсортировать и записать отчёт.
- **Знания:** все `docs/playbook/*.md`; `docs/books/narrative-testing/checklists.md §3`; `narrative-postmortems/checklists.md §3`; разделы «Разбор наших историй» через `docs/playbook/story-findings.md`, чтобы не находить заново уже известное.
- **Готово, когда:** отчёт записан; проход A зелёный или каждая поломка в таблице; все шесть списков QA сданы; у каждой правки есть флаг, узел и симптом; правок на главу не больше 7.

## 4. Адаптация под короткое внимание

### S-11. `attention-adapt` — история для человека с телефоном

- **Когда:** «адаптируй под мобильного игрока», «сделай короче», «игроки бросают», «упрости для телефона», «слишком сложно», «сделай версию на 5 минут», «перегружено для короткого внимания».
- **Основа:** `attention-today/attention.md` целиком: минимальные версии P-01…P-14, точки 30 с / 3 мин / глава 1, возвращение, пороги нагрузки, тёмные паттерны. Плюс разделы `attention.md` других разборов там, где они уточняют пороги (`serial-hooks:P-12`, `yorke-into-the-woods:чек-лист §5`, `snyder-save-the-cat:чек-лист §5`, `vogler-writers-journey:чек-лист §5`).
- **Вход:** история; режим `audit` (по умолчанию) или `short` (сжать до истории на 5–15 минут).
- **Выход:** таблица «было → стало» по метрикам нагрузки и времени; патч ink, разбитый на независимые правки с подтверждением каждой; список «что не трогали, потому что это сюжет».
- **Алгоритм (`audit`)** — порядок важен: сначала то, что увидят все, потом то, что увидят вернувшиеся.
  1. **Замер.** `S-04` (метрики начала), `S-05` (только метрики перегруза), `S-06` (только возвращения). Свести в одну таблицу с порогами `attention-today:§4`.
  2. **К 30-й секунде:**
     - говорит один человек;
     - есть вопрос, понятный без имён;
     - первая кнопка не позже 5-го входящего, и она отвечает на прямой вопрос персонажа.
     Если не так — перенести контекст в ветки ответов (`messenger-genre:/story-opening`).
  3. **К 3-й минуте:**
     - 2–3 кнопки, одна чем-то отличается от соседних;
     - ≤ 3 названных людей и мест, лишние — в `#to:notes` или позже (`attention-today:PAT-02`, `PAT-03`);
     - названа ставка;
     - сессия кончается крючком-вопросом, пауза названа словами персонажа.
  4. **К концу главы 1:**
     - ≤ 5 человек по именам, о каждом игрок может сказать, чего тот хочет;
     - первая пауза ≥ 30m — после 3–5 выборов;
     - паузы ≤ 2h, кроме ночной;
     - есть внешняя память: запись в заметках или переименованный контакт (`attention-today:P-05`).
  5. **Возвращение:**
     - пачка до кнопки ≤ 5 сообщений: «многое случилось в паузе» — это одна сессия с кнопками, а не пять сообщений с часовыми паузами (`attention-today:PAT-08`);
     - первая реплика: деталь крючка плюс новость;
     - после паузы от 6h — ставка или срок и эхо выбора голосом персонажа (`F-02`, `rules.md` R-70);
     - формулы возврата не повторяются;
     - нет пустых пингов «ещё жду» (`attention-today:PAT-07`);
     - пауза не стоит посреди перечисления или инструкции (`P-13`).
  6. **Нагрузка по всей истории:**
     - сообщение — одна мысль до 90 знаков;
     - одна форма имени;
     - ≤ 3 новых сущностей за сцену;
     - ≤ 1 нового чата за сцену;
     - кнопки 2–3 по 2–6 слов;
     - «срочно» ≤ 2 раз на главу и только с настоящим событием (`attention-today:P-11`).
  7. **Тёмные паттерны** (обязательная проверка, правки не предлагаются, только снятие):
     - нет ложной срочности, где исход от неё не меняется;
     - нет сообщений «ты пропал» за неактивность — текст зависит только от выборов и сюжетного времени;
     - молчание не закрывает историю сразу, если соседние варианты ведут дальше;
     - кнопка ждёт вечно, «не успел» не хуже осознанного отказа (`attention-today:§5`, `RED-07`, `LESSON-11`).
  8. **Каждую правку проверить:** не удалила ли она улику или мотив (`attention-today:RED-10`). При конфликте правка отменяется, а сюжетная вещь переносится в другой узел, а не вырезается.
  9. `check:story`, затем повторить замер из шага 1 и записать «было → стало».
- **Режим `short`** — история на 5–15 минут:
  - работают шесть правил: одна мысль до 90 знаков (P-02); ≤ 3 новых имён до кнопки (P-03); кнопка в первые 30 с (P-07); что-то меняется каждые 3–5 реплик (P-12); упрощай подачу, а не сюжет (P-14); финал на вопросе (P-08) — так в `attention-today:§1`;
  - паузы ≥ 1h убрать, история идёт одной сессией (`chat-fiction-apps:P-15`);
  - каркас: три опоры (`yorke-into-the-woods:PAT-11`) или четыре стадии `call / threshold / ordeal / elixir` (`vogler-writers-journey:PAT-11`), 4 бита (`snyder-save-the-cat:чек-лист §5`);
  - из шапки остаются ядро, роль, ставка со сроком и вопрос (`S-01`, короткая форма).
- **Знания:** `docs/books/attention-today/{attention,principles,patterns,flags,checklists}.md`; разделы §2–§4 в `attention.md` всех разборов, которые вызывает шаг (точечно); `docs/playbook/rules.md` §2, §5; `docs/playbook/checks.md` (пороги нагрузки).
- **Готово, когда:**
  - по таблице «было → стало» ни одна метрика `attention-today:§4` не на уровне ошибки;
  - первые 30 секунд и 3 минуты выполнены на каждом маршруте главы 1;
  - ни одна правка не удалила улику или мотив (сверка с `S-09`, если есть тайна);
  - все пункты против тёмных паттернов чисты;
  - живой тест на 5 минут назначен (`narrative-testing:чек-лист §6`): один свежий человек без `?fast=1`, автор молчит.
- **Спорное и решение:**
  - *Сколько держит рабочая память, 3 или 4±1?* Берём 3: на ходу часть памяти уходит на окружение (`attention-today:§1`).
  - *Порог длины главы* сознательно не ставим: данных за «внимание кончается через N минут» нет (`attention-today:§4`, `LESSON-02`).
  - *Полифоническая завязка* (4–5 контактов сразу) для нашего игрока — пять нитей. Если она нужна сюжету, игрок отвечает одному-двум (`attention-today:§1`).

## 5. Голоса и живой тест

### S-12. `voice-check` — голоса и состав персонажей

- **Когда:** «голоса сливаются», «персонажи одинаковые», «плоские персонажи», «добавляю нового контакта», «злодея угадывают сразу», «лист голоса».
- **Слито из:** `nicklin-writing-for-games:/voice-sheet`, `/blind-voice`, `sheldon-character-storytelling:/voice-sheet`, `/cast-check`, `/conversation-cost`, `procedural-storytelling:/story-cast`, `truby-anatomy-of-story:/web`, `vogler-writers-journey:/mask-audit`, `snyder-save-the-cat:B15`.
- **Вход:** история; режим `audit` или `new <id> <роль>`.
- **Выход (`audit`):** таблица профилей по контактам (длина реплики, регистр, эмодзи, обращения, частые словечки), пары, которые сливаются, точность слепого теста по парам, матрица «контакт × глава → функция или маска», контакты без смены состояния, хабы-анкеты. **Выход (`new`):** лист голоса из 6 строк и проверочная сцена: одна новость голосом нового контакта и голосом ближайшего по профилю (`nicklin-writing-for-games:PAT-01`).
- **Алгоритм:**
  1. Собрать реплики по `#from:` (`K-01`), посчитать профиль (`sheldon-character-storytelling:P-05`, `nicklin-writing-for-games:RED-01`). У любых двух контактов совпадает не больше половины маркеров.
  2. Для подозрительных пар — `S-00 voice`. Пары ниже 8 из 10 идут в правки с признаком, которого не хватило.
  3. Прочитать подряд реплики одного контакта: нет строки, которую можно отдать другому без правки (`sheldon-character-storytelling:RED-05`). В ссоре регистр меняется (`maass-fire-in-fiction:RED-11`). Первые 10 сообщений и последняя глава звучат одним голосом (`edgerton-hooked:второй проход`).
  4. **Сеть:** позиция каждого NPC по главному вопросу; пары без конфликта; кандидаты на слияние (`truby-anatomy-of-story:/web`, `RED-11`). У каждого функция в `characters[].role`, у основных — действие-тег (`procedural-storytelling:P-07`, `RED-07`).
  5. **Маски по главам:** вестник, страж, наставник, союзник, оборотень, тень, трикстер. Хотя бы одна смена маски, улика раньше смены (`vogler-writers-journey:/mask-audit`, `P-09`). Не больше двух стражей «кто вы?» на 5 глав (`vogler-writers-journey:RED-08`).
  6. **Превращения:** у каждого персонажа с 20+ репликами есть смена состояния и её триггер (`procedural-storytelling:P-09`).
  7. **Хабы-анкеты:** узлы, которые возвращают в себя ≥ 3 варианта с одним `#to:`. Если их проходят целиком без последствий, нужна переменная терпения (`sheldon-character-storytelling:/conversation-cost`, `RED-09`, `PAT-08`).
  8. **Объём:** контакты меньше чем с 5 строками (`sheldon-character-storytelling:RED-03`) и меньше чем в 3 главах (`choiceofgames-design:RED-16`) — решить «дать глагол» или «убрать».
- **Знания:** `docs/playbook/rules.md` §6; `docs/books/nicklin-writing-for-games/{principles,patterns}.md`; `sheldon-character-storytelling/checklists.md`; `procedural-storytelling/principles.md P-05–P-09`; `vogler-writers-journey/for-relayer.md §3`.
- **Готово, когда:** все пары основных контактов ≥ 8 из 10 в слепом тесте; у каждого основного контакта есть функция, действие и смена состояния; нет хабов-анкет без цены.
- **Спорное и решение:** утрировать манеру (`procedural-storytelling:P-06`) или делать персонажа трёхмерным (`sheldon-character-storytelling:P-01`)? **Разделить слои** (`procedural-storytelling:§6`): манеру письма утрируем, её видно в каждой реплике; мотив и биография остаются многомерными и раскрываются поступками.

### S-13. `playtest` — живой тест: пакет и сводка

- **Когда:** «подготовь тест», «отправлю тестерам», «вот отзывы», «разбери фидбек», «тестер пишет, что …», «проведи разбор главы».
- **Слито из:** `narrative-testing:/playtest-kit`, `/playtest-digest`, `bateman-game-writing:/playtest-protocol`, `nicklin-writing-for-games:/critical-response`, `choiceofgames-design:/tester-feedback`, тест-процедуры §4 всех чек-листов.
- **Режим `kit` — вход:** история, известные проблемы, 1–3 вопроса автора. **Выход:**
  - записка тестеру: срок, вопросы, что не готово, известные баги, форма отзыва;
  - ссылка `?story=<id>&fresh=1`;
  - анкета 1–7 из 9 пунктов с переворотом отрицательных (`narrative-testing:чек-лист §4`);
  - для «ломателей» — список входов `test_*`;
  - лист из трёх вопросов после главы: «что происходит?», «чего ждёшь дальше?», «какой выбор был важным?» — без подсказок (`bateman-game-writing:чек-лист §4`).
- **Шаги `kit`:**
  1. Проверить, что ревью `S-10 --quick` пройдено: тестеров не тратим на то, что ловит бот (`narrative-testing:P-02`).
  2. Набор: 1–2 «ломателя» и 2–3 «обычных» (`narrative-testing:P-07`).
  3. «Обычным» запретить `?fast=1` и отладку минимум на главы 1–2 (`narrative-testing:P-17`).
  4. Вопросы автора переписать в нейтральные, без спрятанного мнения (`nicklin-writing-for-games:чек-лист §4`).
  5. Подставить комментарии `// застрянут:` и `// развилка:` как прогноз автора для сверки.
  6. Выбрать сценарии под историю:
     - ушёл на каждой длинной паузе и вернулся без прокрутки (`attention-today:чек-лист`);
     - игра на телефоне стоя или в дороге (`attention-today:LESSON-03`);
     - пересказ через сутки (`edgerton-hooked:чек-лист §4`);
     - «ради кого откроешь следующее уведомление?» (`vogler-writers-journey:LESSON-08`);
     - версия разгадки до финала (`mystery-fair-play:P-16`);
     - кривая интереса от тестера (`schell-art-of-game-design:чек-лист §4`).
- **Режим `digest` — вход:** отзывы, анкеты, журналы `K-05`. **Выход:** таблица `узел · тип (скучно / непонятно / не верю / нестыковка / баг) · сколько тестеров · симптом · решение`, средние по анкете после переворота, маршруты воспроизведения багов.
- **Шаги `digest`:**
  1. По журналу или сохранению `relay:<storyId>` найти узел каждого замечания (`choiceofgames-design:/tester-feedback`).
  2. Отделить предложения от симптомов (`narrative-testing:P-05`).
  3. Свести совпадения: места с ≥ 2 тестерами — наверх (`narrative-testing:P-06`).
  4. **Анкета:** пункт со средним < 4 — главная проблема волны. Низкие 1–3 → «непонятно», 4 и 7 → «скучно», 6 и 8 → «не верю», 9 → «выбор не ощущается». Сравнивать между волнами, а не с внешней нормой.
  5. Сверить с ботом: места, где откладывали телефон, — с длиной сессий и долей визитов узла (`nicklin-writing-for-games:чек-лист §4`). Кнопки, которые люди жмут чаще 70% при равных вариантах, — перекос знакомства или «правильный ответ» (`narrative-postmortems:RED-05`, `P-18`). Стратегии «всем доверяю / проверяю / молчу» доходят до своих финалов (`choiceofgames-design:чек-лист §4`).
  6. Каждый баг воспроизвести маршрутом через `K-01 --route` и сохранить маршрут.
  7. Список изменений с флажками отправить прошлой волне. На главу 1 позвать хотя бы одного нового человека (`narrative-testing:P-08`).
- **Режим `critical`** — разбор главы вживую по четырём стадиям: что это значило → вопросы автора → нейтральные вопросы игроков → мнения с разрешения. ИИ ведёт протокол и переписывает вопросы с мнением в нейтральные (`nicklin-writing-for-games:/critical-response`).
- **Знания:** `docs/books/narrative-testing/checklists.md §4–6`; `nicklin-writing-for-games/checklists.md §4`; `bateman-game-writing/checklists.md §4`; тест-разделы `checklists.md` остальных разборов (точечно).
- **Готово, когда:** у каждого замечания есть узел и тип; места с ≥ 2 совпадениями закрыты или обоснованы; у каждого бага есть маршрут воспроизведения; посчитаны средние по анкете.

## 6. Ремонтные приёмы

Приёмы нумеруются `F-NN`, чтобы не путать их с правилами `R-NN` из `rules.md`. Аудиты не только находят проблему, но и предлагают один из этих приёмов. Каждый приём — шаг скилла, а не отдельная команда. Общее условие готовности для всех: ink компилируется, `check:story` даёт 0 тупиков, переменные и переходы не меняются, если приём этого не требует.

## 8. Что осталось спорным

1. **Пороги — в основном наша оценка разборов.** Это серия без кнопки, новые имена, длина сообщения, 70% крючков, 2% финала, 30–70% угадывания. Их нужно откалибровать на трёх историях, когда появятся `K-01…K-04`, и сверить с `checks.md`.
2. **Холодный читатель-модель против живого человека.** Для «понятно» модель годится. Для «скучно», «где отложил телефон» и угадывания разгадки разборы опираются на людей (`inkle-ingold:P-15`, `mystery-fair-play:P-16`). `S-00` помечает такие пункты «нужен живой тест» и не выдаёт их за проверенные.
3. **Шапка `D-01`** — компромисс между десятком систем разметки. Поля «ценность» (mckee) и «опыт» (schell) в неё не вошли. Если линзы `S-10` будут часто их восстанавливать, это повод вернуть поля.
