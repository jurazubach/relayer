# План: знания → скиллы → агенты (версия 3)

Задача — перенести базу (`docs/books/`, 30 разборов, 1851 ID) и свод (`docs/playbook/`) в скиллы и агентов Claude Code. Они подхватываются сами по ходу разговора и ведут историю по циклу из раздела 2.

Процесс гибридный: автор накидывает идеи, грумит и выбирает. ИИ прорабатывает, пишет, проверяет, правит и переписывает. Это proof of concept: всё в git, ломать и менять можно что угодно.

Версия 3 учитывает:
- критику (`build-plan-critique.md`);
- разбор цикла (`flow-review.md`);
- оба набора ответов автора (в конце этих файлов).

Пример работы — `flow-example.md` (переписан по разделу 2, задача T-16). Имена скиллов здесь заменяют `skills.md` §0–5; соответствие — в разделе 14. Перечень references и scripts по каждому скиллу — `flow-review.md` §C («References и scripts по скиллам»). Он входит в план с поправками раздела 5.

## 0. Решение автора от 25.10.2026 (выше остального плана)

- **Живых тестов в этом проходе нет.** «Понятно», «скучно» и «работают ли режимы» проверяет симулированная панель (`story-playtest`: профили холодных читателей поверх персон бота) и метрики. Живой тест автор проведёт позже, инструменты для него строятся. Э3 и Э6 идут на симуляции.
- **`docs/style.md` изобретает ИИ** из базы и свода. Утверждать его некому. Ориентир — игры Lifeline по открытым источникам: принципы, а не тексты.
- **Конвейер выполняется целиком, без автора**, решения за него принимает королева в пределах `docs/playbook/_build/INTENT.md`.
- **Три истории** можно править, тестировать и перерабатывать. Финальная задача Э7 проводит их через весь цикл скиллов.

## 1. Принципы

- **Решения автора выше базы.** Всё, что база советует иначе, записывается в `docs/playbook/superseded.md`: ID → решение (дата) → чем заменено. Сборщики не берут отменённое как действующее.
- **Состояние истории живёт в репозитории:** `docs/stories/<id>/`, раздел 7. Каждый скилл первым шагом читает `STATUS.md`.
- **Один стиль повествования для всех историй.** Это `docs/style.md`, «код-стайл» историй (раздел 8). Пишущие и правящие скиллы следуют ему, проверки ссылаются на него.
- **Знания живут в скиллах.** Агенты — исполнители с изолированным контекстом.
- **Оркестрирует только главная сессия.** Агенты не запускают агентов и не вызывают оркестрирующие скиллы.
- **Числа считают команды, модель судит.** Если команда упала, скилл пишет «нет данных: <команда>».
- **Один источник правды на каждый вид знаний:**

  | что | где |
  |---|---|
  | правила | `rules.md` (после правки T-05) |
  | проверки | `checks.md` |
  | числа и пороги | `thresholds.json`: значение, единица, уровень, опора (`source` / `our_estimate`), источники, на чём откалибровано, история правок |
  | владельцы тем | `owners.md` (по кластерам тем) |
  | стиль | `docs/style.md` |
  | решения автора | `superseded.md` и `docs/stories/<id>/decisions.md` |
  | адаптация под внимание | `docs/playbook/attention-merged.md` |
  | этика и монетизация | `story-release/references/ethics.md` |
  | наши уроки | `docs/playbook/local-lessons.md` (`LOCAL-NN`) |
- **Скиллы не привязаны к конкретным историям.** Вход сборщиков очищается от строк про наши истории (T-07). Кейсы наших историй лежат в `docs/lab/cases/` и нужны только для экспериментов.
- **Учит, а не только делает.** Режим «объясни» во всех отчётах. Правка по умолчанию — предложение с вариантами, применяется только одобренное.
- **Модель — Opus** для всех агентов и сборщиков. Это решение автора.
- **Эксперименты и тесты — не через `master`.** Пуш в `master` — это деплой. Тестерам отдаётся `.json` через «Загрузить историю».

## 2. Цикл работы над историей

```
1. идея → story-brainstorm: 3–5 направлений, разных минимум по трём осям, у каждого трейлер на 5 сообщений
2. выбор → story-core: ядро, вопросы автору с вариантами ответа, D-01 «ядро v1»
3. story-architect (фон): 2–3 плана, каждый как skeleton.ink; сравнение числами; отвергнутые → ideas.md
4. в любой момент → story-branch: куда свернуть; бюджет дорогих веток; новая версия плана
5а. скелет всей истории в ink (по строке на сцену, настоящие выборы, переменные, финалы)
    → check:story, story:endings, story:lint --plan, story-review --plan
5б. начисто главы 1–2 (chapter-writer) с заглушкой beta_stop
6. story-review → 7. story-fix → 8. story-time: оба режима, напоминания
9. живой тест волна 1 (story-playtest): .json тестерам, один в реальном времени, второй по клику
Б-2. переписывание по тесту → Б-1. сверка плана → 5в. главы 3–N
→ полное ревью → живой тест волна 2 → 10. story-release
```

Недостающие шаги — каждому есть владелец:

| шаг | что делает | владелец |
|---|---|---|
| Б-1 | переход к главам 3–N: сверка плана с итогами теста, новая версия плана; ранние главы, скорее всего, придётся переписать после поздних | `story-desk` + `story-plan` |
| Б-2 | переписывание после теста: симптом получает тип (скучно / непонятно / не верю / нестыковка / баг) → решение или отказ с причиной → правка → повтор на свежем человеке | `story-playtest` → `story-fix` |
| Б-3 | ревью и тестеры противоречат друг другу: симптом человека реален, его рецепт — нет; по «скучно» человек сильнее модели, по структуре сильнее замер; один тестер против замера — «нужен третий» | `story-review/conflicts.md` |
| Б-4 | автор отверг все варианты: спросить, что не так, по осям; исключить отвергнутое; дать 2 далёких варианта | `story-brainstorm`, `story-branch` |
| Б-5 | возврат к ядру посреди работы: что устарело (план, главы, `facts.md`), пометка в `STATUS.md` | `story-desk` |
| Б-6 | несколько авторов: кто ведёт главу, главы отдельными файлами через `INCLUDE`, решения подписаны | `story-desk` |
| Б-7 | ревью плана до текста: разбор скелета вместе с холодным читателем | `story-review --plan` |

## 3. Время, два режима, длина

Решения автора:
- **Режим выбирается в начале истории.** Сменить его можно только перезапуском: поведение в режимах может отличаться. Режимы равноценны, «по клику» не платный и не бонус.
- **«По клику»:** ожидания нет вообще, следующий шаг приходит сразу. При сюжетном скачке больше N часов — системная метка («спустя 3 часа», «утро»).
- **«Реальное время»:** паузы настоящие (×1). Персонаж не называет, сколько его не будет.
  - **К часам игрока не привязываемся**: часовые пояса и время игры не определяем. Ночью персонаж может писать события и ждать реакции, игрок при желании выключит уведомления в игре.
  - **Напоминания:** если игрок молчит, персонаж 1–2 раза напоминает («алё, ты где? нужно твоё решение»). После этого история идёт дальше сама, ветка «не ответил» запоминается.
  - **Отсутствие не наказывается сильнее, чем осознанное молчание (`#silent`).** Упрёков за то, что игрок пропал, нет.
- **Время суток — время мира истории, а не игрока.** «Доброе утро» пишется как событие у персонажа и не опирается на часы игрока.
- **Длина в реальном времени — по базе:**
  - история до 48 часов, потолок около 3 дней (R-67, `serial-hooks:LESSON-04`, `yorke-into-the-woods`);
  - одна пауза — не больше суток;
  - после последней кнопки — не больше 15 минут пауз (`messenger-genre:P-16`);
  - чтения около 10–15 минут в день (наша оценка);
  - на карточке два числа: «≈ 35 мин по клику · ≈ 2 дня в реальном времени».
- **`speed = 60` — отладочное.** Для тестов вместо него — кнопка «пропустить до следующего» в отладке.

Что это меняет в своде (T-05, записывается в `superseded.md`):
- **R-63** — «называй время, когда напишешь»: заменить на «причина без срока»;
- **R-67** — убрать выравнивание ночи под часы игрока, оставить пределы длины;
- **короткая версия, п. 11–13** — привести в соответствие;
- **отменить уроки** «быстрый режим только после первого финала» и «назови срок паузы» (`serial-hooks:P-13`, `PAT-04`, `chat-fiction-apps:P-04`, `PAT-03`, `messenger-genre:PAT-02`, `narrative-testing:RED-33` и родственные). Записать их как решение автора с опорой (`schell-art-of-game-design:LESSON-06`: давать выбирать темп) и проверить на живом тесте (Э6).

## 4. Контракт скилла

```
.claude/skills/<имя>/
  SKILL.md                ядро: 60–120 строк
  references/*.md         обычно 8–14 файлов
  references/systems/*.md авторские системы по шагам
  scripts/*.mjs           обычно 3–6
```

**`SKILL.md`:**
- frontmatter: `name`, `description` до 300 знаков — симптомы словами автора, главное в начале; `when_to_use` не используем (тратит тот же бюджет); версия — в `metadata.version`; у скиллов с командами — `allowed-tools: Bash(npm run story:*), Bash(node ${CLAUDE_SKILL_DIR}/scripts/*)`; модули — `user-invocable: false` (T-00, `claude-code-format.md` §9);
- ссылки: скрипты — `${CLAUDE_SKILL_DIR}/scripts/x.mjs`, references — относительной ссылкой markdown; самое важное — в первых строках `SKILL.md` (после сжатия контекста остаётся только начало);
- **первый шаг** — прочитать `docs/stories/<id>/STATUS.md` и `docs/style.md`, если скилл пишет или правит текст. Если шаг истории не тот, о котором просят, сказать об этом;
- граница с соседями поимённо, вход и выход;
- алгоритм в 5–9 шагов. На каждой развилке — какой reference читать, на каждом подсчёте — какую команду запускать;
- 5–10 главных правил по ID;
- формат результата, «готово», режим «объясни», строка версии скилла.

**`references/`** — виды файлов:

| вид | что внутри |
|---|---|
| `decisions-*.md` | развилки «если A → X». У каждой записи поля: «когда не работает», «масштаб» (5 сообщений против 50), `basis` (`checked` / `secondary` / `model` / `our_estimate`) |
| `patterns-*.md` | приёмы с примерами ink, которые компилируются; те же поля |
| `systems/*.md` | авторская система по шагам: вход → выход, что будет без шага, ошибки понимания, короткая форма |
| `contradictions.md` | спор источников → наше решение → на чём стоит |
| `flags.md` | красные и зелёные признаки: команда, которой обнаружить, правка |
| `fixes/F-NN-*.md` | ремонтные приёмы скилла |
| `lessons.md` | карточки уроков на 3–5 строк с классом доказательства: A — эксперимент или данные, B — постмортем с цифрами, C — мнение |
| `attention.md` | разделы `attention-merged.md`, нарезанные по якорю, без пересказа |
| `explain.md` | для автора: почему так, упражнение |
| `sources.md` | генерируется скриптом из ссылок, проверяется на существование |

**Связи между файлами.** Правила подтягиваются по ID (`npm run story:rule R-61`), числа — только по ключу `thresholds.json`: число без ключа роняет линт. Reference ссылается на свод и на reference другого скилла не глубже одного уровня.

**`scripts/`** — обёртки над `scripts/lib/`. Каждый скрипт прогоняется на трёх историях и мутантах.

**Находка:**

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер | модель | человек · уверенность]
```

Находка, которую автор отклонил, не всплывает снова, пока не изменится узел (хэш узла в `decisions.md`).

## 8. Стиль повествования (`docs/style.md`)

Это «код-стайл» историй: что и как рассказываем, в каком формате, что хорошо и что плохо. Любая новая история и любая правка следуют ему.

Собирается из свода и базы, автор правит:
- формат сообщения: длина, одна мысль, регистр, пунктуация, эмодзи;
- голос и тон: как пишут персонажи, как отличаются;
- что запрещено: канцелярит, упрёки игроку, обещания срока паузы, реальные бренды и люди;
- как подаём время мира, паузы, системные строки;
- кнопки: длина, род игрока, разные ответы;
- 30–50 образцовых реплик и 30–50 антиобразцов с объяснением.

Каждая правка автора в главе, написанной ИИ, пополняет образцы. Проверка — `style-diff.mjs` в `story-voice` (глава против образцов) и правила `story:lint`. Если авторов несколько, у каждого может быть свой `docs/authors/<имя>/style.md` поверх общего.

## 9. Разметка в ink — только то, что кто-то читает

**Шапка, 4 строки** (`ставка`, `вопрос`, `оси`, `логлайн`) — как в версии 2.

**Метки, 3 вида:**
- `// reveal: clue_x` — для `story-mystery`;
- `// намеренно: C-NN причина` — гасит ложное срабатывание;
- `// финал: <имя>` — у узла финала, для `story:endings` и C-40. Финалы объявляются явно: у THE NUMBER одно `END`, и различаются финалы состоянием.

**Персонажи** — в `characters` файла `meta.json`.

**Валидатор** входит в `story:lint`. `rules.md` (около 20 меток) приводится к этой разметке задачей T-05.

## 12. Монетизация и этика

Владелец — `story-release/references/ethics.md`, остальные ссылаются на него.
- Граница — только на стыке глав, на сильном крючке, как в сериале: что-то случилось, и хочется продолжения.
- Обещание на границе сбывается сразу после неё (`boundary-check.mjs`).
- «По клику» не продаётся: режимы равноценны.
- Платных вариантов выбора нет. Бесплатный путь не наказывается. Пауза не растягивается ради выручки.
- Напоминания — сюжет, а не давление: не больше двух, без упрёков, история идёт дальше.

  - стоимость;
  - доля «замер / модель / человек»;
  - принятые правки;
  - время автора на отчёт;
  - регрессии;
  - сколько видит «отвлечённый» после паузы до кнопки.
