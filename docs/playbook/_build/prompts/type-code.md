# Как делать задачу с кодом

- Перед правкой прочитай код, который меняешь, и его тесты.
- Перевод скрипта на общую библиотеку не меняет поведение: сравни вывод до и после на трёх историях.
- Новые команды — npm-скриптом в `package.json`, с `--help` и `--json`.
- Изменения в `src/` проверяй сборкой (`npm run build`) и e2e (`HEADLESS=1 npm run test:e2e`).
- Если меняешь формат истории или поведение чата, обнови README, `CLAUDE.md` и `docs/capabilities.json` в том же коммите.
- Для своей части добавь самопроверку (`npm run test:lib` или аналог), которую прогонит конвейер.
- **Сначала посмотри, что уже есть в `build/main`:** `docs/playbook/thresholds.json`, `scripts/lib/` (загрузчик порогов, словари, время игрока, бот), `scripts/lint/`, `scripts/story/`. Используй их, не заводи копий. Нужен новый порог или словарь — добавь ключ в `docs/playbook/thresholds.json` точечно, даже если файла нет в твоих путях: это общий реестр. Своих файлов порогов (`*.default.json`, константы в коде) не заводи.
- **Имена ключей:** порог проверки — `C-NN.<что>`, даже если её строку в `checks.md` правит другая задача; `story.*` — только общие определения истории (длина, паузы), `engine.*` — движок, `lab.*` — эксперименты, `skill.*` — контракт скиллов, `dict.*` — словари.
- **`--json` в трубе:** в конце скрипта `process.exitCode = …`, а не `process.exit(…)` сразу после `console.log` — иначе вывод обрежется на 64 КБ.
