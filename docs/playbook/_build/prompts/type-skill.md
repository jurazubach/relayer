# Как собирать скилл

Контракт — `docs/playbook/build-plan.md` §4. Перечень файлов для твоего скилла — строка в §5 и раздел `docs/playbook/flow-review.md` §C («References и scripts по скиллам») с поправками из §5. Формат скиллов Claude Code — `docs/playbook/claude-code-format.md`.

## Структура

```
.claude/skills/<имя>/
  SKILL.md
  references/*.md
  references/systems/*.md
  references/fixes/F-NN-*.md   (если скилл владеет ремонтными приёмами)
  scripts/*.mjs
```

## `SKILL.md` (`skill.core.min_lines`–`skill.core.max_lines` строк из `thresholds.json`)

- **Frontmatter.**
  - `name: <имя>`.
  - `description` — не длиннее `skill.description.max_chars`, симптомами словами автора («игрок не понимает, кто пишет», «кнопки ничего не меняют»), а не названиями теорий.
  - `when_to_use` не используй: он дописывается к `description` и тратит тот же бюджет (`claude-code-format.md` §1.2). Главные симптомы — в начале `description`.
  - Модуль (не пользовательский вход, план §5) — `user-invocable: false`: скрыт из меню `/`, но модель видит описание и вызывает его через `Skill`. Не `disable-model-invocation` и не «чтение `SKILL.md` по пути»: это запрещённый обход (`claude-code-format.md` §1.5).
  - Версия — в `metadata: { version: 1 }` frontmatter; строку «Версия: 1» в конце тела оставь тоже, для человека.
  - Если скилл запускает команды подсчёта — `allowed-tools: Bash(npm run story*), Bash(npm run -s story*), Bash(node ${CLAUDE_SKILL_DIR}/scripts/*)`. Не `story:*`: такое правило совпадает с `npm run story *` и `story:lint` получает отказ (LOCAL-03). Проверь в `claude -p`, что команды шагов не получают отказ в правах.
- **Ссылки:** скрипты своего скилла — `node ${CLAUDE_SKILL_DIR}/scripts/x.mjs`; references — относительной ссылкой markdown `[references/x.md](references/x.md)`. Скрипт работает с cwd = корень проекта, пути внутри считай от `import.meta.url` или от корня.
- **Главное — в первые строки `SKILL.md`:** после сжатия контекста от скилла остаются только первые тысячи токенов.
- **Первый шаг алгоритма:** прочитать `docs/stories/<id>/STATUS.md`. Историю не угадывай: если неясно, о какой речь, спроси.
- **`docs/style.md` — в том шаге, где скилл пишет реплику, кнопку или пример ink** (а не условием в шаге 1: в Э2-мини ни один прогон его не прочёл, LOCAL-09).
- **Команды в `SKILL.md` — ровно так, как их запускать, по одной на вызов:** без `cd`, пайпов, `;`, `&&`, `>`, `$?` и `for` с переменной — составные команды получают отказ в правах; длинный вывод — `--summary` или `--json`, а не `| head`; свои скрипты — `node ${CLAUDE_SKILL_DIR}/scripts/…`.
- **Диагностический скилл — обязательный шаг перед отчётом: сверь каждую находку замера с ink и с правилом** (узел, контекст, исключения правила). Все ложные находки Э2-мини — повтор замера без такой сверки (LOCAL-04).
- **Границы с соседями** — поимённо. Вход и выход.
- **Алгоритм** из 5–9 шагов. На каждой развилке — «читай `references/<файл>`», на каждом подсчёте — «запусти `npm run story:…` / `node ${CLAUDE_SKILL_DIR}/scripts/<x>.mjs`». Числа только из команд. Если команда упала: «нет данных: <команда>».
- **5–10 главных правил** по ID (`R-NN`, `C-NN`), без чисел: числа — ключами `thresholds.json`.
- **Формат результата:** сначала находки строго строкой `P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]` — узел третьим полем, F-NN в правке; потом разговорный текст. В живых ответах поля плавали.
- **Раздел «Состояние»:** что скилл передаёт `story-desk` — отчёт `docs/stories/<id>/reviews/<дата>-<скилл>.md` с находками и одна строка для `STATUS.md` (через `story-desk`, после одобрения). Иначе находки не доходят до состояния истории (LOCAL-10).
- **Режим «объясни»**: почему, откуда правило, как сделать самому.
- Строка `Версия: 1`.

## `references/` — главное богатство скилла

Одна тема — не больше двух файлов references. В `SKILL.md` — карта references одной таблицей «развилка → файл». Образец — `story-choices` v2.

| вид | содержание |
|---|---|
| `decisions-*.md` | развилки «если A → X». У каждой записи поля «Когда не работает», «Масштаб» (5 сообщений против 50), `basis: checked\|secondary\|model\|our_estimate` и ID источников |
| `patterns-*.md` | приёмы с примерами ink, которые компилируются (теги только `ready` из `docs/capabilities.json`), с теми же полями |
| `systems/*.md` | авторская система по шагам: вход → выход, что будет без шага, ошибки понимания, короткая форма. Своими словами |
| `contradictions.md` | спор источников → наше решение → на чём стоит. Учти `docs/playbook/superseded.md` |
| `flags.md` | красные и зелёные признаки: какой командой ловить, как чинить |
| `fixes/F-NN-*.md` | ремонтные приёмы: шаги, ink до и после, что нельзя сломать |
| `lessons.md` | карточки уроков на 3–5 строк с классом доказательства (A — эксперимент или данные, B — постмортем с цифрами, C — мнение) |
| `attention.md` | нарезка `docs/playbook/attention-merged.md` по якорям `{#attn-...}` для твоей темы: текст правил без пересказа, числа — ключами; списки источников — в `sources.md`, а не в `attention.md` |
| `explain.md` | для автора: почему так, упражнение |
| `sources.md` | список `алиас:ID`, из которых собран скилл. Генерируй скриптом, если он есть (`npm run story:coverage -- --sources <имя>`) |

- Каждый reference — не длиннее `skill.reference.max_lines` строк (`thresholds.json`), в конце раздел «Источники».
- Решения автора (`INTENT.md`, `superseded.md`) выше базы: отменённое не переносить как действующее.
- Правила свода подтягивай по ID, не переписывая. Число без ключа `thresholds.json` — ошибка.

## Откуда брать знания

- **Разборы** — из очищенной копии `docs/books/_clean/<алиас>/`. Она не в git: в свежем worktree её нет, поэтому первым делом запусти `npm run kb:clean -- --quiet` (секунды). Не читай `docs/books/<алиас>/` напрямую: там строки про наши истории, а скиллы к ним не привязываются. Читай целиком: `principles`, `patterns`, `flags`, `lessons`, `attention`, `checklists`, `for-relayer`.
- **Чем ты владеешь** — `docs/playbook/owners.md` (§1 — скиллы, §3 — проверки, §4 — ремонтные приёмы, §6 — якоря внимания). Это единственный источник раскладки: если строка «владеет» в задании или `flow-review.md` §C расходится с `owners.md`, прав `owners.md`. Чужие ID не переписывай к себе — ссылайся на владельца.
- **Как `story:coverage` признаёт покрытие** (`npm run story:coverage -- --help`): блок в reference владельца с ID строки в заголовке (`### алиас:P-07 · …`), длиннее `skill.coverage.block_min_chars`, с ключевыми терминами строки, у P и PAT — «Когда не работает», у строки с порогом — ключ `thresholds.json`. L3 — плюс исполняемость: проверка `story:lint`, развилка в `decisions-*.md`, компилируемый пример ink или мутант. `sources.md` не пиши руками: `npm run story:coverage -- --sources <имя> --write` (большой скилл — с `--compact`, если файл длиннее `skill.reference.max_lines`). Дубли закрывай статусом (`npm run story:coverage -- --record <ID> status=merged-into:<ID>` или `rejected:duplicate:<кластер>`), а не формальными блоками ради `--min L2`: ревьюер сверяет смысл блока с источником.
- **Своя часть матрицы покрытия:** `npm run story:coverage -- --skill <имя>` (если команда есть) и `docs/playbook/owners.md`. Закрой свои кластеры: L2 — правило своими словами плюс «когда не работает»; L3 — исполняемо: проверка, развилка, пример ink или мутант. Отказ — только с причиной из фиксированного списка.

Имена и контакты в примерах — свои: не из трёх историй каталога и не из основы мутантов `docs/lab/mutants/_base` (skill-check предупредит).

## `scripts/`

- Тонкие обёртки над `scripts/lib/` и командами `story:*`.
- У каждого скрипта `--help`, вывод для человека и `--json`.
- Прогони каждый на трёх историях: `src/stories/*`, и сравни вывод скрипта с соответствующей командой `story:*` — числа должны совпасть.
- `scripts/lib` не меняй. Если там чего-то не хватает — просьба в `requests.md`.

## Тест срабатывания

Создай `docs/lab/triggers/<имя>.json`: `lab.triggers.phrases_min`–`lab.triggers.phrases_max` фраз автора, на которые скилл должен сработать, и 5 соседних фраз, на которые не должен (они относятся к другим скиллам). Формат — как у других файлов в `docs/lab/triggers/` или как описано в `scripts/lab/`.

## Мутанты

Если скилл диагностический, проверь, что мутанты твоей зоны (`docs/lab/mutants/`) ловятся: `npm run skills:test -- --skill <имя>`.

## Свои проверки

Тесты своих проверок — в `scripts/lint/selftest-<имя скилла>.mjs` (`export function register(test, { has, hasNot, lint, keys })`, файл подключается сам). Строку «Ключи» своих проверок в `docs/playbook/checks.md` правь точечно (общий файл), иначе `test:lint` упадёт. Сырые прогоны (`lab:triggers`, `skills:test`, живые `claude -p`) — в `docs/lab/runs/<задача>/` и коммить вместе со скиллом: это данные эксперимента.

Если ты владеешь проверками C-NN (`owners.md` §3), их модули `scripts/lint/checks/C-NN.mjs` — в твоих путях: ложные срабатывания и пропуски, которые найдёшь на трёх историях и мутантах, чини там же, с тестом в `npm run test:lint`. Новый порог — ключ `C-NN.<что>` в `docs/playbook/thresholds.json` (общий реестр, правь точечно, даже если его нет в твоих путях) с записью в `history`. Вставляй ключ рядом с ключами своей проверки (`C-NN.*`), а не в конец файла: так параллельные задачи не конфликтуют при слиянии.

## Таблица «симптом → скилл»

Допиши одну строку своего скилла в таблицу «Скиллы: симптом → скилл» в `CLAUDE.md` (общий файл, правь точечно): главные симптомы словами автора → имя скилла.

## Приоритеты находок

P1/P2/P3 диагностический скилл выставляет по общей таблице `.claude/skills/story-review/references/priority.md`, а не своей шкалой: иначе линзы и ревью расходятся.
