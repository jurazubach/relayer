# Как собирать скилл

Контракт — `docs/playbook/build-plan.md` §4. Перечень файлов для твоего скилла — строка в §5 и раздел `docs/playbook/flow-review.md` §C («References и scripts по скиллам») с поправками из §5. Формат скиллов Claude Code — `docs/playbook/claude-code-format.md`.

## Структура

```
.claude/skills/<имя>/
  SKILL.md
  references/*.md
  references/systems/*.md
  references/fixes/F-NN-*.md   (если скилл владеет ремонтными приёмами)
  scripts/*.mjs
```

## `SKILL.md` (60–120 строк)

- **Frontmatter.**
  - `name: <имя>`.
  - `description` — до 300 знаков, симптомами словами автора («игрок не понимает, кто пишет», «кнопки ничего не меняют»), а не названиями теорий.
  - Модуль (не пользовательский вход) — пометь его так, как предписывает `claude-code-format.md`.
- **Первый шаг алгоритма:** прочитать `docs/stories/<id>/STATUS.md`, а если скилл пишет или правит текст — `docs/style.md`. Историю не угадывай: если неясно, о какой речь, спроси.
- **Границы с соседями** — поимённо. Вход и выход.
- **Алгоритм** из 5–9 шагов. На каждой развилке — «читай `references/<файл>`», на каждом подсчёте — «запусти `npm run story:…` / `node .claude/skills/<имя>/scripts/<x>.mjs`». Числа только из команд. Если команда упала: «нет данных: <команда>».
- **5–10 главных правил** по ID (`R-NN`, `C-NN`), без чисел: числа — ключами `thresholds.json`.
- **Формат находки:** `P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]`.
- **Режим «объясни»**: почему, откуда правило, как сделать самому.
- Строка `Версия: 1`.

## `references/` — главное богатство скилла

| вид | содержание |
|---|---|
| `decisions-*.md` | развилки «если A → X». У каждой записи поля «Когда не работает», «Масштаб» (5 сообщений против 50), `basis: checked\|secondary\|model\|our_estimate` и ID источников |
| `patterns-*.md` | приёмы с примерами ink, которые компилируются (теги только `ready` из `docs/capabilities.json`), с теми же полями |
| `systems/*.md` | авторская система по шагам: вход → выход, что будет без шага, ошибки понимания, короткая форма. Своими словами |
| `contradictions.md` | спор источников → наше решение → на чём стоит. Учти `docs/playbook/superseded.md` |
| `flags.md` | красные и зелёные признаки: какой командой ловить, как чинить |
| `fixes/F-NN-*.md` | ремонтные приёмы: шаги, ink до и после, что нельзя сломать |
| `lessons.md` | карточки уроков на 3–5 строк с классом доказательства (A — эксперимент или данные, B — постмортем с цифрами, C — мнение) |
| `attention.md` | нарезка `docs/playbook/attention-merged.md` по якорям для твоей темы |
| `explain.md` | для автора: почему так, упражнение |
| `sources.md` | список `алиас:ID`, из которых собран скилл. Генерируй скриптом, если он есть (`npm run story:coverage -- --sources <имя>`) |

- Каждый reference — до 300 строк, в конце раздел «Источники».
- Решения автора (`INTENT.md`, `superseded.md`) выше базы: отменённое не переносить как действующее.
- Правила свода подтягивай по ID, не переписывая. Число без ключа `thresholds.json` — ошибка.

## Откуда брать знания

- **Разборы** — из очищенной копии `docs/books/_clean/<алиас>/`, если она есть. Иначе из `docs/books/<алиас>/`, игнорируя строки про наши истории. Читай целиком: `principles`, `patterns`, `flags`, `lessons`, `attention`, `checklists`, `for-relayer`.
- **Своя часть матрицы покрытия:** `npm run story:coverage -- --skill <имя>` (если команда есть) и `docs/playbook/owners.md`. Закрой свои кластеры: L2 — правило своими словами плюс «когда не работает»; L3 — исполняемо: проверка, развилка, пример ink или мутант. Отказ — только с причиной из фиксированного списка.

## `scripts/`

- Тонкие обёртки над `scripts/lib/` и командами `story:*`.
- У каждого скрипта `--help`, вывод для человека и `--json`.
- Прогони каждый на трёх историях: `src/stories/*`.
- `scripts/lib` не меняй. Если там чего-то не хватает — просьба в `requests.md`.

## Тест срабатывания

Создай `docs/lab/triggers/<имя>.json`: 8–15 фраз автора, на которые скилл должен сработать, и 5 соседних фраз, на которые не должен (они относятся к другим скиллам). Формат — как у других файлов в `docs/lab/triggers/` или как описано в `scripts/lab/`.

## Мутанты

Если скилл диагностический, проверь, что мутанты твоей зоны (`docs/lab/mutants/`) ловятся: `npm run skills:test -- --skill <имя>`.
