# S-cast · просьбы за пределами путей задачи

1. **`scripts/lint/checks/C-10.mjs` — экспортировать `wrongResponders(tree, service)`.** Сейчас C-50 вызывает
   `C10.run(ctx, …)` целиком и забирает из находок только `C-10.wrong_responder`, чтобы не дублировать место
   (решение S-choices-v2). Экспорт функции убрал бы лишний расчёт остальных подпроверок C-10 и зависимость от
   формы `data` находки (`line`, `to`). Владелец — `story-choices`.

2. **`scripts/lab/mutants-spec.mjs` — мутанты для RED зоны `story-cast`**, чтобы они дошли до L3 (RED засчитывается
   на L3 только с мутантом): `messenger-genre:RED-14` (строка рассылки между вопросом и кнопкой — C-50 (б)),
   `sheldon-character-storytelling:RED-03` (основной контакт в главе только отвечает — C-45 п. 5), шум выше
   `C-50.noise_share` (C-50 (в)). Сейчас m07 попутно ловится C-50 (в) — в `catches` его можно добавить.

3. **`docs/lab/mutants/README.md` или основа `_base`.** README говорит, что основа чистая и без подсказок, но
   `story:lint --only C-45` даёт на ней 4 подсказки (lev в двух главах из четырёх, «1 заметный говорящий» в главах
   1, 3, 4). Прогону мутантов это не мешает (сравнение с основой), но «основа без подсказок» неверно — поправить
   текст или основу.

4. **`scripts/story/cast.mjs` (`story:cast`) — служебные контакты.** `notes` из `dict.service_contacts` попадает в
   таблицу как «эпизодический · нет в characters · # contact без реплик»; `story:lint` его не считает. Предлагаю
   отмечать служебные отдельным уровнем «служебный» (как `cast.mjs` скилла), чтобы автор не видел ложную пометку.

5. **`docs/lab/triggers/_routing.json`** (общий файл): добавить 2–3 маршрута к `story-cast`
   («Игрок ответил брату, а пишут все, кроме брата», «Когда ввести нового героя»), чтобы граница с `story-choices`
   (C-10 «ответил не тот» против C-50 «ответ в пустоту») проверялась и общим прогоном.
