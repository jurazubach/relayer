# E-03 · просьбы за пределами разрешённого

1. **`scripts/story/core/run.mjs`, `readSave`: брать режим из журнала.** Выгрузка журнала (`format: "relayer-choices"`)
   несёт `mode` (`realtime` / `click`), а `story:trace --from-save` режим из файла не читает: автор должен сам
   передать `--mode`. Без этого маршрут с `-1` («не ответил») по умолчанию идёт в реальном времени — это верно,
   но журнал игрока «по клику» прогонится не в его режиме. Предложение: `readSave` возвращает `mode`, а `trace`
   берёт его, если `--mode` не задан. Зачем: одна команда на файл тестера без знания его режима.
2. **`scripts/story/selftest.mjs`: тест на формат журнала.** Сейчас совместимость журнала движка и `readSave`
   проверяет только e2e (`e2e/choice-log.spec.ts`, прогон `trace.mjs --from-save` по скачанному файлу).
   Нужен быстрый тест в `test:story-cmd` на образце `relayer-choices` (поля `route`, `start`, `set`; в файле
   нет `storyState` и `relay:<id>`), чтобы правка `readSave` не ломала разбор журналов тестеров.
3. **`story-playtest` (сводка, `digest.mjs`): читать `choices[]`.** Привязка отзыва к узлу — `choices[].knot`
   и `chapter`; «отложил телефон» — `waitMs` и записи `remind`; осторожность с файлами, где `exact: false`
   (тестер прыгал в отладке). Это для задачи, которая строит `story-playtest`.
4. **Бот и напоминания перед ответом.** Если игрок ответил после напоминания, `--route` повторяет нажатие,
   но не напоминание: в `bot.play` стратегия решает раньше, чем случается молчание. В журнале это видно
   (`reminders` у записи `choice`, отдельные записи `remind`), а в прогоне `story:trace` реплики «алё» не будет.
   Если для разбора тестов это важно — нужен формат маршрута «молчал до n-го напоминания, потом кнопка k».
