# T-06 · просьбы за пределами разрешённого

1. **`docs/playbook/rules.md`, вступление** (после абзаца о решениях автора). Добавить строку: «Как звучит текст — формат реплики, голос, тон, кнопки, системные строки, юмор — `docs/style.md` (положения `ST-NN`). Где style.md повторяет правило, рядом стоит `R-NN`; при расхождении чисел прав этот файл и `thresholds.json`». Зачем: документ, который пересекается с другим, отмечается в обоих местах; сейчас пометка есть только в `style.md`.
2. **`CLAUDE.md`, схема «Устройство»**. Добавить строку `docs/style.md  стиль повествования: код-стайл историй, образцы и антиобразцы`. Зачем: план §1 называет `style.md` единственным источником правды по стилю, а в схеме проекта его нет.
3. **Сборщик промпта (`npm run prompt`, `docs/PROMPT.md`)**. Вставлять в промпт раздел «1. Короткая версия» из `docs/style.md` рядом с короткой версией `rules.md`. Зачем: короткая версия написана для промпта, и генератор должен получать её автоматически.
4. **`docs/playbook/checks.md`, «Общие данные» → «Словари»**, и **C-47**. Завести словари из `docs/style.md` §14.5 (канцелярит, игровые слова в репликах, ярлык финала, громкость, драма прилагательными) как строки C-47 уровня «подсказка». Отдельной строкой — регистры `nicklin-writing-for-games:P-19` (`#sys` > 6 слов или с «я / ты / ? / !», эмоции в заметках) и `P-18` (глава без `#sys`, `#rename`, `#photo`, `#unlock`). Зачем: `style.md` §14.1 ссылается на эти проверки, а в `checks.md` их нет. Исполнитель — T-03b.
5. **`docs/playbook/thresholds.json` (T-03a / T-03b)**. Ключи для чисел стиля без проверки-владельца: `style.emoji_per_line` (1), `style.ellipsis_per_queue` (1), `style.blind_min` (8 из 10), `style.queue_gap` (3–8 с внутри очереди, 1–5 мин между очередями); пороги `#sys` ≤ 6 слов, ≤ 2 шутящих контакта, пауза внутри шутки ≤ 1 мин. Все с опорой из `style.md` §14.4. После этого числа в `style.md` заменяются ключами.
