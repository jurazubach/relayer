# S-desk · просьбы за пределами путей задачи

## 1. `sources.md`: метка кластера `K-<алиас>:<ID>` читается приёмкой как неизвестный алиас

- **Где:** `scripts/kb/coverage.mjs`, `sourcesMd()` (строка `const cl = x.cluster !== x.id ? \` · ${x.cluster}\` : ''`)
  и/или `docs/playbook/_build/checks/skill-check.mjs`, проверка «sources.md: алиасы существуют».
- **Что:** генератор пишет в строку источника метку кластера, например `· K-narrative-postmortems:P-07`.
  Регулярка приёмки `([a-z0-9-]+):(?:P|PAT|…)` не видит заглавную `K` и берёт алиас `-narrative-postmortems`
  → «✗ sources.md: неизвестные алиасы -narrative-postmortems». Упадёт у любого скилла, у которого есть
  кластер вида `K-<алиас>:<ID>`.
- **Как починить (любое из двух):**
  - в `skill-check.mjs` — граница перед алиасом: `/(?<![\w-])([a-z0-9-]+):(?:P|PAT|GREEN|RED|LESSON|SYS)-?\d*/g`;
  - или в `coverage.mjs` — писать метку кластера в обратных кавычках с префиксом, который не похож на ID
    (`· кластер \`K-…\`` всё ещё ловится — значит, лучше чинить регулярку приёмки).
- **Что сделано сейчас:** в `.claude/skills/story-desk/references/sources.md` после генерации вручную убраны
  две метки `· K-narrative-postmortems:P-07` (строки `P-07` и `RED-12`). Остальное — вывод генератора без правок.
  После починки инструмента — перегенерировать: `npm run story:coverage -- --sources story-desk --write`.
- **Зачем:** без этого `skill-check` не проходит, хотя все алиасы в файле существуют.

## 2. `docs/playbook/thresholds.json`: два новых ключа (сделано точечно, для сведения)

- `story.rewrite.early_chapters` (2 главы) и `story.rewrite.late_chapters` (3 главы) — пороги
  `stale-check.mjs` п. 5 по `narrative-postmortems:P-07` («если тега нет в главах 1–2, но он есть в трёх
  поздних») и `RED-12`. Записи в `history` есть. Если королева предпочтёт другую область ключей (`desk.*`) —
  переименовать в обоих местах: ключи и `stale-check.mjs`, `references/staleness.md`, `decisions-desk.md`, `SKILL.md`.

## 3. Мутант на `narrative-postmortems:RED-12` (по желанию)

- **Где:** `docs/lab/mutants/` (задача T-13 или владелец мутантов).
- **Что:** мутант «приём есть в поздних главах и нет в ранних» (например, `#rename` только в главах 4+).
  Сейчас RED-12 держится на L3 по кластеру `P-07` (развилка), а RED на L3 по правилам покрытия — только с
  мутантом. Ловит его `stale-check.mjs --tags-only`, а не `story:lint`, поэтому `skills:test` пока не умеет
  его проверять — сначала решить, ловит ли такой мутант линт или скрипт скилла.
