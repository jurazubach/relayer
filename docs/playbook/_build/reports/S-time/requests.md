# S-time · просьбы за пределами моих путей

1. **`docs/playbook/checks.md` C-27, «Как считать»** — дописать два исключения, которые теперь есть в
   `scripts/lint/checks/C-27.mjs` (калибровка S-time по базе): причина не нужна, (а) когда последняя строка до
   паузы — `#sys` «Прочитано» (тишина сама событие: `messenger-genre:P-01#нюанс`, `attention-today:P-09#нюанс`);
   (б) на стыке глав, если в окне есть срок события в мире (`dict.world_deadline`) без срока возвращения
   (R-63 разрешает время события, R-64 — это крючок). Зачем: спецификация и код расходятся. Итог по трём
   историям: предупреждений C-27 было 22 / 0 / 2, стало 20 / 0 / 0 (chuzhoy-golos / slepoe-pyatno / the-number);
   m08 ловится.

2. **`docs/playbook/checks.md` C-32 п. 7, «Как считать»** — заменить «и после запасной кнопки» на контекст строки
   (решение королевы T-08, код — `reproachContexts` в `C-32.mjs`): упрёк за отсутствие — после напоминания, в
   ветке «не ответил» (в том числе когда ею стал `#silent`), после паузы от `story.pause.notice_min`, которую
   поставила история, и после запасной кнопки, если перед ней были напоминания. Ответ на нажатую кнопку до
   паузы (и на запасную, где кнопка ждёт по замыслу) — не упрёк за отсутствие: та же строка у любого игрока,
   смысл судит C-47. Зачем: ложное срабатывание в каталоге («Спасибо. Наконец-то.» — ответ на кнопку
   «Согласен, закрываем»), и после паузы истории упрёк теперь ловится даже после нажатого `#silent` (R-74).

3. **`scripts/story/trace.mjs`, `--compare silent`** — считать упрёки тем же `reproachContexts` из
   `scripts/lint/checks/C-32.mjs` (экспорт есть), а не «последняя кнопка не `#silent`». Зачем: сейчас trace и
   C-32 расходятся на той же строке «Спасибо. Наконец-то.» (trace — упрёк, C-32 — нет). Тест
   `scripts/story/selftest.mjs` («наконец-то, ты долго» после «не ответил») останется зелёным: это контекст
   noanswer.

4. **`docs/style.md` ST-66 и §14.1** — убрать «Синтаксис интервалов — E-02, когда станет `ready`» и
   «(deferred:E-02)» в строке ST-66: синтаксис `#remind` / `#noanswer` готов с 0.4 (`docs/capabilities.json`).
   Зачем: пишущий скилл прочитает, что напоминаний ещё нет.

5. **Кластер `K-messenger-genre:RED-11` и `messenger-genre:PAT-07`** (сейчас TH-49 у `story-time` по кластеру) —
   по смыслу это эхо и распределитель (`story-choices` TH-56 / `story-endings` TH-60). Я держу их блоками со
   стороны времени (`length.md`), чтобы ни у кого не было L0; при следующей сверке `story-choices` предлагаю
   перенести в его «опору», когда там будут блоки. Решает королева.

6. **Автору — кандидат в `docs/capabilities.json` (`planned`)**: для повтора — старт с главы и пропуск
   прочитанного (`messenger-genre:LESSON-04`, `sheldon-character-storytelling:LESSON-11`). Реестр не трогал:
   это решение о поведении чата.

7. **Словарь `dict.pause_reason` (владелец — инфраструктура `story:lint`)** — на трёх историях подсказки C-27
   дают причины, которых нет в словаре: «бегу», «водит», «я на аукционе» (дело в процессе). Не правил: словарь
   общий, а сверка с ink в скилле (шаг 7) снимает такие находки как ложные. Если королева решит
   калибровать — кандидаты: `бегу|бежим|лечу|плыву|в пути|на месте`.
