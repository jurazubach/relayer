# A-cold · Агент cold-reader — сборка

## Сделано

- **`.claude/agents/cold-reader.md`** — тонкая обёртка над командой. Frontmatter: `tools: Bash`, `model: opus`,
  `omitClaudeMd: true`, `color: cyan`, `description` «Вызывается скиллами …» без фраз автора; `hooks.PreToolUse`
  на `Bash` — пропускает только одну команду `npm run [-s] story:cold-read [-- аргументы]` без `; & | < > $ \``,
  обратной косой и перевода строки, остальное — exit 2. Тело: роль, таблица «ситуация → скилл → `--mode` → на
  чём стоит» (story-opening, story-playtest, story-pauses, story-time, story-mystery, story-voice, story-review),
  режимы и профили словами автора, порядок в 4 шага (разбор задания, одна команда с `--ask --json` и
  `timeout: 600000`, коды 0/1/2, возврат), общий формат выхода (шапка, изоляция, ответ дословно цитатой, ключ,
  маршрут, находки P3 механическим переводом «теряю» и «отложил бы»), запреты.
- **`.claude/skills/story-playtest/references/cold-reader.md`** — единственный протокол; «Формат ответа»: блок
  «Интерес:» по четырём точкам (после первых сообщений, на первой кнопке, перед паузой, после возвращения) —
  «держит / ровно / теряю» с цитатой и причиной одной строкой; «нет», если точки в отрезке нет. В опоре —
  раздел «Шкала интереса по точкам (решение королевы, A-cold)» с «когда не работает».
- **`.claude/skills/story-playtest/scripts/digest.mjs`** — `interestOf` (разбор блока, точки узнаются по словам),
  «теряю» с цитатой → строка «скучно» с пометкой «интерес», таблица «Интерес по точкам» в сводке и поле
  `interest` в `--json`; принимает и `.json` от `story:cold-read --json`; из папки — только `.md` (рядом
  `panel.mjs` кладёт `.json` того же читателя). Починен `--no-lint` перед файлом (съедал имя файла как значение).
- **`scripts/story/cold-reader-protocol.md`** — удалён; **`scripts/story/cold-read.mjs`** — протокол по умолчанию
  `PROTOCOL` из скилла, запасного пути нет; справка говорит про агента.
- **`scripts/story/selftest.mjs`** — протокол скилла (режимы, пять профилей, «виновник» в контроле, все точки
  шкалы в «Формате ответа»), тест `--last`/`--profile`, тест разбора шкалы интереса.
- **`scripts/story/README.md`** — строка таблицы и раздел «Холодный читатель»: контракт вызова, протокол один,
  режимы, `--profile` (профили и персоны по умолчанию), `--last N`, формат ответа со шкалой, изоляция, коды.

## Решения

- **Хук встроен в frontmatter агента** (`node -e` одной строкой): мои пути — только файл агента, а план требует
  ограничение именно хуком. Вынести в `scripts/hooks/` — просьба 2.
- **Агент всегда зовёт с `--json`:** ему нужны `key` и `isolation` для возврата, а ключ (финал маршрута,
  «дальше пришло бы», голоса) скилл сверяет сам. Читателю ключ не уходит — это делает команда.
- **Агент не выбирает узел и не чинит вызов** (seed, персону): истории он не видит, а подбор узла — работа
  скилла. Нет `--until` — «нет данных», код 2 — первая строка ошибки как есть.
- **Находки агента — только механический перевод** «теряю» и «Итог: отложил бы», P3, уверенность «низкая»:
  судить об истории — дело скилла (`digest.mjs`, разметка), агент возвращает ответ как есть. «Слабое место» и
  списки профиля («Не верю:» у скептика) в находки не идут — их размечает `story-playtest`.
- **Шкала интереса не заменяет «Итог»:** `panel.mjs` (`verdictOf`) продолжает читать «Итог» и «Слабое место»,
  шкала — добавочный блок; так совместимы старые прогоны S-playtest.
- **Точки узнаются по словам** (`перв… сообщ`, `кнопк`, `перед пауз`, `возвращ`), а не по точной строке: модель
  пишет заголовки точек по-разному (жирным, с уточнением).

## Открыто

- Подпись в транскрипте дублирует имя, если реплика в ink начинается с имени отправителя (просьба 1) — скептик
  принял это за огрех текста.
- Хук печатает агенту всю свою команду при отказе (~300 знаков) — просьба 2.
- В режиме `opening` до первого хаба точек «перед паузой» и «после возвращения» нет — шкала там из двух точек;
  полную кривую дают `return` и прогон до узла после первой длинной паузы. Это выбор узла в скилле, не в агенте.
- **Автору:** оба прогона снова «Итог: дочитал бы» и «держит» на обеих точках — шкала пока не показала «теряю»
  на начале; станет ли она различать скуку, видно будет на `return` и середине глав (Э2/Э6).
