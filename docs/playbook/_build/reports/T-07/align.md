## Дрейф (если есть)

Дрейфа нет.

- **Замысел.** Задача прямо исполняет запрет INTENT «не привязывать скиллы к трём текущим историям»: сборщики получают `docs/books/_clean/`, кейсы лежат в `docs/lab/cases/`. Боль автора, на которую это работает: скиллы учат общим правилам, а не пересказывают три proof-of-concept-истории, которые всё равно будут переписаны. Решений против автора нет: чат, время, оплата, модель, `master` не затронуты.
- **План.** Изменения не выходят за `writes` задачи: `scripts/kb/**`, `docs/lab/cases/**`, `package.json` (две строки) и отчёты. `.gitignore` уже содержал `docs/books/_clean`. `docs/books/*` не изменён. `src/` и `capabilities.json` тоже не тронуты.
- **Отступления от спецификации записаны в `build.md`.** Чистка идёт по предложениям, а не по строкам: так правило остаётся, а уходит только пример. Это точнее исполняет пункт «удаляются только строки-примеры». Пункты целиком про историю (7 штук) получают пометку и переносятся, как требует спецификация.
- **Единые правила.** В скрипте нет числовых порогов, поэтому `thresholds.json` (его пока и нет) не нужен. Скиллов в ветке ещё нет (`.claude/skills/` отсутствует), дублей быть не может.
- **Утечки.** Строки про наши истории есть только в `docs/lab/cases/`, а это разрешённое место. Кейсы — копии строк из базы, то есть нашего пересказа, а не текста книг. Реальных брендов нет: «£12», «Kind regards, J.» и прочие строки в `EXTRA` взяты из наших вымышленных историй. Я проверил: `--verify` возвращает код 0, `test:kb:clean` проходит 5/5.

## Риски для следующих задач

- **`_clean` игнорируется git.** В свежем worktree следующей задачи (T-09, все `S-*`) этой папки нет. В `inputs` у T-09 есть «после npm run kb:clean». В спецификациях `S-*` написано только «очищенные», без пути и без команды. Сборщик скилла может молча взять `docs/books/` и вернуть в скилл примеры из наших историй.
- **Пересказ без имён проходит фильтр.** Строки вроде «кнопка живёт в `ch5`» и «наш прогон 400 путей…» словарь не ловит. Голые `chN` оставлены намеренно. Из-за этого `--verify` не гарантирует, что утечек нет. Нужен второй рубеж: ревьюер скилла ищет примеры без названий.
- **Остались советы «образцовые сцены из наших историй» и «замеры по нашим историям»** (см. `requests.md` п. 2). Если свод не заменит их придуманным эталоном, они попадут в скиллы как правило.
- **`EXTRA` — ручной список.** После X-E7 (переписывание историй) новые имена из реплик и `#rename:` сами в словарь не попадут. Конфликт с «Сол» из придуманного примера в `meaningful-choice` пока не решён.
- **Для X-E2mini.** `slepoe-pyatno` — отложенная история. Её кейсы в `docs/lab/cases/slepoe-pyatno.md` лежат в репозитории открыто. Скиллу их показывать нельзя: следить за этим нужно в промпте эксперимента, иначе прогон будет загрязнён.
