# T-10 · Просьбы за пределами разрешённых файлов

1. **`docs/playbook/attention-merged.md` §10 «Нарезка по скиллам и покрытие»** — под таблицей добавить строку:
   «Владельца каждого раздела закрепляет `owners.md` §6; здесь — кто раздел берёт». Зачем: таблица там называет
   несколько скиллов на якорь, а `owners.md` выбирает одного (`#attn-player` → `story-time`, `#attn-check-cold` →
   `story-playtest`, `#attn-load` → `story:lint`). Без пометки сборщик возьмёт §10 как раскладку владельцев.

   «Списки ID уточнены `owners.md` §5 и §7: если ID стоит у двух файлов, его держит владелец из `owners.md`».
   Зачем: в §C один ID часто стоит у двух-трёх скиллов (`ashwell:PAT-01…PAT-13` у `story-branch` и `story-plan`,
   `truby:P-09` у трёх файлов), T-16 должен брать раскладку из одного места.
3. **`docs/playbook/build-plan.md` §5** — в абзаце «Перечень references и scripts — `flow-review.md` §C с
   поправками ниже» дописать «и `owners.md`». Там же отметить T-10 выполненной (§10).
4. **T-09 (`story:coverage`)** — колонки `owner_skill` и `target` брать из `owners.md`: строки R/C/F/якорей — по
   ID, строки базы — по кластеру TH-NN из колонки «опора»; строке без кластера владельца назначает ревьюер, и
   она дописывается в «опору» нужного TH-NN. Парсер может переиспользовать проверку из `owners.md` §8.
5. **T-03 (`story:lint`)** — `owners.md` назначает `story:lint` владельцем C-52, C-53 и порогов
   `#attn-load`; отчёт линта мог бы печатать у находки владельца из `owners.md` §3 (кто чинит).
