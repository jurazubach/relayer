# X-E2mini — сверка с замыслом

Вердикт: drift-minor

Курс верный. Срез отвечает на боль автора «выбор не ощущается»: 22 кнопки кормят счётчик, который звучит
один раз, а естественный вопрос скрыто ведёт к плохому финалу. Срез показывает, что `story-choices` видит это
сам по фразе автора. Решений против `INTENT.md` нет:
- сроков паузы, упрёков, привязки к часам игрока, платных выборов и замков между историями нет;
- скиллы и истории не тронуты, в `master` ничего не ушло;
- правки текста только предложены королеве.

Задача уложилась в свой раздел. Правка `story-findings.md` вне `writes` задачи, но её прямо просит
расширенная постановка («после W0…»). Всё, что за пределами разрешённого, вынесено в `requests.md`, а не сделано
тихо. Дрейф мелкий: регрессия покрытия (поправил) и одна запись про модель (ниже).

## Исправил сам

- **Новый `local-lessons.md` ронял две проверки перед коммитом.** `npm run test:coverage` и
  `npm run story:coverage -- --summary` давали код 1: «без владельца 10» (LOCAL-01…10). Без файла обе проходят.
  Ревью это пропустило. В «опору» `owners.md` LOCAL не дописать: парсер «опоры» (`kb-owners.mjs`, `ID_TOKEN`)
  знает только R/C/F и ID разборов. Поэтому владельцы назначены через `manual.th` в
  `docs/playbook/clusters.json`, как подсказывает сама команда:
  - LOCAL-01 → TH-49 (`story-time`, длина);
  - LOCAL-02, 03, 04, 07, 08 → TH-28 (`story-review`, формат находки и уровни «замер / модель»);
  - LOCAL-05 → TH-58 (цена);
  - LOCAL-06 → TH-56 (отклик);
  - LOCAL-09 → TH-55 (кнопки);
  - LOCAL-10 → TH-100 (состояние).

  После правки обе команды — код 0, `--build-clusters --check` — «свежий», `--unowned` — 0.
- **Рецепт слепой копии** (`docs/lab/runs/X-E2mini/README.md`) дополнен: из копии убирать и
  `docs/playbook/local-lessons.md`. Когда шли прогоны, файла не было, а теперь LOCAL-04…06 и LOCAL-10 пересказывают
  находки по «Слепому пятну».

## Дрейф (если есть)

- **Модель haiku в проверке прав** (`permissions.md`). INTENT: «Модель — Opus для всех агентов». Haiku не делал
  разбор истории: на нём проверяли только, какое правило `allowed-tools` пропускает команду. Это записано
  в `build.md` и не влияет на числа полноты и точности. Но это отступление от решения автора, и прецедент
  лучше не закреплять. Как вернуть: повторные проверки прав (при правке LOCAL-03) гонять на Opus. Правило
  «вспомогательные прогоны — тоже Opus» записать в `prompts/type-experiment.md`.
- **Предложение «≥ 3 прогонов на историю в Э2»** (`build.md`, «Прочее»; ревью его повторяет). План §13 и задача
  X-E2 говорят «два прогона». Если королева примет, число должно стать ключом `thresholds.json`, например
  `lab.stability_runs`, а не жить в тексте задачи. Нужна и правка §13.

## Риски для следующих задач

- **X-E2 (отложенная — снова `slepoe-pyatno`).** Находки по ней теперь лежат и в `docs/playbook/local-lessons.md`
  (LOCAL-04…06, 10), а его читают `story:rule` и `story-desk/decision-add.mjs`. Скилл, который пойдёт по ссылке `LOCAL-NN` из своего `lessons.md`, увидит кейсы отложенной
  истории. Слепую копию X-E2 собирать по обновлённому рецепту (без `local-lessons.md`). Иначе: держать в LOCAL
  только вывод, а пример из истории — в журнале.
- **LOCAL-03 до любых новых `skills:test` и W1.** Пока `allowed-tools`/`ALLOW` пишут `Bash(npm run story:*)`,
  каждый прогон скилла идёт без замера. Тогда W1 (`skills:test`, `lab:triggers`) и X-E2 мерят только суждение
  модели, и цифры несравнимы со срезом после правки. Это правка из `requests.md`, она вне зоны этой задачи.
- **Ссылки «строки NNNN» больше не работают.** Всё, что ссылается на старую нумерацию по полю `ink`
  (`baseline.md`, `cases/*`, старые отчёты `_build`), читать по тегу `stories-v1`. X-E7 переписывает истории, и
  ссылки `chNN.ink:строка` в `story-findings.md` тоже устареют. Привязка к имени узла надёжнее номера строки.
- **Бренд в истории.** `src/stories/slepoe-pyatno/ch04.ink:8, 207, 209` — `[audit] github: …`. Реальная компания
  в тексте истории против INTENT. Это не эта задача, строка была и раньше. X-E7 (переработка трёх историй)
  должна её убрать.
- Заголовки `## LOCAL-NN · …` попадают в матрицу с титулом «· …»: `kb-rows.mjs` срезает после ID только точку.
  Это косметика. Либо `\.?` → `[.·]?` в регулярке, либо заголовки через точку.

## Предложения королеве

1. Принять список правок шаблона и `story-choices` из `build.md` как есть. Все правки на курсе. В двух из них
   прямо работает INTENT:
   - п. 6 шаблона: находки ревью доходят до состояния;
   - `story-desk`: предлагать черновик ядра, а не спрашивать автора («ИИ предлагает варианты»).
2. LOCAL-03 сделать до W1 отдельной маленькой задачей. Затрагивает скиллы, `skills-test.mjs`, `type-skill.md` и
   `claude-code-format.md` §9. После неё перезапустить `skills:test --skill story-choices` как новую базовую
   точку.
3. В `prompts/type-experiment.md` добавить:
   - новые `LOCAL-NN` сразу получают владельца (`manual.th` в `clusters.json`), иначе падает `story:coverage`;
   - вспомогательные прогоны `claude -p` — тоже Opus;
   - слепая копия исключает `local-lessons.md` и всё, где есть кейсы отложенной истории.
4. Научить `parseOpora` разбирать `LOCAL-NN` как глобальный ID (рядом с R/C/F). Тогда владельцы уроков живут
   в `owners.md` §5, как всё остальное, а `manual.th` в `clusters.json` убрать. Задача уровня T-09/T-10.
5. Решить, где живут находки скиллов вне 28 свода. Например, «кнопка Рите — отвечает Кай»: раздел «найдено
   скиллами» в `story-findings.md` или `docs/lab/cases/`. Для полноты X-E2 ключ должен расти вместе с находками.
6. Ключ дефектов основы мутантов (LOCAL-07) нужен до X-E2. Без него точность на мутантах не меряется, а это
   один из трёх показателей Э2 (§13).
