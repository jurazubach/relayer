# A-auditor · просьбы за пределами разрешённых путей

1. **Сторож Bash аудитора — в файл `scripts/hooks/auditor-guard.mjs`** (сейчас — однострочный `node -e` в
   `hooks:` frontmatter `.claude/agents/story-auditor.md`).
   Зачем: при отказе Claude Code показывает агенту весь текст команды хука (≈ 800 знаков) перед сообщением —
   лишний шум в контексте (`claude-code-format.md` §2.5: вывод хука нужен короткий). Короткая команда
   `node "$CLAUDE_PROJECT_DIR"/scripts/hooks/auditor-guard.mjs` + случаи в `npm run test:hooks`
   (разрешено / отказ — те же 17 строк, что в `build.md`, раздел «Проверки»). Логику переносить как есть.

2. **`story:lint --owner <скилл>`** — фильтр находок по полю `owner` (`docs/playbook/owners.md` §3).
   Где: `scripts/lint/lint.mjs`. Зачем: `story-review` отдаёт каждому аудитору узлы его линзы; сейчас фильтровать
   приходится по `--json` скриптом или списком `--only C-NN,…`, который дублирует `owners.md` в каждом
   `SKILL.md`.

3. **Команда «показать узел»** — ink одного узла с его stitch'ами по имени (например `story:rule`-подобная
   `npm run story:node -- <id> <узел>`, на `scripts/lib/ink.mjs`).
   Где: `scripts/story/`. Зачем: аудитор по контракту читает узлы, а не весь ink; сейчас он ищет строку узла
   `grep -n` и читает `Read` с `offset`/`limit`, и диапазон часто выходит шире узла. `story:diff -- HEAD . --text
   --node <узел>` показывает реплики, но без условий, переменных и тегов.

4. **Словарь событий для C-36 / `turns.mjs`.** Оба прогона аудитора признали ложной пометку «без перемены»
   у сцены, где угроза сказана словами вне словаря («это легко исправить»). Где: `docs/playbook/thresholds.json`
   (`dict.*`), владелец — `story-pace`. Зачем: меньше ложных C-36.
