# T-04a · Просьбы за пределами разрешённых файлов

1. **`docs/playbook/thresholds.json` (T-03a / T-03b).** Перенести ключи из
   `scripts/story/core/thresholds.default.json` (24 ключа: `bot.*`, `trace.*`, `sessions.*`, `click.*`,
   `cast.*`, `endings.*`, `vars.*` — с единицей, опорой и источниками) и удалить запасной файл. Загрузчик
   `scripts/story/core/thresholds.mjs` понимает плоский ключ (`"sessions.gap": {value}`), вложенный объект и
   раздел `thresholds` — какой формат ни выберет T-03, команды его прочтут; запасной файл берётся, только если
   ключа в главном нет. Отдельно: у `click.jump_label` (метка «спустя N» по клику) числа нет ни в плане, ни у
   автора — сейчас 1 ч (наша оценка = «длинная пауза»). Нужно решение (T-05 п. 5 просит о том же).
2. **`scripts/lib/bot.mjs` (владелец — T-01, расширяет E-02).** Строки после перехода прямо перед `-> END`
   получают узел предыдущей строки: после последнего `Continue()` у inkjs пусты и `previousPointer`, и
   `currentPathString`. Пример: `{h > 0: -> cold}` → `=== cold === понятно -> END` — строка «понятно» в журнале
   числится за прежним узлом. `story:endings` обходит это счётчиками посещений (`visited`), но в `story:trace`
   такая строка подписана чужим узлом. Предложение: если оба пути пусты, брать узел из
   `story.state.currentPointer` до `Continue()` или из разницы `VisitCountAtPathString` до и после.
3. **`scripts/lib/ink.mjs` (T-01 / T-03).** Однострочное условие с переходом `{x == 1: -> a}` разбирается как
   реплика с текстом `{x == 1: }` и отдельный `divert` без условия. Из-за этого его считали бы репликой (и
   чтением, которое видит игрок). В `scripts/story/core/vars-index.mjs` это обойдено `isInlineDivert()`;
   правильнее разбирать такие строки в `cond` с веткой. Этим же страдает `story:lint` (C-06, C-03).
4. **`CLAUDE.md`, раздел «Команды».** Добавить:
   ```
   npm run story:trace         # прохождение персоной: переписка, маршрут, переменные, оба режима (--help)
   npm run story:vars          # переменные: где пишется → где читается, мёртвые и невидимые
   npm run story:sessions      # расписание без часов игрока: сессии, микросессии, длина против карточки
   npm run story:cast          # контакты и их уровень: ось / сторона / источник / фон / эпизодический
   npm run story:endings       # финалы, доли по персонам, что их решает
   npm run test:story-cmd      # самопроверка команд story:*
   ```
   и в «Устройство» — строку `scripts/story/  команды story:* на scripts/lib (README внутри)`.
5. **E-02 (движок, напоминания).** Точка подключения — `noAnswer(choices)` в `scripts/story/core/personas.mjs`:
   сейчас она отдаёт `#silent` той же развилки или −1 («история стоит»). Когда синтаксис напоминаний станет
   `ready`, она должна отдавать ветку «не ответил», а `bot.mjs` — писать события напоминаний; тогда
   `story:trace --compare silent` начнёт сравнивать по-настоящему разные ветки (сейчас они совпадают по
   построению) и сможет проверить C-32 п. 6 (число напоминаний, дословный повтор, продолжение).
6. **Словари (T-03).** `scripts/story/core/lexicon.mjs` повторяет словари из `checks.md` («закрывающие»,
   «обещание», «упрёк за отсутствие»). `checks.md` требует хранить их в одном месте. Если `story:lint` заведёт
   свой модуль, стоит вынести общий в `scripts/lib/lexicon.mjs` и импортировать из обоих.
7. **T-02 (формат истории).** `story:sessions` предупреждает «на карточке нет days» у всех трёх историй —
   поле заводит T-02; после него сравнение реального времени с карточкой заработает само.
