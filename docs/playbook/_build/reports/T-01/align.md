## Исправил сам

- **Несколько финалов в одном узле терялись.** План §9 прямо говорит: «у THE NUMBER одно `END`, и финалы
  различаются состоянием». А `findEndings` брал только первую `// финал:` в узле (`knot.ending`), остальные
  метки молча пропадали. Если поставить метки по веткам `{ … }` общего узла финала, `story:endings` и C-40
  увидели бы один финал вместо нескольких. Теперь каждая метка `финал` — отдельная запись
  `{ id, name, line, file? }`, где `line` — строка метки. `knot.ending` (первая метка) я оставил для карты.
  В карте `endings` — уникальные id узлов, поэтому подсчёт «N финалов» на карте прежний.
- Заодно добавил `file` в записи финалов: ревьюер просил его для историй из нескольких файлов (T-02, T-03, T-04).
- В `selftest.mjs` добавлен случай «одно END, две метки по веткам», в `scripts/lib/README.md` дописана строка про это.
- После правки: `test:lib` 26 из 26, `check:story` 0, `graph` 0 (узлов 165 / 36 / 76, как в отчёте),
  `build` 0, `prompt -- --quiet` 0.

## Риски для следующих задач

- **T-03a / C-40 «финал без метки».** Узел с `-> END` без метки попадает в `unmarked`, даже если все пути
  в него уже размечены выше (как `fin` в синтетическом тесте: `good` / `bad` → `fin` → END). C-40 на таком
  графе даст ложное срабатывание. Решить в T-03a: либо считать «финал без метки» только по путям, где перед END
  не было метки, либо требовать метку в самом узле END (тогда см. правку выше: метки по веткам).
- **T-04a, персона «неотвечающий» и `--mode`.** В боте есть стратегия выбора `(choices, ctx) → индекс`,
  но нет понятия «не ответил»: напоминаний и ветки молчания пока нет и в движке (E-02). Персона в T-04a
  сможет только выбирать вариант «молчу», если он есть кнопкой. Нужно либо отложить её проверку до E-02, либо
  в E-02 расширить `bot.mjs` (у E-02 `scripts/lib/**` есть в `writes`).
- **T-02.** Если рядом лежат папка и `.json` с одним id, `listStories` берёт папку, а `.json` считает копией
  от `story:pack`. T-02 должен закрепить именно это, иначе разойдутся `check:story` и сайт. Ещё два правила:
  шапку держать в главном файле (в INCLUDE она уходит в метки узла) и не ставить узлы в главном файле после
  `INCLUDE` (иначе разъедется нумерация глав).
- **T-03a.** Однострочные условия `{a: x | y}` не разбираются на ветки. Проверкам, которым нужны ветки
  внутри строки, придётся расширить `ink.mjs`.
- **W0** ждёт `npm run test:lib`: команда есть, имя совпадает.
