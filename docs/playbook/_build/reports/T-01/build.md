# T-01 · Общая библиотека разбора ink scripts/lib — сборка

## Сделано

- `scripts/lib/ink.mjs`: разбор исходника в дерево. Узлы — knot и stitch (`knot.stitch`), функции лежат отдельно в `functions` (с параметрами и телом). Выборы: глубина, `(метка)`, условия `{…}`, текст кнопки `[…]`, теги, `+`. Ещё сборки, многострочные условия и switch, `~`, переходы, туннели, `->->`, теги строк, говорящий (`#from` / `#me` / `#sys`), главы `#chapter`, `VAR/CONST/LIST`, `INCLUDE`, `EXTERNAL`. **Комментарии — токены** (`type: 'comment'`, строчные и блочные, номера строк не сдвигаются). Метки `reveal` / `намеренно` (с id проверки и причиной) / `финал` собираются в `knot.marks`, шапка `ставка / вопрос / оси / логлайн` — в `tree.head`. Ещё есть `findEndings`, `nodeIds`, `walk`, `stripComments`, `resolveTarget`, `allMarks`, `splitTags`, `parseTag`, `parseDelay`, `tokenize`. Можно разбирать несколько файлов сразу (главный и INCLUDE) с полем `file` у узлов.
- `scripts/lib/compile.mjs`: `compile()` через inkjs с обработчиком файлов для INCLUDE. Ошибки приходят как `{ severity, file, line, message, excerpt }` с тремя строками исходника вокруг, без исключения. Ещё есть `formatMessages()` и `newStory()`.
- `scripts/lib/bot.mjs`: `play()` — одно прохождение с журналом. События: `knot`, `delay`, `line` (текст, вид, говорящий, теги, узел), `choice` (варианты, выбранный), `var` (имя, было, стало), `end` или `stuck`. Возвращает итоги: шаги, сумму пауз, выборы, посещённые узлы, переменные. Стратегии `random / first / last / scripted`; персона — любая функция `(choices, ctx) → индекс`. `seeded(seed)` даёт повторяемые прохождения; `setup` — старт с узла и заданных переменных.
- `scripts/lib/story.mjs`: `loadStory(id | путь)` читает три формы: `src/stories/<id>.json`, папку `src/stories/<id>/` (`meta.json` + `story.ink`, INCLUDE подтягиваются рекурсивно) и голый `.ink`. Ещё `listStories()` (если есть и папка, и `.json` того же id, берётся папка), `storyRefs`, `parseStory`, `compileInput`.
- `scripts/lib/index.mjs` (бочка), `scripts/lib/README.md` (API кратко).
- `scripts/lib/selftest.mjs` + `npm run test:lib`: 26 тестов. 17 синтетических: комментарии и метки, `https://` в тексте, функции и stitch, выборы, условия, туннели, говорящий и главы, финалы, несколько файлов, ошибки компиляции и INCLUDE, журнал бота, стратегии и seed, бесконечный цикл, `setup`, загрузка всех форм во временной папке. По 3 на каждую историю каталога: узлы разбора = содержимое компилятора без функций; переходы разрешаются; главы = `chapters` описания; все строчные `//` стали токенами; финал найден; бот доходит до конца. Есть `--help`, `--json`, `--only`.
- `scripts/check-story.mjs`: переведён на библиотеку. Добавлены `--help`, `--json`, `--seed N`, принимает id и пути. Ошибки компиляции печатаются с файлом, строкой и куском исходника.
- `scripts/story-graph.mjs`: переведён на библиотеку, собственный разбор удалён. Добавлены `--help`, `--json` (сводка с финалами и их источником), `--seed N`, id или пути. В данные карты добавлены `endings` истории, а у узла — `marks` и `ending`, если они есть.
- `scripts/story-graph.html`: финалы считаются по `S.endings` из библиотеки; для старых данных без этого поля остался прежний подсчёт по рёбрам. Метки узла показываются в панели.
- `package.json`: одна строка `test:lib`.

## Решения

- **Узел — knot или stitch, не функция.** Счёт `check:story` у `chuzhoy-golos`: было 166 (считалась `function sync_world`), стало 165, как на карте. Посещения считаются по `VisitCountAtPathString` для каждого узла из разбора. По текущему пути больше не считаются: путь мог занести в список функцию.
- **Финалы:** как только в истории есть хоть одна `// финал:`, финалами считаются только размеченные узлы, а узлы с `-> END` без метки отдаются в `unmarked` (опора для проверки «финал без метки»). Без меток финал — узел с `-> END`. `DONE` финалом не считается, как сказано в задаче; на карте ребро в `DONE` по-прежнему рисуется «концом истории».
- **К чему относится комментарий:** если после комментария до заголовка узла нет кода, он относится к этому узлу (`lead` и метки узла). Иначе он становится элементом текущего контейнера. Так `// финал:` можно ставить и над `=== узел ===`, и внутри узла.
- **Форма данных карты не изменилась:** в карту идут элементы без комментариев (`stripComments`), метки — отдельным полем. Иначе комментарий между двумя кнопками разбивал бы в шаблоне одну развилку на две.
- **Поведение разбора сохранено один в один**, включая особенности: теги кнопки читаются только внутри `[…]`; говорящий не переносится в следующий узел. Имена узлов теперь принимают любые буквы (`\p{L}`): на ASCII-историях результат тот же.
- **Случайность:** `rng` подставляется в бот, по умолчанию `Math.random`. Бот тратит те же случайные числа в том же порядке, что старые скрипты, поэтому старое и новое можно сравнить на одном seed.
- **Папка и `.json` одного id:** берётся папка, потому что `.json` рядом с ней — собранная копия (`story:pack`). Окончательно это решает T-02.
- **Без новых зависимостей:** самопроверка написана на `node:assert` со своим маленьким прогонщиком, чтобы были `--json` и `--only`.

## Открыто

- Числа ботов (400 / 2000 прохождений, 2000 / 3000 строк, 140 знаков) по-прежнему в скриптах. Их надо перенести в `thresholds.json`, когда он появится (T-03); просьба в `requests.md`.
- `CLAUDE.md` не знает про `npm run test:lib` и `scripts/lib`. Просьба в `requests.md`.
- Разбор условий построчный, как раньше: однострочные `{a: x | y}` внутри текста остаются текстом реплики, ветками не становятся (переходы из них ловятся). Если `story:lint` понадобятся ветки однострочных условий, разбор нужно расширить.
- Порядок файлов при INCLUDE: главный файл, затем подключённые по ходу текста. Главы нумеруются в этом порядке. Если в главном файле есть узлы после INCLUDE, номера глав могут разойтись с тем, что увидит игрок. T-02 стоит держать главный файл без узлов.
- Автору: что считать финалом, если `-> END` нет нигде, а история кончается на `-> DONE`? Сейчас такой узел финалом не считается, но на карте помечен как конец.
