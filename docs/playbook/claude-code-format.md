# Формат скиллов, агентов и хуков Claude Code — что проверено

Версия Claude Code: **2.1.310** (`claude --version`, 24.10.2026). Документ — источник правды о Claude Code
для конвейера и скиллов. Неизвестный факт сначала ищем здесь, потом в документации.

Метки у каждого пункта:
- **[док]** — проверено документацией: code.claude.com/docs/en/{skills, sub-agents, hooks, settings, settings-reference, cli-reference}.
- **[эксп]** — проверено экспериментом через `claude -p` в песочнице (протоколы — в разделе 7).
- Пункт без метки сюда не попадает. Расхождение документации и эксперимента отмечено «⚠».

Документ заменяет раздел «Технические ограничения Claude Code → Предположения (проверить в T-00)»
из `flow-review.md` §D. Итоги по каждому предположению — в разделе 8.

## 1. Скиллы

### 1.1. Где лежат и как называются

- `.claude/skills/<имя>/SKILL.md` — проектный скилл. Личные — `~/.claude/skills/`, плагинные — с префиксом
  `плагин:имя`. При совпадении имён побеждает личный, затем проектный **[док]**.
- `name` по умолчанию — имя папки. Неизвестные поля frontmatter молча игнорируются; битый YAML — скилл грузится
  без метаданных, и модель не может подобрать его по описанию (`claude --debug` покажет ошибку) **[док]**.
- Проверка frontmatter без запуска сессии: `claude plugin validate .claude/skills` **[док]**.

### 1.2. Поля frontmatter

| поле | что делает | метка |
|---|---|---|
| `name` | имя для `/` и для инструмента `Skill` | [док] [эксп] |
| `description` | по нему модель решает, вызывать ли скилл; попадает в листинг | [док] [эксп] |
| `when_to_use` | **дописывается к `description` через « - »** в той же строке листинга и считается в тот же лимит. Отдельного механизма нет | [док] [эксп] |
| `allowed-tools` | инструменты **без запроса разрешения** на ход, в котором вызван скилл. Не ограничивает набор инструментов. Сбрасывается со следующим сообщением пользователя | [док] |
| `disallowed-tools` | убирает инструменты, пока скилл активен (до следующего сообщения) | [док] |
| `disable-model-invocation: true` | скилл **пропадает из листинга**, вызов через `Skill` модель получает ошибкой; не предзагружается в агентов | [док] [эксп] |
| `user-invocable: false` | скилл скрыт из меню `/`, но в листинге модели остаётся с описанием, модель вызывает его сама | [док] |
| `context: fork` | тело скилла становится заданием отдельного субагента; истории разговора он не видит | [док] [эксп] |
| `agent` | тип субагента для `context: fork`: `general-purpose` (по умолчанию), `Explore`, `Plan` или свой из `.claude/agents/` | [док] [эксп] |
| `background` | с `context: fork`: `false` — ждать результат в том же ходе. В `-p` ждёт всегда | [док] [эксп] |
| `model` | модель на текущий ход; с `context: fork` — модель субагента. Принимает значения `/model` или `inherit` | [док] |
| `effort` | `low` … `max` | [док] |
| `paths` | glob-маски: автоактивация только при работе с подходящими файлами (относительно рабочего каталога) | [док] |
| `hooks` | хуки, которые регистрируются при вызове скилла и живут до конца сессии | [док] |
| `arguments`, `argument-hint` | именованные аргументы `$name` и подсказка в `/` | [док] |
| `metadata` | свободная карта для своих инструментов, Claude Code её не читает. Сюда — версию скилла | [док] |

Подстановки в теле: `$ARGUMENTS`, `$0…$N`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_SESSION_ID}` **[док]**.
Если аргументы ничему не подставились, Claude Code дописывает в конец `ARGUMENTS: <значение>` **[док]**.

### 1.3. Ссылки на `references/` и `scripts/`

- `${CLAUDE_SKILL_DIR}` в теле заменяется **абсолютным путём** к папке скилла **[док] [эксп]**.
  В `allowed-tools` тоже: `Bash(node ${CLAUDE_SKILL_DIR}/scripts/*)` снимает запрос разрешения для своих скриптов **[док]**.
- Относительная ссылка markdown `[references/info.md](references/info.md)` работает: модель сама достраивает путь
  от папки скилла и читает файл через `Read` **[эксп]**. Документация советует именно так ссылаться на supporting-файлы **[док]**.
- **Скрипт запускается с cwd = корень проекта**, а не папка скилла **[эксп]**: `process.cwd()` в
  `node ${CLAUDE_SKILL_DIR}/scripts/x.mjs` вернул корень. Пути внутри скрипта считать от `import.meta.url`
  или от корня проекта, но не от cwd «как будто мы в скилле».
- Тело `SKILL.md` грузится один раз при вызове и дальше не перечитывается; после сжатия контекста
  возвращаются первые 5000 токенов каждого вызванного скилла, все вместе — не больше 25 000 **[док]**.
  Главное — в начало `SKILL.md`. Документация советует держать `SKILL.md` до 500 строк **[док]**.

### 1.4. Листинг и бюджет

- Модель видит листинг один раз за сессию, строка на скилл **[эксп]**:
  ```
  - <name>: <description> - <when_to_use>
  ```
  У скилла в режиме `name-only` — просто `- <name>`.
- Бюджет листинга — **1 % окна контекста** (`skillListingBudgetFraction`, по умолчанию `0.01`) **[док]**.
  Если не влезает, все имена остаются, а **описания выпадают целиком, начиная с реже всего вызываемых
  скиллов** **[док]**. Предупреждение пишется в debug-лог **[док]**.
- Лимит на одну строку — 1536 знаков `description` + `when_to_use` (`skillListingMaxDescChars`) **[док]**.
- Абсолютный бюджет в знаках: переменная `SLASH_COMMAND_TOOL_CHAR_BUDGET` **[док]**. Стоимость листинга —
  `/doctor` и строка Skills в `/context` **[док]**.
- **Окружение автора до чистки** (сессия на Opus 5.5 в этом worktree, листинг из транскрипта) **[эксп]**:
  листинг 29 980 знаков, 114 скиллов, у **59 описания выпали** (все `cockroachdb:*`, `engineering:*`, часть
  `brightdata-plugin:*`, synced `anthropic-skills:*`). Потолок около 30 000 знаков совпадает с 1 % от окна 1M.
  Новые скиллы проекта при таком раскладе остались бы без описаний.
- **После чистки** (раздел 6) **[эксп]**: листинг 8 054 знака, 20 скиллов, без описания только `claude-api`
  (так задумано). Под наши скиллы свободно около 22 000 знаков.
- Бюджет зависит от машины: чужие плагины у другого автора снова его съедят. Проектный `.claude/settings.json`
  отключает только перечисленные по имени плагины **[док]**.

### 1.5. Как скрыть скилл из листинга, но оставить вызываемым

| способ | в листинге модели | меню `/` | модель вызывает через `Skill` | метка |
|---|---|---|---|---|
| по умолчанию | имя + описание | да | да | [док] [эксп] |
| `user-invocable: false` (frontmatter) | имя + описание | нет | да | [док] |
| `skillOverrides: {"x": "name-only"}` (settings) | **только имя** | да | **да** — модель выбрала скилл по одному имени | [док] [эксп] |
| `skillOverrides: {"x": "user-invocable-only"}` | нет | да | нет | [док] |
| `skillOverrides: {"x": "off"}` | нет | нет | нет, вызов по имени — ошибка | [док] [эксп] |
| `disable-model-invocation: true` | нет | да | **нет** — ошибка инструмента | [док] [эксп] |

- `disable-model-invocation` блокирует вызов строго **[эксп]**. Ответ инструмента: «cannot be used with Skill tool
  due to disable-model-invocation… Do not replicate this skill's workflow by other means». Поэтому схема
  «скрытый модуль читается по пути» с этим полем **противоречит сообщению самого Claude Code**. Однажды модель
  нашла `SKILL.md` через `find` и прочитала его сама, но опираться на это нельзя.
- Вывод: «скрыть, но вызывать» = **`name-only` в `skillOverrides`** проектного `.claude/settings.json`
  (полностью скрыть и вызывать нельзя). `skillOverrides` действует на личные, проектные и synced скиллы
  (проверено на `travel-assistant`, `xlsx`, `anthropic-skills:pptx`), **но не на плагинные** **[док] [эксп]**.

### 1.6. `context: fork`

- Есть и работает **[эксп]**: вызов `Skill(fork-probe)` → в потоке `task_started` с `subagent_type: general-purpose`,
  результат приходит строкой «Skill "fork-probe" completed (forked execution). Result: …».
- Форк получает CLAUDE.md проекта (кодовое слово из `CLAUDE.md` назвал) и полный набор инструментов
  general-purpose, включая `Agent` и `Skill` **[эксп]**. С `agent: Explore`/`Plan` CLAUDE.md не грузится **[док]**.
- Скилл с `context: fork` **всегда** уходит в форк. Нельзя один и тот же скилл звать то в главной сессии,
  то изолированно **[док]**. Скилл без задачи, только с правилами, в форке ничего полезного не вернёт **[док]**.
- Фоновый форк работает с урезанным набором инструментов фоновых агентов; если шаги требуют полного набора —
  `background: false` **[док]**.

## 2. Агенты

### 2.1. Где лежат

`.claude/agents/<имя>.md`, тело — системный промпт. Приоритет: managed → `--agents` (JSON в CLI) → проект →
`~/.claude/agents/` → плагины. Изменения подхватываются без перезапуска **[док]**. Для тестов агента можно не
писать файл: `claude -p --agents '{"имя":{…}}'` **[док] [эксп]**.

### 2.2. Поля frontmatter (имена в camelCase, неизвестные молча игнорируются)

| поле | что делает | метка |
|---|---|---|
| `name`, `description` | обязательные. Имя приходит в хуки как `agent_type` | [док] [эксп] |
| `tools` | allowlist **имён** инструментов. Без поля — наследует всё | [док] [эксп] |
| `disallowedTools` | denylist; применяется до `tools`. `Bash(git push *)` здесь убирает **весь** Bash | [док] |
| `model` | `opus`, `sonnet`, `haiku`, `fable`, полный ID или `inherit` | [док] [эксп] |
| `permissionMode` | `default`, `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan` | [док] |
| `skills` | список скиллов, **полное тело которых вставляется при старте** (до 32). Доступ к остальным скиллам не ограничивает | [док] [эксп] |
| `hooks` | хуки только на время работы агента; `Stop` превращается в `SubagentStop`. У проектного агента требуют принятого доверия к папке | [док] |
| `mcpServers` | MCP только для агента | [док] |
| `maxTurns` | лимит ходов; по достижении вывод помечается неполным | [док] |
| `memory` | `user` / `project` / `local` — своя постоянная память агента (включает Read/Write/Edit) | [док] |
| `background` | `true` — всегда в фоне | [док] |
| `omitClaudeMd` | `true` — без CLAUDE.md (и, по эксперименту, без индекса автопамяти) | [док] [эксп] |
| `isolation: worktree` | агент работает во временном git worktree | [док] |
| `effort`, `color` (`red`, `blue`, `green`, `yellow`, `purple`, `orange`, `pink`, `cyan`), `initialPrompt`, `autoCompactWindow` | как названо | [док] |

### 2.3. Что агент может

- **Вызывать скиллы** через `Skill`, если инструмент есть в `tools` **[док] [эксп]**: агент-проба вызвал
  `pelican-weather`, прочитал его reference и запустил скрипт. Субагент с `Skill` видит тот же листинг,
  с теми же `skillOverrides` **[эксп]**. Запретить — убрать `Skill` из `tools`.
- **Предзагрузка `skills:`** работает **[эксп]**: строка из тела предзагруженного скилла была в контексте агента
  без вызова. Скилл с `disable-model-invocation: true` предзагрузить нельзя **[док]**.
- **Запускать других агентов — да, по умолчанию** **[док] [эксп]**: агент с `Agent` в `tools` запустил
  general-purpose (`spawn_depth: 2`, `parent_task_id` в потоке). Глубина по умолчанию — три уровня под главной
  сессией (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, `"1"` выключает вложенность) **[док]**.
  **Чтобы агент не запускал агентов — не давать `Agent` в `tools`** (или `disallowedTools: Agent`) **[док]**.
  Форк-скилл получает `Agent` всегда (тип general-purpose) **[эксп]**.
- Ограничение путей: `tools` ограничивает только имена **[док]**. Пути — правила `permissions` (`Edit(src/stories/**)`)
  или хук `PreToolUse`, в том числе в `hooks:` самого агента **[док]**.

### 2.4. Что агент получает при старте

| что | обычный агент | `omitClaudeMd: true` | Explore / Plan | метка |
|---|---|---|---|---|
| тело агента как системный промпт + окружение | да | да | — | [док] |
| задание от вызывающего | да | да | да | [док] |
| `CLAUDE.md` проекта (вся иерархия) | **да** | нет | нет | [док] [эксп] |
| индекс автопамяти `MEMORY.md` | ⚠ **да** | нет | — | [эксп] |
| снимок git status | да | да | нет | [док] [эксп] |
| история разговора главной сессии | нет | нет | нет | [док] |
| листинг скиллов | только если есть `Skill` | — | — | [эксп] |

⚠ Документация: «не получает вашу auto memory». Эксперимент в этом репозитории (`--agents`, агент с одним `Read`,
без вызова инструментов) дословно процитировал строки `MEMORY.md` пользователя. С `omitClaudeMd: true` индекса
не было. Похоже, индекс памяти едет вместе с блоком CLAUDE.md. Считаем, что **агент видит и CLAUDE.md, и индекс
памяти**, пока не включён `omitClaudeMd`.

### 2.5. Хуки на действиях агента

- Хуки из `.claude/settings.json` срабатывают на инструментах агента **[док] [эксп]**: `PostToolUse` на `Write`
  агента пришёл с `agent_id` и `agent_type: "probe-agent"`. В главной сессии этих полей нет. Хук может по
  `agent_type` выбирать быстрый режим для `chapter-writer`.
- Сообщение хука (exit 2, stderr) видит **сам агент**, а не главная сессия **[эксп]**: агент процитировал
  «PostToolUse:Write hook blocking error from command: …: HOOK-POST-777». Значит, вывод хука засоряет контекст
  агента — нужен короткий вывод.
- `SubagentStart` срабатывает на каждом агенте, включая вложенного и форк-скилл; матчер — имя агента **[док] [эксп]**.

## 3. Хуки

### 3.1. Формат в `.claude/settings.json` **[док] [эксп]**

```json
{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|clear|compact",
        "hooks": [ { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/scripts/hooks/session-start.sh" } ] }
    ],
    "PostToolUse": [
      { "matcher": "Write|Edit",
        "hooks": [ { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/scripts/hooks/post-edit.sh", "timeout": 60 } ] }
    ]
  }
}
```

- Матчер из букв, `|`, `,` — точные имена; иначе — регулярное выражение без якорей **[док]**.
- Поле `if` с синтаксисом правил разрешений (`"Edit(src/stories/**)"`) сужает срабатывание на инструментах **[док]**.
- `timeout` в секундах, по умолчанию 600 **[док]**. `$CLAUDE_PROJECT_DIR` — корень проекта, даже если сессия
  ушла в worktree **[док]**.
- Хуки из разных файлов складываются, а не заменяют друг друга **[док]**. В `-p` в непроверенной папке
  проектные хуки сработали **[эксп]**.

### 3.2. Вход хука

JSON на stdin: `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`. У инструментов —
ещё `tool_name`, `tool_input` (пути абсолютные), `tool_use_id`, у `PostToolUse` — `tool_response`, у агента —
`agent_id`, `agent_type` **[док] [эксп]**. У `SessionStart` — `source`
(`startup` / `resume` / `clear` / `compact` / `fork`) **[док]**.

### 3.3. Что из вывода видит модель

| событие и вывод | видит ли модель | метка |
|---|---|---|
| `PostToolUse`, exit 0, обычный stdout | **нет** (только debug-лог) | [док] [эксп] |
| `PostToolUse`, exit 0, JSON `hookSpecificOutput.additionalContext` | да: «PostToolUse:Write hook additional context: …» рядом с результатом | [док] [эксп] |
| `PostToolUse`, exit 2, stderr | да: «PostToolUse:Write hook blocking error from command: …: <stderr>». Действие не отменяется — инструмент уже отработал | [док] [эксп] |
| `PostToolUse`, JSON `{"decision":"block","reason":…}` | `reason` рядом с результатом | [док] |
| exit 0, stderr | никогда | [док] |
| другой код выхода | не видит; пользователю — первая строка stderr | [док] |
| `SessionStart`, обычный stdout или `additionalContext` | да, в начале разговора: «SessionStart:startup hook success: …» | [док] [эксп] |

- Каждое поле вывода — не больше 10 000 знаков. Больше — модель получит путь к файлу и превью на 2000 знаков,
  и читать файл ей никто не велит **[док]**. Вывод хука держим коротким.
- В `stream-json` хук виден событиями `hook_started` / `hook_response` со `stdout`, `stderr`, `exit_code` **[эксп]**.
- ⚠ **Запись файла через `Bash` не ловится матчером `Write|Edit`** **[эксп]**: на просьбу «создай файл» модель
  сделала `mkdir && echo > file` через Bash, и хук не сработал. Для `src/stories/**` нужен ещё матчер `Bash`
  (или запрет записи через Bash правилом/`PreToolUse`), иначе быстрая проверка пропустит правки.

## 4. `claude -p` для тестов

### 4.1. Холодный читатель: пустой каталог, без инструментов **[эксп]**

```bash
mkdir -p "$TMP/cold" && cd "$TMP/cold"          # пустой каталог вне репозитория
claude -p "$PROMPT" \
  --model opus \
  --tools "" \                                  # ни одного встроенного инструмента
  --strict-mcp-config \                         # ни одного MCP (без --mcp-config)
  --setting-sources "" \                        # не читать user/project/local settings
  --disable-slash-commands \                    # ни скиллов, ни команд
  --settings '{"autoMemoryEnabled":false}' \    # без автопамяти
  --system-prompt "$ROLE" \                     # вместо системного промпта Claude Code
  --no-session-persistence \                    # не писать сессию на диск
  --output-format json < /dev/null
```

- Проверка: модель на вопрос «что у тебя в контексте» ответила — CLAUDE.md нет, памяти нет, навыков нет,
  инструментов нет. Остался блок окружения (каталог, платформа). Вход — около 1000 токенов **[эксп]**.
- Тот же вызов **из каталога репозитория** даже с `--tools ""` подтянул CLAUDE.md проекта, индекс памяти
  пользователя и общий системный промпт (около 8000 токенов) **[эксп]**. Поэтому — только пустой каталог.
- `--bare` для этого не годится: без `ANTHROPIC_API_KEY` пишет «Not logged in», вход через claude.ai он не
  использует **[эксп]**.
- `< /dev/null` обязателен в скриптах: иначе `-p` ждёт stdin 3 секунды и печатает предупреждение в вывод **[эксп]**.
- Переписку передавать в промпте или через stdin (`cat chat.txt | claude -p …`) **[док]**.

### 4.2. Тест срабатывания: какой скилл вызван **[эксп]**

```bash
claude -p "$PHRASE" --model opus --output-format stream-json --verbose \
  --no-session-persistence --strict-mcp-config --max-turns 3 < /dev/null > run.jsonl
```

Каждая строка — JSON-событие:
- `{"type":"system","subtype":"init", "skills":[…], "agents":[…], "plugins":[…], "mcp_servers":[…]}` — что
  загружено (удобно проверять, что окружение чистое);
- `{"type":"assistant","message":{"content":[{"type":"tool_use","name":"Skill","input":{"skill":"<имя>"}}]}}` —
  **вызов скилла**. Ответ: `tool_result` «Launching skill: <имя>»;
- события из агента несут `parent_tool_use_id` (вложенность), запуск агента — `system/task_started` с
  `subagent_type` и `spawn_depth`;
- `{"type":"system","subtype":"permission_denied","tool_name":"Bash","tool_use_id":"…","decision_reason_type":…}` — отказ в правах по ходу: приходит после `tool_use` и до `tool_result` (`is_error: true`). Прогон, оборванный на вызове `Skill`, до `result` не доживает — отказ на сам `Skill` виден только здесь **[эксп, T-17]**;
- `{"type":"result","result":"…","usage":{…},"permission_denials":[{tool_name, tool_use_id, tool_input}]}` — итог и все отказы прогона.

**Одна команда на вызов Bash.** Составные команды (`;`, `&&`, `|` с переменной, `>`, `$?`, `for` с переменной) правило `Bash(npm run story*)` не покрывает целиком — отказ «multiple operations» или «variable can't be checked» **[эксп, W1]**. В `SKILL.md` команды пишутся по одной.

Срабатывание = первый `tool_use` с `name == "Skill"` в событиях без `parent_tool_use_id`. Если ни одного —
«ничего». Результат недетерминирован, поэтому на фразу — `lab.triggers.runs_per_phrase` прогонов (не меньше
`lab.triggers.runs_per_phrase_min`) и доля: фраза проходит, если нужный скилл вызван не реже `lab.triggers.min_share`,
а чужой скилл или вызов на фразе «ничего» — не чаще `lab.triggers.max_false` (ключи — `docs/playbook/thresholds.json`).
`--max-turns` обрывает прогон после N ходов (выход с ошибкой **[док]**). Для теста срабатывания это нормально: нужен только первый вызов.

## 9. Что это значит для плана

### §4 «Контракт скилла» — подтвердилось

- Структура `SKILL.md` + `references/` + `scripts/` — штатная. Ядро от `skill.core.min_lines` до `skill.core.max_lines` строк
  укладывается в рекомендацию документации до 500.
- В листинг идут только имя и описание; references грузятся, только если `SKILL.md` велит их прочитать.
  Правило «на каждой развилке — какой reference читать» остаётся обязательным.
- `description` не длиннее `skill.description.max_chars` — разумно: лимит строки 1536, а 21 скилл с описанием такой
  длины занимает меньше трети из 22 000 свободных знаков (наша оценка по замеру раздела 1.4).

### §4 — поменять

1. **Не использовать `when_to_use`.** Он просто дописывается к описанию и тратит тот же бюджет. Симптомы
   словами автора — прямо в `description`, главное в начале.
2. **Ссылки:** скрипты — через `${CLAUDE_SKILL_DIR}/scripts/x.mjs`; references — относительной ссылкой markdown.
   В шаблон `SKILL.md` внести обе формы. Скрипты считают пути от `import.meta.url` или корня проекта,
   cwd = корень проекта.
3. **Строка версии** — в `metadata: {version: …}` frontmatter, Claude Code её игнорирует.
4. В `allowed-tools` модулей с командами — `Bash(npm run story*)`, `Bash(npm run -s story*)` и
   `Bash(node ${CLAUDE_SKILL_DIR}/scripts/*)`, чтобы команды подсчёта не спрашивали разрешения. Только снимает
   запросы, не ограничивает. Не `story:*`: хвост `:*` равен « *», и `npm run story:lint` под правило не подходит
   (проверено экспериментом, LOCAL-03, `docs/lab/runs/X-E2mini/permissions.md`).
5. **Самое важное — в первые строки `SKILL.md`**: после сжатия контекста от скилла остаются первые 5000 токенов.

### §5 «Скиллы» — поменять пункт про скрытие модулей

«Если T-00 подтвердит скрытие из листинга, модули скрываются и вызываются чтением `SKILL.md` по пути» —
**заменить**. Полное скрытие (`disable-model-invocation` / `off`) запрещает вызов моделью, а чтение по пути
Claude Code считает обходом. Решение:
- 8 входов — обычные скиллы с полным описанием;
- 13 модулей — `user-invocable: false` (не мусорят в меню `/`, остаются в листинге с коротким описанием и
  вызываются через `Skill`). Сейчас бюджет позволяет держать описания у всех 21;
- если бюджет станет тесным (новые плагины, другой автор) — модули в `skillOverrides: "name-only"`
  проектного `.claude/settings.json`: вызов по имени из таблицы «симптом → скилл» работает (Э3).

### §6 «Агенты» — подтвердилось

- `tools`, `model: opus`, предзагрузка `skills:`, фоновые агенты, `color` — всё есть.
- `tools` ограничивает имена, пути — `permissions` или `PreToolUse` (в т. ч. `hooks:` агента).
- Хуки срабатывают на правках `chapter-writer`; быстрый режим хука нужен.
- `cold-reader` через `claude -p` из пустого каталога — правильно, и это **единственный** чистый способ.

### §6 — поменять

1. **«Агенты не запускают агентов» не выполняется само.** Во всех четырёх агентах — `tools` без `Agent`.
   Проверка конвейера: grep по `.claude/agents/*.md`, что `Agent` в `tools` нет.
2. **`story-auditor` оставить агентом**, а не заменять форк-скиллом. `context: fork` существует, но скилл с ним
   форкается всегда, а диагностические скиллы нужны и в главной сессии (`story-fix`, `story-review` inline).
   Аудитор: `tools: Read, Bash, Skill`, без `Agent`; `story-review` говорит ему, какой скилл вызвать через `Skill`.
   Если какому-то аудиту нужна только изоляция и никогда inline — тогда `context: fork` + `agent: story-auditor`.
3. **`cold-reader` как агент с «нет tools» — невозможен честно**: агент получает CLAUDE.md, индекс памяти и
   git status. Строку таблицы поменять: «агента нет, только `npm run story:cold-read`» (раздел 4.1). Если
   агент всё же нужен — `omitClaudeMd: true`, но git status и формулировка задания остаются утечкой.
4. **Ограничение путей:** `chapter-writer` и `story-architect` пишут через `Write`/`Edit`. Хук `PreToolUse`
   с проверкой `tool_input.file_path` и `agent_type` (вход хука) — надёжнее правил разрешений, которые
   глобальны для сессии. Bash у `chapter-writer` — только `npm run story*` через `PreToolUse` на `Bash`.
5. **`permissionMode`** для пишущих агентов — `acceptEdits` (поле есть **[док]**; что фоновый агент без него
   упрётся в запросы — наша оценка, не проверялось).

### §10 Т-11 и Т-12 — уточнения

- T-11: `PostToolUse` — матчер `Write|Edit` **и** `Bash` (или запрет записи в `src/stories/**` через Bash),
  иначе правка через Bash проскочит. Вывод модели — `additionalContext` или exit 2 + stderr; обычный stdout она
  не видит. Вывод не длиннее `skill.hook.max_output_chars`; по `agent_type` выбирать быстрый режим.
- T-11: `SessionStart` — обычный stdout уже попадает в контекст; матчер `startup|resume|clear|compact`, чтобы
  статус возвращался и после сжатия.
- T-12: разбор по разделу 4.2; запускать с `--no-session-persistence --strict-mcp-config`; первый `Skill`
  без `parent_tool_use_id`. Перед прогоном сверять `init.skills` с ожидаемым набором, чтобы чужой плагин не
  испортил замер.
