# Приёмы структуры на ink и переходы между структурами

Рабочие формы для скелета: как записать структуру на ink так, чтобы её увидели бот и `story:lint --plan`.
Каталог с ценой — `structures.md`, развилки «что выбрать» — `decisions-structure.md`. Примеры компилируются,
теги — только `ready` из `docs/capabilities.json`; строки в примерах — строки-сцены скелета, а не реплики
начисто (реплики пишет `chapter-write` по `docs/style.md`).

## Горлышко и отложенное ветвление

### bateman-game-writing:PAT-01 · Ветвление с бутылочным горлышком — основная структура relayer

Развилка внутри главы, ветки сходятся до следующего `#chapter` в горлышке, разница проходит через него только
переменными (branch and bottleneck). Цена — текст веток плюс одна-две условные строки в горлышке на каждую
переменную; сложность растёт с числом переменных, а не веток.
- **Когда не работает.** Ветки не оставляют следа в переменных — это уже окраска, а не горлышко. Ловушки:
  переменная ставится, но в горлышке не читается (C-01, C-03); горлышко повторяет текст ветки дословно; третья
  кнопка не ставит переменную и для сюжета равна второй.
- **Масштаб.** 5 сообщений: одна кнопка с `~` и одна условная строка сразу после. 50: горлышко на границе
  главы, и в нём читаются все переменные главы.
- basis: secondary · `bateman-game-writing:PAT-01`.

```ink
# contact: gleb, Глеб, teal
VAR took_side = ""
-> ch2
=== ch2 ===
Глава 2 · Склад #sys:gleb #chapter
[2.1] Глеб у склада: охранник спит, ключ на столе #from:gleb
* [Бери ключ #to:gleb]
    ~ took_side = "key"
    [2.2] Глеб берёт ключ, сторож шевелится #from:gleb
* [Уходи оттуда #to:gleb]
    ~ took_side = "leave"
    [2.2б] Глеб уходит, но фотографирует журнал #from:gleb
- -> ch2_bottleneck
=== ch2_bottleneck ===
[2.3] горлышко: утром склад опечатан, у всех — новость #from:gleb
{took_side == "key": [2.4] Глеб: ключ теперь улика против меня #from:gleb}
{took_side == "leave": [2.4б] Глеб: в журнале наша фамилия #from:gleb}
-> END
```

#### bateman-game-writing:PAT-01#нюанс · горлышко на 5 и на 50 сообщениях

Нюанс по масштабу: на 5 сообщениях горлышко — одна кнопка с `~` и одна условная строка сразу после, и это
уже вся структура. На 50 горлышко стоит на границе главы, и в нём читаются все переменные, которые глава
записала, — иначе выбор главы пропадает до следующей главы.

### mobile-interactive-stories:PAT-01 · Branch and bottleneck на рынке историй с выбором

Основная форма крупных приложений интерактивных историй — ветвление с бутылочным горлышком: ветки
расходятся на сцену и сходятся к общему событию.
Цена — плюс 1–3 реплики на ветку, сложность не растёт. Термин пришёл из англоязычного сообщества IF, к рынку
его применили мы.
- **Когда не работает.** Последняя глава, где ветки должны дойти до разных финалов. Ветки без следа в переменной —
  через две главы выбор забыт (C-04 у `story-choices`).
- basis: secondary · `mobile-interactive-stories:PAT-01`.

#### mobile-interactive-stories:PAT-01#нюанс · на 5 сообщениях узлы не нужны

Нюанс: на 5 сообщениях горлышко — сразу следующая реплика, ветки различаются одной строкой. Тогда это уже
дружелюбный коридор, отдельные узлы не нужны: weave со сборкой `-` (как у `chapter-write`). Отдельный узел —
когда ветка живёт дольше двух-трёх строк или в неё приходят из нескольких мест.

### ashwell-standard-patterns:PAT-11 · Delayed branching — отложенное ветвление

Основной способ сделать горлышко дешёвым: выбор не разводит узлы, а меняет счётчик, который проверяется на
пороге через одну-две главы. Цена низкая по узлам, но нужна дисциплина: у каждого счётчика хотя бы один порог,
который игрок способен заметить; порог, недостижимый в случайных прохождениях, — мёртвый текст.
- **Когда не работает.** Игрок должен увидеть последствие сразу — тогда поверх записи нужна реплика-отклик
  (дружелюбный коридор). Записей много, а чтений мало — выбор не чувствуется (C-02, C-09).
- basis: secondary · `ashwell-standard-patterns:PAT-11`; порог держит одна функция — `emshort-structures:PAT-11`.

```ink
# contact: zoya, Зоя, rose
VAR warm = 0
-> ch1
=== function reply_tone() ===
{ warm >= 2:
    ~ return "с тобой не надо спорить. скажу тебе первой"
- else:
    ~ return "ладно. позже расскажу"
}
=== ch1 ===
Глава 1 · Звонок #sys:zoya #chapter
[1.1] Зоя: мне снова звонили с того номера #from:zoya
* [Я рядом #to:zoya]
    ~ warm += 1
* [Не бери трубку #to:zoya]
- [1.2] Зоя: он назвал моё старое имя #from:zoya
* [Я тебе верю #to:zoya]
    ~ warm += 1
* [Может, ошибся номером? #to:zoya]
- -> ch3
=== ch3 ===
Глава 3 · Имя #sys:zoya #chapter #delay:2h
[3.1] {reply_tone()} #from:zoya
-> END
```

#### ashwell-standard-patterns:PAT-11#нюанс · нехватка отложенного ветвления — частая ошибка

Нюанс: практик выбора считает нехватку отложенного ветвления первой из четырёх частых ошибок — если каждый
выбор ветвит сразу, выборов в истории может быть мало, и остальные становятся мелкими. Отложенное чтение
должно назвать поступок словами («с тобой не надо спорить»), а не просто сменить тон (R-49 у `story-choices`).

### emshort-structures:PAT-11 · Счётчик тона с функцией-реакцией

Наше расширение scored choice: много кнопок различаются только тоном; тональная кнопка пишет `~ warm ± 1` и
сразу сходится, а функция `reply(warm)` в другом узле и главе выдаёт реакцию. Порог живёт в функции, узлы
только вызывают её. Цена — одна строка `~` на кнопку и одна функция на собеседника.
- **Когда не работает.** Выбор меняет факты сюжета — тогда это флаг поступка, а не тон. Ловушки: счётчик
  читается только в финале; порог дублируется в узлах с разными числами (пример — функция выше).
- basis: model (наше расширение) · `emshort-structures:PAT-11`.

## Переходы между структурами

### ashwell-standard-patterns:PAT-12 · Из коридора в ветвление с горлышком

Когда применять: доля узлов с посещаемостью 100% больше `skill.plan.spine.max_share`, а выборы в основном меняют реплики. Шаги:
каждую косметическую развилку привязать к одной из осей (`~ ось += 1`); в начале каждой главы со второй
поставить отклик на ось — условную реплику, новую кнопку, другой порядок; в одном-двух горлышках сделать
настоящее расхождение узлов по оси с 2–3 исходами и свести ветки к следующей главе. Цена — 10–20% текста
сверху; узлов прибавляется немного, условных строк — много.
- **Когда не работает.** Накачать переменные и нигде их не прочитать: после перехода сверь записи и чтения
  (`npm run story:vars`, C-01, C-02).
- basis: secondary · `ashwell-standard-patterns:PAT-12`.

#### ashwell-standard-patterns:PAT-12#нюанс · в истории на 1–2 главы — окраска лучше

Нюанс: не применять, если у истории одна-две главы — накопить состояние негде. Лучше усилить окраску
(дружелюбный коридор с разными ответами) и финал, где последняя кнопка задаёт намерение, а немногое
накопленное — исход (`ashwell-standard-patterns:P-11` у `story-endings`).

### ashwell-standard-patterns:PAT-13 · Из коридора с последним выбором — в шляпу

Когда финал решается последней кнопкой или каскадом проверок в последнем узле, а прошлые главы на исход почти
не влияют. Шаги: перенести проверку итога на одну-две главы раньше финала (`~ route = …`); дописать линии,
каждая — почти коридор; оставить финальную кнопку, но так, чтобы её смысл зависел от линии. Цена — 1,5–2
главы текста на линию.
- **Когда не работает.** Пять и больше линий — это уже несколько историй, бюджет взрывается. Каждую линию бот
  должен проходить достаточно часто: доля ниже `C-40.rare_share` — повод проверить пороги (C-40).
- basis: secondary · `ashwell-standard-patterns:PAT-13`.

#### ashwell-standard-patterns:PAT-13#нюанс · перед распределением сверить экранное время

Нюанс: перед переносом распределения сверь экранное время кандидатов — у кого игрок провёл больше реплик, тот
выигрывает заранее (C-17 у `story-choices`). И не переноси распределение в главу 1: ранняя шляпа оставляет
почти неинтерактивную вторую половину (`ashwell-standard-patterns:PAT-06#нюанс` в `structures.md`).

## Параллельные пути, воронка, критический путь

### bateman-game-writing:PAT-02 · Хребет с параллельными путями

Нужно ощущение свободы маршрута, а цель одна: два-три пути (parallel paths) расходятся и сходятся на хребте.
Цена — два коротких узла и одна условная строка; дешевле горлышка, потому что пути не обязаны что-то менять
дальше. Путь с открытием контакта (`#unlock`) выглядит богаче — дай второму свою награду: тишину, время, деталь.
- **Когда не работает.** Пути различаются только длиной паузы — пустой выбор. Если `route` нигде не читается,
  это компромисс-окраска: честно, пока на карточке не обещано ветвление глав.
- basis: secondary · `bateman-game-writing:PAT-02`.

#### bateman-game-writing:PAT-02#нюанс · путь вдесятеро дольше — уже воронка

Нюанс, пограничный случай: если один путь в реальном времени в 10 раз дольше другого, он уже не параллельный,
а воронка — по нему пройдёт тот, кто не дождётся паузы на другом. Держи разницу в паузах путей не больше чем
втрое (наша оценка); по клику разница исчезает, поэтому судят по реальному времени.

### dille-ultimate-guide:PAT-02 · Воронка — ветки расходятся внутри главы и сходятся на её границе

Funneling: главы в реальном времени, следующая начинается через часы; схождение на границе главы дёшево, а
память выбора — в переменной. Цена — одна переменная на развилку и 1–3 строки условного текста в точке
схождения. Схождение сразу после кнопки, без своего узла и реакции, игрок замечает: ответ одинаковый.
- **Когда не работает.** Выбор должен изменить события следующей главы, а не только реплики — нужен узловой
  путь или отдельная ветка. Переменную не читают в точке схождения — воронка косметическая (C-01).
- basis: secondary · `dille-ultimate-guide:PAT-02`.

#### dille-ultimate-guide:PAT-02#нюанс · чтения после воронки — с запасом

Нюанс: на 5 сообщениях схождение воронки должно отличаться хотя бы одной репликой. На 50 нужно 2–3 чтения в
следующей главе: одно игрок может пропустить, отвлёкшись на другой чат, и тогда выбор для него пропал
(дальность отклика — C-04 у `story-choices`).

### dille-ultimate-guide:PAT-03 · Критический путь с необязательными узлами

Главы-расследования: одна обязательная улика и несколько дополнительных (critical path). Цена — хаб и по узлу
на ветку; каждая необязательная ветка требует хотя бы одного чтения своей переменной. Нельзя давать
необязательную улику всем через другой узел — награда обесценивается.
- **Когда не работает.** Короткая глава-кульминация: отступления сбивают темп. Выход из хаба открыт до
  обязательного узла — критический путь рвётся (C-19).
- basis: secondary · `dille-ultimate-guide:PAT-03`.

#### dille-ultimate-guide:PAT-03#нюанс · обязательный контакт назван перед хабом

Нюанс: если обязательный контакт не назван в последней реплике перед хабом, игрок с короткой сессией застрянет
— он не помнит, кому ещё не писал, и бродит по необязательным веткам. Последняя реплика перед хабом называет
того, без кого критический путь не пройти.

### dille-ultimate-guide:PAT-04 · Узловая структура: контакт как место

Nodal: середина истории, у игрока 3–5 открытых чатов, у каждого контакта своя короткая дуга (вопрос →
сопротивление → улика), порядок свободный; глава кончается, когда дуги закрыты или наступил срок. В ink — хаб,
у каждой ветки свой `=== x_end ===` с `x_closed = true`; выход — кнопка по условию или «день закончится» с
`#label`. Цена большая: 2–4 узла на контакт, выгоднее всего, когда дуги отдают улики друг другу.
- **Когда не работает.** Первые пять минут, пока игрок не знает людей, и финал, где нужен один фокус. Дуги не
  пересекаются — это пять отдельных историй.
- basis: secondary · `dille-ultimate-guide:PAT-04`.

#### dille-ultimate-guide:PAT-04#нюанс · разные паузы создают ложный приоритет

Нюанс: в первой главе не больше двух дуг (`attn.chats.waiting`). В реальном времени дуга с паузой в часы в
одном чате и дуга с паузой в минуту в другом создают ложный приоритет: игрок решит, что медленный чат неважен.
Паузы параллельных дуг выравнивай по смыслу, а не оставляй случайными.

## Счётчики

### failbetter-qbn:PAT-02 · Цепочка на одном счётчике

Questicle или venture: линия с началом, серединой и концом внутри главы или двух, шаги строго по порядку,
`stage = 1 → 2 → 3`, финал при `stage >= 3` и флаг-награда. Цена — одна переменная на линию; дешевле любой
связки флагов.
- **Когда не работает.** Порядок не важен — это хаб сторилетов (`hubs.md`). Ловушки: стадии поднимают в разных
  главах разные авторы; пропуск стадии (`stage = 3` сразу из 1).
- basis: secondary · `failbetter-qbn:PAT-02`.

#### failbetter-qbn:PAT-02#нюанс · на коротких — порядок узлов вместо stage

Нюанс: цепочка работает при любой длине. На коротких историях счётчик `stage` не нужен — его заменяет порядок
узлов: шаг 2 просто идёт после шага 1. Счётчик окупается, когда линия цепочки прерывается другими чатами и
возвращается через главу.

### emshort-structures:PAT-10 · Прогресс и угроза

Серия однотипных испытаний (взлом, погоня, допрос), где ошибки копятся, а не обрывают историю сразу: верно —
`progress += 1`, ошибка — `menace += 1`; ворота: угроза выше порога — провал, прогресс — успех. Цена — 2
переменные и 2 проверки вместо дерева ошибок; по сути смертельный коридор, где ошибка не сразу обрывает.
- **Когда не работает.** Одно решение с ясной ценой. Угрозу видно только цифрой в отладке — собеседник должен
  нервничать сильнее с каждой ошибкой; петля на `*` вместо `+` даёт тупик.
- basis: secondary · `emshort-structures:PAT-10`; приём угрозы в тексте — F-14 у `story-choices`.

```ink
# contact: efim, Ефим, slate
VAR progress = 0
VAR menace = 0
-> door
=== door ===
{
- menace >= 2: -> caught
- progress >= 2: -> inside
}
[3.2] Ефим у кодового замка, за дверью шаги #from:efim
+ [Набери год постройки #to:efim]
    ~ progress += 1
    [3.3] щёлкнуло. ещё один #from:efim
    -> door
+ [Набери день рождения сторожа #to:efim]
    ~ menace += 1
    [3.3б] пищит. шаги ближе #from:efim
    -> door
=== caught ===
[3.4] Ефим: свет в коридоре, я ухожу #from:efim
-> END
=== inside ===
[3.4] Ефим: открыто. внутри архив #from:efim
-> END
```

### emshort-structures:PAT-12 · Петля с ростом

Loop-and-grow: история идёт днями или сменами, каждый день повторяет рамку (утро — разговор — вечер), но
состояние копится и рамка звучит иначе; у нас день и так задаёт реальное время. Петля — на `+`: вариант `*`
исчезает после первого дня и даёт тупик на втором (на этом обожглись при проверке примера в разборе).
- **Когда не работает.** Каждый день приносит новое событие — рамка не нужна, это обычные главы. Дней больше
  3–5 — в реальном времени неделя одинаковых утр; рамка не меняется — игрок видит повтор.
- basis: secondary · `emshort-structures:PAT-12`.

#### emshort-structures:PAT-12#нюанс · рамка сдвигается, даже если игрок не меняется

Нюанс: даже если игрок каждый день выбирает одно и то же, рамка всё равно должна сдвинуться — день недели,
погода, усталость героя. Нужно не меньше двух кругов петли (иначе это не петля); на 50 сообщениях — три круга, на каждом 1–2
строки по счётчику.
