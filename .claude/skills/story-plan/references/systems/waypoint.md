# Разговор, который ведёт персонаж: путевые точки и повторный вход

Как устроить разговор, где у собеседника своя цель, а игрок тянет время или выбирает темы. Это форма сцены внутри
главы; на плане — строка «разговор по путевым точкам» в главе и переменные, которые он пишет.

### emshort-structures:SYS-4 · Нарратив по путевым точкам (waypoint)

**Элементы.** Метод путевых точек (waypoint): сеть тем; реплики висят на переходах между темами, а не на самих темах; темы-триггеры двигают сюжет;
персонаж прокладывает путь к ближайшему триггеру; пройденные переходы весят меньше; есть запасной текст; есть темы,
куда может свернуть только игрок, и они уводят в другие сцены. Метод описан на примере короткой игры, где игрок —
говорящий попугай.
**Шаги.** Нарисовать сеть тем (граф на 3–8 тем) → написать реплику на каждый переход → отметить триггеры → назначить
игроку темы, недоступные персонажу → прогнать: из любого состояния персонаж доходит до триггера.
**Если шаг пропустить.** Без реплик на переходах персонаж отвечает «не по теме», как бот; без понижения весов ходит
одним путём; без запасного текста — тупик; без тем только для игрока у игрока нет рычага, он только тормозит.
**Ошибки понимания.** «Игрок ведёт разговор»: ведёт персонаж, игрок проявляет подтекст и задерживает. «Это дерево
диалога»: нет, реплика определяется парой «откуда — куда».
**Короткая форма.** Три-пять тем, переходы руками, после двух уводов персонаж говорит прямо.

### emshort-structures:PAT-09 · Разговор по путевым точкам

У собеседника своя цель (выманить, признаться, попросить), а игрок может тянуть время и уводить разговор: переменная
`topic`, счётчик уводов `pulled`, любой путь ведёт к цели. Цена — реплика на каждый переход; в ink держи сеть в 3–5
темах.
- **Когда не работает.** Игрок сам ведёт разговор, у собеседника нет цели. Ловушки: на увод персонаж отвечает не по
  теме; нет прямого выхода, разговор зацикливается; приём растянут на всю главу, и игрок только тормозит чужой
  разговор — узкую роль игрока сам практик признаёт слабостью.
- basis: secondary · `emshort-structures:PAT-09`.

```ink
# contact: arina, Арина, violet
VAR pulled = 0
-> talk
=== talk ===
[5.1] Арина: мне нужен твой ответ про пятницу. у гаража — это ты? #from:arina
- (ask)
* {pulled < 2} [Как там Тимур? #to:arina]
    ~ pulled += 1
    [5.2] Арина: Тимур спит. не уходи от вопроса #from:arina
    -> ask
* {pulled < 2} [А ты сама где была? #to:arina]
    ~ pulled += 1
    [5.2б] Арина: дома. я спрашиваю тебя #from:arina
    -> ask
* [Да, я. там стояла серая машина #to:arina]
    [5.3] Арина: вот. теперь рассказывай всё #from:arina
    -> END
* {pulled >= 2} [Не скажу #to:arina]
    [5.3б] Арина: тогда я спрошу у Лады. и она скажет #from:arina
    -> END
```

После двух уводов персонаж говорит прямо, а кнопки увода пропадают (`pulled`) — прямой выход есть всегда.

### emshort-structures:PAT-04 · Узел разговора с повторным входом

Нужно выдать экспозицию или улики, порядок неважен, и хочется узнать, что интересует игрока (re-enterable
conversation node): `*` — тема пропадает после выбора, `+` — выход доступен всегда, счётчик `asked` ограничивает число
тем. Цена — одна реплика на тему плюс флаг, ветвления нет.
- **Когда не работает.** Темы зависят друг от друга по порядку — тогда цепочка. Ловушки: нет выхода без перебора всех
  тем; все темы обязательны — линейный текст с лишними кликами; флаги интереса нигде не используются (C-01).
- basis: secondary · `emshort-structures:PAT-04`; пример хаба тем — `hubs.md`.
