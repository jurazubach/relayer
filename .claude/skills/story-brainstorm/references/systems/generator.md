# Система: раунд направлений как генератор

Раунд направлений — генератор: из сырой идеи он выдаёт несколько вариантов, и ценность у него та же, что у
любого генератора, — заметно разные результаты, которые проходят опись свойств. Ниже — устройство по шагам:
сначала по разбору генераторов, потом наш раунд на его основе.

## procedural-storytelling:SYS-2 · Генератор по шагам: мастер, опись, метод, выборка, различимость

Устройство генератора по главе о том, как их начинать (оригинал статьи не открылся, восстановлено по пересказам,
уверенность средняя):
1. **Художник в коробке.** Вход — что генерируем; выход — как это сделал бы мастер руками. Без шага генератор
   подражает другому генератору, а не мастеру.
2. **Опись.** Вход — несколько образцов, сделанных руками; выход — свойства, общие для всех хороших, и запреты.
   Без шага оценка — «нравится / не нравится», спор не решается.
3. **Метод.** Как собирать: из кусков по шаблону или отсевом лишнего из множества вариантов. Выбор механики —
   после описи.
4. **Проверка на выборке.** Вход — десяток результатов; выход — доля, проходящая опись. Без шага автор видит
   лучший запуск, а игрок — средний.
5. **Различимость.** Результаты различимы на глаз, а не только формально уникальны («овсянка»).
- **Ошибка понимания:** «овсянка» — не призыв к большему разнообразию, а требование заметных различий: иногда
  лучше три заметно разных варианта, чем сотни неразличимых.
- **Короткая форма:** шаги 2 и 4 — это и есть команда генерации: опись свойств, затем несколько вариантов и
  автоматические проверки.

## Наш раунд: та же система для направлений

| шаг | вход → выход | чем | что будет без шага |
|---|---|---|---|
| 0. Банк | сырая идея → похожее в банке и каталоге | `ideas-bank.mjs --query` | новое направление повторит отвергнутое или готовую историю |
| 1. Опись | идея → что автор закрепил, что запрещено (вымысел, A-01…A-06) | разговор, `fiction.md` | направления нарушат решения автора |
| 2. Таблица осей | опись → метки семи осей для всех направлений сразу | `decisions-direction.md` | направления — вариации первого |
| 3. Проверка различия | таблица → пары с числом различных осей | `directions.mjs` | перефразировки дойдут до автора |
| 4. Текст | метки → название, логлайн, «что трудно», трейлер | `premise-check.mjs`, `trailer.md` | автор выбирает по таблице, вслепую |
| 5. Проверка формы | текст → трейлер компилируется, логлайн в норме | `directions.mjs`, `premise-check.mjs` | автор увидит нерабочий трейлер |
| 6. Совет | направления → сочетания и риски по R-02, R-04, R-05, R-06 | `decisions-rounds.md` | совет «B и D сочетаются» — мнение без критерия |

- **Ошибки понимания.** «Больше направлений — больше выбора»: автор не умеет строить сюжеты и тонет в шести
  похожих вариантах; число — `skill.brainstorm.directions.count`. «Различие — в антураже»: нет, в решениях осей.
- **Короткая форма.** Идея на пять минут: три направления, четыре оси (роль, герой, правило, ставка), трейлеры.
- **Когда не работает:** автор принёс готовое направление — генерировать нечего, это шаг ядра (`story-core`).
