# Системы: роли как функции, три акта, правило → проверка

Откуда берутся оси «роль игрока», «герой» и «структура». Своими словами. Полные схемы (двенадцать стадий,
пятнадцать битов) короткая история не вмещает — `#attn-cut` в `attention.md`.

## vogler-writers-journey:SYS-2 · Восемь архетипов как функции

Восемь функций, которые должны быть в мире истории: герой, наставник, страж порога, вестник, оборотень, тень,
союзник, трикстер; один персонаж может выполнять разные функции в разных сценах.

| функция | вход → выход в сцене | без неё | ошибка понимания | у нас |
|---|---|---|---|---|
| герой | несёт риск и перемену | не за кого переживать | считать героем игрока | главный собеседник |
| наставник | страх → готовность | испытание решает случай | «мудрый старик» как тип | чаще игрок |
| страж порога | порыв → допуск | особый мир без правил | непробиваемый тупик | первый трудный контакт |
| вестник | норма → вопрос | история стоит | вестник обязан быть человеком | первый пишущий; бывает событием |
| оборотень | доверие → «верить ли?» | персонажи угадываются | злодей в маске без улик | контакт с переименованием или сменой тона |
| тень | спокойствие → угроза | нет напряжения | тень всегда внешний злодей | противник, пишущий сам |
| союзник | одиночество → опора | мысли героя не слышны | безликий помощник | часто игрок |
| трикстер | монотонность → разрядка | одна нота | обязателен комик | любой контакт в одной сцене |

- **В раунде.** Ось «роль игрока» — какие две-три функции держит игрок (наставник, союзник, вестник); ось
  «противник» — кто тень. Два направления, где игрок держит одни и те же функции, совпадают по роли.
- **Короткая форма.** Герой, тень и одна функция игрока.

## skolnick-video-game-storytelling:SYS-1 · Три акта с поворотными точками

Три акта по Филду в изложении Сколника: поворотные точки делят историю, перелом делит второй акт.

| шаг | вход | выход |
|---|---|---|
| первый акт | герой, его обычный разговор | игрок знает, что на кону |
| поворот 1 | ставка | обязательство игрока, которое нельзя забрать: ответ, деньги, ложь |
| второй акт до перелома | цель «как понимаем» | растущая цена и улики |
| перелом | улики первой половины | новая цель, сформулированная кнопкой игрока |
| второй акт после перелома | новая цель | противник в полную силу |
| поворот 2 | всё собранное | последнее решение, все сведения у игрока |
| третий акт | решение | исход, вытекающий из решения |

- **Без шага.** Без первого акта ставки пусты; без поворота 1 игрок не чувствует, что взялся, и уходит на первой
  длинной паузе; без перелома середина однообразна; без поворота 2 финал решает случай.
- **Ошибка понимания.** Первый акт — не глава «нормы»: у нас он сжат до двух-четырёх обменов внутри открытого
  вопроса (`contradictions.md`).
- **В раунде.** Ось «структура» короткой строкой: «обязательство игрока — …, перелом — …, последнее решение — …».

## cron-wired-for-story:SYS-1 · Правило для текста и проверка к нему

- **Элементы.** Книга — набор пар: наблюдение о том, как человек обрабатывает историю → правило для текста →
  проверка уже написанного.
- **Вход → выход.** Готовый черновик → места, где правило нарушено. Книга полезнее для правки, чем для первого
  черновика.
- **Без шага.** Без наблюдения правило становится догмой («никакой предыстории») и вредит там, где неуместно;
  без проверки правило не доходит до текста.
- **Ошибки понимания.** Принимать «секреты мозга» за доказанную науку; читать главы как порядок письма, а не
  проверки.
- **В раунде.** Тот же принцип у нас: правило в скилле — только с командой проверки (`directions.mjs`,
  `premise-check.mjs`) или с вопросом автору. Для истории на пять минут хватит пяти проверок: главный вопрос,
  желание, несоответствие на первом экране, конкретика, одна ось.
