# Разные направления: оси, двухпроходная генерация, банк

Модель склонна выдавать перефразировки одной идеи: два направления «про найденный телефон» с одним миром и
одной ролью игрока — это одно направление (`flow-review.md` §A шаг 1). Здесь — правило различия, как его
соблюсти генерацией в два прохода, режим «ещё» и Б-4. Считает `directions.mjs`; на глаз различие не судим.

## Правило различия

Любые два направления раунда расходятся не меньше чем по `skill.brainstorm.directions.axes_min_diff` осям из
семи (`decisions-direction.md`). Направлений в раунде — `skill.brainstorm.directions.count`. Ось сравнивается
по метке (текст до « — »): метки с долей общих основ `skill.brainstorm.axes.same_overlap` — одно значение.
- **Если** `directions.mjs` пишет «A и B расходятся по N осям» → перепиши слабое из двух по тем осям, что
  совпали (команда их называет), а не формулировку.
- **Если** различие держится на одной метке, переписанной синонимом («курьер» → «доставщик») → это то же
  значение; метка — категория, а не слово.
- **Когда не работает:** автор сам закрепил ось («игрок обязательно сыщик») — эта ось у всех одинакова, и
  различие набирается по остальным шести; закреплённую ось запиши в шапку раунда, чтобы не считать её
  нарушением.
- **Масштаб:** раунд для истории на 5 сообщений — три направления, различие по роли, правилу и ставке; для
  сезона — пять, различие и по структуре.
- basis: source · `build-plan.md` §2; `flow-review.md` §A шаг 1.

### procedural-storytelling:P-04 · Заметные различия, а не формальная уникальность

Генератор выдаёт тысячи математически разных тарелок овсянки, а человек видит одну овсянку: ценится различимость
на взгляд. Память держит факты и события, а не формулировки, — два варианта с одним смыслом в ней сливаются.
Для раунда направлений это главное правило: различия по фактам мира, роли и последствию, а синонимы не считаются
(порог — `skill.brainstorm.directions.axes_min_diff` осей).
Лучше три заметно разных направления, чем пять неразличимых.
- **Если** автор говорит «они все одинаковые» → различие формальное; смени по одной оси на каждое
  направление роль, ставку или противника, а не название и антураж.
- **Когда не работает:** если ветки (или направления) обязаны сойтись в одно — различие переносится в эхо позже.
- **Масштаб:** раунд — три различимых лучше пяти похожих; внутри истории — различие факта в следующей реплике.
- basis: secondary · опора: `procedural-storytelling:P-04`; порог доли пустых кнопок — у `story-choices`.

Варианты различаются фактом, адресатом и последствием, а не формулировкой:

```ink
# contact: mark, Марк, blue
VAR told = false
ключ от склада у тебя? #from:mark
* [Да #to:mark]
    тогда не отдавай никому #from:mark #delay:10s
* [Да. Но о нём знает соседка #to:mark]
    ~ told = true
    зачем ей это знать #from:mark #delay:10s
* [Промолчать #to:mark #silent]
    Марк не в сети #sys:mark #delay:30s
- -> END
```

#### procedural-storytelling:P-04#нюанс · различие сходящихся веток — в отложенном следствии

Нюанс: правило заметного различия не работает, когда ветки по сюжету должны сойтись: тогда различие переносится
в одну реплику-эхо позже, а не в саму ветку. На 5 сообщениях различие — факт в следующей же реплике; на 50 оно
может быть отложенным следствием, но тогда нужно эхо, иначе игрок не свяжет причину и следствие. Для раунда:
если два направления сходятся в один финал, различие обязано быть в пути, а не в развязке.

## Генерация в два прохода

1. **Таблица осей.** Сначала только метки семи осей для всех направлений сразу, без текста. Так видно, что
   совпало, и переписывать дёшево. Запусти `directions.mjs` — различие должно пройти до текста.
2. **Текст.** Потом для каждого: название, логлайн (`premise-check.mjs`), «что трудно», трейлер (`trailer.md`).
   Текст не меняет метки: если при письме роль поплыла, правь метку и перезапусти проверку.

Почему так: модель, начав с текста, пишет первое направление удачно, а остальные — его вариациями. Таблица
заставляет решить различие на уровне решений, а не формулировок. Устройство по шагам — `systems/generator.md`.
- **Когда не работает:** если автор пришёл с готовым направлением и просит «доведи» — это не раунд, а ядро
  (`story-core`).
- basis: model · опора: `procedural-storytelling:SYS-2` (опись свойств → метод → проверка на выборке).

## Источник различий: матрица и семейства

### video-three-things:PAT-02 · Матрица вариаций

Вещи ядра по строкам и столбцам; в каждой клетке — сцена, где две вещи сталкиваются; на диагонали — последствия
одной вещи. Каждая глава закрывает клетку; глава без клетки — кандидат в чужеродное. Для раунда матрица
показывает, хватит ли ядру материала: три вещи дают шесть клеток — хватит на пять глав.
- **Если** направлению не хватает клеток на заявленную длину → правило слишком узкое; добавь вещь, которая
  сочетается, или сократи длину.
- **Когда не работает:** история на одну главу — хватит одной пары.
- **Масштаб:** 5 сообщений — одна клетка; сезон — таблица до начала работы.
- basis: secondary · опора: `video-three-things:PAT-02`, `RED-09` (`flags.md`).

```ink
# contact: vera, Вера, teal
VAR heard = false
// клетка 2+3: голосовые приходят раньше × их слышит сосед
пришло голосовое от тебя. завтрашнее #from:vera
и сосед говорит, что слышал его через стену #delay:6s
* [Это не мой голос #to:vera]
    значит, запишешь #from:vera #delay:20s
* [Что там? #to:vera]
    ~ heard = true
    твой голос просит не открывать ему дверь #from:vera #delay:20s
- -> END
```

#### video-three-things:PAT-02#нюанс · клетка из чувства долга

Нюанс: клетки, которые автор заполняет из чувства долга, видно сразу — в описании главы нет глагола
столкновения («X мешает Y», «X открывает Y»). Для истории из одной главы матрица не нужна. В раунде: если у
направления в описании нет ни одного такого глагола, его правило не сталкивается ни с чем, и материала не
будет.

### video-three-things:PAT-07 · Лестница вариаций: от себя наружу

Порядок масштаба: я и вещь ядра → я и один собеседник → круг людей вокруг вещи → город или система. Повтори
лестницу в сюжете; переменная запоминает, на какую ступень игрок поднялся сам. Для оси «структура» это
готовый скелет: направление «сначала личное» и «сначала масштаб» различаются структурой.
- **Если** направление начинается с масштаба («партнёр, регулятор, кластер») → вход дороже; законно, если
  сужение к личному — его принцип.
- **Когда не работает:** перепрыгнуть ступень — масштаб «все, кто тебе пишет» до «я и ты» снова россыпь.
- **Масштаб:** 5 сообщений — две ступени; 50 — четыре.
- basis: secondary · опора: `video-three-things:PAT-07`.

```ink
# contact: yan, Ян, amber
VAR scope = 0
он переслал мне твоё «я дома» #from:yan #delay:5s
это ведь не мне было
* [Не тебе. Удали #to:yan]
* [Ты видишь всё, что я пишу? #to:yan]
    ~ scope = 1
    всё. и ответы тоже #from:yan #delay:20s
- {scope == 1: и пишут тебе, кажется, уже не только люди} #from:yan #delay:10s
-> END
```

### edgerton-hooked:PAT-05 · Каталог инцидентов для мессенджера

Пять семейств первого события, у каждого своя первая поверхностная проблема: адресат (пишут не тебе — «кто
ты?»), доступ (номер, аккаунт, код достались тебе — «это не моё»), просьба (работа, услуга — «соглашаться
ли?»), тревога (сломалось сейчас — «что делать в ближайшие минуты?»), пропажа (человек замолчал — «где он?»).
Для раунда это источник различия по роли: два направления из одного семейства почти наверняка совпадут по оси
«роль игрока».
- **Если** все направления раунда из одного семейства → смени семейство у одного-двух.
- **Когда не работает:** «просьба» в одиночку — рутина; к ней нужна странная деталь из другого семейства.
- **Масштаб:** любой — семейство решается до первого сообщения.
- basis: secondary · опора: `edgerton-hooked:PAT-05`, `edgerton-hooked:P-01`.

```ink
# contact: bank, Банк, lime
# contact: unknown, Неизвестный номер, grey
Код для входа 5182. Никому его не сообщайте. #from:bank
#delay:40s
пришёл код? #from:unknown
это мой аккаунт, твой номер у меня старый #delay:6s
* [5182 #to:unknown #label:Переслать код]
    -> END
* [Какой аккаунт? #to:unknown]
    -> END
* [Промолчать #to:unknown #silent]
    -> END
```

#### edgerton-hooked:PAT-05#нюанс · семейство «доступ» требует самопредставления

Нюанс: семейство «доступ» (чужой код, чужой аккаунт) сильнее всех рискует быть непонятным — у игрока нет
ориентира, кто пишет. Нужна строка самопредставления в первых трёх сообщениях трейлера. Если направление раунда
из этого семейства, проверь трейлер на вопрос «кто пишет и почему мне» до кнопки.

## Режим «ещё» и Б-4

- **«Ещё».** `directions.mjs --exclude --story <id>` — метки всех показанных и отвергнутых направлений по осям.
  Новый раунд не повторяет их: `directions.mjs` сверяет новый раунд с прошлыми тем же правилом различия.
- **Б-4: автор отверг всё.** Четвёртый набор тем же способом не генерируем. Спроси, что не так, **по осям**
  (варианты ответа — названия осей: «не та роль», «не тот жанр», «не та ставка»). Запиши их в шапку раунда
  строкой «- не то: …», режим «далеко». Дай `skill.brainstorm.directions.far_count` направления: каждое
  отличается от всех прошлых по каждой отвергнутой оси — `directions.mjs` это проверяет.
- **Банк.** До раунда — `ideas-bank.mjs --query "<идея>"`: отвергнутое в другой истории по причине, которая к
  этой не относится, — готовое направление; готовая история каталога — не повторять.
- **Когда не работает:** автор не может сказать, что не так, даже по осям — покажи два направления на разных
  полюсах одной оси (сыщик против подозреваемого) и спроси, какое ближе; ответ и есть ось.
- **Масштаб:** первый раунд — без банка, если историй нет; с третьей истории банк — главный источник.
- basis: source · `build-plan.md` §2 Б-4, §7 (банк общий); `flow-review.md` §B Б-4.
