# story-endings — чтобы финал был итогом пути

Финал заслужен, когда его **выбирает игрок** кнопкой-ценностью, накопленное **слышно** до финала, перед
кнопкой есть **сводка**, финал **цитирует путь**, а после кнопки — **минуты**, а не часы. Скилл находит, где
это не так, числами из команд, сверяет каждую находку с ink и правилом и предлагает правку приёмами F-09,
F-10, F-12. Числа — только из команд, пороги — ключами `docs/playbook/thresholds.json`. Текст не правит сам:
предлагает варианты, применяет `story-fix` после одобрения.

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`.
Составная команда получает отказ в правах. Длинный вывод — `--summary` или `--json`. Упала команда —
«нет данных: <команда>», не угадывай.

## Границы

- **Вход:** история `src/stories/<id>/` (или папка / `.json`, скелет `--plan`), симптом автора или вызов
  `story-review`.
- **Выход:** находки строкой формата, варианты правки с приёмом и ink, отчёт для `story-desk`, «объясни».
- **Не здесь:** кнопки, эхо и цена до финала — `story-choices` (F-07, F-08; C-03, C-08, C-16); куда свернуть и
  добавить финал — `story-branch`; где поставить распределитель в плане — `story-plan`; длина истории и паузы
  между главами — `story-time`; карточка и её обещания (C-49) — `story-release`; честность разгадки —
  `story-mystery`; голос реплик — `story-voice`; применить правку — `story-fix`; записать — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг не
   тот (идея, ядро без скелета) — скажи. Нет `STATUS.md` (история вне цикла, мутант) — работай и отметь это.
2. **Карта финалов:** `node ${CLAUDE_SKILL_DIR}/scripts/endings-map.mjs --story <id>` — финалы, доли, распределитель,
   что решает, карточка, `VAR ending`. Меток `// финал:` нет — сначала разметка
   ([references/declaring-endings.md](references/declaring-endings.md)). `VAR ending`, которую пишут не в
   последней главе, — исход главы, а не финал. Один финал при обещании нескольких — вопрос автору и `story-release`.
3. **Замер:** `npm run -s story:lint -- --story <id> --only C-06,C-07,C-40,C-41,C-42,C-43` (папка вне каталога —
   путь вместо id; длинно — тот же вызов с `--summary`).
4. **Порог и сводка:** `node ${CLAUDE_SKILL_DIR}/scripts/threshold-visibility.mjs --story <id>` — ✗ «не звучит» →
   F-09, «нет в сводке» → F-10, ◆ последний выбор, Σ итог, ⚠ «последний выбор не решает» — ранний флаг
   перекрывает кнопку (LOCAL-17). Развилки — [references/decisions-threshold.md](references/decisions-threshold.md).
5. **Хвост:** `node ${CLAUDE_SKILL_DIR}/scripts/tail.mjs --story <id>` — хвост, ожидание, люди, длина финала против
   соседей (те же прогоны, что у C-41, C-42) → [references/resolution.md](references/resolution.md), F-12.
6. **Путь и рамка:** `npm run -s story:endings -- --story <id> --frame` — первое входящее рядом с последними
   строками каждого финала. Зеркало, носитель, следы судит модель: [references/patterns-endings.md](references/patterns-endings.md).
7. **Сверка с ink — обязательно, до отчёта.** Каждую находку открой в узле ink и сверь с текстом правила:
   `npm run -s story:rule C-NN` (или `R-NN`). Особенно: C-42 при последней кнопке в предпоследней главе (нужна
   кнопка, а не сжатие); C-43 — вопрос-зеркало первой строки (рамка, а не петля); C-07 — условие на
   переменную кода (не цитата); C-40 без меток — доли ориентировочны; доли бота — не люди. Не подтвердилась —
   «ложное: почему» или `// намеренно: C-NN причина`.
8. **Правка.** Прочитай `docs/style.md` (ST-35, ST-40, ST-80…ST-84, §11) прямо перед тем, как писать реплику,
   кнопку или пример ink. Симптом → приём: [references/decisions-endings.md](references/decisions-endings.md).
   Два-три варианта, до/после на ink, теги только `ready`.
   **Одобрено → вызови `Skill story-fix` с пунктом и вариантом; сам `Edit` не делай** — и когда одобрение пришло в той
   же фразе («почини, вариант выбери сам, одобряю»): страховка `fix-guard` и дифф реплик есть только у `story-fix`.
9. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи записать
   находки в состояние через `story-desk` (раздел «Состояние»); применяет только одобренное.

## Главные правила

- **R-102** финал выбирает игрок кнопкой-ценностью; накопленное уточняет, как сбудется (C-06 `C-06.no_last_choice`).
- **R-104** переменная финала пишется раньше последней главы и звучит словами персонажа (C-03 `C-03.invisible`, F-09).
- **R-105** перед финальной кнопкой — сводка: что есть, чего нет, хватит ли для шага; лучший финал не называют (F-10).
- **R-103** финалы различаются событием и размечены `// финал:`; доли без доминанта и мёртвых (C-40).
- **R-108, R-109** финал цитирует решения из разных глав, последняя строка зеркалит первую (C-07, `--frame`).
- **R-110** после последней кнопки — не больше `C-42.msgs` сообщений и `story.tail.max_delay_min` минут (C-42, F-12).
- **R-111, R-112** финалы без ярлыков; плохой финал полноценный и не ранний (C-41 `C-41.ending_ratio`).
- **R-107, R-113** герой решает сам, мораль не вслух; петля только как крючок сезона (C-43).

## Формат находки

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем, приём F-NN — в поле правки (без приёма — «правка (R-NN)»). Тип:
непонятно / скучно / не верю / нестыковка / баг. **P1** — финал решает скрытая проверка без последнего выбора,
мёртвый финал, часы ожидания после кнопки; **P2** — порог не звучит, нет сводки, финал не цитирует путь, один
финал забирает большинство; **P3** — рамка, носитель, мораль вслух. Отклонённая автором находка не всплывает,
пока не изменится узел. Просят JSON — те же поля: `node`, `check`, `summary`, `fix`.

## Состояние

`story-endings` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-endings.md`: находки строками формата, сверка (ложные с
  причиной), предложенные правки;
- одну строку для `STATUS.md`: «ревью финалов <дата>: P1 — N, P2 — M, главное — …, отчёт — reviews/…».

## Готово, когда

Все находки замера сверены с ink и правилом и разобраны: правка с приёмом, `// намеренно:` или «отклонено» с
причиной; у правки — до/после на ink и перезапуск замера; запись в состояние предложена.

## Объясни

По запросу «объясни»: **почему** (что почувствует игрок), **откуда** (`npm run -s story:rule R-NN`, `алиас:ID`
