# Система: разбор сцены автора по стадиям

Наш порядок наставнического разбора. Основа — критический отклик из разбора Nicklin (метод Лиз Лерман:
стадии, которые отделяют данные от рецептов; владелец системы в своде — `story-review/priority.md`), плюс
замеры командами до суждения. Своими словами, переложено на одну сессию модели с автором.

## Шаги

| шаг | что делает | вход → выход | если пропустить |
|---|---|---|---|
| 0. Замеры | числа, которые модель не должна оценивать на глаз | узел или глава → серии, кнопки, длина, путь игрока | модель «на глаз» спорит с командой и проигрывает в доверии |
| 1. Что сцена сделала | впечатление без оценки: что игрок узнал, почувствовал, решил | сцена → 3 строки | автор не узнаёт, что работает, и при правке ломает сильное место |
| 2. Вопросы автора | автор говорит, в чём сомневается | сомнения → ответы с ID из базы | разбор уходит в то, что интересно модели |
| 3. Нейтральные вопросы | места, где игрок не поймёт, — вопросом, без мнения | сцена → 2–5 вопросов, у каждого узел | мнение маскируется под вопрос, автор оправдывается |
| 4. Советы с разрешения | не больше трёх, у каждого два варианта и ID | согласие автора → советы | поток советов, автор перестаёт слушать |
| 5. Упражнение | одно упражнение на главную слабость | совет → [exercises.md](../exercises.md) | автор понял, но не умеет сделать сам |

## Замеры (шаг 0)

Сцена лежит в `src/stories/<id>/` — команды по одной на вызов:
- `npm run -s story:lint -- --story <id> --summary` — серии без кнопки, длина реплик, кнопки без ответа;
- `npm run -s story:cold-read -- --story <id> --until <узел>` — что игрок видел до узла (без `--ask`: читает
  модель сама, помня, что знает больше игрока);
- `npm run -s story:trace -- --story <id> --help` — маршрут персоной, если вопрос «что будет, если игрок молчит».

Сцена вставлена текстом — замеров нет: «нет данных: сцены нет в src/stories», всё дальше — «модель».

## Ошибки понимания

- **Метод — не способ смягчить критику.** Он отделяет данные (что почувствовал, где не понял) от рецептов:
  рецепты у отвечающих обычно хуже их данных. Поэтому советы — последними и с разрешения.
- **Стадия 1 — не похвала.** «Хорошая сцена» — пусто; «на третьей реплике ясно, что на кону смена» — данные.
- **Нейтральный вопрос — про игрока, не про автора.** «Что игрок знает в момент кнопки?», а не «почему ты так решил?».

## Короткая форма

Сцена до 10 сообщений: шаги 1 и 3, одно упражнение. Глава: все шаги. Повторный разбор той же сцены: шаг 2
первым — автор уже знает, что спрашивать.

## Источники

- `nicklin-writing-for-games:SYS-1` (критический отклик), `nicklin-writing-for-games:SYS-2` (фазы рабочей тетради).
- `narrative-testing:P-05` — рецепты тестеров хуже их данных (владелец `story-review`).
- `INTENT.md`: «Скилл, который оценивает на глаз то, что считает команда», — нельзя.
