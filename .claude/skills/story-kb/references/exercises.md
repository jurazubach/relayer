# Упражнения для автора

Упражнение — короткая работа, после которой автор умеет сделать сам то, что в разборе показал наставник.
Одно упражнение на главную слабость сцены, не набор. У каждого: когда давать, вход, шаги, как проверить
результат командой или читателем, чей это приём в своде. Упражнения вне производства истории: их результат
не идёт в `src/stories/` без одобрения и правки через `story-fix`. Тема TH-107.

## 1. Кавер: чужая сцена в переписку

- **Когда давать:** автор осваивает формат или пишет «как прозу»: длинные реплики, описания жестов.
- **Вход:** сцена из общественного достояния (пьеса, рассказ) или из своего прозаического текста.
- **Шаги:** выписать события сцены по одному в строку → решить, кто кому пишет и почему не звонит → жесты и
  взгляды заменить паузой, `#sys`, молчанием (`#silent`), а не описанием → скомпилировать →
  записать 3–5 решений: что форма добавила и что потеряла.
- **Проверка:** `npm run -s story:lint -- <путь к .ink> --summary` — серии без кнопки и длина реплик; список
  решений автор пишет сам.
- **Опора:** `nicklin-writing-for-games:P-18` (условности мессенджера как приёмы, владелец `story-voice`).
  Упражнение в своде раньше выброшено как «не шаг производства» (`docs/playbook/skills.md` §7) — здесь ему место.

## 2. Сцена-уговор

- **Когда давать:** голоса пары персонажей сливаются; автор хочет развилку «кому подыграть».
- **Вход:** два персонажа, бытовая просьба, у второго — сомнение.
- **Шаги и пример ink:** [mentor.md](mentor.md), `nicklin-writing-for-games:PAT-08`.
- **Проверка:** слепой тест голосов — `npm run -s story:cold-read -- --story <id> --until <узел> --mode voices`;
  хотя бы одна кнопка — провал уговора, который потом читается.

## 3. Три знака «получится» и три «нет»

- **Когда давать:** сцена ровная, «ничего не происходит», хотя событие есть.
- **Шаги:** записать, чего хочет собеседник в этой сцене → придумать три знака, что получится, и три — что
  нет → переписать сцену из чередования этих шагов, остальное вырезать.
- **Проверка:** у каждой реплики есть место в цепочке; серия без кнопки — `story:lint`, проверка C-35.
- **Опора:** `maass-fire-in-fiction:P-08` (владелец `chapter-write`).

## 4. «Никогда бы не»

- **Когда давать:** персонаж предсказуем, поворот не удивляет.
- **Шаги:** выписать, чего ключевой контакт никогда бы не сказал и не сделал → поставить его в ситуацию, где он
  это делает → подготовить поступок одной деталью раньше, чтобы задним числом он был объясним.
- **Проверка:** холодный читатель в режиме `guess` не угадывает поступок заранее, но после него называет деталь.
- **Опора:** `maass-fire-in-fiction:P-12`, `PAT-05` (владелец `story-brainstorm`).

## 5. Лист голоса из маркеров

- **Когда давать:** «все пишут одинаково».
- **Шаги:** для каждого контакта — 3–5 проверяемых маркеров (длина, регистр, пунктуация, любимые слова, что он
  никогда не пишет) → переписать по ним одну сцену → прочитать вслепую.
- **Проверка:** `--mode voices` у холодного читателя; ST-NN из `docs/style.md`.
- **Опора:** `sheldon-character-storytelling:P-05` (владелец `story-voice`).

## 6. Одна-три вещи до первой реплики

- **Когда давать:** начало перегружено именами и фактами.
- **Шаги:** записать 1–3 простые вещи, из сочетаний которых игрок выведет мир → вычеркнуть из первых реплик
  всё, что не из них → каждая следующая сцена — новое сочетание тех же вещей.
- **Проверка:** `story-opening` (C-20, C-21) или холодный читатель `--mode opening`.
- **Опора:** `video-three-things:P-01` (владелец `story-brainstorm`).

## Как выбрать упражнение

| слабость из разбора | упражнение |
|---|---|
| пишет как прозу | 1 |
| голоса сливаются, нужен выбор между людьми | 2, потом 5 |
| сцена ровная | 3 |
| персонаж плоский, поворот предсказуем | 4 |
| начало перегружено | 6 |

Упражнения из методов, а не методы целиком: бери инструмент, а не книгу (`snyder-save-the-cat:LESSON-12`,
владелец `story-review`): метод целиком перегружает, полезен один его инструмент.
