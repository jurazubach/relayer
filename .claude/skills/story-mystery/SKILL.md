# story-mystery — честная загадка

Загадка честна, если игрок на **любом своём пути** получил улики **раньше ответа**, от **разных людей**, и
**сам** сделал вывод кнопкой. Прятать можно вывод, а не улики. Скилл меряет это командами (C-54, `clues.mjs`,
`guess.mjs`), сверяет каждую находку с ink и правилом и предлагает правку с вариантами. Числа — только из
команд, пороги — ключами `docs/playbook/thresholds.json`. Текст не правит сам: применяет `story-fix` после
одобрения. Разметка — метка `// reveal: clue_a, clue_b` над узлом раскрытия и переменные `clue_*`; виновник —
строка «виновник: <id>» в `docs/stories/<id>/facts.md` (A-06: других меток нет).

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`.
Длинный вывод — `--summary` или `--json`. Упала команда — «нет данных: <команда>», не угадывай.

## Границы

- **Вход:** история `src/stories/<id>/` (или папка / `.json`), симптом автора, вызов `story-review` или
  `story-core` (в ядре есть скрытая правда → `references/clue-map.md`).
- **Выход:** находки строкой формата, предложение разметки, варианты правки с ink, отчёт для `story-desk`, «объясни».
- **Не здесь:** хронология правды, кто что знает, факт из другого чата, ложь против `facts.md` (C-49, C-51) —
  `story-continuity`; повороты замысла (ложный союзник, маска) — `story-brainstorm`; куда свернуть — `story-branch`;
  распределитель, скрытый порог финала, длина разбора (C-06, C-42) — `story-endings`; цена и отклик кнопок —
  `story-choices`; возвращение после паузы и «Заметки» (R-100) — `story-pauses`; первые сообщения — `story-opening`;
  живые тестеры — `story-playtest`; применить правку — `story-fix`; записать в состояние — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md` и `facts.md`, если он есть. Не знаешь, о какой истории
   речь, — спроси. Шаг не тот (идея без ядра) — скажи. Нет `STATUS.md` (мутант, черновик) — работай и отметь это.
2. **Разметка и карта улик:** `node ${CLAUDE_SKILL_DIR}/scripts/clues.mjs --story <id>`. Есть `// reveal:` — карта:
   доля дошедших, улики при входе, голоса, ворота. Нет — кандидаты в улики: составь список откровений
   ([references/clue-map.md](references/clue-map.md)) и предложи разметку автору; без неё замер молчит.
3. **Замер:** `npm run -s story:lint -- --story <id> --only C-53,C-54` (папка вне каталога — путь вместо id).
4. **Можно ли угадать:** `node ${CLAUDE_SKILL_DIR}/scripts/guess.mjs --story <id>` — план, затем тот же вызов с
   `--ask`: холодные читатели до узла раскрытия, доля угадавших против полосы `C-54.guess_share`.
5. **Суждение модели** — где замер молчит: ложь помощников, новый механизм в разгадке, приманки и их опровержения,
   двойник, риск у решающих кнопок, тайна в сцене намёка. Чек-лист — [references/flags.md](references/flags.md);
   помечай «модель» и уверенность.
6. **Сверка с ink — обязательно, до отчёта.** Каждую находку замера открой в узле и сверь с текстом правила:
   `npm run -s story:rule R-NN` (или `C-NN`). Особенно: `C-54.gap_choice` (выбор был, но уточняющий или `#silent`?),
   `C-54.channels` (строка улики не та — `~ clue_x` стоит не сразу за ней?), `C-54.long_answer` (кнопка правда
   верная?), виновник из `facts.md` (id тот?). Не подтвердилась — «ложное: почему» или `// намеренно: C-54 причина`.
7. **Правка.** Прочитай `docs/style.md` (§3, §6–8: ST-01…ST-41, ST-60…ST-66) прямо перед тем, как писать реплику,
   кнопку или пример ink. Симптом → решение: [references/decisions-mystery.md](references/decisions-mystery.md);
   приёмы — [references/patterns-mystery.md](references/patterns-mystery.md). Два-три варианта, до/после на ink,
   теги только `ready`; после правки — повтор шагов 2–3.
8. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи записать
   находки через `story-desk` (раздел «Состояние»); применяет только одобренное.

## Главные правила

- **R-92** метка `// reveal:` над узлом раскрытия, улики от разных контактов (C-53, C-54 `C-54.channels`).
- **R-93** обязательная улика — на стволе или в каждой ветке, раньше раскрытия на выбор (`C-54.sure_clue`, `C-54.gap_choice`).
- **R-94** ключевую улику игрок добывает действием, вывод делает кнопкой-версией (`C-54.long_answer`).
- **R-95** загадка названа рано, виновник — в первой трети (`C-54.culprit_late`, `C-54.culprit_error`).
- **R-96** ложный след опровергнут явно, с ценой и чем-то взамен; помощники не лгут.
- **R-97, R-98** придерживать вывод, а не улики; механизм — аналогией заранее; разгадка цитирует улики под `{clue_x:}`.
- **R-99** перед разгадкой — конкретный вопрос; после долгой паузы — напоминание и ход противника.
- **R-101** названная деталь вернётся; спасение — только по переменной игрока.
- **C-54** честная игра улик: при входе в раскрытие — `C-54.min_clues` улик в доле `C-54.clue_share` прогонов.

## Формат находки

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок, узел третьим полем. Своих ремонтных приёмов у скилла нет: в поле правки — приём словами и
файл references (F-NN — только если приём чужой, по `owners.md` §4). Тип: непонятно / скучно / не верю /
нестыковка / баг. **P1** — разгадка нечестна у части игроков (улика только в ветке, виновник из ниоткуда);
**P2** — загадка слабеет (угадывают все, один голос); **P3** — шлифовка (кнопка длиннее). Отклонённая автором
находка не всплывает, пока не изменится узел. Просят JSON — поля `node`, `check`, `summary`, `fix`.

## Состояние

`story-mystery` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-mystery.md`: карта улик, находки строками формата, сверка
  (ложные с причиной), предложенная разметка и правки;
- одну строку для `STATUS.md`: «загадка <дата>: P1 — N, P2 — M, угадали — X (полоса), отчёт — reviews/…».

## Готово, когда

Разметка есть или предложена; находки замера сверены с ink и правилом и разобраны (правка, `// намеренно:` или
«отклонено» с причиной); у правки — до/после на ink и перезапуск `clues.mjs` и C-54; запись в состояние предложена.

## Объясни

По запросу «объясни»: **почему** (что почувствует игрок), **откуда** (`npm run -s story:rule R-NN`, `алиас:ID` из
[references/sources.md](references/sources.md), класс урока), **как сделать самому** — упражнение из
[references/explain.md](references/explain.md).
