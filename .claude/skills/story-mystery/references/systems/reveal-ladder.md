# Раскрытия как каркас сюжета

### truby-anatomy-of-story:SYS-5 · Раскрытия как каркас сюжета

У Труби сюжет держится на порядке раскрытий (revelations), а не на актах: от трёхактной схемы он отказывается
прямо, а раскрытия называет ключевыми поворотными точками; техника сети — расстановка героя относительно других
персонажей. Для загадки это значит: каркас истории — список раскрытий по главам, а не схема битов (схемы
структуры в ink не размечаются, `superseded.md`).

Шаги:
1. **Список раскрытий.** Вход — правда (`facts.md`). Выход — раскрытия по главам, у каждого «цель: было → стало».
   Без шага раскрытия случайны и не учащаются.
2. **Новое решение у каждого.** Вход — раскрытие. Выход — что герой (или игрок) теперь делает иначе. Без шага —
   экспозиция: факт без нового решения.
3. **Место перед паузой.** Вход — раскрытие главы. Выход — оно стоит перед долгой паузой, игрок уходит думать.
   Без шага пауза приходит после «ничего» (C-26 у `story-pauses`).
4. **Ускорение к финалу.** Интервалы между раскрытиями к концу короче. Не подтверждено источником — ближе всего
   практика игр-переписок, где поздние паузы короче; это про темп, а не про раскрытия (класс C).

- **Ошибка понимания.** Считать раскрытием любой новый факт. Раскрытие меняет решение героя; факт без решения —
  экспозиция.
- **Короткая форма.** На 5 минут — одно-два раскрытия; второе отвечает на вопрос первого.
- **Как проверить.** Метки `// reveal:` по главам и доля прогонов через каждую (`clues.mjs`); смену решения
  судит модель по плану главы.
