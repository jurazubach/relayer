# Правило трёх улик и список откровений

Инженерная сторона честной загадки из практики ролевых расследований: игрок пропускает улики, поэтому каждый
вывод страхуется избыточностью, а честность проверяется по обратному списку «что ведёт сюда». Блоки с ID —
`clue-map.md` (`mystery-fair-play:SYS-4`, `SYS-5`, `PAT-01`, `PAT-07`); здесь — шаги целиком.

## Три улики и следствия

| шаг | вход → выход | без шага | ошибка понимания |
|---|---|---|---|
| 1. найти выводы-горлышки | сценарий → список структурных откровений | три улики раскладывают на всё, текст пухнет | «три улики на каждый факт» — нет, на нужный вывод |
| 2. три улики на вывод | вывод → несколько улик | один пропуск ломает загадку | три улики одним голосом подряд — одна попытка (`C-54.channels`) |
| 3. несколько решений у горлышка | препятствие → два пути | игрок застрял на действии, а не на выводе | решения — не ветки: сходиться можно сразу |
| 4. разрешающий поиск | неожиданный разумный путь → улика | хорошая идея игрока отвергнута | у нас ведущего нет: кнопка «свой путь» с той же уликой |
| 5. проактивные улики | застой → ход противника → новая улика | тупик ожидания | не подсказка от NPC, а ход противника (`patterns-mystery.md`) |
| 6. ложные следы переоценены | желание приманки → осторожность | игрок держится за ложную версию | опровержение, убедительное автору, не убеждает игрока |
| 7. ничто не надёжно → список | выводы и улики → отметки «найдено / вывод сделан» | не видно, где потеряна нить | «вывод сделан» — когда игрок его сделал (кнопкой), а не когда мог |

Короткая форма: шаги 1, 2, 5 остаются; 3–4 — «у ворот две-три кнопки, все честные»; 6 — «одна приманка
максимум»; 7 делает бот: `clues.mjs` и C-54 по прогонам.

## Обратное правило и узлы

- **Вход:** узлы (у нас — глава или контакт с вопросом). **Выход:** у игрока всё время есть доступ к уликам,
  ведущим к ещё не пройденным узлам.
- Первое правило защищает конкретный вывод, обратное — движение вообще: при доступе к любым трём уликам игрок
  почти наверняка придёт хотя бы к одному выводу. Правило про доступ, а не про находку.
- **Без шага:** глава кончается «ни с чем», следующей не за что тянуть.
- **Как проверить:** в конце каждой главы, кроме последней, у прогона выставлены `clue_*` к ещё не пройденным
  `// reveal:` — по журналу `clues.mjs --json` (переменные по прогонам); отдельного ключа пока нет.

## Список откровений: два списка, два режима

1. **Правда.** Что на самом деле сделал противник, по шагам, во времени мира — `facts.md` (R-91, `story-continuity`).
   Без неё улики не согласуются между собой.
2. **Структурные откровения.** Без них нет разгадки или хорошего финала; каждому — узел и метка `// reveal:`.
3. **Улики под каждым.** С местом: контакт, глава, ствол или ветка — таблица в плане главы.
4. **Фоновые отдельно.** Без `clue_*`, в проверку не попадают; их пропуск допустим.
5. **В игре — отметки.** Бот: выставлена ли улика в прогоне, дошёл ли прогон до раскрытия с уликами.

- **Ошибка понимания:** рисовать граф вместо списка. `npm run graph` — обзор, честность — по меткам.
- **Короткая форма:** одно откровение, две улики от двух голосов, одна метка.
