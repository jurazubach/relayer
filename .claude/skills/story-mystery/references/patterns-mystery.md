# Приёмы загадки на ink

Приёмы с примерами, которые компилируются (теги — только `ready` из `docs/capabilities.json`). У каждого — когда
не работает, масштаб и basis. Мир примеров — лодочная станция «Сонный причал»: сторож Вера (`vera`), механик Гоша
(`gosha`, приманка), председатель Арсений Павлович (`arseny`, виновник), бухгалтер Зоя (`zoya`), «Заметки»
(`notes`). Перед тем как переносить пример в историю, прочитай `docs/style.md` (§3 сообщение, §6 кнопки, §8
паузы): примеры показывают устройство, а не готовые реплики.

## Разметка раскрытия целиком

Минимальная честная загадка: две улики от двух голосов на стволе, ворота с версиями одной длины, разгадка
цитирует улики под условиями. В `facts.md` истории — строка «виновник: arseny». Замер — C-54 и
`node ${CLAUDE_SKILL_DIR}/scripts/clues.mjs --story <id>`.

```ink
# contact: vera, Вера, teal
# contact: arseny, Арсений Павлович, blue
VAR clue_key = false
VAR clue_fuel = false
VAR solved = false
-> night
=== night ===
катер ушёл ночью, а сарай был заперт. ключ один #from:vera
Вера, ключ висит на доске у моей двери. Все знают. #from:arseny #delay:1m
~ clue_key = true
* [А солярка на месте? #to:vera]
    канистры пустые. а заправляли позавчера #from:vera #delay:30s
    ~ clue_fuel = true
* [Кто был на станции? #to:vera]
    только мы и председатель. и канистры пустые, заправляли позавчера #from:vera #delay:30s
    ~ clue_fuel = true
- -> gate
=== gate ===
кто взял ключ? #from:vera
* [Председатель #to:vera]
    ~ solved = true
* [Механик #to:vera]
* [Не знаю #to:vera]
- -> truth
// reveal: clue_key, clue_fuel
=== truth ===
{clue_key: ключ висел у его двери, сам сказал}
{clue_fuel: а канистры опустели за одну ночь} #from:vera
{solved: ты поняла раньше меня|это он}
-> END
```

- **Когда не работает.** Разгадка на одну реплику без ворот — RED-02; улики в одной ветке — RED-01.
- **Масштаб.** 5 сообщений: так и есть — две улики, одни ворота. 50: три улики в разных главах и чатах.
- basis: checked · опора: R-92…R-94, R-98; `mystery-fair-play:PAT-01`, `PAT-02`, `PAT-06`.

## Спрятать на виду

### mystery-fair-play:PAT-04 · Улика на виду (hiding in plain sight)

Улика остаётся в истории чата, но не бросается в глаза при первом чтении. Четыре способа спрятать: в быту
(организационная реплика «заберу утром», а не та, где говорят о деле); в списке (третий пункт из четырёх, рядом с
ярким первым); перед отвлечением (сразу за уликой — громкое событие); через отсутствие (чего-то нет там, где
должно быть). Цена — ноль строк: улика встраивается в нужный текст. Реплика с уликой короткая —
`attn.msg.chars.key`, улика в первой половине.

```ink
# contact: zoya, Зоя, pink
VAR clue_mud = false
-> list
=== list ===
что купить к субботе: краску, два весла, сапоги председателю, они у него в глине #from:zoya
~ clue_mud = true
и ещё замок на сарай, старый еле живой #delay:5s
* [Запиши всё #to:zoya]
* [Сапоги-то зачем? #to:zoya]
    говорит, свои утопил #from:zoya
- -> END
```

- **Когда не работает.** Спрятано слишком хорошо — разгадка «из воздуха»; строку, тут же скрытую долгой паузой в
  другом чате, могут не прочесть вовсе.
- **Масштаб.** 5 сообщений: не прячь, обе улики заметны. 50: прячь одну из трёх.
- basis: secondary · опора: `mystery-fair-play:PAT-04`, `P-16`.

### mystery-fair-play:PAT-04#нюанс · Прятать только страховочную

Нюанс к PAT-04: на беглом чтении «спрятанная» улика невидима. Прятать только одну из трёх, страховочную;
способ «через отсутствие» — тоже только для неё, и в разгадке NPC называет отсутствие прямо (оно не находится
прокруткой). Две другие улики того же вывода заметны и стоят на стволе.

## Мир действует сам

### mystery-fair-play:PAT-05 · Проактивная улика (proactive clues, «бей по голове»)

Игрок молчит, отвечает «не знаю» или пошёл не туда — сюжет не ждёт: противник делает ход, и ход оставляет новую
улику. Это честное использование `#silent` и «не ответил»: молчание тоже двигает сюжет. Проактивная улика
приходит и тому, кто ответил, — другим путём, иначе молчать выгоднее.

```ink
# contact: vera, Вера, teal
# contact: arseny, Арсений Павлович, blue
VAR clue_paint = false
-> stuck
=== stuck ===
не понимаю, кто это мог #from:vera
* [Механик? #to:vera]
    гоша был со мной #from:vera
* [Промолчать #silent #label:Промолчать]
- Вера, я распорядился перекрасить катер. К понедельнику. #from:arseny #delay:20m
перекрасить? до того, как приедет страховая? #from:vera
~ clue_paint = true
-> END
```

- **Когда не работает.** Игрок уже сделал верный вывод — тогда ход противника нужен для напряжения, а не для
  подсказки.
- **Масштаб.** 5 сообщений: ход противника и есть единственная улика молчащему. 50: ход противника — лучшая
  первая реплика после паузы.
- basis: secondary · опора: `mystery-fair-play:PAT-05`; `inkle-ingold:P-12`; R-52 у `story-choices`.

### mystery-fair-play:PAT-05#нюанс · Лучшая первая реплика возвращения

Нюанс к PAT-05: проактивная улика после долгой паузы — лучшая первая реплика возвращения: событие мира вместо
«привет», и оно же двигает загадку. Схема возвращения (вопрос и улика её же словами → ход противника → ворота) —
ниже, «Возвращение с уликой»; правила первой реплики — у `story-pauses`.

## Разгадка со ссылками

### mystery-fair-play:PAT-06 · Разгадка со ссылками («я же это видел»)

В узле разгадки и в разборе: вывод → две-три улики, на которые он опирается, каждая с местом (чей чат, когда) →
только потом новое. Ссылка зависит от ветки: называй только те улики, которые игрок точно видел, — под условием
`{clue_x: …}`. Без условий ссылка на непоказанное появится в каждой ветке, где улика не пришла (RED-08). Пример —
узел `truth` в разметке выше.

- **Когда не работает.** Улику-отсутствие нельзя «процитировать»: её NPC называет словами.
- **Масштаб.** 5 сообщений: одна-две ссылки дословно. 50: ссылки со временем мира и чатом.
- basis: checked · опора: `mystery-fair-play:PAT-06`, `P-14`, `GREEN-06`, `RED-08`; R-98.

## Две половины

Ключевой факт у двух людей, откровение — по `{a && b}` (`narrative-postmortems:PAT-04`, `clue-map.md`).

```ink
# contact: vera, Вера, teal
# contact: gosha, Гоша, amber
# contact: notes, Заметки, green
VAR clue_light = false
VAR clue_time = false
-> ask
=== ask ===
* [Что ты видела ночью? #to:vera]
    лодку без огней, у дальнего пирса #from:vera #delay:40s
    ~ clue_light = true
* [Когда ты ушёл с мотора? #to:gosha]
    в три. лодка без огней уже отчаливала #from:gosha #delay:1m
    ~ clue_time = true
- {clue_light && clue_time: -> both}
* [Спросить второго #to:notes #silent #label:Подумать, кого ещё спросить]
    -> ask
=== both ===
Лодка без огней, три часа, дальний пирс #sys:notes
-> END
```

- **Когда не работает.** Половины без общего слова: игрок не свяжет их без подсказки автора.
- **Масштаб.** 5 сообщений: один собеседник отвечает на один вопрос из двух. 50: две половины у двух людей.
- basis: secondary · опора: `narrative-postmortems:PAT-04`, `P-08`.

## Возвращение с уликой

После паузы от `story.pause.long_s`, если до неё был открыт вопрос загадки: вопрос и улика её же словами → ход
противника за паузу (новая улика) → вопрос → ворота. Приём ведёт `story-pauses` (возвращение), здесь — его форма
для загадки (R-99).

```ink
# contact: vera, Вера, teal
VAR clue_key = true
-> back
=== back ===
#delay:3h
катер снова у пирса. кто-то пригнал его на рассвете #from:vera
{clue_key: ключ при этом висел на доске у председателя, как и вчера}
кто его пригнал, если ключ не трогали?
* [Значит, есть второй ключ #to:vera]
* [Значит, ключ вернули #to:vera]
- -> END
```

- **Когда не работает.** После короткой паузы внутри сцены пересказ раздражает.
- **Масштаб.** 5 сообщений: паузы нет — приём не нужен. 50: на каждую долгую паузу с открытым вопросом.
- basis: secondary · опора: R-99; `mystery-fair-play:PAT-05`, `LESSON-07`; `attention-merged.md` §5.
