# Развилки правки: если A → делай X

Каждая запись: условие → действие, «когда не работает», масштаб, `basis`. Числа — только из команд.

## Откуда взять вариант

**Если в отчёте линзы у находки есть «Вариант А/Б/В» с ink** → взять дословно: `pick.mjs --report <файл>
--take N:К --story <id>`. Не переписывать «чуть лучше»: автор одобрял именно этот текст.
- **Когда не работает.** `pick.mjs` пишет «устарело» — узел правили после отчёта; вариант не применять, а
  повторить линзу на узле. Вариант противоречит `INTENT.md` (срок паузы, упрёк за отсутствие) — не применять,
  сказать автору, что вариант нарушает A-NN, и предложить исправленный как новый пункт.
- **Масштаб.** Одна реплика — применяется за один Edit. Вариант на несколько узлов — по узлу за раз, `fix-guard.mjs` после каждого.
- basis: our_estimate (задача S-fix после W2: «варианты из отчёта линзы, без пересочинения»).

**Если вариантов нет, а в поле правки стоит F-NN** → открыть файл приёма владельца ([fixes-index.md](fixes-index.md)),
пройти его шаги на узле находки, построить два-три варианта с ink «до» и «после»; перед первой репликой —
`docs/style.md`. Показать и получить одобрение ([approval.md](approval.md)).
- **Когда не работает.** F-15 ещё без файла у `story-plan` — строка `npm run -s story:rule F-15`. Приём требует
  решения сюжета (какой финал важнее, кто виновник) — это вопрос автору с вариантами, не правка.
- **Масштаб.** На 5 сообщениях вариантов обычно два; на главу — до трёх, не больше: автор выбирает, а не читает каталог.
- basis: our_estimate (`owners.md` §4: приёмы у владельцев, `story-fix` держит указатель).

**Если в поле правки «→ <скилл>» (приёма нет)** → вызвать этот скилл через `Skill` на узле находки: он
вернёт находку с вариантами; дальше — как с отчётом линзы.
- **Когда не работает.** Скилл ещё не собран (`story-plan`, `chapter-write`) — сказать «нет данных: скилла
  нет», оставить пункт открытым в отчёте.
- **Масштаб.** Одна находка — один вызов; много находок одной линзы — один вызов со списком узлов.
- basis: our_estimate.

## Порядок и конфликты

**Если находок несколько** → по приоритету (`story-review/references/priority.md`): баг, непонятное, нестыковка,
не верю, скучное; внутри — P1, P2, P3. Баг сначала воспроизводится маршрутом (`narrative-testing:P-16`,
[safety.md](safety.md)).
- **Когда не работает.** Две находки на одном узле с разными типами — ниже.
- **Масштаб.** На главу — не больше `skill.review.top_per_chapter` правок за заход: больше автор не проверит.
- basis: secondary (`edgerton-hooked:LESSON-01`: правка непонятного поднимала дочитывание без смены сюжета).

**Две правки на одном узле** → сначала та, что меняет структуру (кнопки, паузы, переходы), потом та, что
меняет реплики: текст пишется по готовому каркасу. Если вторая отменяет первую (склейка сессий F-03 убирает
паузу, перед которой F-01 поставил крючок), — показать автору конфликт одним пунктом с двумя вариантами.
- **Когда не работает.** Правки в разных ветках одного узла не конфликтуют — применять по очереди.
- **Масштаб.** В короткой истории конфликт почти всегда; в длинной — редко, узлы мельче.
- basis: our_estimate.

**Если правка меняет ядро, план или финалы, а не узел** → это не `story-fix`: `story-desk` (Б-5: что устарело)
и `story-branch` / `story-plan`. `story-fix` фиксирует, что правка вышла за узел, и останавливается.
- **Когда не работает.** Смена одной реплики финала — правка, а не смена финала.
- **Масштаб.** Правка в узле, через который проходят все пути, задевает финалы — смотри `diff-report.mjs` (доли финалов).
- basis: our_estimate (`build-plan.md` §2, Б-5).

## После правки

**Если `fix-guard.mjs` дал «✗»** → правку не сдавать: вернуть пропавшее (улику, запись переменной, метку
финала, переход) или откатить файл. «⚠» — сверить с ink и в отчёте сказать, почему это не поломка.
- **Когда не работает.** Удалённая переменная, которую правка заменила другой (переименование), даёт «⚠» и
  «новая переменная» — это не поломка, если видимые чтения перешли к новой.
- **Масштаб.** На 50+ узлах «⚠» по переменным — частое; сверять каждое, не списком.
- basis: our_estimate.

**Если в `diff-report.mjs` новые находки в чужих местах** → открыть каждую в ink: правка задела соседнюю ветку
(регрессия — новый пункт к одобрению) или замер сдвинулся от перестановки (ложное, LOCAL-04, — в отчёт с
причиной).
- **Когда не работает.** `--quick` даёт другой набор прогонов бота — для сдачи нужен прогон без `--quick`.
- **Масштаб.** После правки одного узла чужих находок обычно нет; после `--compress` — десятки, разбирать по проверкам.
- basis: our_estimate (`flow-review.md` §A шаг 7: «правка паузы могла сломать крючок в другой ветке»).

**Повтор линзы** → после правки та же линза, что нашла проблему, смотрит **только изменённые узлы**: её скилл
через `Skill` с узлами из `text-diff.mjs`, или её проверки `npm run -s story:lint -- --story <id> --only C-NN`.
Находка от холодного читателя — тот же `npm run story:cold-read` с тем же узлом, режимом и профилем.
- **Когда не работает.** Находка человека (тестера) повтором модели не закрывается: «закрыто» скажет только
  свежий человек на следующей волне (`story-playtest`, Б-2) — до того пункт «правлено, ждёт теста».
- **Масштаб.** Одна правка — одна проверка `--only`; правка главы — линза целиком на главе.
- basis: our_estimate (задача S-fix: «повтор линзы на изменённых узлах»).

**Если автор говорит «это намеренно»** → один раз сказать, что теряется, предложить малую альтернативу,
при «да, намеренно» — решение D-NN, потом метка ([approval.md](approval.md)).
- **Когда не работает.** Проверка уровня «ошибка», которая ломает игру (тупик C-52, недостижимое C-15), меткой
  не гасится — это не вкус, а поломка.
- **Масштаб.** Метка гасит проверку во всём узле: на большом узле можно погасить и настоящие находки — лучше
  разбить узел.
- basis: our_estimate (`flow-review.md` §A шаг 7).

## Сжатие

**Если просят «короче», «до N минут», «в одну сессию»** → `--compress` ([compress.md](compress.md)), начиная с
`compress-plan.mjs`. **Если просят «скучно, тянется»** — это ритм: `story-pace`, а не сжатие.
- **Когда не работает.** Нужна демо-часть, а не короткая история — набор с `beta_stop` (`story-playtest`).
- **Масштаб.** Сжатие вдвое — резка структуры; на десятки процентов — подача и реплики.
- basis: secondary (`attention-today:LESSON-02`: резать там, где ничего не меняется, а не по длине).
