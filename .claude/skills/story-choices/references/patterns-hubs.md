# Приёмы хабов и необязательного

Как устроить хаб, чтобы он не стал меню, анкетой или тупиком, и как наградить необязательное ходом. У
каждого приёма — когда применять, когда не работает, масштаб, basis и пример ink, который компилируется.
Правила и проверка C-19 — `hubs.md`.


### inkle-ingold:PAT-06 · Хаб тем с одноразовыми вопросами, выходом и запасным выбором

Допрос, сбор сведений, «написать кому-то из списка»: каждый вопрос — одноразовый `*` с ответом и возвратом
в хаб; выход — `+` по счётчику вопросов; запасной выбор `* -> after` уводит дальше сам, когда вопросы
кончились, и защищает от тупика. Цена — по две-три строки на тему. Ловушки: петля только из `*` без
запасного выбора кончается ошибкой «закончился контент»; выход, доступный сразу, позволяет пропустить весь
хаб; без строки-перехода после хаба пропадёт ощущение, что разговор кончился.

- **Когда не работает.** Порядок вопросов важен для сюжета.
- **Масштаб.** 5 сообщений: два вопроса из трёх. 50: три-четыре темы, ответы пишут знания.
- basis: checked (руководство ink) · ловит C-19 `C-19.no_exit`.

```ink
# contact: lev, Лев, teal
VAR asked = 0
-> hub
=== hub ===
* (where) [Где ты был ночью? #to:lev]
    ~ asked += 1
    дома. как обычно #from:lev #delay:30s
    -> hub
* (who) [Кто ещё знает про сорок третью? #to:lev]
    ~ asked += 1
    консьержка. и ты #from:lev #delay:30s
    -> hub
* (key) [У кого ключ? #to:lev]
    ~ asked += 1
    у управдома. и, похоже, не только #from:lev #delay:40s
    -> hub
+ {asked >= 2} [Хватит. Ясно #to:lev #silent]
    -> after
* -> after
=== after ===
{hub.key:ключ — это важно. запомни #from:lev}
ладно, мне пора #from:lev #delay:10s
-> END
```

### inkle-ingold:PAT-06#нюанс · Собеседник закрывает хаб сам

Нюанс к PAT-06: хаб тем не работает, если порядок вопросов важен для сюжета. Пограничный случай: собеседник
сам закрывает хаб после двух-трёх вопросов («мне пора», встречный вопрос) — это экономит внимание и делает
его живым (`inkle-ingold:LESSON-14`). Масштаб: на пяти сообщениях два вопроса из трёх; на пятидесяти — три-
четыре темы, и ответы пишут знания, которые читаются позже.

### bateman-game-writing:PAT-06 · Тематический хаб с итогом по набору вопросов

Допрос, расспросы, сбор версий: меню вопросов, каждый исчезает после ответа, выход открывается после первого
вопроса, а итог зависит от набора заданных вопросов. Если темы равноценны и итог не зависит от набора — это
меню-справочник, а не сцена. Число сочетаний растёт быстро: при многих темах итог считай только по ключевым
парам.

- **Когда не работает.** Срочная сцена: хаб снимает напряжение, потому что ждёт игрока.
- **Масштаб.** 5 сообщений: не нужен. 50: один хаб на сцену (нюанс ниже).
- basis: secondary · ловит C-19 `C-19.survey` (анкета без последствий).

```ink
# contact: max, Макс, grey
VAR asked_door = false
VAR asked_cam = false
-> topics
=== topics ===
спрашивай. отвечу на что знаю #from:max #delay:3s
-> menu
= menu
* [Кто последним закрывал дверь? #to:max]
    ~ asked_door = true
    я. в десять. ключ сдал #from:max #delay:40s
    -> menu
* [Камера у входа работала? #to:max]
    ~ asked_cam = true
    с понедельника не пишет. все знали #from:max #delay:40s
    -> menu
* {asked_door || asked_cam} [Ладно, всё #to:max]
    -> done
=== done ===
{asked_door and asked_cam:в десять дверь закрыта, камера не пишет. значит, у кого-то второй ключ #from:max #delay:5s}
ещё что-то? я на смену #from:max #delay:3s
-> END
```

### bateman-game-writing:PAT-06#нюанс · Больше трёх тем читается как форма

Нюанс к PAT-06: на телефоне хаб из большого числа тем читается как анкета, а не разговор; потолок держит
`C-19.spokes_max`. Масштаб: на сцене в полсотни сообщений тематический хаб уместен один — второй уже
превращает сцену в форму, а в сцене на пять сообщений хаб не нужен вовсе.

### inkle-ingold:PAT-10 · Награда за побочный чат — новая кнопка в кульминации

Есть необязательный контакт, и надо, чтобы игроки к нему ходили: побочный чат пишет флаг, а в кульминации
по этому флагу появляется ход, которого иначе нет. Цена — одна переменная и одна условная кнопка. Новая
кнопка даёт другой исход, а не ту же реплику другими словами.

- **Когда не работает.** Без этой кнопки кульминация не работает — тогда контакт не побочный.
- **Масштаб.** 5 сообщений: один необязательный вопрос → одна кнопка в конце. 50: несколько побочных чатов,
  каждый открывает свою кнопку.
- basis: checked · ловит C-15 `C-15.rare_button`.

```ink
# contact: lev, Лев, teal
# contact: baba, Соседка, amber
VAR heard_tapping = false
-> optional
=== optional ===
* [Кто там стучит по ночам? #to:baba #label:Спросить соседку сверху]
    кто это? #from:baba #delay:1h
    а, из сорок первой. по ночам в сорок третьей стучат. по батарее #from:baba #delay:30s
    ~ heard_tapping = true
* [Не отвлекаться #to:lev #silent]
- -> climax
=== climax ===
он говорит, в сорок третьей пусто #from:lev #delay:30s
* {heard_tapping} [Там стучат по ночам. Соседка слышала #to:lev #label:Сказать про стук]
    тогда я поднимаюсь #from:lev #delay:20s
* [Поверь и иди домой #to:lev]
    иду #from:lev #delay:20s
* [Промолчать #to:lev #silent]
    ладно. сам разберусь #from:lev #delay:15m
- -> END
```

### inkle-ingold:PAT-10#нюанс · Побочный чат, который почти никто не открывает

Нюанс к PAT-10: приём не работает, если без кнопки кульминация не работает. Пограничный случай: побочный
чат посещает малая доля прогонов — награду никто не видит; поднимай заметность входа (`#label` в хабе,
реплика-подводка). Масштаб: на пяти сообщениях один необязательный вопрос и одна кнопка в конце; на
пятидесяти — несколько побочных чатов, каждый открывает свою кнопку.

### narrative-postmortems:PAT-01 · Необязательный разговор с наградой

Побочные свидетели, справочные чаты, «поспрашивать вокруг»: хаб → побочный чат → факт или контакт → хаб,
где появилась новая кнопка; или «хватит, дальше» → сюжет, и реплика учитывает, что найдено, а что нет.

- **Когда не работает.** Сцена несёт обязательный для финала факт — тогда её не прячь, а сокращай.
- **Масштаб.** 5 сообщений: не нужен. 50: один такой разговор на главу.
- basis: checked (разбор с высокой уверенностью) · ловит C-19, C-15.

```ink
# contact: nora, Нора, teal
# contact: vik, Вик, amber
# contact: dock, Сторож причала, grey
VAR got_key = false
-> hub
=== hub ===
кому пишем? до отлива два часа #from:nora #delay:10s
* [Спрошу Вика про лодку #to:vik #label:Написать Вику]
    лодка? та, что без номера? #from:vik #delay:1m
    сторож знает, чья. вот его номер #from:vik #delay:20s
    ~ got_key = true
    -> hub
* {got_key} [Чья это лодка? #to:dock #unlock:dock #label:Написать сторожу]
    Лодка стоит третью неделю. Хозяина не видел. #from:dock #delay:3m
    -> tide
+ [Хватит. Идём к воде #to:nora]
    -> tide
=== tide ===
{got_key:у тебя есть сторож. это уже что-то|ладно. пойдём вслепую} #from:nora #delay:30s
-> END
```

### narrative-testing:PAT-08 · Пустая ветка хаба → отказ с уликой

Кнопка в хабе ведёт в узел, где ноль-одна строка и возврат в хаб, — это читается как пропущенная реплика.
Лечение: кнопка → «Прочитано» → пауза → короткий отказ, в котором есть факт → флаг → хаб. Цена — две-три
строки на ветку. У каждого отказа своя улика: три одинаковых «не пиши мне» читаются как заглушки.

- **Когда не работает.** Тишина и есть ответ, и персонаж позже её объясняет — тогда объяснение стоит в той
  же главе.
- **Масштаб.** 5 сообщений: хаба нет, отказ — одна реплика. 50: см. нюанс.
- basis: our_estimate (переложение класса ошибок «пропущенные реплики») · ловит C-19 `C-19.thin_spoke`.

```ink
# contact: ola, Оля, teal
# contact: sam, Сэм, grey
VAR sam_alibi = false
-> hub
=== hub ===
кому ещё напишем? #from:ola
* [Ты в ту ночь был в клубе? #to:sam]
    Прочитано #sys:sam #delay:2m
    не пиши мне. я в ту ночь вообще был в другом городе #from:sam #delay:5m
    ~ sam_alibi = true
    -> hub
+ [Хватит #to:ola]
    {sam_alibi:в другом городе? проверим билеты #from:ola|ладно #from:ola} #delay:30s
    -> END
```

### narrative-testing:PAT-08#нюанс · Одна пустая ветка допустима

Нюанс к PAT-08: на пяти сообщениях хаба нет, и отказ — одна реплика. В хабе из многих кнопок одна
намеренно пустая ветка допустима, если её пустота объяснена позже в той же главе; без объяснения она
снова становится пропущенной репликой (`narrative-testing:RED-01`).

### mobile-interactive-stories:PAT-03 · Сцена за доверие

Чтобы наградить игрока, который вкладывался в отношения: счётчик доверия копится выборами → на ключевой
развилке появляется дополнительный вариант → сцена (признание, улика, тепло) → общий узел. Цена — сцена на
несколько строк, которую увидит часть игроков. На рынке такой вариант виден и заблокирован, и это злит; у
нас он скрыт условием, игрок не знает, что упустил, и не чувствует себя наказанным (R-56).

- **Когда не работает.** Без этой сцены непонятен основной сюжет — тогда это не бонус, а потерянная
  информация.
- **Масштаб.** 5 сообщений: не нужна. 50: одна сцена за доверие на главу, без последствия для финала.
- basis: secondary · ловит C-15.

```ink
# contact: mira, Мира, amber
VAR mira_trust = 2
ты завтра придёшь? #from:mira #delay:5s
* {mira_trust >= 2} [Приду. И есть новость из архива #to:mira]
    стоп. архив? и что там? #from:mira #delay:8s
    тогда слушай. я никому этого не говорила #from:mira #delay:20s
    у отца был второй телефон #from:mira #delay:30s
* [Приду #to:mira]
- ок. до завтра #from:mira #delay:10s
-> END
```

### mobile-interactive-stories:PAT-03#нюанс · Не единственный источник улики

Нюанс к PAT-03: не превращай сцену за доверие в единственный источник улики — это та же ошибка переноса,
что у премиум-выбора: вариант, без которого нельзя прийти к лучшему финалу, спрятан за невидимым
счётчиком (`systems/premium-choice.md`). Бонус — тепло и подробность, а не пропуск к финалу.
