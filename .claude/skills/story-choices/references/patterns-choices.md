# Приёмы: подготовка поворота, ценности, ритм, перебивка

Приёмы для поворотных и ритмических выборов. У каждого — когда применять, когда не работает, масштаб,
basis и пример ink, который компилируется. Правила — `choice-types.md`, развилки — `decisions-choices.md`.

### failbetter-qbn:PAT-10 · Сначала ситуация, потом выбор

Любой выбор, после которого меняется финал или контакт: узел-подводка (несколько реплик, цена каждого пути
названа) → короткая пауза → узел выбора с двумя-тремя кнопками и `#label`. Ловушки: подводка пересказывает
прошлое вместо цены будущего; кнопки дублируют подводку слово в слово.

- **Когда не работает.** Мелкие реплики тона — подводка там лишняя.
- **Масштаб.** 5 сообщений: подводка в две реплики. 50: отдельный узел на каждый поворот главы.
- basis: checked (статья Failbetter) · правило — R-50; признак — `failbetter-qbn:GREEN-05`.

```ink
# contact: yan, Ян, teal
-> setup
=== setup ===
они нашли лодку. завтра её заберут #from:yan
если перегоню сам — лодка наша, но меня запомнят на причале #delay:30s
если отдам — нас никто не тронет, но и доказательств не будет #delay:20s
что делать? #delay:10s
-> pick
=== pick ===
* [Перегоняй #to:yan #label:Рискнуть ради доказательств]
    понял. ночью #from:yan #delay:1m
* [Отдай лодку #to:yan #label:Сберечь себя]
    ладно. жалко #from:yan #delay:1m
- -> END
```

### maass-fire-in-fiction:PAT-08 · Выбор между двумя ценностями

Ключевой выбор главы: контакт ставит дилемму с двумя «правильными» сторонами → кнопки с `#label` по
ценности → `#silent` как третий путь, который тоже чего-то стоит → цена каждого варианта видна сразу в
одной-двух репликах → переменная читается позже.

- **Когда не работает.** В мелких ответах: там лучше окраска без жертвы, иначе игрок устаёт решать
  дилеммы каждые две минуты. И если одна из ценностей подана как глупость — выбора нет.
- **Масштаб.** 5 сообщений: две кнопки и `#silent`. 50: переменная выбора читается в следующей главе.
- basis: model (перенос противоречивых чувств на кнопки, уверенность средняя) · ловит C-08, C-16.

```ink
# contact: yana, Яна, amber
VAR told = false
мама просит не говорить отцу, что я нашла письма #from:yana #delay:5s
а отец спрашивает прямо сейчас #delay:4s
он же имеет право знать?
* [Скажи ему. Это и его жизнь #to:yana #label:Правда важнее]
    ~ told = true
    сказала #from:yana #delay:6m
    мама не берёт трубку
* [Промолчи. Мама сама расскажет #to:yana #label:Сберечь маму]
    промолчала #from:yana #delay:3m
    он понял, что я что-то скрываю. ушёл к себе
* [Промолчать #to:yana #silent]
    ладно. решу сама #from:yana #delay:20m
- {told:я сделала по-твоему|ну вот} #from:yana #delay:10s
-> END
```

### meaningful-choice:PAT-08 · Ритмическая кнопка

Длинный монолог собеседника — нужна пауза для вовлечения: две короткие реакции, у каждой свой ответ;
дальше без перехода. Цена — по строке ответа на кнопку. Ловушки: обе кнопки без ответа
(`meaningful-choice:RED-01`); одна кнопка «далее».

- **Когда не работает.** Вместо реального решения в конце сцены — там нужна развилка с ценой.
- **Масштаб.** 5 сообщений: одна-две. 50: не больше трёх подряд (нюанс ниже).
- basis: model (о ритме — знание модели) · ловит C-10 `C-10.group_bodyless`.

```ink
# contact: sol, Сол, amber
-> beat
=== beat ===
и тут он достаёт ключ. от НАШЕЙ двери #from:sol
* [Что?? #to:sol]
    вот и я так сказала #from:sol #delay:20s
* [Откуда у него ключ #to:sol]
    вот это и есть вопрос #from:sol #delay:20s
- дальше хуже #from:sol #delay:30s
-> END
```

### meaningful-choice:PAT-08#нюанс · Ритм с переменной — уже зеркало

Нюанс к PAT-08: ритмическая кнопка не работает вместо решения в конце сцены. Пограничный случай:
ритмическая кнопка, которая пишет переменную тона, — это уже зеркало выражения (`meaningful-choice:PAT-03`,
`patterns-echo.md`), и её надо прочитать позже. Масштаб: на пяти сообщениях одна-две; на пятидесяти — не
больше трёх подряд (`C-10.cosmetic_streak`).

### choiceofgames-design:PAT-10 · Фальшивый выбор на эмоции

После сильной новости или в середине длинного рассказа героя, чтобы игрок не был зрителем: новость → три
реакции → у каждой своя короткая реплика → схождение. Ответ различается по тону. Если вариант обещает
действие («Я еду»), а герой его тут же гасит, — допустимо один раз; на третий игрок перестанет верить
кнопкам.

- **Когда не работает.** На решении, которое игрок считает важным (пойти / не пойти, сдать / прикрыть):
  там фальшивка раскрывается и злит. Если на все варианты отвечают одним «ок» — выбор выдал себя.
- **Масштаб.** 5 сообщений: одна такая развилка. 50: в эмоциональных точках, не подряд.
- basis: checked · признаки — `choiceofgames-design:GREEN-09`, `choiceofgames-design:RED-11`.

```ink
# contact: zoya, Зоя, teal
его нашли #from:zoya #delay:3m
живой. в больнице #from:zoya #delay:40s
* [Слава богу #to:zoya]
    ага #from:zoya #delay:30s
* [Что с ним? #to:zoya]
    ничего не говорят #from:zoya #delay:30s
* [Я еду #to:zoya]
    не надо. ночь же #from:zoya #delay:30s
- завтра пустят к нему #from:zoya #delay:20s
-> END
```

### bateman-game-writing:PAT-07 · Событие перебивает разговор

Нужно сломать ровный темп, создать срочность или дилемму «кому отвечать»: контакт A начинает важное →
контакт B вклинивается со срочным → кнопки A или B → у выбора B есть цена в разговоре с A. Цена — одна-две
реплики второго контакта и ветка с последствием. Перебивка каждые несколько сообщений приучает игрока
игнорировать уведомления.

- **Когда не работает.** В момент признания, если перебивка не задумана как жестокость сюжета, — иначе
  выглядит как небрежность; и без последствия для первого разговора (нюанс ниже).
- **Масштаб.** 5 сообщений: не нужна. 50: одна на главу, с последствием.
- basis: secondary (событийные диалоговые системы; перенос на чаты — наш).

```ink
# contact: lena, Лена, teal
# contact: courier, Курьер, grey
VAR waited = false
слушай, про отца. я давно хотела сказать #from:lena #delay:3s
он не уезжал. его увезли #from:lena #delay:6s
Подъезд 3, вы дома? Откройте дверь #from:courier #unlock:courier #delay:4s
* [Лена, подожди минуту #to:lena]
    ~ waited = true
    подожду #from:lena #delay:30s
* [Кто это? Заказа не было #to:courier]
    Доставка на ваше имя. Жду у подъезда. #from:courier #delay:20s
- {waited:так вот. его увезли в ту ночь #from:lena|ладно. потом расскажу #from:lena} #delay:2m
-> END
```

### bateman-game-writing:PAT-07#нюанс · Перебивка без события — шум

Нюанс к PAT-07: событийный диалог стоит в ряду с остальными типами, но у него своя цена — перебивка без
нового события превращается в шум, и игрок учится пропускать уведомления. Событие должно что-то менять в
первом разговоре: цену ожидания, тему, отношение собеседника.
