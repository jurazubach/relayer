# Приёмы цены и компромисса

Приёмы, которые дают развилке цену. У каждого — когда применять, когда не работает, масштаб, basis и
пример ink, который компилируется (теги — только `ready` из `docs/capabilities.json`). Правила, на которых
они стоят, — `cost.md`.

### meaningful-choice:PAT-02 · Цена в двух чатах

У игрока одна ценная вещь (сведение, фото) и два контакта, которым она нужна. Отдал одному — второй
узнаёт позже и обижен; компромисс идёт через разные `#to`. Цена приёма — две переменные отношений, по
реплике на исход и одна проверка позже. Ловушка: обе стороны потом ведут себя одинаково — компромисс
фальшивый (`meaningful-choice:RED-04`).

- **Когда не работает.** Второй контакт так и не узнаёт о выборе — цены нет.
- **Масштаб.** 5 сообщений: оба контакта уже знакомы, отклик в той же сцене. 50: прошлая глава готовит
  обоих, обида звучит в следующей.
- basis: secondary (компромиссы по Мейеру; `#to` — наше) · ловит C-01 (переменная обиды не читается).

```ink
# contact: ira, Ира, teal
# contact: den, Денис, amber
VAR gave_ira = false
VAR gave_den = false
-> find
=== find ===
фото с парковки у тебя? #from:ira
мне оно нужно больше, чем ему #delay:20s
скинь мне фото. Ира не должна его видеть #from:den #delay:1m
* [Отправить Ире #to:ira]
    ~ gave_ira = true
    спасибо. я твоя должница #from:ira #delay:30s
* [Отправить Денису #to:den]
    ~ gave_den = true
    отлично. теперь молчи #from:den #delay:30s
- -> later
=== later ===
{gave_ira:фото теперь у неё? понятно #from:den #delay:2h}
{gave_den:он показал мне твоё фото. зачем? #from:ira #delay:2h}
-> END
```

### meaningful-choice:PAT-02#нюанс · Когда цена в двух чатах не работает

Нюанс к PAT-02: приём не работает, когда оба контакта потом ведут себя одинаково (фальшивый компромисс)
или когда один из двоих игроку безразличен — выбор очевиден, и формулировкой его не спасти. Пограничный
случай, который работает: у обоих контактов была своя сцена симпатии и сомнения до выбора. Масштаб: на
пяти сообщениях два контакта уже знакомы; на пятидесяти прошлая глава готовит обоих.

### meaningful-choice:PAT-09 · Закрытая дверь

Решение должно ощущаться бесповоротным: после выбора контакт перестаёт отвечать (`#sys`), позже в этом
чате приходят только системные строки или «прочитано» без ответа. Дёшево, а эффект сильный: молчание
контакта видно в списке чатов. Ловушка: контакт «пропал», а через главу пишет как ни в чём не бывало, без
оговорки.

- **Когда не работает.** Контакт нужен сюжету позже — закрой не весь чат, а одну тему.
- **Масштаб.** 5 сообщений: одна строка «не в сети». 50: проверка флага везде, где контакт пишет.
- basis: our_estimate (перевод на мессенджер наш) · ловит C-01, C-03.

```ink
# contact: nik, Ник, grey
VAR nik_gone = false
-> push
=== push ===
ещё раз спросишь про брата — я пропаду #from:nik
* [Где был твой брат в ту ночь? #to:nik]
    ~ nik_gone = true
    Ник не в сети #sys:nik #delay:1m
* [Ладно. Не буду #to:nik]
    спасибо #from:nik #delay:30s
- -> later
=== later ===
{nik_gone:
    Прочитано #sys:nik #delay:4h
- else:
    я подумал. брат был со мной #from:nik #delay:4h
}
-> END
```

### meaningful-choice:PAT-09#нюанс · После потери нужен новый ход

Нюанс к PAT-09: приём не работает, если после потери у игрока нет нового хода — закрытая дверь без другой
двери, и игрок бросает историю. Пограничный случай: закрыть тему, а не контакт. Масштаб: на пяти
сообщениях хватит системной строки «не в сети»; на пятидесяти проверка блока стоит везде, где контакт
мог бы написать, иначе он «воскреснет» в чужой ветке.

### failbetter-qbn:PAT-06 · Каинова печать: одноразовая линия

Предложение, которое можно принять один раз; после этого контакт меняется навсегда. Закончил линию →
скрытый флаг → все входы в линию проверяют флаг → линия пропадает, вместо неё одна реплика-отголосок.
Цена — один флаг и одна реплика. Ловушка: флаг ставится, но вход в линию его не проверяет, и предложение
приходит второй раз.

- **Когда не работает.** Для линий, которые должны оставаться открытыми.
- **Масштаб.** 5 сообщений: одно предложение и отголосок. 50: несколько входов в линию из разных глав —
  каждый проверяет флаг.
- basis: checked (статья Failbetter) · ловит C-01 (флаг не читается на входе).

```ink
# contact: press, Журналист, grey
VAR sold_photo = false
-> offer
=== offer ===
{ sold_photo:
    больше не пишите мне #from:press #delay:1m
    -> END
}
за фото с причала заплачу. сегодня #from:press #delay:5m
* [Ладно. Присылаю #to:press]
    ~ sold_photo = true
    получил #from:press #delay:2m
    -> offer
* [Нет #to:press]
    -> END
```

### schell-art-of-game-design:PAT-05 · Треугольный выбор

Ключевая развилка главы: «безопасно, мало пользы» / «рискованно, много пользы» / молчать. Текст до кнопок
называет цену риска. Цена приёма — одна переменная риска и ветка последствия на несколько сообщений.
Исход риска зависит от прежних переменных, а не от случая: случайный исход в нашем жанре читается как
нечестность, если игрок не видел признаков.

- **Когда не работает.** Бытовые ответы — там риск выглядит надуманным. И когда цены вариантов не видны:
  это «слепой выбор», главная претензия критиков к жанру (нюанс ниже).
- **Масштаб.** 5 сообщений: цена одной фразой. 50: цена и отложенный отклик.
- basis: model (линза треугольности — знание модели, уверенность высокая) · ловит C-08.

```ink
# contact: roma, Рома, teal
VAR roma_trust = 1
VAR risk = false
-> door
=== door ===
дверь склада открыта. сторож спит #from:roma
если полезу внутрь — найду накладные. если поймают, меня уволят #delay:20s
* [Сфоткай дверь и уходи #to:roma]
    фото есть. толку мало #from:roma #delay:1m
* [Лезь, быстро #to:roma]
    ~ risk = true
    {roma_trust > 0:накладные у меня. меня не видели #from:roma|он проснулся. бегу #from:roma} #delay:3m
* [Промолчать #to:roma #silent]
    ладно. сам решу #from:roma #delay:2m
- -> END
```

### schell-art-of-game-design:PAT-05#нюанс · Слепой выбор

Нюанс к PAT-05: треугольный выбор не работает, когда цены вариантов не видны — игрок жмёт вслепую, и
провал ощущается обманом (так критики говорили о популярной игре-переписке: проигрыш без видимой ошибки).
Масштаб: на пяти сообщениях цена называется одной фразой перед кнопками; на пятидесяти — цена плюс
отложенный отклик, который подтверждает, что риск был реальным.

### maass-fire-in-fiction:PAT-03 · Союзники тянут в разные чаты

Середина истории, у игрока два «своих» контакта, они начали ему доверять — и хотят противоположного.
Кнопки: согласиться с одним, передать другому слова первого, спросить второго. Одна переменная стороны;
реплики обоих позже звучат по-разному. Окупается, только если сторона читается в следующей главе.

- **Когда не работает.** В первой главе — игрок ещё не знает, кому сочувствовать. И если один из союзников
  явно неправ, выбора нет.
- **Масштаб.** 5 сообщений: две реплики и кнопка. 50: спор живёт через главу.
- basis: secondary (блогер о трении между собеседниками) · правило — R-49, `people-choice.md`.

```ink
# contact: lev, Лев, teal
# contact: dasha, Даша, amber
VAR side = ""
не отдавай ей флешку #from:lev #delay:5s
она сольёт всё в общий чат #delay:4s
флешка у тебя? #from:dasha #delay:1m
лев против, да? #delay:5s
* [Лев просит подождать #to:dasha]
    ~ side = "lev"
    тогда без меня #from:dasha #delay:40s
* [Скидываю тебе, Даша #to:dasha]
    ~ side = "dasha"
    спасибо. только ему не говори #from:dasha #delay:30s
* [Что мне ей сказать? #to:lev]
    ~ side = "ask"
    скажи, что флешки нет #from:lev #delay:20s
- {side == "dasha":значит, флешка у неё #from:lev #delay:2h}
-> END
```

### truby-anatomy-of-story:PAT-06 · Моральное решение отдельно от проверки

В финальной главе выбор решает «что», накопленное — «получилось ли». Накоплено: улики, отношения;
финальная развилка — ценность A (`#to:x`) / ценность B (`#to:y`) / молчание; маршрут: выбор × накопленное →
финал. Если финал выбирает только скрытая проверка, игрок не чувствует, что решал; если только кнопка —
полтора часа игры ничего не значат. Обе ценности должен защищать кто-то живой: ценность без лица —
абстракция. Распределитель финалов держит `story-endings`; здесь — чтобы финальная кнопка была выбором.

- **Когда не работает.** У истории нет морального вопроса в посылке — сначала чини ядро (`story-core`).
- **Масштаб.** 5 минут: две кнопки, два финала, без проверки. 90 минут: выбор × накопленное, до нескольких
  финалов, часть сливается.
- basis: secondary (моральное решение — книга; разделение «выбор / накопленное» — наш вывод).

```ink
# contact: sasha, Саша, teal
# contact: inna, Инна, amber
VAR proof = 0
-> last
=== last ===
у меня есть запись. отдам тому, кому скажешь #from:sasha
* [Отдай Инне. Пусть судит открыто #to:sasha #label:Выбрать правду]
    {proof >= 2:Инна выложила запись. всё кончено #from:inna|Инна выложила запись. ей никто не поверил #from:inna} #delay:2m
* [Сотри. Пусть живут спокойно #to:sasha #label:Выбрать покой]
    стёр. надеюсь, так лучше #from:sasha #delay:1m
- -> END
```

### truby-anatomy-of-story:PAT-06#нюанс · Когда моральное решение ломается

Нюанс к PAT-06: приём ломается, когда один вариант очевидно правилен (большинство идёт в «добро») или
финал подкреплён наградой — значком, «правильным» финалом, видимым плюсом. Масштаб: история на пять минут
— две кнопки, два финала, без проверки накопленного; история на полтора часа — выбор × накопленное, до
шести финалов, часть сливается.
