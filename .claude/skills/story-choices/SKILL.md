# story-choices — чтобы выбор ощущался

Выбор ощущается, когда у кнопки **свой ответ**, у решения **память** («это потому, что я тогда…») и **цена**,
видимая до нажатия. Скилл находит, где этого нет, числами из команд, сверяет каждую находку с ink и правилом
и предлагает правку приёмами F-07, F-08, F-11, F-14. Числа — только из команд, пороги — ключами
`docs/playbook/thresholds.json`. Текст не правит сам: предлагает варианты, применяет `story-fix` после одобрения.

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`.
Составная команда получает отказ в правах. Длинный вывод — `--summary`, а не обрезка. Упала команда —
«нет данных: <команда>», не угадывай.

## Границы

- **Вход:** история `src/stories/<id>/` (или папка / `.json`), симптом автора или вызов `story-review`.
- **Выход:** находки строкой формата, варианты правки с приёмом и ink, отчёт для `story-desk`, «объясни».
- **Не здесь:** финал, распределитель, скрытый порог — `story-endings` (F-09, F-10); куда свернуть сюжет —
  `story-branch`; «не ответил», напоминания, причина паузы — `story-time` (`#silent` — здесь); стена текста и
  коридор — `story-pace`; состав и уровни контактов — `story-cast`; род игрока, голос, регистры — `story-voice`;
  слияния и факт из другого чата — `story-continuity`; оси и число переменных — `story-core`; применить правку
  — `story-fix`; записать в состояние — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг не
   тот (идея, ядро без скелета) — скажи. Нет `STATUS.md` (история вне цикла, мутант) — работай и отметь это.
2. **Замер.** `npm run -s story:lint -- --story <id> --only C-01,C-02,C-03,C-04,C-05,C-08,C-09,C-10,C-11,C-12,C-13,C-15,C-16,C-17,C-18,C-19`
   (папка вне каталога — путь вместо id). Слишком длинно — тот же вызов с `--summary`.
3. **Кнопки:** `node ${CLAUDE_SKILL_DIR}/scripts/choices.mjs --story <id>` — классы по главам, молчание,
   отказы, хабы. Ищи кнопки-позиции без флага, которые потом не возвращаются (R-44, `choice-types.md`).
4. **Память и скрытый штраф:** `node ${CLAUDE_SKILL_DIR}/scripts/echo-map.mjs --story <id>`. Для каждой
   переменной из условия финала — `echo-map.mjs --story <id> --var <имя>`: какие кнопки её пишут и есть ли у
   них сигнал цены до нажатия (C-03 × C-08, R-47). Естественная кнопка со скрытым штрафом — отдельная P1.
5. **Цена и люди:** `node ${CLAUDE_SKILL_DIR}/scripts/position-bias.mjs --story <id>`, затем
   `node ${CLAUDE_SKILL_DIR}/scripts/people-balance.mjs --story <id>`.
6. **Сверка с ink — обязательно, до отчёта.** Каждую находку замера открой в узле ink и сверь с текстом
   правила: `npm run -s story:rule R-NN` (или `C-NN`). Особенно C-17 (решающая дилемма R-49 или просто кому
   поручить дело?), C-19 (хаб порядка — `// намеренно:`), C-04 (условный переход в сцену — уже отклик),
   C-10 «ответил не тот» (забытый `#from`?). Не подтвердилась — «ложное: почему» или `// намеренно: C-NN`.
7. **Суждение модели** — только там, где замер молчит: одинаковый тон ответов, слабая цена, ответ не совпадает
   с кнопкой. Помечай «модель» и уверенность. Развилки — по карте references ниже.
8. **Правка.** Прочитай `docs/style.md` (ST-NN о репликах и кнопках) прямо перед тем, как писать реплику,
   кнопку или пример ink. Симптом → приём: [references/decisions-choices.md](references/decisions-choices.md).
   Два-три варианта, до/после на ink, теги только `ready`.
   **Одобрено → вызови `Skill story-fix` с пунктом и вариантом; сам `Edit` не делай** — и когда одобрение пришло в той
   же фразе («почини, вариант выбери сам, одобряю»): страховка `fix-guard` и дифф реплик есть только у `story-fix`.
9. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи записать
   находки в состояние через `story-desk` (раздел «Состояние»); применяет только одобренное.

## Главные правила

- **R-43** у каждой кнопки свой ответ; одинаковый — это `#me` (C-10, C-13). Отвечает адресат (C-10 `C-10.wrong_responder`).
- **R-44** окраска законна только с откликом на тон (`C-10.cosmetic_chapter`, `C-10.bodyless_chapter`).
- **R-40** каждая переменная читается видимо, не позже следующей главы (C-01…C-05).
- **R-47, R-48** цена названа до кнопки, очевидно лучшего варианта нет (C-08, C-16, C-18).
- **R-52, R-53** `#silent` и отказ — ходы с реакцией и следом (C-11); «не ответил» не дороже `#silent` (A-03).
- **R-49** решающий выбор — между двумя, кого игрок любит, с равным знакомством (C-17).
- **R-45, R-46** две-три кнопки, короткая реплика одной формы (C-12, C-13).
- **R-34, R-36, R-58** хаб с выходом и наградой ходом, редкая ветка коротка, разговор не анкета (C-15, C-19).

## Формат находки

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем, приём F-NN — в поле правки. Тип: непонятно / скучно / не верю /
нестыковка / баг. **P1** — ключевая развилка или скрытый штраф («кнопка «кто это?» тихо ведёт к плохому
финалу»); **P2** — заметно в главе («восемь переменных молчат до финала» — одна находка, не восемь);
**P3** — шлифовка («кнопка длиннее соседей»). Отклонённая автором находка не всплывает, пока не изменится
узел. Просят JSON — те же поля: `node`, `check`, `summary`, `fix`.

## Состояние

`story-choices` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-choices.md`: находки строками формата, сверка (ложные с
  причиной), предложенные правки;
- одну строку для `STATUS.md`: «ревью выбора <дата>: P1 — N, P2 — M, главное — …, отчёт — reviews/…».

## Готово, когда

Все находки замера сверены с ink и правилом и разобраны: правка с приёмом, `// намеренно:` или «отклонено»
с причиной; у правки — до/после на ink и перезапуск замера; запись в состояние предложена.

## Объясни

По запросу «объясни»: **почему** (что почувствует игрок), **откуда** (`npm run -s story:rule R-NN`, `алиас:ID`
