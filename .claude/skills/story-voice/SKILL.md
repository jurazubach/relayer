# story-voice — чтобы каждого узнавали без имени и реплика читалась за взгляд

Голос — это **форма**, которую видно в каждом пузыре (длина, регистр, точка, эмодзи, словечко, «ты» / «Вы»), плюс
**желание** человека. Реплика — одна мысль на один взгляд. Скилл находит, где голоса слились, форма выбилась, реплика
стала стеной, игроку приписан пол, — числами из команд, сверяет каждую находку с ink и правилом и предлагает правку по
`docs/style.md`. Числа — только из команд, пороги — ключами `docs/playbook/thresholds.json`. Текст не правит сам:
предлагает варианты, применяет `story-fix` после одобрения.

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`. Длинный вывод —
`--summary` или `--json`. Упала команда — «нет данных: <команда>», не угадывай.

## Границы

- **Вход:** история `src/stories/<id>/` (или папка / `.json`), глава, симптом автора или вызов `story-review`.
- **Выход:** находки строкой формата, варианты правки реплик на ink, отчёт для `story-desk`, «объясни».
- **Не здесь:** состав, функции, дуги, когда открыть контакт — `story-cast` (голосовая часть карточки — здесь); кнопка
  как ход, сколько кнопок, свой ответ — `story-choices`; правило «упрёк за отсутствие», время игрока, напоминания —
  `story-time` (реплику переписываем здесь); ритм серий, затишье, конкретика (C-35, C-36) — `story-pace`; новые имена в
  начале (C-22) — `story-opening`; повтор после слияния, факты и цифры (C-49) — `story-continuity`; имя-улика как улика
  — `story-mystery`; написать главу — `chapter-write`; применить правку — `story-fix`; записать — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг не тот (идея,
   ядро без глав) — скажи. Нет `STATUS.md` (история вне цикла, мутант) — работай и отметь это.
2. **Замер.** `npm run -s story:lint -- --story <id> --only C-14,C-34,C-44,C-46,C-47,C-48` (папка вне каталога — путь
   вместо id). Слишком длинно — тот же вызов с `--summary`.
3. **Голоса.** `node ${CLAUDE_SKILL_DIR}/scripts/voice-stats.mjs --story <id>` — профиль каждого контакта, сверка с
   карточкой, пары. Голос не меняется или меняется без причины — тот же вызов с `--contact <id> --chapters` (R-82).
   Развилки по симптому — [references/decisions-voice.md](references/decisions-voice.md).
4. **Слепой тест** пары-кандидата (пара с «!», «ниже порога C-44», жалоба «не различить»):
   `node ${CLAUDE_SKILL_DIR}/scripts/blind-sample.mjs --story <id> --pair a,b --ask`. Судьёй себя не ставь — ты знаешь
   историю ([references/blind-test.md](references/blind-test.md)).
5. **Стиль главы.** `node ${CLAUDE_SKILL_DIR}/scripts/style-diff.mjs --story <id> --chapter N` — форма против образцов
   SG-NN, словари `docs/style.md` §14.5, антиобразец AS-NN у каждой находки.
6. **Сверка с ink — обязательно, до отчёта.** Каждую находку замера открой в узле ink и сверь с текстом правила:
   `npm run -s story:rule R-NN` (или `C-NN`). Известные ложные — [references/flags.md](references/flags.md): маска и
   второй номер (C-44), подпись и лог (C-46), упрёк в узле после кнопки (C-47), место мира не из карточки (C-48).
   Не подтвердилась — «ложное: почему» или `// намеренно: C-NN причина`.
7. **Суждение модели** — только там, где замер молчит: работа реплики, юмор и тон, «котик», регистры, речь по
   биографии (ST-18), голос из другой истории (ST-24). Помечай «модель» и уверенность; карта references ниже.
8. **Правка.** Прочитай `docs/style.md` (нужное ST-NN, образец SG-NN, антиобразец AS-NN) прямо перед тем, как писать
   реплику, кнопку или пример ink. Два-три варианта, до/после на ink, теги только `ready`. Новая карточка голоса — в
   `characters[].voice` словами, которые читает C-44 ([references/voice-sheet.md](references/voice-sheet.md)).
9. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи записать находки
   в состояние через `story-desk` (раздел «Состояние»); применяется только одобренное.

## Главные правила

- **R-75** карточка голоса до первой реплики; у двух контактов различаются `style.voice_params` параметра (C-44 `C-44.card_share`).
- **R-82** голос меняется с отношением, триггер рядом (C-44 `C-44.static_voice`).
- **R-59** одно сообщение — одна мысль, до `C-34.long_chars` знаков (C-34).
- **R-81** `#sys` и `#photo` — поведение, а не чувства; поворот главы — интерфейсом (C-47).
- **R-89** реплики игрока без рода, без чувств за него (C-14); **R-119** не сшивать фразы из кусков.
- **R-86** одно имя на человека, `#rename` рядом с именем (C-48); повтор на пути — дефект (C-46).
- **R-87** шутят не больше `style.jokers_max`, по-разному, не о предметах загадки; тёплая реплика в главе.

## Формат находки

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем. У скилла нет своих F-NN: в поле правки — приём словами и положение
(«правка (ST-17: форма ссоры)»). Тип: непонятно / скучно / не верю / нестыковка / баг. **P1** — голоса главных
контактов слились, игроку приписан пол в стволе; **P2** — заметно в главе («шесть строк против карточки» — одна
находка); **P3** — шлифовка. Отклонённая находка не всплывает, пока не изменится узел. Просят JSON — поля `node`,
`check`, `summary`, `fix`.

## Состояние

`story-voice` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-voice.md`: находки строками формата, сверка (ложные с причиной),
  слепой тест (пара, seed, счёт), предложенные правки;
- одну строку для `STATUS.md`: «ревью голосов <дата>: P1 — N, P2 — M, главное — …, отчёт — reviews/…».

## Готово, когда

Все находки замера сверены с ink и разобраны (правка, `// намеренно:` или «отклонено» с причиной); пары-кандидаты
прошли слепой тест или получили правку; у правки — до/после на ink; запись в состояние предложена.
