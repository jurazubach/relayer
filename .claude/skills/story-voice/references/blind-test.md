# Слепой тест голосов

Число C-44 — кандидат; решает, различимы ли голоса, слепой тест: по `style.blind_min.of` реплик двух контактов без
имён, вперемешку, и читатель, который истории не знает, раскладывает их по людям (ST-21). Порог —
`style.blind_min` (угадано не меньше `hits` из `of` у каждого).

## Как провести

1. Найти кандидатов: `node ${CLAUDE_SKILL_DIR}/scripts/voice-stats.mjs --story <id>` — пары с «!» (ближе
   `C-44.distance`) и «ниже порога C-44» у коротких контактов.
2. Выборка: `node ${CLAUDE_SKILL_DIR}/scripts/blind-sample.mjs --story <id> --pair a,b` (без `--pair` — самая близкая
   пара). Реплики, где звучит имя одного из пары, в выборку не идут: они выдают ответ.
3. Судья — **не тот, кто знает историю**. Главная сессия и скилл знают ink, их ответ ничего не стоит. Варианты:
   - `blind-sample.mjs … --ask` — `claude -p` из пустого каталога без инструментов и настроек (та же изоляция, что у
     `story:cold-read`);
   - отдать напечатанную выборку холодному читателю (агент `cold-reader`, `story-playtest`) или человеку и посчитать
     ответ: `blind-sample.mjs … --answer "1A 2B …"`.
4. Если у обоих есть карточки (`characters[].voice`), читатель раскладывает по карточкам; если нет — делит на две
   группы, засчитывается лучшая раскладка. Без карточек тест строже к форме и слабее к желанию.
5. Ниже порога — находка «голоса сливаются» с правкой по [voice-sheet.md](voice-sheet.md) (развести два параметра формы,
   словарь, желание; PAT-01) и повтором теста на другом `--seed`.

Другой режим — голоса в контексте переписки: `npm run -s story:cold-read -- --story <id> --until <узел> --mode voices`
(имена и чаты заменены буквами). Он проверяет, различимы ли люди в потоке, а не в выборке.

### nicklin-writing-for-games:P-03 · проверь голос вслепую

Закрой имена и прочитай сцену — каждый персонаж должен угадываться; в воркшопе Nicklin это критерий готового
диалога. Если голос узнаётся без подписи, игрок держит в голове ансамбль, а не список имён, и не ошибается чатом.
Автоматически проверяется только форма (P-02, C-44); различимость — слепым тестом с порогом `style.blind_min`
(количественный порог наш). Исполняемо: `blind-sample.mjs` с `--ask` или `--answer`.
**Когда не работает:** служебный канал и эпизодический контакт с одной-двумя репликами — выборки не набрать; там
хватит одной резкой черты (R-75) и сверки с карточкой (`C-44.card_share`). `basis: secondary` (критерий — Nicklin,
порог — наш).

### narrative-testing:GREEN-04 · у каждого контакта устойчивый стиль

Зелёный признак нарративного QA: у каждого контакта устойчивые длина, регистр, эмодзи, пунктуация — игрок различает
людей без имени (пункт «голос»). Бот: профиль по говорящему, строка дальше `C-44.outlier_sigma` по
`C-44.outlier_features` признакам идёт в список (C-44); профиль голоса держит карточка (R-75). Держать: строка вне
профиля — либо ошибка голоса, либо событие (паника, подмена, ссора), и тогда её объясняет сюжет.

### nicklin-writing-for-games:LESSON-04 · когда говорящих несколько — подпиши выбор тоном

Класс C (практика одной студии, цифр нет). В ансамблевых диалогах кнопка с готовой репликой заранее решала, кто из
героев говорит; варианты подписали тоном («тихо», «напролом»), а кто ответит, игрок узнавал из результата — реакция
персонажа стала маленьким открытием. У нас кнопка — реплика игрока, поэтому прямо приём не переносится; он подходит
для `#silent` с `#label`, когда игрок не пишет, а решает, как вести себя в общем разговоре («Не вмешиваться» /
«Вступиться»), а ответит тот, кого задели. Для слепого теста вывод такой: чей голос ответит, должно быть понятно по
самому ответу, без `#from`.

```ink
-> crew
=== crew ===
кто вообще дал ему ключи? #from:yara
Ключи мои, голубчик, и давал их я. #from:osip #delay:30s
* [Не вмешиваться #to:yara #silent #label:Не вмешиваться]
    ну и ладно. сама разберусь #from:yara #delay:20s
* [Вступиться за Яру #to:osip #silent #label:Вступиться за Яру]
    Я не с Вами спорю, а с ней. #from:osip #delay:1m
- -> END
```
