# Приёмы ink: каскад условий, перемешанные проходные реплики, сшитая реплика

Три приёма, которыми глава отзывается на состояние, не размножая узлы. Все примеры компилируются
(`node ${CLAUDE_SKILL_DIR}/scripts/ink-compile.mjs --md <этот файл>`), теги — только `ready` из
`docs/capabilities.json`. Мир примеров — канатная дорога ([ink-idioms.md](ink-idioms.md)). Редактура готовой
сшитой реплики — у `story-voice/line-edit.md`; здесь — как её написать.

## Каскад от частного к общему

### procedural-storytelling:PAT-01 · Каскад от частного к общему: самое узкое условие первым

- **Когда применять.** Узел-слияние, куда игрок приходит с разным набором фактов, и реакция персонажа на
  накопленное отношение. Блок условий ink берёт первую подходящую ветку, поэтому самое узкое условие (`a && b`)
  стоит первым, общее `- else:` — последним и есть всегда.
- **Когда не работает.** Вариантов всего два и они равноправны — хватит `{cond:а|б}`.
- **Масштаб.** На 5 сообщениях — две ветки и `else`; на длинной истории — до трёх узких веток над `else`.
- **basis:** secondary (Emily Short о salience, `procedural-storytelling`), проверено компиляцией.

```ink
# contact: roman, Роман, indigo
VAR knows_shift = false
VAR lied_once = false
-> ask
=== ask ===
кто тебе дал этот номер #from:roman
* [Ася дала #to:roman]
    ~ knows_shift = true
* [Нашёл на сайте станции #to:roman]
- ты с ней работаешь? #from:roman #delay:1m
* [Да, давно #to:roman]
    ~ lied_once = true
* [Нет #to:roman]
- -> reply
=== reply ===
{
- knows_shift && lied_once:
    ася тут третью неделю. «давно» не выйдет #from:roman #delay:2m
- knows_shift:
    ася, значит. ладно #from:roman #delay:1m
- lied_once:
    давно, а номер с сайта? #from:roman #delay:3m
- else:
    ладно. раз уж написал, слушай #from:roman #delay:3m
}
-> END
```

Ловушка: поставь `- knows_shift:` первой строкой — ветка `knows_shift && lied_once` станет мёртвой, бот её не
найдёт ни разу (C-15 у `story-choices` ловит недостижимое). Переменные, которые никогда не встречаются вместе,
дают мёртвые ветки.

#### procedural-storytelling:PAT-01#нюанс · Каскад не заменяет сцену с целью

Каскад даёт реакцию, но не ведёт разговор: если персонаж чего-то добивается, сцену с целью пишут ветками и
кнопками, а не блоком условий. Сказанная реплика должна становиться фактом: без записи узкая ветка повторится при
втором заходе в узел, поэтому повторный вход защищают условием на счётчик посещений узла (`{reply > 1: …}`).
Пять против пятидесяти: для короткой истории — две ветки и `else`, для длинной — до трёх узких над `else`.

### emshort-structures:P-11 · Сначала общая реплика, потом частные поверх

Нарратив на значимости берёт из пула реплик самую подходящую к состоянию, при равенстве — случайную. Для
главы это значит: сначала пиши общую реплику на все случаи (приветствие главы, реакция на возвращение в чат,
эпилог), потом добавляй частные — по одной, когда видишь ситуацию, которую стоит отметить. Общая страхует от
пустоты, новое правило почти не даёт побочных эффектов. У каждого многоветочного условного блока есть `else`,
условия идут от узких к широким.

```ink
# contact: roman, Роман, indigo
VAR asked_brigade = false
VAR saw_photo = false
-> morning
=== morning ===
{
- asked_brigade && saw_photo:
    бригаду я опросил. про фото журнала они молчат #from:roman
- saw_photo:
    фото я видел. откуда оно у тебя, спрашивать не буду #from:roman
- else:
    утро. кабину сняли. все живы #from:roman
}
-> END
```

- **Когда не работает.** Общая реплика звучит как заглушка — нюанс ниже.

#### emshort-structures:P-11#нюанс · Общая реплика-заглушка и два равных условия

Приём «частное поверх общего» ломается двумя способами. Первый: общая реплика звучит как заглушка, и игрок,
которому не досталось частной, читает пустое место — общую пишут так же живо, как частные. Второй: два одинаково
узких условия — порядок решает автор, и это надо записать в плане главы, а не оставить случаю. Масштаб: одно
условие плюс `else` на короткой истории, три-четыре условия — на длинной.

### procedural-storytelling:LESSON-02 · Настрой строгость условий: узкие прячут сцену, широкие стирают характер

Wildermyth (интервью основателей): при слишком узких, строгих требованиях к ролям события почти не появлялись —
условия прятали сцену; при слишком широких игрок переставал различать характеры — условия стирали их. Решение — мягкое условие входа в событие, а различия перенесены в строки
внутри него. Для главы: условие, которое не даёт сцене появиться, — тупик контента. Сцена или ветка, которую
бот находит реже `C-15.rare_node` прогонов (C-15 у `story-choices`), — повод ослабить вход и перенести различие
внутрь, в каскад. Класс доказательства — C (интервью, цифр нет).

## Перемешанные проходные реплики

### procedural-storytelling:PAT-06 · Перемешанные проходные реплики: шафл в петле ожидания

- **Когда применять.** Петли ожидания, реакции на молчание, повторяющиеся служебные фразы: `{~вариант|вариант}`
  в повторяемом узле плюс счётчик выхода.
- **Когда не работает.** Любое место, где реплика несёт факт или поворот (P-11 ниже). Варианты должны быть в одном
  голосе персонажа: перемешивание — не повод смешивать стили. Шафл делает прогон недетерминированным: снимки и
  e2e могут плавать.
- **Масштаб.** На 5 сообщениях не нужен; в длинной истории — в двух-трёх местах.
- **basis:** secondary (Kazemi, Compton), синтаксис проверен компиляцией.

```ink
# contact: asya, Ася, teal
VAR called = 0
-> dark
=== dark ===
{~роман?|алё, станция|кто-нибудь} #from:asya #delay:20m
~ called += 1
{ called >= 2: -> alone }
* [Я тут #to:asya]
    хоть кто-то #from:asya #delay:30s
    -> END
+ [Промолчать #to:asya #silent]
    -> dark
=== alone ===
ладно. сама спущусь по лестнице #from:asya #delay:10m
-> END
```

«Промолчать» помечена `+`: со `*` она исчезла бы после первого круга, и выход `alone` стал бы недостижим.

#### procedural-storytelling:PAT-06#нюанс · Граница со спамом и комедия

В петле ожидания — не больше `story.reminders.max` напоминаний, потом персонаж действует сам или уходит из сети;
третье «ты там?» уже спам. В реальном времени петлю «ты там?» заменяет `#remind` у той же развилки: движок сам
присылает напоминание и ведёт историю дальше ([pause-lines.md](pause-lines.md)). Петлю с `+ [Промолчать]` пишут,
только когда молчание и есть сюжет сцены (персонаж зовёт в темноте). В комедийной истории шафл допустим шире —
см. нюанс к P-11.

### procedural-storytelling:P-11 · procedural-storytelling:RED-09 · Варьируй мелочи, повороты пиши руками

Случайная или подставленная реплика иногда промахивается. В проходной фразе промах незаметен, в кульминации
он рушит сцену. Поэтому перемешивание `{~…}` и генерация моделью — только для проходных реплик: «ты там?»,
реакции на молчание, бытовые отклики. Признания, раскрытия, превращения, крючки перед паузой и финалы — авторский
текст без вариаций. Красный флаг RED-09: `{~…}` в узле с поворотом или финалом; правка — заменить авторским
текстом.

- **Когда не работает.** Лёгкая комедийная история — нюанс ниже.

#### procedural-storytelling:P-11#нюанс · Комедия: шафл шире

Пограничный случай — комедийная история. По Тане Шорт, комедия в процедурных системах даётся легче драмы: промах
случайной реплики в шутке читается как ещё одна шутка. Поэтому в лёгкой истории шафл допустим шире, например в
реакциях на бытовые события и в болтовне второстепенного контакта. В детективе и драме перемешивают только
проходные реплики, а раскрытия и крючки пишут руками.

### procedural-storytelling:LESSON-01 · Модели — реакции, каркас главы — автору

Wildermyth пробовал случайную структуру глав и процедурных злодеев — сюжет из случайных препятствий не вёл к
одной точке. Сюжет стали писать руками, процедурными остались герои и их реакции. Для `chapter-write`: повороты,
порядок сцен и финалы задаёт план (`story-plan`), модель пишет реплики персонажей на уже назначенные события —
кто паникует, кто молчит, кто врёт. Если плана главы нет, `chapter-write` не придумывает каркас сам, а зовёт
`story-plan`. Класс доказательства — C.

## Сшитая реплика с согласованием

### bateman-game-writing:P-17 · bateman-game-writing:RED-09 · Собирай реплики из кусков только с согласованием

Реплику можно собирать из кусков: так комментатор в спорте склеивает фразы с подставленным именем и счётом.
Подстановка экономит текст, но русский склоняет и спрягает, и шов виден сразу: «Ася узнал» — нет согласования. Подставлять можно
имена, числа и целые фразы. Если подставленное слово меняет род, число или падеж соседних, условием выбирай всю
фразу, а не одно слово. Красный флаг RED-09: в подставленной фразе не согласован род или число. Проверка —
собрать итоговые строки с `{…|…}` внутри предложения на всех путях (`story:trace` разными персонами) и прочитать
уникальные варианты списком вслух.

- **Когда не работает.** Вариантов больше трёх или они меняют смысл фразы — пиши фразы целиком под условием.

### bateman-game-writing:PAT-09 · Сшитая реплика: переменная внутри предложения

- **Схема.** Переменная → внутри предложения `{cond:вариант|иначе}` → у каждого варианта согласованы род, число,
  падеж. Пробел после двоеточия не ставь: он уйдёт в сообщение и даст двойной пробел.
- **Когда не работает.** Три условия в одной строке уже трудно проверять — проще две строки под
  `{cond: … - else: …}`.
- **Масштаб.** Почти ноль текста, зато внимательное чтение каждого итогового варианта.
- **basis:** secondary (Adams в книге Бейтман), согласование по-русски — наше; оба варианта ниже прочитаны.

```ink
# contact: roman, Роман, indigo
VAR blamed = ""
-> who
=== who ===
кто, по-твоему, не расписался? #from:roman #delay:3s
* [Глеб #to:roman]
    ~ blamed = "gleb"
* [Вера #to:roman]
    ~ blamed = "vera"
- {blamed == "gleb":глеб|вера} уже узнал{blamed == "vera":а}, кто на {blamed == "gleb":него|неё} показывает #from:roman #delay:5s
-> END
```

Итоговые варианты: «глеб уже узнал, кто на него показывает», «вера уже узнала, кто на неё показывает». Род
игрока подстановкой не ставим и здесь: «ты на него показал» приписало бы игроку пол (ST-35, C-14).

### bateman-game-writing:SYS-5 · Взаимозаменяемые реплики: сначала выпиши все варианты

Система Адамса для спортивного комментатора: изучить материал → разложить фразы по категориям → писать
фрагменты по категориям → склеивать с подстановкой. Пропуск раскладки даёт фразы, которые не стыкуются. Для
глав из неё берём один урок: прежде чем писать подстановку, выпиши все варианты, в которые она развернётся, и
прочитай их вслух. Целиком система нам почти не нужна — комментатора в переписке нет.
