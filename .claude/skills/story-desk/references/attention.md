# Внимание: какие разделы `attention-merged.md` берёт `story-desk`

У `story-desk` своих разделов внимания нет (`owners.md` §1, §6): он не пишет текст для игрока. Разделы, на
которые он опирается, берутся **ссылкой на якорь**, а не копией — текст держит владелец.

| якорь | раздел | владелец | зачем `story-desk` |
|---|---|---|---|
| [`#attn-min-process`](../../../../docs/playbook/attention-merged.md#attn-min-process) | 2.10. Процесс | `story-plan` (`attention.md`) | порядок шагов на короткой истории: сначала скелет и бот, кульминация раньше начала, суперкат основного пути, понятность — бот, потом свежий человек; ядро — в `docs/stories/<id>/`, а не в шапке ink |
| [`#attn-superseded`](../../../../docs/playbook/attention-merged.md#attn-superseded) | 9. Отменённое решениями автора | `story-kb` (`superseded.md`) | при записи решения и при сверке плана не поднимать отменённое как действующее (срок паузы, часы игрока, быстрый режим «после финала», концепт-шапки в ink) |

Читать: раздел по ссылке (`docs/playbook/attention-merged.md`, поиск по якорю). Числа нагрузки (`#attn-load`) —
только ключами `thresholds.json`; `story-desk` их не применяет.

## Как раздел «Процесс» ложится на состояние

- «Сначала скелет, потом реплики» → шаг `plan` закрывается скелетом всей истории (`systems/cycle.md`); просьба
  писать главы до скелета — развилка «просьба не к текущему шагу» (`decisions-desk.md`).
- «Начало каждой версии читает тот, кто его не видел» → после переписи ранних глав (Б-1) в «Открытые вопросы»
  `STATUS.md` — нужен свежий человек на начало (ведёт `story-playtest`).
- «Ядро — в `docs/stories/<id>/`» → ядро — запись D-NN, на неё ссылается `STATUS.md`.

## Внимание автора

Тема раздела — внимание игрока, но у `story-desk` есть и своя: внимание автора, который возвращается к истории
через неделю. Наше правило (не из `attention-merged.md`): ответ «где мы» умещается в один экран — шаг, ядро,
план, открытые вопросы, три последних решения, что устарело, следующий шаг. Это вывод `npm run story:status` и
`story-status.mjs --next`; подробности — по просьбе.
