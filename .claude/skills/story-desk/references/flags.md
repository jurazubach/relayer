# Признаки: состояние истории в порядке или нет

Красные (К1…) — что сломано или устарело; зелёные (З1…) — что работает. Номера местные, не правила R-NN. У каждого — команда, которой его видно, и правка.
Числа — только из команд; на глаз состояние не оценивается.

## Красные

| | признак | как обнаружить | правка |
|---|---|---|---|
| К1 | Папки состояния нет, а история в работе | `npm run story:status -- --all` («без состояния») | `story-status.mjs --init <id>`, шаг по факту |
| К2 | Шаг не из списка плана §7 | `story:status` («не из списка»), `story-status.mjs --check` | `story-status.mjs --step <шаг>` |
| К3 | Шаг после `directions`, а ядро не указано | `story-status.mjs --check` | записать ядро D-NN или вернуться к `story-core` |
| К4 | Ядро в `STATUS.md` не найдено в журнале | `story-status.mjs --check` | `decision-add.mjs --kind ядро --set-core` |
| К5 | План построен на старом ядре (`core: D-01`, ядро D-07) | `stale-check.mjs` п. 1 | перестроить план или отвергнуть в банк; агенту — перезапуск |
| К6 | Главы старше ядра или плана, а в «Устарело» пусто | `stale-check.mjs` п. 3 | `--mark` после согласия; перечитать главы целиком |
| К7 | Ревью или итоги волны старше правок глав, а на них ссылаются как на свежие | `stale-check.mjs` п. 4 | новое ревью по изменённым главам; свежий человек на начало |
| К8 | Поздние главы пользуются приёмами, которых нет в первых (`narrative-postmortems:RED-12`) | `stale-check.mjs --tags-only` | перепись ранних глав после последней (Б-1, `staleness.md`) |
| К9 | Отклонённая находка всплывает снова, хотя узел не менялся | `stale-check.mjs` п. 6 («тот же») | не поднимать; ревьюер берёт список отклонённых до отчёта |
| К10 | Две истории с «активная: да» | `story-status.mjs --check` | `story-status.mjs --activate <id>` |
| К11 | У главы второго автора не записан ведущий | `story-status.mjs --owners`, `--check` | строка в «Кто что пишет», решение D-NN |
| К12 | Идея в банке без причины или условия возврата | `idea-park.mjs --list` (колонка «⚠ нет») | дописать или удалить |
| К13 | Решение переписано задним числом вместо новой записи | `git log -p docs/stories/<id>/decisions.md` | вернуть запись, новое решение с `--replaces` |
| К14 | Опора решения указывает на несуществующее правило | `decision-add.mjs` откажет при записи | взять ID из `npm run story:rule` |

## Зелёные

| | признак | как обнаружить |
|---|---|---|
| З1 | У каждого плана в первой строке `core: D-NN`, и он равен ядру в `STATUS.md` | `stale-check.mjs` п. 1 пуст |
| З2 | В «Открытые вопросы» `STATUS.md` заранее записана перепись глав 1–2 после поздних | чтение `STATUS.md` на шаге `chapters:3-N` |
| З3 | Каждое отвергнутое направление и план — в банке с причиной и условием | `idea-park.mjs --list` без «⚠» |
| З4 | Откат ядра — отдельной записью, отвергнутое ядро — в банке | журнал: `вид: откат`, банк: `вид: ядро` |
| З5 | Второй автор по выводу `story:vars`, `story:endings` и карте отвечает, какой финал получит игрок с заданными переменными | передача главы (`multi-author.md`) |
| З6 | `story-status.mjs --check` зелёный у всех историй | команда, код выхода 0 |

## Как ведёт себя скилл на флаге

1. Флаг — по выводу команды, с номером из этой таблицы и строкой вывода.
2. Правка, которая пишет в `STATUS.md`, `decisions.md` или `ideas.md`, — только после согласия автора.
3. Правка ink — не здесь: флаг передаётся владельцу (К8 — `story-fix` по `staleness.md`).
