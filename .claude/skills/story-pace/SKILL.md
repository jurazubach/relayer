# story-pace — где игроку станет скучно

Скучно не от длины, а от того, что **ничего не меняется** и игрок **ничего не решает**. Скилл находит такие места
числами из команд (серии без кнопки C-35, затишье C-36, темп и пропорции глав C-38, повороты сцен, середина),
сверяет каждую находку с ink и правилом и предлагает правку приёмами F-05, F-06 и приёмами из references.
**«Скучно» — только кандидат с пометкой:** окончательно решает живой человек (`story-playtest`). Числа — только
из команд, пороги — ключами `docs/playbook/thresholds.json`. Текст сам не правит: предлагает варианты, применяет
`story-fix` после одобрения.

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`.
Длинный вывод — `--summary` или `--chapter N`, а не обрезка. Упала команда — «нет данных: <команда>», не угадывай.

## Границы

- **Вход:** история `src/stories/<id>/` (или папка / `.json`), симптом автора («тянется», «провисает») или вызов `story-review`.
- **Выход:** находки строкой формата, варианты правки с приёмом и ink, отчёт для `story-desk`, «объясни».
- **Не здесь:** первые 30 с, глава 1 до первой кнопки, монолог в начале (F-04) — `story-opening`; крючок перед паузой,
  возвращение, пачка после паузы, сессии C-33 — `story-pauses`; длина истории, режимы, напоминания, давление C-37 —
  `story-time`; длина одного сообщения C-34, повторы C-46, голос — `story-voice`; хвост после последней кнопки C-42 —
  `story-endings`; кнопки, эхо, правила хабов C-19 — `story-choices`; опоры и формула главы — `story-plan`; применить —
  `story-fix`; записать в состояние — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг не тот
   (идея, ядро без скелета) — скажи. Нет `STATUS.md` (история вне цикла, мутант) — работай и отметь это.
2. **Замер.** `npm run -s story:lint -- --story <id> --only C-35,C-36,C-38` (папка вне каталога — путь вместо id).
   Длинно — тот же вызов с `--summary`.
3. **Ритм по главам:** `node ${CLAUDE_SKILL_DIR}/scripts/pace.mjs --story <id>` — самая длинная серия и узел, где у
   неё больше строк, монолог, затишье, цепочка без конкретики, доли глав, ровные паузы, передышки.
4. **Повороты:** `node ${CLAUDE_SKILL_DIR}/scripts/turns.mjs --story <id>` — узлы без перемены с долей прогонов, биты
   без разрыва. Для главы под вопросом: `node ${CLAUDE_SKILL_DIR}/scripts/turns.mjs --story <id> --chapter N --scenes`.
5. **Середина:** `node ${CLAUDE_SKILL_DIR}/scripts/middle.mjs --story <id>` — окно `C-38.middle_window`, события в нём,
   инициатива игрока, отказы и темп до и после.
6. **Сверка с ink — обязательно, до отчёта (LOCAL-04).** Каждую находку открой в узле ink и сверь с правилом:
   `npm run -s story:rule C-35` (или R-NN). Частые ложные: финал-развязка (это C-42); исповедь после выбора
   «выслушать»; чтение документа с ровным ритмом; сцена горя без кнопок; «передышка», где угроза сказана словами
   вне словаря; узел-склейка; узел редкой ветки. Не подтвердилась — «ложное: почему» или `// намеренно: C-NN причина`.
7. **Суждение модели** — там, где замер молчит: два чувства в очереди (R-80), знак ценности в начале и конце сцены по
   `--scenes` (R-29), меняет ли факт середины цель (R-30). Помечай «модель» и уверенность; «скучно» — «кандидат».
8. **Правка.** Прочитай `docs/style.md` (ST-01, ST-02, ST-52) прямо перед тем, как писать реплику, кнопку или пример
   ink. Симптом → приём: [references/decisions-pace.md](references/decisions-pace.md). Два-три варианта, до/после на
   ink, теги только `ready`.
   **Одобрено → вызови `Skill story-fix` с пунктом и вариантом; сам `Edit` не делай** — и когда одобрение пришло в той
   же фразе («почини, вариант выбери сам, одобряю»): страховка `fix-guard` и дифф реплик есть только у `story-fix`.
9. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи записать
   находки через `story-desk` (раздел «Состояние»); применяется только одобренное.

## Главные правила

- **R-61** серия без кнопки — не длиннее `C-35.series_ch1` в главе 1 и `C-35.series` дальше; монолог одного `#from` —
  до `C-35.monologue`; рассказ режут кнопкой-реакцией с содержанием, не «дальше» (C-35).
- **R-60** ритм рваный: очередь, тишина, скачок темы (`style.queue`); ровные паузы — `C-38.pause_spread`.
- **C-36** затишье: серия без события, узел без перемены, цепочка без конкретики — кандидаты `[модель]`.
- **R-29** в каждой сцене что-то поворачивается; три одинаковых знака подряд притупляют.
- **R-80** в каждой очереди два несовместимых чувства, не названных прямо; вялую сцену чинят близостью, потом подачей,
  событие — последним.
- **R-30** середина (`C-38.middle_window`) меняет цель; после неё отказов больше, игрок пишет новым адресатам.
- **C-38** темп и пропорции глав; две передышки подряд — подсказка, задуманную гасит `// намеренно: C-38`.
- **«Скучно» — кандидат** до живого теста (`narrative-testing:contra-6`): замер даёт место, человек — вердикт.

## Формат находки

```
P1 · скучно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем, приём F-NN — в поле правки (нет F-NN — имя приёма из references). Тип:
скучно / непонятно / не верю / нестыковка / баг. **P1** — ствол, через который идёт почти каждый прогон (серия-ошибка,
середины нет); **P2** — заметно в главе (серия выше порога, три сцены одного знака); **P3** — шлифовка (ровные паузы,
плоская очередь). Похожие находки одной главы — одна строка с перечнем узлов. «Скучно» без человека — с пометкой
«кандидат». Отклонённая автором находка не всплывает, пока не изменится узел. Просят JSON — `node`, `check`, `summary`, `fix`.

## Состояние

`story-pace` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-pace.md`: находки строками формата, сверка (ложные с причиной),
  таблица знаков сцен главы, предложенные правки;
- одну строку для `STATUS.md`: «ритм <дата>: P1 — N, P2 — M, главное — …, кандидаты «скучно» — на живой тест, отчёт — reviews/…».

## Готово, когда

Все находки замера сверены с ink и правилом и разобраны: правка с приёмом, `// намеренно:` или «ложное» с причиной;
у правки — до/после на ink и перезапуск замера; кандидаты «скучно» переданы на живой тест; запись в состояние предложена.
