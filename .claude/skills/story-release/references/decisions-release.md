# Развилки выпуска: находка → решение

Каждая запись: если пункт гейта такой — что решить, когда решение не работает, как оно выглядит на коротком и
длинном тексте, на чём стоит. Числа — только из команд (`release-gate.mjs`, `card-check.mjs`,
`boundary-check.mjs`, `durations.mjs`, `revision-check.mjs`, `pack.mjs`), пороги — ключами `thresholds.json`.
Гейт ничего не правит: решение — вариант для автора, правка — `story-fix` после одобрения.

## Готова ли история

### «Шаг в STATUS — review, а просят выпуск»

- **Если** шаг не `playtest:wave2` и не `release` → скажи прямо: выпуск раньше цикла. Варианты: А — довести
  цикл (`story-review` целиком, потом `story-playtest` волна 2); Б — выпустить часть как набор для теста
  (`story-playtest`, `playtest-kit` с `beta_stop`), это не выпуск; В — автор решает выпускать как есть, это D-NN
  с причиной.
- **Когда не работает.** STATUS устарел (шаг не передвинули после теста) — сверь с `reviews/` и `playtests/`,
  предложи `story-desk` обновить шаг.
- **Масштаб.** Короткая история (одна-две главы, по клику до `lab.playtest.short_story_min`): одной волны
  хватает. Длинная: волна 2 на главах 3–N обязательна.
- basis: checked (`build-plan.md` §2, §7).

### «Линт: есть ошибки»

- **Если** ошибок больше `skill.release.lint_errors` → ✗, выпуска нет. Каждая ошибка — владельцу по
  `owners.md` §3 (строка находки называет «чинит <скилл>»), правка — `story-fix`. Тупик C-52 и недостижимое C-15
  меткой `// намеренно:` не гасятся.
- **Когда не работает.** Ошибка — ложная (проверка не знает приёма): сверь с ink и `npm run -s story:rule C-NN`;
  ложная — в отчёт с причиной и просьба владельцу проверки, а не метка ради зелёного гейта.
- **Масштаб.** 5 сообщений: ошибок обычно нет. 50+ узлов: ошибки часто — одна причина в нескольких местах;
  группируй по проверке.
- basis: checked.

### «Линт: много предупреждений»

- **Если** ошибок нет, а предупреждения есть → ⚠, не блок. Приоритет — по общей таблице
  `.claude/skills/story-review/references/priority.md`: P1 «непонятно» решить до выпуска, остальное — автор
  выбирает «чинить / намеренно (D-NN) / потом».
- **Когда не работает.** Предупреждения этики (C-27, C-32, C-37, C-47) — не «потом»: строка «этика» гейта и
  [ethics.md](ethics.md).
- **Масштаб.** Длинная история даёт десятки предупреждений одной проверки — показывай счёт и 2–3 примера.
- basis: checked.

### «Второй волны теста нет или она старая»

- **Если** нет `playtests/wave-2/`, симуляции и отчёта о волне 2 → ✗. В этом проходе живых тестов нет (INTENT):
  волна 2 — симулированная панель `story-playtest` на полной истории. **Если** волна старше последней правки
  `src/stories/<id>` → ⚠: повторить на правленых главах.
- **Когда не работает.** Правка — опечатка в одной реплике: повтор волны не нужен, это решение D-NN «правка без
  повтора теста» с перечнем узлов.
- **Масштаб.** Пять глав — панель на главах 3–5; десять — по частям, начиная с середины.
- basis: checked (`build-plan.md` §0, INTENT).

## Честна ли карточка

### C-49 (а) · «Число из описания не звучит в тексте»

- **Если** число карточки нет в ink → убери из `synopsis` или введи в главу 1 там, где оно естественно.
  **Если** число — служебное (`#delay:45m`, а не реплика) — тег не текст: игрок его не видит, нужна реплика.
- **Когда не работает.** Число — нарочная ложь `tagline`, которая переворачивается в главе 1 → метка
  `// намеренно: C-49 ложь` в узле переворота.
- **Масштаб.** Одно число — правка одной строки. Таблица фактов (г) с десятками якорей — к `story-continuity`.
- basis: checked (три истории каталога, S-release).

### C-49 (б) · «Карточка называет героя, который появится поздно»

- **Если** имя из `synopsis` впервые звучит после главы `C-49.known_chapter`, а пишет герой после
  `C-49.spoiler_chapter` → замени имя ролью («кто-то из прошлого»), конкретику отдай чату.
- **Когда не работает.** Герой — завязка (его ищут с первой сцены): имя звучит в главе 1, проверка молчит — так
  и должно быть.
- **Масштаб.** Короткая история: в карточке не больше двух имён. Длинная: имена — только первой главы.
- basis: checked.

### R-11 · «Пункт features не звучит в истории»

- **Если** `C-49.feature_absent` → перепиши пункт под то, что в тексте есть, или введи обещанное в главу 1.
  **Если** `C-49.feature_ch1` (ни один пункт в главе 1) → первым поставь пункт, который сбывается в главе 1.
- **Когда не работает.** Пункт про механику приложения («сообщения приходят, пока вкладка закрыта») словами не
  звучит — проверка ложная, это видно по ink; пункт о финалах сверяет (з).
- **Масштаб.** 3–5 пунктов; больше пяти — карточка превращается в список, режь.
- basis: checked.

### C-49 (з) · «Карточка обещает финалы, а их меньше»

- **Если** `C-49.endings_min` → А: честная карточка («один финал, и он помнит твои решения»); Б: финалы есть, но
  не размечены — `story-endings` (метки `// финал:`, C-40); В: финалов правда мало — `story-endings`, это
  переделка, а не правка карточки.
- **Когда не работает.** Финал один, а различается состоянием — это не «несколько финалов» для игрока, пока
  `story:endings` не покажет разные развязки.
- **Масштаб.** «Семь финалов» в карточке требуют, чтобы обычный игрок мог дойти до каждого, а не один из сорока.
- basis: checked (`story:endings` на трёх историях).

### A-05 · «Время на карточке расходится с медианой»

- **Если** `durations.mjs` даёт другое `minutes` или `days` → впиши предложенные числа (это правка `meta.json`,
  через одобрение). **Если** медиана выше `story.length.max_h` или пауза длиннее `story.pause.max_h` → сначала
  `story-time` (сжать паузы), карточку — после.
- **Когда не работает.** Разброс по персонам большой (`--persona all`): ветки идут по-разному долго — карточка
  берёт медиану случайного, а длинную ветку чинит `story-time`.
- **Масштаб.** Короткая история — часы («≈ 3 ч»), длинная — дни; полдня точности хватает.
- basis: checked (`story:sessions`).

## Граница

### serial-hooks:P-12 · «После какой главы ставить границу?»

- **Если** крючок главы 1 сильный (`boundary-check.mjs --free 1`: крючок и выплата на большинстве прохождений,
  до выплаты не дольше `skill.release.boundary.pause_max_min`) → после главы 1 можно (INTENT). **Иначе** →
  `--free 2`: глава 2 даёт второй-третий разговор с героем и самый сильный крючок до середины. Когда не работает:
  в истории две-три главы — граница после главы 1 оставляет бесплатным слишком мало, игроку не к кому
  привязаться; тогда граница после главы 2 или её нет. Масштаб: пять глав — после 1 или 2; десять — не позже 2.
  basis: secondary.

### «На границе нет крючка или выплата не сразу»

- **Если** крючка нет (C-39, C-26 на стыке) → А: сдвинуть границу на стык с крючком (`--free N`); Б: дописать
  крючок конца главы — приёмы `story-pauses` (F-01…F-03) через `story-fix`. **Если** выплаты нет в первых
  `skill.release.boundary.payoff_lines` входящих → начало платной главы отвечает на крючок. **Если** после
  открытия долго ждать → пауза строки `#chapter` короче или длинная пауза — дальше в главе.
- **Когда не работает.** Крючок — решение игрока («кому поверить»), выплата — последствие, словами не совпадает:
  `boundary-check.mjs` не найдёт общих слов. Сверь окно «до/после» глазами.
- **Масштаб.** Одна граница на историю; на ней — самый сильный крючок бесплатной части.
- basis: checked (мутант m19; три истории с `--free 1`).

## Этика, ревизия, файл

### R-115 · «Можно дать купить ускорение? Кнопку „узнать сейчас“?»

- **Нет** → ✗, без вариантов: пауза не продаётся, «по клику» бесплатен с начала (A-04). Если автор хочет
  монетизацию — платная граница по [free-boundary-gate.md](free-boundary-gate.md), больше ничего.
- **Когда не работает.** Никогда: это решение автора выше базы.
- **Масштаб.** Одинаково для любой длины.
- basis: checked (INTENT, `build-plan.md` §12).

### «Ревизия: ломает ли правка сохранения?»

- **Если** `revision-check.mjs` → ✗ «поднять» → `revision` +1 в `meta.json` и строка в журнале изменений.
  **Если** ℹ «зря» → вернуть прошлое число. **Если** ломать не хочется → оставить старые узлы и переменные
  (узел-переход на новое место), тогда revision не трогают.
- **Когда не работает.** Прошлого выпуска нет (тега нет) — сравнивать не с чем; после выпуска поставить тег.
- **Масштаб.** Правка одной главы в начале — тот же риск, что и всей истории: сохранение помнит пути.
- basis: checked (`docs/capabilities.json` → `revision`).

### «Файл выпуска не собирается или склейка играется иначе»

- **Если** `pack.mjs` ✗ → раскладка по `CLAUDE.md` «Как добавить историю» (узлов в `story.ink` нет, `INCLUDE` —
  только из главного файла); готовый `.json` разложить — `npm run story:unpack`.
- **Когда не работает.** История одним `.ink` вне каталога — её сначала раскладывают в папку.
- **Масштаб.** Не зависит от длины.
- basis: checked.

### «Выкладываем на Pages?»

- **Нет, не сами.** Выпуск в каталог — пуш в `master`, это деплой; в конвейере его не делают (INTENT). Гейт
  готовит отчёт, тег и файл `pack.mjs --write`; пуш — автор.
- basis: checked.
