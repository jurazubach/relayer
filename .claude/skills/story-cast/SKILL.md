# story-cast — состав: кто пишет игроку, когда и зачем

«Чатов слишком много» — это перегруз **линий**, а не имён: перегружает тот, кто ждёт ответа и ничего не решает.
Скилл раскладывает контакты по уровням (ось / сторона / источник / фон / эпизодический — `npm run story:cast`), даёт
каждому функцию, расписание открытия и дугу, дозирует фон. Числа — только из команд, пороги — ключами
`docs/playbook/thresholds.json`. Текст не правит сам: предлагает варианты, применяет `story-fix` после одобрения.

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`. Длинный
вывод — `--summary` или `--json`. Упала команда — «нет данных: <команда>», не угадывай.

## Границы

- **Вход:** история `src/stories/<id>/` (папка или `.json`), скелет `--plan`, симптом автора или вызов `story-review`.
- **Выход:** находки строкой формата, варианты правки (карточка `characters`, перенос `#unlock`, слияние, реплика),
  отчёт для `story-desk`, «объясни».
- **Не здесь:** экран до первой кнопки и нагрузка начала (R-18) — `story-opening`; голоса, имена, юмор, регистры —
  `story-voice`; «ответил не тот» на кнопку-вопрос (C-10), выбор между людьми (C-17) — `story-choices`; кто что знает
  между чатами — `story-continuity`; противник, тема, ядро — `story-core`; финал и распределитель — `story-endings`;
  паузы и крючок перед ними — `story-pauses`; напоминания при молчании — `story-time`; применить правку —
  `story-fix`; записать в состояние — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг не тот
   (идея, ядро без скелета) — скажи; на скелете работай с `--plan`. Нет `STATUS.md` (мутант, вне цикла) — отметь.
2. **Замер.** `npm run -s story:lint -- --story <id> --only C-21,C-45,C-50` (скелет:
   `npm run -s story:lint -- --plan --story <id> --only C-21,C-45`). Длинно — тот же вызов с `--summary`.
3. **Карта состава:** `node ${CLAUDE_SKILL_DIR}/scripts/cast.mjs --story <id>` — уровень из `story:cast`, `role`,
   `about`, `arc`, находки по контакту, кто пишет первым по главам (R-79). Развилки уровней — [references/tiers.md](references/tiers.md).
4. **Расписание:** `node ${CLAUDE_SKILL_DIR}/scripts/unlock-plan.mjs --story <id>` — новые по главам, как входят,
   первые реплики, сколько чатов ждут ответа. Читай [references/unlock-schedule.md](references/unlock-schedule.md).
5. **Дуги:** `node ${CLAUDE_SKILL_DIR}/scripts/arcs.mjs --story <id>` — первая и последняя реплика, `#rename`,
   «Вы» → «ты», голос по C-44, ось. Читай [references/arcs.md](references/arcs.md).
6. **Сверка с ink — обязательно, до отчёта.** Каждую находку открой в узле ink и сверь с правилом:
   `npm run -s story:rule C-45` (или `R-NN`). Чаще всего ложное: служебный без `service: true` (C-21, C-45), гость
   главы с закрытой линией (C-45 п. 3), «Прочитано» или ответ через свидетеля (C-50 (а)), канал тревог, который
   несёт сюжет (C-50 (в)). Не подтвердилась — «ложное: почему» или `// намеренно: C-NN причина`.
7. **Суждение модели** — только где замер молчит: функция — профессия, позиции одинаковы, первая и последняя
   реплика совпадают по смыслу, первая реплика нового — справка. Помечай «модель» и уверенность.
8. **Правка.** Прочитай `docs/style.md` (ST-20…ST-26 о голосах, ST-30…ST-38 о кнопках) прямо перед тем, как писать
   реплику, кнопку, карточку или пример ink. Симптом → решение: [references/decisions-cast.md](references/decisions-cast.md).
   Два-три варианта, до/после на ink или `meta.json`, теги только `ready`.
   **Одобрено → вызови `Skill story-fix` с пунктом и вариантом; сам `Edit` не делай** — и когда одобрение пришло в той
   же фразе («почини, вариант выбери сам, одобряю»): страховка `fix-guard` и дифф реплик есть только у `story-fix`.
9. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи записать в
   состояние через `story-desk` (раздел «Состояние»); применяет только одобренное.

## Главные правила

- **R-77** мало контактов, у каждого достаточно реплик; новых — по `C-21.new_ch1` / `C-21.new_other` (C-21, C-45).
- **R-76** в `role` — функция, а не профессия; смена функции — в служебном `arc`; каждый `# contact:` в `characters`.
- **R-78** новый контакт в первых репликах показывает голос, желание и откуда знает игрока.
- **R-79** основной персонаж пишет первым по своей причине; проводник — по запросу (`C-45.reactive`).
- **R-88** каждый блок делает работу; фон — в доле `C-50.noise_share`, из канала ядра (C-50 (в)).
- **R-90** у каждого заметного контакта своя позиция по `// вопрос:`; споры NPC — через игрока.
- **R-83** неожиданный поступок готовят два намёка; полная дуга — у одного носителя (R-82).
- **C-50** ответ не уходит в пустоту, шум не встаёт между вопросом и кнопкой.

## Формат находки

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем, приём — в поле правки (своих F-NN у скилла нет: «перенести `#unlock`»,
«слить контакты», «`service: true`»; ремонт чужим приёмом — с его F-NN). Тип: непонятно / скучно / не верю /
нестыковка / баг. **P1** — путаница или брошенная линия, которая ломает главу («в главе 1 восемь новых, четверо без
обмена»); **P2** — заметно в главе («сторона ничего не решает», «ответ ушёл в пустоту»); **P3** — шлифовка. Нет
узла — `глава N` или `история`. Отклонённая автором находка не всплывает, пока не изменится узел. JSON — те же поля.

## Состояние

`story-cast` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-cast.md`: находки строками формата, сверка (ложные с причиной),
  карта состава (уровни, функции), предложенные правки;
- одну строку для `STATUS.md`: «ревью состава <дата>: P1 — N, P2 — M, главное — …, отчёт — reviews/…».

## Готово, когда

Находки C-21, C-45, C-50 сверены с ink и правилом и разобраны (правка, `// намеренно:` или «отклонено» с
причиной); у каждого заметного контакта названы функция и уровень; у правки — до/после и перезапуск замера; запись
в состояние предложена.

## Объясни

По запросу «объясни»: **почему** (что почувствует игрок), **откуда** (`npm run -s story:rule R-NN`, `алиас:ID` из
[references/sources.md](references/sources.md), класс урока), **как сделать самому** — упражнение из
[references/explain.md](references/explain.md).
