# story-pauses — чтобы игрок вернулся после паузы

В реальном времени пауза — место, где игрок закрывает вкладку. Вернёт его только **крючок**, который он унёс с
собой; вернувшемуся нужна **первая строка-событие** с якорем на то, о чём речь; возвращение должно **окупиться**
— сессией с кнопками, а не тремя строками. Скилл находит, где этого нет, числами из команд, сверяет каждую находку
с ink и правилом и предлагает правку приёмами F-01, F-02, F-03. Пороги — ключами `docs/playbook/thresholds.json`.
Текст сам не правит: предлагает варианты, применяет `story-fix` после одобрения.

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`. Составная
команда получает отказ в правах. Длинный вывод — `--summary` или `--json`. Упала команда — «нет данных: <команда>».

## Границы

- **Вход:** история `src/stories/<id>/` (или папка / `.json`), симптом автора или вызов `story-review`.
- **Выход:** находки строкой формата, варианты правки с приёмом и ink до/после, отчёт для `story-desk`, «объясни».
- **Не здесь:** причина паузы и запрет срока возвращения, режим «по клику», ночь, напоминания при молчании,
  длина истории и пауза больше суток — `story-time` (C-27, C-31, C-32, C-47); серии без кнопки и затишье внутри
  сессии — `story-pace`; кнопки, эхо переменных, `#silent` — `story-choices`; честность улик — `story-mystery`;
  расписание пауз в плане — `story-plan`; первые минуты истории — `story-opening`; применить правку — `story-fix`;
  записать в состояние — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг не тот
   (идея, ядро без скелета) — скажи. Нет `STATUS.md` (история вне цикла, мутант) — работай и отметь это.
2. **Замер.** `npm run -s story:lint -- --story <id> --only C-26,C-28,C-29,C-30,C-33,C-39` (папка вне каталога —
   путь вместо id). Слишком длинно — тот же вызов с `--summary`.
3. **Пары «до / после»:** `node ${CLAUDE_SKILL_DIR}/scripts/hook-pairs.mjs --story <id>` — каждая пауза: последняя
   реплика, крючок, догадка о типе, первая строка после, якорь, пачка, пауза после пустой развилки. Тип крючка
   (угроза, откровение, дилемма, прибытие, событие мира, отношения) ставишь ты по тексту — R-66.
4. **Пачка и сессии:** `npm run -s story:sessions -- --story <id> --persona distracted`, затем
   `node ${CLAUDE_SKILL_DIR}/scripts/return-pack.mjs --story <id>` — что отвлечённый читает стеной и чем она начинается.
5. **Стыки и память:** `node ${CLAUDE_SKILL_DIR}/scripts/seams.mjs --story <id>` (C-39),
   `node ${CLAUDE_SKILL_DIR}/scripts/notes-map.mjs --story <id>` (заметки, R-100).
6. **Сверка с ink — обязательно, до отчёта.** Каждую находку открой в узле ink и сверь с текстом правила:
   `npm run -s story:rule R-NN` (или `C-NN`). Частые ложные: прощание-угроза («спокойной ночи 🙂» от противника);
   тревожная пауза без причины (`messenger-genre:P-01#нюанс`); событие утверждением в начале главы (C-39 б);
   подпись или служебная строка как «формула»; длинная кульминация с частыми кнопками (C-33). Не подтвердилась —
   «ложное: почему» или `// намеренно: C-NN причина`.
7. **Суждение модели** — только где замер молчит: тип и чередование крючков, обещанное сбылось (R-69), рекап
   напоминает невыбранное (R-71). Помечай «модель» и уверенность. Развилки — по карте references ниже.
8. **Правка.** Прочитай `docs/style.md` §8 (ST-60…ST-68) прямо перед тем, как писать реплику, кнопку или пример
   ink. Симптом → приём: [references/decisions-pauses.md](references/decisions-pauses.md). Два-три варианта,
   до/после на ink, теги только `ready`, без срока возвращения (A-01).
9. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи записать
   находки в состояние через `story-desk` (раздел «Состояние»); применяется только одобренное.

## Главные правила

- **R-64** крючок до паузы, а не после; прощание — до крючка; ключевое слово в превью (`style.preview_chars`) — C-26.
- **R-65** пауза после события, а не перед ним; не посреди инструкции; анонс без содержания — C-29 `C-29.tease`.
- **R-66** жёсткий обрыв — на `#chapter` и у самой длинной паузы; типы чередуются; формула не чаще `C-29.closing_repeat`.
- **R-68, R-69** первая строка после паузы — событие, а не «привет»; обещанное сбывается, крючок не отменяют — C-28, C-29.
- **R-70, R-71** напоминание вшито в новость, по длине паузы (`attn.recap.*`); по ветке — условной строкой.
- **R-72** кнопка не дальше `C-28.pack` входящих (после `C-28.pack_long_pause_s` — `C-28.pack_long`); новичок не первым.
- **R-62** возвращение окупается (`C-33.return_min_msgs`); паузы подряд без кнопки — C-30; микросессии — склейка F-03.
- **R-100** что понадобится через паузу — в заметки с переменной, которую потом читают.
- **A-01** причины ухода — да, срока возвращения — нет (C-27 у `story-time`).

## Формат находки

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем, приём F-NN — в поле правки. Тип: непонятно / скучно / не верю /
нестыковка / баг. **P1** — игрок не вернётся или не поймёт возврат («перед самой длинной паузой главы — „ладно,
пока“»); **P2** — заметно в главе («после пяти пауз подряд первым идёт приветствие» — одна находка, не пять);
**P3** — шлифовка («ключевое слово крючка дальше превью»). Отклонённая автором находка не всплывает, пока не
изменится узел. Просят JSON — те же поля: `node`, `check`, `summary`, `fix`.

## Состояние

`story-pauses` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-pauses.md`: находки строками формата, таблица крючков главы
  (тип каждой паузы), сверка (ложные с причиной), предложенные правки;
- одну строку для `STATUS.md`: «ревью пауз <дата>: P1 — N, P2 — M, главное — …, отчёт — reviews/…».

## Готово, когда

Все находки замера сверены с ink и правилом и разобраны: правка с приёмом, `// намеренно:` или «отклонено» с
причиной; у правки — до/после на ink и перезапуск замера; типы крючков размечены в отчёте; запись в состояние
предложена.
