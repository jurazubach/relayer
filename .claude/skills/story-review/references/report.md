# Отчёт автору: что в нём, в каком порядке и сколько

Отчёт собирает `node ${CLAUDE_SKILL_DIR}/scripts/report.mjs --story <id> --explain` из `merged.json`. Модель
не переписывает его своими словами: она добавляет разговорную часть после списка (что главное, с чего начать,
какие варианты правки есть у владельцев) и отвечает на вопросы автора.

## Порядок разделов

1. **Шапка:** история, ревизия `meta.json`, коммит, режим, какие линзы и читатели отвечали, счёт `story:lint`
   и как он сверен (подтверждено / ложное / не разобрано / не сверено), итог P1/P2/P3.
2. **Поломки** — всё типа «баг»: тупики, недостижимое, сломанная разметка (C-52, C-15, C-53). Пустой раздел
   пишется словами «нет» — так видно, что проход был (`narrative-testing:P-02`).
3. **По главам** — впечатление: в каждой главе не больше `skill.review.top_per_chapter` находок, по порядку
   P → тип (баг, непонятно, нестыковка, не верю, скучно) → глава ([priority.md](priority.md)). Находки без
   главы — «Вся история».
4. **Приложение:** остальные находки глав тем же форматом; замер без сверки счётом по проверкам и главам;
   ложные срабатывания с предложением `// намеренно:`; отклонённое автором; человек против замера (Б-3);
   «вне линзы»; «нет данных».
5. **Строка для `STATUS.md`** — её записывает `story-desk` после одобрения.

## Режим «объясни»

`--explain` добавляет под каждой находкой основного списка «почему важно» из трёх частей:
- что почувствует игрок (по типу — [priority.md](priority.md));
- какая проверка и зачем она (заголовок `C-NN` и колонка «зачем» из `checks.md`);
- насколько этому верить: замер, сверенный аудитором; кандидат модели; симптом человека.

Если автор спрашивает дальше — «откуда правило» (`npm run -s story:rule C-NN`, ID источника из
[sources.md](sources.md)) и «как сделать самому» (упражнение из [explain.md](explain.md)).

## Разговорная часть после списка

- Одна-две фразы о главном: «сначала глава 1 — там два P1 „непонятно“, остальное потом».
- По каждому P1 — какой скилл-владелец чинит и каким приёмом; варианты правки на ink строит `story-fix`
  после одобрения (ревью реплик не пишет — LOCAL-09: если автор просит пример реплики, сперва `docs/style.md`).
- Вопрос автору с вариантами: что берём в работу, что отклоняем (отклонённое — через `story-desk` с хэшем
  узла), что откладываем до тестеров.

## Чего в отчёте нет

- Рецептов тестеров как правок ([conflicts.md](conflicts.md)).
- Чисел без команды: если команда упала — «нет данных: <команда>».
- Неподтверждённых строк замера в основном списке (LOCAL-04) — только в приложении счётом.
- Имён и узлов чужих историй в примерах: примеры в отчёте — из этой истории, в references — выдуманные.

- **Когда не работает.** `--lint-only` (аудиторы не запускались): отчёт помечен «только замер», все строки —
  «не сверено»; это черновик для быстрого взгляда, а не ревью.
- **Масштаб.** 5 сообщений — отчёт на один экран, приложение пустое. 10 глав — основной список до
  `skill.review.top_per_chapter` × глав, приложение длиннее: это нормально, автор начнёт сверху.
- basis: our_estimate (W0: больше тысячи строк замера на три истории; правка 8 чекпоинта).
