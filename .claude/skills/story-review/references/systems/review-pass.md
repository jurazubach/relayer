# Проход ревью: от замера к отчёту

Система ревью в нашем цикле — свод двух проходов (поломки, впечатление) и нарративного QA в один порядок шагов.
Каждый шаг — вход → выход, что будет без него, где его понимают неправильно.

| шаг | вход → выход | если пропустить |
|---|---|---|
| 1. состояние | `STATUS.md` → режим (полный, часть, скелет) | ревью скелета как текста или главы как скелета: линзы спорят о том, чего нет |
| 2. замер | история → `story:lint` в папке прогона (`review-cache.mjs`) | аудиторы замеряют каждый сам, числа расходятся |
| 3. выбор линз | признаки, находки, симптом → список линз с причинами (`select-lenses.mjs`) | десять линз на всё — шум; пропущенная линза — дыра |
| 4. аудиторы и читатель | задания → `lens-*.md`, `cold-*.md` параллельно | модель судит всё сама, в одном контексте; «непонятно» оценивает тот, кто знает историю |
| 5. QA «шесть списков» | кандидаты `qa-six.mjs` → `qa-six.md` | голос, имена и хронологию никто не читает отдельно (`narrative-testing:P-14`) |
| 6. люди (если есть) | сводка `story-playtest` → `human-*.md` | спор «ревью против тестеров» решает громкий ([conflicts.md](../conflicts.md)) |
| 7. сведение | ответы + замер + `decisions.md` → `merged.json` | дубли, отклонённое снова всплывает, ложные строки замера в отчёте (LOCAL-04) |
| 8. отчёт | `merged.json` → отчёт с P1–P3 и приложением (`report.mjs --explain`) | тысяча строк, автор не знает, с чего начать |
| 9. состояние | отчёт → `reviews/<дата>-story-review.md`, строка в `STATUS.md` (через `story-desk`) | находки не доходят до истории (LOCAL-10) |

**Ошибки понимания.**
- Ревью = прогон `story:lint`. Нет: замер — шаг 2 из девяти; без сверки и впечатления это черновик (`--lint-only`).
- Ревью правит текст. Нет: ревью предлагает приём владельца; применяет `story-fix` после одобрения (INTENT).
- Чем больше находок, тем лучше ревью. Нет: хорошее ревью — короткий список того, что чинить первым, и честное
  приложение.

**Короткая форма.** История на 5 минут: шаги 2, 4 (две линзы и читатель), 8. QA — одно чтение по контактам
(`qa-six.mjs --contact`).
