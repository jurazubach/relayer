# Система: ранний групповой разбор сюжета (Narrative Review Process)

По пересказу доклада о процессе в Ubisoft Montreal и аннотации статьи; конкретных вопросов анкеты и метрик в
открытых материалах нет. Пересказ свой.

### narrative-testing:SYS-2 · Разбор наброска группой до плейтеста

| шаг | вход → выход | если пропустить |
|---|---|---|
| 1. Группа | половина сценаристов, половина других людей проекта → состав | одни сценаристы найдут огрехи ремесла, но не то, чего не поймёт посторонний |
| 2. Материал | очень ранний набросок сюжетного бита → текст для заметок | разбор готовых сцен приходит, когда менять поздно |
| 3. Заметки | каждый пишет молча и отдельно → набор заметок | громкий участник задаёт мнение группы |
| 4. Сведение | заметки → отчёт ведущего | сценарист получает сырой поток и защищается |
| 5. Разговор один на один | отчёт → сценарист понимает, что нашли | группа обсуждает автора, а не текст |
| 6. Обсуждение решений | отчёт + сценарист → решения | проблемы найдены, но не решены |

- **Заявленный эффект:** сценаристы находили неизвестные им проблемы и получали помощь с известными; сам автор
  пересказа оговаривает, что успех не доказан. Это проверка наброска глазами коллег, а не игроков: понятность
  для постороннего проверяют позже (проверка понимания, [cold-reader.md](../cold-reader.md)).
- **Короткая форма для нас.** Группы нет — её роль играет панель по скелету: `story-review --plan` с холодными
  читателями разных профилей читает `skeleton.ink` (формат — `story-plan`). Заметки «молча и отдельно» — это и
  есть отдельные прогоны `claude -p`: один профиль не слышит другой. Сведение — `digest.mjs`, решения — автор
  (в конвейере — королева).
- **Когда не работает.** Читатель, видевший скелет, уже не свежий для главы 1: разбор скелета и холодный тест
  начала — разные прогоны. На скелете из пяти строк разбор вырождается в «перескажи, что будет».
- **Регрессия после разбора.** Решения разбора, которые меняют маршрут, сохраняются эталоном
  (`route-replay.mjs --save`, [build.md](../build.md)).
