# Волны теста и расход свежих глаз

Свежий взгляд на начало — расходуемый ресурс: человек, который видел главу 1, второй раз её первое впечатление
не проверит. У холодного читателя ресурс бесконечный (каждый прогон `claude -p` из пустого каталога свежий), у
живых людей — нет. Отсюда порядок: панель профилей на каждой версии, люди — волнами.

## Цикл в нашем формате

| шаг | кто | что проверяет | вход → выход |
|---|---|---|---|
| 0. скелет | `story-review --plan` с холодным читателем | структуру до прозы | скелет → правки плана |
| 1. панель | `panel.mjs` на главах 1–2 | «непонятно», «скучно», оба режима | набор → сводка «симуляция» |
| 2. волна 1 | люди, до `lab.playtest.wave1.max`, главы 1–2 | то же на людях + реальное время | набор + бриф → сводка |
| Б-2 | `story-fix` по сводке | — | правки + маршруты |
| 3. волна 2 | новые люди, вся история | всё; одного «обычного» в реальном времени | релиз-кандидат → сводка |
| 4. по списку | люди волны 1 | только список изменений | список → «починено / нет» |

Сейчас живых волн нет (решение автора): шаги 2–4 — инструменты наготове, шаг 1 — всегда. Систему целиком —
[systems/beta-cycle.md](systems/beta-cycle.md).

### narrative-testing:P-08 · Несколько раундов, в каждый — свежие люди

Исправления порождают новые баги, а тестер, который уже знает сюжет, не может проверить начало: второе
прохождение не повторяет первое впечатление, крючок уже не действует. Поэтому раунды волнами: малая быстрая
группа (до `lab.playtest.wave1.max` человек) на главы 1–2 → правки → новые люди на всю историю → тестеры первого
раунда только по списку изменений. Проверка: первую главу в каждом раунде проходит хотя бы один человек, который
видит её впервые. У симуляции свежесть дешёвая: панель гоняется заново на каждой версии. **Когда не работает:**
история до `lab.playtest.short_story_min` минут — хватит одной волны и одного свежего человека после правок; новых
людей негде взять — тогда начало после правки читает только панель, и в сводке это «симуляция».

### narrative-testing:P-08#нюанс · Постоянный и свежий — разные роли

Нюанс: Bromley запрещает звать повторно на проверку понимания тех, кто уже видел историю; Short, наоборот, держит
одного-двух постоянных тестеров. Это не противоречие: постоянный проверяет правки и края, свежий — понимание и
крючок. Не меняй их ролями: человек волны 1 в волне 2 читает список изменений, а не главу 1 «как в первый раз».
У панели та же граница: профиль, которому показали правку с объяснением, уже не холодный — новый прогон
`story:cold-read` без пояснений.

## Сколько людей и каких

- Волна 1: до `lab.playtest.wave1.max`; один «обычный» в реальном времени, один «ломатель» по клику (Э6).
- Один из «обычных» — медленный читатель (`narrative-testing:LESSON-10`) и не из круга автора
  (`procedural-storytelling:LESSON-10`); для сцены-пика — человек, знающий среду (`messenger-genre:LESSON-08`).
- Отзывы — по главам, не одним письмом к сроку (`narrative-testing:LESSON-12`); бета — ради дыр, а не ради
  оценки (`choiceofgames-design:LESSON-06`). Карточки — [lessons.md](lessons.md).
