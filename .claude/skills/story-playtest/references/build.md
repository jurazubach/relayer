# Сборка для теста, входы test_* и регрессия маршрутов

Тестерам уходит `.json` через «Загрузить историю», а не ссылка на Pages: пуш в `master` — деплой для всех.
Набор собирает `playtest-kit.mjs`, маршруты держит `route-replay.mjs`.

## Набор: что делает playtest-kit.mjs

1. Берёт главы `ch01…chNN` по `--chapters N`, остальные выбрасывает.
2. Переходы из оставленных глав в узлы выброшенных (`-> ch3`) ведёт в `beta_stop`; `VAR` выброшенных глав
   переносит в `beta_stop.ink` — иначе набор не скомпилируется. Если `beta_stop` уже есть в главах, он и конец.
3. Меняет id на `<id>-wN` и название на «… · тест N»: встроенная история с тем же id вытеснила бы загруженную,
   а прогресс тестера смешался бы с каталогом. Убирает `free_chapters`, `minutes`, `days` — они о всей истории.
4. Компилирует и гоняет бота с `--partial`: случайная, первая и последняя кнопка в обоих режимах, `lab.playtest.kit.runs`
   прогонов. Не дошёл до `beta_stop` или финала — код 1 и узел.
5. Пишет записки, анкету и `kit.json`. Перед отправкой: `npm run -s story:lint -- --story <набор.json> --partial --summary`.

### narrative-testing:PAT-02 · Волны и заглушка конца (staged beta)

Тест идёт волнами: небольшая быстрая группа на первые главы → правка → новые люди на всю историю → тестеры первой
волны только по списку изменений. В сборке волны 1 после последней готовой главы стоит конец, чтобы тестер знал,
где остановиться. Размер первой волны — `lab.playtest.wave1.max`. **Когда не работает:** правка одной реплики —
её проверяют бот и автор, волна не нужна; заглушку забыли убрать из релиза — `story:lint` без `--partial`
покажет `beta_stop` как финал без метки (проверка релиза — `story-release`).

```ink
# contact: lida, Лида, teal
-> ch1
=== ch1 ===
День 1 · Ключи #from:lida #sys:lida #chapter
ты взяла ключи от подвала? #from:lida
* [Нет #to:lida]
    странно. их нет на гвозде #from:lida
* [Взяла. Верну вечером #to:lida]
    верни до восьми. там счётчики #from:lida
- -> beta_stop
// заглушка набора: дальше глава 2 не готова
=== beta_stop ===
Конец тестовой части · вопросы в записке #sys
-> END
```

basis: secondary (Short, CoG; число волн — наше) · проверка: `playtest-kit.mjs`, `story:lint --partial`.

### narrative-testing:PAT-03 · Вход в середину с набранным состоянием (save files for branches)

Для поздних глав — тестовый узел `test_*`: выставляет переменные, как после типичного маршрута, и прыгает в
главу. Тестер «ломатель» входит через отладку прямо в главу 3, не проходя 1–2 (они уже проверены). Состояние
должно быть таким, которое реально набирается: значения сверяй с медианой бота (`npm run -s story:vars --
--story <id>`). **Когда не работает:** для теста впечатления прыжки вредят — начало и крючок проверяет свежий
человек с первой строки; узел `test_*` не должен быть достижим из игры (C-15 не считает `test_*` редким узлом, а
переход в него из сюжета — ошибка C-52, `C-52.test_entry`).

```ink
# contact: lida, Лида, teal
VAR lida_trust = 0
VAR keys_found = false
-> ch1
// вход для тестеров: глава 2 с набранным состоянием «доверчивого» маршрута
=== test_ch2_trusting ===
~ lida_trust = 3
~ keys_found = true
-> ch2
=== ch1 ===
День 1 · Ключи #from:lida #sys:lida #chapter
ключи от подвала у тебя? #from:lida
* [Да, держи #to:lida]
    ~ keys_found = true
    ~ lida_trust += 1
* [Нет #to:lida]
- -> ch2
=== ch2 ===
День 2 · Подвал #from:lida #sys:lida #chapter
{keys_found:
    я открыла подвал. счётчик крутится #from:lida
- else:
    подвал так и закрыт #from:lida
}
{lida_trust >= 3: тебе одной скажу, что я там нашла #from:lida}
-> END
```

basis: secondary (zarf о сохранениях на развилках) · проверка: `playtest-kit.mjs` печатает входы `test_*`.

## Эталон и регрессия

### narrative-testing:PAT-01 · narrative-testing:PAT-01#нюанс · Эталонный транскрипт (golden transcript)

Перед главой с развилками напиши, как её увидит игрок на одном маршруте (эталонный транскрипт): время, чат,
реплики, нажатые кнопки; отметь, где впервые звучат цель, ставка и крючок. Ветки в сценарии — отклонения от
эталона; основной маршрут потом сверяется с ним и остаётся регрессионным тестом. Нюанс: на 5 сообщениях эталон —
сама сцена; на 50 он окупается только вместе со вторым эталоном «молчуна», иначе «Промолчать» и отказы без
проверки. Компромисс: эталон пишется первым для главы середины, для главы 1 — после неё. Формат скелета до прозы
— у `story-plan` (`skeleton-format.md`). У нас эталон проверяем: `route-replay.mjs --save golden-ch2` по
маршруту, а пометки «цель / ставка» — по `story:cold-read`. **Когда не работает:** правка реплики внутри
готовой сцены — эталон не нужен.

### narrative-testing:GREEN-02 · narrative-testing:RED-20 · Цель и ставка до первой паузы

Зелёный: цель игрока понятна из чужих сообщений до первой паузы от часа — вернётся только тот, кто знает,
зачем. Красный RED-20: ставка (что будет, если ничего не делать) не прозвучала до первой большой паузы на
основном маршруте. Замер — C-24 у `story-opening` (`C-24.share`: доля маршрутов без ставки в стволе);
холодный читатель — вопрос 4 режима `opening` на точке перед первой паузой. Расхождение «замер видит ставку,
читатель — нет» значит, что ставка есть словами, но не читается: это «непонятно», чинит `story-opening`.

### Баг → маршрут → правка → тот же маршрут

Правило `narrative-testing:P-16` (владелец — `story-fix`, `safety.md`): каждый найденный баг сначала воспроизводится маршрутом, потом чинится, и маршрут остаётся тестом.

| шаг | команда |
|---|---|
| журнал тестера → маршрут | `node ${CLAUDE_SKILL_DIR}/scripts/route-replay.mjs --story <id> --save <имя> --from-save <журнал.json> --note "что ловит"` |
| посмотреть, что видел тестер | `node ${CLAUDE_SKILL_DIR}/scripts/transcript.mjs --story <набор.json> --from-save <журнал.json> --partial` |
| после правки | `node ${CLAUDE_SKILL_DIR}/scripts/route-replay.mjs --story <id>` — все маршруты; «оборвался», «застрял», «финал» |

`P-16` у `story-fix` (`safety.md`): правка не закрыта, пока маршруты зелёные или изменение финала записано.
