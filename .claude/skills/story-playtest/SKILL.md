# story-playtest — тест игроками: симулированный сейчас, живой потом

Бот проверяет, что история не сломана; тест игроками — хороша ли она: понятно ли, где скучно, не верится ли,
читаются ли оба режима. **Симулированный тест** (основной сейчас: живых тестов в этом проходе нет, решение автора)
— панель холодных читателей пяти профилей поверх персон бота, в обоих режимах. **Живой** (позже, у автора) —
набор `.json` с `beta_stop`, бриф, анкета, сводка отзывов по узлам. Сводка у обоих одна; у симуляции — пометка
«симуляция». Числа — только из команд, пороги — ключами `docs/playbook/thresholds.json`. Текст не правит:
находки уходят владельцам, правку применяет `story-fix` после одобрения. Холодный читатель — только Opus (A-07).

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`. Длинный
вывод — `--summary` или `--json`. Упала команда — «нет данных: <команда>».

## Границы

- **Вход:** история `src/stories/<id>/` или набор `.json`; симптом автора («поймут ли начало», «подготовь сборку
  для тестеров», «тестеры ответили»); вызов `story-review` или `story-opening` за холодным читателем.
- **Выход:** план и ответы панели, набор для тестеров, сводка «узел · тип · сколько человек · сходится с
  замером», находки строкой формата, маршруты регрессии, отчёт для `story-desk`, «объясни».
- **Не здесь:** что должно прозвучать в начале и как чинить начало — `story-opening` (R-24 — его); темп —
  `story-pace`; крючки и возвращение — `story-pauses`; режимы и напоминания — `story-time`; голоса — `story-voice`;
  ревью целиком и спор «человек против замера» (Б-3) — `story-review/conflicts.md`; правка — `story-fix`; запись
  в состояние — `story-desk`; вторая волна перед выпуском как гейт — `story-release`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг раньше
   `chapters:1-2` (нет глав) — тест только по скелету через `story-review --plan`; скажи об этом.
2. **Какой тест.** Симптом → точка, профили, команда: [references/decisions-playtest.md](references/decisions-playtest.md).
   Живых нет — симуляция; люди есть — набор им, панель до и после.
3. **Сначала поломки.** `npm run -s story:lint -- --story <id> --summary` — читатели не тратятся на то, что ловит
   команда (`narrative-testing:P-02`). Набор с `beta_stop` — тот же вызов с `--partial`.
4. **Панель.** План: `node ${CLAUDE_SKILL_DIR}/scripts/panel.mjs --story <id> --at opening`, затем тот же вызов с
   `--run`; потом `--at ch1`; середина — `--slices`. Для `distracted` нужна точка после долгой паузы:
   `npm run -s story:sessions -- --story <id>` → `--at <узел>`. Пропуски плана («нет #remind», «нет паузы») —
   тоже находки. Профили и протокол — [references/personas.md](references/personas.md), [references/cold-reader.md](references/cold-reader.md).
5. **Живой тест (когда есть люди).** `node ${CLAUDE_SKILL_DIR}/scripts/playtest-kit.mjs --story <id> --chapters N
   --ask "…" --known "…"` — вопросы и известное словами игрока; записки и анкета —
   [references/brief.md](references/brief.md), [references/survey.md](references/survey.md), волны — [references/waves.md](references/waves.md).
6. **Разметка ответов.** Ответы читателей и людей → форма отзыва `- тип · «начало сообщения» · симптом`: только
   сказанное читателем, с его цитатой; рецепт — «предложение». Форма — [references/digest.md](references/digest.md).
7. **Сводка.** `node ${CLAUDE_SKILL_DIR}/scripts/digest.mjs --story <id> <папка отзывов>`. Баг тестера:
   `node ${CLAUDE_SKILL_DIR}/scripts/transcript.mjs --story <набор.json> --from-save <журнал.json> --partial`, затем
   `node ${CLAUDE_SKILL_DIR}/scripts/route-replay.mjs --story <id> --save <имя> --from-save <журнал.json>`.
8. **Сверка с ink — обязательно, до отчёта.** Каждую строку сводки открой в узле ink: что читатель видел —
   `npm run -s story:cold-read -- --story <id> --until <узел>` (без `--ask`); правило и проверка —
   `npm run -s story:rule C-NN`. Частые ложные: читатель «не понял» то, что задумано загадкой; слабое место при
   «дочитал бы» выдано за жалобу; цитата нашлась в другом узле (повтор реплики). Не подтвердилось — «ложное: почему».
9. **Б-2 и отчёт.** Тип → владелец (колонка «чей»), обязательные — правка или причина, «нужен третий» — в бриф
   следующей волны. Если показываешь пример правки репликой или ink — сначала `docs/style.md` (§1, §8). Потом
   отчёт и предложение записать в состояние через `story-desk`.

## Главные правила

- **`narrative-testing:P-02`** сначала поломки (`story:lint`), потом впечатление; не смешивать.
- **`narrative-testing:PAT-10`, SYS-5** пересказ и «почему», а не «понятно?»; точки — `#attn-check-cold`.
- **`narrative-testing:P-05`** симптом и место, а не рецепт тестера; рецепт — в `ideas.md`.
- **`narrative-testing:P-06`** одно место и тип у `lab.playtest.repeat_min` людей — чинить или объяснить письменно.
- **Симуляция ≠ люди.** Совпадение профилей — кандидат; в обязательный список — только с замером или человеком.
- **`narrative-testing:P-08`** начало каждой версии читает свежий: новый прогон панели, новый человек.
- **`narrative-testing:P-04`, `inkle-ingold:P-15`** отзыв с журналом выборов; баг — сначала маршрут (P-16).
- **A-04** оба режима наравне: каждый профиль и `opening`/`return`, и `click`. **A-03** — `unresponsive`.
- **A-07** читатель — только Opus; разброс — повтором и профилями, не второй моделью.

## Формат находки

```
P1 · непонятно · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем, приём F-NN владельца — в поле правки (нет приёма — «→ <скилл>»). Тип:
непонятно / скучно / не верю / нестыковка / баг. Источник: «человек» — живые, «модель» — панель (с пометкой
«симуляция»), «замер» — `story:lint`. **P1** — обязательная строка сводки или «непонятно» в начале у профилей и
замера сразу; **P2** — сигнал: один человек и замер; **P3** — кандидат симуляции. Отклонённая автором находка не
всплывает, пока не изменится узел. Просят JSON — поля `node`, `check`, `summary`, `fix`, `source`.

## Состояние

Скилл сам в состояние не пишет — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-playtest.md`: находки строками формата, сводка, сверка (ложные с
  причиной), пропуски плана; сырьё — в `docs/stories/<id>/playtests/` (`sim-<дата>/`, `wave-N/`, `routes/`);
- одну строку для `STATUS.md`: «тест <дата>: симуляция N читателей / людей M, P1 — K, главное — …, отчёт — …».

## Готово, когда

Панель прогнана в обоих режимах на нужных точках, изоляция у всех «ок»; каждая строка сводки сверена с ink и
правилом и разобрана (владелец, причина или «ложное»); у бага — маршрут; запись в состояние предложена.

## Объясни

По запросу «объясни»: **почему** (что почувствует игрок), **откуда** (`npm run -s story:rule <ID>`, `алиас:ID` из
