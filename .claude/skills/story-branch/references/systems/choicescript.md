# Система: машина выборов и архитектура ветвления Choice of Games

### choiceofgames-design:SYS-1 · Машина ChoiceScript: установить → проверить → кульминация

Выборы по функции, а не по сюжету. **Устанавливающий** (establishing): игрок говорит, кто он, — вход: сцена,
выход: первичные переменные (`bold`, `tact`). **Проверочный** (testing): сюжет спрашивает первичную
переменную — выход: изменение вторичных (цели, отношения, ресурсы). **Вторичный слой** копит итоги проверок.
**Кульминационный** (climax): игрок решает, какую цель добить, — выход: исход по каждой цели. **Фальшивый**
(fake / flavor) держит темп и роль. **Если пропустить шаг:** без установки проверки становятся лотереей; без
проверок первичные переменные мертвы; без кульминации финал решает скрытая проверка, и игрок не видит, что
выбирал. **Ошибки понимания:** «проверка повышает проверенное» — наоборот, исход двигает другую переменную
(иначе ловушка четырёх подходов, `choiceofgames-design:P-18`); «скрытая проверка может решить за игрока» —
действия определяет выбор, проверки — только реакции; «провал = тупик» — провал тоже двигает сюжет (R-32).
**Короткая форма:** на 5 минут машина сжимается до цепочки одна установка → одна проверка → одна кульминация.
Для меню: назови функцию нового хода — установка, проверка или кульминация — и что он пишет.

### choiceofgames-design:SYS-5 · Архитектура ветвления: виньетки → стопка кустов → рука и пальцы

Эволюция внутри студии. 1) Ранние игры — независимые виньетки: общий код толкает выборы к косметике, тяжёлое
ветвление даёт мёртвый текст. 2) Решение — стопка кустов: короткие ветки внутри сцены, отложенные последствия
в переменных. 3) В конце — рука и пальцы: длинные параллельные ветки только у финала. **Мера** — доля слов
одного прохождения от всех слов; у нас — коридор `story.branch.seen_share.min`…`story.branch.seen_share.max` (R-37,
`branch-budget.mjs`). **Если пропустить:** без кустов — экспонента или «рельсы»; без пальцев финал — одна
строка-эпилог; без меры автор не знает, в какую сторону ошибся. **Ошибка понимания:** «почти линейная карта —
плохо». Нет: почти линейная рука — норма; плохо, когда доля текста выше коридора или ветки сходятся без следа.

### choiceofgames-design:SYS-4 · Рубрика конкурса — проверка меню

Жюри конкурса Choice of Games оценивает по девяти критериям с опубликованными весами; ноль в любом снимает
игру с конкурса. Для ветвления важны три: статы применяются последовательно, по одним правилам всю игру;
баланс выборов — ни один вариант и путь не лучше остальных; у каждого персонажа свои мотивы. Шаг для скилла:
прогнать меню по трём критериям — нет ли варианта, который «правильный»; не требует ли он внезапно стата,
которого игрок не копил; не делает ли он персонажа функцией. Подробно о цене — [../costs.md](../costs.md).
