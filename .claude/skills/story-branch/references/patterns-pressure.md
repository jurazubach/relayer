# Давление и накопление: по очкам, колея, лестница, сделка, петля

Второй файл локальных структур (первый — [patterns-branch.md](patterns-branch.md)). Здесь формы, где решение
складывается из нескольких тактов или копится: они дают ощущение «я сам к этому пришёл» без дорогих
веток. Все дешёвые по тексту, но каждая требует переменной, которую потом прочтут. Под телефон — не больше
двух тактов подряд и короткие паузы между ними (`#attn-cut`). Реплики и кнопки — по `docs/style.md`.

### emshort-structures:P-05 · Серию мелких выборов на одну тему решай по большинству

Серию мелких выборов на одну тему решай по большинству. Вместо одного большого «работа или любовь» дай несколько маленьких бытовых решений, каждое прибавляет очко
одной из сторон; исход выбирает перевес. Игрок не видит, что голосует, и выбирает честно, по ощущению — итог
воспринимается как следствие поведения. В мессенджере голос — сам выбор, в какой чат ответить. **Когда не работает:**
 нужно одно ясное решение с понятной ценой; и без переменных структура не работает вовсе.
Проверка: число голосующих кнопок нечётное или ничья обработана явно. `basis: secondary`.

#### emshort-structures:P-05#нюанс · Ничья и монтаж, который лишний

Нюанс: голоса не должны уходить в один чат и быть невидимыми по ходу — на каждый голос нужна реплика-реакция.
При чётном числе голосов возможна ничья — обработай её. Если все голоса за одну сторону с первого хода,
монтаж лишний: игрок решил сразу, дай ему одну кнопку. **Масштаб:** 5 сообщений — три голоса; 50 — пять
голосов, по реплике-реакции на каждый.

### emshort-structures:PAT-03 · Выбор по очкам

Монтаж мелких решений на одну ось (работа ↔ близкий человек, правда ↔ безопасность), исход — по перевесу
очков, число выборов нечётное. Голосование — тем, в какой чат ответить. **Когда не работает:** нужно одно
ясное решение (тогда прямая развилка с ценой). `basis: secondary`.

```ink
VAR work = 0
VAR home = 0
-> evening
=== evening ===
сегодня спектакль у дочки, в семь #from:zoya
отчёт по рейсу к утру #from:dispatch
* [Зое: буду]
    ~ home += 1
* [Диспетчеру: сделаю]
    ~ work += 1
- в восемь совещание, приходи #from:dispatch
* [Диспетчеру: приду]
    ~ work += 1
* [Зое: заберу вас после]
    ~ home += 1
- последний вопрос: подменишь в субботу? #from:dispatch
* [Подменю]
    ~ work += 1
* [Суббота — семейная]
    ~ home += 1
- {work > home: Зоя не в сети #sys|Зоя прислала фото из зала #sys}
-> END
```

### emshort-structures:PAT-02 · Выбор с переключением колеи

Одно трудное решение, где герой должен колебаться и у каждой стороны свои минусы: выбор стороны → минус
текущей стороны → «переключиться / остаться» → ещё минус → «переключиться / решено» → реакция по `flips`.
Цена — каждый такт пишется в двух версиях (по стороне), кнопки общие. Ловушки: реплика такта не зависит от
стороны (переключение бессмысленно); больше трёх тактов утомляет. **Когда не работает:** решение очевидно,
или минусы одной стороны нечем показать. `basis: secondary`.

```ink
VAR side = "brother"
VAR flips = 0
-> choose
=== choose ===
кого выручать первым: брата или напарника? #from:savva
* [Брата]
    ~ side = "brother"
* [Напарника]
    ~ side = "partner"
- {side == "brother": напарник один на барже без связи #from:savva|брат ждёт у моста, и у него сел телефон #from:savva}
* [Переключиться]
    ~ flips += 1
    {side == "brother": -> to_partner|-> to_brother}
* [Остаюсь]
    -> done
=== to_partner ===
~ side = "partner"
-> done
=== to_brother ===
~ side = "brother"
-> done
=== done ===
{flips > 0: ты колебался, я понял #from:savva|ты решил сразу #from:savva}
-> END
```

### failbetter-qbn:PAT-03 · Лестница: копить или действовать сейчас

Игрок готовит удар (разоблачение, разговор с полицией) и сам решает, когда хватит: подготовка +1 стоит
времени, на каждой ступени — «действовать сейчас» (слабый исход) или «готовиться дальше»; на верхней
ступени открывается сильный исход (Midnight Staircase). Цена — 2–4 короткие ветки ожидания. **Когда не работает:**
 если у раннего варианта нет внятного минуса — это не выбор; и подготовка без риска — игрок
всегда копит до максимума. `basis: secondary`.

```ink
VAR prep = 0
-> stair
=== stair ===
{prep == 0: записей с причала у меня одна. идти к капитану сейчас?|записей {prep + 1}. а лодка с грузом уже отходит}
* [Иди сейчас]
    {prep >= 2: -> strong|-> weak}
* {prep < 2} [Собери ещё]
    ~ prep += 1
    -> stair
=== weak ===
капитан посмеялся. одна запись — не улика #from:zoya
-> END
=== strong ===
три записи. капитан побледнел #from:zoya
-> END
```

#### failbetter-qbn:PAT-03#нюанс · Цена ступени — то, что ухудшается

Нюанс: в оригинале цена ступени — время. В нашем режиме «по клику» ожидания нет совсем, а в истории без
длинных пауз ожидание не стоит ничего — игрок всегда копит до максимума. Поэтому цена ступени — событие,
которое ухудшается, пока копишь: свидетель уезжает, запись стирается. Это работает в обоих режимах (A-04).

### failbetter-qbn:PAT-07 · Сделка с ценой и сделка на двоих

Игрок просит контакт о помощи. Простая сделка: польза за цену (игрок получает факт, контакт теряет
безопасность). Социальная — на двоих: выигрывают или теряют оба, отказ ничего не меняет (Faust, Faust's
Tea Party). Цена в тексте — одна переменная цены на контакт и одна реплика в будущей главе, где цена
сработала. **Когда не работает:** если цена нигде не читается — игрок узнаёт, что риск был фиктивным.
`basis: secondary`.

```ink
VAR keeper_risk = false
-> ask
=== ask ===
* [Покажешь журнал маяка?]
    ~ keeper_risk = true
    покажу. но если узнают, меня уволят #from:keeper
* [Ладно, сам разберусь]
    как знаешь #from:keeper
- -> later
=== later ===
{keeper_risk: меня вызвали к начальству. кто-то видел журнал #from:keeper}
-> END
```

### R-38 · Петля на `+` с выходом по условию

Петлю, которая возвращается в свой узел, строй на вариантах `+` с выходом по условию или счётчику. До
порога — не больше трёх кругов, на втором заходе — новая реплика или кнопка. Строку, которую игрок может
увидеть дважды, пиши через `{ stopping: … }` или с условием на счётчик посещений. Петля из одних `*`
кончается тупиком, дословный повтор выдаёт механику. Опора: `ashwell-standard-patterns:P-12`,
`inkle-ingold:P-11`, `emshort-structures:P-10`. `basis: secondary`.

```ink
VAR asked = 0
-> hub
=== hub ===
{stopping: что спросить у смотрителя?|ещё вопрос?|последний, он торопится}
+ [Кто был на маяке ночью?]
    ~ asked += 1
    никого. только я #from:keeper
    -> hub
+ [Чей это фонарь?]
    ~ asked += 1
    нашёл на камнях #from:keeper
    -> hub
+ {asked >= 2} [Хватит, спасибо]
    -> END
```

### ashwell-standard-patterns:P-12#нюанс · Больше двух-трёх заходов — застревание

Нюанс к «оправдывай повтор фикцией»: в реальном времени каждый проход петли стоит часов. Больше двух-трёх
заходов в одну ступицу за главу игрок воспримет как застревание игры, даже если фикция его оправдывает
(вечерняя проверка, утренний отчёт). Это наша оценка. Ступицу без выхода и с повтором меряет `story:lint`
C-19 (у `story-choices`). `basis: our_estimate`.

### inkle-ingold:P-11#нюанс · Строку видно один раз — но вторую лучше сменить

Нюанс к «повторяющийся текст варьируй последовательностями и циклами»: если строку видно один раз, вариация
не нужна. Если реальная пауза между повторами больше суток, игрок может и не заметить повтор, но вторую
фразу всё равно лучше сменить. **Масштаб:** 5 сообщений — не нужно; 50 — на все напоминания и входы в
ступицы. `basis: secondary`.

### emshort-structures:P-10#нюанс · Вариант открылся — намекни, откуда

Нюанс к «решай, что показать дальше, по состоянию, а не по стрелке графа»: ступица из меньше чем трёх
вариантов — пресная. Если вариант открылся по условию, а игрок не знает почему, дай намёк, откуда он взялся
(«раз ты нашёл ключ…»). **Масштаб:** 5 — не нужно; 50 — ступица на 3–4 варианта, 1–2 из них по условию.
`basis: secondary`.
