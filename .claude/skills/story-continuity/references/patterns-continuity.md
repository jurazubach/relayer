# Приёмы связности на ink

Готовые формы для узлов, где пути сходятся, для знаний и для сведений между чатами. Каждый пример
компилируется (теги только `ready` из `docs/capabilities.json`), имена выдуманы. Перед тем как вставлять
реплику в историю, сверь её с `docs/style.md` (ST-03 — без пересказа, ST-05 — время символ в символ,
ST-10 — одно имя, ST-15 — герой знает только написанное ему). Числа — ключами `thresholds.json`.

## P1 · Цепочка знаний

Факт тянет за собой предыдущие: номер не узнать, не увидев машину (`inkle-ingold:PAT-04`, разбор — в
[knowledge-flow.md](knowledge-flow.md)). Кнопка-обвинение — по `knows`.

```ink
# contact: tamara, Тамара, teal
LIST Lead = saw_van, plate_known, owner_known
VAR know = ()
-> yard
=== function learn(x)
~ know += LIST_RANGE(LIST_ALL(Lead), LIST_MIN(LIST_ALL(Lead)), x)
=== function knows(x)
~ return know ? x
=== function between(x, y)
~ return know ? x && not (know ? y)
=== yard ===
у ворот снова фургон. номер вижу #from:tamara
~ learn(plate_known)
{ between(plate_known, owner_known):
    чей он — пока не знаю #from:tamara #delay:20s
}
* {knows(plate_known)} [Пробей номер #to:tamara]
    ~ learn(owner_known)
    пробила. фургон записан на прачечную #from:tamara #delay:2m
* [Не трогай его #to:tamara #silent]
    ладно. номер я записала #from:tamara #delay:5m
- -> END
```

- **Когда не работает.** Факты узнаются в любом порядке — нужен LIST без `LIST_RANGE`; фактов два-три —
  хватит флагов.
- **Масштаб.** 5 сообщений — не нужен. 50 — один LIST на расследование.
- basis: checked (ink-документация; упрощённая запись — наша).

## P2 · Защитный вход: узкое выше, `else` в конце

`inkle-ingold:PAT-03`, R-35. Персонаж помнит, был ли разговор и что игрок видел.

```ink
# contact: gleb, Глеб, amber
VAR saw_list = false
VAR wrote_gleb = false
-> gate
=== gate ===
{
- saw_list && wrote_gleb:
    ты и список видел, и мне уже писал. тогда без вступлений #from:gleb
- wrote_gleb:
    это снова Глеб, сторож #from:gleb
- else:
    это Глеб, сторож склада. мы не знакомы #from:gleb
}
* [Что случилось? #to:gleb]
    ночью кто-то открыл третий бокс #from:gleb #delay:30s
- -> END
```

- **Когда не работает.** В узел ведёт один путь. Веток больше `C-51.cascade_branches` — дели сцену.
- **Масштаб.** 5 сообщений — одна строка `{wrote_gleb: снова я|это Глеб}`. 50 — блок на 2–3 состояния.
- basis: secondary.

## P3 · Слияние с повторным введением факта

`procedural-storytelling:PAT-07`. Кто слышал имя — получает подтверждение, кто нет — короткое введение,
а не пересказ ветки.

```ink
# contact: polina, Полина, purple
VAR heard_name = false
-> start
=== start ===
откуда начнём? #from:polina
* [С соседей #to:polina]
    соседка говорит, его звали Ефим #from:polina #delay:1m
    ~ heard_name = true
* [Сразу с подвала #to:polina]
    иду вниз #from:polina #delay:1m
- -> cellar
=== cellar ===
{heard_name:
    да, Ефим. на двери его фамилия #from:polina #delay:30s
- else:
    на двери фамилия. жильца звали Ефим, ты о нём не слышал #from:polina #delay:30s
}
-> END
```

- **Когда не работает.** Факт короткий и нейтральный — повтор не раздражает, условие не нужно.
- **Масштаб.** 5 сообщений — одна условная строка. 50 — по строке на каждый факт из веток; если их много,
  сократи факты.
- basis: secondary.

## P4 · Факт из одного чата — кнопкой в другой, и эхо назад

R-55, `messenger-genre:PAT-05` (разбор — [cross-chat.md](cross-chat.md)). Получатель реагирует, первый
чат узнаёт об этом.

```ink
# contact: rustam, Рустам, orange
# contact: tamara, Тамара, teal
VAR knows_van = false
VAR told_rustam = false
-> chats
=== chats ===
в 23:10 у склада стоял фургон Рустама. мне прислали снимок #from:tamara
~ knows_van = true
* {knows_van} [Рустам, что твой фургон делал у склада в 23:10? #to:rustam]
    ~ told_rustam = true
    кто тебе это сказал #from:rustam #delay:2m
    Рустам не в сети #sys:rustam #delay:30s
    он мне пишет. что ты ему сказал?? #from:tamara #delay:5m
* [Подожди, не говори никому #to:tamara]
    поздно, я уже спросила его сама #from:tamara #delay:30s
- -> END
```

- **Когда не работает.** У игрока один собеседник или второй чат — фон без своего знания.
- **Масштаб.** 5 сообщений — не нужен. 50 — раз в главу.
- basis: secondary.

## P5 · Закрытый контакт молчит под условием

R-85: заблокировал или ушёл — дальше не пишет как ни в чём не бывало.

```ink
# contact: vadim, Вадим, lime
VAR vadim_blocked = false
-> talk
=== talk ===
ещё раз спросишь про склад — заблокирую #from:vadim
* [Спрошу. Где ты был ночью? #to:vadim]
    ~ vadim_blocked = true
    Вадим заблокировал вас #sys:vadim #delay:10s
* [Ладно, не буду #to:vadim]
    вот и не надо #from:vadim #delay:30s
- -> later
=== later ===
{not vadim_blocked:
    слушай. про ночь. я был у брата #from:vadim #delay:3h
- else:
    сообщение не доставлено #sys:vadim
}
-> END
```

- **Когда не работает.** Закрытие чата — часть сюжета, и контакт возвращается событием (новый номер,
  `#rename`): тогда это новый вход, ему нужен свой защитный вход (P2).
- **Масштаб.** На любом объёме: одна условная развилка на каждую позднюю реплику закрытого контакта.
- basis: secondary.

## Каскад: частное перед общим

### procedural-storytelling:P-12 · Ставь частный случай перед общим и всегда оставляй общий запасной

В одной системе реплик для известного шутера выбирается самое специфичное подходящее правило, а менее
специфичные служат запасными: автор пишет общую реплику и сколько угодно частных поверх неё, не покрывая
все сочетания. Ink проверяет блок `{ - … }` сверху вниз и берёт первую подходящую ветку, поэтому узкие
условия ставят выше, а `else` — всегда. Пример — P2 выше.
- **Когда не работает.** Как двигатель сюжета: каскад — слой реакций, а не выбор, какая сцена будет.
- **Масштаб.** 5 сообщений — два уровня; 50 — до `C-51.cascade_branches`, глубже не тестируется.
- basis: secondary · опора: `procedural-storytelling:P-12`.

#### procedural-storytelling:P-12#нюанс · Каскад не двигает сюжет

Каскад частного перед общим — не двигатель: если им выбирать сцены, дуга истории теряется, потому что
следующую сцену решает случайное сочетание флагов. Держи его слоем реакций поверх авторского пути. На 5
сообщениях хватает двух уровней, на 50 — трёх; глубже каскад не тестируется ни ботом, ни глазами.

### procedural-storytelling:GREEN-03 · Условные блоки идут от узкого к общему и заканчиваются else

Зелёный признак: у блока `{ - … }` есть `else`, а бот за свои прогоны выбирал каждую ветку. Реплика
попадает в ситуацию, персонаж не молчит по ошибке. Проверка веток, которые не выпадали ни разу, —
C-15 (`C-15.never`), блок без `else` — C-15 (`C-15.no_else`), оба у `story-choices`.
- basis: checked · опора: `procedural-storytelling:GREEN-03`.

### emshort-structures:GREEN-08 · Блок реплик от узкого условия к широкому, в конце else

Тот же зелёный признак у другого автора: условные блоки реплик идут от узкого условия к широкому и
заканчиваются `else`; у верхних веток переменных в условии не меньше, чем у нижних. Так система реагирует
на мелочи, а общая реплика страхует от пустоты. Счёт — C-15 у `story-choices`.
- basis: checked · опора: `emshort-structures:GREEN-08`.

### procedural-storytelling:RED-04 · Многоветочный условный блок без else

Красный флаг: при непредусмотренном сочетании ни одна ветка не подходит, персонаж молчит, сцена рвётся.
Статически по ink — C-15 (`C-15.no_else`). Правка — общий запасной вариант последней веткой.
- basis: checked · опора: `procedural-storytelling:RED-04`.

### procedural-storytelling:RED-05 · Широкое условие стоит выше узкого

Красный флаг: `a` выше `a && b` — узкая реплика недостижима, бот ни разу её не выполнил. Ловит C-15
(`C-15.never`) по прогонам; статически видно, что условие ниже — надмножество условия выше. Правка —
переставить, узкое выше.
- basis: checked · опора: `procedural-storytelling:RED-05`.

### emshort-structures:RED-10 · Условный блок без else или с широкой веткой выше узкой

Тот же дефект у другого автора, обе формы сразу: пустая реплика при непредусмотренном состоянии или
частная, которая никогда не выпадает. Бот видит ветку, не выполненную ни разу за прогоны (C-15
`C-15.never`). Правка — переставить ветки и добавить `else`.
- basis: checked · опора: `emshort-structures:RED-10`.
