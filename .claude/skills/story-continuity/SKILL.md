# story-continuity — кто что знает на каждом пути

Переписка — текст без картинки: игрок знает только то, что видел на своём пути, персонаж — только то, что
ему написали или переслали. Скилл находит, где это нарушено (C-51, `knowledge.mjs`), где пути сходятся без
защиты (`merges.mjs`, F-13), где время и факты расходятся (`facts.mjs`, `timeline.mjs`, `facts.md`) и где
чаты не обмениваются сведениями (R-55). Числа — только из команд, пороги — ключами `thresholds.json`.
Текст не правит сам: предлагает варианты, применяет `story-fix` после одобрения.

**Команды — по одной на вызов, ровно как написаны:** без `cd`, пайпов, `;`, `&&`, `>`, `$?`, `| head`.
Длинный вывод — `--summary` или `--json`. Упала команда — «нет данных: <команда>», не угадывай.

## Границы

- **Вход:** история `src/stories/<id>/` (или папка / `.json`), симптом автора или вызов `story-review`.
- **Выход:** находки строкой формата, правка с приёмом и ink до/после, черновик `facts.md`, отчёт для
  `story-desk`, «объясни».
- **Не здесь:** кнопки, эхо, хабы, ветка каскада, которая не выпала (C-15) — `story-choices`; кто есть кто,
  слишком много чатов, шум и адресат (C-50) — `story-cast`; голос, упрёк без основания (C-47), копии текста
  (C-46) — `story-voice`; улики и раскрытия — `story-mystery`; время мира против часов игрока, режимы —
  `story-time`; напоминание после паузы — `story-pauses`; числа карточки (C-49 а–е) — `story-release`;
  якоря фактов в промпте писателя — `chapter-write`; записать в состояние, завести `facts.md` — `story-desk`.

## Алгоритм

1. **Состояние.** Прочитай `docs/stories/<id>/STATUS.md`. Не знаешь, о какой истории речь, — спроси. Шаг не
   тот (идея, ядро без скелета) — скажи. Нет `STATUS.md` (история вне цикла, мутант) — работай и отметь это.
2. **Замер знания.** `npm run -s story:lint -- --story <id> --only C-51,C-15,C-46,C-49` (папка вне каталога —
   путь вместо id), затем `node ${CLAUDE_SKILL_DIR}/scripts/knowledge.mjs --story <id>`: находки C-51,
   «знает лишнее» (R-85), переносы между чатами по главам (R-55).
3. **Слияния.** `node ${CLAUDE_SKILL_DIR}/scripts/merges.mjs --story <id>` — узлы, где узел опирается на то,
   что есть лишь на части входов, широкий каскад, повторы на пути. Подробно по узлу — `--node <узел>`.
4. **Факты и время.** `node ${CLAUDE_SKILL_DIR}/scripts/facts.mjs --story <id>` — кандидаты расхождения и
   сверка с `facts.md`; `node ${CLAUDE_SKILL_DIR}/scripts/timeline.mjs --story <id>` — каждое `ЧЧ:ММ` и часы
   мира на пути. Нет `facts.md` у истории в цикле — находка P3 с черновиком (`facts.mjs --story <id> --draft`);
   у истории вне цикла (нет `STATUS.md`, мутант) — строка отчёта, а не находка.
5. **Сверка с ink — обязательно, до отчёта.** Каждую находку замера открой в узле ink и сверь с правилом:
   `npm run -s story:rule R-NN` (или `C-NN`). Строка сама вводит факт? Контакт — свидетель (в `facts.md` «кто
   знает»)? Время — другого события того же предмета? Ложь помечена `// намеренно: C-49 ложь`? Не
   подтвердилась — «ложное: почему». Развилки — [references/decisions-continuity.md](references/decisions-continuity.md).
6. **Суждение модели** — только где замер молчит: персонаж реагирует на то, о чём узнать не мог, закрытый
   контакт пишет дальше, перенос без реакции получателя. Поле проверки — `—` (не C-51: её замер молчал),
   «модель» и уверенность; P3, а P2 — только с цитатой двух строк, которые противоречат друг другу на одном пути.
7. **Правка.** Прочитай `docs/style.md` (ST-03, ST-05, ST-10, ST-15) прямо перед тем, как писать реплику,
   кнопку или пример ink. Приём — [F-13](references/fixes/F-13-merge-guard.md) или форма из
   [references/patterns-continuity.md](references/patterns-continuity.md). Два-три варианта, до/после на ink,
   теги только `ready`. Черновик `facts.md` — текстом в отчёт, не в файл.
8. **Отчёт и состояние.** Сначала находки строками формата, потом разговор и правки. В конце предложи
   записать находки (и `facts.md`, если нужен) через `story-desk`; применяется только одобренное.

## Главные правила

- **R-85** персонаж знает только написанное ему или пересланное; упрёк — под условием; закрытый контакт молчит.
- **C-51** кнопка и реплика не опираются на факт, которого на части путей не было (`C-51.unknown_fact`);
  контакт не знакомится второй раз в общем узле (`C-51.met_twice`).
- **R-35** вход в узел с несколькими путями — каскад от узкого к общему, `else` последним, веток не больше
  `C-51.cascade_branches`; пропущенный факт — одной фразой (F-13).
- **R-55** раз в главу — кнопка `#to` в один чат с фактом из другого, реакция получателя и эхо назад.
- **R-91** правда — хронология и реестр в `docs/stories/<id>/facts.md`; время в репликах — оттуда, ложь
  помечена; часы мира не расходятся с паузами больше `C-51.clock_drift_min`.
- **`inkle-ingold:SYS-2`** на входе две проверки: нужное и уже лишнее.

## Формат находки

```
P1 · нестыковка · <узел> · симптом · правка (F-NN) · [C-NN · замер|модель|человек · уверенность]
```

Строго этот порядок: узел третьим полем, приём F-NN — в поле правки (нет приёма — «условие» / «реестр» /
«повторное введение»). Поле C-NN — по виду: знание игрока — C-51, расхождение факта или времени — C-49
(пункт г, R-91), повтор на пути — C-46, ветка каскада — C-15, «знает лишнее» и перенос — R-85 / R-55. Тип: непонятно / скучно / не верю / нестыковка / баг. **P1** — факт, на котором
держится вывод или финал, а часть игроков его не видела; одно событие с разным временем. **P2** — заметно в
главе: второе знакомство, «знает лишнее». **P3** — шлифовка: перенос без эха, нет `facts.md` в истории без
тайны. Отклонённая находка не всплывает, пока не изменится узел. Просят JSON — поля `node`, `check`, `summary`, `fix`.

## Состояние

`story-continuity` в состояние не пишет сам — отдаёт `story-desk` (после одобрения автора, в конвейере — королевы):
- отчёт `docs/stories/<id>/reviews/<дата>-story-continuity.md`: находки строками формата, сверка (ложные с
  причиной), правки, черновик `facts.md`, если файла нет;
- одну строку для `STATUS.md`: «связность <дата>: P1 — N, P2 — M, facts.md — есть/нет, отчёт — reviews/…».

## Готово, когда

Все находки замера сверены с ink и правилом и разобраны: правка с приёмом, `// намеренно:` или «ложное» с
причиной; у правки — до/после на ink и перезапуск замера; `facts.md` есть или предложен; запись в состояние
предложена. **Объясни:** почему (что почувствует игрок), откуда (`npm run -s story:rule R-NN`, `алиас:ID` из
[references/sources.md](references/sources.md), класс урока), как сделать самому — [references/explain.md](references/explain.md).
