# Приёмы времени на ink

Каждый пример компилируется (`skill-check.mjs`), теги — только `ready` из `docs/capabilities.json`. Имена и
места выдуманы. Примеры — фрагменты: `story:lint` на них даёт подсказки о начале истории («пауза в первые
минуты», «первая длинная пауза до выбора») — это свойство фрагмента, а не приёма. Перед тем как переносить приём в главу, прочитай `docs/style.md` §8 и образцы §12.5: здесь —
устройство, там — как звучит реплика.

## R-63 · Причина без срока, пауза длиной в дело, результат дела

Персонаж называет дело, «не в сети», пауза длиной в это дело; первая строка после — результат, понятный без
прошлых реплик. Срока в реплике нет: по клику следующее сообщение придёт сразу, и «через час напишу» стало бы
ложью. Тот же приём у источников — `narrative-postmortems:PAT-10` (дело героя) и `chat-fiction-apps:PAT-03`
(в силе только причина).

- **Когда не работает.** Пауза-угроза: персонаж замолкает после опасности, и причина убила бы тревогу —
  тогда перед паузой стоит угроза, а тишину отмечает «Прочитано» или другой контакт.
- **Масштаб.** 5 сообщений: пауз нет. 50: каждая пауза от `story.pause.notice_min` — своё дело, причины не
  повторяются между главами.
- basis: checked (решение автора A-01) · проверка: C-27.

```ink
# contact: zoya, Зоя, teal
-> shed
=== shed ===
в сарае нет света. иду к щитку через двор #from:zoya
он за теплицей, в темноте
Зоя не в сети #sys:zoya
#delay:20m
щиток открыт. кто-то вынул все пробки #from:zoya
* [Пробки рядом? #to:zoya]
    нет. и следов нет #from:zoya
* [Уходи оттуда #to:zoya]
    уже ухожу #from:zoya
- -> END
```

## R-120 · Два напоминания, потом «не ответил» — это `#silent`

Скрытые варианты `#remind` той же развилки, сборка `- (ask)` прямо перед кнопками. Второе напоминание —
с деталью. Своей ветки «не ответил» нет, поэтому после второго история идёт веткой `#silent`: отсутствие стоит
ровно столько, сколько осознанное молчание. Опора — `inkle-ingold:PAT-07`.

- **Когда не работает.** Кнопка без ждущего собеседника (выход из хаба) — напоминать некому, вариантов
  `#remind` не ставят. По клику напоминаний нет — кнопка ждёт.
- **Масштаб.** 5 сообщений: одно напоминание. 50: два, разные, интервал растёт.
- basis: checked (синтаксис E-02) · проверка: C-32 п. 6–7; где их не хватает — `guilt-scan.mjs --missing`.

```ink
# contact: zoya, Зоя, teal
-> gate
=== gate ===
калитка открыта, сторожа нет #from:zoya
заходить? #delay:5s
- (ask)
* [Заходи #to:zoya]
    захожу #from:zoya
    -> yard
* [Промолчать #to:zoya #silent]
    ладно. жду у калитки #from:zoya
    -> wait
* [#remind:40m] алё, ты тут? мне нужно «да» или «нет»
    -> ask
* [#remind:1h] фонарь у сторожки погас. решаю сама
    -> ask
=== yard ===
во дворе пусто #from:zoya
-> END
=== wait ===
стою. слышу шаги #from:zoya
-> END
```

**До и после** для «⚠ ждёт без напоминаний · dock» из `guilt-scan.mjs --missing`: `#silent` нет — нужен `#noanswer`.
```ink
-> dock
=== dock ===
грузить ящик? #from:ilya
* [Грузи] -> sail
* [Оставь] -> sail
=== sail ===
-> END
```
```ink
# contact: ilya, Илья, blue
-> dock
=== dock ===
грузить ящик? #from:ilya
- (ask)
* [Грузи] -> sail
* [Оставь] -> sail
* [#remind:30m] ящик тяжёлый, мне нужно «да» или «нет»
    -> ask
* [#remind:1h] катер уже гудит, ящик пока стоит у трапа
    -> ask
* [#noanswer]
    оставил на причале #from:ilya
    -> sail
=== sail ===
катер отходит #from:ilya
-> END
```

## attention-today:RED-07 · Своя ветка «не ответил» с переменной и поздним откликом без упрёка

Когда отсутствие надо запомнить отдельно от `#silent`, у развилки своя ветка `#noanswer`: она пишет
переменную и ведёт туда же, куда `#silent`, а позже персонаж вспоминает, что игрока не было, — без обвинения.
Так молчание не ведёт к худшему финалу (флаг источника) и «не ответил» не дороже `#silent` (C-32 п. 7, R-74).

- **Когда не работает.** Если `#silent` у развилки нет, ветка «не ответил» — нейтральный ход персонажа, а не
  копия чьей-то кнопки.
- **Масштаб.** 5 сообщений: своя ветка не нужна, хватит `#silent`. 50: переменная и отклик через главу.

```ink
# contact: savva, Савва, amber
VAR no_answer_boat = false
-> pier
=== pier ===
лодку отвязывать? #from:savva
- (ask)
* [Отвязывай #to:savva]
    -> sail
* [Промолчать #to:savva #silent]
    -> stay
* [#remind:30m] мне нужно твоё слово, вода прибывает
    -> ask
* [#noanswer]
    ~ no_answer_boat = true
    не дождался. оставил лодку как есть #from:savva
    -> stay
=== sail ===
отвязал #from:savva
-> later
=== stay ===
сижу на мостках #from:savva
-> later
=== later ===
{no_answer_boat: тебя тогда не было, я решил не трогать лодку. правильно, наверное #from:savva}
утром лодки у мостков нет #from:savva
-> END
```

## attention-today:PAT-05 · Честный дедлайн — срок события в мире

Срок — событие мира («паром отходит в шесть»), выбор решает, успеет ли персонаж, а не скорость ответа игрока.
Мир идёт дальше в любом случае; отказ стоит части улик, но не финала. В реплике нет «у тебя пять минут» —
у движка нет таймеров, такой срок ложный (R-114, C-37 б).

- **Когда не работает.** Если исход не зависит от выбора, дедлайн — ложная угроза: убрать его.
- **Масштаб.** Две ветки по 3–6 реплик и одна переменная.
- basis: our_estimate (приём разбора) · проверка: C-37.

```ink
# contact: ulya, Ульяна, purple
VAR missed_ferry = false
-> dock
=== dock ===
паром отходит в шесть. если капитан тот самый, он уплывёт с ним #from:ulya
* [Беги на причал #to:ulya]
    бегу #from:ulya
* [Не ходи, это опасно #to:ulya]
    ~ missed_ferry = true
    ладно. остаюсь #from:ulya
- Ульяна не в сети #sys:ulya
{missed_ferry: паром ушёл. на причале осталась только его кепка|успела. он на палубе, в кепке} #from:ulya #delay:30m
-> END
```

## R-121 · Сон и утро — время мира

От «сплю» до «доброе утро» проходит ночь мира — не меньше `story.sleep_morning.min_h`; по клику скачок от
`engine.click.time_jump_label` закроет метка «спустя N». Персонаж не угадывает, спит ли игрок. Первая строка
утром — событие, вежливость вторым пузырём. Опора — `messenger-genre:P-12` в части «в силе».

- **Когда не работает.** История на одну ночь без сна — «утра» нет, не упоминай его.
- **Масштаб.** 5 сообщений: ночи нет. 50: одна ночь на стыке глав (R-67).
- basis: checked (решение автора A-02) · проверка: C-32 п. 5, C-47.

```ink
# contact: zoya, Зоя, teal
-> night
=== night ===
глаза слипаются. сплю, дверь заперла #from:zoya
Зоя не в сети #sys:zoya
#delay:7h
дверь открыта настежь. а ключ у меня под подушкой #from:zoya
доброе, кстати
-> END
```

## R-122 · Скачок дальше паузы — свой `#sys`

Когда время мира прыгает дальше паузы (эпилог через месяц), его называет свой `#sys`, а пауза короткая.
Скачок, равный паузе, закрывает метка движка — свой `#sys` её не дублирует. Это и хвост после последней
кнопки в пределах `story.tail.max_delay_min` (R-110, C-42 у `story-endings`).

- **Когда не работает.** Внутри главы: там время мира равно паузе, метку ставит движок.
- **Масштаб.** Один раз за историю — в эпилоге.

```ink
# contact: savva, Савва, amber
-> epilogue
=== epilogue ===
Через месяц #sys:savva #delay:20s
лодку нашли у дальнего мыса. целую #from:savva
-> END
```

## chat-fiction-apps:PAT-05 · Ежедневный выпуск: глава — день, вопрос переходит через ночь

Ежедневный выпуск с напоминанием: конец главы — незакрытый вопрос и причина паузы; начало следующей — строка, которая возвращает этот вопрос, и
кнопка в первые минуты. Пауза стыка одна — на строке `#chapter`; заголовка игрок не видит (A-08), движок переносит паузу на первую реплику.

- **Когда не работает.** История в одну сессию: глав-дней нет.
- **Масштаб.** Одна строка-напоминание на главу. Крючок и первая реплика — у `story-pauses` (C-26, C-28, C-39).
- basis: secondary (Hooked, Dark Matter) · проверка: C-32 п. 4.

```ink
# contact: ulya, Ульяна, purple
-> d1
=== d1 ===
День 1 #sys:ulya #chapter
в шкафу у бабушки второй ключ. от чего — не знаю #from:ulya
устала, иду спать
Ульяна не в сети #sys:ulya
-> d2
=== d2 ===
#delay:8h
День 2 #sys:ulya #chapter
ключ подошёл к почтовому ящику соседей #from:ulya
* [Что внутри? #to:ulya]
    письма на её имя #from:ulya
* [Положи на место #to:ulya]
    поздно, открыла #from:ulya
- -> END
```

## serial-hooks:GREEN-08 · Игрок сам выбирает уйти

Перед самой длинной паузой главы — честная пара «ждать до утра» / «сейчас». Ветка «ждать» получает длинную
паузу, которую игрок выбрал сам; ветка «сейчас» — свою короткую паузу и своё открытие, а не тупик.

- **Когда не работает.** Если «сейчас» ведёт в тупик или к худшему финалу — это наказание за отказ ждать.
- **Масштаб.** Вторая ветка на 2–6 строк и одна переменная.
- basis: our_estimate (вывод разбора) · проверка: C-27 (причину выбрал игрок), C-32.

```ink
# contact: zoya, Зоя, teal
VAR waited = false
-> log
=== log ===
в журнале сторожа запись: калитку открывали в 01:40 #from:zoya
сторож будет утром
* [Ложись. Утром спросим #to:zoya]
    ~ waited = true
    ладно. но не усну #from:zoya
* [Сходи к сторожке сейчас #to:zoya]
    иду #from:zoya
- {waited:
    #delay:8h
    сторож говорит: открывал не он. и ключ у него один #from:zoya
- else:
    #delay:20m
    в сторожке пусто, чайник ещё тёплый #from:zoya
}
-> END
```

## messenger-genre:PAT-09 · Главы как встречи — без упрёка за непрожитое

Глава — встреча через большой срок, свой `#sys` называет скачок мира, первая реплика показывает перемену и
ссылается на прошлый выбор. Между главами персонаж не решает за игрока ничего, за что потом упрекнёт.

- **Когда не работает.** Триллер на одну ночь: разрыв убивает напряжение.
- **Масштаб.** 5 сообщений: одна встреча. 50: глава на встречу.
- basis: secondary (Emily is Away) · проверка: C-47 (упрёк без основания, `story-voice`).

```ink
# contact: ulya, Ульяна, purple
VAR stayed = false
-> y1
=== y1 ===
Лето #sys:ulya #chapter
ты правда уезжаешь в сентябре? #from:ulya
* [Да #to:ulya]
* [Ещё не решил #to:ulya]
    ~ stayed = true
- -> y2
=== y2 ===
Год спустя #sys:ulya #chapter #delay:1m
{stayed:ты так и остался. я рада, хоть и не скажу почему|как там новый город? мне до сих пор шлют твои письма} #from:ulya
-> END
```
