# scripts/lint — story:lint

Проверки сценария C-01…C-54 по `docs/playbook/checks.md`. Пороги, словари и их опора — только в
`docs/playbook/thresholds.json`: код проверки берёт значение по ключу, ключа нет — исключение.
Самопроверка — `npm run test:lint`.

```bash
npm run story:lint                                   # все истории src/stories, 400 прогонов бота (lint.runs.full)
npm run story:lint -- --story <id> --only C-20,C-35
npm run story:lint -- --changed --quick --summary    # для хука: изменённые истории, кратко
npm run story:lint -- --partial путь/к/beta.json     # часть глав с узлом beta_stop
npm run story:lint -- --plan --story <id>            # docs/stories/<id>/skeleton.ink
npm run story:lint -- --json --strict                # код 1, если есть ошибки
npm run story:lint -- --story <id> --transcript 3    # три прохождения бота в .md (C-52 п. 5)
```

Строка находки: `уровень · C-NN · узел · сообщение · порог (опора) · чинит <скилл>`. «Кто чинит» — владелец
проверки из `docs/playbook/owners.md` §3 (в `--json` — поле `owner`). `[модель]` у уровня — метрика-кандидат:
регулярка или профиль нашли место, а решает модель или ревьюер (голоса, смысл; в `--json` — `model: true`).
Похожих находок в одной главе печатается не больше `lint.examples`, остальные — в `--json`.
`--summary` — счётчики по проверкам и `lint.summary.top` находок на историю, не длиннее
`skill.hook.max_output_chars`.

| модуль | что делает |
|---|---|
| `lint.mjs` | командная строка |
| `core.mjs` | контекст истории, запуск проверок, подавление `// намеренно: C-NN причина`, владелец, вывод и `--summary` |
| `static.mjs` | граф узлов, финальные узлы и распределители, индекс переменных, классы кнопок, метки финалов |
| `journal.mjs` | журнал бота: строки, точки выбора, изменения переменных, посещения; время игрока — `scripts/lib/playtime.mjs`; персоны C-16 |
| `endings.mjs` | какой финал прошёл прогон: последняя метка `// финал:` на пути; без меток — ориентировочно по узлам |
| `text.mjs` | крючок перед паузой, корни слов, имена героев, форматы; срок возвращения и закрывающая реплика — из `scripts/lib/lexicon.mjs` |
| `transcript.mjs` | прохождение в `.md` |
| `thresholds.mjs` | прежний путь загрузчика: сам загрузчик и схема `thresholds.json` — `scripts/lib/thresholds.mjs` |
| `checks/C-NN.mjs` | одна проверка: `{ id, title, plan, partial, model?, deferred?, run(ctx, find) }` |

## Как добавить проверку

1. Порог — ключ `C-NN.<имя>` в `thresholds.json` со всеми полями (`value`, `unit`, `level`, `basis`,
   `sources`, `calibrated_on`, `history`). Общий для нескольких проверок — `<область>.<имя>` с полем `checks`.
   Опора — `source`, `our_estimate` или `author_decision` (решение автора, `superseded.md` A-NN).
2. Файл `checks/C-NN.mjs`: регистрировать не нужно. `find(ключ, { node, chapter, message, model? })` — уровень
   находки берётся из порога.
3. `plan: true` — проверка имеет смысл на скелете; `partial: false` — ей нужна вся история; `model: true` —
   все находки — кандидаты для модели.
4. Порог, которому нужна фича движка, — поле `deferred: "E-NN"` у ключа и `deferred: [ключи]` у проверки:
   `find` по такому ключу ничего не делает, а `--json` показывает его в `skipped`.
5. Пример с дефектом и без него — в `selftest.mjs` (первая волна) или `selftest-wave2.mjs`.

## Служебные контакты и финалы

- Служебный контакт — внешняя память игрока, а не персонаж: `dict.service_contacts` (`notes`) и герой с
  `service: true` в `meta.json`. Проверки контактов его не считают (`ctx.service`).
- Финал — последняя метка `// финал: <имя>` на пути. Прогон, дошедший до конца истории без метки, — находка
  C-40, даже если меток нет совсем; общий `END` после размеченных веток — норма.

## Подавление

`// намеренно: C-NN причина` над узлом гасит находки C-NN в этом узле и его stitch'ах; до первого узла —
находки C-NN по всей истории (без узла). Подавленное есть в `--json` (`suppressed`) с причиной. Метка без
ID, с неизвестным ID или без причины — находка C-53.
