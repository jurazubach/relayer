Интерактивные истории в форме мессенджера: сюжет на [ink](https://www.inklestudios.com/ink/)
приходит сообщениями в реальном времени, игрок отвечает кнопками и сам решает, кому написать.
Закрыл вкладку на час — по возвращении переписка догонится, будто сообщения шли, пока тебя не было.

Веб-прототип: без бэкенда, прогресс в `localStorage`, деплой на GitHub Pages.
Открываешь ссылку с телефона и играешь. iOS-приложение — потом, на тех же сценариях.

**▶ Играть:** <https://jurazubach.github.io/relayer/>

## Возможности

- **Время идёт по-настоящему.** Паузы сюжета — реальные минуты и часы, «печатает…» в живом темпе,
  время догоняется, пока игрока нет.
- **Несколько чатов сразу.** Контакты открываются по ходу сюжета, получают настоящие имена,
  уведомление из другого чата всплывает сверху (колокольчик в списке чатов его выключает);
  есть непрочитанные и «ждёт ответа».
- **Молчание у кнопки.** В реальном времени персонаж 1–2 раза напоминает о себе, потом история идёт
  дальше веткой «не ответил». По клику кнопка ждёт. К часам игрока история не привязана.
- **Ветвление на ink.** Переменные, условия, узлы, несколько финалов, главы. Варианты одной
  развилки могут уходить в разные чаты.
- **История одним файлом.** В репозитории история — папка: описание в `meta.json`, сценарий
  по главам в `.ink`. Наружу она собирается в один `.json`: его можно загрузить прямо в приложении,
  поправить и загрузить снова, или выгрузить встроенную историю.
- **Память места.** Перезагрузка возвращает на тот же экран и в тот же чат.
- **Инструменты автора.** Панель отладки, бот-тестировщик на 400 прохождений, промпт для генерации
  новых историй, который собирается из реестра возможностей движка.

## Быстрый старт

Нужен Node.js 22+.

```bash
git clone git@github.com:jurazubach/relayer.git
cd relayer
npm install
npm run dev                 # http://localhost:5173
npm run dev -- --host       # чтобы открыть с телефона по IP компьютера
```

Сразу попасть в нужное место без ожидания:
<http://localhost:5173/?story=the-number&fresh=1&fast=1>

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер на `:5173` |
| `npm run build` | `tsc -b && vite build` → `dist/`, затем `story:pack` → `dist/stories/<id>.story.json` |
| `SINGLE=1 npm run build` | всё в один `index.html` → `dist-single/` |
| `npm run preview` | посмотреть собранное |
| `npm run check:story` | бот прогоняет каждую историю 400 раз (если редкий узел не встретился — добирает до 2000): компиляция, тупики, недостижимые узлы, финалы, длительность |
| `npm run graph` | карта сюжета → `graph/index.html`: узлы по главам, реплики, куда ведёт каждый выбор (`-- --open` — сразу открыть) |
| `npm run story:pack` | папки историй → по одному `.json` в `dist/stories/` для загрузки и телефона (`-- --out <папка>`, `-- --flat` — главы склеить в одно поле `ink`) |
| `npm run story:pack -- --check` | разложить и собрать в памяти и сверить, что ничего не потерялось; проверить раскладку по главам |
| `npm run story:unpack` | история одним `.json` → папка `src/stories/<id>/` с главами (`-- путь.json`, `--keep` — не удалять исходник) |
| `npm run test:lib` | самопроверка `scripts/lib`: синтетические примеры ink, раскладка и сборка, три истории |
| `npm run test:e2e` | Playwright: сценарии использования в настоящем браузере |
| `npm run test:e2e:ui` | интерактивный режим Playwright |
| `npm run shots` | скриншоты всех экранов в `screenshots/<устройство>/` |
| `npm run prompt` | собрать промпт для генерации историй → `docs/PROMPT.md` (`-- --copy` — ещё и в буфер) |

Проверка перед коммитом:

```bash
npm run check:story && npm run test:lib && npm run story:pack -- --check && npm run build && npm run test:e2e && npm run prompt -- --quiet
```

## Параметры в адресе

Игра идёт настоящими минутами, поэтому для проверки руками, тестов и снимков есть флаги:

| Параметр | Что делает |
|---|---|
| `?story=<id>` | сразу открыть историю (по умолчанию — сразу играть) |
| `?screen=home` \| `story` \| `game` | какой экран показать |
| `?fresh=1` | стереть прогресс перед запуском |
| `?fast=1` | без пауз сюжета, набор текста ×4 |
| `?mode=click` \| `realtime` | режим новой игры, если она начинается не с экрана истории |

## Формат истории

Экраны устроены лесенкой, назад всегда на уровень выше:
**чат → список чатов → описание истории → главный**.

В репозитории история — папка `src/stories/<id>/`:

```
src/stories/demo/
├── meta.json     описание для экрана истории, герои, главы, обложка
├── story.ink     шапка (# title:, # contact:), VAR, начальный -> ch1 и INCLUDE глав
├── common.ink    функции и общие узлы до первой главы (если есть)
├── ch01.ink      глава 1: от узла с #chapter до следующей главы
└── ch02.ink
```

`meta.json`:

```jsonc
{
  "format": "relayer-story",
  "version": 1,
  "id": "demo",                    // латиницей, без пробелов: по нему хранится прогресс
  "revision": 1,                   // ревизия сценария: +1 на каждую выпущенную правку текста
  "series": "Пример",              // надпись над названием (мир или сериал)
  "title": "Не туда попали",
  "tagline": "Одна строка — она же на карточке",
  "synopsis": "Абзац-два: завязка без спойлеров.",
  "minutes": 3,                    // сколько минут в режиме «по клику», без ожиданий
  "days": 0.5,                     // сколько дней в реальном времени; дробное — меньше суток
  "free_chapters": 1,              // сколько первых глав бесплатно; нет поля — бесплатны все
  "cover": { "from": "#7c2d12", "to": "#140b08", "glyph": "?" },  // градиент и знак карточки
  "features": ["Чем история интересна", "Ещё одна строка"],
  "chapters": [{ "title": "Ошиблись номером", "when": "вечер", "about": "Одно предложение." }],
  "characters": [
    {
      "id": "lena", "name": "Лена", "role": "пишет на ваш номер", "about": "Пара предложений.",
      // служебное — экран истории это не показывает:
      "voice": { "length": "2–5 слов", "case": "строчные, без точек", "emoji": "никогда",
                 "word": "короче", "address": "ты", "wants": "чтобы её услышали" },
      "arc": [{ "from": 1, "role": "просит о помощи" }, { "from": 3, "role": "скрывает правду" }]
    },
    { "id": "bank", "name": "Банк", "role": "уведомления о платежах", "service": true }
  ]
}
```

- Обязательны только `title` и сценарий, остальное — для красоты экрана истории и для проверок.
- `id` персонажа совпадает с id контакта в сценарии (`# contact: lena, …`) — тогда кружок героя
  того же цвета, что и в чате.
- `voice` и `arc` у героя — для автора и проверок (`docs/playbook/rules.md`, R-75 и R-76): карточка
  голоса и функция в сюжете по главам. Игрок их не видит: «виновная с главы 8» на экране истории
  была бы спойлером. В `role` и `about` пишут только то, что можно показать.
- `service: true` — служебный контакт: заметки, пульт, банк, сервис. Он пишет в чат, но героем
  не считается: на экране истории его нет в списке «Герои», а `story:lint` не ждёт от него голоса и арки.
- `minutes` и `days` — два числа на карточке и экране истории: «≈ 3 мин по клику · ≈ 12 ч в реальном
  времени». Режим игрок выбирает перед началом (реальное время или «по клику»), сменить его можно
  только перезапуском; в файле режим не пишется.

**Раскладка по файлам.** Главы подключаются через `INCLUDE`, inkjs собирает их и в браузере. Правила,
без которых INCLUDE ломается или съезжает нумерация глав:

- в `story.ink` — шапка, `VAR`, начальный переход и строки `INCLUDE` в самом конце. Узлов в главном
  файле нет: после `=== узла ===` строка `INCLUDE` читается как реплика;
- в файле главы до первого `===` — только комментарии и `VAR`; `INCLUDE` — только из `story.ink`;
- комментарии над заголовком узла (`// финал:`) лежат в том же файле, что и узел.

`npm run story:pack -- --check` проверяет раскладку и что склейка глав играется так же, как INCLUDE.

### Один файл для загрузки

`npm run story:pack` собирает папку в `dist/stories/<id>.story.json` (это же делает `npm run build`,
так что файлы лежат и на Pages рядом с сайтом). В нём то же, что в `meta.json`, плюс сценарий:

```jsonc
{
  "format": "relayer-story", "version": 1, "id": "demo", "title": "Не туда попали", /* … */
  "ink": "# title: Демо\n# contact: lena, Лена, amber\n\n-> ch1\nINCLUDE ch01.ink\n",
  "includes": { "ch01.ink": "=== ch1 ===\nГлава 1 · Ошиблись номером #chapter\n..." }
}
```

- `includes` можно не писать: тогда весь сценарий в одном `ink` — так выглядит
  [`examples/demo.story.json`](examples/demo.story.json) и так пишет генератор. `story:pack -- --flat`
  склеивает главы в один `ink`.
- Можно загрузить и голый `.ink`: описание соберётся из заголовка файла, карточка будет без обложки.

### Добавить в репозиторий

Положить папку `src/stories/<алиас>/` — и всё. Каталог собирается через `import.meta.glob`,
регистрировать нигде не нужно. Если `id` в `meta.json` не задан, им становится алиас.
Готовый `.json` разложить по главам: `npm run story:unpack -- путь/к/истории.json`.

Если рядом лежат папка и `.json` с одним id, источник — папка, а `.json` — её копия от `story:pack`:
так считают и сайт, и `check:story`, и инструменты в `scripts/lib`.

### Загрузить без репозитория

1. Главный экран → **«Загрузить историю»** → выбрать `.json` (от `story:pack` или с одним `ink`) или `.ink`.
   История появится с пометкой «свой файл».
2. Поправить файл и загрузить снова — история с тем же `id` заменится, место в списке сохранится.
3. **«Скачать .json»** на экране истории выгружает её обратно — удобно взять за основу встроенную.

Прогресс хранится по `id`, а не по происхождению: если загруженная история потом приедет
в репозиторий, встроенная вытеснит копию, а прогресс останется.

## Теги сценария

Полный и всегда актуальный список — в реестре [`docs/capabilities.json`](docs/capabilities.json).
Коротко:

**В начале файла**

| Тег | Что делает |
|---|---|
| `# title: THE NUMBER` | название сценария |
| `# contact: theo, Тео, blue` | завести контакт: id, имя, цвет |

Цвета: `blue` `amber` `red` `grey` `green` `purple` `pink` `teal` `orange` `lime` `cyan` `indigo`.

**На строке**

| Тег | Что делает |
|---|---|
| `#from:theo` | дальше пишет контакт theo (до следующего `#from`) |
| `#me:theo` | игрок сам пишет первым в чат theo |
| `#sys` · `#sys:theo` | серая системная строка («Доставлено», «Тео не в сети») |
| `#delay:30s` · `#delay:12m` · `#delay:2h` | пауза сюжета перед строкой |
| `#unlock:dina` | открыть новый чат |
| `#rename:watcher, Слоун` | контакт получает настоящее имя |
| `#chapter` | строка начинает новую главу (текст строки — её название) |
| `#photo` | строка показывается как фото *(частично: пока заглушка)* |

**На кнопке выбора** — внутри квадратных скобок

| Пример | Что делает |
|---|---|
| `* [Тео, тут пришло кое-что #to:theo]` | ответ уходит в чат theo; кнопки одной развилки могут жить в разных чатах |
| `* [Промолчать #to:theo #silent]` | выбор без исходящего сообщения |
| `* [428193 #to:watcher #label:Переслать код]` | на кнопке намерение, в чат уходит точный текст |
| `* {theo_trust >= 3} [Текст #to:ray]` | вариант появляется по условию |
| `* [#remind:40m] алё, ты тут?` + `-> ask` | напоминание, если игрок молчит 40 минут; кнопкой не видно |
| `* [#noanswer]` / `* [#noanswer:30m]` | ветка «не ответил» после напоминаний; без неё — `#silent` |

**Напоминания.** Скрытые варианты развилки: интервал — тишина игрока с появления кнопок (для второго —
с первого напоминания), `*` тратит каждое один раз, `-> ask` возвращает к тем же кнопкам, поэтому
сборка `- (ask)` стоит прямо перед кнопками, а не перед вопросом. После последнего напоминания —
через столько же — история идёт веткой `#noanswer`, а если её нет, по `#silent` той же развилки.
В режиме «по клику» напоминаний нет. Без `#remind` и `#noanswer` со сроком кнопка ждёт, как раньше.

```ink
звонить хозяину? #from:ann
- (ask)
* [Звони] -> call
* [Промолчать #silent] -> quiet
* [#remind:40m] алё, ты тут?
    -> ask
* [#remind:1h] мне нужно да или нет. я у двери
    -> ask
```

Переменные, узлы, переходы и финалы — обычный ink (`VAR`, `~`, `=== knot ===`, `->`).
Символ `#` внутри тега нельзя: ink считает его началом нового тега.

**Задумано** (статус `planned` в реестре): контакты-ссылки в сообщении, настоящие фото
на весь экран, управляемый статус «в сети», доставлено/прочитано, голосовые и вложения,
удалённые и отредактированные сообщения, групповые чаты, «набирает и передумал».

## Генерация историй моделью

[`docs/capabilities.json`](docs/capabilities.json) — источник правды о том, что умеет чат:
каждая фича с синтаксисом, примером, статусом (`ready` / `partial` / `planned`) и описанием вида.
`npm run prompt` собирает из него [`docs/PROMPT.md`](docs/PROMPT.md): скопировать в чат с моделью,
дописать внизу, о чём история, получить `.json` и загрузить в приложение. Модель знает ровно то,
что движок умеет, и предупреждена о том, чего он ещё не умеет.

Сборщик сверяет реестр с `engine.ts`: тег со статусом `ready`, который движок не разбирает
(или `planned`, который уже работает), роняет сборку с объяснением.

## Панель отладки

Шестерёнка в чате открывает панель:

- переключение между историями и выход на главный экран;
- режим игры (сменить — только перезапуском с экрана истории);
- в реальном времени — отладочное ускорение пауз: ×1 (как у игрока, по умолчанию), ×10, ×60, без пауз;
  не сохраняется — и сколько осталось до следующего сообщения или, у кнопок, до напоминания;
- «Быстрый набор (×4)» для «печатает…»;
- «Пропустить до следующего»: следующее сообщение приходит сразу, без паузы и набора; у кнопок
  в реальном времени — следующее напоминание или ветка «не ответил» («без пауз» кнопку не торопит);
- переменные: переключать флаги и менять числа на лету;
- прыжок к главе или к любому узлу;
- стереть прогресс сцены.

Сбросить прогресс без отладки можно на экране истории — под кнопкой запуска.

## Тестирование

**Бот-тестировщик** — `npm run check:story [-- <id | папка | файл.json>]`. Компилирует сценарий
и делает 400 случайных прохождений (если редкий узел не встретился — добирает до 2000): ищет тупики
и недостижимые узлы, показывает, какие финалы
выпадают и сколько эпизод длится в реальном времени. Допустимые теги берёт из реестра возможностей.

**Карта сюжета** — `npm run graph [-- путь/к/истории.json] [-- --open]`. Собирает один HTML
со всеми историями: узлы ink — карточки (в углу номер главы), дерево идёт сверху вниз.
Выходы карточки разделены: «Игрок выбирает» — кнопки (оранжевые стрелки) и «Скрытая проверка» —
ветки по переменным, которых игрок не видит (синий пунктир). Финалы и обрывы — в красной рамке.
Клик по узлу открывает весь его текст: реплики по собеседникам, кнопки с вложенными ветками,
условия, переходы-ссылки. На карточке — сколько в узле кнопок и какая доля случайных прохождений
бота до него доходит: так видно редкие ветки. Спойлеры целиком,
поэтому файл лежит в `graph/` и в репозиторий не попадает.

**Playwright** — `npm run test:e2e` поднимает дев-сервер (порт 4173) и проверяет: карточку
и описание истории, запуск и ход сюжета, навигацию назад, «начать заново» и сброс прогресса,
возврат в тот же чат после перезагрузки, загрузку своего файла, ошибку на негодном файле,
удаление загруженной истории и вытеснение копии встроенной (`smoke.spec.ts`), режимы
(`modes.spec.ts`), напоминания и выключение уведомлений (`reminders.spec.ts`). Гоняет все спеки,
кроме снимков (`--grep-invert @shots`).

| Проект | Вьюпорт |
|---|---|
| `phone` | 390×844 |
| `small` | 360×640 |
| `desktop` | 1280×900 |

```bash
npx playwright install chromium          # один раз
npm run test:e2e -- --project=phone      # одно устройство
HEADLESS=1 npm run test:e2e              # без окна, быстрее
SLOWMO=400 npm run test:e2e              # помедленнее, чтобы разглядеть
E2E_PREVIEW=1 npm run test:e2e           # по продакшен-сборке
npx playwright show-trace test-results/*/trace.zip
```

По умолчанию браузер видимый: окно уезжает вправо, движения замедлены на 120 мс, воркер один.

**Скриншоты** — `npm run shots` снимает главный, описание, героев, главы, список чатов,
переписку, панель отладки и главный с загруженной историей на всех трёх устройствах
в `screenshots/<устройство>/` (папка не в гите). Самый быстрый способ убедиться, что вёрстка цела.

## Архитектура

React + Vite + TypeScript, из зависимостей только `inkjs` и React. **Логика живёт в `engine`,
оформление — в `ui`**: компоненты получают данные и обработчики пропсами и ничего не знают
про хранилище, маршруты и разбор файлов; `ui` импортирует только из `../engine`.

```
src/
├── App.tsx              связывание: маршруты и передача данных в экраны
├── engine/
│   ├── engine.ts        движок сценария: inkjs, разбор тегов, очередь сообщений, сохранение
│   ├── story.ts         тип Story: описание, герои, главы и ink (главный файл + includes)
│   ├── library.ts       каталог: папки src/stories/<алиас>/ + загруженные
│   ├── bundle.ts        разбор и выгрузка файла истории, палитра контактов
│   ├── uploads.ts       загруженные истории в localStorage
│   ├── progress.ts      прогресс без запуска движка
│   ├── flags.ts         параметры в адресе и доступ к localStorage
│   ├── useRouter.ts     маршруты home | story | game с запоминанием
│   ├── useLibrary.ts    список историй, загрузка, удаление, сброс прогресса
│   ├── useGame.ts       игровая сессия: компиляция, тиканье, уведомления
│   └── index.ts         публичный API для ui
├── ui/                  HomeScreen, StoryTile, StoryScreen, ChatsScreen, ChatScreen,
│                        DebugSheet, Notice, ErrorScreen, Avatar, Icons
├── styles/              tokens.css, base.css, blocks/*.css
└── stories/             <алиас>/ — истории каталога: meta.json, story.ink, ch01.ink…
examples/demo.story.json пример истории
examples/e2e.story.json  фикстура e2e-тестов и снимков
docs/                    capabilities.json — реестр, PROMPT.md — собранный промпт
scripts/                 check-story.mjs, build-prompt.mjs, story-graph.mjs (+ шаблон .html), story-pack.mjs
scripts/lib/             общая библиотека разбора: ink, компиляция, бот, загрузка и раскладка историй
e2e/                     smoke / modes / reminders .spec.ts — проверки, shots.spec.ts — снимки
```

### Хранилище

| Ключ `localStorage` | Что там |
|---|---|
| `relay:<storyId>` | прогресс истории |
| `relay:route` | где игрок был: экран, история, открытый чат |
| `relay:uploads` | загруженные истории целиком |
| `relay:fast` | быстрый набор в отладке |
| `relay:notices` | `0` — игрок выключил уведомления в игре (общая настройка всех историй) |

## Деплой

Каждый пуш в `master` запускает [`deploy.yml`](.github/workflows/deploy.yml): `npm ci` →
`check:story` → `build` → GitHub Pages. Если сценарий не компилируется или в нём тупик,
сборка падает, и на сайте остаётся прошлая версия.

Для своего форка: Settings → Pages → Source: **GitHub Actions**. Сайт будет по адресу
`https://<логин>.github.io/<репозиторий>/` — сборка с `base: './'` работает из любой подпапки.

## Договорённости

- Код и комментарии на русском; комментарий объясняет «почему», а не «что».
- Никаких зависимостей сверх необходимых: прототип должен собираться в один файл.
- **Меняешь поведение чата — правь `docs/capabilities.json` в том же коммите.**
  Реализовал фичу из «Задумано» — `status: ready`, уточнить `syntax`, дописать `looks`, пример и `since`.
- Стили по БЭМ: `block`, `block__element`, `block--modifier`, общие состояния — `is-`.
  Значения только из токенов `src/styles/tokens.css`, без вложенных селекторов.
  Новый блок — новый файл в `src/styles/blocks/` и строчка импорта в `src/styles/index.css`.
- Экраны внутри `.phone` — flex-колонка; блокам, которые не должны ужиматься, — `flex: none`.
- Селекторы в тестах — только `data-testid`, не классы.

Подробная памятка для ИИ-ассистентов — в [`CLAUDE.md`](CLAUDE.md).
