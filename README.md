# THE NUMBER · веб-прототип

Простая оболочка «мессенджер на телефоне» для проклацывания сценариев на ink.
На главном экране истории лежат карточками: тап — и ты внутри переписки, «← Истории» — обратно.
Каждый пуш в `master` проверяет сценарии и выкладывает сайт на GitHub Pages.
Открываешь ссылку с телефона, играешь. iOS-приложение делаем потом, на том же ink.

## Экраны

- **Истории** — главный: все истории карточками. Отсюда же кнопка «Загрузить историю».
- **Описание истории** — о чём, как играется, герои, главы. Отсюда запуск: «Начать» / «Продолжить».
- **Чаты и переписка** — собственно игра: список чатов, сообщения, варианты ответа, шестерёнка с отладкой.

Назад всегда ведёт на уровень выше: из чата → к списку → к описанию истории → на главный.

## Запуск локально

```bash
npm install
npm run dev            # http://localhost:5173, с телефона по IP компьютера: npm run dev -- --host
npm run check:story    # 400 случайных прохождений каждого сценария
npm run build          # сборка в dist/
npm run test:e2e       # Playwright: проверки в настоящем браузере
npm run shots          # скриншоты всех экранов в screenshots/<устройство>/
```

Игра идёт настоящими минутами, поэтому для быстрой проверки есть флаги в адресе:
`?story=pilot` (сразу открыть историю), `?screen=home`, `?fresh=1` (с чистого листа),
`?fast=1` (без пауз сюжета). Например `http://localhost:5173/?story=pilot&fresh=1&fast=1`.

## Первый деплой

1. Создать репозиторий на GitHub и запушить этот проект в ветку `master`.
2. В репозитории: Settings → Pages → Source: **GitHub Actions**.
3. Дальше каждый `git push` сам собирает и выкладывает. Ссылка вида `https://<логин>.github.io/<репозиторий>/`.

Если сценарий не компилируется или в нём есть тупик, сборка падает и старая версия остаётся на сайте.

## Сценарии

- `src/stories/the-number.json` — пилот THE NUMBER, 5 глав: Доставлено → Код → Эвакуатор → Прачечная → Рэй.
  Описание, герои, главы и весь сценарий в одном файле

`npm run check:story` показывает, сколько длится эпизод в реальном времени, какие финалы выпадают и нет ли недостижимых узлов.
- `examples/demo.story.json` — короткий пример истории одним файлом, он же шаблон для своих

## Что умеет движок (и промпт для новых историй)

Список возможностей чата лежит в [`docs/capabilities.json`](docs/capabilities.json) — это
источник правды: каждая фича с синтаксисом, примером и статусом (`ready` / `partial` / `planned`).

```bash
npm run prompt              # собрать промпт из реестра → docs/PROMPT.md, напечатать
npm run prompt -- --copy    # ещё и положить в буфер обмена
```

[`docs/PROMPT.md`](docs/PROMPT.md) — готовый текст: скопировали в чат с моделью, дописали
внизу, про что история, получили .json, загрузили в приложение. Модель знает ровно то,
что движок умеет, и явно предупреждена о том, чего он ещё не умеет.

**Правило: добавили поведение в чат — добавьте фичу в `capabilities.json`.** Сборщик промпта
сверяет реестр с движком: если тег помечен `ready`, а движок его не разбирает (или наоборот,
`planned` уже работает) — падает с объяснением.

## История одним файлом

История — это один `.json`: описание, герои, главы и сам сценарий внутри. Такой файл можно
передать кому угодно, открыть приложение, нажать «Загрузить историю» — и сразу играть.
Готовый пример и шаблон: [`examples/demo.story.json`](examples/demo.story.json).

```jsonc
{
  "format": "relayer-story",
  "version": 1,
  "id": "demo",                    // латиницей, без пробелов: по нему хранится прогресс
  "series": "Пример",              // надпись над названием (мир или сериал)
  "title": "Не туда попали",
  "tagline": "Одна строка — она же на карточке",
  "synopsis": "Абзац-два: завязка без спойлеров.",
  "minutes": 3,                    // сколько примерно занимает
  "cover": { "from": "#7c2d12", "to": "#140b08", "glyph": "?" },  // градиент и знак карточки
  "features": ["Чем история интересна", "Ещё одна строка"],
  "chapters": [{ "title": "Ошиблись номером", "when": "вечер", "about": "Одно предложение." }],
  "characters": [
    { "id": "lena", "name": "Лена", "role": "пишет на ваш номер", "about": "Пара предложений." }
  ],
  "ink": "# title: Демо\n# contact: lena, Лена, amber\n\nпривет #from:lena\n..."
}
```

Обязательные поля: `title` и `ink`. Остальное — только для красоты экрана истории.
`id` у персонажа должен совпадать с id контакта в сценарии (`# contact: lena, ...`),
тогда кружок героя будет того же цвета, что и в чате.

Как с этим работать:

1. Открыть приложение → «Загрузить историю» → выбрать файл. История появится на главном с пометкой «свой файл».
2. Поиграть, что-то не понравилось — поправить файл и загрузить снова: история с тем же `id` заменится.
3. Кнопка «Скачать .json» на экране истории выгружает её обратно — удобно взять за основу встроенную.

Можно загрузить и голый `.ink` — тогда описание соберётся из заголовка файла, а карточка будет
без обложки. Для быстрой проверки сценария этого хватает.

## Как добавить историю в репозиторий

Положить файл `src/stories/<алиас>.json` — и всё. Приложение само собирает каталог
из этой папки, регистрировать нигде не нужно. Алиас файла становится `id` истории,
если поле `id` в файле не задано.

Так истории, которые хочется сохранить, едут в гит и открываются на сайте, а черновики
живут в браузере через «Загрузить историю».

## Теги в сценарии

- `#from:theo` — дальше пишет контакт theo (действует до следующего `#from`)
- `#me:hold` — исходящее сообщение игрока в чат hold (сам пишет первым)
- `#sys` — серая системная строка («Доставлено», «Тео не в сети»); `#sys:theo` — в чат theo
- `#photo` — строка показывается как фото
- `#delay:12m` — пауза перед строкой: `s`, `m`, `h`
- `#unlock:dina` — открыть новый контакт
- `#chapter` — строка начинает новую главу (текст строки = название главы)
- `#rename:watcher, Слоун` — контакт получает настоящее имя

Теги на кнопке выбора (внутри квадратных скобок):

- `* [Тео, тут пришло кое-что #to:theo]` — ответ уходит в чат theo. Кнопки одной развилки могут жить в разных чатах: игрок сам решает, кому написать
- `* [Промолчать #to:theo #silent]` — выбор без исходящего сообщения
- `* [428193 #to:watcher #label:Переслать код с ошибкой]` — на кнопке намерение, под ним точный текст сообщения

Глобальные теги в начале файла:

```ink
# title: Last Errand · День 1
# contact: theo, Тео, blue
```

Цвета: blue, amber, red, grey, green, purple, pink, teal, orange, lime, cyan, indigo.
Символ `#` внутри тега нельзя: ink считает его началом нового тега.

## Панель отладки (шестерёнка)

- переключение между историями и выход на главный экран
- скорость пауз сюжета: ×1 (как у игрока), ×10, ×60, без пауз. Набор текста («печатает…») всегда идёт в реальном темпе
- «Быстрый набор (×4)» — ускоряет «печатает…», чтобы быстро проклацать весь пилот
- «Пропустить ожидание»
- переменные: переключать флаги и предметы на лету
- прыжок к главе (или к любому узлу)
- начать сцену заново

Прогресс хранится в браузере телефона. Закрыл вкладку на час: при возвращении время догонится, как будто сообщения приходили, пока тебя не было.

## Проверка в браузере

`npm run test:e2e` поднимает дев-сервер и прогоняет сценарии использования: карточка на главном,
описание истории, запуск, возврат назад, «начать заново», продолжение после перезагрузки,
загрузка своего файла и удаление загруженной истории.

Браузер по умолчанию **видимый** — видно, что происходит, окно открывается справа.
`HEADLESS=1 npm run test:e2e` — без окна и быстрее, `SLOWMO=400` — помедленнее, чтобы разглядеть.
`npm run shots` делает снимки главного, списка чатов, переписки и панели отладки
на трёх экранах (`phone`, `small`, `desktop`) — лежат в `screenshots/`, удобно сравнивать варианты вёрстки.

Нужен один раз: `npx playwright install chromium`.

## Устройство

Логика — в `engine`, оформление — в `ui`. Компоненты `ui` ничего не знают про хранилище
и маршруты: им передают данные и обработчики.

```
src/App.tsx                связывание: маршруты и передача данных в экраны
src/engine/engine.ts       движок сценария: inkjs, разбор тегов, очередь сообщений, сохранение
src/engine/story.ts        формат истории: описание, герои, главы и ink в одном объекте
src/engine/library.ts      каталог: истории из src/stories + загруженные с устройства
src/engine/bundle.ts       разбор и выгрузка файла истории, палитра контактов
src/engine/uploads.ts      загруженные истории в localStorage
src/engine/progress.ts     прогресс прохождения без запуска движка
src/engine/flags.ts        параметры в адресе (?story, ?fast, ?fresh)
src/engine/useRouter.ts    три экрана и возврат на уровень выше
src/engine/useLibrary.ts   список историй, загрузка, удаление, сброс прогресса
src/engine/useGame.ts      одна игровая сессия: тиканье времени и уведомления
src/ui/                    экраны и компоненты на React, только оформление
src/styles/                токены, база и блоки БЭМ
src/stories/<алиас>.json   сами истории
examples/demo.story.json   пример истории одним файлом, он же шаблон
docs/capabilities.json     что умеет чат; из него собирается промпт
scripts/check-story.mjs    бот-тестировщик историй
e2e/                       Playwright: smoke.spec.ts (проверки), shots.spec.ts (снимки)
```

## Оформление

Стили разложены по БЭМ: блок — независимая часть интерфейса (`story-tile`), элемент — её
часть (`story-tile__title`), модификатор — вариант (`story-tile--started`, `btn--primary`).
Вложенных селекторов нет: блок знает только про себя, поэтому его можно переставить куда угодно.

```
src/styles/tokens.css   цвета, отступы, скругления, размеры текста, слои
src/styles/base.css     сброс и общая типографика
src/styles/blocks/*.css по файлу на блок
```

Правила: значения берём из токенов (никаких случайных `14px` в блоках), состояние элемента —
модификатор (`chat-row__preview--typing`), общие состояния — префикс `is-` (`is-rising`).
Новый блок — новый файл и строчка импорта в `src/styles/index.css`.
